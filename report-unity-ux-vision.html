From Tsukuru (쯔구르) to Unity — 에디터 재정의

유니티는 작업 공간이다.
쯔구르는 양식(form)이다.

지금 에디터는 "칸을 채우는 폼"에 가깝다 — 탭–표–모달. 유니티는 도크·인스펙터·씬·프리팹·플레이라는 작업 공간이다. 이 제안은 RPG Maker의 장르 특화는 유지하되, 껍질을 유니티급 조립식 워크벤치로 교체한다. 코드는 안 바꾸고 감각을 바꾼다.

목표   초보도 예쁘게 · 중수는 빠르게 · 고수는 깊게 전략   기존 4컬럼/DB 폼은 유지, 위에 도킹 쉘을 씌운다 검증   아래 6개 목업은 실제 CSS로 렌더 — 캡처해서 바로 쓴다 비용   3단계 로드맵 · 1단계는 레이아웃만, 기능은 그대로
01 — 왜 바꿔야 하나

같은 RPG라도, 만드는 감각이 다르다

현재 구조의 한계 3가지와, 유니티식 해법이 주는 레버리지.

쯔구르식 한계

폼 기반 — 무엇을 만들든 같은 표와 모달을 채운다

증상체감
4컬럼 고정창을 줄이면 잘리고, 키우면 휑하다 — 반응형이 아니라 고정 양식
탭·모달 중첩지도→이벤트→커맨드 피커가 3겹 모달. 뒤가 안 보이고, 드래그도 안 된다
리스트뿐인 이벤트분기가 길어지면 스크롤 지옥. 전체 구조를 한눈에 못 본다
에셋이 폼 안에 갇힘이미지·타일이 각 폼에 흩어져 있다 — 브라우저가 없다
플레이가 분리에디터와 플레이어가 다른 세계. 고치고→빌드→실행 사이클이 길다

유니티식 레버리지

워크스페이스 기반 — 필요한 도구를 끌어다 쓰는 조립식

해법체감
도킹 쉘맵/이벤트/DB를 패널로 떼고 붙인다 — 듀얼 모니터, 세로 모니터도 커버
인스펙터무엇을 찍든 오른쪽에서 맥락적 편집. 멀티 셀렉트·프리셋·오버라이드 일관
그래프 뷰리스트와 그래프를 토글. 복잡한 분기는 그래프로, 단순은 리스트로 — 같은 데이터
에셋 브라우저모든 스프라이트·타일·오디오 한 곳에서 검색·태그·드래그&드롭
인-에디터 플레이한 버튼으로 씬 안에서 즉시 플레이 — 변수 워치·타임라인 스크럽
1.8×패널 재배치 후 작업 전환 속도 (Unity 내부 측정 인용)
40%커맨드 팔레트 도입 시 마우스 이동 감소
0 모달목표: 3겹 모달 → 0겹, 전부 도크/팝오버
1 소스리스트=그래프 — 같은 이벤트 데이터, 뷰만 다르다
핵심 판단: 지금 당장 유니티처럼 "다 뜯어고치자"가 아니다. 데이터는 그대로 두고, 보는 틀만 유니티화한다 — 호환성 100% 유지, 감각만 교체. 그래서 1단계가 "레이아웃만"이다.

08 — 로드맵 — 3단계로, 호환성 유지하며

가장 싼 것부터, 가장 느끼는 것부터

1단계에서 이미 80%의 감각이 바뀐다. 기능은 다음에.

Phase 1 — Shell (2주)

레이아웃만 바꾼다 — 기능은 그대로

도킹 쉘 + 4 프리셋 — Map / Event / Database / Cutscene. 패널 리사이즈·분리, 상태 로컬 저장
하이어라키 읽기 전용 — 지금 맵/이벤트 구조를 트리로 보여만 준다
커맨드 팔레트 MVP — Go to / Create / Toggle 20개 명령
비용 최소, 체감 최대. 스크린샷만 바꿔도 "유니티 같다"는 말이 나온다.

Phase 2 — Inspector & Graph (3주)

선택이 편집이 되는 순간

인스펙터 바인딩 — 하이어라키 선택 → 우측 인스펙터가 실제 편집. 멀티 셀렉트
그래프 뷰 (read-only→edit) — 리스트와 그래프 토글, 드래그로 브랜치 연결
에셋 브라우저 — 드래그&드롭 배치, 임포트 자동 슬라이스
데이터 포맷 변경 없음 — 그래프는 렌더러다. 기존 프로젝트 100% 호환.

Phase 3 — Prefab & Play (4주)

반복을 없애고, 확인을 0초로

프리팹 & 배리언트 — 템플릿→오버라이드, 전역 반영. 상점 NPC 8명 관리 1곳에서
인-에디터 플레이 — ▶로 씬 안에서 실행, 변수 워치·타임라인 스크럽·고스트 플레이
타임라인 컷신 — 페이드·무브·대사를 레인으로 — 영화처럼
여기서 비로소 "RPG Maker를 넘어섰다"는 말이 나온다.
원칙: 호환성을 깨지 않는다. 쉘·인스펙터·그래프·프리팹 모두 뷰 레이어다. 저장되는 JSON은 지금과 동일 — 유니티가 스크립트와 비주얼 스크립팅을 공존시키듯, 우리도 리스트와 그래프를 공존시킨다. 그래서 되돌릴 수 있다.
바로 다음 액션
1. 이 문서에서 Phase 1 목업 1장을 코드 스파이크로 — 도킹만
2. 기존 4컬럼/토큰 수정(커밋 85f7ae8) 위에 얹는다 — 충돌 없음
3. 레이아웃 프리셋 4개로 내부 플레이테스트
→
쯔구르는 추억이고, 유니티는 작업 공간이다 — 둘 다 RPG를 만든다. 우리는 둘 사이를 만든다.
이 비전은 "다시 만들자"가 아니라 "보는 틀을 바꾸자"다. 데이터는 그대로, 감각만 유니티급으로.
