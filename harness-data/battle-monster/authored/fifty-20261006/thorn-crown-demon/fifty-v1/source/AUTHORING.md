# 가시관마귀 — 앞손·갈고리·수면 무릎 교정

## 범위와 원본

이 후보의 `source` 안에서만 수정했다. 현재 원본은 `poses/` 9장과 `actions/` 9장의 완전한 96×96 ASCII 격자다. 팔레트는 기존 18색을 그대로 유지했다. 이번 수정 전 18장, 팔레트, 저작 행 기록과 문서는 `before-hand-knee-repair/`에 보존했다. 그보다 앞선 기록도 남겼다.

첨부 시트와 64px 검객 참고 PNG를 실제로 열어 보았다. 암자주 피부의 넓은 왼쪽 위 빛 면, 흰 가시관, 녹청 허리띠, 회갈 발과 우향 얼굴을 유지했다. 참고 픽셀을 추출하거나 복사하지 않았다.

## 직접 고른 수정 군집

좌표는 0기준 native 픽셀이다. `repair_hand_knee.py`와 `authored_rows.txt`에 자세별 실제 좌표와 리터럴 문자열을 남겼다. 한 자세의 좌표를 다른 자세로 자동 이동하지 않았다.

| idle_b | x50–75, y66–79 | 해당 자세의 넓어진 허리와 전완 위치에서 손목과 손가락을 별도 문자열로 저작했다. 발과 기본 다리 윤곽은 유지했다. |

첫 수정 PNG에서 준비의 뒤손을 바깥으로 빼면서 x24–27/y70–83의 왼쪽 허리 윤곽까지 지워진 것을 발견했다. 손과 몸 사이를 억지로 채우지 않고, 몸의 O/S/P 경계와 허리띠 T/U/t 행만 실제 좌표에서 다시 골라 복구했다. 대기 손 아래 y77–79에서 불필요하게 바뀐 다리 외곽도 원래 위치의 리터럴 군집으로 정리했다.

`move`, `recover`, `hit`, `dead`, 기술 3장, 독 2장, 기절 2장은 이번 수정 전 원본과 바이트가 같다. 기존 기술은 손끝의 기 모으기→연결된 두 가시 줄기→짧은 잔상과 분리 파편이다. 독은 배를 누르는 팔과 기포, 기절은 처진 머리/팔과 별, 수면은 닫힌 눈과 접힌 두 다리다. 추가 동작 9장 모두 별도의 완전한 리터럴 격자로 존재한다.

## 실제 그림 확인과 파일 재읽기

현재 18장 전체의 밝은/어두운/체커 배경 1배 PNG와 최근접 3배 PNG를 열어 윤곽, 목, 복부, 팔꿈치, 손목, 두 발과 의도한 빈 공간을 확인했다. `rendered/repair-after-detail.png`에는 세 대기 손, 준비 양손, 공격 갈고리와 수면 두 장을 확대해 함께 놓았다. 1배에서 손이 허벅지 밖에 놓이며 공격 손가락 끝이 굽는 것을 확인했다. 수면 두 장의 눈은 짧은 닫힌 눈꺼풀로 남아 있다.

`render.py`로 현재 격자를 native PNG 18장과 GIF 8개로 인코딩했다. 각 GIF의 모든 프레임을 다시 읽어 원본 RGBA 및 TIMING의 노출 시간과 일치함을 확인했다. 8개의 실제 GIF 디코딩 시트를 열어 준비→전진→접촉→회수의 같은 앞팔과, 기술/상태별 변화 및 발 위치를 확인했다.

`rendered/READBACK.json`은 현재 원본/PNG/GIF의 실제 SHA-256과 인코딩 재읽기 기록이다. `rendered/REPAIR-READBACK.json`은 이번 수정 전 원본 대비 픽셀 차이와 크기/여백/접지 실측이다. 18장 모두 96행×96열, 알려진 팔레트 기호, 투명 외곽, 최하단 y=92이고 서로 다른 배열이다. 팔레트는 수정 전과 바이트가 같다. 저장소 테스트/게이트나 독립 시각 검수 결과가 아니다.

## 남은 시각적 한계

96px에서 갈고리 사이 틈과 손가락의 명암 경계는 작다. 수면은 낮은 웅크림이므로 무릎 면이 얕고 손과의 구분은 짧은 어두운 경계에 의존한다. 대기·수면의 호흡 변화는 작으며 공격은 네 핵심 자세 사이에서 빠르게 변한다. GIF의 프레임 순서를 디코딩 시트로 확인했지만 실제 시간 재생의 매끄러움, 게임의 hop 경로·접촉 판정·피해 연출은 이 작업에서 확인하지 않았다.

별도 검수자는 직접 호출하지 않았다. 현재 그림의 독립 검수와 판정은 하네스가 수행한다. 사용자 승인이나 검수 통과를 선언하지 않는다.
