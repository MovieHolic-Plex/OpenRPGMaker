# 심연현무 — 갑각 어깨 밀치기 교정

## 이번 수정의 범위

제공된 현재 18자세 시트와 64px 검객 참고 이미지를 실제로 열어 실루엣·광원·크기·얼굴을 관찰했다. 참고 픽셀은 추출·추적·리샘플하거나 산출물에 넣지 않았다.

현재 원본은 `palette.json`, `poses/*.pxgrid` 9개와 `actions/*.pxgrid` 9개다. 모두 native 128×128의 완전한 ASCII 행이며 점은 투명이다. **이번 실제 격자 변경은 `poses/attack.pxgrid` 하나다.** 다른 17개 자세와 기존 18색 팔레트는 수정 직전 파일 해시와 같으며 기술/독/기절/수면도 보존했다. 모든 쓰기는 이 후보의 `source/` 안에서만 했다.

전달받은 현재 독립 지적은 attack의 x=88/y=94 부근이었다. 머리가 앞테보다 앞에 남고 가까운 앞발이 보행의 지지발처럼 보여, 실제 갑각 어깨 밀치기를 강화하라는 내용이다. 판정 기록이나 사용자 선택은 변경하지 않았다.

## 직접 고른 ASCII 군집

좌표는 셀 좌상단 (0,0) 기준이다. `edits/shell-bash.rows`에 직접 고른 y/x/ASCII 문자열과 첫 PNG 확인 뒤의 후속 교정을 순서대로 남겼다. `apply_shell_bash.py`는 그 문자열만 지정 좌표에 대입하며 전체 128행 격자를 저장한다. 자동 픽셀 선택·명암·연결·구멍 채우기·전체 프레임 이동·회전·보간 기능은 없다. 이전 저작 코드는 역사 자료이며 현재 격자 위에 재실행하지 않았다.

### 앞 돌갑각과 금빛 접촉 테두리

- 총 1,490픽셀 변경, 실제 변경 범위 x=83…122/y=53…124.
- 공격의 윗면 y=0…52와 모든 행의 x=0…82는 수정 전 그대로다. 윗빛/중앙 금 문양/주요 사선·가로 금 홈, 뒷발과 물결 꼬리의 배열을 보존했다.
- x=83…114/y=53…94에 어두운 j/s의 넓은 돌갑각 앞면과 r/a/k의 이어진 하단 금 테두리를 직접 저작했다. 앞테 x=109…114/y=75…90이 목보다 먼저 나오는 접촉 면이다. 기존 사선 금 홈은 x=83…85/y=76…85에서 유지하며 하단 금 띠는 원래 왼쪽 띠와 이어진다.
- 첫 수정 PNG에서는 y=64…67의 윤곽이 안으로 꺾여 새 앞면이 별도 돌출 조각처럼 보였다. y=53…77의 행을 다시 골라 위쪽 돌갑각에서 접촉 앞면으로 내려오는 하나의 볼록한 윤곽으로 고쳤다. 절차 도형이나 자동 윤곽 정리는 사용하지 않았다.

### 앞테 아래로 접은 목과 작은 머리

- 기존 x=104…115/y=88…99의 노출된 머리를 명시한 점 문자열로 제거했다. x=98…109/y=95…102에는 별도로 고른 좁은 목 굽힘과 작은 머리의 L/H/C/B/D 면, 짧은 닫힌 입 경계를 저작했다.
- 작은 금 눈은 x=103…105/y=98…99의 k/a/v 군집이다. 공격의 뜬 눈이며 수면 눈을 복사하지 않았다. 머리 끝은 x=109, 앞 갑각 윤곽은 x=113…114이므로 머리가 접촉 면 뒤에 있다.
- x=83…99/y=95…105의 넓은 청색 어깨와 목 밑면은 실제 색 면으로 이어진다. O/D 경계는 겹침을 나누며 목을 검은 외곽선만으로 연결하지 않았다.

### 앞으로 버티는 가까운 앞다리

- x=84…108/y=102…117에 상완·앞쪽 팔꿈치·아래팔·압축된 손목의 굵은 L/H/C/B/D 군집을 직접 골랐다. 가는 선 다리나 신체 전체 이동으로 만들지 않았다.
- x=97…119/y=117…124에 넓게 퍼지는 앞발과 세 개의 짧은 발톱을 따로 저작했다. 실제 가까운 발바닥 O 행은 x=102…119/y=124다. 뒤 지지발의 기존 x=12…27/y=124도 유지했다.
- 먼 앞다리는 목/어깨 뒤 x=104…122/y=103…113에서 따로 이어지고 짧은 발끝으로 마무리된다. 가까운 다리와 먼 다리 사이의 배경 공간은 의도한 틈이며 자동으로 채우지 않았다.
- 준비·이동·회수 원본은 보존했다. 이동의 뒤발 밀기 → 접촉에서 목을 접고 앞테를 내밀며 앞발을 앞으로 버팀 → 회수에서 목과 발을 몸으로 당김의 네 자세를 나란히 열어 비교했다.

## 보존한 기술과 상태 자세

기술 3격자는 갑각 앞쪽 청금 기 준비, 실제 입에서 연결되는 서로 분리된 두 물 파문, 낮춘 목과 세 잔물보라의 기존 리터럴 원본이다. 독 두 자세의 아픈 목/앞발과 다른 거품, 기절 두 자세의 처진 머리와 다른 별, 수면 두 자세의 감긴 눈/접힌 발/말린 꼬리/작은 머리·갑각 호흡도 그대로다. 추가 9격자는 모두 완전한 128행이며 이번 수정에서 같은 공격 자세나 색조 변환으로 대체하지 않았다. 입 앵커와 노출 시간은 `TIMING.md`에 있다.

## 실제 확인한 산출물

`render.py`로 18 native PNG, 기본/추가 시트, 세 배경 전체 시트와 8GIF를 갱신했다. 저장 GIF를 다시 디코딩한 불투명 색/알파가 원본 격자 PNG와 일치하는지 렌더러가 비교했다. 고정 원본 팔레트를 사용하며 GIF 색 양자화나 동작 합성은 없다. 확대는 진단에만 사용하고 PNG/GIF 원본 셀은 128px다.

실제로 열어 확인한 그림:

- `previews/attack-repair-backgrounds.png`: 밝은/어두운/체커의 실제 1배 및 최근접 3배. 앞면·목·어깨·앞발의 연결과 투명 틈을 확인했다.
- `previews/shell-bash-before-after.png`: 수정 직전/현재 공격의 1배·3배 비교.
- `previews/shell-bash-neck-foot-detail.png`: 실제 목/머리/두 앞다리/발의 진단 확대.
- `previews/shell-bash-sequence.png`: 준비·전진·접촉·회수를 1배·3배로 비교. 넓은 위쪽 돌갑각과 금 홈의 정체성, 바뀐 접촉 면을 함께 확인했다.
- `previews/{light,dark,checker}-native.png`: 전체 18자세. 같은 갑각/목/발 부위의 명백한 새 결손은 보이지 않았다.
- `previews/{idle,attack,hit,dead,skill,poison,stun,sleep}-gif-strip.png`: 실제 저장 8GIF에서 디코딩한 모든 프레임. 연결·의도한 빈틈·프레임 간 자세 변화를 정지 비교했다.

`inspect_shell_bash.py`는 원본을 읽어 비교판과 `previews/shell-bash-file-observations.json`만 만든다. 18격자의 행 수/길이는 모두 128, 미등록 글자와 불투명 테두리는 0개, 최하단 ink는 모두 y=124다. idle_a의 실제 발 접지는 y=124다. 팔레트와 다른 17격자가 보존됐다는 파일 해시 비교 및 GIF 유지 시간도 기록했다. 이는 파일 관찰이며 독립 미감 판정이 아니다.

## 원본과 이력

- `revisions/before-shell-bash/`: 이번 수정 직전 공격 격자·팔레트·AUTHORING/TIMING 사본 및 전체 원본 파일 해시. 기존 교정 기록은 이 폴더의 AUTHORING에 보존했다.
- `edits/shell-bash.rows`: 이번 직접 선택한 문자열과 PNG 확인 뒤의 후속 선택.
- `apply_shell_bash.py`, `inspect_shell_bash.py`, `render.py`: 좌표 대입·읽기·진단·native 출력 보조 코드.
- 다른 기존 revision/edits/저작 보조 코드는 삭제하지 않았다.

## 남은 시각적 문제와 표현 한계

- 접촉의 앞면은 이동/회수보다 넓게 드러난다. 윗면과 주요 금 홈을 보존했지만, 앞테 전진이 단단한 갑각의 자세 변화로 읽히는지, 폭 변화가 과해 보이는지는 새 독립 검수에서 확인할 부위다.
- 이동에서 목을 크게 접는 접촉으로 전환하고 회수에서 다시 세우므로 네 자세 사이의 목 변화는 크다. 중간 프레임을 합성하지 않았으며 실제 게임의 돌진 거리·접촉·피해 시점과 재생 중 체감 타이밍은 여기서 관찰하지 않았다.
- 접힌 작은 공격 머리는 1배에서 눈과 목이 보이지만 어두운 배경에서는 목/먼 다리의 겹침 대비가 낮다. 기존 수면과 쓰러짐은 가까운 낮은 자세이며 수면의 들린 목/감긴 눈/금 홈과 쓰러짐의 갑각 균열로 구분된다. 기존 상태 쌍의 움직임은 작다.

테스트/게이트와 별도 검수자 호출은 하지 않았다. 저장소·게임 저장소·ledger·brief·다른 후보·판정은 변경하지 않았다. 새 독립 검수는 하네스가 맡는다. 사용자 승인이나 검수 통과를 선언하지 않는다.
