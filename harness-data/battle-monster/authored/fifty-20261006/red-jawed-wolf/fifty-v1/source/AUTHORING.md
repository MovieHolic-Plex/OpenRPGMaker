# 붉은턱늑대 — skill_b 뒤쪽 등·엉덩이 윤곽 교정

## 현재 수정: 지적된 경계 세 픽셀만 복원

첨부 늑대 시트와 64px 검객 참고 이미지를 실제로 열어 관찰했다.
현재 후보의 18자세는 이미 전체 64×64 ASCII 행으로 존재한다.
이번 수정은 `actions/skill_b.pxgrid`의 다음 세 좌표뿐이다. 좌표는 0부터 시작한다.

| x | y | 이전 | 현재 |
|---|---|---|---|
| 17 | 31 | L | K |
| 17 | 32 | H | K |
| 17 | 33 | L | K |

K는 기존 어두운 윤곽색 `#111a29`다. 위쪽 x17/y30의 K에서 내려오는
경계를 복원했다. 각 픽셀 바로 오른쪽의 밝은 털 면은 그대로 남겼다.
투명 픽셀은 하나도 바꾸지 않아 꼬리와 몸 사이의 실제 빈 공간을 보존했다.
나머지 17자세와 16색 팔레트는 수정 직전 원본과 바이트가 같다.
효과의 두 갈래·입 앵커·발·몸의 크기와 모든 GIF 순서/hold를 보존했다.

`repair_skill_back_outline.py`에 직접 고른 세 좌표를 보존했다.
납품 원본은 전체 리터럴 행의 pxgrid이며, 도형 생성·자동 채움·음영 합성·
전체 프레임 이동/회전/보간을 사용하지 않았다.
수정 직전 18격자·팔레트·문서·실제 파일 해시는
`history/before-skill-back-outline-repair/`에 보존했다.

### 현재 출력의 실제 확인

- `preview/skill-back-outline-repair.png`를 실제 열었다. 밝은·어두운·체커
  배경의 전후 native 1배와 최근접 3배 및 좌표 구역 확대에서 세 K 경계와
  오른쪽 밝은 면, 남겨 둔 꼬리 빈 공간을 확인했다.
- `preview/sheet-native.png`의 18자세를 실제 열어 전체 윤곽을 관찰했다.
- `render.py`로 PNG와 8GIF를 리터럴 원본에서 다시 만들었다.
  GIF를 재읽어 모든 프레임의 RGBA와 시간표 hold가 원본과 일치함을 확인했다.
  실제 GIF 디코드 결과인 `gif-basic-contact.png`, `gif-actions-contact.png`를
  열어 기본/기술/상태 동작의 연속 자세를 확인했다. 실시간 재생 검수는 하지 않았다.
- `preview/skill-back-outline-readback.json`에 실제 세 변경 좌표,
  나머지 17프레임/팔레트 보존, 64×64, 유효 기호, 투명 테두리,
  최하단 y≤60을 기록했다. idle_a의 최하단은 정확히 y60이다.
  18프레임은 서로 다르고 알파는 0/255다.
- `preview/source-sha256.json`과 `gif-readback.json`은 재생성한 현재 파일의
  로컬 사실이며 독립 검수 결과나 사용자 선택 binding이 아니다.

### 남은 시각적 문제와 확인 범위

요청된 skill_b의 밝은 면 노출은 세 경계 픽셀로 보완했다.
현재 확인판에서 이번 수정으로 생긴 새로운 투명 홈이나 몸의 이동은 보이지 않는다.
어두운 배경에서는 원래 K 윤곽의 대비가 약하고, 수면의 꼬리/접힌 뒷발은
작은 군집으로 남는다. 포효의 각진 두 갈래와 160ms 발동의 인상,
실제 전투 이동·접촉 타이밍은 하네스/게임에서 판단할 범위다.
이번에 그 표현을 추가 변경하지 않았다.

모든 쓰기는 이 후보의 `source/` 안에서만 했다. 테스트/게이트나 별도 검수자를
호출하지 않았으며, 하네스의 새로운 독립 검수는 아직 받지 않았다.
사용자 승인, 이 후보 또는 50종 전체의 검수 통과를 선언하지 않는다.

재생성 명령:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 source/render.py
PYTHONDONTWRITEBYTECODE=1 python3 source/inspect_skill_back_outline.py
```

## 작업 범위

첨부 `reference.png`와 `references/human-size.png`를 실제로 열어 관찰했다.
늑대의 두 귀, 긴 주둥이, 검푸른 털, 붉은 목털과 왼쪽 위 광원을 유지했다.
64px 검객은 크기와 얼굴·손 연결의 관찰 자료로만 보았다. 참고 이미지의
픽셀 추출·추적·리샘플링·재배포를 하지 않았다.

기본 9자세와 추가 동작 9자세, 총 18개의 전체 64×64 ASCII 격자를 유지한다.
이번에는 `idle_a/b/c`, `skill_b`, `sleep_a/b`의 6자세를 수정했다.
나머지 12자세와 16색 팔레트는 수정 직전 파일과 바이트가 같다.
모든 출력은 이 후보의 `source/` 안이다. 정본 게임 저장소·brief·ledger·다른 후보·
독립 검수 결과나 사용자 선택 기록을 수정하지 않았다.

## 직접 고른 좌표와 군집

좌표는 0부터 시작한다. `repair_roar_sleep_notch.py`에 모든 수정의
`(x, y, ASCII 문자열)`을 보존했고, 납품 원본은 전체 행의 `.pxgrid` 파일이다.
도형 본체, 음영 합성, 자동 구멍 채움, 전체 프레임 이동·회전·보간을 사용하지 않았다.

### 대기 자세: 어두운 꼬리 뿌리 경계

- idle_a와 idle_c는 `(17,31)`, `(16,32)`, `(16,33)`에 각각 K를 찍었다.
  밝은 등 면 x17/y32–33을 안쪽에 남기고 그 밖으로 1px 경계를 이어 준다.
- idle_b는 기존 x16/y31–32 경계를 보존하고 `(17,30)`에 K 한 픽셀을 찍었다.
- 변경량은 각각 3, 1, 3픽셀이다. raised tail 주변의 의도한 빈 공간은 유지한다.
  발과 몸·얼굴은 그대로이며 idle_a의 바닥은 정확히 y60이다.

### skill_b: 입 안의 하나의 포효 뿌리

- 실제 변경 범위 x34–62/y26–46, 335픽셀.
- x37–39/y30과 x37–38/y32–33의 어두운 입 공간, x38–40/y29의 송곳니를
  나누었다. y30/x40의 어두운 r이 송곳니와 밝은 발광부 사이를 분리한다.
- 가장 밝은 공유 뿌리는 x40–41/y31의 FF다. 그 왼쪽의 x39/y31은 C,
  바깥 x42–43/y31은 O다. 작은 붉은 혀/뿌리에서 위·아래 갈래로 이어진다.
- 위 갈래는 입에서 x57–61/y15–25 방향으로 이어지고,
  아래 갈래는 x44–60/y33–46으로 길고 낮게 펼쳐진다.
  길이·끝 모양이 다른 두 갈래만 남겨 겹치는 추가 꺾쇠를 없앴다.
- x34–38/y35–37의 넓은 O/C 수평 목털 연결을 줄이고 K 아래턱 경계를 찍었다.
  붉은 목털은 입 아래에 남으며 포효의 밝은 뿌리와 별도로 읽힌다.
- 준비 skill_a, 닫힌 턱과 세 잔기 덩어리의 skill_c는 보존했다.

### sleep_a/b: 엉덩이·옆구리·말린 꼬리 분리

- 실제 변경 범위 x5–32/y33–59. 변경량은 sleep_a 366, sleep_b 362픽셀.
- 등에서 발끝까지 이어지던 긴 대각선 L/M 광택을 끊었다. 엉덩이의 짧고 넓은
  윗빛은 x9–21/y34–38, 중간은 B 기본 털 면으로 직접 찍었다.
- x25–26/y35–38에서 시작하는 S 그림자 경계가 x23–24/y40–42,
  x20–21/y44–45, x16–18/y47–48로 굽어 엉덩이와 오른쪽 옆구리를 나눈다.
  이 경계는 불투명한 털 그림자이며 투명 홈이 아니다.
- x8–21/y49–52에 접힌 뒷발/발목의 면과 짧은 발끝을 넣었다.
  위 엉덩이 면과 이어지고, 꼬리의 아래 경계와 구분한다.
- x3–27/y50–59의 꼬리는 배 밑을 돌아 오른쪽 위로 말린다.
  안쪽의 S 경계와 B/M 털 면, x21–26/y53–56의 끝 군집을 직접 찍었다.
  바닥 전체를 밝은 테두리로 두르던 면을 줄였다.
- 두 프레임은 같은 엉덩이·뒷발·꼬리 배열을 사용한다. 기존 y27–32의 작은
  등 호흡과 오른쪽 가슴 면 차이는 유지한다. 본체 전체를 움직이지 않았다.
- x37–38/y42의 짧은 K 닫힌 눈꺼풀, 주변 얼굴색, 코, 귀,
  x29–42/y51–59의 접힌 앞다리/두 앞발, y60 접지선은 유지했다.

## 보존과 실제 그림 확인

수정 직전 18격자·팔레트·AUTHORING/TIMING·실제 파일 해시는
`history/before-roar-sleep-notch-repair/`에 보존했다. 이전 교정 원본과 보조 코드도 유지했다.

현재 PNG와 8GIF는 `render.py`로 리터럴 격자를 그대로 디코드해 만들었다.
GIF의 각 프레임을 다시 읽어 원본 RGBA 및 시간표의 hold와 비교했다.
`preview/gif-readback.json`은 실제 파일의 프레임 수·순서·시간 읽기 결과다.
현재 원본의 실제 로컬 해시는 `preview/source-sha256.json`이며 검수/승인 binding이 아니다.

다음 실제 PNG를 열어 관찰했다.

- `preview/roar-sleep-repair.png`: 전후 입/수면, 각 밝은·어두운·체커 배경,
  native 1배와 최근접 3배. 목털과 포효 뿌리가 분리되고, 수면의 굽은 엉덩이
  경계·꼬리 말림·작은 발이 읽히는지 확인했다. 닫힌 눈은 검은 코와 분리되어 있다.
- `preview/idle-notch-repair.png`: 대기 세 자세의 같은 전후/세 배경/두 크기.
  밝은 등 면 밖의 어두운 경계와 남겨 둔 꼬리 주변 빈 공간을 확인했다.
- `preview/sheet-native.png`, `sheet-light.png`, `sheet-dark.png`, `sheet-checker.png`:
  18자세의 전체 윤곽·관절·투명 공간을 확인했다.
- `preview/gif-basic-contact.png`, `gif-actions-contact.png`: 실제 8GIF를 디코드한
  연속 프레임을 열어 순서와 프레임 간 차이를 확인했다. 수면의 얼굴·앞발·꼬리는
  고정되고 등과 가슴에서 숨이 바뀐다. 실시간 재생/게임 전투 확인과는 구별한다.

`preview/roar-sleep-notch-readback.json`에 변경 좌표, 나머지 12자세/팔레트 보존,
64×64·유효 팔레트·투명 테두리·최하단 y≤60을 기록했다.
`preview/source-facts.json`은 서로 다른 18프레임, 16색, alpha 0/255,
idle_a 바닥 y60, 8GIF를 기록한다. 이는 파일 사실이며 미감 통과 판정이 아니다.

## 남은 시각적 한계와 검수 상태

- 수면은 압축된 큰 엉덩이의 웅크림이다. 꼬리 안쪽과 뒷발이 1배에서 작은 군집이며,
  어두운 배경에서 S/K 그림자 대비가 약하다. 새 독립 검수에서 몸/꼬리 분리를 판단해야 한다.
- 포효는 두 직선에 가까운 각진 털빛 갈래로 남는다. 수정 목적은 원점과 아래턱을
  명확히 하는 것이며, 짧은 160ms 발동에서의 인상은 재생/독립 검수 대상이다.
- 기존 준비→돌격→물기의 큰 자세 차이와 skill_b→skill_c의 몸 회수 차이는 보존했다.
  실제 게임 접촉·이동 거리·스킬 적용·재생 속도는 확인하지 않았다.
- 테스트/게이트나 별도 독립 검수자를 호출하지 않았다. 하네스의 새 검수가 남아 있다.
  이 후보나 50종 전체의 통과, 사용자 승인, 검수 모델/실행 provenance를 선언하지 않는다.
