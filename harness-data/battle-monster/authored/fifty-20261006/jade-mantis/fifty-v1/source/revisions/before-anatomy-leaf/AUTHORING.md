# 옥날사마귀 — 공격·옥엽절 연결 교정

## 범위와 원안

이번 교정은 `poses/attack.pxgrid`, `actions/skill_b.pxgrid`, `actions/skill_c.pxgrid`의 리터럴 픽셀만 바꿨다. 나머지 15자세와 기존 15색 팔레트는 직전 원안과 바이트 단위로 같다. 머리·눈·목·잎날개·복부의 큰 면과 지지다리·접지를 보존했다. 독·기절·수면의 좋은 원안도 유지했다. 총 18개 완전한 64×64 ASCII 격자이며 각 자세는 서로 다르다.

직전 원안 18격자, 팔레트와 문서·교정 코드는 `revisions/before-scissors/`에 보존했다. 더 이른 저작 원본은 기존 `original/`에 남아 있다. 모든 쓰기는 이 후보의 `source/` 안에서만 수행했다.

첨부 사마귀 자세표와 자체 검객 참고 이미지를 실제로 열어 관찰했다. 사마귀의 삼각 머리, 두 어두운 눈, 긴 목, 큰 접힌 잎날개와 가는 지지발을 기준으로 삼았다. 검객은 native 몸집과 명암 덩어리 관찰에만 사용했다. 참고 픽셀의 추출·추적·리샘플링·재배포는 하지 않았다.

## 직접 선택한 수정 — 0부터 세는 좌표

### attack: 마름모 고리 대신 두 날의 가위 베기

- 위 앞다리는 어깨 약 (33,32)에서 팔꿈치 약 (44,29)로 이어지고, 내려오는 날은 x=47..62, y=30..36에 있다. 오른쪽 끝은 (62,35), 바로 안쪽 밝은 날끝은 (61,35)이다.
- 아래 앞다리는 어깨 약 (31,35)에서 아래 팔꿈치 약 (40,41)로 이어진다. 넓은 비취 날은 (41,38) 부근부터 위로 휘며 (58..61,29)/(61,28)의 다른 끝을 만든다.
- 교차부 (49,32)/(50,32), (50,33)/(51,33)에 짧은 `o/s` 겹침 경계를 직접 골랐다. 두 날의 넓은 `l/j/g` 면은 이 경계 양쪽에서 각자의 팔꿈치로 이어진다. 오른쪽 끝 사이의 빈 공간은 유지하고, 원안의 합쳐진 마름모 외곽은 제거했다.
- 첫 수정 PNG를 보고 아래로 남은 세 번째 끝처럼 보이는 x=58..61, y=37..38을 지웠다. y=34..36의 내려오는 날 면도 개별 문자열로 다시 골라 두 끝만 남겼다.

### skill_b: 바깥 관절이 아닌 실제 날끝에서 발사

- 위 낫은 x=40..54, y=23..28의 연결된 비취 날로 다시 찍었다. 끝 (54,23)과 안쪽 밝은 (53,23)이 위 청록 갈래를 향한다. 첫 효과 픽셀 (55,23)은 날끝에 바로 붙는다. (55..58,22)/(57..60,21)을 지나 기존 (61,19)의 가는 끝으로 이어진다.
- 아래 낫의 넓은 날은 x=40..54, y=35..39에 있다. 휜 받침과 밝은 등, 어두운 아랫날을 구별했다. 실제 끝 (54,36) 바로 옆 (55,36)에 청록 발사 뿌리를 두고 (56..59,37)/(59..62,38)로 갈라지는 짧은 잎칼날을 찍었다.
- 두 낫 뒤의 가는 관절을 날의 대용으로 쓰던 연장을 제거했다. 목과 어깨에서 비취색 앞다리·날끝까지 실제 픽셀이 연속된다. 청록은 distal 날끝 바깥에서 시작한다.

### skill_c: 가슴으로 접는 낫과 잔엽 회수

- 위 팔은 어깨에서 약 (46,30)의 가까운 팔꿈치로 이어지고, x=40..47, y=23..27의 낫은 목 옆으로 되접힌다. 안쪽 날끝 (41,26)에 (39,26)/(40,26)의 `c/w` 잔엽이 붙는다.
- 아래 팔은 가슴에서 약 (40,40)의 짧은 팔꿈치로 돌아온다. x=35..42, y=35..41의 날은 위·안쪽으로 접었다. 첫 잔엽 (35,34)/(36,34)은 되접힌 날의 (35..37,35)에 붙는다.
- 아래 낫 내부의 (38,38)/(37..38,39) 빈 공간은 굽힌 관절 사이의 의도한 틈이다. 둥근 주먹처럼 읽히던 첫 수정에서 이 부위를 직접 다시 골랐다.
- 외부 잔엽은 위 (53..54,24)/(51..52,25), 아래 (52..53,36)/(50..51,37)의 작은 끊어진 조각이다. 원안의 넓게 열린 낫과 그 아래에 남은 x=31..45, y=43..45의 옛 날 조각을 지웠다. 지지다리 픽셀은 보존했다.

## 원본·저작 보조 코드

`scissors_revision.py`는 프레임·행·열·리터럴 ASCII 문자열로 지울 픽셀과 찍을 픽셀을 명시한다. 도형·선 래스터화, 수식 본체/음영, 전체 프레임 이동·회전·보간, 자동 구멍 채우기를 하지 않는다. 출력 격자는 매번 전체 64행·64열이다.

`author_pixels.py` → `repair_pixels.py` → `scissors_revision.py`가 보존된 초기 격자에서 현재 교정으로 이어지는 저작 경로다. `render_pixels.py`와 `render_revision_inspection.py`는 격자를 읽어 PNG/GIF와 표시용 확대·라벨만 만든다. 확대는 진단 표시 전용이고 원본과 GIF는 64px이다.

직전 원안과 다른 픽셀 수: attack 139, skill_b 144, skill_c 263. 이것은 파일 차이 수이며 미감 평가나 승인 근거가 아니다.

## 실제 그림 확인과 저장 파일

- 수정 전 참고 이미지와 기존 자세 확대를 열었다. 수정 후 밝은·어두운·체커 배경의 전체 자세표와 상세도를 열어 팔꿈치, 날끝, 의도한 틈과 접지 위치를 살폈다.
- 최종 `preview/revision-inspection.png`를 실제로 열어 세 수정 자세를 각 배경의 1배와 최근접 3배에서 확인했다. 전체 자세표의 native 칸이 마지막 줄에서 잘리던 진단 배치를 고쳐 모든 18자세가 완전히 보이게 했다.
- `preview/motions-readback.png`는 저장된 8GIF를 실제 디코드한 연속 프레임이다. 이 그림을 열어 준비→전진→교차→회수, 기술 모음→발사→접힘과 상태 변화 사이의 연결을 확인했다. 원래의 지지발 변화와 목/몸의 기울기는 유지했다.
- `preview/`에는 18 native PNG, 전체 투명 시트, 세 배경 자세표, 8GIF, HTML 보기와 실제 GIF 디코드 기록이 있다. `source-readback.json`에는 실제 원본 SHA-256, 크기·알파·접지·차이 수를 기록한다. 해시나 모델/검수 결과를 임의로 만들지 않았다.
- 18격자는 모두 64×64, 기호는 기존 팔레트와 점만 사용한다. 팔레트 15색, PNG 알파 0/255, 1px 투명 테두리, 모든 자세 최저 잉크 y=60이며 idle_a 발도 정확히 y=60이다. 저장된 GIF 색·알파·노출 시간을 원본과 다시 읽어 대조했다.

## 남은 시각적 한계와 검수 범위

아주 어두운 배경에서 얇은 먼 지지다리와 더듬이의 가장 어두운 윤곽은 여전히 대비가 낮다. 기존 팔레트·좋은 자세 보존 범위에서 유지했다. 64px 교차 경계와 회수 잔엽은 작은 클러스터라 실제 전투 표시 배율과 배경에서 가독성을 다시 살펴야 한다. 발사는 한 cast 프레임이므로 비행 경로 자체를 중간 프레임으로 입증하지 않는다.

실제 게임 전투의 피해 접촉, 실시간 재생 체감과 엔진 설치는 이 후보 교정에서 확인하지 않았다. 연속 프레임 그림과 GIF 디코드 대조는 그 검증을 대신하지 않는다. 별도 검수자를 호출하거나 검수 결과·사용자 선택을 수정하지 않았다. 이 결과는 하네스의 독립 검수와 사용자 판단을 받을 교정 후보이며 통과/승인 선언이 아니다. 테스트·게이트는 실행하지 않았다.
