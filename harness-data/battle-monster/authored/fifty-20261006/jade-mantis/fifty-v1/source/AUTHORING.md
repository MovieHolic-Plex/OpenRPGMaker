# 옥날사마귀 — 피격 해부·잎 칼날·지지 다리 교정

## 범위·참고·원안 보존

이 후보의 `source/` 안에서만 작업했다. 기존 18자세의 정체성, 오른쪽을 보는 삼각 머리와 두 검은 눈, 긴 목, 어깨, 큰 접힌 잎날개, 준비→전진→가위 베기→회수와 상태별 본체 배열을 유지했다. 기존 15색 `palette.json`은 그대로다. 새 종이나 다른 후보를 복제하지 않았다.

첨부 `reference.png`와 `references/human-size.png`를 실제로 열었다. 사마귀의 해부와 밝은 날개 면을 관찰했고, 검객은 얼굴·native 몸집 비교에만 사용했다. 참고 이미지는 추출·추적·재배포하지 않았다.

수정 직전의 전체 18격자, 팔레트, AUTHORING/TIMING과 직전 교정 코드는 `revisions/before-anatomy-leaf/`에 보존했다. 더 이른 원안은 `original/`과 `revisions/before-scissors/`에 남아 있다. 쓰러짐 `dead`는 이번 직전 원안과 같다. 다른 17자세는 아래의 개별 클러스터 수정만 적용했다. 상태별 좋은 자세·효과는 보존했다.

## 직접 고른 픽셀 — 좌표는 0부터 센다

### 1. hit: 반동 때도 두 앞다리 보존

- 어깨 (30..33,32)에서 짧은 뒤쪽 앞다리를 (35..40,31)/(35..43,30)으로 연결했다. y=31의 `oljjgggsooo`, y=32의 `jjlljgso`는 연결과 겹침을 직접 정한 문자열이다.
- 뒤로 접힌 낫은 x=35..45, y=24..30이다. 윗마디의 (37..38,24), 왼쪽 위를 향한 `l/h/j` 날 면 (35..41,25..27), 오른쪽 굽은 관절 (41..45,27..29)과 아래 되접힘 면을 각각 찍었다.
- (39..40,28)/(38..40,29)의 빈 공간은 낫 안쪽의 의도한 틈이다. 자동으로 채우지 않았다. 기존 아래쪽 앞낫 x=40..50, y=35..43은 유지했다. 머리·눈·긴 목의 반동도 보존했다.

### 2. skill_b: 가는 빛 궤적을 짧은 두 잎 칼날로

- 위 비취 낫 끝 (54,23)과 첫 청록 (55,23)은 유지했다. 끝 (62,18)로 솟는 잎 몸체를 x=55..62, y=18..23에 직접 찍었다. y=20의 `tcwwlc`, y=21의 `cwwllct`는 넓은 청록/흰 중심과 비취 중심 면·그늘 가장자리다.
- 아래 낫 끝 (54,36)과 발사 시작 (55,36)도 유지했다. 아래 잎은 x=55..62, y=35..41에서 오른쪽 아래 끝 (62,41)로 접힌다. y=36의 `ccwwct`, y=37의 `cwwllct`, y=38의 `.tcwllc`로 넓은 몸체를 찍고 y=39..41을 다른 길이의 문자열로 좁혔다.
- 두 잎은 최대 가로 7px의 중심 면을 갖고, 위는 길게 상승하며 아래는 짧고 넓게 하강한다. 두 발사체를 같은 궤적·원 오라로 만들지 않았다. 앞다리, 팔꿈치, 실제 날까지의 기존 연결은 유지했다.
- 첫 수정 확대에서 여전히 얇은 굽은 띠처럼 보이는 끝을 확인해, 위 x=57..62,y=19..22와 아래 x=55..62,y=35..40을 다시 직접 골랐다. 최종 그림을 다시 열었다.

### 3. 지지 다리: 왼쪽 위 중간 밝기 면

- idle_a의 가는 뒤 지지다리 (18..21,49..57)에 `jg`/`jj`를 짧게 찍었다. 지적된 (20,52)은 `j`, (21,52)은 `g`다. 오른쪽 다리의 (28..32,51..57)은 기존 `g/j` 면을 `j/j`로 보강했다. (30,54)은 이제 `j`다.
- 왼쪽 앞 지지다리의 무릎 (8..10,51..52)과 발목 (9..12,54..58)에 기존 녹색을 중간 밝기의 `j`로 바꿨다. 어두운 외곽과 바닥 발은 보존했다. 넓은 날개는 `l/h`가 가장 밝고 가는 다리는 `j/g`이므로 광원·명도 관계를 유지한다.
- idle_b/c와 같은 다리가 보이는 windup/move/attack/recover/hit, skill_a/b/c, poison_a/b, stun_a/b도 각 자세의 실제 좌표를 따로 지정했다. 코드로 다리나 본체를 이동·회전하거나 픽셀 변경을 전파하지 않았다.
- sleep_a/b는 웅크린 기존 다리의 x=9..20,y=55..59 및 x=30..34,y=56..59만 짧게 보강했다. 닫힌 눈, 낮은 낫과 숨 변화는 유지했다. dead는 넓게 누운 별개 본체를 보존했다.

## 원본과 보조 코드

`anatomy_leaf_revision.py`에는 프레임마다 `(y,x,ASCII 문자열)`로 직접 고른 변경이 모두 남아 있다. 이 코드는 보존한 직전 격자에 명시된 문자열만 적용해 전체 64행을 쓴다. 최종 납품 원본은 `poses/`의 기본 9격자와 `actions/`의 추가 9격자다. 도형/선 래스터화, 수식 음영, 프레임 전체 변형, 자동 구멍 채우기, 생성 이미지는 사용하지 않았다.

`author_pixels.py`, `repair_pixels.py`, `scissors_revision.py`는 이전 저작 기록이다. 현재 교정 재현은 `anatomy_leaf_revision.py`를 쓴다. `render_pixels.py`, `render_revision_inspection.py`, `render_anatomy_leaf_details.py`는 원본 읽기·PNG/GIF 저장과 진단용 최근접 확대/라벨만 수행한다. native 원본과 GIF는 64px이다.

## 실제 그림 확인·파일 재읽기

- 수정 전 참고 이미지, hit native PNG, idle의 밝은/어두운/체커 표시를 열었다. 수정 후 `preview/revision-inspection.png`에서 idle_a/hit/skill_b를 세 배경의 native 1x와 최근접 3x로 실제로 열었다. `preview/anatomy-leaf-details.png`에서 피격 낫 내부와 두 잎 중심 면을 크게 살폈다.
- `preview/contact-light.png`, `contact-dark.png`, `contact-checker.png`에는 전체 18자세가 있다. 최종 세 시트를 열어 밝은 다리 면, 팔/낫 연결, 원치 않은 투명 단절, 상태 자세를 확인했다. 의도한 다리 사이·낫 내부 빈 공간은 유지했다.
- 8GIF를 원본 팔레트로 다시 만들고 저장 파일을 실제 디코드했다. `preview/motions-readback.png`의 연속 프레임을 열어 피격→회복, 준비→전진→교차→회수, 기술→잔엽 회수와 상태 쌍의 배열 변화를 확인했다. 원안의 본체 움직임은 유지했고 새 다리 명도 면이 같은 관절을 따른다.
- 실제 재읽기: 18개 모두 서로 다른 64×64 완전 ASCII 격자, 팔레트 15색, PNG 알파 0/255, 1px 투명 테두리, 모든 최저 잉크 y=60, idle_a 발은 정확히 y=60이다. 저장 GIF의 보이는 RGB·알파·노출 시간은 원본/시간표와 일치했다.
- 실제 원본 해시·파일 정보는 `preview/source-readback.json`, 직전 원안 대비 변경 수는 `preview/anatomy-leaf-changes.json`, GIF 디코드 결과는 `preview/render-notes.json`이다. 해시·모델 출처·판정을 만들거나 승인 근거로 사용하지 않았다.

## 남은 시각적 한계·판정 범위

가장 먼 오른쪽 지지다리와 더듬이의 어두운 외곽은 아주 어두운 배경에서 여전히 약하다. 두 잎의 폭은 셀 오른쪽 경계 안에서 제한되며 native에서 작은 짧은 칼날로 보인다. 피격 때 뒤로 접힌 낫도 작고 목/어깨에 가까워 실전 배율에서 겹침의 가독성을 다시 봐야 한다.

GIF 디코드 연속 시트는 실시간 전투 재생·대시 속도·피해 접촉·투사체 비행 확인을 대신하지 않는다. 이 작업에서 엔진 설치나 게임 전투는 수행하지 않았다. 별도 검수자를 호출하지 않았고 검수 결과·ledger·사용자 선택을 편집하지 않았다. 이 결과는 하네스의 독립 검수와 사용자 판단을 기다리는 교정 후보다. 통과 또는 사용자 승인을 선언하지 않는다. 테스트·게이트는 실행하지 않았다.
