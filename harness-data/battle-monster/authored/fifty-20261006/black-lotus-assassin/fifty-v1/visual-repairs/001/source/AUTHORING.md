# 흑련자객 — literal native64 candidate

## 범위와 상태

이 후보의 `source/` 안에서만 저작했다. 기본 9자세, 추가 9자세,
18색 팔레트, native PNG, 8 GIF와 저작 보조 원본을 보존한다.
프로젝트/저장소 코드/brief/ledger/다른 후보는 수정하지 않았다.
독립 검수자를 호출하지 않았다. 이 문서는 저작·자체 관찰 기록이며,
하네스의 독립 검수 결과나 사용자 승인 기록이 아니다.

## 참고 관찰

첨부 `human-size.png`를 실제로 열었다. 작은 눈 위 눈썹, 눈 앞의 볼 여유,
목에서 어깨로 이어지는 피부/옷깃, 잡은 손에 붙은 무기와 두 신발을 관찰했다.
그림의 픽셀·팔레트를 추출하거나 추적/재표본화/복제하지 않았고 참고 그림을
이 source에 복사하지 않았다. 검객의 갓/긴 검 대신 묶은 검은 머리,
남청 복면, 먹색 무복, 자주 띠와 짧은 단검을 새로 저작했다.

## 원본과 저작 방식

- 정본 저작 그림: `palette.json`, `poses/*.pxgrid`, `actions/*.pxgrid`.
- 모든 최종 pxgrid는 64행 × 64 ASCII 문자다. `.`은 투명이며 팔레트에 없다.
- `author_rows.py`는 직접 선택한 ASCII 행과 명시한 위치를 보존한다.
  빈 64×64 격자에 그 행의 잉크를 쓰고 투명 여백을 남길 뿐이다.
  효과/가드 손 보완 블록의 `.`은 기존 잉크를 삭제하지 않는 투명이다.
- `author_rows_first_pass.txt`는 자체 관찰 교정 전 18자세 저작 코드의 사본이다.
  첫 초안의 바닥 초과와 짧은 기술 연결 문제도 원문 그대로 보존한다.
- `render_preview.py`는 literal 격자를 디코딩하여 PNG/GIF와 진단 시트를 만든다.
  확대는 관찰판에서만 최근접으로 한다. 납품 프레임은 native64다.
- 원/다각형/선 마스크, 수식 본체/명암, 이미지 생성, 회전/전체 프레임 이동,
  보간, 자동 구멍 채우기, 팔레트 변환으로 그림을 만들지 않았다.
- 실행: 후보 폴더에서 `python source/author_rows.py`,
  이어서 `python source/render_preview.py`.
  저장소 테스트/게이트는 실행하지 않았다.

## 본체와 재질

대기 본체는 y=8..60, 높이 53px다. 주 머리 덩어리는 약 20px 폭이고,
피부 면은 머리 오른쪽에 12~14px 폭으로 둔다. 검은 눈은 작은 눈썹과
한 픽셀 눈동자로 나누고 흰자를 넓히지 않았다. 복면은 모든 18자세에 남겼다.
목의 S/F/P 피부 군집에서 남청 옷깃과 두 어깨로 이어진다.
발목 띠는 M/T/N, 신발은 H/I와 O 경계로 바지와 구별했다.

| 재질 | 문자 | 실제 선택한 면 |
|---|---|---|
| 윤곽 | O | 몸의 바깥 경계, 눈과 짧은 겹침 경계 |
| 머리/신발 | H I J | 검은 큰 면, 왼쪽 위의 짧고 굽은 반사 |
| 무복 | C B L | 넓은 먹청 기본면, 겹침 그림자, 위팔/허벅지 밝은 면 |
| 복면/발목 띠 | N M T | 남청 천 면, 위쪽 접힌 모서리 |
| 피부 | S F P | 목/손목/손바닥/볼의 실제 부피 |
| 허리띠/흑련/독기 | V R A | 자주 천, 세 갈래 칼기와 별도 둥근 독기 |
| 단검/기절 별 | E W | 짧은 은색 날과 밝은 날 끝, 직접 찍은 별 |

광원은 왼쪽 위다. 천의 빛 면은 금속보다 어둡고 넓게,
금속은 짧은 E/W 중심축으로 찍었다. 머리의 검은 넓은 면과 무복을 다른
색 덩어리로 나눴다. 각 자세에서 어깨/위팔/팔꿈치/소매/손목 경계를 고른다.

## 자세별 저작

| 자세 | 저작 내용 |
|---|---|
| idle_a/b/c | 같은 신원·얼굴·접지. 가슴 면, 머리 끝, 파지와 단검 각도의 작은 변화 |
| windup | 머리를 낮추고 같은 오른쪽 단검 팔을 가슴 앞에서 뒤 허리로 접음. 반대 손은 가드 |
| move | 낮게 내딛으며 뒤 다리를 밀고, 앞 허벅지/무릎을 굽힘. 단검은 아직 뒤쪽 |
| attack | 오른쪽 어깨·위팔·팔꿈치·아래팔·소매·손을 앞으로 펴고 은단검으로 찌름 |
| recover | 앞 무릎을 펴며 어깨/단검을 몸 가까이 회수. 뒤 다리는 아직 대기보다 벌어짐 |
| hit | 눈썹/눈의 긴장, 기울어진 어깨, 벌어진 보조 팔과 떨어진 단검 손 |
| dead | 낮은 수평 몸통, 접힌 두 다리/발, 피부 목, 닫힌 눈과 복면. 손 옆 단검 |
| skill_a | 접힌 오른쪽 팔의 단검 날 위에 자주 핵을 모음 |
| skill_b | 오른팔을 전진시키고 실제 날 끝에서 길이가 다른 세 연꽃잎 칼기를 펼침 |
| skill_c | 무기/어깨를 아래로 회수하면서 두 어둔 자주 파편을 분리해 남김 |
| poison_a/b | 턱을 받친 보조 손, 굽은 무릎, 내려간 단검, 직접 새로 찍은 위치/크기의 독기 방울 |
| stun_a/b | 낮은 머리, 내려간 어깨·양팔·무기. 큰 별과 작은 별의 위치가 서로 달라짐 |
| sleep_a/b | 앉아 접은 두 다리, 내려놓은 단검, 닫힌 눈. 가슴 빛 면과 묶은 머리 끝의 작은 숨 변화 |

## 실제 관찰과 좌표 교정

좌표는 0부터 센다. 자동 연결 검사로 잉크를 추가하지 않았다.

1. 기본 idle_a를 `idle-detail.png` 최근접 8배로 열어 얼굴/목/옷깃/
   어깨/파지/신발을 먼저 관찰했다. 이후 18자세를 실제 1배와 3배가 함께 있는
   `contact-light.png`, `contact-dark.png`, `contact-checker.png`에서 열었다.
2. 준비/전진 초안의 팔이 뒤쪽 어깨에서 뻗은 듯 읽혀, windup y=33..43과
   move y=36..44의 오른쪽 어깨→가슴 앞→접힌 팔꿈치→뒤 파지를 실제 행으로
   다시 저작했다. 반대 가드 손은 windup x=28..33/y=39..41,
   move x=34..39/y=41..43에 각각 별도로 찍었다. 다른 자세로 자동 전파하지 않았다.
3. attack의 앞 발목/신발, skill_a의 허벅지, skill_c의 뒤 무릎,
   dead의 볼/목 겹침 행을 각각 압축하여 낮은 잉크가 y=61로 내려간 초안을 교정했다.
   최종 18자세 모두 실제 신발/앉은 몸/쓰러진 몸이 y=60에 닿는다.
4. 기술 초안에서 효과의 투명 블록이 단검 일부를 지운 것을 발견했다.
   literal 블록의 투명 처리만 정리하고, 기술 칼기를 새 행으로 다시 찍었다.
   최종 skill_b는 파지 x=43..46/y=38..39, 은날 x=47..51/y=38..39,
   밝은 발원점 (50,37)이 이어진다. 손에서 직접 오라가 나오게 두지 않았다.
5. skill_b의 중간 꽃잎 y=31..32 끝이 x=63에 닿는 초안을 실제 끝 군집으로
   줄여 x<=62에 보존했다. 위 꽃잎 끝은 (56,20), 중간 끝은 x=62 근처,
   아래 꽃잎 끝은 x=57..58/y=46이다. 세 끝 사이의 틈은 남겼다.
6. sleep_a와 sleep_b의 닫힌 눈은 각각 (31..32,32), (36..37,32)의
   두 짧은 O 군집이다. 그 위/아래를 피부로 저작하여 평상시 눈동자를 재사용하지 않았다.
   코/볼은 F/P로 남겨 눈과 검은 코가 합쳐지지 않는다.
7. 생성한 8 GIF 파일을 열고 GIF에서 다시 읽은 전체 프레임의
   `decoded-*.png`를 열어 같은 팔/파지, 무릎, 수면 눈과 발을 순서대로 관찰했다.
   저장된 GIF의 RGBA/노출시간을 원본과 대조한 결과는 `pixel-report.json`에 있다.
   이 대조는 파일 인코딩 자료이며 예술적 판정은 아니다.

## 결과 보기

## 남은 시각적 한계

대기/수면의 숨 변화는 의도적으로 작다. native64에서는 셔츠의 면 변화가 확대보다
약하게 읽힌다. 검은 머리/신발의 가장 어두운 바깥 픽셀은 매우 어두운 배경에서
대비가 낮지만 안쪽 I/J와 천 L 면으로 실루엣을 나눴다. 독기 방울은 팔레트 일관성을
위해 자주색이며 녹색 독 효과는 아니다. 공격의 접촉은 원본 정지 자세로 저작했고,
실제 게임의 피해 판정/투사체/카메라와 결합한 결과는 이 source 범위에서 확인하지 않았다.
현재 독립 검수/사용자 선택은 하네스가 맡는다.
