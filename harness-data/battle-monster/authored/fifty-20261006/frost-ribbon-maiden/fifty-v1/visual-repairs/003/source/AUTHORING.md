### 직접 선택한 좌표와 군집

좌표는 좌상단 (0,0) 기준이다. `repair_anatomy.py`의 `PATCHES`와 `REFINEMENTS`는 자세마다 따로 선택한 `y x pixels` 리터럴이다. 수정 직전 다섯 원본은 `checkpoints/anatomy-before/`에 보존했다. 첫 저작 보조 코드 `author_pixels.py`는 기존 커프·결정 교정 뒤 이 새 리터럴을 적용하도록 연결했다. 전체 몸 이동·회전·보간, 본체 도형, 음영 공식, 다른 자세로의 좌표 전파 또는 자동 연결/구멍 채우기를 사용하지 않았다.

### PNG를 연 뒤의 추가 직접 교정

첫 수정 PNG에서 이동 앞발의 연결이 약해 보이고, 공격의 y=78–85 기존 아래 치마가 새 허리 아래에서 각진 돌출로 남아 있었다. `REFINEMENTS`에 이동 (44–58,77–84)의 치마/발목 접점과 공격 (44–63,75–87)의 아래 주름·발목 문자열을 따로 기록해 다시 골랐다. 검사 결과를 이용해 자동으로 채운 것이 아니다. 최종 밝은/어두운/체커 비교 PNG에서 이 부분을 다시 열었다. 본체와 채찍 사이, 뒤 소매 아래의 의도한 빈 공간을 보존했다.

최종 실제 수정량은 이동 497픽셀, 공격 574픽셀, 회수 283픽셀, 기절 a 199픽셀, 기절 b 242픽셀이다. `preview/anatomy-diagnostics.json`은 수정 전후 실제 격자 해시와 변경 경계를 기록한다. 공격의 x=59–66, y=50–53 손/띠 뿌리, x≥65의 채찍 호, 기술 회수의 x≥70 얼음 파편은 수정 전후 같다. 이 진단은 모델 출처·미감 합격·사용자 승인 기록이 아니다.

### 이번에 실제 연 그림과 저장된 산출물

- 수정 다섯 장은 `preview/anatomy-before-after-1x.png`, `anatomy-before-after-3x.png`에서 세 배경의 수정 전후를 함께 열었다. 수정 과정의 첫 확대 확인판은 `anatomy-before-5x.png`, `anatomy-current-5x.png`다. 후자는 발/아래 치마 추가 교정 전 중간안이며 최종 비교는 `anatomy-before-after-*`를 따른다.

- 렌더러의 원본 재읽기에서 18개 서로 다른 96×96 ASCII, 18색, 알파 0/255, 투명 테두리, 최하단 y≤92, `idle_a` 발의 y=92를 확인했다. `source-diagnostics.json`은 현재 실제 격자/RGBA/PNG 해시다. 저장소 테스트/게이트는 실행하지 않았다.

### 남은 시각적 한계 / 판정 상태

허리의 큰 S자 변형은 줄였지만 바닥까지 내려오는 겹옷이 여전히 허벅지·무릎을 가린다. 이동의 앞발은 대기 기준보다 3픽셀 위에 있으며, 실제 hop 이동의 접지와 하중 타이밍은 게임에서 확인하지 않았다. 공격의 소매 아래 어두운 경계와 회수의 작은 손가락은 1배에서 미세하고 밝은 배경에서 청백 재질의 대비가 낮다. 기절의 머리/어깨 흔들림도 작으며 실제 재생에서 충분히 읽히는지는 새 독립 검수로 확인해야 한다. GIF를 재디코드해 정지 프레임 순서를 확인했으며 게임 실행 또는 실시간 GIF 재생 관찰을 완료했다고 주장하지 않는다.

이번 쓰기는 모두 이 후보 `source` 내부다. 별도 검수자 호출, 하네스 판정/ledger/brief 수정, 저장소·게임 정본·다른 후보 수정은 수행하지 않았다. 사용자 승인이나 검수 통과를 선언하지 않는다. 현재 원본은 하네스의 새 독립 검수 대상이다.

## 이번 소매·결정 교정 (2026-10-06)

이번 작업은 이미 존재하는 18자세의 한정 교정이다. 아래 첫 저작 기록은 이력을 위해 보존한다. 이번에 실제 격자가 바뀐 것은 `idle_a`, `idle_b`, `idle_c`, `skill_b` 네 장이다. 팔레트와 다른 14자세의 격자는 수정하지 않았다. 모든 쓰기는 이 후보의 `source` 안에서만 수행했다.

### 직접 고른 픽셀

좌표는 0부터 시작한다. `repair_pixels.py`에 자세별 독립 리터럴 패치를 저장했다. 수정 전 네 격자는 `checkpoints/cuff-crystals-before/`에 보존했다. `author_pixels.py`도 같은 리터럴 패치를 마지막에 적용하므로 나중에 첫 저작 보조 코드를 실행해 이번 교정이 사라지지 않는다.

- **대기 세 장의 커프–손바닥:** 각 자세에서 (54–55,54)에 `lc`, (53–55,55)에 `cln`, (53–55,56)에 `ocn`, (54–55,57)에 `oo`를 직접 선택했다. 실질 변경은 자세당 9픽셀이다. 밝은 천 `l`과 중간 천 `c`가 손의 기존 `f/n/t` 면에 겹쳐 비스듬한 손목으로 이어진다. 손 바깥쪽 x=60 이후의 띠 뿌리는 유지했다. 아래와 몸 사이의 의도한 투명 공간도 유지했다. 세 자세의 해당 위치를 각각 열어 확인했으며 한 자세를 변형해 다른 자세를 생성하지 않았다.
- **기술 접촉의 세 결정:** `skill_b`의 x=72–93, y=41–72 구역을 직접 고른 짧은 행들로 수정했다. 위의 긴 결정과 오른쪽의 짧은 사선 결정 사이에 (85–86,44), (85,45), (83–84,46), (82–84,47), (80–83,48)의 투명 홈을 남겼다. 공통 뿌리는 y=49–50에 이어진다. 사선 결정의 끝 아래는 투명하게 비워 아래 결정의 가는 연결 목과 구분했다.
- 위 결정의 x=83, y=33–40에는 기존 팔레트 `b`를 선택해 오른쪽 음영 면을 따로 읽히게 했다. 가운데 결정은 짧은 비스듬한 밝은 축과 `l/b/c` 끝면을, 아래 결정은 y=56–69의 넓은 쐐기 면과 아래·오른쪽 `c/b` 그림자를 별도로 찍었다. 기존 아래의 갈라진 두 꼬리 끝을 하나의 넓은 결정 끝으로 정리했다.
- 수정 PNG를 열었을 때 x=94의 이전 결정 외곽이 네 픽셀로 남아 있었다. (94,57), (94,58), (94,59), (94,62)를 각각 직접 지웠다. 현재 기술의 최우측 잉크는 x=93이고 x=94–95는 투명하다. 연결 검사로 메우거나 지운 결과가 아니다.
- `skill_b`의 실질 변경은 262픽셀이며 변경 경계는 x=76–94, y=33–72다. 몸·소매·손은 그대로이고 **x=62–70, y=49–53의 손–띠 뿌리**는 원본과 같다. 이 수치는 실제 수정 전후 격자를 읽어 계산한 진단이며 검수 판정이 아니다.

### 이번에 실제 연 자료

- 첨부 `reference.png`와 `references/human-size.png`를 먼저 열었다. 작은 우향 얼굴, 은백 머리/비녀, 두 소매와 파지를 관찰했으며 참고 픽셀을 추출·추적·복제하지 않았다.
- 최종 18자세의 밝은/어두운/체커 1배·최근접 3배 PNG를 열었다. 네 수정 자세는 `preview/repair-before-after-1x.png`, `repair-before-after-3x.png`에서 같은 배경의 수정 전후를 함께 열어 비교했다. 손의 연결, 세 결정 사이 홈, 아래 결정의 외곽과 투명 여백을 확인했다.
- 8개 GIF를 다시 저장하고 실제 GIF를 재디코드한 `gif-*-frames.png` 8장을 모두 열어 자세 순서를 살폈다. 대기 손목 면이 동일 구조로 유지되고 기술의 준비 핵 → 세 결정 → 파편 회수 순서가 보인다. 공격의 연결된 소매/채찍, 독·기절의 다른 군집, 수면 두 장의 닫힌 눈도 같이 확인했다. 실시간 애니메이션 재생이나 게임의 hop 이동을 확인했다는 의미는 아니다.
- 렌더러로 원본을 다시 읽어 18장의 서로 다른 96×96 ASCII, 18색, 알파 0/255, 투명 테두리, 최하단 y≤92와 `idle_a` 발의 y=92를 확인했다. 8개 GIF의 재디코드 픽셀·노출 시간도 원본과 일치했다. 저장소 테스트/게이트는 실행하지 않았다.
- `preview/repair-diagnostics.json`은 실제 변경 수·경계·손뿌리 유지 여부를 기록한다. `source-diagnostics.json`의 격자/RGBA/PNG 해시도 현재 파일에서 재계산했다. 모델 출처나 사용자 선택을 만들어 기록하지 않았다.

### 남은 시각적 문제와 검수 상태

커프와 세 결정은 이번 정지 PNG에서 더 분명하게 구분된다. 다만 가운데 결정은 작은 1배 군집이며 기술 최고점의 160ms 유지가 실제 전투에서 충분한지는 확인하지 않았다. 청백색 머리·옷·얼음의 밝은 배경 대비와 치마가 가린 다리의 체중 표현은 아래에 적은 기존 한계로 남는다. PNG의 자체 확인은 독립 검수 또는 사용자 승인으로 기록하지 않는다. 수정본은 하네스의 새 독립 검수 대상이며 별도 검수자를 호출하거나 검수 결과·ledger·brief를 수정하지 않았다.

- 보조 코드는 투명 캔버스 여백을 덧붙이고 지정한 행/좌표 문자열을 저장한다. 본체 도형, 음영 공식, 전체 프레임 이동·회전·보간, 자동 구멍 채우기, 이미지 생성은 사용하지 않았다.
- 참고 `human-size.png`를 직접 열어 작은 우향 얼굴, 성인 체형, 손과 무기의 연결을 관찰했다. 참고 픽셀을 추출하거나 원본 참고 이미지를 복사하지 않았다.

## 직접 저작한 구조

- 20–39행의 은백 머리와 작은 우향 얼굴, 40–44행의 목·겹옷깃을 먼저 저작했다. 청색 비녀는 머리 오른쪽에 붙는다. 평상시 눈은 좁은 검은 군집이며 코 앞에 얼굴색을 남겼다.
- 머리는 밝은 `w/h`와 차가운 `s` 면, 겹옷은 `w/l/c`와 넓은 `b/d` 그림자로 구분했다. 광원은 왼쪽 위다. 밝은 면을 무작위 점으로 채우지 않았다.
- 뒤 소매는 어깨에서 왼쪽 아래 팔꿈치로 내려가고 68–70행 손끝까지 접힌다. 앞 소매는 어깨에서 오른쪽 팔꿈치와 손목으로 이어진다. 두 소매의 길이와 명암 경계가 다르다.
- 발은 치맛자락 아래에 피부/신발의 밝은 윗면과 어두운 밑창을 따로 찍었다. 대기 기본 발의 최하단은 92행이다.
- `windup`은 손을 어깨로 당긴 접힌 팔, `move`는 뒤 지지발과 들어 올린 앞발, `attack`은 뻗은 소매·손과 전방 채찍, `recover`는 팔과 띠를 접어 회수한 배열이다. 앞발·치맛자락·머리·목은 각각 해당 자세의 행을 따로 선택했다.
- `hit`은 닫히듯 찡그린 눈, 낮고 비스듬한 어깨와 접힌 팔을 저작했다. `dead`는 별도 빈 캔버스에서 바닥의 치마·팔·목·감은 얼굴·늘어진 머리카락을 저작했다.
- `skill_a`는 앞 손에 각진 얼음 핵, 현재 `skill_b`는 띠 끝에 위의 길쭉한 결정/옆의 짧은 사선 결정/아래의 넓은 쐐기 결정, `skill_c`는 내려 접은 손과 깨진 불규칙 파편이다.
- 독은 턱을 짚은 손과 배를 감싼 소매, 입의 어두운 아픈 표정, 각기 다른 독 기포를 찍었다. 기절은 낮은 머리와 길게 처진 앞 소매·손·띠, 다른 위치의 별이다.
- 수면은 별도 앉은 본체와 접힌 두 발, 무릎의 옷 경계, 바닥으로 내려놓은 띠다. 두 수면 자세 모두 59행에 짧은 닫힌 눈꺼풀을 직접 찍고 평상시 눈 군집을 제거했다. 가슴·무릎 면의 작은 변화로 숨을 표현했다.

## 그림을 열어 확인하고 고친 부분

좌표는 0부터 시작한다. 자동 연결 검사는 진단으로만 읽었고 수정 좌표는 직접 골랐다.

1. 처음 대기 그림은 뒤 팔이 머리카락에 묻혔다. `idle_a`의 (19–33, 48–71)에 뒤 소매·팔꿈치·커프·손을 직접 추가했다.
2. `idle_b/c`의 초기 상체 행 교체가 뒤 소매 중간에 가로 삭제를 만들었다. 52–58행과 70–71행의 불필요한 전체 행 교체를 제거하고 실제 소매 면을 보존했다. 최종 대기 세 장을 함께 다시 열었다.
3. 기술 아래 결정의 58–61행이 오른쪽 투명 여백을 넘었다. 해당 가지의 끝과 면을 짧은 리터럴 문자열로 다시 골랐다. 현재 가장 오른쪽 잉크는 93열이고 94–95열은 투명이다.
4. `recover`의 (66–67,90)에 띠와 떨어진 2픽셀이 있었다. 두 픽셀을 지우고 (63–66,88), (63–65,89), (64,90)에 이어지는 접힌 끝을 찍었다.
5. 초기 `dead`는 하단 행의 머리 위치가 왼쪽으로 급격히 변해 얼굴이 긴 머리 띠처럼 읽혔다. 최종안에서는 72–92행에 머리를 따로 찍고, 78–92행에 몸·팔·목의 실제 문자열을 덧붙였다. 얼굴의 닫힌 눈은 (69–71,83), 목과 소매는 87–88행에서 만난다. 두 중간안을 보존했다.
6. `move/attack`의 머리와 목을 각각 다시 저작해 접촉 때 작은 전방 기울기를 추가했다. 전체 몸을 이동시킨 프레임은 아니다.
7. `attack`의 긴 띠 끝이 바닥의 추가 발처럼 보일 수 있었다. (65–72,78–84)에 위에서 접힌 실크 끝을 찍고 85–92행의 띠 끝만 직접 제거했다. 실제 앞·뒤 발은 유지했다.

## 확인 자료

- `preview`의 18개 native PNG와 밝은/어두운/체커의 1배·3배 시트를 실제 열었다. 최종 수정된 쓰러짐·공격은 GIF 재디코드 접촉 시트와 최종 밝은/체커 시트로 다시 확인했다.
- 8개 GIF를 원본 팔레트 그대로 인코딩했다. GIF에서 모든 프레임을 다시 읽어 native RGBA와 노출 시간이 같은지 확인하고 `gif-*-frames.png`를 열어 자세 순서와 튐을 살폈다. 보간된 중간 그림은 없다.
- 렌더러의 파일 진단은 18개 서로 다른 96×96 원본, 최대 18색 팔레트, 알파 0/255, 1픽셀 이상 투명 테두리, 최하단 92행, `idle_a`의 92행 접지를 확인했다. 이것은 미감 합격 판정이 아니다.
- `source-diagnostics.json`의 해시는 현재 실제 격자·native RGBA·PNG 파일을 읽어 계산한 값이다. 독립 검수나 사용자 선택 기록으로 쓰지 않는다.

## 남은 시각적 한계와 검수 상태

- 긴 겹옷이 넓게 덮어 허벅지·무릎의 피부 경계는 드러나지 않는다. 공격의 체중 이동은 치마 열림과 앞발/뒤발에서 읽어야 한다.
- 은백 머리와 청백 옷은 밝은 배경에서 색 차가 작다. 외곽과 어깨/뒤 소매의 어두운 경계로 분리했지만 실제 게임 배경에서의 대비는 아직 확인하지 않았다.
- 96px 안에 손과 눈을 작게 유지했다. 빠른 공격 120ms/기술 160ms 구간의 손가락·작은 결정 면은 확대보다 덜 또렷하다.
- 몸의 천 흐름은 과장된 곡선을 사용한다. 실제 전투의 이동 거리·피격 타이밍·게임 설치는 이 원본 동작 후보의 확인 범위에 포함되지 않는다.
- 현재 후보는 하네스 독립 검수와 사용자의 선택을 기다린다. 사용자 승인이나 검수 통과를 선언하지 않는다.
