# 뇌각기린 — 지정된 native 픽셀 보수

## 작업 범위와 보존

이번 변경과 출력은 모두 이 후보의 `source/` 안에 있다. 수정 직전의 18격자, 팔레트, 저작 코드와 문서는 `before-native-cluster-repair/`에 보존했다. 이전 저작 문자열과 보존 폴더도 유지했다. 저장소·게임 저장소·ledger·brief·다른 후보·검수 결과에는 쓰지 않았다.

첨부 현재 시트와 64px 검객 이미지를 실제로 열었다. 비취 사족의 긴 목, 두 귀, 푸른 갈기, 금뿔과 배판, 다리의 가까운/먼 겹침을 관찰했다. 검객은 얼굴·크기의 참고로만 보았다. 참고 픽셀을 추출·추적·복제하지 않았다.

현재 원본은 `poses/`의 기본 9자세와 `actions/`의 기술·상태 9자세, 총 18개의 완전한 128×128 ASCII 행이다. 기존 18색 팔레트와 지적되지 않은 자세를 유지했다. 추가 9자세도 이미 있는 리터럴 원본을 보존하면서 필요한 두 기술 자세와 기절 자세만 보수했다.

## 직접 선택한 변경

좌표는 0부터 시작한다. 아래 변경은 `native-cluster-repair-runs.txt`에 자세별 `(y, x, ASCII)` 문자열로 기록되어 있다.

| 자세 | 실제 변경 |
|---|---|
| attack: 뿔 | x105–126/y74–81에서 이마의 금색 밑동 → 넓은 금색 면 → 가늘어지는 끝을 직접 다시 찍었다. 예를 들어 y78/x105의 `OOwvvvvkkkkggOO.`와 y79/x105의 `OvvvkkkkggOO`는 금백 윗빛, 금 기본색, 황토 중간면, 갈색 밑면, 어두운 외곽을 만든다. y76/x112의 `OOOOOOwvvvvkgOO`는 오른쪽 끝으로 좁아지는 별도 군집이다. 가장 오른쪽 잉크는 x126이며 x127은 투명하다. 머리/목을 낮춘 기존 접촉 자세를 유지했다. |
| attack: 다리 | (85,111), (22,113)에 각각 `O`를 골라 대각선 관절의 두 단일 투명 점을 닫았다. 주변 어두운 윤곽을 잇고 다리 사이의 넓은 공간은 보존했다. |
| hit: 뒤다리 | (51,117), (53,118)에 각각 `O`를 골라 겹친 뒤다리/굽 내부의 단일 투명 점을 닫았다. |
| hit: 먼 앞굽 | y118/x86의 `ngkknnO`로 짧은 발목 금테를 찍고 y119–120/x87의 `OnrrnnnO`, `OnnnnnnO`로 회색 윗면과 짙은 굽 몸체를 만들었다. y121/x88의 `OOOOOO`는 짧은 밑바닥이다. 들린 발의 가장 낮은 윤곽은 y121로, 가까운 지지 굽의 y124와 구별된다. |
| dead: 엉덩이/갈기 | (24,94)는 갈기 경계의 `O`, (25,95)는 인접 비취 그림자의 `t`로 직접 닫았다. 내려온 몸과 접힌 다리 밑의 큰 빈 공간은 보존했다. |
| skill_b: 지지 굽 | (80,120)에 `O`를 골라 굽의 단일 투명 점을 닫았다. 실제 뿔 발원점과 번개 갈래 사이의 의도된 빈 공간은 유지했다. |
| skill_c: 목 | x69–88/y75–81의 비취/목 그림자/금 목판을 각 행의 별도 문자열로 다시 골랐다. 금판 오른쪽 경계는 y74–82에서 x85 → 86 → 87 → 87 → 86 → 85 → 83 → 82 → 81로 돌아온다. y77의 한 줄 역행과 인접한 큰 직각 단절을 함께 정리했다. 뿔 끝의 짧은 잔전류는 유지했다. |
| stun_a: 잔여 점 | (67,119)의 고립된 `O`를 `.`로 지웠다. 실제 앞/뒤 다리와 머리 위 금색 별은 유지했다. |

모든 변경은 직접 고른 짧은 ASCII 문자열 또는 단일 좌표다. 전체 프레임 이동·회전·보간, 도형 래스터화, 합성 음영, 생성 이미지, 자동 구멍 채우기나 다른 자세로의 좌표 자동 전파는 사용하지 않았다. 보조 코드는 선택된 문자열 적용과 격자 읽기·렌더링·진단 표시만 한다.

## 실제 PNG 확인과 후속 교정

첫 수정 후 전체 18자세를 밝은·어두운·체커 배경의 native 1배 PNG로 열었다. 수정한 6자세도 세 배경의 최근접 3배 PNG로 열었다. 공격 뿔의 금색 면/밑면, 작은 투명 점, 먼 앞굽, 쓰러짐의 갈기 경계와 기절 잔여 점을 보았다.

첫 목 수정은 y77만 이어 주변 금판의 급한 경계를 드러냈다. 따라서 y75–81을 행마다 직접 다시 골랐고, 최종 세 배경의 확대 PNG를 다시 열어 목판 곡선과 비취/그림자 면의 연결을 확인했다.

최종 전체 체커 확대와 18자세 수정 전후의 1배 PNG도 실제로 열었다. 다른 자세의 뿔·목·갈기·대각선 다리·굽을 함께 보았으며, 이번에 지적된 동일한 단일 투명 결손이나 고립 잔여 점은 추가로 식별하지 못했다. 의도된 다리 사이·접힌 발 사이·번개 분기의 빈 공간을 메우지 않았다.

8개 저장 GIF를 다시 디코딩한 1배 프레임판도 열어 준비 → 밀기 → 낮은 뿔 접촉 → 회수와 기술/상태 쌍을 비교했다. 이는 실제 GIF의 정지 프레임 비교이며 시간에 따른 재생 감각이나 게임 내 타격을 관찰한 것은 아니다.

## 원본과 출력

- `native-cluster-repair-runs.txt`: 이번 직접 좌표/문자열 선택 기록.
- `apply_native_repair.py`: 이 기록의 명시 문자열만 현재 격자에 적용한다.
- `author.py`: 기존 저작 기록 뒤에 이번 기록도 읽도록 추가했다. 이전 기록과 전체 리터럴 행을 보존한다.
- `render.py`: 원본 PNG, 투명 3×3 시트 둘, 8GIF, 저장 GIF의 재디코딩 판을 기록한다. 출력의 파일 해시는 실제 파일에서 계산된다.
- `native_repair_diagnostics.py`: 원본을 읽어 세 배경의 1배/3배/전후 비교 PNG를 기록한다. 그림을 수정하지 않는다.
- `previews/light-1x.png`, `dark-1x.png`, `checker-1x.png`: 현재 18자세의 native 판.
- `previews/native-repair-*-3x.png`: 수정한 6자세의 세 배경 확대.
- `previews/native-repair-comparison-*-1x.png`: 수정 직전과 현재 18자세 비교.
- `previews/battle-sheet.png`, `actions-sheet.png`: 현재 기본/추가 9자세의 투명 원본 시트.
- `previews/idle.gif`, `attack.gif`, `hit.gif`, `dead.gif`, `skill.gif`, `poison.gif`, `stun.gif`, `sleep.gif`: 현재 8동작.
- `previews/eight-gifs-decoded-1x.png`: 저장된 8GIF의 native 프레임판.
- `review.html`: 현재 PNG/GIF 비교용 페이지. 판정/승인 기록 기능은 없다.
- `before-native-cluster-repair/`: 이번 수정 전 원본과 이전 문서·코드. 이전 수리 진단 출력은 그 안의 `previews/`에 보존했다.

## 남은 시각적 한계

- 우향 실루엣은 측면 성격이 강하며 3/4 깊이는 겹친 다리와 작은 볼/어깨 면으로 표현된다.
- 공격 뿔은 낮아진 이마의 짧은 투영 길이를 따른다. 끝이 x126에 가까워, 실제 게임 표시에서 접촉 범위와 잘림을 확인해야 한다.
- 접촉 → 회수에서 목 높이 변화가 크다. GIF hold는 기존 값을 유지했고 실제 시간의 튐이나 전투 충돌은 확인하지 않았다.
- 수면 호흡과 idle의 변화는 native 1배에서 미세하다. 수면 두 자세의 짧은 감긴 눈과 접힌 발/꼬리는 유지했다.
- 밝은 배경에서 금백 번개/별의 대비가 약하고, 어두운 배경에서 먼 굽의 어두운 윤곽이 약하다.

테스트/게이트나 별도 검수자는 실행하지 않았다. 검수 판정·모델/저작자 기록·사용자 승인 상태를 만들거나 수정하지 않았다. 이번 결과는 새 독립 검수와 사용자의 판단을 위한 보수 후보다.
