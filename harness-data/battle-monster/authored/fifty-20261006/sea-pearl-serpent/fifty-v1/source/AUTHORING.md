# 해주영사 — 원본 저작 기록

## 이번 독립 지적에 따른 수정

첨부 현재 시트와 64px 검객 참고를 실제로 연 뒤, 전달받은 두 지적을 원본 격자에 직접 반영했다. 수정 대상은 `move`, `attack`, `recover` 세 자세다. 팔레트와 다른 15자세는 바이트 그대로 유지했다. 기존 기본 9자세와 추가 9자세가 모두 있으므로 새로운 상태 자세로 덮어쓰지 않았다.

| 원본 | 명시적으로 다시 찍은 위치와 구조 |
|---|---|
| move | y=102–124 하단 몸통. (58,111)을 포함한 닫힌 고리의 가로 연결을 지우고, 왼쪽 지지 굽음→넓은 바닥 몸통→오른쪽으로 풀려 올라가는 끝을 별도 literal 행으로 저작했다. 상단 코일의 중심 빈 공간은 남겼다. |
| attack | y=104–124 하단 몸통을 이동보다 길게 풀었다. 상단 코일 아래의 열린 통로, 두꺼운 청록 면, 금 배판의 하중 면과 바닥 접촉을 함께 유지했다. 몸통은 목과 연결된다. |
| recover | y=107–124 하단 코일. 길게 풀린 끝을 짧은 안쪽 굽음으로 모으되, 대기 고리로 완전히 닫히기 직전의 작은 열린 통로를 남겼다. 이동/공격의 좌표를 복사하거나 옮기지 않았다. |
| attack 턱 | x=70부터 y=62–72의 아래턱·혀·금 입술·어두운 외곽·이빨을 다시 골랐다. 기존 x≈97의 짧은 끝을 윗주둥이 끝에 가까운 긴 물기 끝으로 연장하고, 아래쪽은 단계적으로 가늘어지게 찍었다. (94,51)의 떠 있던 외곽 한 픽셀도 직접 지웠다. |

첫 수정 PNG에서는 풀린 끝이 너무 가늘고 금 배판이 작은 받침처럼 보였다. 실제 1배와 3배 그림에서 이를 확인한 뒤, 중간 몸통의 폭과 넓은 D/C 면, 연속된 G/H/I/J 배판을 새 행 문자열로 두 차례 보완했다. 자동 팽창이나 구멍 채우기를 사용하지 않았다. 최종 실루엣에서는 두 닫힌 고리에서 열린 하단 C형 몸통으로 풀리고, 공격에서 더 길게 뻗은 뒤 회수에서 모인다.

`original-before-repair/`에 수정 전 18개 격자와 팔레트, 저작 기록·시간표를 보존했다. `repair-clusters.py`와 `repair-clusters.json`은 이번에 직접 고른 x/y/ASCII 문자열 및 국소 지우기 기록이다. 생성하는 내용은 선택한 행 끝의 투명 여백뿐이다. 최종 128×128 전체 literal 행은 `poses/`와 `actions/`에 있다. 최종 원본과 저장한 수정 전 원본의 다른 픽셀 수는 move 1,271개, attack 1,326개, recover 545개다.

## 이번 이미지 확인

수정 세 자세의 어두운·밝은·체커 3배 PNG와 전체 18자세의 1배 세 배경 PNG를 실제로 열었다. 코일 중심과 열린 하단 통로는 의도한 투명 공간이다. 목/진주/몸통의 연결, 아래턱 끝, 배판의 하중 윤곽을 함께 보았다. 세 수정 자세의 불투명 본체는 각각 4방향으로 이어진 한 군집이며, 실제 몸통이 y=124에 닿는다. 이 읽기 전용 진단은 그림을 자동 보정하거나 미감 판정을 만들지 않는다. 결과는 `preview/repair-diagnostics.json`에 있다.

8개 GIF를 다시 만들고 실제 파일을 열었다. 이미지 도구가 시간에 따른 재생을 보여 주지 않으므로, 저장된 GIF를 다시 읽어 만든 8개 native 시간순 비교 PNG도 모두 열었다. 대기→준비→이동→물기→회수의 같은 머리·진주·코일 경로와 접지를 비교했다. 렌더러는 GIF를 재읽어 원본 RGBA 및 각 노출 시간을 확인한다. 현 원본의 실제 SHA256과 형식 자료는 `preview/render-report.json`에 남겼다. 테스트/게이트나 독립 검수자는 호출하지 않았다.

이번 수정에 대한 하네스의 새 독립 검수 및 사용자의 선택은 아직 기록되지 않았다. 이 문서는 수정·관찰 기록이며 통과나 승인을 선언하지 않는다.

## 범위와 참고

이 후보의 `source/` 안에 팔레트, 기본 9자세, 추가 9자세, 저작 보조 코드, PNG와 8개 GIF를 저장했다. 실제 독립 검수는 이 저작 세션에서 호출하지 않았다. 이 문서는 작가의 확인 기록이며 하네스 판정이나 사용자 선택 기록이 아니다.

첨부 `human-size.png`를 실제로 열어 얼굴의 작은 눈, 머리 대비 신체 크기, 손목→손→검의 연결을 관찰했다. 참고 이미지는 픽셀 추출·추적·재배포하지 않았다. 이 종은 사람이 아닌, 뿔과 발이 없는 바다 뱀으로 별도로 저작했다.

## 원본과 보조 코드

- `palette.json`: 투명색을 제외한 ASCII 기호 18개. A/B/C는 깊은 청록 외곽과 그림자, D/E/F는 비늘의 기본·빛 면, G/H/I/J는 금 배판, K/L은 구강·혀, M/N/O는 진주·물결, P/Q/R은 독 기포.
- `poses/*.pxgrid`, `actions/*.pxgrid`: 모든 자세가 128행×128글자의 완전한 literal ASCII 원본이다. 점은 투명이다.
- `sketches/*.txt`: 직접 고른 각 자세의 native 행·좌표 군집과 수정 기록. 프레임 상속이나 다른 자세에서의 좌표 자동 전파는 없다.
- `author.py`: 빈 투명 캔버스에 지정된 literal 문자열을 쓴 뒤 전체 행으로 저장한다. `@`는 투명 기호를 포함한 명시적 교체, `@+`는 문자열에 명시된 불투명 군집의 덧쓰기다. 도형·음영 생성·회전·리샘플링·프레임 이동·보간·구멍 메우기 기능은 없다.
- `patches.json`, `hole-repairs.json`: 직접 고른 자세별 좌표·문자열 기록. 실제 적용 결과는 각 sketch와 full pxgrid에 보존한다.
- `render.py`: 원본 기호를 팔레트 RGBA로 일대일 변환한다. 최근접 확대는 라벨이 붙은 진단 PNG에만 사용한다. GIF 색 양자화는 하지 않는다.
- `preview_gifs.py`: 저장된 GIF 프레임을 읽는 진단 도구. 원본 그림은 수정하지 않는다.

## 신체와 자세별 저작

두 금빛 눈을 긴 주둥이 위에 놓고, 짧고 둥근 귀지느러미 둘, 아래턱에서 목으로 이어지는 금 배판, 청백 진주 목장식을 유지했다. 실제 몸통의 두 코일과 꼬리가 같은 청록 재질로 이어진다. 코일 중심의 빈 공간은 의도한 음영·외곽과 구분해 남겼다. 왼쪽 위의 넓은 E/F 면과 오른쪽·아래쪽 C/B 면을 직접 고른 행으로 찍었다.

| 자세 | 직접 바꾼 군집 |
|---|---|
| idle_a/b/c | 머리·턱 높이, 목의 진주 위치와 부피, 코일의 이완, 꼬리 끝의 굽음 |
| windup | 목을 뒤로 당긴 굽음, 수축한 코일, 후방의 하중 |
| move | 앞으로 낮춘 긴 턱, 펼친 코일 구멍, 굽은 목 밑동 |
| attack | 긴 주둥이의 전진, 분리해 찍은 윗턱/아랫턱/구강/혀/짧은 이빨, 붙어 있는 목과 진주 |
| recover | 닫힌 턱, 회수하며 굽힌 목과 돌아오는 코일 |
| hit | 찌푸린 작은 눈과 낮아진 뒤쪽 머리, 기울어진 목과 눌린 코일 |
| dead | 바닥 가까이 내려온 머리·닫힌 눈, 몸통으로 이어진 부피 있는 목, 넓게 풀린 코일과 따로 읽히는 꼬리 |
| skill_a/b/c | 실제 구강 안의 핵, 입에 붙은 두 물결, 턱 회수와 떨어진 물보라 셋 |
| poison_a/b | 아픈 열린 턱·비틀린 목의 차이, 서로 다른 기포 군집 |
| stun_a/b | 처진 머리·목의 차이, 별 두 개의 위치·군집 |
| sleep_a/b | 짧게 감긴 두 눈, 코일 위에 내려놓은 턱, 진주를 유지한 압축/이완 윤곽 |

## 실제로 보고 고친 좌표

1. 첫 대기 PNG에서 목과 몸 사이 y=76의 빈 한 행을 발견했다. `idle_a`의 (35,76)에 목/배판 행을 직접 추가했다.
2. 처음 좁게 찍은 코일은 `idle_a-coil.rows`의 새 literal 행으로 넓혔다. 다른 자세의 코일도 각 자세에서 별도로 찍었다.
3. 첫 기술 PNG에서 효과 블록의 점이 주둥이를 지우는 문제를 확인했다. effect 군집의 명시적 덧쓰기 의미를 구분하고 `skill_b`의 (73,48)부터 입과 두 갈래를 잇는 native 군집을 추가했다.
4. 전체 PNG에서 근거리 귀지느러미와 아래쪽 넓은 그림자 면을 자세별 좌표로 추가했다. 독·수면의 일부 추가 지느러미 픽셀은 몸 밖의 의도한 윤곽이다.
5. 그림자 문자열이 코일 중심을 침범한 곳은 (51,99) attack, (44,97) move, (47,99)/(43,114) poison_b, (45,98)/(41,114) recover, (40,113) skill_b, (42,116) sleep_a, (47,101)/(42,116) sleep_b에서 각각 직접 투명 행으로 되돌렸다. 연결 검사로 칠하지 않았다.
6. `move` y=65–83, `recover` y=68–81, `attack` y=65–87의 목 밑동을 다시 찍었다. 공격 주둥이의 (84,38)부터 윗턱과 (70,62)부터 아랫턱을 늘렸으며, 목 수정 뒤 잘린 진주는 (47,69)부터 원래 재질의 둥근 부피로 복원했다.
7. 쓰러짐의 높게 남은 목을 제거하고 (55,92)부터 낮은 머리·실제 목 면으로 다시 저작했다. (68,112)의 목 진주도 연결된 금 장식 안에 남겼다.

## 확인 자료

원본 1배 PNG와 최근접 2배·3배 진단 PNG를 실제 열었다. 밝은 배경, 어두운 배경, 체커 배경의 전체 18자세를 확인했다. 수면의 작은 감긴 눈을 1배에서 보았고, 공격·회수의 같은 턱/목/진주 경로와 쓰러짐의 바닥 윤곽을 함께 보았다.

8개 GIF의 모든 프레임을 원본 RGBA 및 노출 시간과 재비교했다. 실제 GIF를 연 뒤, 도구가 첫 프레임만 보여 주는 한계 때문에 8개 GIF에서 직접 읽은 시간순 비교 PNG를 모두 열어 변화와 튐을 확인했다. 실제 재생은 `preview/index.html`에 보존했다.

각 자세의 본체는 4방향 연결 진단에서 하나의 큰 군집이었다. 독의 기포, 기절의 별, 기술 회수의 잔기는 의도한 분리 군집이다. 이 진단은 픽셀을 수정하지 않으며 시각 품질 판정을 대신하지 않는다. 캔버스·투명 여백·y≤124 확인과 실제 source 파일 SHA256은 `preview/render-report.json`에 있다. idle_a의 실제 하중 코일은 y=124에 닿는다.

## 남은 표현 한계

- 대기 b의 코일 오른쪽 윤곽이 a/c보다 넓어, 240ms 순환에서 호흡이 다소 크게 보일 수 있다.
- 새 하단 몸통은 열린 C형이며, 앞쪽 끝은 몸통 중간보다 가늘다. 공격의 코일 풀림이 돌격의 추진으로 충분히 읽히는지는 새 독립 시각 검수가 필요하다.
- 이동→공격의 끝 길이 차이와 회수→대기의 닫힘은 이 소수 핵심 자세에서는 눈에 띈다. 정지 그림과 시간순 비교만으로 실제 재생의 부드러움이나 전투 접촉을 확정할 수 없다.
- 피격 GIF도 기존 시간표대로 recover를 공유한다. 수정한 회수 자세의 작은 코일 열림이 피격 후에도 나타난다.
- 두 물결은 다른 굵기와 끝을 갖지만, 윗갈래의 길고 가는 마루가 물보다 빛의 띠로 읽힐 가능성이 있다.
- 코일의 금 배판과 등 장식은 간결하게 찍었다. 보스의 장엄함을 더 요구하면 해당 부위의 실제 군집을 추가로 저작해야 한다.

통과 판정이나 사용자 승인은 기록하지 않았다.
