# 흑건 자객 — baram-wuxia-v2 / QUALITY_REPAIR

이번 작업은 `QUALITY_REPAIR.md`에 지정된 7자세의 국소 수리다. 기존 청색 두건·먹청 도복·성인 체형과 얼굴 간격을 보존했다. 원본은 `palette.json`, `poses/*.pxgrid` 9장, `actions/*.pxgrid` 9장이다. 최종 격자는 모두 ASCII 64행 × 64열의 완전 행이다. 투명 문자는 `.`이며 팔레트는 기존 18색 그대로다.

## 초안 이력 보존

- 수정 전 18격자, 팔레트, 원래 `AUTHORING.md`와 `TIMING.md`, 기존 저작 보조 파일을 `history/before-quality-repair/`에 바이트 그대로 보존했다. 당시 SHA-256은 그 폴더의 `sha256.json`에 있다.
- 원래 문서의 v1 저작 설명과 당시의 한계는 역사 기록이다. 그 문서에 쓰인 **기절의 내려간 복면·벌어진 입**은 이번 수정에서 복원한 대상이며 현재 결과의 설명이 아니다.
- 기존 `author.py`, `idle_author.py`, `poses_author.py`, `actions_author.py`, `refine_author.py`는 수정·재실행하지 않았다. 초기 초안 단계 기록이므로 재실행하면 최종 격자를 덮어쓸 수 있다.
- 기존 `progress/` 그림은 초안 이력으로 남겼다. 현재 원본에서 새로 렌더한 그림은 `progress/repair-v2/`다. 이전 원본에서 직접 렌더한 비교 그림은 `progress/repair-before/`다.

## 동결 범위와 파일 관찰

`windup`, `move`, `recover`, `hit`, `dead`, `skill_b`, `skill_c`, `poison_a`, `poison_b`, `sleep_a`, `sleep_b` 11격자는 수정 전 사본과 **바이트 단위로 동일**하다. 팔레트와 기존 저작 보조 파일도 바이트 동일하다. `REPAIR_REPORT.json`에 이전/이후 해시, 변경 픽셀 수와 경계를 기록했다.

렌더러가 최종 완전 행을 읽으면서 64×64와 팔레트 문자, x1..62 / y1..60 안의 도트 영역을 확인했다. 모든 자세의 최하단 도트는 y60이고, idle_a의 두 신발 밑창도 y60 그대로다. 18격자는 서로 다른 내용이다. PNG는 팔레트 색과 0/255 알파를 그대로 쓰며, 확대는 검토 화면에만 최근접으로 적용했다.

`progress/repair-v2/suite.png`의 18장 1배·3배와 수정 부분의 밝은/어두운 8배 PNG를 직접 열었다. 파일 관찰과 자체 그림 확인이며 독립 검수나 하네스 합격 판정은 아니다. 테스트·게이트는 실행하지 않았다. 이 작업의 쓰기는 모두 `source/` 안이며, 게임 저장소·원장·브리프·다른 후보는 수정하지 않았다.

## 남은 시각 문제

- 공격의 먼쪽 팔은 작은 X 교차 뒤로 일부 가려진다. 소매와 감개를 연결했지만 native64에서는 칼 두 개와 전완이 밀집해 보일 수 있다.
- 결인의 손가락 사이 틈은 1px다. 보라색 가장자리와 짙은 소매는 어두운 전투 배경에서 대비가 약하며, 실제 표시 크기에서 추가 검토가 필요하다.
- 기존 대기의 호흡과 수면의 움직임은 작다. 이번에는 정지 PNG를 확인했으며 실제 GIF 리듬이나 게임 전투를 확인하지 않았다. 동결된 11장에 대한 미감 변경은 하지 않았다.

이 결과는 사용자가 판단할 수정 후보다. 사용자 Allow/Modify/Deny나 승인·선택이 이루어졌다고 주장하지 않는다.
