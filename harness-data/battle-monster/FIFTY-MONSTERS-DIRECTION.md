# 신규50종·전부 통과 · 사용자 목표

사용자 원문: **그래 한 50개 만들고 전부 통과시켜**

`fifty-monsters-plan.json`의 서로 다른 신규50종을 만든다. 기존23종/사용자 Allow·Modify·Deny는
이 목록에 포함하거나 변경하지 않는다. 짐승10·요괴16·인간형12·대형 보스12, 원본64/96/128,
각18자세/8GIF, 총900자세/400GIF가 최종 목표다. 색만 바꾼 복제나 기본 자세만으로 수를 채우지 않는다.

## 통과의 근거

- 현재 원본의 실제 팔레트/격자/투명/접지/자세·PNG/GIF 재읽기 검사 PASS.
- 실제 별도 GPT6.1sol/high 독립 검수 job/result가 현재 원본/실제 첨부 PNG에 묶이고 추천이 keep.
- 지적이 나오면 지정한 자세/좌표를 직접 교정하고 별도 새 검수를 받는다. 이전 원본·실제 rework
  결과·출처는 남긴다. 결과/점수/해시를 고쳐서 통과시키지 않는다.
- 사용자의 이번 일괄 통과 지시를 근거로 대시보드 API에 위임된 Allow를 저장한다.
  원문/현재 원본 binding/실제 검수 job/요청 UUID를 남기며 사용자가 버튼50개를 눌렀다고 주장하지 않는다.
- 이후 직접 들어온 사용자 Modify/Deny는 앞선 일괄 지시보다 우선한다. 실패한 결과는 통과로 세지 않는다.
- 원본을 지속 보관하고 같은 자산 원본/선택/선택 팩을 다시 읽어 확인한다. 게임 프로젝트 설치는 별도다.

## 제작

하네스 `wave --visual-repairs 4 --visual-repair-authorization <사용자 원문 파일>`의 명시적 경로를 쓴다.
기존 wave/Modify의 기본 동작은 동일하다. 이번 사용자가 전부 통과하라고 지시했으므로 실제 지적 좌표
교정을 허용한다. 이 모드에서 rework인 결과는 게시하지 않는다. 제한에 닿으면 실패로 남고 감독이
현 원본/실제 호출 상태를 확인해 이어서 교정한다. 자동 점수 조작/전면 랜덤 재생성은 하지 않는다.

먼저 금각사슴64·청동종귀96·일금봉황128을 완성해 실제 그림을 보고 나머지47종을 제작한다.
각 작가가 서로 다른 후보/source만 편집하며 게임 정본/공통 코드/ledger를 쓰지 않는다.
실제 모델은 GPT6.1sol/high, 최대3명 병렬. 자체 검객은 크기/얼굴 관찰용이며 외부 이미지 복제가 아니다.
프레임마다 명확한 관절/도구 연결, 광원/재질/부피, 큰 실루엣/표정과 공격·스킬·상태이상의 구분을 본다.

실제 중간 PNG와 완성 GIF 대시보드를 사용자에게 공유한다. 제작 중 수는 대시보드에서 표시하되
미완성/불통과 원본은 완료 후보로 노출하지 않는다. 목표는50종 전체이며 먼저 완성된 몇 종을
전체 완료로 바꾸지 않는다.
