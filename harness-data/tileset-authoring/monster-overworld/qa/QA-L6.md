## 2. 지적 목록(이번 회차)

#### N64. [중] 「자르기」 장애물이 정본 자르기 나무(야생 `wild_forest.cut_tree`)와 다른 그림이다 (L5 까지 놓친 결함)
- **위치:**
  - route_b 위층 `bush0` (8,3)·(5,7), `bush1` (17,15)
  - 시트 `bush0`·`bush1`. 라벨은 semantic.json 「덤불(자르기 이벤트를 올릴 자리)」이다.
- **그림:** `qa-l6/cmp_bush_cut8.png`(왼쪽부터 본 시트 bush0·bush1 | 야생 bush0·bush1 | 야생 정본 cuttree), `qa-l6/r_bush8.png`
- **문제:**
  - REGIONS 2-1 정본 표는 「자르기 나무 = 야생 `wild_forest.cut_tree`」다. 체육관 시트도 `gy_cuttree = wf.cut_tree(...)` 로 그 함수를 부른다.
  - 그런데 본 시트의 자르기 대상은 줄기가 거의 없는 반구 덤불 `o2.bush` 다.
  - 같은 게임 안에서 「자르기」 장치가 두 그림이 된다. 도로·마을에서는 둥근 덤불, 숲·체육관에서는 줄기 선 작은 나무다.
  - 같은 이름 `bush0/1` 은 야생과 바이트가 같지만, 야생에서는 장식이고 자르기는 `cuttree` 가 맡는다. 역할이 엇갈린다.
  - 바로 「같은 장치인데 다른 그림」(2-1 머리말에 적힌 실패 유형)이다.
- **원작 근거:**
  - RSE·FRLG 의 자르기 나무는 지역과 무관하게 한 그림이다(줄기 선 작은 나무 1칸).
  - Route101 류 도로에서도 같은 칸을 쓴다.
- **고침:**
  1. `monster_overworld.py` 에서 `import wild_forest as wf` 하고 `sh.add("cuttree", wf.cut_tree(P2))` 로 정본 칸을 받는다. 바닥 그늘만 grass 최암으로 인자를 준다.
  2. `bush0/1` 의 semantic 라벨을 「장식 덤불(막힘, 자르기 아님)」으로 바꾼다. 또는 bush 를 시트에서 빼고 cuttree 로 대체한다.
  3. route_b 의 자르기 자리는 원작 문법대로 **샛길 하나를 실제로 막는 자리**에 `cuttree` 를 둔다. 지금 덤불 셋은 빈 풀밭에 떠 있어서 길을 막지 않는다. 예: 서쪽 꽃밭 (4..5,25) 으로 들어가는 1칸 틈.

## 4. 「같은 게임」 검사 (칸 이름 단위 픽셀 비교, 각 시트 최신 run)

**본 시트 책임 [중] 2건.**

**같은 픽셀로 확인한 것**
- 돌계단: rock_stairs·rock_stairs_r·stairs_v 가 야생과 같다.
- 고원 앞면: rock_at19/137 = 야생 gface_at2/8.

**참고: 지역 시트 쪽 몫, 본 시트 결함으로 세지 않음.** 감독이 지역 루프에 넘길 것들이다(`qa-l6/cmp_shared_ow_wild_coast6.png`).

- **풀·턱이 다르다.** 야생 `tall0/1`·`ledge_s_*` 가 다른 그림이다(L5 에서 이미 보고).
