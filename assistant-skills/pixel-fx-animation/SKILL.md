# 전투 효과의 프레임별 직접 도트 저작

동봉된 [pixel-dot-authoring](../pixel-dot-authoring/SKILL.md)을 읽고 각 프레임의 픽셀을 직접 저작한다.
프로젝트 전용 격자 도구가 없으면 그 스킬의 `scripts/pixelgrid.py`를 사용한다. 두 스킬을 같은 스킬 폴더에 설치한다.

## 연출을 정한다

- 대상 그림, 시전자/착탄 앵커, 화면의 실제 표시 크기, 재생 간격과 피해가 들어가는 시점을 먼저 확인한다. 상자 가운데와 몸/손/발의 실제 위치는 다르다.
- FF6 등 특정 게임을 참고하면 요청한 버전의 **실제 연속 장면**을 확인한다. 밝기 최고점 하나만 보고 전체 동작을 추측하지 않는다. 형태·진행 방향·시간 배분을 기록한다. 원본 그림을 복제하려면 사용자의 요청 범위와 프로젝트 자산 조건을 따른다.
- FF6 SNES 연출을 참고하는 작업이면 [확인한 원본 장면과 층 구성](references/ff6-snes-study.md)을 읽는다. 소환은 몸 구조가 읽히는 원화 한 장을 먼저 마무리하고, 그 그림을 대상이 있는 전투 화면에서 확인한 뒤 동작을 찍는다.
- 발동/준비 → 진행/팽창 → 접촉/최고점 → 붕괴/잔상의 단계와 앵커를 짧게 정한다. 이 단계는 설계 도구이며 모든 기술에 같은 박자나 프레임 수를 강제하지 않는다.
- **큰 상자와 많은 프레임이 목표가 아니다.** 작은 원본에서도 속성·방향·강도가 읽혀야 한다. 최고점의 인상과 전후 변화가 기술을 구분해야 한다.

## 각 프레임의 픽셀을 찍는다

1. 접촉/최고점의 핵심 프레임을 먼저 찍는다. 실루엣, 색 대비와 대상 가독성을 확인한다.
2. 준비와 잔상의 핵심 프레임을 별도로 찍는다. 커다란 도형을 작게/크게 바꾼 버전으로 채우지 않는다.
3. 중간 프레임마다 덩어리가 이동·벌어짐·찢어짐·부서짐을 직접 그린다. 앞 프레임의 행을 읽고 재사용할 수 있지만, 형태와 명암이 바뀌는 지점은 해당 프레임의 좌표로 다시 결정한다. 코드로 변형·보간·전파하지 않는다.
4. 노출 시간을 조절한다. 붙잡는 핵심 프레임은 `durationMs`로 유지하고, 똑같은 프레임을 여러 장 넣어 프레임 수를 부풀리지 않는다. 엔진이 일정한 간격만 지원하면 그 계약을 따른다.

속성별로 서로 다른 조형을 선택한다. 아래는 설계 질문이며 고정 템플릿이 아니다.

| 효과 | 직접 찍을 변화 |
|---|---|
| 불 | 어디서 붙어 어떤 갈래가 자라는가? 가장 뜨거운 핵과 식는 가장자리가 어떤 덩어리로 갈라지는가? |
| 얼음 | 결정이 어떤 면으로 자라는가? 접촉 뒤 균열과 파편은 어느 면에서 어떤 방향으로 떨어지는가? |
| 번개 | 굵은 주 경로와 짧은 가지를 어디에 찍는가? 닿는 순간의 섬광과 이후 끊어진 잔전류는 어떻게 다른가? |
| 베기·타격 | 검의 진행과 곡선, 접촉점, 파편 방향이 일치하는가? 빛 궤적만 커지고 무기의 방향이 사라지지 않는가? |
| 회복·보호 | 빛이 몸을 따라 어디서 어디로 흐르는가? 공격의 폭발과 다른 상승/감싸기 형태가 읽히는가? |
| 소환 | 몸·얼굴·날개·턱·사지의 구조가 유지되는가? 등장과 공격은 별개의 자세인가? 브레스/투사체가 입/손에서 실제 대상까지 닿는가? |

## 보고 고친다

- 프레임마다 이름/단계/지속 시간/접촉 앵커를 남긴다. 전체 접촉 시트와 실제 속도의 GIF를 열고, 의심스러운 구간은 두세 프레임씩 느리게 비교한다.
- 위치가 갑자기 튀는 윤곽, 깜빡이는 내부 명암, 잘린 갈래, 중심만 같은 확대 도형, 엇나간 접촉점, 불필요하게 긴 준비를 좌표/프레임으로 지적하고 고친다.
- 알파/색 수/프레임 변경률은 형식 자료다. 모두 달라졌다는 이유로 애니메이션이 자연스럽다고 판단하지 않는다.
- 실제 게임에 적용하는 요청이면 시전 포즈·투사체·착탄·피격·피해/소리 시점을 엔진에서 확인한다. 무음 효과 GIF와 완성 전투 녹화를 구분한다. 테스트 실행 제한은 프로젝트 지침을 따른다.

## 결과

프레임별 격자 원본, 팔레트, 시간표, PNG 시트, 접촉 시트와 GIF를 남긴다. 어떤 부분을 실제 게임에서
확인했는지 명시한다. 정본/공용 등록이 필요한 작업은 그 절차까지 수행한다. 검토용 그림만 만든 요청은 그 범위로 보고한다.
