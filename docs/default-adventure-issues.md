# 기본 게임/에셋 정리 중 발견한 문제점

작성일: 2026-07-02

## 기본 캐릭터셋 혼입

- 새 기본 게임(`별등 마을`)이 처음에는 삭제된 레거시 캐릭터칩을 기본 NPC 그래픽으로 사용하고 있었다.
- 새 이벤트 생성, 이동 경로 그래픽 변경 입력 기본값, 이벤트 속성 placeholder에도 삭제된 레거시 캐릭터칩이 남아 있었다.
- 번들 로더가 삭제 대상 PNG를 별도 텍스처로 계속 로드하고 있어, 코드 참조를 끊어도 파일만 있으면 다시 살아날 수 있었다.
- 기본 리소스 프로필에 삭제된 레거시 캐릭터칩이 monster 리소스로도 등록되어 있었다.
- 조치: 제품 코드의 기본값을 EasyRPG People1 CharSet 텍스처로 통일하고, 삭제 대상 PNG 파일을 제거했다.

## 런타임 fallback 문제

- 이벤트 그래픽을 찾지 못하면 플레이 화면이 예전 레거시 NPC 텍스처로 fallback하고 있었다.
- 플레이어 스프라이트 리소스도 EasyRPG 캐릭터셋을 찾지 못할 때 legacy sprite resource로 떨어지는 경로가 있었다.
- 조치: fallback도 EasyRPG People1 CharSet으로 바꿔서 삭제된 기본 캐릭터셋이 렌더링 경로에 남지 않게 했다.

## 스위치/변수 슬롯 보정 문제

- `ensureSwitchVariableSlots`가 커스텀 참조 ID가 먼저 들어온 경우 낮은 번호 슬롯(`sw_0002` 등)을 건너뛸 수 있었다.
- 새 기본 게임은 이벤트 조건/명령 때문에 참조 스위치와 변수가 추가되므로 이 문제가 테스트에서 드러났다.
- 조치: 비어 있는 낮은 번호부터 채우도록 보정 루프를 수정했다.

## 테스트/fixture의 낡은 기준

- 여러 테스트와 fixture가 삭제된 레거시 캐릭터칩을 기본 정상값으로 전제하고 있었다.
- 조치: 현재 테스트 기준은 EasyRPG CharSet ID로 치환했다.

## UI/검증 과정에서 본 문제

- 모바일 테스트 플레이 창에서 titlebar가 좁은 화면에서 잘리는 문제가 있었다.
- 조치: windowed test-play 레이아웃의 최소 폭과 titlebar overflow를 조정했다.
- 초기 E2E 테스트는 실제 대화 진행 순서와 맞지 않는 선택지 대기, 숨겨진 debug JSON 텍스트 충돌, Space/Enter 입력 차이로 불안정했다.
- 조치: 테스트 helper와 locator를 실제 플레이 흐름 기준으로 바꿨다.

## 이번 정리에서 추가로 닫은 문제

- 이전 확인용 임시 이미지와 과거 브라우저 trace/evidence 산출물에 삭제된 레거시 캐릭터칩 스냅샷이 남아 있었다.
- 조치: 런타임 입력이 아닌 생성 산출물 중 금지 토큰이 포함된 파일만 선별 삭제하거나 새 증거로 재생성한다.
- Vite build에는 `src/project/store.ts`의 정적/동적 import 혼용 경고가 남아 있었다.
- 조치: classic event editor capture 경로의 store 관련 동적 import를 정적 import로 바꿔 build warning이 재발하지 않게 한다.

## 남은 주의점

- Git 히스토리에는 과거 삭제 전 상태가 남아 있을 수 있다. 이번 기준은 현재 작업트리의 소스, 문서, 테스트, public asset, 생성 산출물에서 금지 토큰이 검색되지 않는 것이다.
- 새 데모 게임은 에디터 UI를 통해 작성한 export만 fixture로 보관하며, 직접 손으로 만든 프로젝트 데이터는 데모 기준으로 인정하지 않는다.
