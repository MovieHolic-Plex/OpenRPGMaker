사용자가 직접 웹 조사를 요청했다. 이전 공용 효과 24종/소환 v2는 반려됐으며 기본값 배선은 철회했다.

## 연속 장면 관찰

웹 검색의 설명만 읽고 본 것으로 보고하지 않았다. Playwright에서 공개 영상을 재생하고
실제로 표시된 비디오 영역을 시간별로 촬영했다. 미디어 파일을 다운로드하지 않았다.
`inspect-reference.mjs`와 각 폴더의 `observations.json`에 주소/시간/비디오 준비 상태를 남겼다.
영상 표본은 소리를 보존하지 않는다. 3초 간격의 큰 구간 탐색은 짧은 접촉을 놓칠 수 있다.
탐색 중 일부 구간은 영상 버퍼링으로 중단됐다. 폴더의 실제 PNG 목록/요청 시각은
`capture-index.json`에 따로 모았으며, 아래에 명시한 연속 표본 구간을 관찰 근거로 사용했다.
검토용 사본은 팔레트와 크기를 줄였다. 대표 장면 세 장의 촬영 원본은 `source-captures/`에 보존했다.
Git에는 비교 시트·대표 장면·관찰 기록을 보존한다. 개별 탐색 프레임 전체는 로컬 촬영 기록이며
`inspect-reference.mjs`로 다시 촬영한다.

### 화염·빙결·번개 중급/상급

[2:51 이후 원본](https://www.youtube.com/watch?v=XSoHSGRyNPo&t=171s).
171~207초를 0.5초 간격 73장으로 확인했다. `elemental-contact.png`와
`firaga-blizzaga-thundaga.png`가 서로 다른 접촉/최고점의 비교판이다.

| 기술 | 표본에서 확인한 차이 |
|---|---|
| Fira | 대상 높이까지 솟는 길고 밝은 황금빛 화염 |
| Blizzara | 면이 있는 결정들이 흩어지고 대상에 밝은 접촉 표시 |
| Thundara | 굵은 노란 주 경로·푸른 경로·옆 가지, 대상도 금빛으로 변함 |
| Firaga | 붉어진 전장과 대상 위치의 아주 밝은 핵 |
| Blizzaga | 대상 둘레의 푸른 구체와 큰 흰 팽창 |
| Thundaga | 화면 높이를 쓰는 여러 낙뢰와 넓은 섬광 |

작은 불/얼음/번개 아이콘의 색만 바꾸는 구성으로 세 계열과 강도를 만들면 이 차이를 잃는다.

### 홀리 / Pearl

[3:39 원본](https://www.youtube.com/watch?v=XSoHSGRyNPo&t=219s).
219~227초를 0.25초 간격 33장으로 확인했다. 특히 `holy-final-0.png`, `holy-final-1.png`를 본다.

| 영상 시각 | 실제로 보이는 구성 |
|---|---|
| 약 220초 | 시전자에 주황색 시전 표시 |
| 약 221.5초 | 전장이 짙은 파랑으로 바뀌며 촘촘한 물결 전개 |
| 약 222.75~224초 | 흰 구슬 세 개가 서로 다른 위치로 회전하며 하강 |
| 약 224.25~225.25초 | 대상 둘레의 큰 흰 빛이 팽창/축소하고 다시 번쩍임 |
| 약 225.5~226.25초 | 전장이 거의 흰색, 대상 윤곽은 남음 |
| 약 226.5초 | 원래 전장 복귀 |

시간은 녹화 영상의 표본 위치이며 원본 엔진의 정확한 밀리초 규격이 아니다.
역분석 소스의 `HOLY_SPRITE`, `HOLY_BG1`, `HOLY_BG3`를 별도로 확인했다.
구슬은 앞뒤 우선순위와 나선 하강, 큰 빛은 별도 층, 배경은 물결/색 변화다.
이전 `hand_holy_lance`의 금색 막대/별은 이 연출의 형태·공간·순서를 반영하지 못했다.

### 바하무트 / Sun Flare

[5:43 원본](https://www.youtube.com/watch?v=Shu1GcI9FIw&t=343s).
336~351.5초의 0.5초 표본을 확인했다. `bahamut-final-1.png`에 등장~소멸이 이어진다.

큰 용은 목/턱/가슴/발/날개 뼈/막/꼬리가 붙은 원화로 읽힌다. 전장을 어둡게 하고,
푸른 파동이 적진으로 크게 번지며 그 안에서 여러 착탄이 이어진다. 끝에 용이 희게 빛나며 사라진다.
역분석 소스 `BAHAMUT_BG1/BG3/SPRITE`도 소환체/파동/착탄을 나눠 제어한다.
등장 원화의 윤곽을 상당 시간 유지한다. 날개 두 포즈를 교대로 흔드는 것만으로 소환을 만들지 않는다.

## 다음 기본값 팩의 저작 범위

아래는 참고 대상을 정한 제작 목록이다. 미승인 그림을 기본값에 설치하는 지시가 아니다.

| 묶음 | FF6에서 조사/비교할 대표 | 이번 반려에서 고칠 점 |
|---|---|---|
| 화염 | Fire / Fira / Firaga | 몸에 붙는 불, 갈래/명암 덩어리, 터지는 핵과 잔불 |
| 빙결 | Blizzard / Blizzara / Blizzaga | 결정 면과 큰 덩어리, 얼어붙는 접촉 뒤 파쇄 |
| 번개 | Thunder / Thundara / Thundaga | 굵은 낙뢰 경로, 대상의 번쩍임, 짧은 잔전류 |
| 큰 마법 | Holy / Flare / Ultima / Meteor | 기술마다 다른 진행, 배경 변화와 대상 착탄의 시차 |
| 대지·바람 | Quake / Tornado | 발밑/전장과 연결된 힘, 움직임의 방향과 규모 |
| 회복 | Cure / Cura / Curaga / Raise / Esuna | 대상의 몸을 따라 흐르는 변화와 마무리 |
| 보조 | Protect / Shell / Reflect / Haste / Slow | 작은 떠 있는 배지 대신 몸을 감싸거나 몸 색이 변하는 접촉 |
| 소환 | Ifrit / Shiva / Bahamut / Phoenix / Odin | 먼저 구조가 읽히는 원화 한 장, 그 뒤 등장/공격/퇴장 |
| 물리·특기 | Bushido / Blitz / Tools / Throw / Lore | 캐릭터 포즈·진행 방향·연타 박자가 맞는 궤적과 착탄 |

세부 묶음의 시각 관찰 정도는 다르다. 위 원소 중급/상급과 홀리/바하무트는 연속 표본과 소스, 나머지는
구간 탐색/제작자 목차/해당 원본 스크립트로 찾아 둔 참고 후보다. 후보를 완성 기준작으로 취급하지 않는다.

## 우리 엔진에서 필요한 작업

현재 `RetroFxLayer`에는 시전자/대상/전체 대상/화면/투사체 층과 시작 시각, 배율, 반복, 효과음이 있다.
화면 흔들림/섬광/어둡게와 소환 시트도 이미 지원한다. **그림을 늘리는 것만으로 완료되지 않는다.**
홀리의 전장 물결·대상 앞뒤 교차는 현재 일반 시트의 배치/단순 화면 효과와 같지 않다.
우선 직접 저작한 구슬·착탄·배경 층을 실제 대상 위에서 맞춰 보고, 추가 합성 기능은 그 장면에 필요한 범위로 판단한다.
소환은 작은 아이콘을 크게 확대한 시안을 반복하지 않고, native 크기의 몸 구조부터 확인한다.

1. 다음 대표는 금색 창 대신 **성광: 물결 전장 → 구슬 하강 → 큰 착탄**으로 설계한다.
2. 소환은 원화 한 장의 얼굴/가슴/발/날개를 먼저 검토한다. 원화가 반려되면 모션 수를 늘리지 않는다.
3. 대표 연출을 실제 전투 크기/속도에서 검토한 뒤 나머지 팩을 제작하고 공용 기본값에 연결한다.

이번 작업에서 사용자 SQLite·원격 DB는 수정하지 않았고 gates/vitest/전체 typecheck는 실행하지 않았다.
연속 표본 미리보기는 736/320px에서 가로 넘침·JS 오류 없이 표시됐고, 1회 재생이 마지막 표본에서 멈췄다.
