# Slates 단계별 조립 지침 — 두 번째 전달판

이 문서는 **관찰 자료를 새 맵 저작으로 옮기는 절차**다. [첫 독립 실험](../docs/experiments/slates-astra/RESULT.md)은 성곽과 통행을 만들었지만 지붕 접합·건물 반복·공간 밀도가 부족했다. 학습 완료와 그림 완성도를 혼동하지 않는다.

[그림으로 보는 조립·실패·측정 안내](../reports/slates-assembly-v2/index.html)와 아래 지정 그림을 실제로 연다. 파일 수를 많이 읽는 것이 과제가 아니다. 사용하는 부품의 연결과 출처를 설명할 수 있어야 한다.

## 1. 이번에 폐기하는 일반화

- 기존 지침의 “폭 4/6칸 지붕, 150/151에서 매 행 확장”은 특정 옛 배치의 기록이다. **임의 폭/깊이의 집을 만드는 공식이 아니다.** 이전의 “결합부 확인”을 품질 인증으로 인용하지 않는다.
- 뾰족한 지붕의 폭만 넓힌 뒤 앞쪽에 작은 박공을 덧대면 큰 삼각 벽면과 맞지 않는 처마가 생길 수 있다. 부품이 타일 격자에 맞는다는 사실은 지붕 구조가 맞는다는 뜻이 아니다.
- `reference-context`는 배경 포함 관찰이다. `partial`은 남은 결함이 있다. `experiment`는 명시된 반복 행의 한정된 실험이다. `hold`는 통째 자동 배치 금지다. 새 구조마다 판정한다.

## 2. 필수 입력과 정확한 합성 해독

**건축을 시작하기 전에 아래 JSON을 실제로 읽고 첫 집의 부품을 해독한다.**

- `public/assets/slates/slates-mastery-catalog.json`: `cards[id=projecting-house|joined-shops|wall|parapet-corner|tower|gate|inn]`의 review, patches, sourceParts.
- `public/assets/slates/slates-mastery-fine-recipes.json`: 원본 사각형과 8px 세부 합성.
- `public/assets/slates/slates-assembly-exercises.json`: 위 7개 표본을 **원본 픽셀 사각형+대상 픽셀 좌표+순서**로 풀어 적은 2478개 연산. 읽기 쉬운 파생 자료이며 완성 오브젝트 라이브러리는 아니다.

정확한 좌표 계약:

```text
card.patches[y16][x16] = [r0, r1, ...]     // 같은 16px 칸 안의 그리는 순서
fine.rects[r] = [source, sx, sy, size=16, dx=0, dy=0]
destination = (x16*16 + dx, y16*16 + dy)
source 0 = v2 56열, source 1 = v1 48열
```

원본을 확대·회전하지 않고 동일 크기로 alpha-over 합성한다. 8px 조각을 16px로 늘리지 않는다. 뒷바닥→그림자→세부처럼 기록된 순서를 유지한다. 관찰 카드 재조립은 원본 비교용이며 map art는 **오직 아틀라스의 사각형**에서 온다.

32px 셀로 포장할 때는 `cell=(floor(dx/32),floor(dy/32))`, 셀 내부 위치 `(dx%32,dy%32)`로 나눈다. 원본 사각형이 셀 경계를 넘으면 사각형을 분할한다. 홀수 개의 16px 칸을 무조건 잔디로 패딩하지 말고 목적지 바닥·투명 실루엣을 고려한다.

**필수 산출:** 첫 집과 상점 접합에서 실제로 사용한 16px 부품, 필요한 경우 8px 부품의 source rect / destination / 순서를 기록한다. 장식 한 칸만 반칸 합성하고 건축은 예전 32px 공식으로 만드는 것은 이 실습을 충족하지 않는다. 8px 사용 개수 자체를 품질 점수로 삼지는 않는다.

## 3. 조립 카드의 형식 — 그림과 좌표를 함께

새 모듈마다 `modules.json`과 PNG를 만든다.

| 필드 | 필수 내용 |
|---|---|
| completeImage / explodedImage | 조립 결과와 부품·행/열 번호판. 바닥 포함 비교본과 순수 실루엣을 구분 |
| operations | 원본 버전, source rect, destination, layer, draw order |
| silhouette | 배경을 제외한 건물/탑/벽의 차지 영역. 다른 집을 자르는 문맥은 제거 |
| anchors | 문 바닥 중앙, 문 앞 접근, 좌우 처마 접점, 기단 높이. 좌표 단위 명시 |
| fixedParts / repeatBands | 고정한 꼭짓점·끝·모서리와 반복 가능한 **특정 행/열 범위**. 반복 전후 PNG 필수 |
| joins | 무엇과 어느 방향으로 붙는지, 일치시킬 접점과 다른 높이를 처리하는 부재 |
| collision | 시각 실루엣과 별도의 32px 통행칸. 수관·문턱·기단을 분리 |
| review | pass/partial/reject, 실제 관찰, 남은 결함. 자기평가임을 표시 |

원본 표본을 같은 배경째 복사하여 여러 장 늘어놓는 것은 새 마을 조립이 아니다. **바닥/그림자/대상 오브젝트를 구분한 뒤 새 문맥에 맞춘다.** RGB 색 하나로 배경을 삭제하면 노란 벽·창을 함께 지울 수 있으니 부품 좌표와 명시적 마스크로 분리한다.

## 4. 접합별 올바른 상태와 반례

| 접합 | 유지해야 할 상태 | 반려할 상태 |
|---|---|---|
| 지붕 면 ↔ 전면 박공 | 같은 지붕의 능선·좌우 경사·처마가 연속. 원본의 박공 벽면과 형태 일치 | 넓은 지붕에 작은 지붕을 임의 덧붙여 빈 삼각 벽면·끊긴 경사 생성 |
| 두 상점 ↔ 공유 접합 | 두 몸통의 높이 차이를 처마·세로 가새·벽으로 설명 | 완성 집 두 개를 겹쳐 창이나 처마를 절단 |
| 돌출층 ↔ 1층 | 창 아래 받침/보가 상층 폭을 지지하고 아래 벽·문 연결 | 지붕 아래 동일 창 행만 반복, 상층이 지지 없이 떠 있음 |
| 기단 ↔ 문 ↔ 길 | 기단 끝이 닫히고 문 중앙 아래에 접근 가능한 바닥 | 문 아래 풀/투명 구멍, 길을 가로지르는 높은 기단, 접합선 16px 어긋남 |
| 성벽 직선 ↔ 모서리 | 뒤 경계·보행면·앞 흉벽·수직면의 방향과 높이를 연결 | 가로 벽을 회전, 보행면을 벽 기둥으로 채움, 탑으로 결함 전부 가림 |
| 탑 ↔ 성문 | 육지 밑동·양쪽 착지·열린 지상 통로를 분리 | 물 반사를 육지에 사용, 닫힌 격자 아래 통행 허용 |

## 5. 밀도와 골목 — 실측과 설계 제안을 구분

[측정 데이터](../public/assets/slates/slates-reference-layout-measurements.json), [오버레이 그림](../reports/slates-assembly-v2/index.html#measure).

- 참고 `ville_0.png`는 1088×960, native 544×480. 내부를 대략 잡은 native `[0,0,544,344]`에서 수작업 건물 실루엣 7개를 칠한 면적은 **약 48.7%**다. 화면 밖으로 잘린 집과 일부 성벽 중첩이 있으므로 정밀 건물 점유율이나 전체 도시 통계가 아니다.
- 그림 위에 표시한 4개 단면의 시각 여백은 **17 / 49 / 15 / 29px**, 32px 타일 기준 약 **0.53 / 1.53 / 0.47 / 0.91칸**이다. 참고의 길과 기단 여백이 상당히 좁다는 관찰이다. 도로 전체 평균이나 게임 충돌값이 아니다.
- **새 50×50의 초기 설계 제안:** 성벽 내부의 건축 실루엣 45~60%, 주거리 2~3칸, 골목 통행 1~2칸, 문 앞 최소 한 칸. 건물 실루엣 최소 4종, 같은 실루엣을 3채 연속 놓지 않는다. 이것은 이번 과제의 출발 범위이며 원본 실측치나 자동 품질 합격점이 아니다.
- 반칸 여백 그림을 그대로 통행 폭으로 쓰지 않는다. 길로 쓸 곳은 **32px 한 칸 이상의 연속 통행**을 확보하고 기단·그림자·울타리로 시각 가장자리를 세분화한다.
- 건물·마당·시장/정원·길의 마스크를 분리해 면적을 계산한다. 바닥까지 든 사각 스탬프 면적을 건물 점유율로 계산하면 안 된다. 수치 맞추려고 집을 복제하거나 통로를 끊지 않는다.
- 성벽 내부를 균일한 직사각 필지로 채우지 않는다. 붙은 상점가, 한 채짜리 필지, 깊이가 다른 안뜰, 좁아졌다 열리는 광장, 최소 한 번 꺾이는 주동선을 함께 계획한다. 50×50은 참고 화면보다 훨씬 넓으므로 같은 집 몇 채만 넣으면 비게 된다.

## 6. 필수 단계 — 앞 단계의 결함을 마을로 복제하지 않는다

1. **집 한 채:** 문서의 반칸 조립을 해독하고 실루엣·기단·문 앞을 분리. 원본/부품/조립 PNG, 정확한 출처, 통행 마스크 제출.
2. **붙은 상점 두 채:** 높이 또는 깊이가 다른 몸통을 붙이고 접합부를 확대. 1단계 집 두 개를 단순 겹치지 않는다.
3. **성벽 모서리와 열린 성문:** 가로·세로 단면을 연결하고 실제 통로를 저작. hold 격자문은 복원했다고 주장하지 않는다. 통행·육지 밑동 확인.
4. **작은 거리:** 앞 모듈들을 새 배치에 넣고 겹침·문 접근·그림자·길 폭을 확인. 여기서 잘못된 반복/연결을 고친다.
5. **50×50:** 검토한 모듈을 사용하여 독자 배치. 모듈 종류·반복 횟수·면적·문 접근을 보고. 화면 전체와 접합 확대를 모두 검토.

독립 에이전트 실험에서는 1~3단계를 먼저 제출하고 감독자가 그림을 본 뒤 4~5단계로 넘긴다. 이것은 사용자에게 다시 승인을 요청하는 단계가 아니라 에이전트 간 품질 검토다. 감독자 피드백도 실행 기록에 남긴다.

## 7. 네 가지 판정을 분리

- **구조:** 원본 부재의 방향/접합/끝 처리/그림자. 실루엣과 지붕 연결의 육안 판정.
- **구성:** 반복감, 필지의 차이, 밀도, 주동선과 작은 여백. 수치와 전체 그림을 함께 평가.
- **통행:** 새 지도 전용 충돌, 문 앞/성문/광장 연결과 성벽 우회 누출. 실제 엔진 확인.
- **저장:** Supabase 저장·재로드, 기존 맵 보존. 저장 성공으로 앞 판정을 대신하지 않는다.

최종 보고는 각각 pass/partial/reject와 이유를 적는다. 목표를 못 맞추면 결과를 남기되 “학습 완료/참고 수준”이라고 부르지 않는다.
