# Slates 32px 마을 저작 — 다음 AI가 읽을 시각 매뉴얼

**먼저 [성곽 구조 학습·교정 기록](slates-structure-learning.md)을 읽는다.** 아래의 물버들 마을/단순 주택은 성곽 마을의 품질 표준이 아니다.

이 문서는 Slates로 **새 마을을 만들기 전** 읽는 작업 지침이다. 글만 읽지 말고 아래 PNG를
이미지 열람 도구로 열어 지붕·나무·부두의 실제 모양을 확인한다. 번호는 모두 **v2 원본,
0-based, 56열, `id = y * 56 + x`**다. 16px 기본 칩셋의 번호나 48열 v1과 섞지 않는다.

## 1. 근거를 찾는 순서

1. 이 문서의 이미지와 규칙 → [연구 기록](slates-study.md).
2. `public/assets/slates/slates-study-catalog.json`: `facts`(개별 확인), `groups`(블록),
   `regions`(넓은 구역), `kits`(조립 예제). 구역 분류는 모든 타일이 검증되었다는 뜻이 아니다.
3. `reports/slates-study/index.html`: 전체 확대 도감, 레이어/통행 및 조합을 직접 살펴보는 HTML.
4. 원본 `public/assets/slates/slates-v2-32px.png`와 아래 번호판을 대조한다.
5. [50×50 물버들 마을](#7-50×50-적용-사례)의 스크립트·배치·저장 증거를 확인한다.

이미지는 `openwiki/images/slates/`에 함께 보관한다. 임시 `output/` 파일이나 이전 대화에 의존하지 않는다.

## 2. 땅·길·물

![지형: 번호가 붙은 원본 조각](images/slates/terrain.png)

| 용도 | 원본 번호/좌표 | 조립 규칙 |
|---|---|---|
| 잔디 / 모래 / 흙 / 포장 | 중심 57 / 61 / 65 / 69 | 각각 (0,0), (4,0), (8,0), (12,0)의 3×3. 중앙을 반복, 변·모서리를 보존 |
| 물 | 243 | 불투명 하위 바닥, 통행 불가 |
| 모래섬 | (16,4), 3×3 | 중앙 297은 **모래**. 파란 외곽 물은 243. 노란 물결을 물로 분류하지 않는다 |
| 꽃 | 629·630·631 | 잔디 위 알파 덧그림. 통행 유지 |
| 세로 판자 | 23·79·135 | 물 243 위에 합성한 하위 칸. 위/중간/아래 끝막음 유지 |

길은 집의 문 앞들을 연결한 뒤 광장·출구에 붙인다. 50×50을 커다란 십자 도로와 빈 풀밭으로
채우지 않는다. 집 마당, 가게 앞 여백, 물가 접근로, 숲의 가장자리를 따로 계획한다.
지형의 3×3은 직사각 패치용이다. 임의 곡선·오목 모서리를 자동 해결하는 오토타일이라고
가정하지 않는다. 불규칙 경계에는 원본 16px 부분의 출처를 남기고 합성하거나 직접 검토한다.

## 3. 집 — 지붕과 벽을 분리

![목조·지붕·석조 번호판](images/slates/architecture.png)

검토한 작은 집의 위→아래 행:

```text
상위: 150 151       지붕 꼭짓점
      204 205       박공의 아래
      644 647       창
      196 199       몸통 (선택: 이 행만 세로 반복)
     1060 647       문 + 창
하위: 문 행은 588 591 벽, 나머지는 마당 바닥
```

폭 2칸 조립은 연구실에서 확인했다. 더 넓은 집은 사면/박공/중앙을 새로 맞춘 뒤 실제 PNG로
확인한다. 36–39열 전체를 하나의 집으로 복사하지 않는다. 굴뚝, 지붕창, 뾰족 지붕이 혼재한다.
꽃 창은 648–651, 문은 1060. 투명 문 아래에 벽이 있어야 풀밭이 실내처럼 비치지 않는다.
문 그림을 붙였다고 실내 이동 이벤트가 생기지는 않는다.

## 4. 나무 — 한 그루의 범위를 지킨다

![수목과 물가 조각 번호판](images/slates/nature.png)

| 조립 대상 | 원본 사각형 | 통행/레이어 |
|---|---|---|
| 독립 침엽수 | (8,18), 2×3 | 위 두 행 수관 ★, 마지막 밑동 행 X |
| 독립 활엽수 | (12,18), 2×3 | 같은 규칙. 하위 잔디 유지 |
| 죽은 나무 | (14,19), 2×2 | **18행까지 잘라 2×3으로 만들지 않는다** |
| 독립 덤불 | 1022·1023 | 죽은 나무 위에 뜨는 조각이 아님 |
| 군락 | (8,12)/(12,12), 4×4 | 여러 그루가 붙은 별도 블록. 독립 나무 규칙과 혼동 금지 |

집·길을 놓은 뒤 나무를 놓는다. 나무 밑동이 길을 막거나 수관이 문/간판을 가리는지 확대 확인한다.

## 5. 마을 소품 — 의미에 맞는 자리

![상점 간판·차양·벤치·문·물레방아 번호판](images/slates/props.png)

- 우물: (26,16)~(27,17)의 **각 칸이 별개 변형**. 네 칸을 한 우물로 붙이지 않는다.
- 벤치 1118, 상자 1004, 문 1060. INN 간판 940, 상점 간판 942.
- 시장 가판대 108–111은 한 줄의 판매대 변형이다. 붉은 천·파란 천의 기둥/띠는 따로 맞춘다.
- 물레방아는 (48,10) 2×3 등 네 자세. 한 자세만 조립하면 정지 소품이다.
- 원본 3×3 목재 격자는 빈틈이 있다. 통행 가능한 꽉 찬 판자 다리와 다르다.
- 성벽 전면은 막고 위 보행면은 별도로 둔다. 계단 없이 성벽 위 길이 연결됐다고 하지 않는다.

## 6. 레이어·저장·완료 조건

![조립 연구실: 집·모래섬과 다리·석조·독립 나무](images/slates/assembly-lab.png)

- `map.tileSize = 32`, 칩셋도 32. 하위/상위 배열 각각 `width * height`.
- 투명도는 통행이나 레이어를 결정하지 않는다. 물 X, 지면 O, 수관 ★, 밑동 X를 따로 저작.
- **AI `layerBacking`만으로 받침이 적용되지 않는다.** 사용자 확정으로 위장하지 않는다.
  필요하면 원본 바닥+원본 소품을 32px 파생 타일로 합성하고 원본 번호/순서/사각형을 남긴다.
- 원본 메타를 바꿔 기존 맵 통행을 망가뜨리지 않는다. 새 마을 전용 칩셋을 만든다.
- 문 앞·출구·다리 양끝에서 충돌을 읽어 연결성을 확인한다. 이후 실제 에디터 PNG와
  전용 `player.html`을 확인한다. 타일 배열만 올바른 것은 시각 완료가 아니다.
- Supabase **연결 확인 → 최신 root 읽기 → SHA 조건 저장 → root/맵/칩셋 재로드 비교**.
  임시 에디터에서 예쁘게 보이는 것만으로 완료하지 않는다. 로컬 SQLite 프로젝트도 갱신한다.
- 사진이나 참고 스크린샷을 맵 배경으로 붙이지 않는다. 칸별 편집 가능한 원본 타일을 쓴다.

## 7. 50×50 적용 사례

- 맵 `slates_village_50`, **물버들 마을**, Slates 32px, 50×50.
- 저작기 `scripts/content/build-slates-village-50.mjs` (배치·집 조립·받침 출처).
- 배치/접근 목표 `verify-shots/slates-village-50/layout.json`.
- 저장 및 재로드 `verify-shots/slates-village-50/persistence.json`, `local-persistence.json`.
- 스크린샷/관찰 `verify-shots/slates-village-50/SUMMARY.md`.
- Supabase 프로젝트 `rpg-zzu-slates32-38e6`. 이전 예제 맵과 연구실을 보존한다.

### 50×50에서 추가로 확인한 조립

- 지붕 폭 4/6칸: 꼭짓점 150·151에서 매 행 양쪽으로 1칸씩 확장한다. 내부 왼쪽 면 36,
  오른쪽 면 39. 처마/박공 끝 204·205, 내부 목조 196·199. 굴뚝 변형 541.
  원본 2칸 집을 가로로 단순 늘린 결과가 아니다. 최종 PNG에서 결합부를 확인했다.
- 창 행은 644–647 / 꽃 창 648–651 / 긴 창 700–703. 문은 589+1060 합성.
- 2칸 폭 다리는 23/79/135의 가운데 `x=8..23` 16px 폭을 각 32px 칸에 두 번 반복했다.
  물 243을 먼저 깐다. 원본 보드를 두 칸 나란히 놓으면 가운데 물 틈이 생긴다.
- 원본 1232칸 + 배치용 88칸 = 전용 아틀라스 1320칸.
  `public/assets/slates/slates-village-recipes.json`의 `sourceIds`는 그리는 순서다.
  숫자는 원본 전체 32px, 객체는 `{tile,rect:[x,y,w,h],dest:[x,y]}`. 확대/색 변경 없음.
- 프로젝트의 `slates_village_32.structureKits`에 실제 건물 13개를 저장했다.
  도감의 원본 메타/그룹도 보존했다. 파생 타일의 통행은 해당 배치 맥락에서 저작한 값이다.
- 외부 풍경 맵이다. **NPC 대화, 집 내부 이동 이벤트는 없다.** 꽃을 심은 흙 구획은
  재배 시스템이 작동하는 농장이 아니다. 물레방아도 정지 그래픽이다.

### 다음 작업의 입력과 저장

```bash
node scripts/content/read-slates-project.mjs output/slates-next/source
```

이 읽기 전용 명령은 최신 Supabase 문서와 SHA를 받아 저장한다. 이미 있는 스냅샷은 덮지 않는다.
새 마을 작업은 해당 스냅샷으로 시작하고, `build-slates-village-50.mjs`의 배치/조립을 참고해
**새 map id**를 만든다. 이 스크립트의 입력 경로는 이번 50×50 작업용으로 고정돼 있으므로
그냥 재실행해서 예전 root를 다시 저장하지 않는다. 저장기 `save-slates-village-50.mjs` 역시
이번 경로에 고정되어 있다. 다음 작업에서는 새 입력·출력 경로와 읽기 시점 SHA를 일치시킨다.
저장 성공만으로 끝내지 말고 같은 저장기의 root/미러 재로드 비교와 로컬 SQLite 재로드를 수행한다.
