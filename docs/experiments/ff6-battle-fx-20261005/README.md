> 아래 네 시안은 기준작이나 승인작이 아니다. 후속 저작은 `assistant-skills/pixel-dot-authoring`과

사용자가 FF6에서 참고하고 싶은 범위를 **그래픽: 마법·소환·타격 연출**로 선택했다.
현재 공용 연출의 대표 그림을 확인하고, 형태와 시간 흐름을 구분하는 네 가지 원본 도트 시안을 만들었다.

## 그림

- `preview.gif`: 네 시안의 합성 무대 재생. 각 칸은 독립적인 시안이며 네 공격이 동시에 실행되는 게임 화면이 아니다.
- `preview.png`: 효과마다 서로 다른 대표 시점을 고른 확인판.
- `*-comparison.gif`: 왼쪽 현재 대표 시트 / 오른쪽 새 시안. 같은 정수 2배, 실제 60ms 칸 간격. 화염·얼음·번개는 같은 골렘과 지면 위치로 비교한다.
- `sheets/*.png`: 128×128 원본 칸을 가로로 붙인 24칸 시트. 시트당 불투명 색 6~14색, 알파 0/255. `manifest.json`은 저장한 PNG 픽셀에서 확인한 값이다.

| 시안 | 그림의 단계 | 현재 비교 시트 |
|---|---|---|
| 홍염 기둥 | 땅의 불씨 수렴 → 서로 다른 높이의 불기둥 → 상승하는 연기·잔불 | `mage_fire_burst` |
| 빙정 파쇄 | 얼음 결정 성장 → 면의 균열 → 튀는 파편 | `mage_blizzard` |
| 창뢰 연타 | 푸른 전하 구체 → 세 번의 황색 낙뢰 → 잔전류 | `mage_chain_bolt` |
| 성익룡 소환 | 소환진 → 날개와 턱이 움직이는 용 → 브레스 → 소멸 | `monk_dragon_aura` |

비교는 서로 다른 기술의 **효과 그림** 비교다. 새 시안은 큰 상위 마법/소환을 위한 방향이며,
기본 마법보다 크거나 오래 재생된다는 사실이 품질 향상을 증명하지 않는다.
현재 비교 시트는 8~12칸, 시안은 24칸이므로 공통 2.4초 반복 안에서 효과가 끝나는 시각이 다르다.
GIF 인코더가 동일한 칸을 합칠 수 있으며 그 칸의 지속 시간은 보존한다.

## 참고와 범위

참고한 특징은 한정된 팔레트, 속성마다 다른 실루엣, 형태가 변하는 발동/착탄/잔상,
노란 낙뢰와 푸른 구체의 색 대비, 무대를 차지하는 소환자의 몸동작이다.
FF6의 실제 그림을 잘라 쓰거나 픽셀을 복사하지 않고 `render.py`의 좌표로 새로 그렸다.

- FF6 전투/소환 시스템의 원자료: [Square Enix FFVI Advance 설명서 사본](https://www.squarepalace.com/sites/default/files/pdf/ff6-gba-us-notice.pdf)
- 낙뢰의 색과 형태를 참고한 게임 장면: [FF6 썬더가 화면](https://blog.livedoor.jp/madoyuka/archives/26163290.html)
- 현재 도트 규격과 이전 비교의 한계: `openwiki/native-enemy-retirement.md`, `src/assets/retroClassSkills.ts`

이 폴더는 **검토용 시안**이다. 공용 효과 카탈로그나 실제 프로젝트에 등록하지 않았다.
시전자 동작, 피해 시점, 피격, 효과음, 화면 흔들림을 포함한 완성 전투 녹화가 아니며 GIF는 무음이다.
성익룡은 소환 실루엣과 몸동작의 시안이고, 브레스를 다른 적 위치까지 보내는 런타임 경로는 저작하지 않았다.
아직 FF6의 모든 마법이나 소환수에 대한 목록/영상 분석을 수행한 것은 아니다.

## 재생성

```bash
python3 docs/experiments/ff6-battle-fx-20261005/render.py
```

Python/Pillow와 기존 `scripts/asset-gen/pixel-fx/lib_mage.py`의 색인 캔버스를 쓴다.
원본 효과에는 확대·블러·안티앨리어싱을 적용하지 않고 확인판만 최근접 정수 2배로 표시한다.
기존 공용 골렘은 합성 무대의 비교 표적이다. 생성 결과는 이 폴더 안에만 쓴다.
앱 코드와 SQLite 정본은 변경하지 않았다. 세션 지침에 따라 gates/vitest/typecheck를 실행하지 않았다.
