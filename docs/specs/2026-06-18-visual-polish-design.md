- **날짜**: 2026-06-18
- **상태**: 설계 승인됨 → 구현 계획 단계로 이동
- **대상**: 기 구현된 RPG 메이커 MVP의 UI/UX 비주얼 업그레이드
- **선행 스펙**: `2026-06-18-rpg-maker-mvp-design.md`

## 1. 목표와 범위

### 1.1 핵심 문제
MVP의 뼈대(에디터/플레이어/이벤트/저장)는 완성됐으나, 현재 에셋은 `Graphics.generateTexture`로 그린 **절차적 블럭**이라 시각적으로 투박함. "이미지 리치하지 못하다"는 것이 가장 큰 비주얼 결함.

### 1.2 목표 (Goal)
1. **캔버스 에셋을 32비트 모던 픽셀 실제 이미지로 전환** — codex로 PNG 생성 → 정밀수정 → 파일로 저장 → 코드는 파일 로딩.
2. **"Play 모드를 켜면 진짜 예쁜 RPG" 달성** — 에셋 + 대사창 32비트 톤 정돈.
3. **codex 에셋 워크플로우(생성 → 정밀수정 → 교체)를 코드 구조가 자연스럽게 지원** — 에셋이 단순 PNG 파일로 존재하여 언제든 codex에 첨부·수정 가능.

### 1.3 비목표 (이번 패스 제외)
- 에셋 종류 대폭 확장 (타일 8종 → 20~30종). 파이프라인 검증 후 다음 단계.
- 캐릭터 종류 확장 (2종 → 5~8종).
- 에디터 UI까지 32비트/레트로 톤 통일 (B 안).
- 게임 무드 보드/마스터 팔레트/테마 시스템 (C 안).
- 쓰기 편의성/워크플로우 개선(단축키·실행취소 등) — A(쓰기편의)가 아닌 B(비주얼)에 집중.

### 1.4 핵심 결정 요약

| 결정 | 선택 | 이유 |
|---|---|---|
| 캔버스 비주얼 스타일 | **32비트 모던 픽셀** (스타듀밸리/RPG메이커 MZ 감성) | 해상도 높고 색 풍부, codex 결과 깔끔, "예쁜 RPG" 직결 |
| 에셋 범위 | **핵심 세트만** (타일 8종 + 캐릭터 2종 + 대사창) | 파이프라인 먼저 작게 검증 |
| 에셋 저장 방식 | **정적 PNG 파일** `public/assets/` | codex 정밀수정(이미지 첨부) 파이프라인과 직결 |
| 에디터 UI 톤 | **모던 다크 UI 유지**, 캔버스+대사창만 게임 톤 | 도구(에디터)와 결과물(게임 화면)의 분리 — 프로 도구 정석 |
| 작업 순서 | **에셋 → 캔버스 전환 → 대사창 → 에디터 정돈** | 임팩트 큰 에셋 먼저, 파이프라인 검증 우선 |

## 2. 아트 디렉션: 32비트 모던 픽셀

### 2.1 스타일 가이드
- **해상도**: 타일 32×32, 캐릭터 32×32 (프레임당)
- **색조**: 풍부하지만 통일된 팔레트. 과포화 금지. 부드러운 음영(gradient shading) 허용.
- **톤**: 따뜻하고 친근한 스타듀밸리/RPG메이커 MZ 감성. 어둡고 진한 판타지 톤 아님.
- **테두리**: 타일 경계에 안티앨리어싱 없이 깔끔하게 맞닿음(타일 seam 방지).
- **일관성**: 8종 타일 + 2종 캐릭터가 **동일 톤/팔레트/음영 스타일**. 한 에셋만 다르게 튀면 안 됨.

### 2.2 codex 프롬프트 템플릿 (에셋 생성용)
```
32-bit pixel art, modern JRPG style (Stardew Valley / RPG Maker MZ aesthetic),
warm and friendly tone, soft gradient shading, no anti-aliasing on tile edges,
[대상: tileset/sprite], [상세: 8 tiles in a row / 4 directions × 2 frames],
top-down view, consistent palette across all assets, 32px per unit
```

## 3. 에셋 파일 구조

### 3.1 디렉토리
```
public/assets/
  tiles_default.png      # 타일셋: 8종을 한 행(8×1)으로 나열, 타일당 32px → 256×32
  hero.png               # 캐릭터: 4방향×2프레임 (2열×4행), 32px → 64×128
  npc_villager.png       # NPC: 동일 레이아웃
  dialogue-frame.png     # 대사창 프레임 (선택, 9-slice 가능한 테두리 텍스처)
  MANIFEST.md            # 에셋별 생성 프롬프트·버전·수정 히스토리
```

### 3.2 그리드 레이아웃 규칙 (코드가 가정하는 구조)
- **타일셋**: 가로 8열 × 세로 1행. 인덱스 0~7 = `TILE.GRASS..STAIRS` 순서 (기존 상수 유지).
  - 데이터 모델/에디터/저장 스키마 **변경 없음**.
- **캐릭터**: 가로 2열(걷기 프레임 0,1) × 세로 4행(방향: down=0, left=1, right=2, up=3).
  - 기존 `bundled.ts`의 `spriteFrameIndex(dir, frm)` 로직과 동일 → 그대로 재사용.

### 3.3 매니페스트 (`MANIFEST.md`)
각 에셋에 대해:
- 파일명
- 최초 생성 프롬프트
- 버전 (v1, v2, …)
- 정밀수정 히스토리 ("v2: 물 타일 파도 진하게, codex에 v1 첨부 후 수정")
- codex 재수정 시 참고용

## 4. codex 에셋 워크플로우

### 4.1 생성 사이클 (수동, 코드가 지원)
```
1. 프롬프트 작성 (§2.2 템플릿 + 대상 상세)
2. codex 호출 → PNG 생성
3. [정밀수정] 결과 PNG를 codex에 다시 첨부 → 부분 수정 요청 → 새 PNG
   예: "이 타일셋의 물 타일을 더 파도치게, 나무 잎을 진한 초록으로"
4. public/assets/ 덮어쓰기
5. 코드 재빌드 → 자동 로드 (Vite HMR)
6. MANIFEST.md 업데이트 (버전·수정내역)
```

### 4.2 핵심 원칙
- 에셋은 **단순 PNG 파일**. base64 인라인 금지. (codex 정밀수정 파이프라인이 파일 기반이어야 자연스럽기 때문)
- 파일명 고정. 버전은 매니페스트로 관리 (코드는 항상 동일 파일명 로드).
- 부분 재생성 가능: 타일셋 전체 재생성 대신, codex에 기존 PNG를 넣고 특정 타일만 수정.

## 5. 코드 전환: 절차적 → 파일 로딩

### 5.1 `assets/bundled.ts` 재구성
- **제거**: `generateTileset`, `generateHero` (Phaser Graphics 생성 로직)
- **변경**: `ensureBundledTextures`가 `this.load.image(...)` 기반으로 전환
  ```ts
  // preload에서 파일 로드
  this.load.image(TEX_TILESET, "assets/tiles_default.png");
  this.load.image(TEX_HERO, "assets/hero.png");
  this.load.image(TEX_NPC, "assets/npc_villager.png");
  this.load.image(TEX_DIALOGUE_FRAME, "assets/dialogue-frame.png");
  ```
- **유지**: 타일 프레임 등록(`tile_0`..`tile_7`) 로직 — 텍스처 소스만 파일로 바뀌고 프레임 등록은 동일.
- **유지**: `TILE_SIZE`, `TILES_PER_ROW`, `SPRITE_COLS`, `SPRITE_ROWS` 상수 (그리드 레이아웃 호환).

### 5.2 폴백 (에셋 미생성 시 안전망)
- 에셋 파일이 없는 상태(또는 로드 실패)에서 앱이 깨지지 않도록, 기존 절차적 생성을 **폴백으로 유지**:
  - `ensureBundledTextures`가 파일 로드 실패 시 콘솔 경고 + 절차적 생성 폴백.
  - codex로 실제 에셋 생성 완료 후 폴백은 제거 대상(명시).
- 이유: 첫 에셋이 만들어지기 전까지 dev 서버가 검은 화면이 되면 안 됨.
- **제거 시점**: Phase V2에서 에셋 3종(타일셋·hero·npc)이 모두 정상 로드 확인된 후, 같은 Phase 내에서 폴백 코드 제거. dialogue-frame은 V3에서 다루므로 V3 종료 후 최종 확인.

### 5.3 preload 패턴 (Phaser)
- `EditScene.preload` / `PlayScene.preload`에서 에셋 로드.
- `create`에서 프레임 등록 + 캔버스 렌더.
- 기존 `ensureBundledTextures(scene)` 인터페이스는 유지하여 호출부(EditScene/PlayScene) 변경 최소화.

## 6. 캔버스 렌더 정돈

### 6.1 타일 렌더
- `tileSourceXY` 기반 크롭 또는 프레임 등록(`tile_<i>`) — 현재 프레임 방식 유지.
- 에셋이 실제 이미지가 되면 자동으로 32비트 톤 적용 (코드 변경 최소).

### 6.2 캐릭터 렌더
- `PlayScene`의 스프라이트 프레임 인덱스(`DIR_ROW * SPRITE_COLS + walkFrame`) 그대로.
- 걷기 애니메이션 타이밍(90ms 토글) 유지 — 에셋 품질에 맞춰 미세조정 가능.

### 6.3 픽셀 퍼펙트 렌더링
- Phaser `roundPixels: true` 설정 추가 (픽셀 아트 흐림 방지).
- 캔버스 이미지 렌더링 시 `image-rendering: pixelated` CSS (확대 시 뭉개짐 방지).

## 7. 대사창 32비트 톤 정돈

### 7.1 비주얼
- 어두운 반투명 패널(현행 유지) + **대사창 프레임 텍스처**(`dialogue-frame.png`)로 테두리 장식.
- 스피커 이름: 작은 픽셀풍 뱃지.
- 본문: 가독성 높은 시스템 폰트 유지 (픽셀폰트는 가독성 해침 → 선택적).
- 선택지 버튼: 프레임 텍스처와 조화되는 둥근 보더.

### 7.2 9-slice 프레임 (선택 구현)
- `dialogue-frame.png`가 9-slice 가능 텍스처(모서리+가장자리+중앙)면, 대사창 크기에 맞춰 테두리가 늘어남.
- 구현 복잡도 있으면 단일 텍스처 + CSS border-image로 대체(MVP 단계).

## 8. 에디터 UI 정돈 (모던 다크 유지, 캔버스와 분리)

### 8.1 정돈 범위 (게임 톤 적용 안 함)
- 색감 통일: 기존 CSS 변수(`--bg`, `--accent` 등) 정제. 과도한 대비 완화.
- 타이포: 폰트 크기/행간 정리. 섹션 헤더(`h3`) 일관성.
- 여백: 패널 내 패딩/간격 정돈.
- 아이콘: 도구/버튼 이모지(✏🚧💬) → 일관된 아이콘 세트(계조 통일).

### 8.2 명시적 비적용
- 패널 보더·버튼·폼 입력에 픽셀 스킨/픽셀폰트 입히지 않음 (가독성 해침).
- 에디터는 시스템 UI로 두어 텍스트 밀도 높은 편집(명령 리스트·대사 입력)이 편하게.

## 10. 리스크 & 대응

- **에셋 스타일 불일치**: codex 여러 번 호출 시 톤이 흔들릴 수 있음 → 동일 프롬프트 템플릿(§2.2) + 매니페스트로 스타일 기록·유지.
- **타일 seam**: 인접 타일 경계가 어긋나면 틈 보임 → 프롬프트에 "no anti-aliasing on tile edges" 명시 + 정밀수정으로 보정.
- **캐릭터 프레임 어긋남**: 그리드 레이아웃(2×4)이 어긋나면 깨짐 → codex에 레이아웃 명시 + 정밀수정으로 맞춤.
- **폴백 영구 잔류**: 에셋 완성 후에도 폴백 코드가 남을 수 있음 → V2 완료 후 명시적 제거 태스크.
- **9-slice 복잡도**: 대사창 프레임 9-slice 구현이 까다로우면 CSS border-image로 회귀 (V3에서 결정).

---

## 11. 완료 기준 (Definition of Done)

1. Play 모드 진입 시 캔버스에 **실제 32비트 픽셀 에셋**(타일+캐릭터)이 렌더됨.
2. 대사창이 32비트 톤 프레임과 어우러져 "게임 화면" 느낌.
3. 에디터 UI는 정돈되었으나 여전히 모던 다크(게임 톤 아님).
4. `public/assets/`의 PNG 파일을 codex로 정밀수정 → 덮어쓰기 → 자동 반영 사이클이 동작.
5. `MANIFEST.md`에 각 에셋의 프롬프트·버전 기록.
6. 기존 MVP 기능(저장·이벤트·멀티맵)이 비주얼 전환 후에도 회귀 없음.
7. 기존 단위 테스트(43개) 전부 통과 유지.
