# RM2003 이벤트 명령 버튼 동작 문서

## 목적

이 문서는 이벤트 편집기의 `@>` 줄을 더블클릭했을 때 열리는 1~4번 이벤트 명령 창을 실제 기능과 연결하기 위한 작업 기준이다. UI 문구는 한글을 유지하고, 배치는 RPG Maker 2003의 `Event Command` 창을 따른다.

## 현재 동작 경로

1. `src/editor/panels/eventEditor/content.ts`
   - 실행 내용 영역 끝에 `@>` 빈 명령 줄을 렌더링한다.
   - `@>`를 더블클릭하면 `openEventCommandPicker()`를 호출한다.
   - 선택된 명령은 `actions.addCommand([], command)`로 현재 이벤트 페이지의 루트 명령 목록에 추가된다.

2. `src/editor/panels/eventEditor/commandPicker.ts`
   - 1~4 탭과 명령 버튼 목록을 정의한다.
   - `kind`가 있는 버튼만 실제 추가 버튼이다.
   - `kind`가 없는 버튼은 RM2003 목록에는 보이지만 아직 비활성 버튼이다.

3. `src/editor/eventCommandFactory.ts`
   - `newCommand(kind)`가 새 명령의 기본 데이터를 만든다.
   - 버튼을 실제 동작시키려면 여기에서 해당 `Command.kind`의 기본값이 반드시 생성되어야 한다.

4. `src/project/types/events.ts`
   - 모든 이벤트 명령의 직렬화 타입 `Command`를 정의한다.
   - 새 명령을 추가하려면 이 union에 타입을 먼저 추가해야 한다.

5. 명령별 편집 UI와 런타임
   - 편집 UI는 이벤트 명령 렌더러 및 세부 편집 컴포넌트에서 처리한다.
   - 플레이 모드에서 실제 효과가 있어야 하는 명령은 런타임 실행기에도 반영해야 한다.

### 4번 탭

4번 탭은 RM2003 목록을 보여주는 상태이며, 현재 대부분 비활성이다. 우선순위는 낮지만 RPG Maker 2003 느낌을 맞추기 위해 목록은 유지한다.

## 비활성 버튼을 실제 기능으로 만드는 순서

1. 타입 추가
   - `src/project/types/events.ts`의 `Command` union에 새 `kind`와 필요한 필드를 추가한다.
   - 예: 장비 변경이면 actorId, slot, equipmentId, operation 같은 필드가 필요하다.

2. 기본 명령 생성
   - `src/editor/eventCommandFactory.ts`의 `newCommand(kind)`에 기본값을 추가한다.
   - 기본값은 빈 문자열만 넣고 끝내지 말고, 편집 UI가 열렸을 때 깨지지 않을 최소 데이터여야 한다.

3. 명령 버튼 연결
   - `src/editor/panels/eventEditor/commandPicker.ts`에서 해당 버튼에 `kind`를 지정한다.
   - 연결 전에는 disabled로 보여야 하고, 연결 후에는 클릭 가능한 버튼으로 바뀌어야 한다.

4. 세부 편집 UI 추가
   - 명령 목록에 추가된 후 사용자가 값들을 바꿀 수 있어야 한다.
   - RM2003 기준으로 별도 대화상자가 필요한 명령은 작은 서브다이얼로그로 분리한다.

5. 직렬화/저장 확인
   - Supabase 저장 프로젝트에서 명령 데이터가 그대로 저장/복원되어야 한다.
   - 새 필드가 optional인지 required인지 명확히 정한다.

6. 런타임 실행
   - 플레이 모드에서 효과가 필요한 명령은 런타임 실행기에 반영한다.
   - 편집 전용 명령이 아니라면 “추가만 됨” 상태로 끝내면 안 된다.

7. e2e 기준
   - `@>` 더블클릭으로 명령창 열림.
   - 해당 탭으로 이동.
   - 버튼 클릭.
   - 이벤트 명령 목록에 추가됨.
   - 세부 편집 후 저장/복원됨.
   - 플레이 모드에서 효과가 필요한 명령은 실제 상태 변화까지 확인.

## 우선 구현해야 할 버튼

1. 장비 변경
   - DB에 장비/배우/직업 데이터가 있으므로 가치가 높다.
   - `changeEquipment` 타입을 새로 두는 편이 좋다.

2. HP/MP/상태/모두 회복
   - 전투와 상점/여관 흐름에 직접 필요하다.
   - `changeActorHp`, `changeActorMp`, `changeState`, `recoverAll`로 분리하는 편이 안전하다.

3. 주인공 이름/별명/그래픽/얼굴 변경
   - NPC/이벤트 연출에서 자주 쓰인다.
   - DB의 actor/resource 참조 검증과 같이 가야 한다.

4. 화면 효과
   - 화면 색조, 플래시, 흔들기, 날씨, 그림 이동, 애니메이션 표시는 연출 핵심이다.
   - 런타임 오버레이와 애니메이션 재생기가 필요하다.

5. 위치/탈것/메뉴/세이브 접근
   - RPG2003 parity에는 중요하지만, 현재 게임 루프 기초가 먼저 안정되어야 한다.

## UX 규칙

- `@>` 줄은 항상 명령 목록의 마지막 빈 줄처럼 보여야 한다.
- 더블클릭은 명령창을 열고, Enter도 같은 동작을 해야 한다.
- 명령창은 1~4 탭 구조를 유지한다.
- 비활성 버튼도 목록 위치를 유지하되 회색 처리한다.
- 버튼이 실제 동작하기 전까지는 임의의 가짜 명령을 넣지 않는다.
- 창 제목, 버튼, 필드명은 한글이어야 한다.
- RM2003 스타일 값은 `--rm2k3-event-command-*` CSS 토큰으로 관리한다.

## 완료 판정

새 버튼을 “작동한다”고 부르려면 아래를 모두 만족해야 한다.

- 버튼이 disabled가 아니다.
- `Command.kind` 타입이 있다.
- `newCommand(kind)`가 기본 데이터를 만든다.
- 명령 목록에 추가된다.
- 세부 편집 UI에서 주요 필드를 바꿀 수 있다.
- 프로젝트 저장/복원 후 데이터가 유지된다.
- 플레이 모드에서 해당 명령의 효과가 관찰된다. 단, 순수 편집용 명령은 예외를 문서에 명시한다.
