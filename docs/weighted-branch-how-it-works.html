가중 분기
이 에디터에서 어떻게 도는지

스크린샷의 가중 분기 창은 “확률 분기 블록”이 아니라, 가중치 표를 굴려 결과 인덱스를 변수에 쓰는 명령이다. 실제 if/else 갈래는 그 다음 조건 분기가 맡는다.

1. 에디터 창 해부

스크린샷 UI를 그대로 재구성. 왼쪽이 입력, 오른쪽이 미리보기 요약이다.

가중 분기

×
명령 카탈로그
M2/현대 명령
가중치 표 · table
success=1 failure=1

한 줄 = 한 선택지. 이름=가중치 형식.

결과 변수 · resultVariableId
loot_roll

비우면 롤은 하지만 변수에 안 남김.

M2/현대 명령
가중 분기 : table: success=1 failure=1

확인을 누르면 이벤트 목록에 한 줄 명령으로 들어간다. 이 순간에는 아직 난수를 굴리지 않는다 — 플레이/테스트 실행 시 굴린다.
1
가중치 표 (table) 줄바꿈으로 분리된 label=weight 목록. 라벨은 사람용, 엔진은 = 오른쪽 숫자만 읽는다.
2
결과 변수 (resultVariableId) 선택된 줄의 0-based 인덱스가 들어간다. success면 0, failure면 1.
3
미리보기 패널 저장 직전 요약 문자열. 실제 확률 계산/검증 UI는 아니다.

2. 실행 파이프라인

이벤트 인터프리터가 이 명령에 도달했을 때의 경로.

①
이벤트 도달 페이지 커맨드 목록에서 Weighted Branch 실행
②
표 파싱 줄 분리 → = 뒤 숫자 → 양수만 유지
③
misc RNG nextSessionRandom(session, "misc")
④
가중 선택 누적 감산 커서로 인덱스 결정
⑤
변수 기록 variables[id] = index
weights = [1, 1] success, failure
→
total = 2 양수 가중치 합
r = misc() × total 0 ≤ r < total (사실상)
→
index ∈ {0, 1} 변수에 저장되는 값

세션 RNG는 encounter / battle / movement / misc 네 갈래다. 가중 분기는 misc만 소모한다. 그래서 전투 난수·인카운트 난수와 섞이지 않고, 세이브/로드 후에도 같은 시퀀스를 이어갈 수 있다.

3. 가중 선택 시각화

기본 표 50:50 과 테스트에서 쓰는 rare/common 10:90 비교.

기본값 · success=1 / failure=1

success 50%
failure 50%
success
1 / 2
→ 변수 0
failure
1 / 2
→ 변수 1
1:1 균등 분기

바늘이 멈추는 구간 = 선택 인덱스

전리품 예 · rare=1 / common=9

rare 10%
common 90%
rare
1 / 10
→ 변수 0
common
9 / 10
→ 변수 1
1:9 희귀 드롭

테스트 픽스처: loot_roll ∈ {0, 1}

커서가 가중치를 깎아 먹는 방식

cursor = random × total 후, 앞에서부터 weight를 빼며 0 이하가 되는 순간 그 인덱스를 고른다.

0 · rare=1
1 · common=9
1
총합 10, 난수 0.73 → cursor = 7.3
2
index 0 (1) 차감 → 6.3 > 0, 계속
3
index 1 (9) 차감 → −2.7 ≤ 0 → 선택 1 (common)

4. 코드가 실제로 하는 일

src/player/interpreter/m2ModernRuntime.ts — 에디터 필드를 런타임 값으로 환원하는 핵심.

// 1) 명령 디스패치 case "Weighted Branch": recordWeightedBranch(session, runtime, fields); return true; // 2) 표 → 가중치 배열 → 인덱스 function selectWeightedIndex(session, table) { weights = table .split(/\r?\n/) .map(line => Number(line.split("=").at(1) ?? 0)) .filter(v => Number.isFinite(v) && v > 0); if (weights.length === 0) return 0; total = sum(weights); cursor = nextSessionRandom(session, "misc") * total; for (index, weight of weights) { cursor -= weight; if (cursor <= 0) return index; } return lastIndex; } // 3) 부작용 runtime.session.weightedBranch = { table, resultVariableId }; if (variableId) session.variables[variableId] = selectedIndex;
입력 줄 파싱 결과 처리 인덱스
success=1 1 KEEP 0
failure=1 1 KEEP 1
broken 0 (NaN→0) DROP —
zero=0 0 DROP —
bonus=2.5 2.5 KEEP n
중요: 라벨 문자열(success/failure)은 런타임 분기 키로 쓰이지 않는다. 엔진은 오직 줄 순서 인덱스만 변수에 넣는다. 줄 순서를 바꾸면 기존 조건 분기 값이 어긋난다.

5. 이벤트 작성 패턴

가중 분기 단독으로는 대사가 안 갈라진다. “롤 → 변수 비교 → 본문” 3단이 정석.

이벤트 커맨드 목록 · 도박 / 보물상자 예
00
◆ 가중 분기
table: success=1 / failure=1
결과 변수 chest_roll
01
◆ 조건 분기
변수 chest_roll == 0
02
◆ 메시지
“반짝이는 검을 손에 넣었다!”
03
◆ 아이템 증가
검 × 1
04
◆ 그 외의 경우
05
◆ 메시지
“상자 안은 먼지뿐이었다…”
06
◆ 분기 종료

왜 이렇게 쪼개나?

가중 분기는 RM2000/2003의 “확률 분기 블록”처럼 들여쓰기 가지를 자동 생성하지 않는다. 현대 명령(M2)으로 결과 값만 생산하고, 기존 조건 분기(fork) 인프라에 연결한다.

3갈래 이상

표에 줄을 더 넣으면 된다. crit=1 / hit=6 / miss=3 → 변수 0/1/2. 조건 분기를 연쇄하거나 변수 비교를 여러 번 걸면 된다.

재현 가능한 난수

같은 세션 시드 + 같은 misc 소비 순서면 같은 결과가 나온다. 세이브 직후 다시 로드해도 misc 스트림 상태가 복원된다.

6. 함정 / FAQ

자주 헷갈리는 지점만 압축.

Q. success/failure 문자열이 조건인가?

아니다. 라벨은 주석에 가깝다. 조건에는 숫자 인덱스를 써야 한다.

Q. 결과 변수를 비우면?

롤은 수행되고 m2Runtime.session.weightedBranch에도 기록되지만, 이후 분기할 값이 없다. 사실상 관측 불가.

Q. 가중치 0 / 빈 표?

양수 가중치가 하나도 없으면 인덱스 0을 반환한다. 조용히 실패하는 편.

Q. 전투 명중률이랑 같은 RNG?

아니다. 전투는 battle, 인카운트는 encounter, 가중 분기는 misc.

Q. 줄 순서를 바꿨더니 보상이 바뀜

정상. 인덱스가 라벨이 아니라 순서에 묶여 있다. 표 수정 시 조건 분기 값도 같이 점검.

Q. 에디터 미리보기가 확률을 보여주나?

현재는 요약 텍스트만. 확률 바/검증 UI는 없고, 플레이 실행 때 비로소 굴린다.

한 줄 정신 모델: 가중 분기 = “주사위를 굴려 번호를 변수에 적어 두는 스탬프”. 갈래 연출/보상/대사는 그 번호를 읽는 다음 명령들이 한다.
