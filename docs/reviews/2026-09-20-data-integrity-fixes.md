## 구조와 검증

- `databaseRecordReferences.ts`는 주어진 프로젝트를 검사하는 순수 계층이다.
  UI의 `databaseReferences.ts`는 현재 store를 전달하고 AI 도구는 자기 draft를 전달한다.
  명령 스캐너도 이벤트 이름을 프로젝트 계층에서 가져와 도구에서 UI/store를 로드하지 않는다.
- 아이템 참조는 로더의 기존 수집기를 재사용했다. 전체 FK 검증을 생성하는 시스템으로 바꾼 것은 아니다.
- `test/reviewDataIntegrity.test.ts`에 삭제 차단, 미사용 판정, 부분 갱신, 저장/재로드 계약 10개를 추가했다.
  저장소 지시에 따라 **실행하지 않았다**. gates/vitest/전체 typecheck도 실행하지 않았다.
- 변경 TypeScript 15개 파일의 문법 변환 검사: 진단 0. 이는 의미적 타입 검사나 테스트 통과를 뜻하지 않는다.
- `git diff --check` 확인.
- Chromium 1280×900에서 실제 편집 컴포넌트를 직접 마운트하고 입력한 결과:
  - 동영상 기본값 true/true, 끈 뒤 저장 false/false.
  - 첫 스위치만 false로 변경해도 `[sw_0001, sw_0002]` 순서 유지.
  - 첫 목적지 X를 3으로 수정해도 두 번째 목적지와 두 switchId 유지.
  - [관측값](2026-09-20-data-integrity-evidence/observations.json), [화면](2026-09-20-data-integrity-evidence/editor-components.png).
  - 이 화면은 CSS 없는 독립 컴포넌트 확인이며, 전체 편집기 레이아웃/런타임 QA 증거가 아니다.
    메모리 검증 fixture에서 remote persistence를 끈 상태로 수행했으며 게임 콘텐츠를 새로 배포하거나 DB에 쓰지 않았다.
