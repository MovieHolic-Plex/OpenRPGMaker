게임 오버도
제작자가 만드는 콘텐츠.

한 프로젝트에 여러 게임 오버를 저장하고, 사건마다 다른 항목을 실행합니다. 화면 분위기와 패배 이후 처리를 분리해 조합합니다.

자료집 → 시스템 → 게임 오버에서 만들고, 이벤트 명령의 실행할 게임 오버에서 고릅니다.

01 · 추격자에게 붙잡힘

정적 1초 → 직접 쓴 장면 → 공포형 제목 → 재시도 선택.

02 · 전투 전멸 · 회복소

암전 → 패배 메시지 → 파티 회복 → 지정 위치 귀환. 진행 변수 37 유지, 귀환 후 이동 확인.

03 · 시간 초과

암전 → 독립된 메시지 → 타이틀 자동 복귀. 재시도 메뉴를 거치지 않는 결말.

이름별로 만들고, 이벤트에서 선택

확인한 범위

  • 세 항목을 브라우저 UI로 저작한 뒤 serialize/deserialize 왕복에서 보존.
  • 복제본 수정이 원본에 영향을 주지 않음. 기본·참조 중인 항목 삭제 차단.
  • 이벤트 선택 ID가 메시지 편집 후에도 유지. 명시 ID 및 기본값 호출 확인.
  • 출하 경로인 독립 player.html에서 실제 실행. 게임 오버 뒤 변수 777 명령 미실행.
  • 전투 이벤트에 지정한 항목도 전달됩니다. canLose 전투에서 명시적 게임 오버를 호출하고 이후 명령이 중단됨을 확인했습니다.
  • 메인 저작·플레이 브라우저 page error 0건. 증거 메타데이터.

GIF는 실제 게임 화면 녹화입니다(1배속·12fps·무음). QA 프로젝트는 메모리 fixture이며 SQLite 정본 저장 증거가 아닙니다. Vitest·전체 typecheck·gates는 이번 세션에서 실행하지 않았습니다.
