01지금 무엇이 허접한가 — 실측 10건

스크린샷은 scripts/capture-ai-assistant-current.mjs 로 재현한다(포트만 바꾸면 된다). 번호는 아래 목록과 같다.

  • 1표면이 둘이다. 기록 카드(`.ai-chat-body`)와 입력 캡슐(`.ai-command-bar`)이 형제로 떠서 가운데 맵이 비친다. 하나의 도구로 읽히지 않는다.
  • 2본문이 모노스페이스. 조수 답변·사용자 발화 전부 --font-mono. DESIGN.md 는 「RM 스타일 @> 명령 로그」를 이미 폐기 방향으로 적었지만 표면은 그대로다. 한국어 모노는 가독성이 가장 나쁜 조합이다.
  • 3글리프 버튼 열. ▼(접기) +(새 대화) 🕒(이전 대화) ☰(더보기) ⌾(성향) 「맥락 —」. 라벨 없음, 이모지·기호 굵기 제각각, 호버 전엔 뜻을 알 수 없다.
  • 4크롬 소음. − 100% + 기록 줌 스테퍼와 드래그 핸들이 기록 카드 상단을 점유한다. 대화 UI 에 줌은 일반적 기대가 아니다.
  • 5시스템 행이 대화에 섞인다. 「이전 대화를 열었습니다.」 가 조수 발화와 같은 모양으로 들어온다.
  • 6작업이 안 보인다. 툴 호출 4개가 작업 1 ▸ 로 접히고, 펼쳐도 함수 이름(place_npc)이다. 진행 중에는 캡슐에 아무 변화가 없다(하단 「시뮬레이션」 참고).
  • 7추천이 따로 뜬다. 팝오버가 캡슐과 분리된 상자다. 안내 문장(「길이 없어요…」)은 좋은 신호인데 단어 칩 6개가 그 아래를 차지한다.
  • 8힌트 텍스트가 자리를 먹는다. 「Enter 전송 · Shift+Enter 줄바꿈」 156px 가 포커스마다 액션 행에 나타난다(코드 주석도 이를 인정한다).
  • 9메뉴가 비어 있다. 「대기 화면」 3분기(추천 함께/조수만/입력창만)는 설정 항목인데 메뉴 최상단을 차지하고, 항목엔 아이콘·부가 정보가 없다.
  • 10변경 카드가 상자 속 상자다. 배지·칩·썸네일·버튼이 기록 카드 안에 다시 테두리로 싸여 있고 폭 596px 중 썸네일은 183px.

그 밖의 표면

측정 주의. 「턴 진행」 사진(19-turn-running-sim.png)은 실제 LLM 없이 is-turn-running 클래스만 붙인 시뮬레이션이다. 결과는 완료 상태와 픽셀 단위로 같았다 — 상태 글자(ai-status)가 is-assistant-idle 에서 숨겨지기 때문이다. 실제 턴에서는 액션 행 오른쪽에 작은 상태 글자가 나온다. 「진행 중 표시가 약하다」는 사실이고 「없다」는 과장이다.

02설계 원칙 5

P1 · one instrument표면은 하나

대화·작업·결과·입력이 같은 유리판 위에 있다. 팝오버는 데크에 6px 붙어서 뜨고 닫히면 hidden(투명 전면 레이어 금지 — 2026-08-19 히트테스트 P0 규칙 유지).

P2 · show the work맵에서 한 일은 맵으로 보인다

모든 공간 작업 행에 맵 칩(해당 좌표 46×32 크롭 + 핀)이 붙고, 결과는 「지금 / 적용 후」 영수증으로 남는다. 이 두 가지가 이 제품만의 서명이다.

P3 · human labels사람 말로 부른다

place_npc → 「상인 배치」, find_open_area → 「빈 자리 찾기」. 아이콘은 Lucide 계열 stroke 1.75 SVG 한 세트(이모지·기호 글리프 0).

P4 · state is visible상태가 보인다

유휴·진행·확인 필요·완료·오류 다섯 상태가 점 색 + 문장 + (진행 시) 상단 2px 헤어라인으로 구분된다. 접힌 알약도 같은 다섯 상태를 든다.

P5 · nothing lost기능은 하나도 잃지 않는다

testid 계약과 진입점 전부 보존. 자리만 바뀐다. 「진입점은 여러 곳에 둬도 된다」(좌측 사이드바 교훈) — 되돌리기는 영수증 카드와 ⋯ 메뉴 두 곳.

P0 · keep the locks이미 잠긴 결정은 지킨다

얼굴 없음 · 도크 하나(float) · 캔버스 우선 · 유리 알파 ≥ .78(제안 .90) · saturate ≤ 1.08 · 유리 위 보조 글자는 --text-2. 유일한 재검토 요청은 38px 상태 레일(7절 D1).

07감독 결정 요청

아래 여섯 가지는 제안대로 가도 되지만, 이전 지시와 부딪히거나 취향이 갈리는 지점이라 먼저 답을 받고 구현하겠다.

D1
38px 상태 레일을 둔다

2026-08-28 「헤더 없는 유리」 지시와 충돌한다. 그때 헤더는 73px 에 얼굴 + ☰ 둘이었다. 이 레일은 상태(점·문장·진행선) + 새 대화·이전 대화·⋯·접기 넷이고 유휴에서는 없다. 추천: 둔다. 거절 시 대안: 상태 문장을 컴포저 행 왼쪽에, 아이콘 넷은 ⋯ 하나로.

D2
사용자 발화는 오른쪽 인디고 말풍선

도구 UI 에서는 좌측 웰(전폭)도 흔하다. 오른쪽 정렬은 역할 구분이 빠르고 조수 산문이 왼쪽 정렬로 넓게 흐른다. 추천: 오른쪽 말풍선.

D3
완료된 작업 그룹은 자동으로 접는다

진행 중은 펼침, 완료는 한 줄 요약(라벨 화살표 연결). 항상 펼침이면 영수증이 밀린다. 추천: 자동 접힘 + 「펼치기」.

D4
모델 이름을 컴포저에 노출

「Gemini 3.7 Flash ▾」 를 보내기 왼쪽에. 초보 모드에서는 숨기고 표준·전문가에서만 보일 수도 있다. 추천: 표준 이상에서 노출.

D5
추천의 출처를 맵 진단으로 바꾼다

지금 예제 칩(길·NPC·상점·상자·집·퀘스트)은 맵과 무관한 고정 단어다. 제안 행은 맵 검사(끊긴 길, 상점 0, 빈 자리)에서 나온 문장으로 바꾸고 감독 프롬프트 칩은 그대로 앞에 둔다. 추천: 진단 기반. 진단 소스는 기존 검사(맵 검사·「길이 없어요」 힌트)를 쓴다.

D6
「대기 화면」 3분기를 설정으로 옮긴다

추천 함께 보기 / 조수만 / 입력창만 은 취향 설정이다. 메뉴 최상단에서 설정 모달로 옮기고 기본값은 「추천 함께 보기」. 추천: 이동. 기능은 유지된다.
