Adversarial product review · 2026-07-31

“만들 수 있다”와
“끝까지 만들 수 있다”는 다르다

RPG ZZU 에디터를 초보 저작자·파워 유저·런타임 소비자 관점에서 공격적으로 검증했다. 정적 코드 감사만 하지 않고 Playwright로 실제 UI를 열고, 모드별 노출량·키보드 접근성·화면효과 픽셀 변화·데이터베이스 필드 도달성을 측정했다.

최종 판정: 짧은 2D JRPG, 대화/선택지/전투/상점/맵 전이/날씨/화면효과를 갖춘 1–3시간 규모 게임은 충분히 만들 수 있다. 하지만 대형 게임의 반복 저작, 초보자의 첫 이벤트 생성, 장비 고급 규칙의 신뢰성에서 UX 부채가 폭발한다. 런타임 천장보다 저작 UX 천장이 먼저 온다.

1. 결론부터: 어디까지 만들 수 있나

현실적으로 가능

완성 가능한 범위

  • 타일맵 기반 JRPG/어드벤처
  • 대화, 선택지, 스위치·변수, 조건분기
  • 맵 전이, NPC 이동, 컷신, 상점·여관
  • 턴제/액션 전투와 상태·스킬·아이템
  • 색조, 플래시, 흔들기, 날씨, 화면 숨김
  • 3–10개 맵, 수십 이벤트의 짧은 상용 데모
위험 구간

깨지기 시작하는 범위

  • 수백 이벤트를 반복 생산하는 장편 RPG
  • 양손무기·장비 상태부여 등 고급 장비 규칙
  • 기본 모드만으로 처음부터 끝까지 저작
  • UI에서 만든 모든 DB 옵션이 런타임에 반영된다는 기대
  • 캔버스 직접 조작을 자동 회귀검증하는 파이프라인

2. 첫 5분 UX: 친절한 척하면서 핵심을 감춘다

개선 반영: 기본 모드에도 키보드로 실행 가능한 테스트 플레이 버튼이 유지된다. 간결한 저작 표면에서도 만들기 → 실행 → 확인 루프가 끊기지 않는다.

3. 이벤트 저작: 엔진보다 발견성이 문제다

이벤트 레이어 단일 클릭은 좌표 선택, 명시적 CTA는 이벤트 생성, 더블클릭은 기존 이벤트 즉시 편집으로 역할을 분리했다. 숨겨진 더블클릭 관습에만 의존하지 않는다.

캔버스 저작 E2E

빈 프로젝트에서 첫 이벤트 선택·생성·대사 저작·로컬 저장·재로드·실제 선택 이벤트 플레이까지 자동 증명한다.

키보드 접근성

기본 모드 테스트 버튼은 Enter로 실행되며, 정보용 partial 명령도 포커스와 설명을 유지한다.

4. 런타임 화면효과: 의심했지만 실제로는 전부 동작했다

처음엔 세션 상태만 기록되고 화면엔 반영되지 않는다고 의심했다. 계측을 고쳐 효과 지속 중 여러 프레임을 캡처하자 가설이 틀렸음이 드러났다. 색조·플래시·흔들기·날씨·화면 숨김 모두 실제 픽셀을 바꾼다. 이 에디터의 런타임은 UI보다 강하다.

5. 125개 커맨드: 범위와 경계를 함께 노출한다

125M2 카탈로그
124runtime-full 표시
84범용 m2Command 처리
18부분 지원 안내 명령

메인 피커는 선택 가능한 명령뿐 아니라 부분 지원 명령도 검색 가능하게 보여준다. 각 행의 지원 수준과 실행 소유자는 COMMAND_GUARANTEES에서 파생되며, 선택 불가 행은 포커스 가능한 설명과 실제 대체 저작 경로를 제공한다.

발견성 개선

advanceTime, advanceCropGrowth, setTime, sleepUntilMorning, promoteActor, changeFriendship, giveMonster, evolveMonster, addFollower, checkpointSave, triggerEnding 같은 기능이 더 이상 존재 자체를 숨기지 않는다.

6. 데이터베이스: 필드 지원 경계를 숨기지 않는다

Item/Equipment 레코드 폼은 databaseFieldSupport.ts에서 파생한 지원 배지를 표시한다. 런타임 필드는 공통 권위로 연결하고, 이미지·사용 문구·legacy 프로필처럼 저작 전용인 필드는 실행 규칙으로 오인되지 않게 구분한다.

레코드런타임 배선명시적 저작 전용
ItemRecordconsumptionLimit, usableClassIds, seedParameterBonusesimageResourceId, iconResourceId, usageMessage, equipmentProfile
EquipmentRecordtwoHanded, usableAsItemSkillId, stateInflictIds, stateInflictionChanceimageResourceId, iconResourceId
개선 원칙: 값이 저장되는 것과 런타임 규칙으로 실행되는 것을 같은 의미로 표시하지 않는다. 배지·피커 메타데이터·공통 transition 권위가 같은 계약을 사용한다.

7. 개선 후 제품 천장

A급

런타임 표현력

대화·분기·전투·상점·맵·화면효과·날씨와 고급 아이템·장비 규칙을 공통 권위로 소비한다.

A-급

데이터 신뢰성

실행 필드는 런타임에 연결되고 저작 전용 필드는 지원 배지로 경계를 공개한다.

B+급

저작 발견성

기본 모드 실행, 첫 이벤트 CTA, partial 명령 안내가 핵심 루프의 숨은 관습을 줄인다.

A-급

검증 가능성

첫 이벤트 저작·저장·재로드·플레이와 격리 원격 인증 라이프사이클을 자동 증명한다.

8. 이번 개선에서 닫은 천장

  1. 필드 신뢰성: item charge, usable class, seed bonus, two-handed, 장비 스킬·상태 효과를 런타임 권위에 연결하고 저작 전용 필드는 배지로 공개했다.
  2. 기본 실행 루프: 기본 모드 테스트 플레이를 유지하고 키보드 실행을 회귀검증한다.
  3. 첫 이벤트 발견성: 단일 클릭 좌표 선택 + 생성 CTA + 실제 캔버스 저작 E2E를 추가했다.
  4. partial 명령 발견성: 메인 피커에서 검색 가능하고 포커스 가능한 정보 행과 대체 경로를 제공한다.
  5. 날씨 정본: 죽은 DOM 경로를 제거하고 Phaser 경로만 유지한다.
  6. 원격 증명: 전용 격리 인증서가 있을 때만 생성·저장·재로드·플레이·소유 행 삭제를 수행하는 fail-closed 라이프사이클을 둔다.

9. 방법과 한계

초기 실측: Playwright Chromium 1440×900/1280×800, 기본/전문가 DOM inventory, 키보드 포커스, 화면효과 픽셀 비교(Jimp), 런타임 상태 확인. 개선 검증: 실제 캔버스 이벤트 생성, 로컬 flush/reload, 전체 및 선택 이벤트 플레이, item/equipment transition 단위·통합 테스트, 프로덕션 번들 브리지 부재 검사. 남은 외부 조건: 라이브 Supabase 인증은 전용 격리 인증서와 사람이 제공하는 대상 자격증명이 있을 때만 실행된다.
