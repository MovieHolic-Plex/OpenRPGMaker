# 감독 직접 플레이테스트 — RPG Maker 2003 대비 비판 보고

> 2026-07-07, Claude(감독) 직접 플레이. 대상: `feat/phase-6a` + 《잿불의 유산》.
> 방법: Playwright 실브라우저 조작(키보드 걷기/조사/메뉴/상점/여관/전투), 증거 스크린샷 30+장 `evidence/playtest-rm2003/`.
> 플레이 커버리지: 타이틀 → 새 게임 → 이동(4방향/대각/대시) → 촌장 대화·선택지 → 메인 메뉴(아이템/스킬/장비/저장) → 상점 구매 플로우 → 여관 숙박 → 슬라임 전투(커맨드→타겟→승리) → 전투 후 복귀.

## A. 정체성 차원의 차이 (가장 중요)

1. **픽셀 밀도 불일치 — "RM2003 느낌"을 깨는 1순위.** 지면 타일(잔디/자갈길)이 1px 노이즈풍 고밀도 텍스처인 반면 캐릭터(24×32)와 건물은 큼직한 픽셀. RM2003은 모든 요소가 16px 그리드의 동일 밀도로 통일돼 있다. 타이틀 배경도 페인팅풍이라 픽셀 아트 정체성과 충돌. → **지면 칩셋 재작업(16px 밀도 통일)이 최우선 아트 과제.**
2. **폰트.** 전 UI가 안티앨리어싱된 시스템 고딕. RM2003의 저해상 비트맵 폰트 감성이 사라짐. 320×240 스테이지에 서브픽셀 폰트가 얹혀 "웹 앱 위에 게임" 느낌. → 비트맵/픽셀 폰트(예: Galmuri, DungGeunMo) 도입 + 정수 배율 렌더.
3. **윈도우 스킨.** 메시지/메뉴 창이 CSS 그라데이션 블루. RM2003은 시스템 그래픽(텍스처+테두리 스킨)이 게임마다 교체 가능한 정체성 요소. 상점 화면은 모서리 라운딩까지 있어 모바일 앱처럼 보임. → 시스템 스킨(이미지 기반 9-slice) 파이프라인 필요. 시스템 그래픽 교체 명령은 현재 스텁이기도 함.

## B. 필드/이동

4. **대각선 이동과 대시가 기본 활성.** RM2003은 4방향 고정·대시 없음. 현대적 편의지만 RM2003 모드가 목표라면 프로젝트 옵션으로 분리해야 함(대각 이동은 통행 판정 착시도 유발).
5. **화면 스케일이 큰 창에서도 2x에 고정.** 1720×960 뷰포트에서 640×480 렌더 + 거대한 검은 여백. fidelity contract는 "창을 덮는 최소 정수 배율(크롭 허용)"인데 실제는 fits-inside처럼 동작. 몰입감 손해.
6. **맵 전환 연출 빈약(관찰 범위).** 성문 전이 연출을 관찰하지 못했고(하단 D 참고), RM2003 시그니처인 다양한 화면 전환(지그재그/블록 와이프) 대비 페이드 중심.
7. **숲 맵의 타일 반복 티가 심함** — 같은 나무 타일 격자 반복. 오토타일/배리에이션 부족과 맵 저작 도구 문제의 복합.

## C. 메시지/대화

8. **대화창 공간 낭비 + 나쁜 페이지 리듬 (중대).** 4줄 높이 창에 본문이 1줄씩만 흐르고 어색한 지점("...꺼져 버렸네. 백 년" / "...동쪽 숲 너머,")에서 페이지가 끊김. RM2003은 저작자가 4줄을 채워 끊는다. 자동 래핑이 있다면 4줄을 채우고 넘겨야 하며, 에디터에서 줄 미리보기가 필요.
9. 화자명 인라인 표시는 RM 관례와 유사(무난). 페이스 그래픽은 기능은 있으나 이 게임 데이터가 활용 안 함(콘텐츠 문제).
10. 텍스트 코드(\v \c \n)는 이번 웨이브에서 구현 완료 — 게임 데이터가 아직 안 씀.

## D. 상점/여관/메뉴

11. **상점: 구도는 RM2003에 근접**(설명 상단/가격 리스트/보유·장비 수/골드). 부족: 파티원별 장비 가능·능력 변화 표시(RM2003 상점의 핵심 정보), 구매 수량 UI 관찰 안 됨, 화면 내 '취소' 마우스 버튼은 RM 문법 밖.
12. **여관: 인사→숙박 흐름 정상.** 15G 요금 표시. 페이드 연출 확인.
13. **메인 메뉴: 명령이 11개로 과밀**(아이템/스킬/장비/저장/로드/상태/열/진형/임무/대기ON/타이틀). RM2003은 5~6개. 확장 기능(임무/진형)은 좋으나 게임별 켜고 끄는 시스템 설정이 있어야 함. 장비 화면은 RM2003 구도를 잘 재현(전후 비교/5슬롯/소지품).

## E. 전투

14. **전투 배경 미스매치: 숲 전투인데 하늘/구름 배틀백.** 배틀백이 하늘 계열만 존재(기존 알려진 한계)하고 지형→배틀백 매핑도 없음. RM2003은 지형 태그별 배틀백 지정.
15. **액터가 맵 차셋 그대로 전투에 등장**(전투 전용 배틀차셋/모션 미사용 — 데이터 미설정 + 폴백). RM2003 사이드뷰는 대기/공격/피격 모션 세트가 정체성.
16. **하단 HUD 3분할(메시지/커맨드/상태)은 가독성 양호**하나 RM2003 구성(파티 상태 창 + 커맨드 창, 메시지는 상단)과 다름. ATB 게이지 존재는 충실.
17. 타겟 선택이 흰 사각 브래킷 + 마우스 클릭 중심 — RM2003의 커서/이름 리스트 문법과 다름(키보드 타겟 선택 확인 필요).
18. 전투 진입 연출(플래시/지그재그 와이프) 미관찰 — 기본 페이드로 보임.

## F. 플레이 중 발견한 결함/의심 (기능)

19. **[의심-중대] playerTouch 성문 전이가 걸어 들어가도 발동 안 됨.** q1 스위치 ON 상태에서 (29,12)→(30,12) 진입해도 맵 전환 없음(자동화 환경 한계 가능성 있으나 재현 2회). 걸어서 확인 필요 — 만약 실사용에서도 그렇다면 치명 버그. (2026-08-20 재검증: 오탐 — 밟기/부딪힘/transfer 세 경로 모두 정상 배선, 회귀 스펙 test/emberQuestGame.test.ts의 성문 걷기 케이스로 고정. 실결함은 "통행 불가 타일 위 밟기형 playerTouch 영구 미발동" 저작 함정이며 lint playerTouch-impassable로 처방)
20. **[확정] 로드 직후 `readState().currentMapId`가 스테일** — 씬은 숲인데 세션 조회는 마을 반환. 디버그 훅/세이브-로드 동기화 버그.
21. **[확정] e2e 스위트 전체 rot** — `default-adventure-game.spec.ts`가 베이스 커밋에서도 실패(AI 패널이 mode-play 클릭을 가로챔). 브라우저 QA가 CI에 없어 썩은 것. 이번 6A의 "저작>실행" 배지처럼, **"e2e가 도는지"부터 신뢰 배관에 포함해야 함.**
22. [소소] 타이틀에서 첫 Enter가 간헐적으로 씹힘(페이드 중 입력 무시로 추정). 게임패드/연타 사용자 기준 불쾌 지점.
23. 여관 NPC 앞에서 Enter 연타 시 숙박 대화가 즉시 재발동 — RM2003도 동일하긴 하나, 대화 종료 직후 짧은 입력 쿨다운이 현대적 관례.

## G. 종합 판정

- **구조(스키마/이벤트/전투 규칙)는 RM2003에 상당히 근접. 그러나 "감각"(픽셀 밀도, 폰트, 윈도우 스킨, 전투 모션, 배틀백, 전환 연출)이 RM2003이 아니다.** 지금까지의 개발이 데이터·룰 충실도에 집중했고, 프레젠테이션 충실도가 다음 병목.
- 우선순위 제안: ①지면 칩셋 픽셀 밀도 통일 ②픽셀 폰트+윈도우 스킨 시스템 ③대화 페이지네이션 수정 ④배틀백 확충+지형 매핑 ⑤배틀차셋 모션 ⑥스케일 정책(정수 최대) ⑦F항 결함 수정(성문 전이 검증 최우선) ⑧e2e 부활을 신뢰 배관에 편입.
