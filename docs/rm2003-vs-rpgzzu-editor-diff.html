RM2003 리듬 vs RPG ZZU 표면

텍스트 스펙이 아니라 실제 화면으로 본다. 왼쪽 클래식 Win32 메이커와 오른쪽 웹 기반 전문가 모드가 같은 작업을 어떻게 배치하는지 — 팔레트, 툴바, 맵 캔버스, 이벤트, DB, AI 독 — 을 스크린샷으로 고정한다.

한 장 판정

RPG ZZU expert 모드는 RM2003의 작업 리듬 — 좌 팔레트, 상단 도구, 중앙 맵, 모달형 DB/이벤트 — 을 의도적으로 따라간다. 동시에 웹 스택·다크 크롬·AI 사이드 독 때문에 “복제”가 아니라 “리메이크”로 읽힌다.

1

레이아웃 골격

좌 팔레트 · 중앙 맵 · 상단 툴바 골격은 이미 맞다. 3분할 클래식 워크스페이스.

2

시각 언어

RM은 Win32 밝은 그레이. ZZU는 다크 글래스. 픽셀 밀도·아이콘 메타포는 아직 다른 제품.

3

AI 독은 순증분

RM2003에 없는 우측 AI 패널. 확장 시 맵 폭을 먹는다 — 의도된 포크 포인트.

4

데몬 정상

dev:keep + supervisor + hub rpg-dev 가 :9999 강제 서빙 중. HTTP 200.

결론. “RM2003처럼 보이게”가 아니라 “RM2003처럼 손 놀리게”가 목표라면 현재 expert 셸은 골격 합격. 남는 갭은 팔레트 셀 밀도, 툴바 아이콘 메타포, DB 탭 밀도, 이벤트 커맨드 리스트 클래식 리듬이다.

셸 레이아웃 · 전체 화면

같은 “맵 편집 중” 상태를 나란히 둔다. RM2003은 밝은 MDI/다중 창, ZZU는 단일 브라우저 셸에 패널을 도킹한다.

읽히는 차이

  • 창 모델 — RM: 여러 플로팅 윈도우. ZZU: 도킹 패널 + 모달.
  • 정보 밀도 — RM 툴바/팔레트가 픽셀 단위로 빽빽. ZZU는 터치·가독 여유.
  • 맵 트리 — RM 하단/좌측 트리 고정. ZZU는 모드/사이드 전환에 묶임.

타일 팔레트

맵 편집의 손 위치. RM2003은 A/B/C/D/E 칩셋 탭 + 조밀한 16px 그리드. ZZU expert는 6열 그리드·레이어 칩·다크 셀 보더로 재해석한다.

palette root
6-col grid crop
갭. RM 팔레트는 “한 화면에 더 많은 타일”이 기본 감각이다. ZZU가 6열을 맞춰도 셀 패딩·보더·배경 톤 때문에 체감 밀도는 낮다. 다음 웨이브: 셀 외곽 1px, 패딩 축소, A–E 탭 리본을 더 클래식하게.

툴바 · 도구 메타포

펜/사각/타원/채우기/선택, 하층·상층·이벤트 레이어, 확대 — RM 사용자가 손 기억으로 찾는 줄.

RM 16×16 아이콘 · 밝은 면 ZZU 벡터 아이콘 · 다크 면 공유 펜/사각/채우기/선택 개념 ZZU only 기본/전문가 모드 토글
아이콘 세트만 클래식 메타포로 바꿔도 “RM 손맛”이 크게 올라간다. 기능 패리티보다 인지 패리티 이슈.

이벤트 · 데이터베이스

RM2003의 핵심 저작 루프는 (1) 맵 위 이벤트 더블클릭 → 페이지/커맨드 리스트, (2) 데이터베이스 탭 리본. ZZU도 같은 루프를 모달/패널로 제공한다.

표면 갭

  • RM 이벤트 커맨드 창: 번호 매긴 리스트 + Insert/Change 리듬이 매우 고정적.
  • ZZU: 그룹/검색/AI 보조가 붙을 수 있어 파워 유저 경로가 갈라짐.
  • DB: 필드 커버리지는 계약(docs/specs/rm2k3-fidelity-contract.md) 기준 — UI 밀도와는 별개.

AI 사이드 독 — 순증분 축

RM2003에는 없는 축. expert 모드에서 우측 도킹. 접으면 맵이 넓어지고, 펼치면 코파일럿이 상주한다.

9999 강제 서빙 데몬

질문: “9999에 npm run dev 강제 서빙 모니터링 데몬 있냐?” → 있다. 그리고 현재 정상.

A

npm scripts

dev → Vite --port 9999 --strictPort
dev:keep → scripts/dev-keepalive.mjs
dev:keep:detached → supervisor

B

동작

자식 exit 시 재시작, HTTP 헬스체크 실패 시 재시작, 포트 좀비 정리, PID 싱글톤 락, --detach 로 셸 사망 생존.

C

지금 상태

keepalive PID 35536 · supervisor 8164 · hub rpg-dev ready · HTTP 200.

로그 / PID 위치

  • output/dev/dev-keepalive.pid · dev-supervisor.pid
  • output/dev/dev-keepalive.log · dev-supervisor.log
  • hub 프로세스 이름: rpg-dev (Vite 직접, 또는 keepalive 하위)
방금 검증: curl http://127.0.0.1:9999/ → 200, node PID 둘 다 tasklist 생존. 최근 로그는 HMR/CSS/배틀 모듈 reload — crash 루프 아님.

에러로 보였을 수 있는 것

  • --strictPort 때문에 9999 점유 시 Vite가 바로 exit → keepalive가 다시 띄움.
  • PowerShell에서 $r 변수가 바깥 셸에 먹혀 헬스 스크립트가 파서 에러 — 서버 문제가 아님.
  • HMR page reload 폭주 시 브라우저 일시 빈 화면 → 새로고침으로 복구, 데몬은 유지.

다음에 손댈 곳

  1. 팔레트 밀도 패스 — 셀 패딩/보더 1px, A–E 탭 리본 클래식화, 한 화면에 보이는 타일 수 RM 체감에 근접.
  2. 툴바 아이콘 메타포 — 펜/사각/채우기/레이어를 RM 사용자가 0.5초 안에 찾게.
  3. 맵 트리 상주 — expert 셸에서 접을 수 있어도 “항상 있는” 위치 고정.
  4. 이벤트 커맨드 리스트 리듬 — 번호 리스트 + Insert/Change 키보드 루프 강화.
  5. 데몬은 유지 — 에이전트 작업 시 npm run dev:keep:detached 또는 hub rpg-dev 를 표준으로.
