OPRN Studio · 이벤트 편집기

좌측 페이지 레일과 레코드 픽커 개선안

실행 중인 편집기(1680×1000)에서 직접 계측한 값에 근거한다. “현재”와 “구현” 이미지는 둘 다 실제 스크린샷이다 — 아래 개선안은 구현·검증을 마쳤다. 섹션 04·05 의 목업은 설계 의도를 보여주기 위해 남겨 둔다.

브랜치 event-editor (main과 동일) 측정일 2026-08-28 텍스트 잘림 3건 레일 높이 1370px 선택 UI 종류 3가지

01 — 진단

233px 컬럼에 12행짜리 조건 폼이 들어가 있다

좌측 “이 페이지 설정” 레일의 실측 폭은 233px다. 여기에 모습·조건·움직임·기억·일정 5개 그룹이 아코디언으로 쌓여 있고, 그중 “언제 보이나요”를 펼치면 조건 12행이 그대로 이 폭 안에 들어온다. 폼이 폭을 감당하지 못해 컨트롤과 라벨이 서로를 밀어낸다.

브라우저에서 scrollWidth > clientWidth로 검출한 잘림은 3건이고, 조건 12행이 전부 2줄로 접혀 레일이 1370px까지 늘어난다. 추정이 아니라 DOM 측정값이다.

같은 화면에서 오른쪽은 비어 있다

덤으로 드러난 것

  • 모든 조건 행이 두 줄로 접힌다 — 268px 안에 체크·라벨·픽커·값이 들어가지 못해 픽커가 다음 줄로 밀린다. 12행이 24행이 되고 레일이 1370px 이 된다.
  • 선택값을 읽을 수 없다 — 아이템·주인공 드롭다운은 91px 라 “0001: 회복약”이 들어가지 않는다.
  • 상태를 한눈에 볼 수 없다 — 그룹이 전부 접혀 있어 이 페이지가 어떤 조건에서 켜지는지 알려면 하나씩 열어야 한다.

초판에서 “요약에 fixed 가 그대로 뜬다”, “그룹 이름이 «기억과 정리»다”라고 적었던 두 항목은 철회한다. 그 화면은 이 브랜치가 아니라 main 보다 뒤처진 다른 워크트리(agent/assistant-headerless)를 서빙하던 dev 서버에서 잰 것이었다. 이 브랜치는 이미 «겹침과 통행»으로 이름이 고쳐져 있고 요약도 «정지»로 나온다.

02 — 진단

한 폼 안에서 레코드를 고르는 방법이 세 가지다

스위치·변수·아이템·주인공은 전부 “데이터베이스 레코드 하나 고르기”라는 같은 일이다. 그런데 현재는 셋이 서로 다른 방식으로 동작한다.

이 창의 문제

  • 번호만 있는 줄이 목록을 채운다 — 새 프로젝트는 이름 없는 스위치 20개로 시작하는데, 목록이 0006: 처럼 번호만 찍어 무엇이 비어 있고 무엇이 쓰이는지 구분되지 않는다.
  • 블록 내비게이션이 200px를 먹는다 — 항목이 5개인데 [0001-0020] 범위 선택이 좌측 절반을 차지한다.
  • 이름이 전부 “새 스위치” — 무엇에 쓰는 스위치인지, 어디서 쓰이는지, 지금 켜져 있는지 어느 것도 알 수 없다. 검색창이 있어도 무의미하다.
  • 버튼 3개의 뜻이 불분명 — “적용”은 이름 변경 전용이지만 라벨만 봐서는 “반영하고 닫기”와 무엇이 다른지 알 수 없다.
  • DESIGN.md 위반 — 문서는 이벤트 편집기에 대해 “no RM2K3 retro presentation”, “no Sw[0001] chip walls”, 폐기된 RM 블루 “must not be reintroduced”라고 명시한다. 이 창은 셋 다 어긴다.

03 — 원인

증상은 여러 개지만 뿌리는 하나다

좌측 레일이 “페이지 상태를 훑어보는 일”과 “설정을 편집하는 일”을 같은 233px 안에서 동시에 하려 한다. 233px는 앞의 일에는 넉넉하고, 뒤의 일에는 절대 부족하다.

픽커도 같은 뿌리다. 좁은 칸에 값을 넣어야 하니 컨트롤을 36px까지 줄이고, 그렇게 줄인 컨트롤로는 선택이 불가능하니 전체 화면 모달을 띄운다. 폭 부족이 모달을 부르고, 모달이 다시 맥락을 끊는다.

따라서 개선안도 두 갈래가 아니라 하나다. 역할을 분리하고, 폭을 있는 곳에서 쓴다.

04 — 개선안 A

좌측은 읽는 면, 편집은 넓은 면

⌄ 시간대 · 계절 · 활동 · 호감도 · 셀프 스위치 4종 — 자주 안 쓰는 조건 5행은 접어 둔다

해결되는 것

  • 잘림 7건 → 0건. 컨트롤이 좁은 칸을 떠났다.
  • 458px 넘침 제거. 요약 5행은 세로 스크롤이 필요 없다.
  • 빈 우측 활용. 조건이 2열로 펼쳐져 12행이 한 화면에 들어온다.
  • 상태를 열지 않고 읽는다. 접힌 채로 “무작위 · 보통 속도”가 보인다.
  • 자연어 요약. 켜진 조건을 한 문장으로 확인 후 저장할 수 있다.
  • fixed 같은 enum 소멸. 요약이 사람 문자열 하나로 통일된다.

유지되는 것

  • testid 전부 보존. evt-rail-group-*, event-page-*-condition-*는 DOM 위치만 옮기고 이름은 그대로 둔다.
  • 그룹 5개 구성 유지. 학습된 정신 모델을 바꾸지 않는다.
  • 기존 폼 코드 재사용. pageConditions.ts가 만드는 노드를 그대로 옮겨 담는다. 폼 로직은 건드리지 않는다.

“겹침과 통행”은 .omo/evidence/event-left-panel에 기록된 이름 수정이 이 브랜치에 아직 안 들어와 있다. 함께 반영한다.

06 — 검토한 대안

왜 이 조합인가
안내용판단
레일 확장 좌측을 233 → 360px로 넓히고 폼은 그대로 둔다 기각. 잘림은 줄지만 1288px 세로 넘침이 남고, 우측 빈 면은 그대로다. 맵 캔버스 폭만 더 뺏는다.
레일 2열 좁은 레일 안에서 조건만 2열 그리드로 기각. 233px를 2열로 쪼개면 칸당 100px 미만 — 지금보다 나빠진다.
역할 분리 좌측=요약, 편집=우측 넓은 면 (개선안 A) 잘림의 원인 자체를 제거하고, 남는 폭을 쓰고, 기존 폼 코드와 testid를 보존한다.
모달 개선 기존 픽커 창의 색·여백만 스튜디오 토큰으로 기각. 외형은 고쳐지지만 빈 슬롯 15줄·블록 내비·맥락 단절· 아이템/주인공 불일치가 전부 남는다.
전역 팔레트 Ctrl+K 명령 팔레트에 레코드 선택을 합친다 기각. 필드 하나를 채우려고 전역 팔레트를 여는 건 과하다. 검색·키보드 조작 방식만 팝오버에 차용한다.
통합 팝오버 레코드 4종을 한 컴포넌트로 (개선안 B) 상호작용 3종을 1종으로 줄이고, 36px 컨트롤을 없애며, 사용처·현재값이라는 새 정보를 얹는다.

제안과 달라진 점

  • «지금 켜짐» 상태 칩은 넣지 않았다. 스위치·변수 값은 실행 중에만 존재하고 저작 시점에는 없다. 참조 수(«쓰는 곳 n곳»)와 «아직 안 쓰임»만 넣었다.
  • 팝오버가 아니라 창을 유지했다. 기존 서브다이얼로그의 포커스 트랩· Esc·모달 스택을 그대로 쓰는 편이 안전하고, event-record-picker testid 도 보존된다.
  • «선택» 버튼을 남겼다. 즉시 반영으로 바꾸면 e2e 3개 스펙의 -row-1 → -ok 순서가 깨진다. 버튼 3개를 1개로 줄여 «적용이 뭐냐»는 문제만 없앴다. 행 더블클릭·↵ 로도 확정된다.
  • 아이템·주인공은 픽커에서 새로 만들 수 없다. 이름만으로 성립하지 않는 DB 레코드라 반쪽짜리가 쌓이는 걸 막았다. 스위치·변수만 생성·이름변경을 지원한다.
  • 1320px 미만에서는 기존 세로 아코디언으로 되돌아간다. 두 면이 나란히 설 폭이 없을 때 갈라 놓으면 더 나빠진다.
  • 자주 안 쓰는 조건 5행 접기는 하지 않았다. 목업이 접자고 한 이유는 268px 에서 12행이 넘쳤기 때문인데, 2열 배치로 레일 높이가 796px 가 되면서 그 문제가 사라졌다. 더 중요한 건 방향이다 — 이 편집기는 「battleResult·all·any·not 조건이 화면에서 통째로 사라진다」(D09)가 P1 결함이었던 곳이다. 조건을 다시 감추는 건 그 결함 쪽으로 되돌아가는 일이다.
