1진단 — 같은 것을 네 번 그린다

「이 페이지가 하는 일」 하나를 네 가지 보기가 각자의 문법으로 그린다. 보기는 3주 사이에 하나씩 늘었고, 지워진 것은 없다.

같은 명령을 두 곳에서 고친다

조건을 붙이는 길도 둘이다

왜 문제인가. 보기·편집면·경로가 늘어날 때마다 사용자는 「어느 것이 진짜인가」를 한 번씩 더 판단해야 한다. 네 보기의 결과가 같다는 사실은 써 보기 전에는 알 수 없고, 인스펙터에서 고친 값이 모달에도 반영되는지도 확인해야 안심이 된다.

더 큰 비용은 시각 언어다. 보기마다 칩 색·아이콘 모양·라벨 어휘·번호 위치가 다르므로, 한 보기에서 익힌 눈이 다른 보기에서는 쓸모가 없다. 다음 절이 그 차이를 잰다.

보기 4종의 도입 시점은 git log -S 로 확인했다: 스토리 1bb59708(08-07), 미리보기 a4a23ca9(08-29), 플로우 cf2471cf(08-30). 인스펙터는 ae6a3ee0(08-04), 모달은 552b440e(07-03).

6진단 — 이름과 정체성

헤더 한 줄에서 이 창이 「무엇」을 편집하는지 읽어 낼 수 없다.

  1. 큰 제목 입력 「첫 만남」은 페이지 이름이다. 이벤트 이름이 아니다. 페이지를 바꾸면 제목이 바뀐다.
  2. 「이벤트: 밤」 — 이벤트 표시명이 마지막 페이지 이름(「밤」)에서 파생된다. 사용자는 이 이벤트를 「밤」이라 부른 적이 없다.
  3. 「61, 23」 — 좌표만 있고 맵 이름이 없다. 「이슬 장터 마을」인지 집 안인지는 편집기를 닫아야 안다.
  4. 「NPC 없음」 칩 — 연결 안 된 상태를 헤더에서 계속 말한다. 연결은 좌측 「NPC와 일정」 그룹에서도 「연결 안 됨」으로 반복된다.
  5. 「페이지 1/3」 — 바로 아래 탭 줄이 같은 정보를 보여 준다.
  6. 페이지 관리 줄 — 「페이지」 라벨 + 복제 · 복사 · 붙여넣기 · ← · → · 삭제 여섯 버튼. 복제와 복사의 아이콘이 거의 같다. 탭 우클릭과 드래그(이미 구현됨, 089038c3)로 대체 가능한 것들이 상시 노출되어 있다.
  7. 원시 ID 노출 — 목록 행 「이동 경로 설정: ev_ux_stress (4개)」, 이동 경로 대화상자의 「특정 이벤트 [ev_ux_stress]」 입력. 2026-07-07 리뷰의 「높음-2」가 그대로 남아 있다.
  8. 영어 제목 「Graphic」 — 그래픽 선택 대화상자만 영어다(cur-18).
  9. 「선택 끝」「분기 끝」 — 목록 보기에서 분기 닫힘을 텍스트 행으로 표시한다. 들여쓰기가 이미 구조를 말해 주므로 이 행들은 정보 없이 세로 공간만 쓴다.

8개선안 — 원칙 세 개와 삭제 목록

새 기능은 하나(인라인 명령 팔레트)뿐이다. 나머지는 있는 것을 하나로 합치고, 남는 것을 지운다.

원칙 1 · 문법 하나
명령은 어디서나 같은 행이다

번호 · 분류 막대 · 아이콘 · 종류 · 사람 문장. 보기 전환을 없애고, 스토리·플로우가 잘 보여 주던 분기 구조는 들여쓰기·연결선·분기 머리 행으로 목록에 흡수한다. 미리보기는 보기가 아니라 인스펙터 위의 「무대」로 상주한다.

원칙 2 · 편집면 하나
인스펙터가 곧 편집기다

더블 클릭은 모달을 열지 않고 인스펙터의 첫 필드에 포커스를 준다. 지도·카탈로그처럼 넓이가 필요한 편집은 인스펙터 자리 위로 미는 사이드 시트다. 목록은 계속 보인다. 가운데 모달은 확인 질문 하나만 쓴다.

원칙 3 · 깊이 하나
Escape 는 맨 위 층만 닫는다

한계

  • 헤드리스 Chromium(swiftshader) 이라 폰트 렌더가 실제 사용자 환경과 다를 수 있다. 픽셀 계측은 비율만 쓴다.
