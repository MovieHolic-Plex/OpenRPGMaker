요약: 조수의 비용은 도구 실행이 아니라 모델 왕복이다(시간의 67~78%) — 단, 큰 프로젝트에선 쓰기 1회에 36초짜리 해시가 그 순위를 뒤집는다. 그리고 구조가 모델 왕복을 곱으로 늘린다 — 요청 하나에 모델 단계가 4~6개 쌓이고, 몇몇 경로는 도구 248개(≈113k 토큰)를 매 호출 다시 보내며, 팀장은 10초마다 깨어나 전체 문맥을 다시 읽는다. 그리고 이 모든 것을 Pi 경로에서는 측정조차 하지 않는다.

2. 매 모델 호출마다 다시 보내는 고정 접두부

경로별 호출 1회당 도구 스키마 + 시스템 프롬프트 토큰 (tiktoken o200k, 제공자에 따라 ±20%). 캐시 키(sessionId/prompt_cache_key)는 어디서도 넘기지 않는다.

3. 가장 무거운 도구 스키마

상위 12개 = 카탈로그의 38%. 설명이 아니라 파라미터 스키마가 94%.

4. Pi 실행 41건은 어디로 갔나

결과별 도구 호출 수. 실패 13건 중 절반이 인프라(terminated·network·watchdog)와 stale-base.

5. 입력 토큰은 "성장"이 아니라 "절편"이 문제였다

구 세션 경로(09-07~09-10, Pi 이전)의 호출별 입력 토큰. Pi 는 이 계측이 없어서 같은 그림을 그릴 수 없다 — 그 자체가 발견이다.

첫 호출부터 23만~37만 토큰. 한 턴에 48회 호출 → 누적 2,450만 입력 토큰. 10회 이상 호출한 턴에서 "첫 호출 크기 × 호출 수" 만으로 실제 비용의 77%. 변화 없이 끝난 턴이 입력 토큰의 49.6% (64.6M / 130.3M)를 먹었다.

6. 시간은 모델이 먹는다

구 세션 경로 23턴 3,224 s 분해. 기타에 의도·검수·압축 LLM 이 섞여 있어 LLM 합계 ≈78%.

7. 헛도는 도구 호출

같은 턴 안에서 같은 도구·같은 인자로 다시 부른 횟수 (전체 2,674 중 308, 11.5%).
