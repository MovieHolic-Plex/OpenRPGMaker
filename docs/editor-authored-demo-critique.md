# 에디터 작성 데모 비판안

## 데모 비판

- 제목은 `안개 항구와 등대의 밤`으로 잡았고, 등대 복구, 항구 NPC 제보, 선택지, 전투, 보상, 엔딩 구조를 목표로 했다.
- 현재 기본 배치 이벤트를 에디터에서 다시 쓰는 방식은 맵 배치 안정성은 높지만, 완전히 새 맵을 만드는 느낌은 약하다.
- 선택지는 이야기 분기 느낌은 만들 수 있으나, 선택 결과가 장기 상태로 더 많이 이어지지 않으면 30분 플레이의 밀도가 부족하다.
- 전투는 고정 전투 1회로 목적은 분명하지만, 난이도 조절과 회복/보상 루프가 더 있어야 반복 플레이가 재미있다.
- 보상은 골드와 아이템으로 명확하지만, 보상을 쓰게 만드는 후속 상황이 더 필요하다.
- 수정됨: 항구 데모가 처음에는 모든 NPC를 같은 EasyRPG People1 프레임으로 렌더링해 역할 구분이 거의 불가능했다. 현재는 People2/People3/Object1 CharSet을 섞어 보이는 NPC 그래픽 9종으로 늘렸다.
- 수정됨: 기존 별등 장로/숲/광산 대사 위에 항구 대사가 덧붙어 퀘스트 흐름이 섞여 있었다. 현재는 `등대지기 하루 -> 항구 NPC 단서 -> 방파제/폐등대 창고 렌즈 조각 -> 등대 꼭대기 점등` 흐름으로 재작성했다.
- 수정됨: 시작 퀘스트 선택지, 진행 안내, 잠긴 등대 문, 렌즈 조각 회수, 최종 엔딩이 같은 등대 복구 목표를 바라보도록 맞췄다.
- 수정됨: 주요 NPC가 모두 제자리 고정이라 마을이 정지된 전시장처럼 보였다. 현재 항구 NPC와 단서 NPC는 랜덤 보행을 하며, 대사에서 서로의 이름과 역할을 언급한다.

## 에디터 사용 중 발견한 문제

- 수정됨: 이벤트 레이어 좌표 계산을 카메라 기준으로 보정했고, 클릭 피드백을 `새 이벤트 위치` / `편집 위치`로 나눠 표시한다.
- 수정됨: 기존 이벤트를 열 때 조건이 붙은 마지막 페이지가 아니라 첫 페이지를 기본 선택한다. 저장 후에도 사용자가 편집하던 페이지 선택을 유지한다.
- 수정됨: `적용`은 저장 후 draft를 다시 열더라도 현재 페이지 선택을 유지한다. 명령 편집 팝업은 확인 전에 입력 컨트롤 값을 한 번 더 커밋하고, 텍스트/엔딩 textarea는 입력 중에도 staged 명령에 반영된다.
- 수정됨: 빠른 명령 버튼도 일반 명령 편집 팝업을 거치도록 맞춰, 작성 흐름을 `명령 선택 -> 편집 -> 확인`으로 통일했다.
- 수정됨: 선택지 가지 편집 영역에 가지별 제목, 별도 command-list test id, 팝업 제목을 추가해 현재 편집 대상이 더 명확하게 보이게 했다.
- 수정됨: 엔딩 명령을 빠른 명령 버튼과 이벤트 명령 picker에서 직접 추가할 수 있게 했다.
- 수정됨: 마을별 설정/관계/퀘스트 단서를 프로젝트 안에 둘 곳이 없어서 AI가 다음 생성 때 맥락을 잃기 쉬웠다. `마을 정보` 모달을 추가해 맵별 `.md` 문서를 편집/미리보기/저장할 수 있게 했다.
- 수정됨: 새 마을 정보 모달의 첫 시각 QA에서 기존 DB 모달 폭 규칙에 밀려 오른쪽 패널이 잘렸다. 전용 CSS 우선순위, 박스 모델, 세로형 편집/보기 구조로 고쳤다.
- 모바일 폭에서는 이벤트 편집 모달과 실행 내용 목록이 좁아져 한글 요약과 버튼이 빠르게 답답해진다.

## 남은 리스크

- 에디터 UI만으로 데모 fixture를 작성하고 export하는 데스크톱 E2E는 통과했다.
- 이번 요청에서 모바일은 제외했다. 모바일 모달/목록 밀도 문제는 별도 작업으로 남긴다.
- 기본 장로 이벤트처럼 이미 명령이 많은 이벤트에 새 데모 명령을 덧붙이면 런타임 플레이 순서가 기존 명령의 영향을 받는다. 완전한 새 데모 플레이스루는 새 전용 이벤트나 기존 명령 정리 정책을 먼저 정해야 한다.
- 남음: visual-qa 이미지 diff 스크립트는 현재 환경에 `bun`이 없어 실행하지 못했다. 대신 브라우저 스크린샷과 프로젝트 데이터 검증으로 확인했다.
- 남음: 마을 정보 문서는 현재 프로젝트 JSON 안에 저장된다. 실제 파일 시스템의 개별 `.md` 파일로 export/import하는 기능은 아직 없다.
