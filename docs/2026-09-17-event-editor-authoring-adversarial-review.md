## P0 — 저작 결과를 배신하는 것 (사용자가 만든 것과 게임이 다르다)

### 1. 이벤트에 이름이 없다. 「이벤트 이름」은 마지막 페이지 이름이다

가장 크고 눈에 띄는 입력 상자(모달 좌상단)는 **페이지 이름**이다(`placeholder="페이지 이름"`, 새 이벤트 기본값 `페이지 1`).
1페이지를 「촌장 할아버지」로 지었고 2페이지는 자동 이름 「페이지 2」인 채로 저장했더니, 맵 툴팁·맵 이벤트 목록·왼쪽
인스펙터·다시 연 모달의 헤더(`이벤트: 페이지 2`)가 전부 **「페이지 2」** 를 이 NPC 의 이름으로 쓴다.

![저장 후 맵 — 이벤트 이름이 「페이지 2」, 큰 「새 이벤트 위치」 배너가 툴팁과 겹친다](./2026-09-17-event-editor-authoring-adversarial-review-assets/61-map-hover-event.png)

- `src/project/eventDisplayName.ts:9-16` — 뒤에서부터 첫 비어있지 않은 페이지 이름을 이벤트 이름으로. 자동 생성된 `페이지 N` 도 이름으로 친다.
- `src/editor/panels/eventEditor/modal.ts:480-500` — 주석이 스스로 「라벨이 이벤트 이름이라 사용자가 속았다」고 기록하고 라벨만 바꿨다. 근본은 GameEvent 에 name 필드가 없는 것.
- 왼쪽 인스펙터 문구는 「이벤트 이름·페이지 이름·NPC 코드와는 다르다」고 셋을 구분해 말하는데, 편집기 어디에도 이벤트 이름을 짓는 자리가 없다.

### 2. 조건 칩 한 번 누르면 게임의 1번 퀘스트 스위치에 묶인다

「언제 보이나요 → 스위치」 칩을 누르자 확인 없이 **0001 「Q1 약초 의뢰 수락」** 에 바로 묶였다. 페이지 탭도
`2 페이지 2 Q1 약초 의뢰 수락 켜짐` 으로 바뀐다. 이 상태로 저장하면 내 촌장은 다른 퀘스트의 진행에 따라 켜진다.

### 3. 분기 안에 명령을 넣는 길이 사실상 하나뿐이고, 그 하나도 반대로 간다

분기 안 「스위치 조작」 행을 선택한 채 상단 **「+ 명령」** 을 눌러 아이템 변경을 추가했더니 **분기 밖 최상위 3번**으로 들어갔다.
피커에는 어디에 삽입되는지 표시가 없다. 결과: 거절해도 회복약을 받는 논리 버그를 사용자가 알 수 없다.

![선택된 중첩 행을 무시하고 최상위에 삽입](./2026-09-17-event-editor-authoring-adversarial-review-assets/36-list-after-item.png)

- 「위로 이동」은 선택지 블록 전체를 한 번에 뛰어넘는다. 분기 안으로는 못 들어간다.
- 스토리 뷰에서 행을 드래그하면 **텍스트가 선택**된다(`draggable` 요소 2개뿐, 행은 아님).
- 분기가 명령을 하나 가지면 「비어 있음 — 여기에 명령 추가」 슬롯이 사라져 두 번째 명령을 넣을 곳이 없다.
- 유일하게 분기 안으로 들어간 경로는 `편집 ▾ → 잘라내기` 후 중첩 행 선택 + `Ctrl+V`. 이건 선택 행 **앞**에 넣는다. 「+ 명령」은 선택을 무시하고 **끝**에 넣는다. 두 삽입 규칙이 서로 다르다.

![드래그하면 행이 아니라 글자가 선택된다](./2026-09-17-event-editor-authoring-adversarial-review-assets/39-drag-in-progress.png)

### 4. 2페이지를 보다가 닫으면 맵에서 NPC 가 사라진다

편집기를 2페이지(그래픽 없음) 상태로 닫자 맵 (46,41) 은 빈 칸이 되고 툴팁·목록·요약이 모두 2페이지 것을 보인다.
데이터는 멀쩡하다(`project-export-json` 확인: 1페이지 sprite `tex_easyrpg_charset_people1`, 명령 2개). **맵 렌더가
편집기의 「페이지 미리보기 상태」를 닫힌 뒤에도 따른다.** 「편집 위치 46,41」 배너도 닫힌 뒤 그대로 남는다.

![닫은 뒤 — 스프라이트 없는 칸, 멈춘 「편집 위치」 배너, 2페이지 툴팁](./2026-09-17-event-editor-authoring-adversarial-review-assets/72-map-after-discard-hover.png)

### 5. 1024 에서 본문이 무너지고 768 에서는 저장 버튼이 사라진다

- **1024×700**: 명령 열이 400px 로 줄어 행마다 칩/태그/본문이 3줄로 쌓이고 본문은 10글자. 빈 인스펙터가 폭의 1/3 을 점유한다.
- **768×1024**: 본문 열 폭 0(칩만 남음), 중첩 행은 단어 단위 줄바꿈(`아이템/변경:/회복약/더하기/3`), 페이지 액션 줄 잘림,
  **푸터의 취소·적용·저장하고 닫기가 화면 밖**. 저장할 방법이 없다.

![1024×700](./2026-09-17-event-editor-authoring-adversarial-review-assets/67-viewport-1024x700.png)

### 18. 문구 · 배치 잡음

- 서브다이얼로그 제목이 2~3번 반복된다(창 제목 「문장 표시」 + 소제목 「문장 표시」 + 미리보기 제목 「문장 표시」). 그래픽 피커 제목만 영어 「Graphic」.
- 그래픽 피커의 시트 목록 스크롤바가 2px — 20개 중 10개가 숨어 있다는 표시가 없다. 「그림 없이 계속」 버튼은 「이미지 선택」 을 눌러 들어온 사람에게 붙는 버튼이 아니다.
- 「시작 방식」(트리거)이 「언제 보이나요」(가시 조건) 안에 들어 있고 legend 가 위 테두리에 잘린다. 같은 패널에 조건 시스템이 둘(칩 14개 + 「고급 조건」 목록).
- 문장 표시 인스펙터: LIVE 배지 옆에 「미리보기 새로고침」 버튼. 헤더 「문장 / 표시」 가 두 줄로 찢어진다.
- 「미리보기 / 플로우」 뷰로 가면 인스펙터 열이 사라져 탭 줄이 오른쪽으로 점프한다.
- 「공유 캐릭터 외형」 드롭다운은 항상 「연결 안 함 …」 으로 잘린다.
- 도구 ▾ 메뉴: 「따라오기 / 프리셋 ☠ 필드 몬스터 템플릿」 — 이모지 아이콘, NPC 편집기 문맥에 몬스터 템플릿.
- ESC 확인 다이얼로그(「계속 편집 / 버리고 닫기」)는 있다. 좋다. 다만 「저장하고 닫기」 선택지가 없어 저장하려면 돌아가야 한다.

## 인정할 것

- ESC 에 미적용 변경 확인이 뜬다. 최소화 칩 「이벤트 편집 계속: …」 은 좋은 패턴이다.
- 문장 표시·선택지의 LIVE 미리보기, 플로우 뷰의 분기 상자, 목록 뷰의 전문 표시는 잘 만들어져 있다.
- 스위치 피커의 「이 맵에서 쓰는 중 / 쓰는 곳 N곳」 은 RM 계열에 없던 실질적 개선이다.
- 그래픽 피커의 AI 이름 학습은 조수 경로에는 유용하다(단, 처음 스프라이트를 고르는 화면에 있을 이유는 없다).

## 지금 당장 할 다섯 가지 (우선순위)

1. **이벤트 이름을 모델에 넣고** 헤더 상자를 이벤트 이름으로 되돌린다. 페이지 이름은 탭 안에서 고친다. `eventDisplayName` 은 자동 이름(`페이지 N`)을 이름으로 치지 않는다.
2. **조건 칩과 명령 다이얼로그의 `switches[0]` 기본값을 없앤다** — 칩을 누르면 피커가 열리고, 피커는 아무것도 미리 선택하지 않는다. 인라인 개명은 명시 버튼 뒤로.
3. **삽입 규칙 하나로**: 「+ 명령」·피커·붙여넣기 모두 「선택 행 바로 아래, 같은 깊이」. 분기 슬롯은 명령이 있어도 항상 보이거나 hover 로 나타난다. 스토리 뷰 행에 `user-select: none` + 드래그 재배치.
4. **닫을 때 페이지 미리보기 상태와 「편집 위치」 배너를 해제**한다. 맵은 게임 시작 시 켜질 페이지를 그린다.
5. **1024/768 레이아웃**: 인스펙터가 비었으면 접고, 768 에선 2열(설정은 서랍), 푸터는 항상 보이게 고정. 본문 잘림은 폭 기준(`text-overflow`)으로.

그다음: 35px 입력(#6), 불투명 3단계 배경(#9), 서브다이얼로그 초기 포커스(#10), aria-label 7천 자(#12), 새 이벤트의 기본 경고(#14).
