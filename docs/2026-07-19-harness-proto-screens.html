설계 v2의 핵심 루프 1개를 실제 에디터에서 실동시켰다: 유저가 성벽 단면(5줄)을 가로로 반복해 찍는다 → 휴지 2초 → 그림 제안 카드 → [등록] → 팔레트 '내 스탬프'에 렌더 아이콘 → 그 스탬프로 다른 곳에 찍기. 아래 4장은 전부 Playwright가 실브라우저(1440×900)에서 실제 페인트·클릭으로 만든 화면이다 — 목업 HTML 삽입 없음. 패턴 감지는 실감지 (맵 데이터 결정적 스캔, 폴백·하드코딩 트리거 아님).

① 패턴을 반복해 찍는 중 — 제안 없음

② 휴지 2초 — 그림 제안 카드

③ [등록] — 팔레트 '내 스탬프' 렌더 아이콘

④ 스탬프로 찍기 — 다른 곳에 성벽 재현

감지 휴리스틱 (실감지 — 폴백 아님)

  • 입력: 현재 맵의 lowerTiles/upperTiles + 최근 편집 bbox(±6타일 여유). 출력: 최고 점수 후보 1개.
  • 높이 h=6→2 밴드마다 각 열의 (하위,상위) 타일 튜플 서명을 만들고, 주기 p=1~4로 sig[x]==sig[x-p] 연속 구간을 찾는다(반복 = ⌊구간폭/p⌋ ≥ 3).
  • 후보 확정 시 배경(최빈 하위 타일) 단색 행을 상/하단에서 트리밍 — 잔디 여백이 단면에 붙는 오검출 차단.
  • 단위 블록의 서로 다른 타일 수 ≥ 3 (단색 채우기·2색 줄무늬 배제). 점수 = 트리밍 후 높이 × 스팬 폭, 동점은 작은 주기 → 작은 y → 작은 x.
  • LLM·난수 없음 — 같은 맵이면 항상 같은 결과. 데모 시나리오(성벽 5줄 단면 ×9열)를 e2e에서 실제 페인트로 3회 연속 감지.

격리·안전 준수

  • 메인 작업트리는 읽기만 — 전 작업은 rpg-zzu-proto 워크트리·feat/harness-suggestion-proto 브랜치. main 미푸시(원격 푸시 안 함).
  • 에디터는 ?blankProject=1(원격 저장 스킵) + .env.local 비활성(.env.local.bak으로 개명)으로 구동 — Supabase 설정이 있으면 맵 편집 락이 공유 락 테이블을 조회하고 takeover 유도가 떠서(다른 세션과 충돌 위험) 아예 차단했다. 락 takeover는 한 번도 수행하지 않음.
  • dev 서버는 전용 포트 5199(기존 세션 9173과 분리), 검증 후 종료.

알려진 한계

  • 한계 감지는 "가로 반복 단면" 한 종류만 — 세로 반복, 2D 타일링, 페어/세트(성문·타워 얹기) 문법은 미구현. 상위 레이어 포함 패턴은 감지·저장 스키마는 지원하나 데모는 하위 레이어만 검증.
  • 한계 자동 이름이 칩셋 영문 라벨("Castle roof N 단면") — 설계의 "자동 이름 + 클릭해서 변경" 중 변경 UI(및 LLM 작명)는 미구현. 제안 빈도 다이얼(보통/조용히/끄기)도 미구현(고정 2초·세션 톰스톤만).
  • 한계 스탬프 페인트는 "고른 그대로"(autoConnect 없음) — 등록 킷이 오토타일 성형·build_* 시공 경로와는 아직 연동되지 않는다. 카드 표출 중 최하단 맵 행이 카드에 가려질 수 있다(위치 고정 오버레이).
