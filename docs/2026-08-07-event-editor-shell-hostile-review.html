호스트가 먼저 깨뜨리는 것

“0→폭 점프 방지”는 첫 프레임만 막는다. 이후 innerWidth 변화(브라우저 리사이즈, DevTools 도킹, OS 스케일)는 computeSideChatWidth 재호출 없이 남는다. 사이드 폭은 고착, 캔버스는 줄어들어 720 근처에서 가로 스크롤/겹침이 난다.

치명 — 1px 보더가 만드는 2px 넘침

.event-editor-modal-window { width:100vw; height:100dvh; border:1px solid … } — 보더 포함이면 100vw+2px라 가로 스크롤이 생긴다. dvh에서도 모바일 주소창 접힘 시 100dvh 재계산으로 세로 점프. backdrop이 이미 overflow:hidden이라 가려지지만, 내부 position:absolute 요소(리사이즈 핸들·드롭다운)는 잘린다.

.backdrop { display:grid } /* position:fixed 없음 — body 스크롤을 못 잠근다 */ .window { width:100vw; height:100dvh; border:1px solid } → iOS 사파리/안드로이드 크롬에서 “뒤 페이지가 같이 스크롤”

드래그 — translate는 영구, 리사이즈는 휘발

modalDrag.ts는 translateX/Y를 누적한다. 드래그 후 윈도우를 리사이즈하면 getBoundingClientRect().left가 translate를 포함한 값이라 다음 드래그 시작점이 어긋난다. 또한 닫고 다시 열면 translate 리셋 — 사용자가 “내가 옮긴 위치”를 기대하지만 매번 원점.

nextX = clamp(startX + dx, 0, innerWidth - min(width,160)) → 160px만 남기고 밖으로 밀 수 있어, 헤더를 화면 밖으로 보내면 “닫기 ×”를 잃는다.

단일 진실 공급원 위반 — settings-track이 세 곳에 복제

layoutResize.ts의 clampColumnWidth와 CSS의 --event-editor-settings-track 초기값·미디어쿼리 값이 서로 다른 clamp로 중복 정의. JS는 min 220/288, reserve 260/380+280로 계산하고, CSS는 clamp(320,36vw,540)로 고정. 둘이 어긋나면 드래그 중 “턱” 걸림이 생긴다.

JS: max = workbenchWidth - ( <1180 ? 260 : 660 ) CSS: 320–540 / 260–360 / 250–320 (미디어쿼리 3단계) → JS 드래그로 400을 찍어도 CSS clamp가 320–360으로 다시 조인다.

명령 인스펙터 — 은근한 유령 컬럼

1180 미만에서 reserveRight가 260으로 줄어 Inspector 280을 더 이상 예약하지 않는다. 그런데 그리드는 여전히 3컬럼. Inspector는 display로 숨지 않고 그리드 밖 오버플로로 밀려, 좁은 창에서 마우스로 닿을 수 없는 영역에 렌더된다.

관찰: 900px 창에서 명령을 클릭해도 우측 인스펙터가 안 보이면 “편집이 안 된다”로 오해한다. 실제로는 아래로 밀려 있다.

포커스 증발 — dynamic을 통째로 갈아끼우기

renderEventEditorDynamic은 clearChildren → render로 동적 영역 전체를 재생성한다. captureInteraction → restoreInteraction으로 포커스를 복원하려 하나, 그 사이에 activeElement가 <body>로 빠지는 grace 400ms 동안 다음 필드로 포커스가 옮겨가면 복원 대상이 어긋난다. 버튼 클릭 직전 rAF 재렌더는 클릭 자체를 유실(qa-troops 회귀 주석이 증거).

requestAnimationFrame(run) { if (isEditing || withinGrace) pending=true else refreshDatabasePanel(body) // 편집 중이면 보류 } // grace = 400ms — 근데 human tab은 120ms, click은 80ms

Draft & Checkpoint — 왜 1.5초마다 전체를 체크포인트하나

checkpointEventDraft를 open 즉시 + 1500ms 간격으로 돌린다. autosave(4s 디바운스)와 별개로 또 저장. 이벤트 하나 편집에 2개의 저장 루프가 경쟁하면, store.restoreEventDraftFromVault가 “사라진 이벤트를 되살리는” 방어 코드까지 필요해진다. 방어가 필요할 정도로 저장이 과하다는 신호.

처방 — “덜 그리고, 덜 저장하기”

• dynamic 전체 재생성 대신 필드 단위 패치로. 최소한 포커스 중인 필드는 건너뛰기.
• 포커스 트랩: inert + Tab 루프 + focusout 가드.
• 체크포인트는 dirty일 때만, interval 대신 store.subscribe + debounce 800ms 한 루프로 통합.
• 닫기 경로는 closed 플래그로 한 번만 실행(현재 있음) — backdrop과 Esc가 같은 플래그를 공유하는지 테스트로 고정.

검증 포인트: 한글 IME 조합 중 자동 리프레시 → 조합 유지, Tab 20회 왕복 → 포커스 탈출 없음, Esc 2회 연타 → draft 1회만 discard

두 개의 세계가 한 모달에 산다
