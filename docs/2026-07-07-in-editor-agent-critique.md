# 감독 직접 사용 — 인-에디터 AI 에이전트 비판 평가

> 2026-07-07, Claude(감독) 직접 에디터 채팅으로 게임 제작. 모델: gemini-3.1-flash-lite(기본), 실 OpenRouter 호출.
> 시나리오: 블랭크 프로젝트에서 자연어 4턴 — ①24×18 마을+흙길+집2채+시작위치 ②남쪽 연못+꽃/나무 꾸미기 ③주민 NPC '리나' 배치(2대사) ④run_lint 검증·자가수정. 이어서 테스트 플레이 VisualQA.
> 증거: `evidence/agent-eval/` (프로포절/결과 스크린샷 + timeline.json).

## 잘 되는 것 (2026 기준 상위권 — 재구축 금지)

- **에이전트 UX 표면이 실제로 좋다.** 스킬 칩(맵 인터뷰/집 짓기/맵 검증 리포트/마을 생성/시연으로 가르치기/퀘스트 빌더), 추론 표시, 툴 활동 로그(✓/✗ 툴별 결과), 프로포절 카드(수락/거부), 퀵리플라이. 상용 툴 다수보다 앞선다.
- **안전 아키텍처가 진짜다.** set_build_spec(밑그림) → 구역 격리 → paint/build → projectLint 게이트 → 프로포절. paint_road가 할당 영역을 1칸 벗어나자 **하드 차단**되어 재계획을 강제했다(과엄격하지만 안전은 작동).
- **자가수정이 작동한다.** place_npc 3회 실패 후 성공, set_build_spec 검증 실패 후 재제출.
- **시맨틱 리소스 검색**(list_resources "people1" → charset 8개)으로 그래픽을 이름으로 찾는다.
- **한 문장으로 플레이 가능한 맵을 실제로 산출**했다: create_map + build_house×2 + paint_road + set_start_position → 테스트 플레이에서 목재/석재 집과 도로가 렌더됨(evidence 51).

## 치명적 문제 (증거 기반)

1. **"새 프로젝트/freshProject"가 블랭크가 아니라 별등 마을 어드벤처 전체다.** `createBlankProject()`가 `createAdventureMaps()`+`configureAdventureProject()`를 호출(defaultProject.ts:44). 증거: "블랭크"라던 초기 화면에 이미 맵 4개(별등 마을/달샘 숲/낮은 구리 광산/하늘늪 사당)와 집·도로가 있음(evidence 00). → 사용자가 "새로 만들기"를 하면 남의 5맵 게임을 물려받는다. **진짜 빈 프로젝트 옵션이 없다.**
2. **에이전트가 만든 맵이 화면에 안 보인다 — 에디터가 그 맵으로 이동하지 않는다 (최중대 UX).** AI가 '평가 마을'을 생성하고 시작 맵으로 지정했지만, 캔버스는 4턴 내내·종료 시까지 '별등 마을'을 표시(상태바 "맵: 별등 마을", evidence 50). **사용자가 지켜봐도 캔버스에 아무 변화가 없다.** 공간 작업이 안 보이는 맵에서 일어난다. 플레이 모드로 가야 비로소 평가 마을이 나온다. → 에이전트는 편집 중인 맵으로 캔버스를 포커스해야 한다.
3. **"흙길"이 보라/마젠타 자갈로 렌더된다.** 팔레트 스와치(흙길 오토타일)도, 인게임 도로도 보라색(evidence 51). 에이전트는 "흙길" 타일을 충실히 썼는데 에셋/라벨이 틀려서 결과가 깨져 보인다. → 충실도+타일 시맨틱 버그. **AI 산출물이 옳아도 틀려 보이게 만드는 함정.**
4. **꾸미기 작업(T2 연못)이 0% 산출.** 연못이 도로와 겹친다는 걸 감지하고 **자율 해결(연못을 남쪽으로 이동) 대신 사용자에게 되물었다.** 안전하지만 합리적 요청에 아무것도 안 만들었다. 게다가 미해결 질문을 이후 턴까지 끌고 다녀 응답을 지저분하게 만듦("이전 질문이었던 2번…").
5. **place_npc 컴파일러 취약성.** 3연속 실패 — "commands[0].kind가 문자열이 아닙니다", "(page.conditions ?? []) is not iterable" — 후 성공. SimplePage→EventPage 컴파일러가 모델 출력에 취약하거나, 모델이 반복적으로 잘못된 args를 냈다. 자가수정이 구했지만 툴 예산/지연을 소모.
6. **스펙 게이트 과엄격.** 도로가 할당 영역을 **1칸** 벗어나자 하드 차단→전체 재계획. 1칸 여유(slack)만 줬어도 재계획 사이클을 피했다.
7. **모델 품질(flash-lite) 병목.** "하지 말고 되묻기" 성향과 place_npc 스래싱이 소형 모델 특성. evals 실측 25% 통과율과 일치. **계층화(계획=상위 모델)면 연못 겹침을 자율 해결했을 것.**
8. **지연은 수용 가능하나 턴 체감이 길다.** 첫 프로포절 15~18초(양호). 다중 툴 턴은 더 길고, **툴 실행 중 캔버스 진행 표시(고스트 프리뷰가 공간이 아니라 diff 텍스트뿐)가 없어** 기다림이 불투명.
9. **"미완성 콘텐츠 위의 클린 린트".** T4가 lint 0/0/0을 보고했지만 연못은 없다. lint는 무결성만 보고 의도/완성도는 안 본다. 에이전트가 미완 꾸미기를 언급 없이 "매우 깨끗"으로 제시.

## 종합 판정

- **커널(안전 아키텍처 + 에이전트 UX)은 진짜로 강하다.** 스펙 게이트/체인지셋/린트/프로포절/스킬은 상용급.
- 그러나 경험을 깨는 3가지: (a) 에이전트가 **사용자가 볼 수 없는 맵**을 편집하고, (b) 간판 타일 "흙길"이 **보라색으로 렌더**돼 옳은 산출도 틀려 보이며, (c) 소형 모델이 **하지 않고 되묻고** NPC 배치에서 스래싱한다.
- 즉 이 에이전틱 메이커는 "한 문장으로 플레이 가능한 맵 저작"은 증명했으나, **꾸미기**와 **자기 작업을 보여주기**는 아직 못 한다.

## 즉시 개선 제안 (우선순위)

1. **에디터 캔버스 자동 포커스**: create_map/paint/place_* 프로포절 수락 시 대상 맵으로 자동 네비게이트 + 편집 영역 하이라이트. (UX 최우선)
2. **"흙길" 타일 에셋/시맨틱 교정** — 보라 자갈이 아니라 갈색 흙길로. 지면 칩셋 밀도 통일 과제와 함께.
3. **진짜 빈 프로젝트 옵션** + "새 프로젝트"의 기본을 예제 로드가 아니라 빈 캔버스로(또는 명시적 "예제로 시작").
4. **place_npc 컴파일러 견고화** — 모델이 흔히 내는 malformed page/command를 관용 파싱하거나, 스키마 오류를 모델에 더 명확히 반환.
5. **스펙 게이트 1~2칸 slack** — 경계 근접 초과는 경고로, 하드 차단은 큰 이탈에만.
6. **모델 계층화** — 계획/공간추론은 상위 모델, 반복 배치는 소형. (합의 조항 9)
7. **공간 고스트 프리뷰** — 툴 실행 중 캔버스에 반투명 진행 표시.
8. **완성도 인지 린트** — "요청한 꾸미기가 미반영" 같은 의도-완성도 갭을 프로포절 요약에 노출.
