## 1. 현황 진단 (비판)

전제부터 명확히 하면: 이 편집기는 이미 "텍스트 덤프 수준"은 넘었다. 커맨드 요약에 톤 컬러(ON/OFF 배지, +=/-= 연산 색), 더블클릭 편집 모달의 우측 이미지 프리뷰 패널(`commandPreview.ts`), 드래그 재정렬(`commandListDragDrop.ts`), 키보드 단축키(Enter 삽입/Space 편집/Ctrl+X·C·V/Del)까지 갖췄다. 문제는 **이 좋은 인프라가 표면 절반에만 적용되어 있고, 나머지 절반(선택지 편집, 스위치 조작 폼, 이동 경로, 그래픽 선택, 커맨드 피커)은 레이아웃이 깨져 있거나 1990년대 텍스트 UI 그대로**라는 점이다.

### 1.1 치명 (기능적으로 깨진 것)

**[치명-1] 선택지 표시 편집 다이얼로그 — 패널 겹침으로 사실상 판독 불가**
- 근거: `12-choices-edit-dialog.png`
- "선택지 1 가지 편집" 인라인 패널이 우측의 "취소할 때" 라디오 그룹과 선택지 2~5 입력 필드 **위에 그대로 겹쳐서** 렌더링된다. 가지 안의 커맨드 줄(`[1001: 별등 의뢰...`)은 우측이 잘려 나가고, "선택지 2" 라디오는 패널 뒤에 반쯤 가려져 있다. 1720px 광폭 뷰포트에서도 재현되므로 창 크기 문제가 아니라 `choicesDialog.ts` + 가지 인라인 에디터의 레이아웃 결함이다.
- 더 근본적으로: 선택지 가지의 커맨드를 다이얼로그 안에서 또 편집하게 한 설계 자체가 메인 커맨드 리스트와 역할이 중복된다. RM2003 원본은 선택지 다이얼로그에서 텍스트/취소 동작만 정하고, 가지 내용은 리스트에서 편집한다.

**[치명-2] 스위치 조작 편집 다이얼로그 — 셀렉트 폭 붕괴 + 겹침**
- 근거: `13-switch-edit-dialog.png`
- 스위치 셀렉트가 90px 남짓으로 찌그러져 "1001: 별등 의..."로 잘리고, `...`(레코드 피커) 버튼과 **수직으로 겹쳐** 떠 있다. 필드셋 상단 보더가 셀렉트를 관통한다. 다이얼로그 면적의 70%가 빈 공간인데 정작 핵심 컨트롤이 뭉개져 있다. `commandBodyCore.ts`/`commandBodyVariable.ts` 계열 폼 그리드의 문제로 추정.

### 1.2 높음 (실사용에서 반복적으로 아픈 것)

**[높음-1] 커맨드 피커 — 숫자 탭 4개, 검색 없음, 같은 그룹명이 탭마다 반복**
- 근거: `09-command-picker-tab1.png`, `10-command-picker-tab2.png`, `10b-command-picker-tab3.png`, `17-command-picker-tab4.png`
- 탭 라벨이 "1 2 3 4" 숫자뿐이라 어느 탭에 뭐가 있는지 열어보기 전엔 알 수 없다. RM2003 원본 재현이긴 하나, 원본의 탭도 사용자들이 수십 년간 욕한 부분이다. 게다가 "맵/이동" 그룹이 탭1(장소 이동, 이동 경로)과 탭3(주인공 위치 얻기, 탈것)과 탭4(이벤트 호출/생성)에 흩어져 있어 같은 이름의 섹션이 다른 내용을 담는다. 검색/필터 입력이 없어서 "화면 흔들기"가 몇 번 탭인지 매번 순회해야 한다. 100여 개 버튼 전부 텍스트뿐, 아이콘 0개 (`m2ModernCatalog.ts`, `commandPicker.ts`에 icon 필드 자체가 없음).
- 탭4에서는 하단 고정 "취소" 버튼이 스크롤 콘텐츠("타이틀 화면으로" 버튼)와 겹친다.

**[높음-2] 이동 경로 다이얼로그 — 30여 개 텍스트 버튼 + 원시 리소스 ID 노출**
- 근거: `16-move-route-dialog.png`
- "위로 이동/오른쪽으로 이동/왼쪽 90도 회전…" 30여 개가 전부 같은 크기·같은 모양의 텍스트 버튼이다. 방향 커맨드에 화살표 아이콘 하나 없어서 스캔이 안 된다. 매개변수 영역에 `그래픽 ID: tex_easyrpg_charset_people1`, `효과음 ID: se_route_chime` 같은 **내부 리소스 ID가 날 것의 텍스트 입력으로 노출**된다 — 그래픽 피커(`npcGraphicPicker.ts`)가 이미 있는데도 여기선 안 쓴다. 좌측 경로 리스트는 빈 상태에서 `$>` 한 줄뿐이고, 입력한 경로가 맵 위에서 어떻게 움직이는지 시각화가 전혀 없다 (`previewMoveRoute.ts`가 있는데 이 다이얼로그에는 연결 안 됨).

**[높음-3] 스위치/변수 레코드 피커 — 검색 없음 + 빈 이름 지옥**
- 근거: `15-switch-record-picker.png`
- `[0001 - 0020]` 범위 페이지네이션만 있고 이름 검색이 없다. 좌측 범위 리스트는 20개 단위로 수십 줄을 스크롤해야 하고, 우측은 "0001:", "0002:" … 이름 없는 행 20개가 늘어선다. 스위치가 수백 개가 되는 실전 프로젝트에서 이 UI는 번호 암기를 강요한다. RM2003 원본 재현으로서는 정확하지만, 원본에도 있던 고통까지 재현했다.

**[높음-4] 그래픽 선택 다이얼로그 — 리스트는 텍스트, 프리뷰는 정지 프레임**
- 근거: `06-graphic-dialog.png`
- 좌측 리소스 리스트가 "Actor1, Monster1, Object2…" 텍스트 행이다. 행마다 붙은 조그만 색 줄무늬 아이콘은 내용물과 무관한 장식이라 정보가 0이다. 어떤 캐릭터가 들었는지는 클릭해서 우측 그리드를 봐야만 안다. 걷기 애니메이션 프리뷰가 없어 패턴(왼쪽/가운데/오른쪽) 라디오의 의미를 초심자가 알 수 없다. 하단에 `tex_easyrpg_charset_people2` 원시 ID 입력이 그대로 노출된다.

**[높음-5] 페이지 탭 — 맨숫자 1·2·3·4, 정보 스캔트 0**
- 근거: `03-event-editor-fullpage.png`, `11-page2.png`
- 좌측 세로 페이지 탭이 숫자뿐이다. 페이지 2가 "스위치 1001 ON일 때의 대사"라는 사실은 탭을 눌러 조건 패널을 읽어야만 안다. 4페이지짜리 장로 이벤트에서 원하는 페이지 찾기가 러시안룰렛이다. 페이지별 그래픽 썸네일도, 조건 요약 배지도, 페이지 이름도 탭에 없다.

### 1.3 중간

**[중간-1] 커맨드 리스트 — 종류 식별 시각 신호가 텍스트 라벨뿐**
- 근거: `07-command-list.png`
- 모든 행이 `◆ 라벨: 내용` 패턴이라 시각적 리듬이 균일하다. 톤 컬러(라벨 보라, 값 강조, ON 배지)는 잘 되어 있으나, 행 종류를 나타내는 아이콘·카테고리 색 레일이 없어서 20줄 넘는 스크립트에서 "소리 커맨드만 훑기" 같은 스캔이 안 된다. 아이콘 토큰 인프라(`CommandSummaryIconPart`)는 이미 있는데 아이템/장비에만 쓰인다.

**[중간-2] 실행 내용 영역의 공간 낭비**
- 근거: `03-event-editor-fullpage.png`
- 커맨드 12줄이 패널 상단 1/3에 몰리고 아래 2/3가 빈 공간이다. 반면 좌측 조건 패널은 안 쓰는 조건 행(타이머 1·2 등)까지 항상 펼쳐져 세로를 다 먹고, 트리거/우선순위/애니메이션/이동 속도는 스크롤 아래로 잘린다(이동 속도 셀렉트가 반쯤 잘린 채 렌더). 정보 밀도 배분이 반대로 되어 있다.

**[중간-3] 문장 표시 편집 다이얼로그 — 폼 절반이 빈 공간, 프리뷰에 얼굴 없음**
- 근거: `08-command-edit-form.png`
- 우측 라이브 말풍선 프리뷰(화자 이름 + 본문)는 이 편집기의 최고 자산이다. 그러나 좌측 폼은 화자/내용 두 필드가 어색하게 떠 있고 필드셋 레전드 "내용"이 보더 중앙을 관통한다. 얼굴 그래픽(변경된 faceset)이 프리뷰에 반영되지 않고, 문장 제어문자(\\C[n] 등) 힌트도 없다.

**[중간-4] 모달 깊이 — 최대 4겹**
- 이벤트 에디터 → 커맨드 편집 다이얼로그 → 선택지 가지 인라인 에디터 → 커맨드 피커/레코드 피커. 각 층이 ESC 한 번에 어디까지 닫히는지 예측이 안 되고, 배경 흐림(blur)이 겹칠수록 아래 문맥이 사라진다. 근거: `12-choices-edit-dialog.png`, `15-switch-record-picker.png`.

**[중간-5] 런타임 미지원 경고 배지(주황 삼각형)의 설명 부재**
- 근거: `10b-command-picker-tab3.png`, `17-command-picker-tab4.png`
- 피커 버튼 절반에 주황 삼각형 아이콘이 붙어 있는데(런타임 미지원 표시, `commandRuntimeBadge.ts`) 범례가 어디에도 없다. 초심자는 "경고인지 프리미엄 기능인지" 알 수 없다.

**[중간-6] 하단 버튼 행 — 삭제가 확인 바로 옆**
- 근거: `03-event-editor-fullpage.png`
- `삭제 / 확인 / 취소 / 적용 / 도움말`이 한 줄에 나열되고 파괴적 동작(이벤트 삭제)이 확인 버튼과 8px 간격이다. RM2003 원본도 이 배치가 아니다(삭제는 좌측 분리).

### 1.4 낮음

- **[낮음-1]** 모달 타이틀 "이벤트 에디터 · ID:0001"이 어느 이벤트(장로, 14,15)인지 말해주지 않는다. 이름은 폼 안에서만 보인다.
- **[낮음-2]** 모달 상단의 최소화(–)/최대화(□) 버튼 — 웹 모달에서 기대 동작이 불명확하고 눌러볼 이유도 없다.
- **[낮음-3]** 그래픽 프리뷰의 초록 크로마키 배경은 RM2003 감성 재현으로 좋으나, 선택 커서(흰 사각형)가 얇아 8개 캐릭터 그리드에서 현재 선택이 잘 안 보인다.

### 1.5 잘 되어 있는 것 (유지해야 할 자산)

- 커맨드 편집 모달의 이미지 리치 프리뷰 패널(`commandPreview.ts` — 말풍선 목업, ON 램프, 분기 플로우, 이동 경로, 그림/오디오 프리뷰 렌더러가 이미 존재).
- 커맨드 요약 톤 시스템(`commandSummary.ts` — op-add/op-sub/badge-on 등 의미론적 색).
- 드래그 재정렬 + 우클릭 컨텍스트 메뉴 + RM2003 단축키(Enter/Space/Ctrl+X·C·V/Del/Ctrl+A) (`14-command-context-menu.png`).
- 선택지/조건 분기 들여쓰기와 `: 받는다` 가지 라벨의 컬러 구분 (`07-command-list.png`).
- AI 명령 생성 드로어가 접혀 있어 RM2003 화면을 침범하지 않는 점 (`18-ai-assist-drawer.png`).

## 2. "이미지 리치 모던 편집기" 전환 방안

원칙: **기존 인프라(아이콘 토큰, 프리뷰 렌더러, 레코드 피커, 그래픽 피커)를 아직 안 쓰는 표면에 재사용**하는 것이 최우선이다. 새 개념 도입보다 싸고, 시각 언어도 통일된다.

### P0 — 깨진 것 수리 + 최소 비용 최대 효과 (1주 내)

| 방안 | 내용 | 난이도 | 근거 파일 |
|---|---|---|---|
| 선택지 다이얼로그 레이아웃 재설계 | 겹침 제거. 가지 인라인 에디터를 다이얼로그에서 제거하고 질문/선택지 텍스트/취소 동작만 편집(가지 내용은 메인 리스트에서). 우측 프리뷰는 유지 | 중 (레이아웃은 하, 가지 에디터 분리는 설계 결정 필요) | `src/editor/panels/eventEditor/choicesDialog.ts`, `commandBodyChoices.ts` |
| 스위치/변수 조작 폼 그리드 수리 | 셀렉트 최소폭 보장, `...` 버튼과 수평 배치, 빈 공간에 현재 값/참조 요약 표시 | 하 | `commandBodyCore.ts`, `commandBodyVariable.ts` |
| 레코드 피커 검색창 | 이름/번호 인크리멘털 필터 1개 추가. 범위 리스트는 유지(정체성) | 하 | `recordPicker.ts`, `classicRecordPickerDialog.ts` |
| 커맨드 피커 검색 + 카테고리 아이콘 | 피커 상단에 전 탭 통합 검색 필드. 그룹 헤딩에 카테고리 아이콘+색, 버튼에 16px 아이콘 슬롯. 탭 1~4 구조는 유지하되 탭에 대표 아이콘 부여 | 중 | `commandPicker.ts`, `m2PickerLayout.ts` (그룹 순서 상수 이미 존재), `m2ModernCatalog.ts` |
| 커맨드 리스트 카테고리 색 레일 | 행 좌측 2px 색 레일 + kind 아이콘. `data-command-kind` 어트리뷰트가 이미 렌더되므로 CSS 중심 작업 | 하~중 | `commandList.ts` (renderCommandItem 에 dataset.commandKind 이미 존재), `commandSummary.ts` 아이콘 토큰 확장 |
| 피커 하단 취소 버튼 겹침 수정 + 경고 배지 범례 | 푸터를 sticky 분리, 주황 삼각형에 title 툴팁 + 하단 1줄 범례 | 하 | `commandPicker.ts`, `commandRuntimeBadge.ts` |

### P1 — 이미지 리치 본편 (2~4주)

| 방안 | 내용 | 난이도 | 근거 파일 |

## 3. RM2003 정체성 보존 원칙

`docs/specs/rm2k3-fidelity-contract.md`는 "The editor can remain modern and resizable"라고 명시한다 — 즉 **계약상 충실도가 강제되는 곳은 런타임 표현(320x240, 16x16 타일, RM2K3 자원 프로파일)이지 에디터 크롬이 아니다.** 따라서 에디터 모던화의 법적 여지는 넓다. 그러나 이 프로젝트의 핵심 가치가 "RM2003 감각 복원"인 이상, 다음 경계는 침범하면 안 된다.

1. **실행 내용은 텍스트 스크립트가 정본이다.** `◆ 라벨: 내용` 줄, 들여쓰기, `: 가지명` 라벨, `@>`/`◆` 빈 줄 — 이 텍스트 표현을 카드/블록 UI로 대체하지 말 것. 아이콘·썸네일·색 레일은 텍스트 줄에 **부가**되어야 하며, 줄 높이가 상 아이콘 때문에 널뛰면 안 된다 (16px 상한 유지 — `commandSummary.ts`의 현행 아이콘 토큰 규약).
2. **커맨드 피커의 1~4 탭 구조와 한글 명령어 명칭은 유지한다** (`docs/specs/rm2k3-event-command-buttons.md`가 이를 작업 기준으로 못박음). 검색·아이콘은 추가하되, RM2003 사용자가 눈 감고도 찾는 위치(탭1 문장 표시 좌상단 등)를 재배열하지 말 것.
3. **키보드 문법은 RM2003 그대로.** Enter=삽입, Space=편집, Del=삭제, Ctrl+X/C/V — 이미 구현된 이 동선(`commandListContextMenu.ts`)은 어떤 모던화에서도 후퇴 금지.
4. **페이지 모델·조건 패널의 의미 구조 불변.** 조건(스위치 2개/변수/아이템/주인공/타이머 2개), 트리거, 우선순위, 이동 유형의 항목 구성과 용어는 RM2003 어휘를 유지한다. 접기/펼치기로 밀도만 개선.
5. **데이터는 구조화된 Command union 그대로** (fidelity contract: "structured, typed data rather than stringly typed blobs"). 시각화는 전부 파생 뷰여야 하며 편집 데이터 모델을 UI 사정으로 바꾸지 말 것.
6. **레코드 피커의 `[0001 - 0020]` 범위 리스트와 번호: 이름 표기는 RM2003 시그니처다.** 검색을 얹더라도 범위 내비게이션을 제거하지 말 것.
7. **모던 전용 표면(AI 드로어, 라이브 프리뷰, 플로우차트)은 기본 접힘 + 명시적 토글.** RM2003 화면 안으로 스며들지 말고 옆에 서 있을 것. 현행 AI 드로어의 접힘 처리가 좋은 선례.
