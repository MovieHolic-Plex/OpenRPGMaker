# 영역 작업 UI/UX 를 캔버스로 옮긴다 (2026-09-10)

목업: `docs/2026-09-10-region-task-uiux-redesign.html`
(렌더 이미지: `docs/2026-09-10-region-task-uiux-redesign-assets/{a-current,b-compose,c-running,d-result}.png`)

## 1. 왜

### 1.1 산수

1280 폭에서 캔버스는 **740px** 이다 (1280 − 좌측 패널 220 − AI 도크 320).
영역 작업 팝오버는 **380px** — 캔버스의 **51%**.

"창이 대상을 가린다"는 배치 버그가 아니라 산수였다. `avoid` 사각형 협상,
`positionRegionTaskPopover`, `schedulePopoverReposition` 재클램프는 전부 자리가 없는
문제를 자리를 옮겨 풀려던 시도였고, 옮길 자리가 애초에 없다.

### 1.2 한 컬럼이 성격이 다른 세 일을 맡는다

| 단계 | 필요한 공간 | 현재 |
|---|---|---|
| 작성 | 작다. 대상 **옆**이면 된다 | 380px 컬럼 — 적정 |
| 실행 | 거의 불필요. 배지로 충분 | 같은 컬럼의 타임라인 |
| 검토 | **크다. 대상 위에 겹쳐야** 한다 (기하 판단) | 같은 380px — 질식 |

작성 단계의 크기에 검토 단계를 맞춘 결과 검토가 죽었다.
`region-task.css:38` 의 기록이 증상이다 — `단일 A/B 미리보기 전환으로 팝오버 폭을
슬림하게 축소 (460 → 380)`. 검토를 넓히는 대신 좁혔다.

### 1.3 기하를 계산해 놓고 축척을 버린다

`RegionChunk.cells` 는 `{x, y, index}` 셀 목록 — 정확한 도형이다.
`changeOverlay()` 는 그 셀로 격자를 만들지만 **팝오버 안 74px 썸네일** 위에 그린다.
`describeChunkPosition()` 은 같은 기하를 평균 내 `"왼쪽 위"` 텍스트 한 조각으로 뭉갠다.

버려지는 것은 기하가 아니라 **축척**이다. 어휘(하이라이트 `is-focus`, 격리
`is-isolating`, 제외 `is-excluded`, 여백 2칸 컨텍스트 프레임, 이벤트 마커 연동)는
전부 이미 구현돼 있고 우표 크기에서 돌고 있다.

### 1.4 진입 시점 선택 과부하

아무것도 입력하지 않은 상태에서 노출되는 컨트롤 덩어리 7개:
모드 스위치(조수/생성기) · 추천 칩 + 「모두 보기」 · textarea · 「AI 없이 실내 초안」
(select 2 + 버튼) · 「주변과 어울리게 다듬기」 · 「AI 실행」 · 「중단」.
생성기 모드를 켜면 +5 (오퍼레이터 select · 파라미터 · 시드 · 「해석」 · 재료 슬롯 보드).

사용자가 진입 시점에 "AI 쿼터를 쓸까, 파라미터로 할까"를 판단할 근거는 없다.
그건 시스템이 아는 것이다 — `resolveOperatorIntent(instruction)` 이 **이미**
문장→오퍼레이터 설정 해석을 하는데, 지금은 「해석」 버튼 뒤에 있어서 사용자가
먼저 「생성기」를 골라야 닿는다.

## 4. 검토 표면 (핵심)

### 4.1 청크를 캔버스 도형으로

`RegionChunk.cells` 를 타일 좌표 → 화면 좌표로 변환해 클릭 가능한 도형으로 그린다.
새 데이터는 없다. 변환은 `regionClientRect.ts` 가 이미 하는 일과 같은 종류다.

상태 세 가지: 포함(기본) · 제외 · 포커스.
클릭 = 포함/제외 토글. hover = `is-focus` + 나머지 물러남(기존 `is-isolating` 어휘).

### 4.2 제외 = 고스트를 걷는다

썸네일에서는 제외를 **표시**할 수밖에 없었다(`is-excluded` 사선). 캔버스에서는
그럴 필요가 없다 — 제외한 청크의 고스트를 걷어 원본 타일을 그대로 보여주면 된다.

```
청크 토글
  → composePartialProject({ base, clipped, mapId, region, selectedChunkIds, groups })
  → replaceAgentGhostPreviewFromProjectDiff(base, partial)
```

`composePartialProject` 는 완성된 `Project` 를 돌려주고,
`replaceAgentGhostPreviewFromProjectDiff(base, draft)` 는 두 프로젝트 diff 를 고스트
셀 목록으로 만든다. `groups` 는 이미 계산된 `allChunks` 를 넘겨 재계산이 없다.
**고스트 렌더러는 한 줄도 바뀌지 않는다.**

얻는 성질: **미리보기와 적용이 같은 합성 함수를 쓴다.** 지금은 썸네일(전체 결과 고정)
+ 제외 표시를 사용자가 머릿속에서 합성해야 했고, 그 어긋날 여지가 구조적으로 사라진다.

부수 효과: 여백 2칸 컨텍스트 프레임(`expandRegion` 호출부, `hasPreviewMargin` 분기)
삭제 — 캔버스에서는 주변이 원래 보인다.

### 4.3 레이어 겹침

바닥/위 청크는 같은 칸을 공유할 수 있어 동시에 그리면 읽히지 않는다.
**한 번에 한 레이어만 활성.** 액션 바에 토글 2개 + 포함 카운트(`바닥 50/59`, `위 17/17`).
비활성 레이어 청크는 흐리게(존재만 알림), 클릭은 활성 레이어만.
기본 활성 = 변경 칸이 더 많은 레이어.

### 4.4 키보드 — 반드시 대체해야 하는 것

현재 청크는 `<input type=checkbox>` 라 Tab 순회 · Space 토글 · 포커스 하이라이트가
공짜로 따라온다. 캔버스 도형에는 없다. 그냥 옮기면 **키보드 사용자에게 기능이 사라진다.**

대체:
- 청크에 읽기 순서(위→아래, 좌→우) 부여, `tabindex` 로 순회
- Space = 토글, 화살표 = 이웃 청크 이동
- 순회 중 청크는 `is-focus`, 화면 밖이면 카메라 추적
- `aria-label` 은 `describeChunkPosition()` **재사용** — 이 함수는 삭제하지 않고
  시각 표현의 보조로 강등한다
- Enter 적용 / R 다시 / Esc 버리기 유지

### 4.5 액션 바

캔버스 하단 중앙, 얇은 알약:

```
[생성기로 만듦 · LLM 0콜 0.4초] | [바닥 50/59] [위 17/17] | [AI로 다시] [조절…] [다시 R] [확정 ⏎]
```

부분 선택 시 라벨 전환 규칙 유지: `선택한 N칸만 적용` / 전부 해제 시 disabled +
`적용할 구역을 고르세요`.

## 5. 작성 표면

```
┌─ 선택 사각형 위 (자리 없으면 아래) ──────────┐
│ [이 영역에…                      ] [다듬기 ▸] │
│  주변과 어울리게 · 침엽수 숲 · 오솔길 하나      │
└────────────────────────────────────────┘
```

- 입력이 비어 있으면 실행 버튼은 「다듬기」. 뭐라도 쓰면 「실행」.
  → 별도 `polishButton` 불필요
- 추천 칩 3개 (`suggestRegionCommandsByContext` + `nextSuggestedRegionCommands` 그대로)
- 입력 포커스 → `loadRecentInstructions` 드롭다운 (기존 기능 승격)

### 5.1 라우팅을 코드가 맡는다

```
실행
 ├ resolveOperatorIntent 성공 → 오퍼레이터 (LLM 0콜, 즉시, 시드 재롤)
 └ 실패 → intentDeclaration → 조수 / 실내 초안 (facility + space=interior)
```

값싼 경로를 먼저 시도한다.

### 5.2 사전 → 사후로 미루는 것

| 지금 (진입 시점) | 바뀐 뒤 |
|---|---|
| 모드 스위치 조수/생성기 | 없음. 액션 바가 경로를 표시 + 반대 경로 재실행 버튼 |
| 오퍼레이터 파라미터 · 시드 | 액션 바 `[조절…]` — 오퍼레이터 경로일 때만 |
| 「새 시드」 | `[다시 R]` 에 흡수 (같은 설정, 다른 시드) |
| 실내 프리셋 · 분위기 select | 문장으로. 안 맞으면 `[조절…]` |
| 재료 슬롯 보드 | `[조절…]` 안으로 |
| 「모두 보기」 카테고리 시트 | `commandPalette.ts` 로 이관. `ALL_REGION_COMMANDS` · `regionCommandCategories` 는 유지 |

컨트롤 덩어리 **7 → 5개** (입력 1 + 칩 3 + 버튼 1).

### 5.3 대가

라우팅을 코드가 정하므로 오라우팅이 발생한다. 완화: 액션 바가 경로를 말하고
반대 경로 재실행을 한 클릭으로 준다 (`생성기로 만듦 · [AI로 다시]`).
오라우팅이 한 클릭에 복구되고, 사용자가 두 경로의 차이를 **결과를 보고** 배운다.

## 6. 확정 모델 — 적용은 즉시, 확정은 지연

| | 지금 | 제안 |
|---|---|---|
| 결과 도착 | 고스트 + 승인 대기 | 이미 맵에 적용됨 (미확정) |
| 부분 제어 | 체크박스로 *적용할* 것 고르기 | 캔버스에서 *되돌릴* 청크 클릭 |
| 기본 상태 | 아무것도 적용 안 됨 | 전부 적용됨 |
| 버리기 | 「버리기」 버튼 | Esc |
| 종료 | 「적용」 버튼 | 다른 작업 시작 = 자동 확정 |

근거: **되돌리기는 볼 수 있는 것에 대한 행동이고, 적용은 상상해야 하는 것에 대한 행동이다.**

### 6.1 방어 세 겹

1. 미확정 리본이 캔버스 상단에 **항상** 보인다
   (`● 미확정 — 적용됨 76칸 · 되돌림 9칸 · 다른 작업을 시작하면 확정됩니다`)
2. Esc 한 번에 전부 원복
3. 확정 전에는 저장하지 않는다 — 저장은 확정을 의미한다

### 6.2 자동 확정 트리거 (명시)

다른 영역 선택 · 도구 변경 · 저장 · 맵 이동 · 새 AI 턴.
확정 시 토스트로 알리고 `mapEditHistory.undoMapEdit()` 에 **한 항목**으로 들어간다 —
확정돼도 ⌘Z 한 번이면 빠져나온다.

### 6.3 계약 변경

`pendingRegionApply` 의 의미가 "적용 전 승인" → "확정 전 되돌림 가능" 으로 바뀐다.
`vite-env.d.ts` 에 E2E · 하네스용으로 노출된 pending get/apply/discard 훅의 계약을
다시 써야 한다. **이 설계에서 공짜가 아닌 유일한 부분이다.**

## 7. 절대 깨뜨리면 안 되는 불변식

### 7.1 부분 적용을 열어도 되는 조건

```
partialUseful = 청크 2개 이상 && 구조 제안 아님 && 이벤트 변경 없음
```

`composePartialProject` 는 **타일만** 옮긴다. 이벤트가 섞인 제안에 부분 적용을 열면
NPC 이동 · 상자 배치가 조용히 사라진다(다듬기는 재배치가 본업이라 특히 위험).
실내 · 맵 추가 제안은 타일만 부분 복사하면 문 · 맵 · 세션이 분리된다.

→ 캔버스에서도 동일. **부분 적용 불가 제안은 청크 도형을 그리지 않는다.**
대신 액션 바에 `이 제안은 통째로만 적용됩니다` 한 줄. 도형이 있으면 클릭할 수 있다고
믿게 되므로 없는 것이 정직하다.

### 7.2 칸 수는 `pending.changedCells`

청크 셀 합산은 레이어별로 따로 세므로 한 칸이 양쪽에서 바뀌면 2가 된다
(코드 주석의 실측: 버튼 18칸 vs 요약 12칸). 액션 바 라벨도 같은 출처를 쓴다.

### 7.3 표면 열림 신호

`escapeToPan.ts` 와 `coachMarks.ts` 가 `.region-task-backdrop` **클래스 존재**로
"영역 작업 창이 떠 있다"를 판정한다. 팝오버를 없애면 조용히 깨진다 — Esc 가 캔버스
팬으로 새고, 코치 카드가 검토 중에 튀어나온다.

→ `dispatchRegionTaskStatus` 를 단일 진실원으로 승격하고 두 곳이 클래스 대신 구독한다.

## 9. 테스트 전략

기존 26개 테스트 파일이 `regionTaskModal` 또는 `region-task-*` 클래스를 참조한다.

- **순수 로직 우선**: 청크 → 화면 사각형 변환, 토글 상태 기계, 키보드 순회 순서는
  DOM 없이 테스트 가능한 순수 함수로 분리한다 (`regionChunkOverlay.ts`).
- **불변식 테스트**: `partialUseful` 조건과 `changedCells` 출처는 회귀 테스트로 고정.
- **기존 testid 유지**: `region-task-chunk-${id}` 등은 캔버스 도형에 그대로 옮겨
  하네스 · E2E 의 querySelector 경로를 살린다.
- **A/B 절차**: `npm run gates` 의 "새로 실패" 는 베이스라인이 낡아 과보고한다.
  변경 전후로 해당 파일만 재실행해 실패 이름 집합을 비교한다.
