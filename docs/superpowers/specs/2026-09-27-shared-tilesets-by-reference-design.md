# 공용 타일셋을 프로젝트 문서에 복사하지 않고 참조로 두기 (설계)

상태: 1단계 구현(2026-09-27) — **저장소 층에서만** 접는다. `electron/local-store/tilesetFold.ts` 가 타일셋마다 내용 주소 본문을
`tileset_blobs` 에 두고 `current_json` 에는 `{"$blob":sha}` 표식만 남긴다. 문서 해시·와이어·렌더러는 그대로라
아래 3.2–3.6(렌더러 쪽 `$shared` 참조, 판본 고정)은 아직 제안이다. 실측과 계약은 `openwiki/runtime-project-schema.md`
「타일셋 접기」. 렌더러가 81MB 를 받고 파싱하는 비용은 이 단계로 줄지 않는다.
배경 측정: `verify-shots/perf-app-save/SUMMARY.md` (Electron 앱, 실제 82MB 프로젝트 `ce922871` 사본).

## 1. 문제

프로젝트 문서 `project.current_json` 81.6MB 중 80.7MB 가 `tilesets` 다. 실측(2026-09-27, `ce922871`):

| 출처 | 칸 수 | 크기 | 큰 필드 |
|---|---:|---:|---|
| 앱 번들 (`BUNDLED_EASYRPG_CHIPSET_ASSETS` → `ensureBundledTilesets`) | 38 | 24.6MB | tileMeta 10.7 · referenceDocuments 6.5 · passability 3.7 |
| 공용 카탈로그 (`shared_*`, `ensureSharedContent`) | 316 | 56.1MB | tileMeta 16.6 · referenceDocuments 15.4 · structureKits 13.3 · passability 5.8 |
| 저자가 만든 타일셋 | 0 | 0 | |

저자가 쓴 바이트는 1MB 안팎이다. 나머지는 앱 번들이나 호스트 카탈로그에 이미 있는 사본을 프로젝트마다 한 벌씩 더 저장하는 것이다.
작업실 폴더의 프로젝트 파일이 하나에 37–245MB 인 이유가 이것이다.

앱으로 옮겨도 이 비용은 사라지지 않는다. 앱은 네트워크 대신 IPC 를 쓰지만, 렌더러가 82MB 를 파싱·정규화·복제·비교하는 일은 그대로다.
앱 실측: 부팅 33–50s, 저장 한 번 18–27s, 한 칸 칠하기(도구) 5–8s.

2026-09-27 의 구조 공유(안 바뀐 타일셋 객체를 복제하지 않는다, 이 설계와 같은 PR)로 저장·편집의 복제는 줄였지만,
로드(파싱·정규화·요약), 저장 파일 크기, 조수 저장 증명의 전체 요약은 문서 크기에 비례해 남는다.

## 2. 목표 / 비목표

목표
- 프로젝트 행에는 저자가 소유한 데이터와 "이 공용 타일셋을 이 판본으로 쓴다"는 참조만 남긴다.
- 로드된 편집기 메모리의 `project.tilesets[id]` 모양은 바꾸지 않는다 — 331곳의 `store.update` 와 도구가 그대로 동작해야 한다.
- 저자가 공용 타일셋을 고치면(통행·메타·그룹) 그 차이만 프로젝트에 남는다.
- 내보낸 게임(`player.html`, `.oprn` 패키지)은 자급자족한다 — 참조를 풀어 실제 값을 싣는다.

비목표
- 공용 카탈로그 자체의 전송 최적화(이미 판본 캐시·304 가 있다).
- 타일 그림 바이트(이미 `assets/` 와 `oprn-asset://` 로 분리됨).

## 3. 설계

### 3.1 저장 형태

```jsonc
// project.current_json
"tilesets": {
  "forest_harmony": { "$shared": { "source": "bundled", "revision": "<bundle sha>" }, "$overlay": { "passability": { "412": 3 } } },
  "shared_paw_direct_food": { "$shared": { "source": "catalog", "revision": "<catalog revision>" } },
  "my_custom_sheet": { /* 저자 소유: 지금과 같은 전체 TilesetDef */ }
}
```

- `$shared` 가 있으면 로더가 번들(`bundledEasyRpgTileset` 계열)이나 카탈로그(`sharedContentTileset(id)`)에서 원본을 가져와 펼친다.
- `$overlay` 는 원본 대비 저자 변경분이다. 필드 단위 병합이 아니라 경로 단위 패치로 둔다(배열 칸·사전 키 단위). 형식은 기존 `ProjectDocumentPatch` 의 dict-patch 를 재사용한다.
- 저자 소유 타일셋은 지금과 똑같이 저장한다.

### 3.2 로드 (펼치기)

`deserialize` 뒤, `normalizeCurrentProject` 앞에서 한 번 펼친다. 결과는 지금과 같은 `Project` 다.
- 번들 원본은 앱과 같이 배포되므로 항상 있다. 카탈로그 원본은 `loadSharedContent({ scope: 'defaults' })` 가 끝난 뒤에만 있다.
  원본이 없으면(오프라인·카탈로그 판본 불일치) **로드를 막지 않는다**: 그 칸을 읽기 전용 자리표시로 두고 저장에서 참조를 그대로 되쓴다.
- 펼친 원본 객체는 모든 프로젝트·모든 로드가 **공유**한다(동결). 오버레이가 없는 칸은 같은 객체를 가리키므로 복제·비교가 공짜다.
  이것이 2026-09-27 구조 공유의 연장이다 — 스토어는 타일셋을 update draft 로만 바꾸므로 공유 객체가 제자리에서 바뀌지 않는다.

### 3.3 저장 (접기)

`projectWireView` 단계에서 접는다: 각 칸을 원본과 비교해 같으면 `$shared` 만, 다르면 `$shared + $overlay` 를 쓴다.
- 원본 객체와 같은 객체면 비교 없이 참조만 쓴다(대부분의 칸).
- 다르면 `diffProjectDocuments` 의 dict-patch 로 오버레이를 만든다. 오버레이가 원본 크기의 절반을 넘으면 저자 소유로 승격해 전체를 쓴다(원본 판본이 바뀌어도 저자 결과가 흔들리지 않게).
- 커밋 로그·맵 패치·팀 병합은 **펼친 문서**로 계속 동작한다. 접기는 와이어 경계에서만 한다.

### 3.4 판본이 바뀔 때

- 번들 판본(앱 업데이트)이나 카탈로그 판본이 바뀌면 로드 시 새 원본을 펼치고 오버레이를 다시 얹는다.
- 오버레이가 가리키는 칸이 새 원본에 없으면(칸 수 축소) 그 항목은 버리지 않고 저자 소유로 승격한다.
- 기존의 `ensureBundledTilesets` / `ensureShared*References` 보강기는 "원본을 갱신"하는 일이 되어 프로젝트 행을 고치지 않는다 — 이것만으로 로드 정규화 대부분이 사라진다.

### 3.5 이관

1. 로더가 두 형태(전체 TilesetDef, `$shared`)를 모두 읽게 한다. 이 단계에서는 저장이 여전히 전체를 쓴다(되돌리기 쉬움).
2. 저장이 접기를 쓰게 한다. 기존 프로젝트는 다음 저장에서 저절로 줄어든다. 첫 저장 전에 `backups/` 스냅숏을 한 번 남긴다.
3. 호스트 작업실 전체를 스크립트(`scripts/content/fold-shared-tilesets.mjs`, 신규)로 한 번에 접는다 — 감독자가 백업 확인 뒤 실행.

문서 스키마 판본(`document_version`)을 올린다. 옛 앱은 `$shared` 를 못 읽으므로 이관 2단계는 앱 배포 뒤에만 켠다
(`openwiki/release-and-version.md` 의 문서 스키마 축).

### 3.6 내보내기

`webExport` / `.oprn` 패키지 / `player.html` 은 펼친 문서를 싣는다. 게임은 카탈로그를 모른다.

## 4. 기대 효과 (추정 — 구현 후 같은 하네스로 잰다)

- 프로젝트 행: 81.6MB → 1–2MB. 작업실 폴더·백업이 같은 비율로 준다.
- 로드: 파싱·정규화·요약이 저자 데이터 크기에 비례. 공용 원본은 앱 수명 동안 한 번 펼친다.
- 저장 증명·체크포인트의 전체 요약: 공유 원본은 요약 기억이 앱 수명 동안 유지된다.

## 5. 위험과 결정할 것

- **카탈로그가 없는 환경**: 오프라인 앱에서 `shared_*` 원본이 없으면 그 타일셋을 그릴 수 없다. 번들로 옮길지(앱 크기 증가), 프로젝트 폴더에 원본 캐시를 둘지 결정이 필요하다. 권장: 프로젝트 폴더 `assets/shared-tilesets/<revision>.json` 캐시 — 폴더를 통째로 옮겨도 열린다.
- **공유 객체의 제자리 수정**: 계약 위반 하나가 모든 프로젝트를 오염시킨다. 펼친 원본을 `Object.freeze` 로 깊게 동결해 위반을 즉시 예외로 만든다(개발·테스트 빌드). 2026-09-27 감사 결과는 이 PR 설명에 있다.
- **팀 호스트 병합**: 오버레이 단위 병합이 필요하다. 첫 단계는 칸 단위(타일셋 id) 병합을 유지한다 — 지금과 같다.
