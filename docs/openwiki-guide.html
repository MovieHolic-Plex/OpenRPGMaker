OpenWiki는
에이전트의 작업 지도다

이 프로젝트의 OpenWiki는 유저 매뉴얼이 아닙니다. 코딩 에이전트가 코드를 건드기기 전에 읽는 프로젝트 전용 설명서 서랍입니다. 파일 구조 · 읽는 순서 · 실제 활용 루프를 한 장에 정리합니다.

경로 openwiki/ 입구 AGENTS.md 페이지 12개 갱신 npm run openwiki:cpen 검증 npm run openwiki:verify
한 줄 요약 비유 파일 구조 페이지 카드 읽는 순서 시나리오 코드 소유권 작업 루프 유지보수 안 하는 것

1. 한 줄로 이해하기

🧭

OpenWiki = “어디를 열고, 뭘 조심하고, 어떻게 검증할지” 알려주는 AI용 지도

앱 기능이 아닙니다. 게임 도움말도 아닙니다. AGENTS.md가 입구 안내판이고, openwiki/ 안의 마크다운이 구역별 작업 수칙입니다.

구조 읽는 법

입구 2개 — 루트 AGENTS.md + openwiki/PROJECT_WIKI.md. 둘 다 “어디부터 읽지?”를 알려줍니다.

핵심 4장 — quickstart, architecture, ai-workflow, testing. 거의 모든 작업의 뼈대입니다.

대형 2장 — editor-workflows, runtime-and-data. 실무 디테일이 몰려 있습니다. 통째로 외우지 말고, 작업 영역에 맞는 섹션만 파세요.

포커스 페이지 — 마을 생성, 오토타일, 성 맵처럼 한 서브시스템 전용.

유지보수 — cpen 래퍼와 verify 스크립트. 문서 자동 갱신/존재 검사용.

5. 어떻게 읽나 (필수 순서)

에이전트는 파일을 감으로 뒤지지 않습니다. 이 순서를 탑니다.

1

AGENTS.md

루트 입구. “wiki 먼저 읽어” + Supabase 하드 룰 확인.

2

PROJECT_WIKI

전체 지도. 소유 경계와 어떤 세부 페이지로 갈지 결정.

3

영역 페이지

editor / runtime / village / architecture / testing 중 필요한 것만.

4

소스 파일

wiki가 지목한 실제 코드만 연다. 랜덤 탐색 금지.

5

검증 계획

어떤 테스트/브라우저 시나리오로 증명할지 정한 뒤 수정.

📌

핵심 원칙

wiki가 소스와 충돌하면 당장 고칠 때는 소스가 이긴다. 고친 뒤에는 같은 작업 안에서 wiki를 맞춰서, 다음 에이전트가 또 헛발질하지 않게 한다.

6. 실제 시나리오로 읽기

시나리오 A

“세이브 스키마 필드 추가”

“100×100 강 마을 만들어”

  • 3

8. 어떻게 활용하나 (작업 루프)

Phase 1 · Before

지도 읽기

AGENTS → PROJECT_WIKI → 영역 페이지 → 지목된 소스. 검증 방법도 미리 고른다.

Phase 2 · During

경계 안에서 수정

소유 모듈 안에서 고친다. 스키마 건드리면 migration/fixture/save 경로까지 같이 본다.

Phase 3 · Sync

Wiki 동기화

구조·워크플로·위험 포인트가 바뀌면 같은 작업에서 해당 openwiki 페이지를 업데이트.

Phase 4 · After

검증 + 보고

가장 가벼운 테스트부터. UI는 브라우저 증거. 콘텐츠는 Supabase 재로드 증명.

# 작업 끝
[ ] 관련 openwiki 페이지 갱신 (구조/규칙 변경 시)
[ ] 최소 검증 실행
[ ] 콘텐츠면 Supabase save + reload + project id 보고

9. 유지보수 커맨드

문서 자동 갱신

글로벌 openwiki CLI를 CPEN 래퍼로 감싸 호출. 페이지 단위로 돌릴 것 (토큰 예산).

npm run openwiki:cpen

# 필요 env
CPEN_API_KEY=...
OPENAI_BASE_URL=https://cpenrouter.space/v1

존재/엔트리 검증

필수 페이지와 AI 입구가 있는지 검사. wiki-only 수정 후 최소 게이트.

npm run openwiki:verify

# 구현
scripts/verify-openwiki-editor-wiki.mjs
⚠️

이 프로젝트의 커스텀 포인트

공식 langchain-ai/openwiki를 “그대로” 쓰는 게 아닙니다. scripts/openwiki-cpen.mjs가 글로벌 CLI를 찾고, non-stream 패치 + CPEN fetch 어댑터를 씌운 뒤 실행합니다. 페이지 레이아웃도 이 에디터 전용으로 커스텀되어 있습니다.

10. 하는 것 / 안 하는 것

✅ OpenWiki가 하는 일

  • 에이전트 pre-edit 컨텍스트 제공
  • 모듈 소유권·위험 포인트 안내
  • 영역별 소스 파일 지도
  • 검증 기대치 공유
  • 구조 변경 시 다음 에이전트에게 지식 전달

❌ OpenWiki가 아닌 것

  • 플레이어용 게임 도움말 / 제품 UI
  • 맵·이벤트 콘텐츠 정본 (정본은 Supabase)
  • blankProject / fixture만으로 끝내는 변명
  • API 키·실자격 증명 저장소
  • 소스 대신 믿는 절대 진리 (충돌 시 소스가 이김)
🚫

콘텐츠 작업 함정

?blankProject=1 / ?freshProject=1 / 일부 dev-showcase는 remotePersistenceEnabled = false 입니다. 그 경로에서 저장 버튼을 눌러도 Supabase로 안 갑니다. 마을·맵·이벤트·데모 게임 작업은 원격 저장 + 재로드 증명까지가 완료입니다.
