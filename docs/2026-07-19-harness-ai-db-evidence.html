정리 — "봇은 이 스탬프를 어떻게 이해하는가"의 실증 답

  • 이해: 봇에게 스탬프는 그림이 아니라 structureKits 행렬 데이터다. 시스템 프롬프트 다이제스트가 존재를 알리고, list_structure_kits가 행렬을 준다.
  • 사용: stamp_structure_kit은 위치·반복만 받는 결정론 시공 — 타일 선택권은 끝까지 유저의 학습물에 있다(castleKit/houseKit 규약에 편입).
  • 관리: 같은 데이터가 DB '스탬프' 탭에서 타일 렌더로 보이고, 개명·삭제·팔레트 사용이 즉시 전 표면(팔레트/AI 다이제스트)에 반영된다.

한계·주석

  • 주석 실 LLM 왕복(채팅 "화단 이어줘" → 모델이 스스로 툴 선택)은 시도했으나 저장소 env의 LLM API 키가 프로바이더에서 무효 토큰(HTTP 429)으로 거부되어 캡처하지 못했다. 본 증거는 모델이 구동하는 기계 표면(프롬프트+툴 경로) 실측이다 — 유효한 키만 있으면 같은 경로가 그대로 돈다.
  • 주석 상위 레이어 킷은 하위(잔디 받침)까지 함께 굽는다 — 받침 없는 "상위 전용 스탬프" 옵션은 미구현.
  • 주석 팔레트 '찾기' 탭이 이 기준선에서 0×0으로 렌더되는 기존 결함을 발견(본 작업과 무관·미수정) — e2e는 상위 레이어 시트로 우회했다.
