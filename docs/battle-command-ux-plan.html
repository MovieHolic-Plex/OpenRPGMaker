전투 처리와 전투 커맨드 변경

둘 다 “전투”라는 단어만 공유하고 작업 대상이 다르다. 전자는 지금 이 이벤트에서 어떤 싸움을 열까, 후자는 주인공 전투 메뉴 버튼을 어떻게 고칠까. 지금 화면은 둘 다 그 질문에 먼저 답하지 않는다.

상태 P0 설계 (구현 전 플랜) 범위 battleProcessing + m2 Change Battle Commands 날짜 2026-07-17 앵커 commandBodyDatabase.ts · commandBodyM2.ts
TL;DR 지금 깨짐 멘탈 모델 전투 처리 타깃 커맨드 변경 타깃 정보 구조 페이즈 파일 다음 액션

TL;DR 결정

  1. 두 명령을 하나로 합치지 않는다. 전투 처리 = 전투 세션 시작, 전투 커맨드 변경 = 메뉴 버튼 편집.
  2. 전투 처리는 “적 그룹 카드”가 메인. 탈출/패배/전투 방식은 규칙 카드로 내려보낸다.
  3. 전투 커맨드 변경은 generic M2 폼을 버린다. 대상 액터 + 조작(추가/제거/설정) + 커맨드 슬롯 미리보기.
  4. 프리뷰가 답을 말한다. 전투 처리 → 미니 전장 + 적 목록. 커맨드 변경 → 전투 메뉴 버튼 바.
  5. P0는 UX/스키마 최소 확장. battleProcessing은 레이아웃+프리뷰 강화 우선. Change Battle Commands는 전용 폼 + 세션 오버라이드 런타임까지 묶는다.
이미 있는 것: battleProcessing { troopId, canEscape, canLose, battleFlow? }, 트룹/적 DB, 직업 classes[].battleCommands, 전역 database.battleCommands, 우측 미니 전장 프리뷰 뼈대.
약한 것: 전투 처리 폼이 “드롭다운+체크박스 한 줄”. Change Battle Commands는 M2 껍데기만 있고 대상 필드가 자유 텍스트, 미리보기는 operation:set 원시 덤프.

전투 처리 전투 커맨드 변경 공통

전투 처리 — 지금 스크린샷

  • 1 메인 질문이 “누구랑 싸워?”인데 빈 드롭다운만 큼직하다.
  • 2 탈출/패배/전투 방식이 같은 줄에 몰려 규칙이 안 읽힌다.
  • 3 우측 프리뷰는 배경 이미지만 있고 적 멤버·보상·결과 분기가 없다.
  • 4 필드 몬스터/보스/도망 불가 전투 같은 장르 프리셋이 없다.
  • 5 트룹 미선택 경고가 약하다. 빈 전투 명령을 확인해도 티가 안 난다.

전투 커맨드 변경 — 지금 스크린샷

  • 1 제목은 “전투 커맨드 변경”인데 셀렉트는 “M2/현대 명령”.
  • 2 대상이 자유 텍스트. 주인공 얼굴/이름 픽커가 없다.
  • 3 조작=설정 하나만 보이고 추가/제거 의미가 안 보인다.
  • 4 커맨드 선택 후 “선택 없음” 유령 필드가 남아 레이아웃이 깨진다.
  • 5 우측 프리뷰가 디버그 문자열: operation:set.
  • 6 런타임이 부분 지원(m2-092 partial). 폼만 있어도 실행 기대가 어긋난다.

멘탈 모델

전투 처리 = 전투 세션 열기

작가가 고르는 것:

  1. 어느 적 그룹(troop)과 싸울지
  2. 도망/패배 규칙
  3. 게이지 vs 엄격 턴제(옵션)
  4. (후속) 승리/패배/도망 분기

엔진 앵커: pause("battleProcessing") → PlayScene 전투 → battleResult.

전투 커맨드 변경 = 메뉴 버튼 편집

작가가 고르는 것:

  1. 누구의 전투 메뉴인가 (주인공 / 파티)
  2. 무엇을 하는가 (추가 / 제거 / 목록 설정)
  3. 어느 커맨드인가 (공격·스킬·아이템·방어…)

엔진 앵커: 직업 기본 메뉴 + 세션 오버라이드. DB 직업 편집과 이벤트 편집을 혼동하면 안 된다.

비유: 전투 처리는 “던전 문 열기”, 전투 커맨드 변경은 “컨트롤러 버튼 리맵”. 같은 방(전투)을 다루지만 도구가 다르다.

폼 규칙

  • 1행 트룹 카드(아이콘+이름+멤버 부제). 빈 값이면 빨간 배지 “적 그룹 필요”.

  • 3행(선택 P1) 결과 분기 토글: 승리/패배/도망 시 이벤트 본문에서 마커로 편집 (choices/fork 패턴 재사용).
