사용자 편집 가능한 하네스 — 타일셋 지식 개방 설계안

rpg-zzu · 2026-07-18 · 전제 문서: docs/2026-07-18-harness-tileset-failure-log.html(실패 사례집) · docs/2026-07-18-castle-grammar.html(캔버스 역공학 실증) · 오토타일 템플릿 위저드(구현 완료 2026-07-16)

지금까지 모인 하네싱 자산 — 타일 시맨틱, 오토타일 그룹, 하우스/성 킷, 문법 린트 — 은 대부분 코드 정본이다. 사용자가 자기 칩셋과 자기 문법으로 이걸 바꿔 쓰려면, 정본을 데이터로 옮기고 코드는 해석기로 내려앉히는 개방 설계가 필요하다. 이 문서는 그 방법을 4계층 모델 + 캔버스 학습 루프로 제안한다.

① 현황: 무엇이 열려 있고 무엇이 갇혀 있나 ② 설계 원칙 ③ 4계층 개방 모델 ④ 캔버스 학습 루프 ⑤ L3 킷 편집기 ⑥ L4 문법 규칙 ⑦ 안전장치 ⑧ 로드맵

요약: 타일 단위 지식(L1·L2)은 이미 개방돼 있다. 갇혀 있는 것은 "타일 여러 장을 묶는 지식" — 킷(구조물 조립법)과 문법(조합 규칙)이다. 이 둘을 여는 것이 이 설계의 본론이다.

② 설계 원칙 — 실패 사례집에서 도출

  1. 정본은 데이터, 코드는 해석기. 같은 지식이 코드 상수와 UI 양쪽에 있으면 반드시 어긋난다(라벨 이중 소스 458/480 사건). 편집 가능하게 만드는 순간 코드 상수는 "기본값 시드"로 강등한다.
  2. 불변식은 편집기가 강제한다. 자유 편집이 member≠variantMap 같은 위반을 만들 수 있으면 성형이 사용자의 손맵을 파괴한다. 위저드/편집기는 "잘못 만들 수 없는" 입력만 노출한다(템플릿 종류+앵커 → 그룹 자동 생성이 그 모범).
  3. 미리보기 없이 커밋 없음. 모든 편집은 실제 성형/조립 렌더 미리보기(render_group_sample 계열)를 거쳐 승인한다 — 우리가 문법을 검증한 방법 그대로.
  4. 사용자 수정은 시드를 이긴다, 영원히. source:"user" 우선 + 삭제 톰스톤. 하네스 자가 치유 시드는 사용자 레코드를 절대 덮지 않는다.
  5. 게이트는 하드, 그러나 사용자의 것. 문법 린트는 계속 하드 게이트로 작동하되, 그 규칙 자체를 사용자가 고치거나 끌 수 있어야 한다 — "내 칩셋에선 데크 없는 벽이 정상"일 수 있다.
  6. 실측이 코드보다 정본. 사용자가 직접 찍은 맵에서 문법을 역공학하는 경로(§④)를 1급 시민으로 만든다 — 성 문법 정본화에서 2회 실증된 워크플로다.

③ 4계층 개방 모델

L2 마무리 2건 선행 과제

위저드는 이미 동작한다(템플릿 4종, 42/42 테스트). 남은 것: ① 커스텀 물 애니 실재생 — 렌더 2곳의 isDefaultTilesetTexture 가드를 animationStrips 기반으로 교체, ② 앵커를 칩셋 미리보기 시트 클릭으로 선택(현재는 번호 입력). 이 2건이 끝나야 "내 칩셋을 들고 와서 물·길·지형을 전부 직접 등록"이 완결된다.

④ 킬러 워크플로 — 캔버스 학습 루프 신규 제안

성 문법이 정본화된 실제 경로를 그대로 제품화한다: 사용자가 캔버스 맵에 직접 찍으면, 시스템이 문법을 역공학해 킷과 린트를 제안하고, 승인하면 하네스에 등록된다. "설정 화면에서 규칙을 작문"하는 것보다 압도적으로 자연스럽다 — 사용자는 이미 타일을 찍을 줄 알기 때문이다.

⑤ L3 — 킷을 데이터로: 스키마와 편집기

킷 레코드는 세 가지 원자로 충분하다는 것이 성·집·울타리 정본화의 결론이다: 단면(section) — 북→남 행 순서 규칙, 세트(set) — 함께 배치되는 페어/묶음, 반복(repeat) — 어느 조각이 어느 축으로 늘어나는가. 성 커튼월을 레코드로 쓰면:

⑥ L4 — 문법 린트를 선언적 규칙으로

성 린트 (a)~(h)를 일반화하면 규칙 원형은 놀랄 만큼 적다. 아래 6종이면 성·집·울타리·소품 문법이 전부 표현된다:

규칙 원형선언 예 (JSON)커버하는 실사례
requireAbove{ "when":[51,81], "above":[109,"walk",19] }성 (a) 데크 없는 맨 벽 금지
forbid{ "tiles":[21,48,79,50] }성 (b)(h) · 바위 441/442 밴 · 443 밴
pair{ "tiles":[179,209], "axis":"vertical" }성 (f) 반쪽 배너 · 석상 266+296 · 나무 수관+밑동
preserveUnder{ "upper":[24,25,54,55], "keepLower":true }성 (d) 캡·베이스 잔디 강제 금지
stackPattern{ "columns":2, "rows":[…], "alternate":[…] }성 (e) 타워 창 교대 · 킷 stack과 공유
noCut / fullPierce{ "protect":["deck-top","deck-walk"], "pierce":["gate-stair"] }성 (c)(g) · 지붕 침범 · 길↔데크 침범

규칙은 tileset.grammarRules[]에 저장되고 — 캔버스 학습이 초안을 만들고, 문법 탭에서 on/off·수정 — 모든 평가 게이트(evaluate_castle/village/interior)와 에디터 실시간 경고가 같은 규칙을 소비한다. 에디터 통합이 중요하다: 사용자가 직접 찍는 중에도 위반을 옅은 하이라이트로 보여주면(차단은 하지 않음, RM 감성 유지) 문법이 "시공 도구의 규칙"이 아니라 "칩셋의 지식"이 된다.

⑦ 안전장치 — 자유가 파괴가 되지 않게

  1. 시드 vs 사용자: 자가 치유 시드는 source!=="user"인 레코드만 갱신. 시드 킷을 수정하면 사본이 생기고 원본은 🔒 유지 — "기본으로 되돌리기"가 공짜가 된다. 삭제는 톰스톤(그룹 삭제와 동일 규약).
  2. 불변식 강제: 킷 편집기는 member=variantMap급 위반을 만들 수 없는 입력만 노출(행 단위 편집, preserveLower가 스키마 기본값 true). 린트 통과가 저장 게이트.
  3. 영향 미리보기: 킷/규칙 변경 시 "이 킷을 쓴 기존 맵 N개" 목록 + 대표 1곳 전/후 렌더. 소급 재시공은 하지 않는다 — 맵은 데이터, 킷은 다음 시공부터.
  4. 버전과 출처: 킷 레코드에 version·learnedFrom·수정 이력. 캔버스 재학습은 새 버전 제안으로(덮어쓰기 아님).
  5. 멀티 에디터: 킷/규칙도 프로젝트 저장 경로에 실림 — 기존 LegacyDb 충돌 병합 규약을 그대로 탄다. AI 어시스턴트의 킷 수정은 반드시 소프트 컨펌 경유(직접 쓰기 금지 — propose_tile_vocabulary를 LLM 비노출로 강등했던 것과 같은 원칙).

순서의 논리: 스키마(P1) → 게이트(P2) → 입력 방법(P3). 캔버스 학습을 먼저 만들면 학습 결과를 담을 그릇과 검증할 게이트가 없다. 성을 파일럿으로 세로 관통을 먼저 뚫고(P1~P3), 수평 전개(P4)는 그 다음이다.
