# 2026-07-07 도그푸딩 비판 평가 — "모든 맵 삭제 후 에이전트로 마을 만들기"

> 감독(Claude Fable 5) 직접 수행. 지시: "모든 맵을 삭제하고, 에디터 기능만으로 마을 하나를 만들어라. 에이전트를 최대한 이용하고 비판적으로 평가하라."
> 환경: feat/phase-6a 942b350 빌드(9988 정적 서빙) + dev 서버. 인-에디터 AI = `google/gemini-3.5-flash` (사용자 확정 상위 모델).
> 증거: `evidence/fable-village-eval/` (P1~P10 스크린샷 + 타임라인 + p9/p10 상세 계측 로그 jsonl).
> 결과물: LegacyDb 프로젝트 `fable-village` ("Fable 마을") — 흙길 십자로 + 집 3채 + 연못 정원 + NPC 2명(마리/토무, 대사 포함) + 시작 위치. `evidence/fable-village-eval/fable-village.json` 아티팩트 동봉.

## 요약 판정

- **에이전트 코어는 강하다.** 3.5-flash + 스펙 게이트 + 맵 렌더 이미지 피드백 조합으로 "흙길 십자로+집 3채" 같은 요청을 **턴당 33~54초, 프로포절 1개**로 정확히 이행. NPC 대사 품질도 상용급.
- **그러나 "에디터를 신뢰하고 오래 쓸 수 있는가"에는 아직 아니오.** 맵 삭제 하나로 프로젝트가 로드 불가(벽돌)가 되고, 세션 작업물이 소리 없이 사라지는 함정이 여러 개다. 이번 평가에서 완성된 마을을 **4번 잃고 5번째에 영속화**했다.

## 결함 목록 (심각도순)

### 치명
1. **맵 삭제가 참조 무결성을 안 지켜 프로젝트를 벽돌로 만든다.**
   맵 트리에서 시작 맵/mapTree 루트가 참조하는 맵까지 삭제 가능. 그 상태가 저장되면 재부팅 시 shape 검증(`mapTree: mapId(...)가 존재하지 않는 맵`)에서 로드 자체가 실패 → **에디터가 안 뜬다**. (P2~P3 재현, 로컬 사본 벽돌화 실증. 마지막 1~2개 맵에서만 삭제 버튼 disabled 보호 존재 — 참조 검사는 없음.)
2. **벽돌 상태의 에러 표면이 오진 + 복구 경로 부재.**
   위 상황에서 "DB 연결이 필요합니다" 화면이 뜬다(실제로는 데이터 무결성 문제). 더 나쁜 것: DB 연결 설정의 "연결 시도"는 로드를 우선하므로 **깨진 프로젝트에는 접속 자체가 실패**해 에디터 내 복구 수단이 없다. (P6 실증: `DB 연결 실패: mapTree: ...`) "저장만" 버튼이 있으나 벽돌 화면에서는 도달 불가.

### 높음
3. **"마을 생성" 스킬 파이프라인이 사실상 죽어 있다.** 상위 모델(3.5-flash)로도 **2회 연속 7분+ 소요, 산출 0** (P5·P6). 동일 내용을 일반 채팅으로 보내면 33~54초에 완수 — 스킬 폼 경로 자체의 결함. (flash-lite 시절 "모델 탓"으로 보였던 것이 모델 업그레이드 후에도 재현 → 파이프라인 문제로 판정 변경.)
4. **스킬 종료 시 풀스크린 테스트 플레이 모달이 자동으로 열려 AI 패널까지 전부 가린다.** 그 뒤에서 후속 턴/프로포절이 계속 처리되므로 사용자는 진행을 전혀 볼 수 없다 (P5에서 3턴이 모달 뒤에서 진행됨).
5. **0건 프로포절이 세션을 "검토 대기"로 블로킹한다.** 모델이 밑그림(set_build_spec)만 승인받고 실제 빌드를 안 하면 "변경 제안 (0건)" 카드가 뜨는데, [확인]을 수동으로 눌러야 다음 진행이 가능. 카드의 [확인] 버튼이 `ai-proposal-reject` testid를 재사용하는 것도 정리 필요. (P8 실증 — 이때 C.2-8 완성도 린트가 "⚠ 미이행: road_horiz/road_vert/house_a 외 2개 영역 미변경"을 정확히 표시한 것은 **신기능의 실전 첫 검증 성공**.)
6. **LLM 네트워크 오류 시 재시도 UX가 없다.** LLM 일시 오류 2건으로 T4가 조용히 죽고 상태 배지만 "오류"로 남음 (P6). 재시도 버튼/자동 백오프 필요.

### 중간
7. **맵 삭제에 확인 다이얼로그가 없다** — 원클릭 파괴 (undo 존재하나, 결함 1과 결합하면 치명 콤보).
8. **미저장 변경이 있는 채로 창을 닫아도 경고가 없다** — P1에서 삭제 12건이 통째로 증발 (반대로 이번엔 벽돌을 막아줬지만, 일반 사용자의 작업 유실 경로).
9. **AI busy 중 입력이 차단되지 않아 메시지가 쌓인다** — 처리 중 후속 메시지가 UI에 스택되고 순서/상태 표시가 없음 (P4에서 4턴이 20초에 적체).
10. **dev/평가용 URL 모드(blankProject 등)에서 저장이 조용히 스킵된다** — 상태바는 "저장 대기 없음"으로만 표시. 이 평가에서 완성 마을을 4회 유실한 직접 원인. 최소 "이 모드는 저장되지 않습니다" 배너 필요.
11. **프로젝트 내보내기가 다운로드를 만들지 않음** (P6에서 메뉴 클릭 → 무반응. 원인 미추적 — 재확인 필요).
12. **DB 연결 설정 진입점이 비일관** — 어떤 세션에선 열리고(P6) 어떤 세션에선 진입 버튼을 찾을 수 없음(P7/P9). 상태바 "가져오기"(맵 잠금 해제)와 혼동 유발.

### 관측성 (사용자 지적 반영)
13. **진단 가능한 세션 로그가 부족하다.** "검토 대기" 멈춤의 원인을 밖에서 알 수 없었다. AI 패널의 "로그" 버튼이 있으나, 상태 전이·툴 호출 타임라인·네트워크 오류를 묶은 **export 가능한 구조화 로그**가 필요 (합의 조항 10 관측성 텔레메트리와 연결). 이번에 드라이버 측 계측(jsonl 초당 틱)으로 우회했지만 제품이 자체 제공해야 한다.
