# 편집기 다국어 (i18n) — 한국어 · English · 日本語 · 简体中文

2026-09-27 도입. 편집기 화면(톱바·메뉴·패널·모달·부트 로더)을 네 언어로 보여 준다.
**한국어가 원문(정본)** 이고 나머지 셋은 번역 카탈로그다. 게임(런타임) 화면은 번역하지 않는다 —
저자가 출하하는 게임의 글자이기 때문이다.

## 언어가 정해지는 순서

`src/i18n/locale.ts` 의 `resolveLocale` 이 정본이다. `index.html` 의 부트 로더 인라인 스크립트가 같은 규칙을 복제한다.

1. URL `?lang=en|ja|zh|ko` — QA·공유 링크용. 저장하지 않는다.
2. 사용자가 「보기 ▾ → 언어」에서 고른 값 — localStorage `oprn:locale`.
3. 자동화 브라우저(`navigator.webdriver`)면 **한국어**. Playwright 기본 로캘이 en-US 라서, 이 가드가 없으면
   한국어 라벨을 누르는 e2e 스펙이 전부 깨진다. `?localeDetect=1` 로 가드를 끈다.
4. `navigator.languages` 에서 처음 지원하는 언어. `zh-TW`·`zh-Hant` 도 간체 카탈로그로 간다.
5. 그 밖의 언어는 영어.

`<html lang>` 은 `ko` / `en` / `ja` / `zh-CN`, `<html data-locale>` 은 `ko|en|ja|zh`.

## 구조

| 파일 | 역할 |
|---|---|
| `src/i18n/locale.ts` | 언어 결정·저장. 순수 함수 `resolveLocale` |
| `src/i18n/translator.ts` | 한국어 원문 → 번역. 정확 일치 + `{0}` 템플릿 일치(고정부가 긴 템플릿이 이긴다) |
| `src/i18n/domTranslator.ts` | MutationObserver 로 텍스트 노드와 `title`·`aria-label`·`placeholder`·`alt` 를 번역 |
| `src/i18n/index.ts` | `initI18n()`(부팅), `setLocale()`(메뉴), `t()`(코드에서 직접 번역) |
| `src/i18n/catalogs/{en,ja,zh}.json` | 카탈로그. 키 = 공백을 한 칸으로 접은 한국어 원문 |
| `scripts/i18n/extract-ui-strings.mjs` | 소스에서 원문 목록 추출, 언어별 누락 수 |

부팅: `src/main.ts` 의 `bootEditorWithOpenedProject` 가 `bootApp` 보다 먼저 `await initI18n()` 한다.
한국어면 카탈로그를 받지 않고 옵서버도 설치하지 않는다(한국어 사용자 비용 0).

## 왜 DOM 계층 번역인가

한국어 UI 문자열이 1,100여 파일에 약 1만 4천 개 인라인으로 있다. 호출부를 `t()` 로 감싸는 전환은 한 번에 끝낼 수
없고 그동안 새 코드가 계속 한국어를 넣는다. 그래서 원문 소스는 그대로 두고 **렌더된 DOM** 을 바꾼다.
카탈로그에 없는 글자(사용자 저작 콘텐츠·AI 답변·맵 이름)는 절대 바뀌지 않는다 — 조회가 실패하면 원문 그대로다.

번역하지 않는 영역: `.player-layout`(게임 화면), `textarea`, `contenteditable`, `code`/`pre`,
`[translate="no"]`, `.notranslate`, `[data-i18n-skip]`. 사용자 글이 들어가는 새 표면은 이 중 하나를 붙인다.

## 코드가 화면 글자를 다시 읽을 때 (지켜야 할 계약)

번역 뒤에는 `element.textContent` 가 영어·일본어다. **화면 글자를 한국어 리터럴과 비교하지 마라.**
- 비교가 필요하면 `sourceTextOf(node)` / `sourceAttributeOf(el, name)` (`@/i18n`) 로 원문을 읽는다.
- 더 좋은 방법은 상태를 `data-*` 속성이나 변수에 두고 그것을 비교하는 것이다.
- 2026-09-27 감사에서 고친 곳: `aiChatPanel`(상태 톤·스튜디오 대기·활동 줄·입력 안내),
  `aiRegionTaskRunner`(오류 판정), `databaseFieldHud`, `transferPlayerDialog`·`mapPointDialog`(확대 단추),
  `tilesetChipsetPreview`(통행 aria-label), `databaseAiBar`, `projectInterviewDialog`, `teamReadOnlyUi`(검색칸 판정).

## 새 문구를 추가하면

1. 코드는 평소처럼 한국어로 쓴다.
2. `node scripts/i18n/extract-ui-strings.mjs` 로 누락 수를 보고, `--missing en` 으로 목록을 뽑아 세 카탈로그에 넣는다.
   누락은 오류가 아니다 — 그 문구만 한국어로 보인다.
3. 번역은 `docs/terminology/product-terminology.md` 의 영어 정본을 따른다(예: 바닥 = ground layer, 테스트 실행 = test play).
4. 자리표시자 `{0}` `{1}` 는 원문과 같은 집합이어야 한다(`test/i18n.test.ts` 가 막는다).

추출 대상은 `src/editor`(content·tools 제외), `src/app`, `src/project/eventCommands`. 저작 콘텐츠와 AI 도구 본문은 데이터라 제외한다.

## 알려진 한계

- 카탈로그는 기계 번역 초안이다(용어집 적용). 사람 검수 전까지 어색한 표현이 있을 수 있다.
- 런타임에 조립되는 문장 중 추출기가 못 보는 모양(여러 함수에 걸친 조립)은 한국어로 남는다.
- `window.confirm` 같은 네이티브 대화상자는 DOM 이 아니라 번역되지 않는다 — 필요하면 `t()` 로 감싼다.
- AI 조수의 답변 언어는 모델 설정을 따른다. 이 계층은 편집기 크롬만 번역한다.
