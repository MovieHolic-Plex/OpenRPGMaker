## 95% 이상 유사도 요청에 따른 계곡 개정

초기 44×36 절차적 계곡은 참고 이미지와 구도가 달랐다. 사용자 요청에 따라 원본의 타일
격자·화면 잘림을 역산하고 **25×20, 16px 타일**로 복원했다. 다리는 6×2칸이며, 대각선 절벽,
폭포 두 줄, 물가, 나무·입석·꽃·흙길의 실제 배치를 맞췄다. 다른 두 필드의 지형은 보존한다.

- `scripts/lib/emeraldFieldReference.json`: 참조에서 식별한 하위·상위 타일, 19개 8×8 조립 레시피,
  고정 뷰포트 변환과 입력 SHA256. 원본 스크린샷 픽셀을 게임 리소스에 넣지 않는다.
- `scripts/refine-emerald-reference.mts`: World 원본 타일 및 쿼터만 복사해서 전용 팔레트를 만들고
  맵을 수정한다. 타일 선택과 쿼터 조립은 편집 가능한 저작 데이터다.
- 전용 타일셋 `tileset_twinfalls_reference_20260914`와 업로드 리소스
  `asset_twinfalls_native_quarters_20260914`는 **Supabase 프로젝트 데이터에 포함**한다.
  480개 원본 칩, 19개 경계 조합, 가로 재배열한 폭포 애니메이션을 사용한다.
- 전용 custom 팔레트는 원본 RM 지형 자동 재해석을 적용하지 않는다. 일반 칩을 선택해
  계속 편집할 수 있다. 물가의 쿼터 방향을 현재 맵 이웃에 맞춰 재계산하면 참조 그림이 바뀐다.
- 계곡 서쪽 출구 `(1,19)` → 숲길 `(41,27)`, 동쪽 `(24,15)` → 유적 `(2,27)`.
  숲길에서 계곡으로는 `(2,18)`, 유적에서 계곡으로는 `(23,15)`에 도착한다.
  이웃 맵의 수정 범위는 계곡을 향한 기존 이동 명령의 목적지 좌표뿐이다.
- 참고 이미지에는 안내판이 없으므로 계곡의 이전 안내판을 제거했다. 이웃 필드의 안내판은 보존한다.

## 저장·재현 보호

`refine-emerald-reference.mts`는 실행 시작 시 원격 DB를 로드한다. 마지막 로컬 재로드
영수증과 해당 필드·전용 팔레트·이미지가 일치해야 수정하며, 이후 사용자 변경은 덮어쓰지 않는다.
기본 실행은 미리보기까지, `--apply`는 canonical 저장 및 전체 정규화 재로드 비교까지 수행한다.
업로드 이미지 SHA256도 재로드본에서 별도로 검증한다.

초기 제작기 `scripts/author-emerald-fields.mts`는 이제 충실 복원 팔레트가 존재하면
실행을 거부한다. 과거 절차적 맵으로 회귀시키지 않도록 최신 개정기를 사용한다.

저작 시점의 main `e9583a5d2`는 원격 프로젝트의 `placement.wallOverlap`를 읽지 못했다.
호환되는 `codex/compact-house-furnishing` (`858f254e5`) 코드를 읽기 전용으로 사용했다.
구버전에 맞추려고 원격 필드를 삭제하지 않았다. 호환 변경 통합 전에는 다음 두 옵션이 필요하다.

```bash
RPG_ZZU_SOURCE_ROOT=<호환 소스 경로> bun --tsconfig-override <호환 소스 경로>/tsconfig.json scripts/refine-emerald-reference.mts --apply
```

## 실제 플레이어에서 발견한 업로드 팔레트 결함

`tex_tiles_default`로 해석하고 preload에서도 생략했다. 따라서 원격 재로드·맵 ID·이동 검사가

누락 이미지의 기본 칩셋 오표시 방지를 확인한다.

QA는 호환 스키마 커밋 `858f254e5`의 별도 `/tmp/rpg-zzu-fields-runtime-qa` 체크아웃에

9809 에디터도 이 검증 체크아웃을 사용한다. 원본 워크트리에는 엔진 수정 diff를 남긴다.

### 계단 높이와 맵 경계 길 수정

- 계단 생성기가 `y+h-1`부터 `y+h+face`까지 칠하여 절벽보다 두 행 길었다. 실제 절벽 면 `[y+h, y+h+face)`에만 계단 374를 놓는다. 위·아래 한 행은 통행 가능한 흙길 진입부다.
- 네 계단은 절벽 높이와 동일하게 3/3/2/2행. 양쪽 계단 열 모두 정확한 타일 수, 진입부 비계단 여부, 진입부 도달을 검사한다.
- 서쪽 `(0,55..56)`, 동쪽 `(79,49..50)`, 남쪽 `(22..23,63)`에 두 칸 폭의 길을 연결했다. 다음 맵은 해당 반대편 경계에서 같은 좌표/폭으로 이어 저작한다. 아직 대상 맵을 새로 만들거나 전환 이벤트를 지정한 것은 아니다.
- 쿼터 합성 때 출입구 바깥에만 가상 흙길 이웃을 주어 막다른 길의 둥근 마감을 방지한다. 다른 외곽은 기존 undefined 이웃 의미를 유지한다. `exit-seam-proof.json`은 출입구 여섯 칸의 바깥쪽 중앙 픽셀이 실제 흙길 색인지 확인한다.
- QA 경로는 343칸, 네 계단의 아래/위 진입부와 세 경계를 포함한다. 최신 시각 목록은 계단 아래 세 장과 동/남 경계 두 장이다. 최신 수치는 `checks.json` / `supabase-proof.json`을 따른다.

### 대각 절벽 적극 활용

- 북쪽 쌍폭포 장면의 좌우 연장 능선을 연속 45도 대각선으로 저작했다. 두 열마다 높이를 바꾸면서 매번 사선 캡을 놓으면 톱니 모양이 되므로 연속 사선 구간은 열마다 한 행씩 이동한다.
- 서쪽·남서쪽 고지대와 동쪽 두 단 고지대의 앞면 네 곳을 최대 다섯 칸의 사선으로 깎았다. 계단 주변에는 수평 절벽 면을 남긴다.
- 상단 캡 18/19, 절벽 몸통 231/232, 하단 캡 48/49를 방향에 맞게 사용한다. 삼각형 캡 둘을 포함한 사선 조립은 `face+1`개의 타일 행을 차지하되 실제 수직 두께는 평평한 `face`행과 같다. 계단은 기존 3/3/2/2행 그대로다.
- 최종 대각선 캡 111개, 활엽수 67그루, 키 큰 나무 118그루, 관목 200개, 꽃 장식 57개, 경계 쿼터 82개. 주요 12지점이 포함된 2,923칸에 도달 가능하다.
- 저장 후 전체 정규화 재로드를 검증한다. 현재 QA 경로는 서쪽 사선 절벽 관찰 지점을 추가한 383칸/18비트이며 계단 네 곳과 경계 출구 세 곳을 포함한다. 최신 근거는 동일 `emerald-wide-v2` 증거 디렉터리와 런타임 요약을 따른다.

### 16분할 검토 후 절벽 형태 재수정

앞선 대각 절벽 개정은 시각 품질 판정이 잘못됐다. `inspection-16/REVIEW.md`에 남긴 16구역 검토에서 긴 평행 바위 띠, 북동 능선의 잘린 끝, 직각 윗면 테두리와 별도로 생성한 사선 앞벽, 반복되는 고지대 형태를 확인했다. 이전 절의 대각 타일 개수/통행 성공을 시각 합격 근거로 사용하지 않는다.

- `scarp`의 상단 높이와 벽 깊이로 상단·밑단 윤곽을 함께 저작한다. 상단과 밑단의 기울기는 각각 계산한다. 깊이가 변하는 끝부분에서 상단 기울기를 밑단에 그대로 쓰면 틈이나 돌출이 생긴다.
- World 18의 대각선 시작은 타일 좌상단이고 139의 수평 경계는 타일 아래쪽이다. 내려가는 사선 18은 기준 수평 립보다 한 행 아래에 놓아야 한다. 48의 밑단에도 해당 방향 보정을 적용한다.
- 작은 고지대의 별도 78–140 직각 테두리는 제거했다. 뒤쪽은 숲과 이어지고 앞쪽은 굴곡진 절벽이다. 서쪽·남서쪽은 서쪽 경계로, 동쪽 두 단은 동쪽 경계로 이어진다. 내부의 자유 끝은 한 행 높이까지 줄인다. 자유 끝 상단에 138/140을 놓으면 불필요한 수직 잔디 테두리가 솟으므로 139를 쓴다.
- 북서 두 절벽은 서로 다른 굴곡과 간격으로 원본 쌍폭포에 연결한다. 북동 능선은 6행에서 4행으로 좁아진 뒤 북쪽 맵 경계 밖으로 이어져 잔디 한가운데서 잘리지 않는다.
- 일곱 절벽의 상단/밑단이 열마다 최대 한 행씩 변하는지, 서로 겹치지 않는지, 상하 캡이 같은 셀에 겹치지 않는지 검사한다. `cliff-contours.json`에 윤곽을 남긴다. 계단 네 곳은 3/3/2/2행과 위아래 진입부를 보존한다.
- 남서쪽 기존 길은 새 절벽에 막히므로 절벽 아래를 돌아 계단으로 이어지는 길로 고쳤다. 서/동/남 경계의 두 칸 폭 출구 위치는 동일하다.
- `node scripts/qa/emerald-wide-v2-inspect.mjs`는 실제 에디터 렌더를 4×4 분할하고 최근접 2배 확대한다. `inspection-16-fixed/manifest.json`의 원본 이미지 해시로 검토 대상을 식별한다. 16구역을 모두 열어 검토한 뒤 저장본에서 같은 이미지가 나오는지 확인한다.
- 보행 QA의 서쪽 관찰점은 새 벽면 아래 `(2,38)`이다. `prepare-emerald-wide-v2.mts --preview`로 저장 전 경로 계산이 가능하며, 최종 QA는 기본 인자로 원격 재로드 영수증을 사용한다. 최신 수치와 실제 플레이 판정은 `VALIDATION.md`, `checks.json`, 런타임 `SUMMARY.md`를 따른다.

### 두 번째 16분할 재검토 — 길 연결과 주변 구성

- 저장본을 새로 촬영한 `review-round2-before/`의 16개 PNG를 모두 열어 다시 분석했다. 구역별 문제는 `ANALYSIS.md`. 앞선 검토는 좁은 길과 계단 진입부의 시각 단절을 놓쳤다.
- 한 칸 폭 길은 대각 Bresenham 셀끼리만 닿았고 quarter compositor는 상하좌우 이웃을 사용했다. `road`는 대각 이동마다 통행 가능한 중간 직교 셀을 함께 칠한다. 잔디를 통한 보행 성공은 길의 시각 연결을 입증하지 않는다.
- 분리된 흙 한 칸이 없는지, 길/계단/다리의 각 연결 성분이 서쪽 출구 또는 원본 모듈에 이어지는지 검사한다. 좌우 맵 경계의 행 넘김 이웃은 금지한다. 증거는 `road-graph.json`이다.
- 동쪽 두 계단의 길은 실제 계단 열 x73/x70을 따라 연결한다. 남서 계단의 아래 진입부 x14–15를 하단 길까지 연장한다. 서쪽 강변 지선은 물가에서 끝내지 않고 본길에 합류시키며 남동쪽의 막다른 길은 좁은 숲 순환 지선으로 연결한다.
- 섬 세 곳은 행별 비대칭 윤곽으로 저작한다. 북동 섬은 본토와 붙지 않도록 물 간격을 남긴다. 맵 경계의 물에는 바깥 물 이웃을 제공해 가짜 잔디 마감을 없앤다. 경계 길의 흙 이웃 정책은 유지한다.
- 서쪽/동쪽 절벽의 불필요한 한 행 M자 돌출 제거, 북동 사선에 수평 구간 추가. 단차 높이/비중복/캡 위치 검사는 유지한다.
- 키 큰 나무의 자동 양옆 배치 빈도와 작은 어두운 풀 조각을 줄였다. 북서 상단과 북동 반도에 수목군 보완. 전망 길 끝은 바위/꽃으로, 다리 둑은 통행을 막지 않는 바위로 정리한다.
- 분할 도구는 출력 폴더를 인자로 받는다: `node scripts/qa/emerald-wide-v2-inspect.mjs review-round2-after`. 이전 사진은 덮어쓰지 않는다. 최종 저장본 렌더의 해시를 검토 원본과 비교한다.
- 실제 플레이 QA는 북쪽 좁은 길, 서쪽/동쪽 전망 지점, 남동 숲길 세 지점을 추가했다. 최종 수치와 판정은 `VALIDATION.md`와 런타임 요약을 따른다.

- 재검토 중 길 셀이 붙어 있어도 계단/다리를 길 이웃으로 인식하지 않아 가는 잔디 틈이 남는 문제를 추가로 확인했다. 흙길 합성 전용 `roadPadded`에서 계단/동굴 입구/다리 데크를 흙길 이웃으로 본다. 물은 원래 강바닥 이웃을 유지하여 다리 아래에 가짜 풀 해안이 생기지 않게 한다.
- `node scripts/qa/emerald-wide-v2-seams.mjs [--preview]`는 실제 팔레트 픽셀로 계단 상하 진입부 16곳, 새 다리 양쪽 진입부 12곳, 경계 길 6곳, 열린 물 경계 3곳을 검사한다. 경계 중앙에서 흙/물 색을 확인하는 37개 표본이며, 전체 형태의 시각 판정은 16분할 검토로 따로 수행한다.
