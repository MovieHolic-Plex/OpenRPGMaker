# murim-chipset — 무림(중국 무협) 칩셋 후보 하네스

중국 무협 배경 공용 칩셋 **`murim_wuxia`**(계열 `oprn-murim`, 16px 칸, 3/4 시점)에 넣을 조각의 후보를 만들고 **사람이 고르게** 한다.
그림은 생성 이미지가 아니라 **행 문자열 격자로 화소를 직접 찍은 코드 손 도트**다(`joseon_baram` 과 같은 방식, `assistant-skills/pixel-dot-authoring`).
화풍은 하나로 고정하지 않는다 — **컨셉 줄(line)** 마다 따로 그리고 따로 고른다(아래 「줄」).
타일셋은 아직 계획 단계다 — 이 하네스는 고른 그림을 `harness-data/murim-chipset/picked/` 까지만 남기고 **번들(`src/assets/bundled.ts` 등)에 굽지 않는다.**

## 줄 (line) — 컨셉 계열

사용자 결정(2026-10-08): style-r1 을 보고 「무림은 A 묶음이 낫군」 → 「A 랑 B 서로 컨셉 다르게 해서… 마을 A, 마을 B. 버리긴 아깝군」.
그래서 화풍 하나를 고르는 대신 **A 와 B 를 서로 다른 컨셉 줄로 둘 다 남긴다.** A 가 주 줄이다.

| 줄 | 이름 | 컨셉 | 화풍 기준 |
|---|---|---|---|
| A (주) | 밝은 문파 | 산중 명문 정파 본산 — 밝은 소나무 가로 마루·큰 네모 판석·흰 회벽+주칠 둥근 기둥·정통 청회색 수키와·밝은 소나무 목인장·짙은 나무 원탁+북 걸상 | style-r1 의 A 조각 |
| B | 강남 무관 | 강남 물가 마을의 오래 쓴 무관·객잔 — 붉은 칠 세로 마루·장대석·청회 기와 담머리+황토 회벽·비늘 평기와+주칠 처마판·짙은 나무 목인장·소나무 탁자 찻자리 | style-r1 의 B 조각 |

- 줄은 시드 `lines`(id → `name`·`concept`·`origin{round, letter}`·`primary`)에 있다. style-r1 의 **C 는 줄이 아니다** — 고르지도 버리지도 않은 채 둔다. 사용자가 말하면 `lines` 에 더한다(그 전에는 `pick style-r1 … C` 를 거부한다).
- **화풍 판**(시드 `rounds.<판>.keys = "letter"`, style-r1): 후보 글자 = 줄. 줄마다 하나씩 고른다.
- **이후 판**(`keys = "line"`, frame-r1 부터): **줄마다 후보를 그린다.** 후보 키는 `<줄><번호>`(A1 A2 B1 B2 …), `pick` 이 앞 글자로 줄을 안다.
  판의 `lines` 에 적힌 줄마다 항목당 후보 2개 이상(validate 가 막는다).
- **줄의 화풍 기준은 style-r1 의 그 글자 조각이다.** 같은 색·결로 그린다(style-r1 의 먹 윤곽은 따르지 않는다 — 「외곽선 규칙」). 항목의 `styleRef`(style 항목 id 목록)가 기준 조각을 가리키고,
  시트는 줄 후보 옆에 그 조각을 놓고, 관문 Y 가 주 재료 램프를 대조하고, 관문 J 의 `@style` 이 기준 조각과의 이음을 본다.
- 고르기는 **(항목, 줄)마다 하나**. 같은 항목·같은 줄을 다시 고르면 앞 기록을 대체한다. 고른 그림은 `picked/<줄>/<항목>.png`.
- `status` 는 줄별 묶음별로 센다(지금: 줄 A style 6/6, 줄 B style 6/6). `list` 는 항목마다 `★A ★B`.

## 흐름

```
rounds/<판>.py  (화풍 판: 후보 A·B·C = 줄 / 이후 판: 줄마다 A1 A2 B1 B2 … — 색만 바꾼 것이 아니라 구조가 다른 안)
   │ draw   → qa-runs/harnesses/murim-chipset/<판>/<항목>/<글자>.png, -x8.png, manifest.json(그림 해시)   (gitignore)
   │ gate   → 기계 관문 P Z Q F S R J Y G K (FAIL) · T L N OUTLINE CONTRAST (WARN) → gate.json, ledger.json 에 실행 기록(줄별 FAIL·WARN, 외곽선 경고 목록)
   │ sheet  → ~/claude-viz/murim-<판>.html  (FAIL 이 있으면 안 쓴다)
   ▼
사람이 시트를 보고 줄마다 고른다 ──► pick <판> <항목> <후보>   (시트 때 해시 = 지금 그림 해시일 때만 기록, (항목, 줄)마다 하나)
                                 └► reject <판> <항목> <후보> --why "…"
```

- **감독·에이전트는 고르지 않는다.** `pick` 은 사람이 고른 글자를 받아 적을 때만 부른다. 「관문을 다 통과했으니 A」 같은 대리 선택 금지.
- **관문 통과는 합격이 아니다.** 관문은 깨진 그림(팔레트 밖 색·크기·투명 계약·윗면 띠 없음·반복 이음·색만 바꾼 후보)만 거른다.
  3/4 시점이 맞는지(윗면이 보이고 옆면이 없는지), 화풍, 조선 옆 어울림은 사람이 본다
  (교훈: 실내 3/4 관문 ok 를 근거로 구운 그림 44종이 명백한 위반이었다 — 메모리 `view34-gate-is-not-evidence`).
- 그림이 바뀌면 그 그림의 고른 기록은 **무효**다(`status`·`list` 가 `VOID` 로 보인다). 다시 시트를 만들어 다시 보여 줘야 한다.

## 명령 (`npm run harness -- murim-chipset …` 또는 `python3 src/harnesses/murim-chipset/harness.py …`)

| 명령 | 뜻 |
|---|---|
| `validate` | 시드(항목 id·묶음·종류·층·크기·반복 축·brief/criteria·조선 기준 조각 파일)·판 모듈·금지 조항·팔레트 호환 점검 |
| `palette` | 램프 단별 밝기를 joseon_baram 범위와 대조, 가장 가까운 조선 램프와 거리. 파일을 쓰지 않는다 |
| `list [--wave W]` | 항목 목록. 줄마다 ★ = 사람이 고른 것 중 지금 그림과 해시가 맞는 것 |
| `draw <판>` | 후보를 그려 PNG·manifest 를 쓴다 |
| `gate <판>` | draw + 관문. 줄별 FAIL·WARN 을 센다. FAIL 이 있으면 종료코드 1 |
| `sheet <판> [--force]` | draw + gate + 시트. `--force` 는 실패를 사람에게 보여 줄 때만 |
| `pick <판> <항목> <후보> [--note]` | 사람이 고른 후보 기록 + `picked/<줄>/<항목>.png` 복사. 같은 (항목, 줄)의 이전 pick 은 대체. 화풍 판은 후보 글자 = 줄(줄 아닌 글자는 거부), 이후 판은 `<줄><번호>` |
| `reject <판> <항목> <후보> --why …` | 사람이 버린 후보와 이유(다음 판의 「하지 말 것」) |
| `status` | 판별 그림·관문·시트 유무, **줄별** 묶음별 고른 것과 해시 일치 여부, 판별 외곽선 경고 수(OUTLINE·CONTRAST)와 **굽기 전에 다듬을 목록**(고른 것 중 경고) |

시트 주소는 `http://mdc-server:18301/murim-<판>.html`(정적 서버 `claude-viz.service`).

## 팔레트 (잠금)

램프 9개 × 7단(0 = 가장 어두움) + `ink`(`#0c0e16` — 사람 비교·그림자용, **조각에 쓰지 않는다**, 아래 「외곽선 규칙」) + 그림자 한 가지(ink, alpha 88) + 공유 램프 `cao`.

| 램프 | 쓰임 |
|---|---|
| `wa` | 청회색 유약 기와 |
| `zhu` | 주칠(朱漆) 기둥·난간 — 조선 `red`(진홍)보다 주황 쪽 |
| `huang` | 황토·오커 회벽 |
| `bai` | 흰 회벽·창호지(크림색, 조선 plaster 의 분홍기보다 노랑 쪽) |
| `mu` | 짙은 나무(가구·보·판벽) |
| `song` | 밝은 소나무(마루·목인장) |
| `shi` | 회색 청석(마당·기단) |
| `zhuz` | 대나무 녹색 |
| `jin` | 금박·등롱 금색 |
| `cao` | 풀밭 — **joseon_baram `leaf` 램프 그대로**(같은 게임에서 땅이 이어지게, 장면용) |

- **조선 호환 규칙:** 램프 단마다 밝기가 joseon_baram 7단 램프들의 같은 단 밝기 범위(±0.04) 안에 있어야 한다(`palette`·`validate` 가 검사).
  색상은 조선 램프와 다르게 골랐다(`palette` 가 가장 가까운 조선 램프와 거리를 보여 준다. 거리 기준은 아직 강제하지 않는다).
- 색을 코드에 직접 쓰지 않는다. 후보 코드는 범례 `{'글자': ('램프', 단)}` 만 쓴다. 관문 P 가 잠금 밖 색 한 화소도 막는다.
- **다시 잠그면 모든 후보 해시가 바뀌어 pick 이 전부 무효가 된다.** 팔레트를 바꾸면 판을 다시 보여 줘야 한다.

## 관문 (gate.py) — 깨짐만 거른다

| 코드 | 수준 | 보는 것 |
|---|---|---|
| P | FAIL | 불투명 화소가 잠긴 색 안 · 반투명은 그림자(ink, alpha 88)뿐 |
| Z | FAIL | 크기 = 칸 × 16px |
| Q | FAIL | tile·wall 전부 불투명 / roof 윗줄 불투명·90%(조각의 `qMin`·`qTopRow` 로 추녀·용마루 끝만 완화) / object 위 귀퉁이 투명·채움 15~95% |
| F | FAIL | wall·roof·object: 후보가 선언한 윗면 행(`meta['top']`)이 2행 이상·폭 50% 이상이고 바로 아래 앞 모서리 줄보다 밝다(object 는 실루엣 위쪽 절반에서 시작). **띠가 있는지만 본다 — 시점 판정이 아니다** |
| S | FAIL | 반복 축마다 감은 이음(끝 열→첫 열)의 밝기 차 ≤ 안쪽 열 경계 최대 + 0.02(줄눈·귀틀처럼 일부러 그은 선은 허용) |
| R | FAIL | 같은 항목의 두 후보가 실루엣 같고(IoU > 0.97) 밝기 배치 상관 > 0.92 = 색만 바꾼 안 (줄을 가리지 않고 모든 후보 쌍) |
| J | FAIL | 세트 항목: 시드 `joins`(+`joinsAll` 의 모든 순서쌍 × x·y)로 이웃하는 두 조각의 맞닿는 열(줄) 밝기 차 ≤ 두 조각 안쪽 경계 최대 + 0.02. `@style` = 그 줄 style 조각(이어 붙일 수 있어야 한다) |
| Y | FAIL | 이후 판(`keys=line`): 후보 불투명 화소 8% 이상인 램프가 그 줄 style 조각(`styleRef`)에 1% 이상 쓰인 램프 ∪ `extraRamps` ∪ ink 안. 다른 줄 재료로 그린 후보를 거른다 — **화풍 판정 아님** |
| G | FAIL | 시드 `footOnEdge`(항목·조각): 불투명 화소 맨 아래 행 = 칸 아래 경계(마지막 행). 걸상·탁자·계산대·아궁이·술독·세우는 등롱이 뜨지 않는다 |
| K | FAIL | 시드 `layout`(배치 견본, 지금은 `set_table_four`): ① 후보 그림 = 같은 번호 탁자·걸상을 layout 대로 합성한 것(화소 일치) ② 좌·우 걸상 앉는 면 가운데 = 탁자 윗면 가운데 ±2px ③ 뒤 걸상 앉는 면이 탁자에 가리고도 50% 이상 보임 ④ 탁자 받침(맨 아래 화소) 아래 바닥 틈 2~4px 뒤에 앞 걸상 앉는 면, 앞 걸상은 탁자와 한 화소도 안 겹침(받침 기둥에 꽂혀 보이지 않게), 발은 견본 안 ⑤ 좌·우 걸상이 탁자 다리(띠 아래 화소)와 안 겹침. 탁자 meta `ellipse`·`band`·`foot`, 걸상 meta `seat` 를 읽고, 그 첫 행이 실제 맨 위 화소인지도 본다. **기계 검사는 눈 판정을 대신하지 않는다** |
| T | WARN | object 폭 1px 화소 비율 > 0.14 |
| L | WARN | object 오른쪽 반이 왼쪽 반보다 밝음(빛은 왼쪽 위) |
| N | WARN | 네 이웃이 같은 색인데 혼자 다른 1px 잡티 > 3% |
| OUTLINE | WARN | 외곽선 규칙. 가장자리 화소 중 먹(ink 또는 밝기 ≤ 0.09) > 15%, 또는 object 빛 쪽(위·왼) 가장자리 중 먹·재질 0~1단 > 50%(시드 `outlineClass: "structure"` — 계단·난간 같은 큰 구조 — 는 먹만 본다). object = 실루엣 바깥 1px, 지형(tile·wall·roof) = 반복 축·`joins` 변을 뺀 바깥 테두리 띠 2px |
| CONTRAST | WARN | 크기 ≤2칸 object(세트면 조각마다)의 그늘 쪽(아래·오른) 실루엣 가장자리 평균 밝기 vs 줄 대표 바닥(`outlineRule.contrastGround`) 평균 밝기 차 < 0.15 = 바닥에 묻힘 |

옛 **O**(object 가장자리 75% 이상 먹·0~1단, FAIL)는 외곽선 규칙과 정반대라 2026-10-08 에 지웠다. 그 자리를 OUTLINE(WARN)이 받는다.

실측(style-r1 첫 관문): R 이 둥근 탁자 A·C(재질만 다르고 배치가 같았음)를 잡았다 → C 를 기둥 없는 돌 북 탁자 + 귀퉁이 걸상으로 다시 그렸다.
S 의 첫 판(감은 이음 / 안쪽 평균 × 1.8)은 귀틀·줄눈이 타일 경계에 걸린 정상 타일을 떨어뜨려서 「안쪽 최대 + 0.02」로 바꿨다.

## 시트 (`~/claude-viz/murim-<판>.html`, 자체완결)

- 항목마다: brief·criteria → **조선 같은 용도 조각**(1×·4×, 시드 `joseonRef`) → **Actor1 정면 가운데 프레임**(1×·4×, 사람 크기) → 후보 A·B·C(1×·4×, 반복 타일은 3×3 / 벽·지붕은 3×1 이어 붙임 2×, 관문 배지, 고르기·버리기 명령 복사 버튼, 해시 앞 16자).
- 맨 아래: 조선 객잔 지도 같은 크기 자락(기준) + **후보 글자별 6×5 칸 장면 두 장**(바깥 = 지붕·벽·돌바닥·목인장 / 안 = 벽·마루·탁자, 사람은 Actor1). 항목마다 다른 글자를 골라도 된다.

## 그리는 법 (후보 코드)

- 한 글자 = 한 화소. `grid(rows, legend)` 는 행 길이가 다르면 바로 오류를 낸다(손으로 찍다 틀린 자리). `.` 투명, `~` 그림자.
- 반복 무늬 주기(`_rep`)·감기 덧칠(`stamp(..., wrap=True)`)·돌 이음 모서리 밝힘(`_course`, `_paving`)은 내가 고른 좌표를 찍는 보조다.
  원·다각형 마스크로 본체를 만들거나 노이즈로 표면을 채우지 않는다.
- 3/4 시점: 수평 면(보·담머리 윗면, 지붕 사면, 통나무 끝, 상판, 받침판)은 위에서 보이는 면으로 2px 이상, 그 아래 어두운 모서리 줄(재질 어두운 단), 앞면은 전체 높이. 옆면(아이소메트릭) 금지.
- **먹 윤곽을 그리지 않는다**(「외곽선 규칙」). 범례에 `'ink'` 를 넣지 않는다. 가장자리는 그 재질의 단으로 — 빛 쪽(위·왼) 밝은 단, 그늘 쪽(아래·오른) 어두운 단(1단 이상).
- 후보끼리는 구조를 다르게: 판재 방향·폭, 돌 모양, 벽 구성(회벽·판벽·창살), 기와 구성(수키와 골·비늘 평기와·용마루 포함), 받침 방식.

**감독 2차 지적(2026-10-08, inn-r1 첫 시트)과 고친 것.**
1. 첫 견본(4×2)은 앞 걸상을 두께 띠 2px 아래(16행)에 두어 받침 기둥 바로 위에 겹쳤다 — 「기둥에 꽂힌 탑」. 세트를 4×3 으로 늘리고 앞 걸상을 (24,27)로 내려
   받침판·다리 발이 다 보이고 그 앞 바닥 틈 3px 뒤에 앉는 면이 오게 했다. 관문 K 의 앞 걸상 기준도 「띠 아래 2~4px」에서 「받침 아래 바닥 틈 2~4px + 탁자와 한 화소도 안 겹침」으로 바꿨다(옛 자리 (24,16)은 네 후보 모두 틈 −8px·26~68화소 겹침으로 FAIL).
2. 장면 8×6 에서 세트가 맨 아래 줄에 붙어 앞 걸상이 잘렸다 → 장면 8×8, 세트는 칸 (0,4)·(4,4), 맨 아래 줄은 빈 바닥.
3. 줄 B 탁자 소품(흰 찻주전자·잔 = 흰 덩이 + 먹 점)이 눈·얼굴처럼 읽혔다 → B1 은 자사(짙은 흙빛) 찻주전자 하나(윤곽 mu 1단, 홀로 떨어진 점 없음, 고리 손잡이·솟은 부리),

   둥근 덩이 둘이 나란히 놓이면(찻주전자 + 잔) 다시 눈으로 읽힌다 — 탁자 위에는 덩이 하나, 또는 모양이 다른 둘을 대각선으로.

| 기본 — 지형(바닥·벽면·지붕)과 기물(탁자·걸상·문·술독·목인장…) | **먹 윤곽 없음.** 재질 자신의 명암으로 형태를 읽게 한다. 빛 받는 위·왼 가장자리 = 그 재질의 밝은 단, 그늘 아래·오른 = 그 재질의 어두운 단(1단 이상) |
| 예외 — 바닥과 밝기가 비슷한 작은 기물(1~2칸: 술독·걸상·등롱…) | 그늘 쪽(아래·오른)만 그 재질의 **가장 어두운 단** + 바닥 닿는 곳 접지 그림자(`~`)를 진하게. 그래도 먹은 쓰지 않는다 |
| 큰 구조(벽 덩어리·지붕·담·계단·난간) | 바깥 실루엣은 재질의 어두운 단, 먹이 아니다. 안쪽 이음(기와 골·판재 이음·줄눈)은 중간 단 |
| 사람 | 외곽선 있음 — Actor1 그대로(우리는 그리지 않는다) |

- **먹** = palette `ink` 또는 밝기(0.299R+0.587G+0.114B) ≤ **0.09**. 근거: ink 0.056 과 0단 mu 0.049·wa 0.061·zhuz 0.070·cao 0.074·zhu 0.079 는 먹과 구별되지 않고
  (시연 「0단은 먹과 밝기가 같아 다시 윤곽이 된다」), 그다음 어두운 mu 1단 0.099·song 0단 0.100 은 시연이 그늘 쪽에 쓴 재질 단이다. ink 색은 비교·그림자용으로만 남긴다.
- **관문은 경고(WARN)만 한다** — 이미 그린 판(style-r1·frame-r1·inn-r1)은 사람이 고르는 중이라 그림(판 코드)을 고치지 않는다. 그림을 바꾸면 해시가 바뀌어 고른 기록이 VOID 가 된다.
  경고는 「고른 것만 굽기 전에 다듬을 목록」이다 — `status` 맨 아래에 고른 것(현재 해시) 중 OUTLINE·CONTRAST 경고가 줄·항목별로 나온다. 다음 판부터는 처음부터 규칙대로 그린다.
- **OUTLINE 기준값.** 가장자리 먹 > 15%: 시연 before(먹 1px) 탁자·술독·계단 95~100%, after(빛 쪽만 한 단 밝힌 sel-out) 60~81%, 「외곽선 없음」 0%.
  빛 쪽 먹·0~1단 > 50%: before 100%, after 47~60%(계단 100%), 「외곽선 없음」 0%. 지형은 바깥 테두리 띠 2px 의 먹 비율만 본다(큰 구조는 재질 어두운 단 실루엣이 허용이라 빛 쪽 검사를 하지 않는다).
- **CONTRAST 기준값 0.15.** 시연 잔돌 B1(던전): stone 0단 윤곽 0.21 vs 흙바닥 0.38 = 차 0.17 이 바닥 반점(0.24)에 묻혔다고 했고, 같은 잔돌 「외곽선 없음」은 그늘 쪽 0.38 = 차 0.00 으로 바닥에 녹는다.
  예외 규칙대로 그늘 쪽을 재질 0단으로 내리면 0.18. 「0단까지 내려도 0.15 미만」이면 접지 그림자를 진하게 하거나 재질을 바꿔야 하는 자리다. 지시 예시 0.12 는 석순 「외곽선 없음」 0.11 을 겨우 잡아 올렸다.
  **그늘 쪽만 재는 까닭:** 규칙대로 빛 쪽을 밝게, 그늘 쪽을 어둡게 칠하면 가장자리 전체 평균은 바닥과 비슷해져 묻힘을 못 가린다. 무림 실측: 시연 술독 「외곽선 없음」 0.20·탁자 0.23 은 통과.
- 줄 대표 바닥 = 그 줄 style 조각(style-r1 의 그 글자). 시드 `outlineRule.contrastGround` 가 묶음별로 정한다(style·frame·inn = `inn_floor_wood`, dojo·outdoor = `yard_floor_stone`), 항목 `contrastGround` 로 바꾼다(벽에 거는 `menu_board` = `inn_wall_pillar`).

## 함정

- `qa-runs/` 는 gitignore 다. 고르지 않은 후보 PNG 는 커밋되지 않는다 — 판 코드(`rounds/*.py`)가 정본이고 언제든 다시 그린다.
- 시트는 관문 FAIL 이 있으면 안 써진다. 고친 뒤 다시 만든다.
- `pick` 은 manifest(시트 때 해시)와 지금 그림 해시가 다르면 거부한다 — 시트를 본 뒤 코드를 고쳤다면 시트를 다시 만들어 다시 보여 줘야 한다.
- `pick` 은 시트를 본 뒤 하네스 코드를 고쳐도 판 코드(`rounds/*.py`)를 안 건드렸다면 해시가 같아 그대로 된다. **판 코드를 고치면 그 판의 고른 기록이 VOID 가 된다** — style-r1 은 줄의 기준이므로 고치지 않는다.
- 장면의 바깥 그림은 벽 조각을 지붕 바로 아래에 붙인 것이다. 벽 후보 B(담머리 기와)는 지붕 아래에서 기와 띠가 두 번 보인다 — 바깥 담으로 쓸 때의 모습이다.
