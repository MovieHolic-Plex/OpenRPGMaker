# 버들항 건물 · 적대적 Visual QA와 사람의 허용/거절

2026-10-05 사용자는 처음 검수한 10종의 지붕·건물 질감이 원본과 다르다고 전부 반려하고, 사람 검수에 올라오기 전 적대적 Visual QA를 요구했다. 이전 후보/선택 행과 공개 그림은 삭제했다. 삭제 목록과 해시는 `harness-data/beodeul-building-review/deleted-round-1.json`에 남긴다. 반려 그림 한 장만 비공개 부정 대조군으로 보존한다. 기존 지도·원본 타일은 수정하지 않는다.

## 실행

```bash
npm run harness -- beodeul-building-review produce
# 또는 단계별 실행
npm run harness -- beodeul-building-review build
npm run harness -- beodeul-building-review validate
npm run harness -- beodeul-building-review gate
npm run harness -- beodeul-building-review publish
npm run harness -- beodeul-building-review serve --port 18317
npm run harness -- beodeul-building-review status
npm run harness -- beodeul-building-review export
```

`produce`는 build → validate → gate → publish를 직렬 실행한다. 질감에서 이미 탈락한 경우 구조 검사로 진행하지 않고 차단한다. 어느 단계든 실패하면 공개를 중단한다. `build`는 **비공개 drafts/staging**에만 쓴다. 예외를 무시하거나 판정을 손으로 작성하거나 통과 점수를 낮춰 10개를 맞추지 않는다.

검수 화면: http://mdc-server:18317/ . 서버는 검증 증거가 유효한 후보만 보낸다. 화면은 5초마다 갱신한다. 후보를 큰 카드로 모아 보는 갤러리, 검색, **검수 대기 / 허용됨 / 거절됨** 탭과 모든 형태/새 형태 필터, 고정된 검수 패널을 제공한다. 기본 탭은 미선택만 표시한다. 허용·거절하면 해당 상태의 탭으로 이동하고 검수 대기 목록에서 빠진다. 마지막 대기 건물을 결정하면 패널을 닫고 빈 목록 안내를 표시한다. 허용됨 바로 보기: `?tab=allowed`, 거절됨: `?tab=denied`, 새 형태: `?ui=5&new=1`. 탭 전환은 메모를 보존하며 URL에도 선택 탭을 남긴다. 탭 위의 좌우/Home/End 키는 탭 이동에만 쓰며, 「저장 후 다음 미선택 건물」을 끄면 결정한 건물을 해당 상태 탭에서 계속 보여준다. 선택 취소는 검수 대기 탭으로 돌아간다. 허용됨 탭의 메모만 저장은 허용 상태를 유지한다. 패널의 메모·결정 버튼은 갤러리 스크롤에 묻히지 않는다. 집중 보기, 원본/잔디·기존 집·나무 비교, 맞춤/1/2/3/4/6배 최근접 확대, 격자와 배경 선택도 제공한다. 모바일은 목록에서 후보를 열고 목록으로 돌아간다.

**화면 구성 (2026-10-06 개편):** 어두운 셸 + 잔디 무대. 위쪽 진행 막대(허용/거절 비율·남은 수), 왼쪽 목록(대기/허용/거절/**전체** 탭·검색·회차 필터·정수배 썸네일·허용/거절 도장·메모 표시), 가운데 큰 무대(건물만/원본과 비교, 맞춤·1~6배, 배경 견본, 픽셀 격자는 16px 칸 선 포함), 아래 결정 막대(메모·빠른 메모·거절 D/허용 A·결정 취소). 결정 뒤 알림의 「되돌리기」(Z)는 직전 결정·메모로 다시 기록한다. 단축키 도움말은 `?`. 대기 목록이 비면 무대 자리에 완료 안내와 ZIP 단추를 보인다.

**그림 로딩:** 서버는 그림 요청마다 전체 영수증을 다시 검증해 병렬 요청에 매우 느리다(12개 동시 26초). 그런데 `queue.py`는 `visual_gate.files_profile()`에 들어가므로 **고치면 모든 영수증이 무효가 되어 화면이 0개가 된다** — 서버를 손대지 말 것. 화면이 동시 2개·선택 건물 우선으로 받고, SHA가 들어간 URL을 키로 IndexedDB(`beodeul-review-images`)에 보관한다. 결정 저장 중에는 그림 받기를 멈춘다. `web/index.html`은 프로필 밖이며 요청마다 다시 읽힌다.

A/D와 화살표는 입력 중 실행하지 않는다. 그림 로드가 끝나기 전에는 결정 버튼을 막는다. 후보를 바꾸거나 새로고침해도 입력 중 메모를 후보 ID+그림 SHA별 localStorage에 보존한다. 임시 메모는 해당 브라우저에만 있으며 **메모만 저장** 또는 허용/거절을 눌러야 SQLite에 확정된다. 메모만 저장은 현재 선택 상태를 유지한다. 저장 실패 시 후보를 넘기지 않고, 결정 성공 시 다음 미선택 후보로 이동한다.

round 2의 10종과 기존 선택을 보존하고, round 3에서 T자·쌍박공·깊은 차양·옆채·첨탑·안마당·높낮이가 다른 점포·원뿔 탑 등 10종을 추가한다. 간판과 명시한 지붕 팔레트 변경으로 용도를 구분한다. 활성 시드 20종 전체가 같은 엄격한 검증을 통과한 뒤 공개된다. 예전 4개 Allow는 동일 그림 해시를 유지하며 자동으로 추가 선택하지 않는다.

## 원본 도트와 초안

`seed.json`의 `authoring: native-parts`와 명시적 source/crop/at/replace 레시피를 `node/native_author.py`가 조립한다. 원본 시트와 승인된 beodeul-architecture 집의 픽셀을 1:1로 읽는다. 원본 기와·벽 입자·색 수를 줄이지 않는다. 각 PNG의 전체 팔레트 인덱스 배열도 `.pixels.json`으로 보존한다. 이 배열은 **원본 조립 결과를 풀어 쓴 것**이며 신규 손 격자 저작이라고 주장하지 않는다.

지붕 윗면과 남쪽 정면이 보이는 3/4 시점. 측면을 강요하지 않는다. 신규 후보의 형태 변경 허용은 사용자 요청 범위이며 기존 원본 보정 계약은 beodeul-architecture를 따른다. 문 메타데이터는 입구 위치 설명일 뿐, 실제 문 한 개의 시각 증거가 아니다.

round 3 저작 출처는 `round3-detail-sources.json`이다. 원본 부품 좌표, 간판 16×24 행/팔레트, 지붕 색상표와 명시적 변경 좌표를 보존한다. `node/author_round3_details.py`가 재현한다. 원뿔 제분소의 지붕 내부와 기초는 원본 기와·석재 픽셀을 명시한 좌표로 옮겨 거친 면을 보정한다. 명시한 하이라이트 픽셀도 원본 음영색으로 보정한다. 신규 질감을 절차적으로 생성하거나 이미지 생성 서비스로 대체하지 않는다. 연구 근거는 `harness-data/beodeul-building-review/round3-design-references.md`이며 타 게임 픽셀은 포함하지 않는다. 후보 소스는 사용자 Allow 전까지 런타임 번들에 설치하지 않는다.

## 공개 전 검증 관문

`node/visual_gate.py`와 `gate-rules.json`이 검사 계약을 소유한다.

1. **파일/출처 계약**: 활성 시드의 모든 후보 존재, 서로 다른 그림 해시, 16px 크기 정렬, PNG 해시 일치, 레시피와 실제 RGBA 픽셀 일치, 원본 부품의 색, 반려 그림 해시 금지, 입구 범위/알파 확인, 원본 crop 범위와 불필요한 투명 바닥 한 줄도 확인.
2. **질감 Visual QA**: 최대 5개씩 나누어 새 읽기 전용 Codex 프로세스가 실제 원본/후보/장면 이미지를 보고 `roof_grain`, `wall_grain`, `palette`, `light_consistency`를 검사한다. 각 항목 94 이상이며 구체적 결함이 없어야 통과.
3. **구조 Visual QA**: 최대 5개씩 나누어 별도의 새 읽기 전용 프로세스가 후보 한 채만 담은 4배 최근접 확대를 보고 `projection`, `roof_joints`, `single_door`, `wall_consistency`, `ground_contact`, `complete_silhouette`을 실제 픽셀로 검사한다. 각 항목 90 이상이며 결함이 없어야 통과.
4. **숨긴 부정 대조군**: 모든 묶음에 대조군을 반복하여 각 묶음이 독립적으로 보정 검사를 통과해야 한다.  질감 검사에 사용자 반려 그림을, 구조 검사에 지붕/벽 사이가 뜬 그림과 문 두 개짜리 원본을 섞는다. 모두 FAIL이며 질감 표본의 roof_grain/wall_grain, 지붕 간격 표본의 roof_joints, 중복 문 표본의 single_door 점수가 각 하한 미만이어야 검사 자체가 유효하다. 대조군 정답은 검사자에게 주지 않는다.
5. **증거 봉인**: 후보 해시·레시피·검사 코드/규칙·원본 파일 프로필, 실제 모델 출력/실행 로그 해시, 두 역할 판정과 대조군 결과, 실제 검사 이미지·비교 장면·픽셀 배열 해시를 서명된 영수증에 묶는다. 검사 중 입력이 바뀌면 무효다. 활성 시드의 모든 후보가 현재 증거를 갖춰야 `publish`가 공개한다.

묶음 판정은 점수를 평균하거나 감독이 다시 작성하지 않는다. 각 후보는 해당 실제 모델 판정을 그대로 갖고, 모든 후보를 검사한 합본과 각 묶음의 실제 출력/로그 해시를 함께 봉인한다. 각 묶음 출력/로그를 변조해도 API가 차단한다. 20종/10종 요청의 구조 프로세스 제한 종료를 해결한 실행 크기 조정이며 점수/결함/대조군 하한은 바꾸지 않는다. 검사 코드가 바뀌면 과거 영수증도 무효가 되어 전체를 재검수하고, 기존 인간 결정은 같은 그림 SHA로 보존한다.

gate 자체도 후보 반려 시 실패 종료한다. 모델 오류, 출력 누락, 점수/판정 모순, 대조군 실패, 증거 누락/변조/노후화는 차단한다. API 상태·그림 URL·결정·내보내기도 현재 영수증을 다시 검사한다. PNG만 공개 폴더에 복사하거나 DB 행을 추가해 검증을 우회할 수 없다. 기계 계약 통과와 진짜 이미지 검사를 구분한다. 두 Visual QA 통과는 **사람의 미적 허용을 대신하지 않는다**.

## 저장과 사람의 결정

기본 데이터: 저장소 밖 `~/.local/share/oprn/beodeul-building-review/`의 `review.sqlite`, `staging/`, `items/`, `visualqa/<profile>/<고유 회차>/`, `gate-receipts/`, `decisions.json`. `BEODEUL_BUILDING_REVIEW_DATA`로 QA 데이터를 분리한다. `gate-secret`은 권한 0600이며 저장소에 넣지 않는다. 모델 프로세스는 별도 `vision-work`에서 읽기 전용으로 실행한다.

허용/거절/미선택 취소는 append-only 결정 로그에 PNG SHA256·메모·시간을 저장한다. 같은 그림에만 유효하다. 다시 그린 그림은 재검증과 새 사람 선택이 필요하다. 현재 그림/증거와 맞지 않는 결정은 409로 거부한다. 결정 CLI나 감독자의 자동 선택은 없다.

`export`/화면 다운로드는 **현재 검증이 유효하고 사람이 허용한** 그림만 담는다. PNG·픽셀 배열·레시피·판단 메타데이터를 ZIP으로 내보낸다. 후보가 없으면 만들지 않는다. 사용자 허용 후 공용 번들·구조 키트·통행·참고문서·새/기존 프로젝트 ensure 적용은 별도 단계다. 지도 적용을 요청받으면 SQLite 정본 저장+재로드까지 수행한다.

이전 반려 form-wing/inn/smithy/warehouse는 기존 지도를 읽기 위한 데이터만 남기고 공용 선택에서 제거되어 있다. 이 그림들을 승인본이나 새 후보 기준작으로 추천하지 않는다.

## 근거와 제한

`verify-shots/beodeul-building-review/`에 실제 Visual QA 결과 요약·전체 후보·화면·브라우저 근거를 남긴다. 상세 모델 출력/실행 로그는 외부 데이터 폴더에 보존한다. 버튼 저장·새로고침·취소·허용만 내보내기·낡은 해시/유효하지 않은 증거 거부는 **분리 QA 데이터**에서 확인한다. 실제 사용자 대기열에는 모의 선택을 기록하지 않는다.

브라우저 검증: 갤러리·메모 유지·메모만 저장·필터·집중 보기·모바일은 `scripts/qa/beodeul-building-gallery-browser.mjs` (분리 서버 18319). 기존 검증은 `scripts/qa/beodeul-building-review-browser.mjs` (분리 서버 18318, 실제 18317은 읽기/화면만). 실제 정본 마을/게임 런타임 변경은 없다. 이미지 검사는 모델 판정이므로 사람이 마지막으로 판단한다.

### 긴 실행과 세션 종료

묶음 검사 전체는 도구 셸의 장시간 제한을 넘길 수 있다. 셸이 SIGTERM으로 종료되면 합격 증거가 만들어지지 않으므로 publish하지 않는다. 이 작업에서는 세션과 분리된 단일 Python 프로세스에서 기존 `run_gate(DATA)` → 성공한 경우에만 `publish(DATA)`를 실행하고 PID·로그·단계·종료 결과를 `output/beodeul-building-review/durable-gate*.json|log`로 관찰했다. 종료된 검사자의 미완성 출력을 합격으로 재사용하거나 손으로 판정을 작성하지 않는다.

### 서명한 실제 판정 이어가기

각 5종 묶음의 실제 모델 JSON과 로그를 검증한 뒤 `vision-checkpoints/`에 HMAC으로 보관한다. 코드/원본 프로필·역할·원본 비교 시트·모든 후보/대조군 그림 해시·모델 출력/로그가 모두 일치할 때만 재사용한다. 입력은 검사 전후에도 대조한다. PASS와 FAIL 모두 보존하므로 그림을 고치지 않고 반복하여 합격을 뽑지 않는다. 변조된 체크포인트나 출력/로그는 즉시 차단한다. 미완성·서명 없는 옛 출력은 재사용하지 않는다. 묶음마다 부정 대조군 보정 검사는 다시 확인하며, 최종 공개는 모든 후보의 두 역할 증거가 현재 그림/레시피와 일치해야 한다. 모델 실행 제한은 1,200초이고, 시간 초과는 실패다. 점수/결함/대조군 기준은 유지한다.

### 검사용 그림과 출력 식별값

질감 검사는 후보·원본 비교와 동일 크기 장면을 유지한다. 구조 검사는 원본 비교 집의 문을 후보에 섞어 읽지 않도록 **후보 한 채만 4배 최근접 확대**한다. 숨긴 두 구조 대조군에도 동일한 표시를 적용하고, 지붕 간격·중복 문 하한은 유지한다. 원본 중복 문 표본의 픽셀은 바꾸지 않는다. 모델 출력 schema의 ID/SHA enum은 해당 요청의 실제 값으로 제한하며 ID와 SHA의 짝은 별도로 엄격히 검사한다. 검사 중 미완성/잘못된 SHA 출력은 고쳐 재사용하지 않는다.

각 역할 안에서는 최대 4개의 **읽기 전용** 묶음 검사를 독립 폴더에서 동시에 실행한다. 후보나 프로젝트 콘텐츠를 병렬 수정하지 않는다. 모든 묶음 결과와 대조군을 검사한 뒤 다음 역할/영수증/공개로 진행하므로 부분 합격이나 먼저 끝난 결과로 공개하지 않는다. 코드/검사 표현이 바뀌어 과거 프로필은 무효이며 20종 전체를 새로 검사한다.

### 저장 · 설치 · 서비스 (2026-10-07)

**사람 결정 로그.** 정본은 `review.sqlite` 의 `decisions(seq,item,sha,decision,note,at)`(그림 sha256 에 묶임, 덧붙이기 전용)이고, 저장소 사본은 `harness-data/beodeul-building-review/decisions.json` 이다. 서명 대상이 **아니다**(수정해도 영수증 무효화 없음).
`npm run harness -- beodeul-building-review decisions export|restore|backup|status` — export 는 기존 로그가 접두사로 남아 있어야 쓰고(되돌림 거부), restore 는 빈 표에만 복원, backup 은 sqlite `.backup` 을 `~/backups/beodeul-review/` 에 떠 14개만 남긴다. 영수증·`gate-secret`·로그·staging 은 git 에 넣지 않는다. **커밋 전에 export.**

**공용 번들 설치.** `npm run harness -- beodeul-building-review install` (`node/install.py`): 결정 로그에서 현재 그림 해시에 **허용**된 후보만(그림 원본 sha256 일치 확인) 골라 `public/assets/beodeul-reviewed/chipset.png` + `src/assets/beodeulReviewedCatalog.json` + `tiledata/beodeul-reviewed/` 출처 사본으로 굽는다. 건물 한 채 = 본체(3층 `bd-house-rv-<라운드>-<번호>`) + 바닥 그림자(2층 `bd-rv-shadow-*`) + 기초(4층 `bd-rv-foundation-*`), 같은 원점. 통행: 벽 칸 막힘(문 칸 포함), 처마·지붕 칸 걸을 수 있음 — 벽은 칸별 밝은 회벽·돌 색 비율로 가려 열 지면에서 이어 붙인 **휴리스틱**이고 통나무집은 지붕 아래 띠 전체를 막는다. 한 번 허용된 뒤 반려로 바뀌면 다음 설치에서 빠진다.
