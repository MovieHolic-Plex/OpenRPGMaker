# dungeon-chipset — 공용 던전·동굴 칩셋(beodeul_dungeon) 후보 하네스

## 왜
2026-10-07 저작권 정리 뒤 편집기에는 던전·동굴 칩셋이 하나도 없다. 조수 지침은 「등록된 던전 장소를 가져오라」지만
장소도 0곳이라, 장르 시험에서 조수가 얼음 동굴을 로마풍 항구 도시 칩셋(beodeul_city)이나 네모난 손 도트 실내로 지었다
(`openwiki/chipset-gap-inventory.md` 1번). 이 하네스는 **버들항과 같은 계열(`oprn-atlas`)** 의 던전 문법 — 불규칙 바위 벽·천장·바닥
오토타일, 물·용암·얼음 가장자리, 다리, 계단, 문·창살문, 기둥, 횃불, 상자, 함정, 지렛대, 장식 — 을 후보로 만들고 **사람이 고르게** 한다.
계열이 같으므로 버들항 마을 맵과 던전 맵을 섞어도 계열 전환 거부(`toolRunner.rejectTilesetFamilyChange`)에 걸리지 않는다.

버들항에는 이미 던전 **키트**(바다 동굴·지하묘지·수로·신전·화산굴 — 참고문서 용도 `beodeul-picks-dungeon`/`special`)가 있다.
화법의 기준은 그 조각들이다. 빠진 것은 아무 모양이나 칠할 수 있는 **문법**(오토타일·가장자리·끼우는 조각)이다.

## 줄(line) — 컨셉마다 따로 고른다 (2026-10-08 사용자 결정)
style-r1 을 본 사용자: 「던전은 컨셉이 다양할 수 있으니까, A B C 셋다 써도 그만일거같은데? … 버리긴 아깝군.」
그래서 화풍을 하나로 고정하지 않고 **A·B·C 를 서로 다른 던전 컨셉 줄 셋**으로 남긴다(시드 `lines`).

| 줄 | 이름 | 컨셉 |
|---|---|---|
| A | 해안 흙굴 | 버들항 바다 동굴 계보 — 어둠 위 갈색 흙 띠·밝은 끝선, 이끼 낀 녹회색 돌 앞면, 갈색 반점 흙, 맑은 물. 해안·습지·초반 동굴 |
| B | 산속 바위굴 | 천장 어둠 대신 갈라진 회색 바위 윗면, 큰 바윗덩이 앞면, 어두운 흙·자갈, 검푸른 고인 물. 산 속 굴·광산 |
| C | 검푸른 심층굴 | 돌 혹 테두리와 깊은 어둠, 물결 층리 검푸른 화산암 앞면, 차가운 회색 자갈. 고대·심연·후반 던전 |

**작업자 지시(이후 판을 그리는 에이전트):**
- 이후 판은 **줄마다** 후보를 그린다. 후보 키는 `<줄><번호>`(A1 A2 B1 B2 C1 C2). `pick` 은 앞 글자로 줄을 안다.
- 줄의 화풍 기준은 **style-r1 의 그 글자 조각**이다 — 같은 램프, 같은 결(점·띠·층리). 다른 줄 화법을 섞지 않는다.
- **윤곽은 style-r1 이 아니라 「외곽선 규칙」(아래 절, 시드 `rules.outline`)을 따른다** — 먹(밝기 ≤ 0.12) 윤곽 없이 재질 명암으로. 기존 판의 먹·0단 윤곽을 본뜨지 않는다.
- 줄 컨셉에 안 맞는 항목은 **그 줄에서 빼도 된다** — 시드 `lines.<줄>.skip` 에 `{항목: 이유}` 로 적고 그 줄 후보를 그리지 않는다(`validate` 가 빠진 줄 후보·이유 없는 skip 을 잡는다).
- 같은 줄의 같은 번호끼리는 한 세트로 보이게(장면에서 같이 깐다), 같은 줄 다른 번호끼리도 바꿔 끼울 수 있게(같은 램프·사분면 경계 깊이) 그린다.
- 고르기 단위는 (항목, 줄). 고른 그림은 `picked/<줄>/<항목>.png`. 해시 묶기는 그대로 — `--sha` 가 시트 해시와 다르거나 시트 뒤 그림이 바뀌면 거부, 고른 뒤 바뀌면 `status`·`list` 에서 VOID.
- `list` 는 줄마다 `★A`(고름) · `·A`(아직) · `-A`(그 줄에서 뺌), 시트는 고른 후보 카드에 「★ 줄 A 고름」.
**감독·에이전트는 고르지 않는다.** 기계 관문 통과는 합격이 아니다 — 시점·화풍·읽힘은 사람이 시트에서 판단한다.
번들(`src/assets/bundled.ts`)·타일셋 정의 배선·참고문서는 사람이 고른 뒤의 **별도 작업**이다(AGENTS.md 「새 타일·타일 학습은 공용에」 절을 따른다).

## 명령 (`npm run harness -- dungeon-chipset …` 또는 `python3 src/harnesses/dungeon-chipset/harness.py …`)
| 명령 | 뜻 |
|---|---|
| `palette [--check]` | 버들항 조각에서 팔레트를 다시 뽑는다(`--check` 는 다시 뽑아 지금 파일과 같은지만) |
| `validate` | 시드·계열·Actor1·기준 그림·팔레트 최신·판 모듈·후보 코드 hex 금지 점검 |
| `list [--wave W]` | 묶음별 항목, 줄마다 ★A = 고름(현재 해시와 맞을 때만) · ·A = 아직 · -A = 그 줄에서 뺌 |
| `draw <판>` · `gate <판>` | 그리기 · 그리기+관문(FAIL 이면 종료코드 1, ledger 에 실행 기록) |
| `sheet <판> [--force]` | 고르기 시트. 관문 FAIL 이 있으면 `--force` 없이는 쓰지 않는다 |
| `pick <판> <항목> <후보> --sha <앞 8자리> [--note]` | 사람이 고른 것. 후보 = 화풍 판은 줄 글자, 이후 판은 `<줄><번호>`. 시트 해시 앞자리와 manifest·현재 그림 해시가 모두 맞아야 기록, (항목, 줄)마다 하나 |
| `reject <판> <항목> <후보> --why "…"` | 사람이 버린 것과 이유(다음 판의 「하지 말 것」) |
| `status` | 판·관문·시트, 줄별·묶음별 고른 것 현황(그림이 바뀌면 고른 기록은 VOID 로 보인다), 판별 외곽선 경고 수와 **굽기 전에 다듬을 목록**(고른 것 중 OUTLINE·CONTRAST) |

## 잠금 팔레트 — 어떻게 뽑았나
`palette.py` 가 램프마다 출처 조각(`tiledata/beodeul-variants/<장소>/parts/*.png` — 공용 시트 꼬리 23,936~ 에 구워진 그림)을 정하고,
필요하면 색상 조건으로 그 재료 화소만 거른 뒤(예: 신전 벽의 이끼 초록) **화소 수 0.3% 미만의 잡티 색을 빼고 밝기 범위를 k 등분해 칸마다 가장 많이 쓰인 실제 색** 을 고른다.
평균을 내지 않으므로 모든 색이 버들항에 실제로 있는 화소 색이고, 마지막에 공용 시트 `public/assets/beodeul-city/beodeul-city-chipset.png` 에 있는지 대조한다(없으면 실패).
처음엔 화소 수로 등분했는데 드문 윤곽색·빛색이 빠져(돌 램프 3색) 밝기 구간 등분으로 바꿨다. 칩 램프 gold·red 는 `scripts/content/lib/city_v6/palette.py` 의 `RAMPS_CHIP` 에서 그대로 가져와 시트 존재만 대조한다.
반투명은 버들항 조각에서 가장 흔한 바닥 그림자 (12,14,20,α88) 하나만 허용(윗층 기물 전용).
램프: void · rim · cfloor · crock · stone · cata · brick · water · pool · lava · ice · vrock · wood · iron · fire · bone · moss · glow · gold · red.

## 동굴 문법 (dot.py)
- 격자 `#` 바위 · `.` 바닥 · `w` 물. **바닥에 남쪽으로 닿은 바위 = 앞면 아랫단, 그 위 = 앞면 윗단, 나머지 바위 = 천장(윗면).**
  동·서·북쪽 바위 가장자리는 윗면 테두리만 보인다(옆면을 그리지 않는다 — 3/4). 앞면 위에는 천장이 한 칸 이상(`structure_errors`).
- 천장 오토타일은 **천장끼리만** 이어진 것으로 본다 — 앞면과 만나는 남쪽 변에 테두리(벽 윗면 끝선)가 그려진다. RPG Maker A4 와 같은 규칙.
- 오토타일: 후보는 32×32 **틀**(모서리·변 조각, 가운데는 비움) + 16×16 **안 모서리 칸** + 16×16 **몸통** 을 찍는다.
  `dot.Autotile` 이 A2 와 같은 사분면 규칙(TL=(N,W,NW) 등)으로 자리만 옮겨 8방 47 변형을 만든다. 조각의 `.` 은 투명으로 남겨 조립할 때 **그 칸 자리의** 몸통이 비친다
  — 처음 판은 몸통을 틀에 8px 밀어 구워 넣어서 모서리·변 조각 안의 몸통이 어긋났고, 관문 S(물 A 남변)가 잡았다.
  변 조각은 8·16·24 열/행(사분면 경계)에서 같은 깊이로 맞춰야 바꿔 끼워도 이어진다. 엔진에는 `variantMap`(256 마스크 → 칸)으로 그대로 옮길 수 있다.
- 앞면: 32×32 표본, 윗 16줄 = 윗단 · 아래 16줄 = 아랫단, 가로 0~7 왼끝 · 8~23 가운데(16칸 주기) · 24~31 오른끝. 같은 단 앞면이 옆에 없으면 끝 마구리.

## 기계 관문 (gate.py) — 깨짐만 거른다
FAIL: **P** 팔레트 잠금(불투명은 palette 색만, 반투명은 그림자 하나) · **Z** 16 배수·시드 크기 · **Q** 아래층 불투명(오토타일 47 변형·앞면 8조합·계단·문 전부) ·
**F** 윗면(기물: 선언한 윗면 줄 ≥3 이고 앞면보다 밝음 / 동굴: 모든 앞면 윗단 위 칸 아래 2줄이 어둠이 아님 / 물: 북쪽 물가 띠가 몸통과 다름) ·
**S** 이음(몸통 6×6 반복·변 띠 반복·앞면 가운데 반복에서 칸 경계 차이 > 칸 안 중앙값×1.5 이고 +8 초과면 실패. 왼쪽 열을 일부러 어둡게 한 몸통으로 검출 확인: 62.7 vs 12.8) ·
**G** 동굴 구조 · **A** 물·용암 장면(4장면, 47 변형마다 장면끼리 바뀌는 화소는 물·용암 램프뿐 = 물가 화소 동일, 이웃 장면 몸통이 다름, 장면마다 Q·S) ·
**K** 얼음 상태(47 변형마다 칸 둘레 2px 가 상태끼리 같음, 상태끼리 몸통이 다름) · **J** 다리 키트(가로 서끝|가운데|동끝 · 세로 북끝|가운데|남끝 맞닿는 줄의 투명 모양이 같음 + 가운데 조각 반복 S).
F 는 물·용암·낭떠러지 모두 북쪽 가장자리 띠가 몸통과 다른지 본다. WARN: **R** 같은 항목 후보끼리 밝기 윤곽선이 90% 넘게 겹침(색만 바꾼 후보) ·
**OUTLINE** 외곽선 규칙 — 가장자리 먹(밝기 ≤ 0.12) > 15% 또는 기물 빛 쪽(위·왼) 가장자리 먹·0단 > 50%. 기물 = part 실루엣 바깥 1px, 다리 = 칸 안 투명과 맞닿은 실루엣(큰 구조라 먹만),
오토타일 = 한 변만 끊긴 변형 넷에서 몸통과 달라진 가장자리 띠(몸통이 어둠인 천장·낭떠러지는 안 잼), 앞면 = 끝 마구리(가운데 조각과 달라진 화소)·아랫단 밑 2줄 ·
**CONTRAST** 크기 ≤2칸 기물 part 의 그늘 쪽(아래·오른) 실루엣 가장자리 평균 밝기 vs 줄 대표 바닥(style-r1 그 글자 동굴 바닥 몸통) 평균 밝기 차 < 0.15 = 바닥에 묻힘.
옛 **O**(기물 가장자리 70% 이상 어두움, FAIL)는 외곽선 규칙과 정반대라 2026-10-08 에 지웠다.
시점·화풍·읽힘은 수치로 대신하지 않는다(메모리 view34-gate-is-not-evidence). 사람이 시트에서 본다.

## 시트
항목마다: 버들항 기준 조각(같은 용도, 1배·4배) · Actor1 정면(1배·4배) · 후보마다 원본 1배·4배 · 같은 글자 동굴 위 장면 1배·3배(meta `anim` 이 있으면 3fps GIF) ·
동굴은 바닥/천장 몸통 6×6 과 앞면 6칸 이어 붙임 · 관문 결과 · 해시 앞 8자리. 맨 아래 **세트 장면**: 글자마다 다섯 항목(동굴·물·계단·문·상자+횃불)+Actor1 을 한 장면(12×9)에, 그리고 잠금 팔레트.
벽돌 앞면(문 항목의 바탕)은 **맥락이지 후보가 아니다** — built 묶음에서 따로 고른다.

### edges-r1 2차 수정 (2026-10-08, 감독 지적 4건)
1. **장면이 반듯한 네모 상자** → 후보 장면·줄별 장면을 ㄱ자 물길·튀어나온 곶·좁은 목으로 다시 깔았다(오토타일 안/바깥 모서리가 다 나온다).
   가장자리 자체도 울퉁불퉁하게: 변마다 손으로 적은 굴곡 표(`WOB`, 0~2px, 사분면 경계·바깥 끝은 0)만큼 띠를 물 쪽으로 밀고 빈 자리를 줄 바닥 결로 채운다(`wobble`).
   줄마다 표를 다르게(A 그대로 · B 뒤집기 · C 남북·동서 맞바꿈). 물·용암·낭떠러지 끝선에는 줄 돌(`studs`: A 녹회색 · B 회색 둑돌 · C 밝은 자갈 · 용암 화산암)을
   사분면 조각 하나 안에만 얹는다(경계를 넘으면 이웃 변형에서 돌이 반쪽이 된다). 물가는 이제 「style-r1 물가 + 굴곡 + 테두리 돌」이다.
2. **물 장면에 다리가 안 보이고 사람이 물가 테두리 위** → 다리가 물 한가운데 줄을 동서로 6칸 건너고(양끝이 바닥), 사람 발을 상판 가운데에 둔다(`at_cell(foot=)`).
3. **낭떠러지가 작은 검은 네모** → 구조를 바꿨다(`Chasm`). 구덩이 칸마다 북쪽 끝선에서 내려온 칸 수 d 로 바탕을 고른다: 먼 벽 앞면 1단·2단(·3단) → 어둠 그라데이션
   → 어둠. 그 위에 몸통 투명 **끝선 오토타일**(북 끝선 L·D, 서·동·남 턱, 굴곡 + 돌)을 얹는다. <줄>1 = 앞면 2단(32px), <줄>2 = 3단(48px).
   먼 벽 결은 줄 style-r1 앞면을 행마다 램프 단을 내린 것, 그라데이션은 그 결이 void 2→1→0 으로 묻히는 것. 칩셋으로는 「끝선+어둠 47 변형」 +
   「먼 벽 단·그라데이션 16칸 주기 조각」(빌더가 벽 앞면처럼 끝선 아래에 놓음)이다. 장면 구덩이는 4칸 깊이, 다리가 4칸 걸린다. 관문 Q·S 는 단 조각도 본다(meta `tiles`).
4. **얼음 후보 윤곽 97% 겹침(WARN R)** → 두 안을 다른 물건으로: 1 「매끈한 빙판」(두께 없음, 윤곽 1px, 반사 획, 바탕 ice 2) /
   2 「금 간 두꺼운 얼음 덩이」(3px 솟음, 남쪽 앞면 ice 0 에 세로 금, 짙은 바탕 ice 1·0 + 하얀 균열선). 줄끼리도 굴곡 표와 몸통 자리(A 그대로·B 180°·C 8칸 밈)가 달라 WARN R 이 사라졌다.
- 남은 약점(2차, 감독 육안): 물 C1·C2 는 물가가 같고 몸통 점만 달라 WARN R 90%(경계값) · B·C 물 움직임 약함 · 1 번 낭떠러지 3단째부터는 거의 검정이라
