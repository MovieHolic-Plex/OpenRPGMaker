# 지형 설계와 게임 높이 규칙 (2026-10-03)

「높이」 진입 → 캔버스 아래 **지형 설계**. 떠 있는 패널의 도구·옵션을 고르고
캔버스에 외곽/경유점을 찍은 뒤 **적용 / Enter**로 확정한다. 패널을 닫아도 Enter를 쓸 수 있다.
Esc/오른쪽 버튼은 미완성 점을 취소한다. 패널 머리줄은 드래그해 옮긴다.
아래 도구 막대는 아이콘이며, 도구별 설정은 별도 위 줄에 표시한다. 물음표 도움말은 모달로 열린다.
기본 높이·표면·강·군집 선택으로 돌아가면 설계 패널을 닫는다.
도구별 배치 계약과 아이콘/모달 소유는 [terrain-placement-tools.md](terrain-placement-tools.md)의
「아이콘 도구와 도움말」을 읽는다.

## 도구 계약

| 도구 | 입력과 결과 |
|---|---|
| 절벽 윤곽 | 다각형 / 사각형 / 폭 있는 선. 각 칸의 현재 높이에 입력한 변화량을 더한다. 음수는 내리기. |
| 집 외관 | 아래 막대의 집 버튼 → 실제 타일 썸네일/등록된 집 선택 → 드래그로 너비·높이를 정하고 놓으면 한 채 배치. 한 번 클릭은 선택한 크기의 문 위치 기준 배치. 합본·Forest Harmony 조립식 집은 너비 5~24칸(짝수 포함), 지붕 몸통 1~12행, 1/2층 벽을 사용한다. 역방향 드래그도 두 모서리의 좌상단에 놓는다. 등록된 완성형 집은 원본 크기를 보존한다. 버들항 등 다른 칩셋은 입구가 등록된 기존 section 집 키트를 사용한다. |
| 길 | 아래 막대 도로 버튼은 드래그하고 놓으면 적용한다. 체크를 끄면 경유점/Enter 방식이다. 경유점 선, 폭. 모퉁이는 직교 연결되고 바닥 autotile을 성형한다. 지형 따라가기는 진행 방향과 남은 길 폭에 맞춰 경사로를 연결하고, 평탄화는 첫 점 높이로 맞춘다. |
| 능선 / 계곡 | 경유점 선과 폭, 높이 변화량. 중심부터 가장자리로 변화량이 줄어든다. |
| 호수·해안 | 다각형 / 사각형, 수위·최대 깊이·걸을 수 있는 물가 폭. 보호된 물체·통로를 제외한 영역의 경계에서 안쪽으로 깊이를 계산한다. |
| 재질 혼합 | 클릭 영역, 풀·흙·돌 비중, 시드. 해당 칩셋의 재질만 사용하고 높이는 유지한다. |
| 혼합 군집 | 클릭 영역, 나무·바위·덤불 비중, 밀도, 시드. 칩셋의 기존 구조 키트를 섞고 원의 가장자리 밀도를 줄인다. 전체 군집은 기존 선택/이동/삭제로 다룬다. |
| 지형 도장 | 두 모서리로 최대 128×128칸을 저장. 같은 칩셋의 다른 맵에 회전/반전해 놓는다. 1~4층·그림자·높이·경사로·수심·벽면 장식·완전한 군집을 포함한다. |
| 영역 잠금 | 다각형 / 사각형 잠그기·해제. 잠긴 칸은 보라색 표시. 공통 타일 편집 경로가 원래 타일·높이·통로·그림자·수심을 보존한다. |
| 경로 검사 | 출발점 → 목적지. 실제 `canMove` 4방향 탐색. 파랑 경로, 노랑 지정 폭 미만 병목, 빨강 끊긴 앞 칸, 출발/목적지 표시. |

고지 1·2·3단 프리셋은 없다. 기존 높이 엔진의 저장 범위는 유지한다.
길의 자동 연결은 `terrainRoadRamps.connectTerrainRoad`가 직교 경유점의 낮은 둑에 경사를 만든다.
폭이 맞지 않는 절벽에서는 실제 빈 통로 폭으로 줄이고, 굽은 진입에는 평평한 착지 칸을 남긴다.
보호된 물체·기존 경사·잠금은 건드리지 않으며 연결 불가 지점 수를 결과 문구로 알린다.
경사 덩어리는 방향과 낮은 높이가 모두 같은 칸끼리만 묶는다(`reliefSlopes`).
경로 검사는 아래 「게임 상태 검사」를 따른다.

## 대칭과 도장

대칭은 없음·좌우·상하·좌우/상하·180°·90° 회전. 90° 회전 대칭은 정사각형 맵에서만 선택한다.
높이·표면·강·경사로/지형지물과 설계 도구가 같은 좌표 변환을 사용한다.
도장은 별도로 0/90/180/270°와 좌우 반전을 제공한다. 경사로 방향과 그림자 비트도 회전한다.
소품의 연결된 그림 조각은 똑바로 유지하며 중심/위치만 변환한다. 여백이 부족하거나 서로
겹치면 적용 전에 거부한다. 군집 일부만 잘라 저장하는 것도 거부한다.

- `project.terrainStamps?`: id·이름·칩셋·크기와 모든 칸 데이터, 선택 장식/군집. 저장 라이브러리는 맵과 별개다.

- 복제/크기 변경: `mapLayers.ts`의 clone/remap/crop이 잠금·수심을 함께 옮긴다.
- 잠금 초크포인트: `store.updateMapTiles` → `terrainLocks.restoreLockedTerrainCells`.
  Undo 및 명시적 전체 맵 교체/크기 변경은 일반 `updateMap` 계약을 따른다.
- 게임 통행: `collision.cellPassOrNull`. 성분 캐시 지문에 수심·높이·경사로를 포함한다.

## 적용한 지형 재편집

도로·호수·절벽·능선·계곡은 `map.terrainDesign.features`에 원점, 옵션, 실제 변경한 칸의
before/after를 저장한다. 패널의 「적용한 지형 재편집」에서 선택하면 제어점과 옵션이 돌아온다.
점을 드래그한 뒤 폭·수위·높이를 바꿔 적용한다. 드래그는 미리보기만 바꾸며 확정은 한 번의 Undo다.
이전 결과를 복원하고 새 계획을 적용하므로 높이가 누적되지 않고 줄인 영역도 원래대로 돌아온다.
다른 붓/지형이 해당 칸을 바꾸거나 잠금이 걸리면 재편집을 거부하고 이유를 표시한다.
데이터가 없던 기존 붓 결과에는 제어점을 추정하지 않는다.
복제는 전체 설계 정보를 보존한다. 크기 변경·밀기·크롭은 칸 번호/기하가 낡아지므로
features를 버리고 완성된 타일·높이·수심·잠금·게임 규칙을 계속 보존한다.
계획: `editor/terrainFeatures.ts`; 저장 타입/검사: `project/terrainDesign.ts`.

## 지형 다듬기와 물 표현

「지형 다듬기」 도구에서 외곽을 찍고 평활화·침식·모서리 정리 및 1~8회 반복을 고른다.
잠금·물·소품·이벤트·경사로는 수정 대상에서 제외한다. `terrainFinish.ts`는 한 반복의 높이 사본을
읽어 변경을 계산하므로 순회 순서에 따라 평활화 결과가 흔들리지 않는다.
`player/terrainWater.ts`는 편집기와 내보내기 플레이어에 공통인 절차 그림이다.
깊은 물은 어둡게, 얕은 물은 밝게 표시한다. 남쪽으로 수심 칸이 이어지고 수위가 낮아지는
경계에는 물줄기·밝은 줄·발치 거품을 그린다. 북/동/서 낙수는 3/4 시점에서 앞쪽 벽이 아니므로
이 그림 경로에서 폭포로 그리지 않는다. 수심 색상은 통행 판정과 같은 저장 배열을 읽는다.

## 게임 상태 검사

「경로 검사」의 「게임 상태로 경로 검사」는 몸 폭/높이, 하단 통행 차단 행, 이벤트 점유,
문 이벤트와 상태, 해당 맵 페이지 조건에 쓰인 스위치를 받는다. 변경은 검사 설정이며 게임의
시작 스위치를 덮어쓰지 않는다. 문을 자동으로 추측하지 않고 저자가 이벤트를 선택한다.
「조건·스위치대로」는 실제 `startSession`·`runtimeEventViewsForMap` 페이지 해석을 쓰고,
강제 열림/닫힘은 선택한 문만 검사에 반영한다. 문·NPC 판정은 실제 통행 사각과 공간 설치 점유다.
이동은 `canMoveFootprint`, 크기 1의 기본 검사는 기존 `canMove`와 같다.
API의 `TerrainRouteOptions.session/positions`는 진행 중 세션과 NPC 좌표를 받아 같은 검사에 쓸 수 있다.
편집기 기본값은 시작 상태와 저작 NPC 위치이며 시간에 따라 움직이는 NPC의 미래 위치를 예측하지 않는다.

## 공용 도장

「공용 지형 도장」에서 프로젝트 도장을 공용 저장소로 복사하고 이름 검색·실제 칩셋 썸네일로 고른다.
카드를 누르면 현재 프로젝트에도 도장을 저장하여 일반 배치/회전/반전에 쓴다.
`oprn-terrain-library` IndexedDB는 프로젝트 id와 독립인 기기/브라우저 라이브러리다.
기기 이동은 `format: oprn-terrain-stamps, version:1` JSON 가져오기/내보내기를 쓴다.
손상된 도장이 한 개라도 있으면 전체 가져오기를 거부한다. 500개/24MB 제한, 같은 id는 갱신한다.
이미지 에셋을 새로 저작하지 않으며 칩셋 정의가 같은 프로젝트에서 쓴다. 타 기기에서는 해당 칩셋도
필요하다. 공용 학습 자료/번들 카탈로그와는 별도인 사용자 라이브러리다.

## 게임 시야와 높이

맵의 `terrainDesign.gameplay`에서 다음을 개별로 켜고 끈다. 시야 차단은 선택 기능이며 기본 OFF다.
`createBlankMap`은 `DEFAULT_TERRAIN_GAMEPLAY`의 새 사본을 저장한다. 새 맵의 시야 차단/고지 시야 확대/발사체 높이 충돌은 OFF이고,
규칙 없는 이전 맵도 OFF로 해석한다. 에디터 미리보기도 기본 OFF다. 저자가 직접 켠 기존 맵은 선택을 유지한다.
게임 규칙 안내에서 기본 꺼짐과 직접 켜는 조작을 명시한다.

- 지형 시야 차단: 관찰자의 눈높이보다 높은 땅과 벽·지붕·나무가 뒤쪽을 가린다. 대상 고지 칸도 검사하며 고지에서는 자기 고지에 가리지 않고 아래를 본다. 모서리를 스치는 ray의 두 칸도 검사한다. 물/길/바닥은 타일의 통행 불가 fallback에서 제외한다. 윗층 물체는 출처 설명에 길/물 낱말이 있어도 지면으로 간주하지 않는다. 버들항 사이프러스·산울타리도 수관으로 판정한다.
- 고지 시야 확대: 기본 반경 + 높이 × 추가 반경. 고지 1/2/3 프리셋을 쓰지 않는다.
- 발사체 높이 충돌: 발사 높이 + 눈높이를 비행 고도로 기억하고 높은 땅에 닿으면 파괴한다.

캔버스 시야 미리보기는 검사 위치를 클릭으로 옮긴다. 미리보기 토글과 실제 게임 규칙 토글은 별개다.
내보내기 플레이어의 시야 마스크·NPC 신선한 감지·전투 타깃 탐색은 같은 `terrainGameplay.ts`를 쓴다.
활성 추격의 마지막 목격 수색/보복 대상은 기존 AI 정책을 유지한다.
시야 차단 OFF는 반경 가림까지 전부 제거한다. 고지 시야 확대를 별도로 켜 두어도 화면 가림은 생기지 않는다.
편집기와 플레이어는 `terrainVisionRaster.ts`의 같은 시야/절벽 실루엣을 사용한다.
가시 칸의 원형 반경·물체 뒤 실루엣에 0.8타일 blur를 적용해 경계를 둥글고 점진적으로 만든다.
`src/player/terrainVisionTransition.ts`는 재사용 canvas 3개로 이전/새 마스크의 알파를 240ms smoothstep으로 이어 준다.
겹쳐 가려진 곳은 additive 합성으로 어두움을 유지하고, 관찰점/카메라 이동 중에도 현재 화면을 이어 받는다.
논리 시야·AI/타깃 판정은 원래 가시 칸 집합을 즉시 사용한다. 화면 효과로 판정을 느리게 하지 않는다.
에디터 미리보기는 팬/줌에도 카메라 범위를 갱신한다. 런타임은 가려진 NPC의 머리/그림자를
렌더 직전에 점진적으로 투명하게 만들고 완전히 사라지면 숨긴다. 렌더 뒤 원래 표시 상태/알파를 복원한다. 저작 페이지/게임 상태는 바꾸지 않는다.
가려진 액션 적의 체력 막대도 그리지 않는다. 높이 도구의 시야 미리보기 중에는
가려진 이벤트 배지/저작 스프라이트도 같은 visible set으로 숨긴다. 차단 또는 미리보기를 끄면 돌아온다.
반경/높이/맵/규칙 또는 카메라 칸 범위가 바뀔 때만 마스크를 다시 계산하며 기본 반경은 8, 높이당 +1, 상한 64칸이다. 마스크 기하는 카메라 범위와 최대 들림 여백만 그린다.
발사체는 실제 액션 전투 `spawnProjectileFrom`/`updateProjectiles`에 연결한다.

## 빠른 집과 도로

`quickHouse.ts`는 현재 지도 타일셋의 집 부품과 section 키트의 입구 부위를 재사용한다.
새 프로젝트 기본인 버들항은 `src/editor/beodeulQuickHouse.ts`가 공용 반목조/통나무 부품으로 집 6종을 조립한다.
반목조는 최소 7칸, 통나무는 최소 5칸, 최대 너비 24칸이다. 집 전체 모드는 지붕 3행과 지붕 끝을 원본으로 유지하고
높이는 창·문을 자르지 않도록 2행짜리 층 단위로 맞춘다(최대 9층). 잔디 위에 버들항 윗층 부품만 놓는다.
숲마을·합본 마을 지도는 해당 지도에서만 기존 `stampRectHouseKit`를 쓴다. 칩셋을 바꾸거나 외부 집 그림으로 대체하지 않는다.
집 원점은 입구의 마지막 행을 클릭한 칸에 맞추며, 문 앞 칸까지 검사한다.
집 전체가 같은 높이의 빈 땅이어야 한다. 잠금·물·길·경사·4층 물체·이벤트·기존 구조물과
겹치거나 경계를 벗어나면 붉은 실제 타일 고스트와 이유를 표시하고 쓰지 않는다.
배치는 기존 `structurePlacements`에 원래 1/3층 타일과 afterHash를 저장하고 한 번의 Undo로 취소한다.
버들항의 「드래그 대상 → 지붕만」은 벽 너비·층수를 고정하고 지붕 너비(벽 이상~24칸)만 바꾼다.
원본 3행의 용마루/처마와 양 끝을 유지하고 가운데 부품만 가로로 반복한다. 넓은 처마 밑의 빈 칸은 땅을 유지한다.
기존 생성 집의 지붕에서 끌면 `roof`/`walls` 부위와 입구 앵커로 벽·창·문 좌표 및 타일을 그대로 유지한다.
옛 생성 집은 kit id/3행 지붕으로 부위를 복원한다. 원래 placement id를 유지하고 before/afterHash를 새 영역으로 기록한다.
직접 덧칠하거나 뒤에 다른 구조물이 겹친 집은 보호한다. 기존 벽 영역의 이벤트는 유지하고 새 지붕 영역의 이벤트/잠금/물체는 검사한다.
교체 전체를 한 번의 Undo/Redo로 처리하고 미리보기/Esc는 실제 타일을 변경하지 않는다.
등록된 집 정의는 기존 구조물 라이브러리처럼 Undo 후에도 재사용한다. 외관 배치만 하며 내부/워프는 기존 이벤트 저작으로 연결한다.
집 그림이나 학습 자료를 새로 만들지 않는다. 생성기는 모든 프로젝트에 공통이고,
등록 집은 각 칩셋의 공용/저작 section 정의를 그대로 사용한다.
`quickBuildPanel.ts`가 실제 칩셋 썸네일·집 목록·크기와 도로 드래그 옵션을 소유한다.
도로는 드래그 중 임시 점만 바꾸고 pointerup에서 기존 `planTerrainFeature`로 한 번 확정한다.
우클릭/취소는 임시 점을 버리며 기존 길 자동타일·경사 연결·잠금/물체 보호를 유지한다.
`terrainRoadTile`은 현재 칩셋의 길 자동타일을 먼저 고른다. 버들항은 `beodeul_road_autotile`의
포석(몸통 3221)이며, 길 그룹이 없는 칩셋만 기존 흙 재질로 돌아간다.

## 시야·빠른 배치 확인

`scripts/capture/capture-visibility-building.mjs`는 실제 집 버튼/사각형 드래그/포인터와 도로 드래그로
새 프로젝트/새 맵 기본이 버들항인지 먼저 확인하고, 기본 집을 7×6칸으로, 다른 반목조 집을
역방향 드래그로 10×8칸, 통나무 집을 7×7칸으로 놓는다. 3길의 포석 자동 연결,
외부 칩셋 바닥 없음, 중복 배치 거부, Esc 취소, Undo/Redo, 통행 연결, 벽과 고지 시야, OFF 화면을 기록한다.

출하 `player.html`/shim에서 저작된 ON/OFF 두 맵과 관찰 위치 이동으로 NPC 실표시를 비교한다.
`save-visibility-building-fixture.mjs`는 독립 SQLite에 저장하고 닫아 재로드하여 타일/집 정의/
구조 배치/길 제어점/시야 규칙을 비교한다. 버들항 증거: `verify-shots/beodeul-building/`.
이전 `verify-shots/visibility-building/`은 숲마을 시연이므로 버들항 기본 타일셋의 완료 근거가 아니다.
AGENTS의 실행 제한을 따라 gates/vitest/전체 typecheck는 실행하지 않는다.

집 드래그는 `terrainHouseDrag`에 두 모서리만 저장한다. `quickHousePreview`와 확정이 같은 `planQuickHouseDrag`를 사용하며, 포인터를 놓기 전에는 지도/라이브러리를 쓰지 않는다. Esc·우클릭·스트로크 취소는 미완성 집을 지운다. 한 집은 Undo 한 번으로 되돌린다. 버들항 높이는 온전한 층을 반복하고, 기존 숲마을/합본 마을 높이는 선택한 층수의 벽을 보존하며 지붕 몸통 조각을 반복한다. 최소/최대 크기는 실제 고스트와 하단 상태 문구에 표시한다.
