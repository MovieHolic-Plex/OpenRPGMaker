# 포켓몬과 다른 2D 게임의 월드맵 조사 (2026-10-04)

사용자 요청: 「포켓몬스터 느낌의 월드맵이나 다른 2D 게임들의 월드맵은 어떤지 조사」.
2026-10-04의 자료 조사와 당시 구현 대조다. 후속 2026-10-05에 여섯 이동 구조를 구현했다.
현재 도구·실제 맵·공용 자료·정본 증거는 [세계 지도 이동 구조](worldmap-navigation-structures.md).

## 조사 범위와 근거

도트 시절 포켓몬 루비·사파이어(GBA), FF VI Advance(GBA), 젤다 A Link to the Past(SNES),
Super Mario World(SNES), Hollow Knight, Slay the Spire **첫 작품**을 비교했다.
최신 3D 포켓몬이나 HD-2D 게임을 옛 2D 월드맵의 근거로 섞지 않았다.

공식 포켓몬 페이지의 포케내비 실제 화면과 설명을 브라우저에서 확인했다.
닌텐도 공식 설명서는 FF VI 인쇄 쪽 14–17, 마리오 5–6, 젤다 15–16·21–22의 실제 그림을 읽었다.
Hollow Knight와 Slay the Spire는 개발사 웹사이트·개발사 게시 Steam 설명을 사용했다.
이 문서의 도식·OPRN 제안은 아래 자료로부터 작성한 **설계 해석**이며 원작의 실제 지도 복제가 아니다.

## 먼저 구분할 것: 전도와 실제 이동 공간

「월드맵」이라는 말에는 서로 다른 물건이 들어간다.

- **전도 UI:** 플레이어 위치·지역 이름·마을·도로의 관계를 요약한다.
- **축소된 이동 필드:** 작은 도시·산 아이콘 사이를 캐릭터가 직접 걷는다.
- **장소/스테이지 선택 UI:** 연결된 거점 중 하나를 고르면 별도 맵으로 들어간다.
- **탐험 공간의 지도:** 실제 필드/방의 형태와 연결을 요약하고 방문·발견 상태를 표시한다.

하나의 게임이 이 중 여러 가지를 함께 가진다. 따라서 전도의 모양만 보고 실제 필드를 저작하면 안 된다.

## 포켓몬식: 지역 전도 + 마을·도로 필드

공식 포케내비 화면은 호연 지방의 땅·물 위에 마을과 길을 단순화해 표시한다.
옆 설명은 **마을·도로·수로의 전체 모습**, 확대 시 포켓몬센터 같은 시설 위치를 보여준다고 명시한다.
실제 모험은 이 전도와 별도의 필드에서 진행된다.
출처: [루비·사파이어 공식 도구 소개](https://www.pokemon.co.jp/game/gba/rs/item.html).

같은 공식 자료에는 마하 자전거가 급경사를, 다른 자전거가 좁은 다리·징검 단차를 통과한다고 나온다.
즉 이동 수단은 속도뿐 아니라 접근할 수 있는 공간과도 연결된다.
또한 111번 도로에서 기술을 얻은 뒤 여러 장소에 비밀기지를 만드는 활동이 소개된다.
출처: [공식 도구 소개](https://www.pokemon.co.jp/game/gba/rs/item.html),
[공식 모험 활동 소개](https://www.pokemon.co.jp/game/gba/rs/expectation.html).

**OPRN에 가져올 설계 해석:**

1. 전도에는 마을·도시, 번호/이름 있는 도로, 숲·동굴·수로, 현재 위치를 읽기 쉽게 표시한다.
2. 실제 필드는 사람 크기로 걷는 마을·도로 맵이다. 지역 연결과 필드 출입구가 같은 자료를 참조해야 한다.
3. 도로마다 포획 풀밭·안전한 길·트레이너·아이템·샛길 등 탐험의 이유를 둔다.
4. 체육관/배지 같은 진행 목표와 이동 능력을 연결하되, 모든 길을 일렬로 잠그지 않는다.
5. 초반에 본 막힌 길이 능력 획득 후 지름길·추가 포획 구역으로 열리게 한다.
6. 전도의 길은 필드 연결을 요약한다. 전도 픽셀 길이와 실제 필드의 칸 수를 1:1로 강제할 필요는 없다.

3–6은 제안이다. 모든 포켓몬 작품에 같은 규칙·순서가 있다는 주장은 아니다.
밝은 팔레트와 작은 집 그림만 적용해도 위 구조가 자동으로 생기지는 않는다.

## 실제 그림에서 보이는 차이

아래는 공식 화면·설명서 그림을 읽은 시각 관찰이다.

- **포켓몬 호연 전도:** 땅·물의 큰 색면에 길과 도시 표시를 얹는다. 건물 외형을 빽빽하게 그리는 대신
  어디와 어디가 연결되는지 읽기 쉽다. 확대된 도시도 시설을 작은 색 사각형으로 요약한다.
  [공식 포케내비 화면](https://www.pokemon.co.jp/game/gba/rs/item.html).
- **FF VI 오버월드:** 캐릭터 옆에 산줄기·초원·작은 거점이 함께 보인다. 도시 전체를 작은 입구 그림으로
  압축하고 들어간 뒤 사람 크기의 건물과 거리로 전환한다. [공식 설명서 14–15쪽](https://csassets.nintendo.com/noaext/image/private/t_KA_PDF/AGB_Final_Fantasy_VI?_a=BATCtdAA0).
- **젤다 전도:** 중앙 성, 북쪽 산, 숲·사막·호수처럼 실제 필드의 특징적인 위치와 형태가 지도에서도 유지된다.
  근접 지도와 전체 지도는 같은 세계의 서로 다른 확대 수준이다. [공식 설명서 21–22쪽](https://www.nintendo.co.jp/clvs/manuals/common/pdf/CLV-P-SAAEE.pdf).
- **마리오 지도:** 둥근 언덕·성·집이 배경의 성격을 전달하고, 굵은 길과 코스 지점이 이동 가능 경로를 드러낸다.
  배경의 빈 땅이 모두 걷는 칸이라는 뜻은 아니다. [공식 설명서 5–6쪽](https://www.nintendo.co.jp/clvs/manuals/common/pdf/CLV-P-SAAAE.pdf).

## 대표 6가지 비교

| 사례 | 전도/이동 구조 | 화면에서 읽을 핵심 | OPRN에 가져올 설계 해석 |
|---|---|---|---|
| 포켓몬 루비·사파이어 | 지역 전도와 실제 마을·도로 필드를 구분 | 마을, 도로, 수로, 시설 위치 | `region-routes`: 지역 연결을 먼저 설계하고 전도와 필드를 함께 만든다 |
| FF VI Advance | 직접 걷는 오버월드와 마을·던전 맵; 별도 작은 전도 | 대륙 지형, 거점 입구, 현재 위치 | `scaled-world`: 작은 거점 아이콘과 큰 대륙을 쓰는 현재 키트에 가장 가깝다 |
| 젤다 A Link to the Past | 실제 필드의 지형을 보여주는 근접/전체 지도 | 성·숲·호수 등 랜드마크, 현재 위치·목적지 | `field-overview`: 필드에서 자동으로 전도를 만들고 장비로 통과할 길을 연다 |
| Super Mario World | 연결된 코스 지점에서 스테이지를 선택 | 코스 지점, 연결 경로, 새로 열린 길 | `stage-nodes`: 클리어·비밀 출구에 따라 연결을 바꾼다 |
| Hollow Knight | 서로 이어진 탐험 공간과 지도 도구 | 지역·연결, 길 선택, 나중에 다시 볼 관심 지점 | `room-network`: 방 연결, 탐험 상태, 능력 조건, 표식을 표현한다 |

## 조사 당시 월드맵 키트와 대조 (2026-10-04)

확인한 코드:

- `tiledata/worldmap-kit/themes/monster.json`: `iconset: monster`, `palette: bright`, `kind: land`.
  자체 `terrain` 또는 `journey` 지정이 없다.
- `tiledata/worldmap-kit/kit/build_world.py`: 테마에 여정이 없으면 `fantasy-5act`를 사용한다.
- `openwiki/worldmap-terrain-editing.md`: 생성 구조에 5막 여정, 31곳, 장벽을 자동 맞춤한다.

따라서 **현재 `monster` 테마를 포켓몬식 월드맵 생성기의 완성으로 보지 않는다.**
현재의 대륙·길·거점 그림을 굽는 방식은 위 분류의 `scaled-world`에 가깝다.
포켓몬식 지역 전도↔도로 필드, 마리오식 비밀 출구, 방 탐험 지도까지 생성·동기화한다는 근거는 없다.
다른 기능에 포켓몬식 전투(`gen1`)가 있는 것과 월드맵 준비 상태는 별개다.

## 조사 당시 다음 구현 제안

**세계관**, **이동 구조**, **그림 표현**을 서로 다른 선택으로 다룬다.
예를 들어 몬스터 수집 세계관도 지역 도로형/축소 대륙형이 가능하고,
우주 세계관도 성계 항행형/행성 선택형/우주선 방 탐험형이 가능하다.
당시에는 위 이름이 제안 식별자였다. 후속 구현에서는 여섯 이름을 실제 `structure` 인자로 사용한다.

우선순위 제안:

1. **지역 도로형:** 포켓몬 느낌을 우선할 때. 지역·도로 연결→필드 출입구→전도 표시를 같은 자료에서 만든다.
2. **거점/스테이지형:** 마리오·우주 행성 선택 등에 쓰는 공통 연결·해금 표현을 만든다.
3. **축소 대륙형:** 기존 키트를 유지하면서 실제 지역 입장·탈것·해금과 연결한다.
4. 방 탐험 지도는 현재 탑다운 에디터에 맞춰 별도로 설계한다. Hollow Knight의 횡스크롤 플레이 재현을 뜻하지 않는다.

조수 검수도 「PNG가 나왔다」 외에 다음을 확인해야 한다(아직 실행한 결과가 아님).

- 전도에 표시한 도로와 실제 필드 출입구의 연결이 일치하는가.
- 초기 상태에서 첫 진행 목표에 도달하고, 필수 능력을 장벽 뒤에 잘못 두지 않는가.
- 능력 획득 뒤 새 길이 열리고 기존 마을로 돌아오는 동선이 생기는가.
- 탐험 표시·해금·출입구를 정본에 저장한 뒤 재로드해도 같은가.
