# 공용 칩셋 로드맵 — Phase · Wave (2026-10-08 시작)

조수 시험(space-craft·장르 시험)에서 「모델이 못 한 것」 중 상당수가 **칩셋·부품이 없거나, 있는데 조수가 못 찾는 것**이었다.
이 문서는 그 빈칸을 채우는 순서다. 진행할 때마다 표의 상태 칸을 고친다.

## 원칙 (어기지 않는다)

- 그림은 **칩셋마다 전용 하네스**로 만든다(`src/harnesses/<id>/`). 손 도트·3/4 시점·생성 이미지 금지(몬스터 예외).
- 후보는 작업자가 그리고 **사람이 고른다**. 감독자·검수자의 ✓ 는 보증이 아니다.
- 고른 것만 굽고, **공용 번들**(`src/assets/bundled.ts` + `ensureBundledTilesets`)과 **번들 참고문서**로 배선한다(AGENTS.md 「새 타일·타일 학습은 공용에」).
- 웨이브 끝마다 조수 시험(space-craft + 그림 판정자 + 사람 판정)으로 「조수가 실제로 쓰는가」를 잰다. 칩셋이 있어도 조수가 못 찾으면 없는 것과 같다.
- 동시에 도는 작업자(서브에이전트·하네스 작업자 합산)는 **최대 2**(사용자 지시 2026-10-08).

W1-A 진행(2026-10-08): 원인 하나 고침 0dd424c8f2 — 업로드 그림판(공용 기물 아틀라스 768px·48칸)에서 이식한 칸을 번들 기본 30칸으로 읽어 투명하게 그렸다. 이식에 소스 칸 배치를 적고, 헤드리스 렌더가 ref 자산을 프로젝트 폴더에서 읽는다. 1회차 GPT 편의점 저장본을 다시 그리면 냉장고·진열대 9·계산대가 있다(판정자 1.7점은 렌더 버그 탓).
조수 워커의 공용 참고 이미지 「fetch() URL is invalid」도 고침(워커가 공용 SQLite 에서 직접 읽음). 무림 수련장 1회차에서 목인장이 저장본에 없던 것도 같은 이식 버그다 — 조수가 찍은 목인장이 미리보기에 안 보이자 스스로 tile_erase 로 지웠다. W1-A 확인은 3회차 이후 재측정(새 빌드)으로.

웨이브 순서: **W1-A(기물이 보이게 — 그림 전에 길부터)** → W1-B 던전 → W1-C 필드·농장 땅 → W1-D 현대 실내(jp_city 하네스·roomKit 경로) → W1-E 판타지 특수 공간. 무림(Phase 2)은 W1 과 나란히 간다.
