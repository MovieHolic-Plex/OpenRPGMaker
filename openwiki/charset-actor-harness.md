## GIF 공방: AI 자유 저작과 사람 선택 (2026-10-04)

사용자의 현재 계약은 **AI가 자유롭게 제작하고 사람이 GIF를 보고 남기기/폐기만 결정**하는 것이다.
`studio.py`/`produce` → `free-worker.md`(GPT 6.1 sol high의 정지·걷기 12프레임 직접 저작) → 결손 검사 → GIF 대기열 → 사람 선택 → 공용 캐릭터/선택 팩이다.
기존 Sonnet 미감 점수로 새로운 자유 후보를 선별하지 않는다. `reviewMode: human`, `strength: free`를 manifest/각 행/후보 meta에 남긴다.

- `chr.gate(free)`는 구조·빈 프레임·색 키·내부 투명 결손·머리 내부 큰 삭제·경계 잘림만 자동 차단한다. 원본 변화율/모자·소품 돌출량/윤곽 명암은 사람에게 맡긴다.
- 현재 저작은 `animationMode: model-12`다. 네 방향의 정지 1과 걷기 0·2를 모두 모델이 직접 찍고 Python은 픽셀 검사·렌더·선택 저장을 한다. 새 `bulk`/`loop`는 전파를 호출하지 않는다.
- `human_ready`는 저작자 종료·현재 published/render binding을 확인한다. 부분 렌더를 사람 선택 대상으로 공개하지 않는다.
- `effective_decision`은 사람의 남김과 폐기를 본 그림 해시에 묶는다. 파일이 바뀌면 선택을 무효화하고 다시 검토한다.
- UI는 한 화면에 한 캐릭터만 보여주며 네 방향 걷기 GIF와 게임 속 이동 GIF를 상시 표시한다. 남기기/폐기는 즉시 다음 후보로 넘어가고 뒤에서 저장한다. A/R, 이전/다음, 직전 선택 되돌리기, 생성 개수/참고 시트, 진행·일시 정지/재개, 남김 ZIP을 제공한다. 주기 갱신은 기존 GIF DOM을 보존한다.
- `studio` 잠금으로 생성/재개/driver 기록을 직렬화하고 `briefs` 잠금으로 지시 목록의 동시 쓰기를 막는다. 산출 누락은 완료로 기록하지 않는다.
- 재개는 공개된 현재 GIF를 그대로 둔다. 일시 정지는 현재 묶음을 끝낸 다음 적용한다. 실패는 상태 파일에 남기며 자동 미감 재시도는 하지 않는다.
- `export_kept`는 사람의 최신 남김만 패킹하고 PNG를 에디터 색 키 ±8로 재읽는다. ZIP에는 GIF/격자/선택 해시/참고 원본/라이선스가 함께 간다. 작업자 설명은 독립 검수 설명과 구분한다.

### 버튼 반응과 저장 (2026-10-04)

화면은 HTML+JavaScript, 저장·생성은 Python API다. 남기기/폐기/되돌리기는 클릭 즉시 카드와 집계를 바꾸며
서버 응답이나 전체 목록 재조회를 기다리지 않는다. `저장 중 N건`과 실패 시 재시도 버튼으로 저장 상태를 알린다.

- 선택마다 고유 `mutationId`를 만들고 localStorage의 개별 키에 먼저 보관한다. 새로고침·네트워크 실패에도 같은 선택을 재전송한다.
- IndexedDB 전송자 잠금으로 같은 출처의 여러 탭이 한 순서로 전송한다. 각 응답은 해당 키만 지우며 탭 사이에 확인된 선택을 전달한다.
- 서버는 결정 잠금 안에서 journal을 fsync하고 같은 `mutationId`의 재시도를 중복 기록하지 않는다. 이미 기록한 응답을 재전송할 때도 최신 선택에 맞춰 accepted 사본을 복구한다. 오래된 남기기 재시도가 뒤의 되돌리기를 취소하지 않는다.
- 4xx는 실패한 선택 하나만 되돌려 재검토하게 한다. 뒤에 누른 되돌리기 등은 따로 검증·저장한다. 연결 실패·5xx는 선택을 보관하고 재시도한다. 미저장 선택이 있으면 다운로드를 기다린다.
- 늦게 도착한 목록 응답은 그 사이 확인된 선택을 덮지 않는다. GIF DOM·이미지 로드 확인은 격자/원본/강도/검사 버전 전체에 결부한다.
- 원본 PNG 파싱만 파일 경로·칸·mtime/ctime·크기로 캐시한다. 후보 격자 해시는 매번 읽고 원본 파일이 바뀌면 캐시도 무효화한다. 사람 선택은 한 후보의 accepted 파일만 동기화한다.

실측: 실행 중인 목록 API 약 1.5초 → 0.11~0.15초. 별도 저장 대상에서 POST를 1.2초 늦춰도 클릭 후 카드 변경은
8~26ms였다. 연속 선택·대기 중 되돌리기·409 뒤 후속 되돌리기 보존·오프라인 새로고침·재시도·늦은 목록·두 탭 동시 선택 등 브라우저 확인 13개를 통과했다.
격리 계약 확인 114개와 브라우저 근거는 데이터 폴더 `evidence/20261004-instant-actions/`에 있다. 실제 사용자 결정과 프로젝트 DB는 확인용으로 변경하지 않는다.

### 한 캐릭터 검토 화면 (2026-10-04)

- 모아 보기/보기 전환을 없애고 모든 탭·검색·실행에서 항상 카드 하나만 표시한다. 이전/다음과 방향키로 이동한다. 남기기/폐기한 카드는 즉시 제거한다. 전체 탭에서 마지막 하나를 선택해도 다음 주기 갱신 때 다시 나타나지 않으며 탭/검색/실행을 바꾸면 목록을 다시 탐색할 수 있다.
- 기존 `views/walk.gif`는 위·오른쪽·아래·왼쪽을 동시에 `0→1→2→1`로 걷게 한다. 방향 이름을 별도로 표시하고 크게 펼친다. `views/stroll.gif`(칸 위 실제 이동)도 접힌 상세 영역에서 꺼내 상시 표시한다. 같은 캐릭터의 두 GIF가 로드된 뒤 선택 가능하며 다음 후보의 두 GIF만 미리 불러온다. 픽셀·렌더 파일·선택 binding을 다시 만들지 않는다.
- 기존 개별 localStorage 선택 큐와 IndexedDB 전송 잠금을 그대로 쓴다. 선택 직후 렌더와 다음 후보 이동을 끝내고 journal/공용 게시를 기다리지 않는다. 직전 선택 되돌리기는 저장 중에도 clear를 별도 요청으로 추가하고 해당 후보를 검토 대기에 즉시 복원한다. 키를 계속 누르고 있을 때의 반복 keydown은 무시한다.
- 영구 거절(4xx)은 실패한 요청만 되돌리고 후속 선택을 보존한다. 네트워크/5xx는 후보를 숨긴 채 선택을 보관하고 뒤에서 재시도한다. 새로고침 뒤에도 미저장 선택은 같은 mutation으로 복구한다.

### 적대적 alpha QA와 검사 정책 2 (2026-10-04)

사용자가 투명색 결함을 다시 지적하여 자유 실행 `20261004-102326-free-c4f23ebb`의 100종·1,200프레임을
자홍색/짙은 회색 체커로 전부 펼쳐 보고 원본과 비교했다. 새로 닫힌 투명 공간은 흰색/검정에서도 따로 확대했다.
옛 게이트는 `enclosed(candidate) & opaque(base)`만 세어 **새 옷/장식 안에 원본 배경을 가둔 12종**을 모두 통과시켰다.

- 새 내부 구멍은 원본 불투명 면의 삭제와 `enclosed(candidate) - enclosed(base)`를 함께 검사한다. 원본부터 닫힌 팔/다리 공간은 보존하며 새로 만든 닫힌 투명 점은 1px도 차단한다. 열린 배경으로 이어져 flood fill이 놓치는 머리 틈은 원본 머리 면에서 윤곽 여유를 한 번 더 뺀 깊은 면의 삭제로 잡는다. 모든 해부학 결함을 자동 증명하는 검사는 아니다.
- `ALPHA_POLICY_VERSION=2`는 검사 캐시만 무효화한다. 이미지/선택 `GATE_VERSION=3` binding은 유지하므로 같은 그림에 대한 정상 사용자 선택·고정 자산 ID는 바뀌지 않는다. 실패한 후보는 `_items`, 새 ZIP, 공용 게시, accepted 동기화에서 제외한다. 사람의 선택 journal과 원본 격자는 보존한다.
- `views`가 실제 `sheet_rgba.png`, `alpha.png`, 12프레임 체커 `alpha_sheet.png`, `walk_checker/white/black.gif`를 추가한다. 진단 렌더는 별도의 `alpha-render.json`으로 현재 그림/원본 해시와 preview 버전에 결부한다. 기존 잔디 GIF를 덮지 않는다.

### 남김 → 공용 캐릭터와 설명 (2026-10-04)

- `harness.py prepare_shared_library`가 현재 기계 검사·공개 렌더·사람 선택의 전체 binding이 일치하는 자유 후보만 만든다. `publish-shared.mjs`는 기존 `publishSharedContent` API로 `~/.local/share/oprn/shared-content.sqlite`의 `charset-actor-kept` 한 행을 CAS 게시하고 같은 행을 재읽어 SHA-256을 확인한다. `OPRN_SHARED_CONTENT_SQLITE`로 저장 대상을 바꿀 수 있다. 실행 중 프로젝트 DB를 직접 수정하지 않는다.
- 기존 남김은 API 시작 때, 새 선택은 journal fsync 뒤 결정 잠금 안에서 등록한다. 등록 실패는 5xx와 `shared-library-error.json`으로 알린다. 브라우저의 기존 저장 큐가 같은 mutation을 재전송하고 최신 전체 남김을 등록한다. 뒤에 폐기한 후보를 오래된 남김 재시도로 되살리지 않는다. `publish-shared` CLI도 같은 결정 잠금을 쓴다.
