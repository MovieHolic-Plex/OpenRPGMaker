# pxgrid — 픽셀을 직접 놓는 작도 도구 (도트 품질 하네스: 그리는 방식)

## 왜 만들었나
지금까지 손 도트(`tiledata/hand-interior/v5`, `refmap-study/drawr.py·propsr.py`)는 파이썬 **수식**으로 칠했다.
`_ramp()` 로 색 줄을 보간하고, `fill(…, lambda x,y,u,v: 0.60 - 0.16*v)` 처럼 상자에 선형 그라디언트를 깔고,
`cyl()`·`dome()` 로 명암을 계산하고, `H()` 해시 잡음·`grain()` 사인파로 결을 넣었다. 그 결과
- 명암이 **같은 간격의 계단 띠**가 된다(값을 12단으로 끊으니 띠 폭이 면 크기 ÷ 단 수로 고르다).
- 결이 **고른 잡음**이 된다(해시 잡음은 어디서나 밀도가 같다).
- 윤곽이 `outline()` 한 번으로 사방 같은 규칙이 되어 모양마다 다른 판단이 없다.

REFMAP 같은 상용 팩은 사람이 덩이(cluster)를 하나씩 놓은 그림이다. 이 도구는 그 방식을 강제한다:
**그라디언트·노이즈·도형 채우기 함수가 없다.** 할 수 있는 것은 글자를 한 칸씩 놓는 것뿐이다.

## 칸 크기: 48px (2026-09-29 사용자 결정)
목표 해상도는 **48px**(REFMAP·RPG Maker MV 와 같다). `pxgrid` 기본 칸은 48이고, 파일에 `@cell 32` 를 적으면 32px 판도 그대로 된다
(캔버스가 칸의 배수가 아니면 오류). 지난 32px 시험은 `trials32/`, 48px 시험은 `trials/`.

## 격자 형식

### 팔레트 `*.pal`
```
@ramp oak 1 2 3 4 5 6 7 8 9     // 램프(어두운→밝은). 점검(단 수·윤곽 비)에만 쓴다
1 #221619                        // 글자 하나 = 색 하나
~ #1c1418 110                    // 세 번째 값 = 알파(0~255). 반투명 그림자
```
- `.` 과 `_` 는 예약이다(`.` = 이 층에서 비움/아래 그대로, `_` = 지우기). 공백 금지. 주석은 `//`.
- 색은 **손으로 고른다.** 램프를 식으로 만들지 않는다. 어두운 끝은 붉은 보라 쪽, 밝은 끝은 누런 쪽으로 옮기고 몸통 채도는 0.2~0.3.
- 공용 팔레트: `palettes/interior.pal`(참나무 1~9, 소나무 a~h, 쇠 i~m, 그림자 `~` `-`, 실루엣 표시색 `#`).

### 격자 `*.pxg`
| 지시 | 뜻 |
|---|---|
| `@size W H` | 캔버스(칸의 배수) |
| `@cell N` | 칸 크기(기본 48). `@base` 는 앞 단계의 칸 크기를 물려받는다 |
| `@palette 경로` | 팔레트(이 파일 기준 상대 경로) |
| `@base 앞단계.pxg` | 앞 단계의 층·조각을 그대로 불러와 그 위에 고친다 |
| `@tile` | 이어 붙이는 타일(점검이 가장자리를 반대편과 잇는다) |
| `@layer 이름` | 그릴 층을 바꾼다. 층은 만든 순서로 아래→위 합성(예: `shadow` 를 먼저 만들면 밑에 깔린다) |
| `@block X Y` + 격자 줄 | (X,Y)부터 줄을 붙인다. 줄 끝 ` *N` = 그 줄 N번. `.` 은 건드리지 않음 |
| `@def 이름` … `@end` | 이름 붙인 조각(판자 한 장, 다리 하나) |
| `@stamp 이름 X Y [NX NY DX DY]` | 조각 붙이기(반복 격자 선택) |
| `@mirror 이름 X Y` | 조각을 좌우 뒤집어 붙이기 |
| `@px X Y C [X Y C …]` | 한 칸씩 찍기 |
| `@symx L R` | 현재 층의 열 L..R 왼쪽 반을 오른쪽에 거울 복사. **실루엣·평면 단계에만.** 명암은 빛이 왼쪽 위라 대칭이 아니다 |

격자 한 줄 = 픽셀 한 행, 한 글자 = 한 픽셀. 칸 경계는 x·y 가 칸 크기의 배수.
`=` 로 시작하는 줄은 「개수+글자」 토큰 표기다: `= 5. 86# 5.` = 점 5 · `#` 86 · 점 5. 긴 같은 색 줄을 세기 쉽게 적는 것뿐이고 색을 계산하지 않는다
(숫자 글자 색도 된다: `867` = 글자 `7` 86개).

### 명령 (저장소 루트)
```
python3 scripts/content/pixel-harness/pxgrid/pxgrid.py render FILE.pxg [-o OUT.png]  # OUT.png + OUT-x4.png + OUT.txt(평탄화 격자)
python3 scripts/content/pixel-harness/pxgrid/pxgrid.py check  FILE.pxg               # 자기 점검 수치
python3 scripts/content/pixel-harness/pxgrid/pxgrid.py tile   FILE.pxg OUT.png [N]   # 타일 N×N 반복 4배
python3 scripts/content/pixel-harness/pxgrid/build.py [시험…]                        # 시험 전부 굽기
python3 scripts/content/pixel-harness/pxgrid/copycheck.py                            # REFMAP 화소 복사 검사
```
`OUT.txt` 는 층을 합친 현재 격자다. 다음 단계를 쓰기 전에 이 파일을 읽어 좌표를 확인한다.

### 램프 격자 (48px 칠한 도트, 2026-09-29 p48-style)
한 글자 = 한 색 팔레트로는 재료 14단 × 수십 재료를 못 담는다. 긴 램프는 「재료:단」 열쇠로 들어가고 격자에는 **재료 글자**와 **단 글자**를 따로 놓는다.
여전히 보간·난수·도형 채우기는 없다 — 단을 손으로 놓는 표기일 뿐이다. 공통 팔레트 `tiledata/px48/palette/px48.pal`, 규칙 `tiledata/px48/STYLE.md`.

| 지시 | 뜻 |
|---|---|
| (팔레트) `@rampc 이름 #hex #hex …` | 재료 램프(0 = 가장 어두움). 열쇠 `이름:0` … `이름:e` |
| `@mat 글자 램프 [기본단]` | 재료 글자. 기본단 `10` 같은 두 자리는 `a` 로 읽는다 |
| `@mblock X Y [only=재료,…]` + 줄 | 글자 = 재료. 이미 단이 칠해진 칸은 **단을 지키고 재료만** 바꾼다(곁 램프 `_r` 섞기). 빈 칸은 기본단 |
| `@tblock X Y [램프\|only=…]` + 줄 | 글자 = 단(`0`~`9` `a`~`e`). 램프를 안 주면 그 칸 재료의 단만 바꾼다 |
| `@tadj X Y [only=…]` + 줄 | 단 옮김: `+` `^` `*` 한·두·세 단 밝게, `-` `v` `x` 한·두·세 단 어둡게. 재료 끝에서 멈춘다 |
| `@tstamp`·`@tmirror`·`@mstamp`·`@astamp 조각 X Y [램프\|only=…]` | `@def` 조각을 단·단(뒤집기)·재료·옮김 격자로 찍는다 |
| `only=재료,재료` | 그 재료가 칠해진 칸만 건드린다(통의 쇠테는 두고 통널만 결 넣기) |

`@tile` 문서에서는 램프 격자도 가장자리를 넘으면 반대편으로 감긴다(바닥·풀·물 조각을 경계에 걸쳐 찍을 수 있다). `OUT.txt` 는 램프 칸을 단 글자로 적는다.
기준 조각: `tiledata/px48/ref/{floor,table,barrel,wall,grass,water}/`.

## 단계형 작도 흐름
단계마다 **파일을 따로 남긴다**(`1-silhouette.pxg` … `5-clean.pxg`, 2단계부터는 보통 `@base` 로 앞 단계를 불러 덧칠).
단계를 굽고 **4배 렌더(`-x4.png`)를 열어 본 뒤** 점검표를 통과해야 다음 단계로 간다. 되돌아가도 된다 — 구조 문제는 1단계에서 고친다.

| 단계 | 하는 일 | 넘어가기 전 점검 |
|---|---|---|
| 1 실루엣 | `#` 한 색으로 모양만. 칸 격자 정렬, 발 칸, 시점(낮은 가구는 윗면 ~¾, 키 큰 가구는 앞면) | 한 색으로도 무엇인지 읽히는가. 곡선의 계단 규칙(아래) |
| 2 평면 색 | 부위마다 재료 몸통 한 색. 드리운 그림자 층(오른쪽 아래, 반투명 두 단) | 부위 구분이 색만으로 되는가. 면적이 큰 면이 가장 밝은가 |
| 3 빛(왼쪽 위) | 윤곽(재료 어두운 단), 빛 쪽 테 바로 안 밝은 줄, 그늘 쪽 어둡게, 원통·구는 밝은 덩이를 왼쪽으로 | **베개 명암 없음**, 윤곽 비, 램프 단 수 |
| 4 재질 결 | 판 이음, 나뭇결, 쇠테 못, 옹이. 결은 재료 방향으로 드물게, 길이를 섞어서 | 결이 고른 점박이가 아닌가. 같은 폭 띠가 없는가 |
| 5 정리 | 외톨이 치우기, 곡선 모서리 안티앨리어싱(중간 톤 한 칸), 너무 곧게 그은 밝은 줄 끊기, 윤곽 비 맞추기 | `check` 수치 + 4배 눈 검사 |

### 자기 점검표 (모든 단계에서 확인)
1. **외톨이 픽셀** — 8이웃에 같은 색이 없는 칸. 못·리벳·반짝임처럼 뜻이 있는 한 칸만 남기고, 나머지는 이웃 덩이에 붙이거나 지운다(`check` 가 좌표를 준다).
2. **베개 명암 금지** — 가장자리를 사방으로 어둡게 하고 가운데를 밝게 하면 빛이 없는 쿠션이 된다. 빛은 왼쪽 위: 위·왼 테 바로 안은 밝게, 아래·오른은 어둡게. `check` 의 「가장자리 바로 안 한 줄/속」에서 빛 쪽 > 1, 그늘 쪽 < 1 이어야 한다.
3. **선 계단 규칙** — 비스듬한 선과 곡선은 한 줄의 계단 길이가 고르게 늘거나 준다(1-1-1, 2-2-2, 1-2-3-3-2-1). 1-3-1 처럼 들쭉날쭉하면 깨진 선으로 보인다. 1차 식탁에서 오른 앞 그늘을 3·4·3 계단으로 깔았다가 돌계단처럼 보여 지웠다.
4. **램프 단 수** — 재료 하나에 32px 에서 3~7단. 3단 미만이면 입체가 안 서고 8단을 넘으면 띠가 흐려진다. 바닥은 조용하게 4~5단, 가구는 대비를 크게.
5. **윤곽 = 그 재료의 어두운 색, 밝기 약 0.6배** — 검정 금지. 아래·오른 테가 위·왼 테보다 어둡다. `check` 목표: 위·왼 0.65~0.85, 아래·오른 0.55~0.65.
6. **같은 폭 띠 금지** — 한 줄에서 색 바뀌는 간격이 계속 같으면 수식처럼 보인다. 덩이 크기를 1·2·3·5 로 섞는다(`check` 가 센다).
7. **최종본에 실루엣 표시색 `#` 이 남지 않는다.**

## 48px 시험 (2026-09-29, 지난 32px 판 약점 고침)
- **식탁 96×96**: 결을 한 단(7→6)만 어둡게 20~40px 길이로, 10~20px 마다 1px 옆으로 흐르게 — 짧은 긁힘이 사라졌다. 판 여섯, 판 무늬 셋을 좌우 뒤집어 섞음(`@def`/`@mirror`).
  다리 8px 폭. 윗면(밝기 약 147)을 마루(약 95)보다 두 단계 밝게 해 장면에서 떨어져 보인다.
- **통 48×48**: 뚜껑을 누런 새 나무에서 바랜 회갈(A~F)로, 테 안으로 들어간 오목(뒤·왼 그늘) + 판 이음 두 줄 + 마개. 테는 계단 3·5·20·5·3 으로 휜다(32px 판은 2단 꺾임이라 부러져 보였다).
- **마루 48×48 변형 셋**: 판 12px, 판 색은 한 줄에서 세 변형이 같다(경계에서 판이 이어지게). 이음은 변형마다 한두 판에만, 옹이는 B 한 장에만, 결은 가장자리에 닿지 않는다.
  섞어 깔면 판이 두세 칸 길이로 읽히고 벽돌 느낌이 없다.
- **REFMAP 과 비교해 아직 모자란 것**: ① 면 안이 한 색이다 — REFMAP 은 판마다 명암이 조금씩 다르고 한 면 안에서도 부드럽게 흐른다(붓 질감). 우리는 결 한 단과 테 밝은 줄뿐이라 평평하다.
  ② 판 이음·통 테가 REFMAP 보다 진하고 굵다. ③ 통 실루엣이 달걀꼴이 아니라 각진 상자에 가깝다. ④ 마루 결이 모두 곧은 가로 대시라 판마다 비슷하다.
  ⑤ 반투명·중간 톤이 거의 없다(REFMAP 반투명 화소 14%, 우리는 그림자뿐).
- REFMAP 복사 검사(`copy-check.json`): 48px 판 8칸 — REFMAP 48px 칸 2348개와 그대로·둘 다 32로 줄여서 모두 **같은 칸 0 · 95% 이상 0 · 90% 이상 0**, 최대 닮음 0.37. 32px 판 6칸도 0(최대 0.50).

## 32px 시험 (2026-09-29 1차, `trials32/`)
- **식탁**: 윗면이 높이의 ¾(y2~45), 앞 두께 5px, 앞다리 둘. 판 넷의 세로 이음 + 드문 세로 결 + 옹이 하나.
  v5 식탁(16px 평면 판)보다 판자·결이 읽히지만 윗면이 넓고 평평해 심심하고, 결이 짧은 대시로 흩어져 「긁힌 자국」처럼 보이는 곳이 있다. 다리가 가늘다.
- **통**: 원통 명암(밝은 덩이가 가운데보다 왼쪽, 띠 폭 섞음), 가운데가 아래로 휜 쇠테 셋, 통널 이음(바깥 이음은 부푼 가운데에서 1px 바깥으로 휜다), 연 뚜껑.
  셋 중 가장 낫다. refmap-study 통(수식)보다 테와 널이 또렷하다. 뚜껑이 누렇게 평평하다.
- **나무 마루**: 판 8px 넷, 이음은 두 판에만(모든 판에 이음을 두면 31px 벽돌로 읽혔다 — 1차 실패), 결 하나는 타일 경계를 넘어간다.
  조용하고 이음매 없지만 32px 한 장이라 옹이가 32px 마다 되풀이된다. 칩셋에서는 변형 2~4장을 섞어야 한다.
