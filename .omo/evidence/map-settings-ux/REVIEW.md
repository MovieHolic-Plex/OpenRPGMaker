# 맵 설정 적대적 리뷰 — 2026-09-05

실제 편집기에서 맵 트리를 더블클릭하여 확인했다. 원격 게임 콘텐츠를 변경하는 작업이 아니라 맵 설정 편집기 코드 개선이다. 다른 모델이나 하위 에이전트를 호출하지 않았다.

| 우선순위 | 문제 | 원인·영향 | 수정 |
| --- | --- | --- | --- |
| P2 | 맵 이름이 헤더 밑에서 잘림 | 내용에 밀려 헤더가 줄어듦. 어느 맵을 편집하는지 놓침 | 맵 전용 헤더 크기·줄 높이 확보 |
| P2 | 작은 글자와 큰 빈 공간 | 10~11px 설명, 서로 높이가 다른 2열 카드 | 고정 내비 + 한 열 본문, 제목 18px·설명/라벨 13px 이상 |
| P2 | 배경 체크박스가 라벨과 분리되고 커짐 | 연결 없는 label, 공용 input 최소 높이 | 클릭 가능한 체크 행, 18px 체크박스, 연결된 폼 라벨 |
| P1 | 토글하면 다른 미완성 입력을 잃음 | 전체 창 DOM 교체 | 변경한 섹션만 갱신, 미적용 JSON/펼침/초점/스크롤 복원 |
| P2 | 배경을 ID로 직접 입력해야 함 | 리소스 탐색·미리보기 경로 없음 | 현재 이름 + 검색/미리보기 선택기 |
| P1 | 크기 축소의 결과를 알 수 없음 | 검증 없이 즉시 적용 | 범위·정수 검사, 손실/위치 이동 안내와 축소 확인 |
| P1 | 연속 편집의 앞선 값이 덮일 가능성 | 렌더 당시 객체 참조 사용 | 제한 플래그·BGM·배경 이동에 최신 store 값 사용 |
| P2 | 빈도 슬라이더와 숫자가 서로 다름 | 슬라이더 상한 40, 숫자 상한 100 | 0~100으로 통일 |
| P2 | 미니맵 설명에 내부 구현 계획이 노출됨 | fog v1 안내, 실제 설정과 다른 참고 썸네일 | 구현 계획 삭제, 참고 이미지의 범위 명시·240×180px 이내 표시 |

추가 시각 리뷰에서 가중치 입력의 `width:100%` 우선순위가 적 그룹 선택과 삭제 버튼을 밀어내는 문제를 발견했다. 숫자 입력을 명시한 CSS 선택자로 너비를 고정하고, 실제 출현 행의 모든 컨트롤이 카드 안에 들어오는지 브라우저 기하 검증을 추가했다.

검증 명령과 최종 결과는 PR 설명에 기록한다. 스크린샷은 같은 변경의 `.superpowers/sdd/qa-shots/map-settings-ux/`에 포함한다. 자동 생성한 전체 캡처는 `output/evidence/map-settings-ux/`에 남긴다.

## 전체 게이트와 수정 전 대조

`npm run gates`는 exit 1이다. 단위 테스트 12,650개 통과 / 221개 실패이고, 저장된 기준선 대비 실패 파일 34개와 공용 표면/CSS 실패가 보고됐다. 전체 게이트가 초록이라고 보고하지 않는다.

수정 전 `7167ae65`의 격리 작업 사본과 수정본에서 해당 34개 파일을 각각 `--maxWorkers=4`로 재실행했다. 수정 전 218 통과/27 실패, 수정본 217 통과/28 실패이며 **실패 26개가 같은 테스트 이름으로 재현**됐다. 수정본에만 남은 2개 중 클립보드 테스트는 기본 제한의 분리 재실행에서 통과했다. 마을 시공 테스트는 15초 제한에 걸렸고, CLI 제한만 60초로 늘린 단독 실행에서 16.8초 만에 통과했다. 테스트 소스나 저장된 게이트 기준선은 변경하지 않았다.

공용 표면 게이트도 수정 전 사본에서 직접 실행해 동일한 6개 스냅샷 실패와 `.selected`의 `bottom` 소실을 재현했다. 맵 설정 변경의 추가 기능 회귀는 집중 재검증에서 관측되지 않았지만, 저장소 전체 게이트는 기존 실패와 실행 시간 민감성 때문에 빨간 상태로 남는다. 기계 판독 근거는 [GATES.json](GATES.json).
