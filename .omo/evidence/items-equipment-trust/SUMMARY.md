## 브라우저 증거

Firefox, 기본 카탈로그를 포함한 `?blankProject=1` 테스트 세션. 1024×768, 1280×800, 1440×900에서 실제 DOM 조작과 화면 측정. 테스트 세션의 원격 저장은 꺼져 있으며 원격 저장 성공 증거로 사용하지 않는다.

| 화면 | 아이템 전체 본문: 전 → 후 | 장비 전체 본문: 전 → 후 |
|---|---:|---:|
| 1024×768 | 2,045 → 1,318px | 3,254 → 916px |
| 1280×800 | 1,504 → 1,001px | 2,308 → 796px |

접힌 초기 상태 기준이다. 고급 카드를 열면 길이가 늘어난다. 장비의 네 능력치 입력은 첫 화면에 보이며 가로 넘침과 페이지 오류가 없다. `before/`와 `after/`의 같은 이름 PNG를 비교하면 된다.

## 검증

- 최신 main `7e2e0242`에 통합한 코드로 집중 검증 **11파일 100테스트 통과** (`focused-tests.log`). 상태 변화·전투 연출·돌봄 편집과 필드 상태 부여도 포함한다.
- Firefox E2E **통과** (`browser.log`): 3개 화면 크기, 사용 시점/소모/대상 요약 동기화, 포획에서 보관된 스킬 효과 제외, 상태 변화와 돌봄 편집.
- 최종 앱 타입 검사 통과. 전체 게이트의 CSS 예산·그래프 통과.
- 전체 `npm run gates`는 **exit 1**: 13,069개 중 12,881 통과 / 173 실패 / 15 건너뜀. 이 수치는 마지막 v3 호환성 수정 전의 전체 실행 결과이며 전체 스위트를 다시 실행하지 않았다 (`gate-result.json`).
- 추적 기준선에 없던 실패 파일 18개를 깨끗한 main `7e2e0242`에서 재실행했다. 실패 assertion 24개는 main에서도 동일했다. 표면 스냅샷 6개와 공용 CSS `.selected/bottom` 실패도 main과 일치한다 (`final-comparison.json`, `surface-comparison.json`). 기준선 파일은 변경하지 않았다.
- 실제 새 회귀 1개는 종류가 없던 v3 스킬 아이템이었다. `normalizeItemRecord`에서 종류가 없는 경우에만 special을 추론하도록 수정했다. 명시된 종류를 덮어쓰지 않는다. 수정 후 전투·아이템 계약 테스트와 마이그레이션·직렬화 38개가 통과했다. 관련 로그는 `final-regression.log`, `migration-tests.log`.
- 붙여넣기 테스트의 일시 실패는 별도 재실행에서 12개 모두 통과했다. 추가로 검사한 `io.test.ts`의 빈 프로젝트 왕복 실패는 깨끗한 main에서도 동일하게 재현됐다. 변경으로 인한 미해결 회귀는 확인되지 않았다.
