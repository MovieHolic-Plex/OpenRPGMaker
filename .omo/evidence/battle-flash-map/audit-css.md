# Battle flash / map exposure CSS audit

## Scope and conclusion

Audited every CSS file under `src/styles/runtime/battle/` and `src/styles/runtime/battle-skins/`, plus `src/styles/runtime/playSurface.css` and `src/styles/runtime/system.css`. The normal scene root is a 640x480 opaque black box scaled to the play surface (`src/styles/runtime/battle/01-scene-base.css:66`, `src/styles/runtime/battle/01-scene-base.css:68`, `src/styles/runtime/battle/01-scene-base.css:77`). The outer play stage is also black, but the Phaser map canvas is inside that stage and below the battle scene, so its background does not mask holes in a moved/translucent battle root (`src/styles/runtime/playSurface.css:53`, `src/styles/runtime/playSurface.css:54`).

There are exactly two exposure mechanisms in the audited CSS:

1. Hit/critical animation classes animate the `.battle-scene` root's own `background-color` to alpha colors and then `transparent` (`src/styles/runtime/battle/06-damage-flash-targeting.css:98`, `src/styles/runtime/battle/06-damage-flash-targeting.css:106`, `src/styles/runtime/battle/06-damage-flash-targeting.css:119`). CSS animation-origin declarations override the root's normal opaque `background: #000`, so map pixels can show through the entire scene (`src/styles/runtime/battle/01-scene-base.css:77`).
2. Screen shake animates `transform` on the root and translates its full-size backing away from the viewport edges, exposing thin map strips on the opposite edges even though every keyframe preserves `scale(var(--battle-stage-scale))` (`src/styles/runtime/battle/04-anim-damage-layers.css:111`, `src/styles/runtime/battle/06-damage-flash-targeting.css:133`).

No audited rule sets or animates `opacity`, `visibility`, or `mix-blend-mode` on the `.battle-scene` element itself. No static battle-skin root background is translucent; the skin roots use opaque colors/gradients, with the final Pokemon override also opaque (`src/styles/runtime/battle/18-pokemon-layout-redesign.css:8`, `src/styles/runtime/battle/18-pokemon-layout-redesign.css:10`).

## MUST CHANGE

Ordered by severity:

1. **Whole-scene backing transparency (full-surface exposure):** remove or neutralize the root animation declarations `.battle-flash-critical { animation: battle-flash-crit ... }` and `.battle-flash-hit { animation: battle-flash-hit-anim ... }` (`src/styles/runtime/battle/06-damage-flash-targeting.css:98`, `src/styles/runtime/battle/06-damage-flash-targeting.css:102`). Their referenced keyframes must not animate the root's `background-color` to alpha/transparent (`src/styles/runtime/battle/06-damage-flash-targeting.css:106`, `src/styles/runtime/battle/06-damage-flash-targeting.css:119`). The existing child overlay implementation already owns all four flash classes and is the safe replacement (`src/styles/runtime/battle/15-juice-capture-fx.css:7`, `src/styles/runtime/battle/15-juice-capture-fx.css:18`).
2. **Whole-scene translation (edge-strip exposure):** do not shake the only opaque backing via `.battle-scene.battle-screen-shake` (`src/styles/runtime/battle/04-anim-damage-layers.css:111`). The nonzero root translations at 25%, 50%, and 75% expose opposite-edge strips despite correctly preserving stage scale (`src/styles/runtime/battle/06-damage-flash-targeting.css:134`, `src/styles/runtime/battle/06-damage-flash-targeting.css:138`, `src/styles/runtime/battle/06-damage-flash-targeting.css:142`); shake a child visual layer or provide a stationary opaque backing instead.

No other audited CSS belongs in MUST CHANGE: the root has no opacity/visibility/blend animation, static root backgrounds are opaque, and the other root transform animation preserves/increases the required scale (`src/styles/runtime/battle/05-poses-motion.css:106`).

## SAFE BY DESIGN

These flash/brighten rules are scoped to a child or pseudo-element and cannot make the scene root backing transparent. They should not be removed as part of this fix.

- **Canonical battle-field flash overlay:** hit, critical, victory, and defeat render on `.battle-field::after`, positioned over the field (`src/styles/runtime/battle/15-juice-capture-fx.css:7`, `src/styles/runtime/battle/15-juice-capture-fx.css:12`). Their alpha backgrounds and `battle-flash-fade` opacity animation affect only that generated overlay, while the root remains opaque (`src/styles/runtime/battle/15-juice-capture-fx.css:18`, `src/styles/runtime/battle/15-juice-capture-fx.css:23`).
- **Animation-authored full-screen flash overlay:** `.battle-scene.battle-screen-flash::before` animates a generated pseudo-element rather than the root's background/opacity (`src/styles/runtime/battle/05-poses-motion.css:175`, `src/styles/runtime/battle/05-poses-motion.css:176`). `@keyframes battle-screen-flash` changes only that pseudo-element's opacity (`src/styles/runtime/battle/06-damage-flash-targeting.css:151`).
- **Target-only screen-blend flash:** `.battle-animation-target-flash::after` owns both the translucent flash background and `mix-blend-mode: screen`; neither property is placed on `.battle-scene` (`src/styles/runtime/battle/05-poses-motion.css:154`, `src/styles/runtime/battle/05-poses-motion.css:160`). Its reduced-motion opacity is likewise pseudo-element-only (`src/styles/runtime/battle/05-poses-motion.css:167`).
- **Hit-stop field brighten:** normal and critical hit-stop filters target the `.battle-field` child, not the root backing (`src/styles/runtime/battle/05-poses-motion.css:97`, `src/styles/runtime/battle/05-poses-motion.css:100`). The accompanying root pulse preserves/increases `--battle-stage-scale` at every step and therefore does not expose edges (`src/styles/runtime/battle/05-poses-motion.css:106`).
- **Battler juice hit/critical flashes:** `.battle-juice-hit` and `.battle-juice-critical` brighten/transform the target battler supplied by `emitBattleJuice`, not the scene root (`src/styles/runtime/battle/05-poses-motion.css:112`, `src/styles/runtime/battle/05-poses-motion.css:124`). The runtime damage call passes `targetNode`, confirming child scope (`src/player/battleDom.ts:225`).
- **Battler pose/motion brightening:** hit-pose and knockback filters are on `.battle-actor`/`.battle-enemy` descendants (`src/styles/runtime/battle/05-poses-motion.css:6`, `src/styles/runtime/battle/05-poses-motion.css:50`). Pokemon-specific hit and knockback overrides remain descendant-only (`src/styles/runtime/battle/14-pokemon-skin-layout.css:275`, `src/styles/runtime/battle/05-poses-motion.css:82`).
- **Target selection flashes:** `oprn-target-flash` and `oprn-target-select-pulse` contain brightness filters, but their consumers are targeted child elements rather than the scene root (`src/styles/runtime/battle/07-640-scene-turn-ribbon.css:24`, `src/styles/runtime/battle/06-damage-flash-targeting.css:162`). Pokemon target blink is even narrower: `.battle-enemy-image` only (`src/styles/runtime/battle/18-pokemon-layout-redesign.css:171`, `src/styles/runtime/battle/18-pokemon-layout-redesign.css:174`).
- **Defend brighten:** `battle-juice-defend` changes brightness/drop-shadow on the selected target element only (`src/styles/runtime/battle/17-sprint-a-polish.css:72`, `src/styles/runtime/battle/17-sprint-a-polish.css:75`).
- **Death/faint brighten and fade:** `battle-death-fade` and `pkmn-battler-faint` change opacity/filter only on defeated enemy/image descendants, not on the scene backing (`src/styles/runtime/battle/15-juice-capture-fx.css:44`, `src/styles/runtime/battle/15-juice-capture-fx.css:49`, `src/styles/runtime/battle/19-adversarial-review-3.css:9`, `src/styles/runtime/battle/19-adversarial-review-3.css:13`).
- **Intro fades:** `battle-intro-field` fades `.battle-field`, and the other intro opacity animations target enemies, actors, and panels; the root remains opaque throughout (`src/styles/runtime/battle/02-intro-reveal.css:8`, `src/styles/runtime/battle/02-intro-reveal.css:25`).
- **Mother backdrop color cycling:** `mother-swirl` applies hue/saturation/contrast to `.battle-backdrop`, a child, and does not alter root alpha (`src/styles/runtime/battle-skins/_mother.css:28`, `src/styles/runtime/battle-skins/_mother.css:32`).
- **Skin transition flashes:** `skin-flash` fades `.battle-transition-flash` inside the separate transition overlay, not `.battle-scene`; when transparent it reveals the still-opaque battle scene rather than the map (`src/styles/runtime/battle-skins/_transitions.css:6`, `src/styles/runtime/battle-skins/_transitions.css:10`). Other translucent/sweeping transition declarations are likewise confined to `.battle-transition-overlay` or its children (`src/styles/runtime/battle-skins/_transitions.css:7`, `src/styles/runtime/battle-skins/_transitions.css:13`).
- **Result dimming:** result brightness targets `.battle-backdrop`, while hidden/transparent result UI consists only of command/enemy/party child panels; the result root itself is explicitly black (`src/styles/runtime/battle/09-keyboard-result-panel.css:120`, `src/styles/runtime/battle/09-keyboard-result-panel.css:128`, `src/styles/runtime/battle/09-keyboard-result-panel.css:132`).

## Audit guardrails checked

- Root backing baseline: opaque `background: #000`, fixed 640x480 logical size, and `scale(var(--battle-stage-scale))` (`src/styles/runtime/battle/01-scene-base.css:66`, `src/styles/runtime/battle/01-scene-base.css:68`, `src/styles/runtime/battle/01-scene-base.css:77`).
- Root alpha/blending: no `.battle-scene` rule in the audited scope declares `opacity`, `visibility`, `mix-blend-mode`, or `backdrop-filter`; the only root-affecting alpha declarations are the animated `background-color` keyframes reached through generic flash classes (`src/styles/runtime/battle/06-damage-flash-targeting.css:98`, `src/styles/runtime/battle/06-damage-flash-targeting.css:106`).
- Root box shrinkage: `battle-hit-stop-pulse` retains or increases `--battle-stage-scale`, and all `battle-screen-shake` keyframes retain it; no audited root keyframe drops the scale term (`src/styles/runtime/battle/05-poses-motion.css:106`, `src/styles/runtime/battle/06-damage-flash-targeting.css:133`). The shake still exposes edges through translation, as listed in MUST CHANGE (`src/styles/runtime/battle/06-damage-flash-targeting.css:135`).
- Static skins: root backgrounds found in battle skins are opaque colors or an opaque conic gradient; representative first/final cascade declarations are `background: #000` and Pokemon `background: #14181f` (`src/styles/runtime/battle/07-640-scene-turn-ribbon.css:49`, `src/styles/runtime/battle/18-pokemon-layout-redesign.css:10`).
- Global files: `system.css` only applies typography/image-rendering to `.battle-scene`, not alpha or geometry (`src/styles/runtime/system.css:78`, `src/styles/runtime/system.css:89`); `playSurface.css` scales the containing `.play-stage` but does not animate it or make it translucent (`src/styles/runtime/playSurface.css:53`, `src/styles/runtime/playSurface.css:60`).
