# showPictureForm 실패 귀속 — 추적 기록

`npm run gates` 가 4개 파일을 "새로 실패"로 지목했다. 그중 `test/showPictureForm.test.ts` 는
내 base 대비 새로 깨진 것으로 보였다. 결론부터: **내 변경이 원인이 아니었다.**

## 추적 과정

| 단계 | 방법 | 결과 |
| --- | --- | --- |
| 1 | base(`aac023090`) vs HEAD 파일 단위 대조 | base 5실패 / HEAD 6실패 → `showPictureForm` 만 차이 |
| 2 | 용의자 `src/assets/bundled.ts` 의 추가 줄만 제거해 실행 | **여전히 실패** → 무죄. 추정 수정을 막았다 |
| 3 | `git bisect run` (임시 워크트리, 22커밋) | 첫 나쁜 커밋 = `05f6942a` |
| 4 | `05f6942a` 정체 확인 | 다른 작업자 커밋, **이미 main 에 병합됨**. 내 커밋 아님 |
| 5 | 계보 확인 | `05f6942a` 는 `aac023090` 의 자손이 **아니다** → 내 base 비교 기준 자체가 분기점이 아니었다 |
| 6 | `origin/main` 에서 직접 실행 | **12/12 통과** → main 에는 이후 수정이 있고 내 브랜치엔 없었다 |
| 7 | `git merge origin/main` (959커밋 뒤처짐) | 충돌 0, 병합 성공 |
| 8 | 병합 후 재검증 | 7파일 **56/56 통과**, `typecheck 0`, 커버리지 감사 0 |

## 배운 것

`handSlot` 회귀를 잡아낸 "base 대비 파일 단위 대조"가 이번엔 **오판을 만들 뻔했다**.
base 로 쓴 커밋이 실제 분기점이 아니면 그 사이 타인의 변경까지 내 것으로 보인다.
bisect + 대상 브랜치 직접 실행으로 교정했다.

남의 변경은 지우거나 되돌리지 않았고, 강제 푸시·히스토리 재작성도 없다.

## 19건은 대부분 내가 만든 측정 오류였다

두 전체 스위트를 **같은 `node_modules` 를 공유하며 병렬 실행**했다. 이 저장소는
`playwright.runtime.config.ts` 주석에서 공유 `node_modules/.vite` 경합을 "실측 사망 경로"로
명시한다 — 내가 그 조건을 그대로 만들었다.

19개를 **격리 실행**하니 **18개 통과 / 1개 실패** (376 테스트 중 375 통과).

## 남은 1건도 내 것이 아니다

`test/aiEditorFullToolCoverage.test.ts` — `upsert_enemy` 가 몬스터 리소스를 거부하는 실패로,
생활 시스템과 무관하다.

| 실행 | 결과 |
| --- | --- |
| 내 브랜치 (격리) | 1 failed / 5 passed |
| `origin/main` (격리) | **1 failed / 5 passed — 동일** |

main 과 결과가 같으므로 **기존 red** 다. 기준선에 흡수하지 않고 이대로 보고한다.

## 귀속 근거 3중

1. 19개 중 내 비병합 커밋이 건드린 파일 **0개** (`mineCount=0`)
2. main 기준 내 브랜치의 `src/` 변경 **없음** — 증거·`test/runtime/life-full.spec.ts`·`scripts/qa/*`·보고서뿐
3. 격리 재실행에서 18/19 통과, 남은 1건은 main 과 동일

**결론: 이 브랜치가 유발한 회귀는 없다.** 이 작업이 만든 유일한 회귀는 앞서 발견·수정한
`test/handSlot.test.ts` 1건이며 현재 통과한다.
