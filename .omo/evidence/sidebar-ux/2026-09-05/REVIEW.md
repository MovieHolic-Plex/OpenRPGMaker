# 왼쪽 사이드바 적대적 리뷰 — 2026-09-05

브라우저의 전문가·표준·초보 모드에서 1440×900, 1280×800, 1024×768을 조사했다. 검증 대상은 에디터 코드이며, 기존 임시 프로젝트로 조작했다. 게임 콘텐츠·원격 프로젝트는 변경하지 않았다. 다른 모델이나 하위 에이전트는 호출하지 않았다.

| 문제 | 실측과 영향 | 개선 |
|---|---|---|
| 초보 소재 누락 | 현재 선택 + 앞쪽 인덱스에서 48칸만 노출. 물·벽 조각이 반복되고 뒤쪽 나무·가구 등은 선택 불가 | 공용 전체 팔레트, 레이어 분류와 오토타일 대표 축약, 검색 제공 |
| 모드 복귀 후 빈 사이드바 공간 | 표준·전문가 → 초보로 바꿔도 이전 인라인 폭 300px가 남음. 레일은 72px인데 캔버스는 310px에서 시작 | 초보 분기에서 인라인 width 제거, 모드 왕복 후 실제 폭·캔버스 시작점 검증 |
| 초보 키보드 포커스 유실 | Enter로 지우기를 선택하면 `document.activeElement`가 BODY가 됨. 표준·전문가는 버튼 유지 | 레일 내부에서 포커스를 캡처하기 전에 부모가 노드를 지우지 않도록 호출 순서 수정 |
| 초보 타일 의미 오류 | `360 360 흙길 중심`처럼 번호 중복, 다른 시트에도 combined_town 라벨 적용 | 기본 시트 라벨은 한 번만 표시, 커스텀 시트는 저작 라벨 사용. 현재 레이어 표시 |
| 초보 타일 탐색 부담 | 48개 버튼이 모두 Tab 순서에 들어감, 행 단위 방향키 탐색 없음 | 공용 2차원 roving으로 탭 정지점 하나, 방향키·Home·End 사용 |
| 작은 창의 맵 탐색 부담 | 표준·전문가 1024×768 맵 목록 높이 48px. 마지막 행까지 스크롤로 닿지만 한 줄씩만 비교 가능 | 작은 창에서 타일 예약 공간 280→200px, 맵 목록 최소 세 행 검증. 큰 창·수동 분할 유지 |
| 보조기기 활성화 무시 | 공용 타일 셀의 click 처리기는 preventDefault만 수행. pointerdown 없는 활성화가 동작하지 않음 | detail=0 click으로 선택, 물리 클릭 중복 방지 |
| 검색 편집 커서 이동 | 필터 입력마다 DOM을 교체하고 focus만 복구하면 문자열 중간 커서가 유지되지 않음 | 검색 선택 범위·커서 복원, preventScroll, 고정된 초보 팔레트의 스크롤 유지 |

추가 점검: 표준·전문가 도구·레이어·더 보기 버튼은 기본 폭에서 실제 중심 좌표로 클릭할 수 있었다. 맵 목록의 마지막 행은 스크롤로 도달했으므로 “영구 잘림”으로 분류하지 않았다. 초보 맵 상세가 아래로 쌓이는 작은 창에서도 맞도록 “오른쪽 상세” 안내를 위치 중립 문구로 고쳤다.

재현·회귀 검증은 `test/e2e/left-sidebar-adversarial.spec.ts`에 있다. 각 모드/크기별로 버튼 중심 hit-test, 3행 이상 맵 공간, 마지막 맵 도달, 레이어 왕복, 검색 중간 커서, 초보 전체 타일·핀·키보드 선택·포커스 반환, 모드 복귀를 확인한다. 코드에만 맞춘 fakeDom 테스트가 놓친 부모 렌더 경로를 실제 브라우저에서 검증한다.

## 검증

- 관련 단위 테스트: 8파일 76개 통과. 이후 커서 복원 11개, 마지막 폭/접근성 수정 관련 11개도 통과했다(중복 재실행 포함).
- 최종 앱 타입 검사: exit 0. CSS 예산·그래프: exit 0. OpenWiki 검증: 통과.
- 표면 게이트: 이벤트 편집기 스냅샷 3건(`changeFace`/`showPicture` AI prompt 컨트롤), `.selected`의 `bottom` CSS 기준선 오류. 수정 전 `b23182dd` 별도 체크아웃에서도 같은 실패 목록과 이유를 재현했다. 기준선을 수정하지 않았다.
