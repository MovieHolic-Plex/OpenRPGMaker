# Pokémon-like characters: authoring contract

이 디렉토리만으로 작동한다. 상위 에디터의 registry, DB, Vite, 환경 키에 연결하지 마라.
먼저 README.md → docs/AUTHORING.md → 실제 판형 이미지/원본 격자를 읽는다.

## 사용자가 받아들인 전략

- 원작 캐릭터를 **몸·걷기 판형**으로 쓴다. 머리/옷/소품을 명시적으로 수정한다.
- 역할마다 맞는 몸형을 고른다. 모든 NPC를 같은 주인공 몸통으로 만들지 않는다.
- 원본 16×32에서 작업한다. 큰 그림 축소, 알파 임계값으로 깎기, 색 양자화, 자동 윤곽 수정은 하지 않는다.
- 원작을 사용했으면 파생임을 정확히 기록한다. 새로 다 그렸다고 주장하지 않는다.

## 작업 순서

1. `node cli.mjs doctor`, `node cli.mjs templates`.
2. 대표 하나를 `new`로 시작하고 실제 `original.png`와 격자를 읽는다.
3. `template.json`의 팔레트와 직접 고른 행 패치를 편집한다. 12포즈의 장식/옷/얼굴이 이어져야 한다.
4. `candidate.json`의 외형/출처를 실제 그림과 맞춘다.
5. `render`로 굽고 검사를 받는다. 실패하면 그림/수정안을 고친다. 검사의 임계값을 낮추지 않는다.
6. 실제 GIF를 열고 4프레임을 디코딩해 다리 교대·팔·얼굴·머리 흔들림을 확인한다.
7. `serve`에 올리고 사용자 Allow/Deny를 받는다. 수정 요청은 새 버전으로 반영한다.
8. 현재 사용자 Allow가 있는 후보만 `export`한다.

## 게이트와 검토 기록

- CLI에서 승인하거나 DB/영수증을 직접 작성하지 마라. 실제 저장소에 자동 Allow/Deny를 쓰지 않는다.
- `tests/`의 합성 판정은 임시 폴더에서만 허용되며 실제 사용자 승인 근거가 아니다.
- 규격 통과를 미감의 완성이나 사용자 승인으로 보고하지 마라.
- 승인된 PNG/GIF/recipe는 변경 불가. 수정은 새로운 초안/출력 경로/후보로 등록한다.
- 파일 해시가 같고 ID가 같으면 같은 후보다. 이름만 바꾼 복제는 새 아트가 아니다.
- `.data/` 전체가 저장 단위다. 종료 후 DB/패키지/영수증을 함께 보존한다.

## 재사용 유지

- 에디터 종속 어댑터는 밖에 둔다. 기본 export는 native PNG/GIF/중립 sprite.json이다.
- `core/` 수정 시 번들을 재생성하고 이 폴더 밖으로 복사하는 `tests/verify.mjs`를 실행한다.
- UI 수정 시 `tests/browser.mjs`로 Allow/Deny/다운로드와 실제 GIF 로드를 확인한다.
- `references/sources.json`의 원본 SHA/출처를 보존한다. 검사 실패를 통과시키려고 원본 해시만 바꾸지 않는다.
