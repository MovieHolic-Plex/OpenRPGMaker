# 판형을 수정하는 방법

## 기본 규격

원작 입력은 인덱스 팔레트 PNG `144×32`(16×32 셀 9개), 투명 인덱스 0입니다.
고정 매핑은 위 `[5,1,6]`, 오른쪽 `[7,2,8]` 좌우 반전, 아래 `[3,0,4]`, 왼쪽 `[7,2,8]`입니다.
이 매핑과 맞지 않는 칩셋을 강제로 줄여 넣지 마세요. 다른 구조에는 명시적인 새 어댑터와 검사가 필요합니다.
완성 시트는 `48×128`, 3열×4행, 불투명색 최대 15개입니다.

## 초안 수정

`new`가 내준 `original-grid.json`에서 포즈별 원본 행과 팔레트 글자를 확인합니다.
예제의 `template.json`은 12포즈의 실제 행 패치를 이미 포함하고 있습니다. 패치는 순차 덧칠이 아니라
**원본에 적용할 최종 행**입니다. 같은 프레임/행을 두 번 등록하면 실패합니다.

```json
{
  "frame": "down_idle",
  "y": 16,
  "rows": ["....D55EE55D...."]
}
```

`y`는 0부터 시작합니다. 한 행은 정확히 16자이고 `.`은 투명입니다. 위 예시는 문법 예시이며,
실제 판형의 해당 행을 읽고 맞는 픽셀을 써야 합니다. `paletteOverrides`는 기존 팔레트 키의 `#RRGGBB`만 바꿉니다.

- 머리 영역 10~20행: 프레임마다 최소 4개 인덱스를 실제로 수정.
- 복장 영역 21~27행: 프레임마다 최소 2개 인덱스를 실제로 수정.
- 28~31행: 원작 발/다리 인덱스 유지. 몸을 통째로 흔들거나 다리를 새 위치로 미는 편법 금지.
- 모든 12포즈에 같은 인물이 유지되는지 사람이 확인.

수치 이상으로 바꿨다는 것만으로 잘 만든 그림이 되는 것은 아닙니다. 패치 수를 채우려고 점을 뿌리지 않습니다.
머리 색만 바꾸면 옷 수정 관문을 통과하지 못합니다. 원본 팔레트의 같은 키는 머리/옷/피부에 공유될 수 있으므로
각 방향을 실제로 보며 수정합니다.

`candidate.json`의 `author`에 실제 저작자/모델을 적으세요. 기본 초안은 저작자 미지정으로 기록되며, 사용하지 않은 모델이나 사람이 그렸다고 쓰지 않습니다.

## 역할과 판형

16개 예제가 있습니다: 주인공, 라이벌, 박사, 간호사, 상인, 어머니, 주민, 체육관장, 회사요원,
선장, 작업자, 탐험가, 학생, 레인저, 월영단장, 등산가.
역할별 예제를 시작점으로 쓰되, 동작이 완전한 다른 판형으로 바꾸려면 해당 원본 격자에서 패치를 다시 저작합니다.
원작 간호사처럼 전체 걷기 셀이 없는 이미지를 완전한 걷기 판형으로 사용하지 않습니다.

새 원작 판형을 추가하려면 `references/`에 원본 PNG를 보존하고 `sources.json`에 고유 `id`, `file`,
`sha256`, `sourceUrl`, `originalArtwork`, `sourceUse`를 기록합니다. 해시는 원본 바이트로 계산합니다.
그림을 먼저 눈으로 확인하고 9셀 의미/인덱스 0 투명/팔레트 계약을 확인하세요.
`templateId`와 `templateSourceSha256`를 맞추고 이 판형에서 다시 `patches`를 씁니다.

## 미감 검토: 지적할 지점

- 1배에서 직업/인물이 구별되는가? 눈과 입이 얼룩처럼 합쳐지지 않는가?
- 정면·후면·측면의 모자, 머리카락, 가방이 같은 디자인인가?
- stepA→idle→stepB→idle에서 발이 실제 교대하는가? 신발이 미끄러지지 않는가?
- 모자/가방/가슴 장식이 프레임마다 깜빡거리거나 커졌다 작아지지 않는가?
- 원작의 작은 바운스가 유지되는가? 머리 전체가 좌우로 요동하지 않는가?
- 같은 판형을 공유하면 어떤 외형 차이를 넣었는가? 색을 제거해도 장식/머리가 설명되는가?

반려 사유에는 `frame, x, y`와 수정할 모양을 구체적으로 적습니다. 거절된 안은 승인된 안처럼 재사용하지 않습니다.

## GIF 분석

GIF는 원본 16×32 네 방향을 68×32에 가로로 놓은 4프레임이며 프레임당 130ms입니다.
렌더링에서 팔레트 인덱스를 정확히 매핑합니다. 이미지 생성 모델, 리사이즈 필터, 양자화는 없습니다.
검사는 각 GIF 프레임을 디코딩해 PNG의 `[0,1,2,1]` 열과 픽셀 단위로 비교합니다.
사람에게는 실제 GIF와 12포즈를 보여주고, AI도 디코딩한 프레임을 열어 관찰해야 합니다.

## 사용자 검토 후

Allow가 있어야 export할 수 있습니다. 외부 엔진에서는 sprite.json의 frame 크기·방향·순서를 읽습니다.
특정 엔진의 패딩/slot 변환은 별도 어댑터에서 처리하며 원본을 축소하지 않습니다.
