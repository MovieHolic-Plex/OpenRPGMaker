- 아이콘: `{SET}` 세트의 `{NAME}` — 역할 {ROLE}({ROLE_NAME}), {W}×{H} 칸(칸 = 16px)
- 설명: {DESC}
- 그림 폴더: {DIR}
- 결과를 쓸 파일: `{DIR}/verdict.json` — **이 파일 하나만 만든다.**

## 월드맵 아이콘 시점 계약 (이게 기준이다)
- 카메라는 **정남쪽 위**에서 비스듬히 내려다본다. 보이는 면 = **윗면(지붕·성벽 위 통로·탑 꼭대기·바닥)** + **남쪽 면(정면 벽·문)** 둘뿐이다.
- 건물 윤곽은 **좌우가 대칭에 가깝고**, 벽의 아래·위 경계는 **수평선**이다. 원통 탑은 위에 타원 머리, 앞에 세로 몸통.
- **옆면이 보이면 안 된다.** 상자의 오른쪽(또는 왼쪽)에 어두운 세로 면이 붙어 깊이 방향으로 비스듬히 물러나는 그림 = 아이소메트릭/경사 투영 = 불합격.
- 불합격 사유(코드):
  - `SIDE` 동·서쪽 옆면이 보인다(오른쪽이나 왼쪽에 다른 명암의 세로 면이 붙어 있다). **이번 검수에서 가장 중요하다.**
  - `DIAG` 지붕·벽 윗선이 사선으로 물러나 마름모·평행사변형 윗면이 된다(수평이어야 할 선이 기울었다).
  - `FRONT` 윗면이 전혀 없는 정면 입면도(지붕·성벽 위가 1px 띠뿐).
  - `TOPDOWN` 위에서 본 판만 있고 남쪽 면(벽·문)이 없다(건물일 때).
  - `READ` 지도 자리(ctx)에서 역할·설명대로 읽히지 않는다(무슨 장소인지 모르겠다).
  - `STYLE` 기준 그림과 윤곽·명암·크기감이 크게 다르다(윤곽선이 없거나, 색이 지형에 묻히거나, 너무 잘다).
- 자연물(화산·거목·바위·동굴 입구 바위·부유섬의 암반)은 `SIDE` 를 면제한다 — 대신 `DIAG`·`READ` 는 본다. 그 위에 얹힌 건물·천막·돌기둥에는 계약을 그대로 적용한다.
{SET_RULE}

## 판정 태도 — 공격적으로 떨어뜨린다 (사용자 지시, 2026-10-02)
사용자는 「정면 + 3/4 탑뷰를 안 지킨 것은 공격적으로 폐기하라」고 했다. 지난 검수는 옆면이 남은 후보를 통과시켜 사용자가 화를 냈다.
- **의심되면 FAIL.** 「조금」「일부」「작은 탑 하나만」 옆면이 보여도 `SIDE` 다. 건물 하나·탑 하나라도 오른쪽(또는 왼쪽)에 다른 명암의 세로 띠가 붙어 깊이를 만들면 떨어뜨린다.
- 집 여러 채짜리 마을: **집마다** 본다. 집 한 채라도 지붕 옆으로 어두운 벽면이 보이면 `SIDE`.
- 지붕 윗선·성벽 위 통로가 좌우로 기울었거나 평행사변형이면 `DIAG`. 좌우 대칭 박공(∧)은 정상.
- 돌원·울타리·성벽처럼 둥글게 두른 것: 위에서 본 고리(돌 머리만 동그랗게)로만 보이면 `TOPDOWN`. 앞쪽 돌은 정면 몸통이, 뒤쪽 돌은 머리 위주로 보여야 한다.
- 「출발 그림의 옆면을 일부만 지운」 그림은 합격이 아니다.
- 합격은 **모든 건물·탑·천막이 윗면 + 남쪽 정면만** 보일 때뿐이다.

## verdict.json 형식 (JSON 하나, 한국어)
```json
{"verdict": "PASS" 또는 "FAIL",
 "codes": ["SIDE", ...],
 "reads_as": "지도 1배에서 이게 뭐로 보이나 — 한 줄",
 "reasons": "불합격이면 어느 부분이 왜 틀렸는지 8배 그림의 위치로(예: 오른쪽 탑 x=40~47 에 어두운 옆면). 합격이면 한 줄 근거.",
 "doubt": "애매해서 사용자가 봐야 할 점(없으면 빈 문자열)",
 "fix": "다시 그린다면 고칠 것(정면 3/4 로: 옆면 지우고 정면 벽 넓히기 등). 합격이면 빈 문자열."}
```

## 금지
- `verdict.json` 말고는 아무것도 만들거나 고치지 않는다. 그림을 직접 고치지 않는다.
- git, npm, vitest, gates, 다른 에이전트 띄우기 금지.

마지막 답: `PASS` 또는 `FAIL` + 한 줄.
