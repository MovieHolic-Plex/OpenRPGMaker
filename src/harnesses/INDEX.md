## monster-collect-species — 몬스터 수집 종 스프라이트

몬스터 수집(포켓몬류) 게임의 종을 도감 시드에서 읽어 앞모습(상대)·뒷모습(내 몬스터) 전투 스프라이트와 대기·공격·피격 애니메이션을 만든다. 생성 그림 속 픽셀 격자를 찾아 진짜 도트로 옮기고, 사람이 후보를 고르며, 64 캔버스(몸 56 이내)·바닥 정렬로 맞춘다.

**이럴 때 쓴다:**
- 몬스터 수집(포켓몬류) 게임의 몬스터 종·스타터·진화 계통 그림을 만들 때
- 몬스터 수집 전투의 앞모습/뒷모습 스프라이트를 새로 만들거나 다시 그릴 때
- JRPG 일반 적(enemy) 그림에는 쓰지 않는다 — 그쪽은 자료집 그림 생성 경로

**단계** (`npm run harness -- monster-collect-species <단계>`):
- `status` — 현황: 시드의 종마다 앞·뒤 그림이 골라졌는지, 번들 결과물이 있는지 보여 준다.
- `front` — 앞모습 후보: 종 설명을 화풍 계약에 넣어 상대 앞모습(왼쪽 3/4) 후보 N장을 생성·도트화하고 비교 시트를 만든다.
- `back` — 뒷모습 후보: 고른 앞모습 도트를 키워 참고로 넣고, 같은 종의 뒷모습(오른쪽 위를 보는 등) 후보를 만든다.
- `action` — 큰 동작 후보: 공격·피격처럼 자세가 크게 바뀌는 동작을 sprite-gen 방식(가로 한 줄 한 장 생성)으로 만들고 재생 시트를 만든다. 대기는 생성하지 않는다(build 가 고른 스프라이트를 1px 씩 움직여 만든다).
- `pick` — 고르기: 사람이 고른 후보(앞·뒤 그림 또는 --action 동작 줄)를 출처(격자 원본·해시·프롬프트)와 함께 기록한다.
- `import` — 가져오기: 이미 있는 생성 원본 PNG 하나를 도트화해 후보로 등록한다.
- `build` — 번들 굽기: 골라 둔 격자 원본을 64 캔버스로 맞춰 public/assets/harnesses/ 아래에 쓰고, 대기·동작 스트립과 anim.json 을 만들고 검사한다.
- `check` — 검사: 번들 스프라이트의 색 수·마젠타 잔점·윤곽·앞뒤 색 일치, 애니메이션 프레임(대기 0번=원본·발 고정, 동작 색·몸집)을 검사한다.
- `refit` — 후보 다시 맞추기: 이미 만든 후보 폴더의 스프라이트·검사·시트를 현재 캔버스 규격(64)으로 다시 만든다. 격자는 그대로, 생성하지 않는다.
- `grid` — 격자 보고: 고른 그림마다 생성 블록 크기·원본 도트 칸 수·64 캔버스로 줄인 배율을 보고한다(격자 계약: 한 도트 = 논리 화소 하나).
- `manifest` — 런타임 목록: 번들 폴더를 읽어 src/assets/harnessMonsterBundle.json(이미지 바이트 없음)을 쓴다. 런타임이 「번들에 종 id 가 있으면 그 그림」 규칙으로 캠페인 종(seed 의 campaignSpeciesId)에 번들 그림을 쓴다. build 가 끝에 자동 실행.
- `preview` — 미리보기: 번들 스프라이트의 대기·동작을 전투 배율로 재생하는 HTML 한 쪽을 만든다.

**들어오는 길:** CLI 있음 · 에디터 화면 아직 없음 · 조수 도구 아직 없음

## pokemon-character-motion — 몬스터 수집 캐릭터 모션

Emeraldnative16×32 걷기·실제 오프닝 클립·64×64 트레이너를15색 후보로 가져오고 시각 검수와 해시에 묶인 관문을 통과한 결과만 굽는다.

**이럴 때 쓴다:**
- 몬스터 수집 게임의 주인공·NPC 걷기 도트나 오프닝 그림 모션을 생성·교체할 때
- 픽셀 수치가 방향·다리 교대 의미를 증명하지 않는다. 애니메이션 재생 증거를 남긴다.

**단계** (`npm run harness -- pokemon-character-motion <단계>`):
- `status` — 현황: 역할별 후보와 관문·검수·결과 해시 상태를 읽는다.
- `import` — 가져오기: 생성 아틀라스 또는 기존 네이티브 시트를 불변 출처와 함께 후보로 저장한다.
- `clip-import` — 오프닝 생성 클립: 생성 아틀라스 또는 직접 저작한 native 포즈를 스트립과 불변 출처로 가져온다. --native는 정확한 cell을 변형 없이 보존한다.
- `portrait-import` — 트레이너 가져오기: 기존 그림을64×64·15색 후보로 가져온다. --native는 직접 저작한64×64를 그대로 보존하고, 생성 원본의 기본 경로는 비율 보존 nearest fit을 쓴다.
- `check` — 구조 검사: 걷기16×32·오프닝 클립·트레이너64×64의 별도 계약과15색·이진 알파를 검사한다.
- `preview` — 시각 검수: 걷기·클립은 재생하고 트레이너는 정적1·2·3배로 검수하는 HTML을 만든다.
- `review` — 시각 판정: 재생 증거·검수자·이유를 출처와 최종 그림 해시에 묶어 기록한다.
- `gate` — 출하 관문: 구조 검사와 현재 해시의 시각 판정을 확인한다. 실패는 종료 코드 1이다.
- `build` — 굽기: 현재 관문·검수의 해시가 같은 결과만 로컬 출력 폴더에 복사한다.

**들어오는 길:** CLI 있음 · 에디터 화면 아직 없음 · 조수 도구 아직 없음

## pokemon-character-casting — 포켓몬 캐릭터 후보 승인

역할별 원작 판형의 머리·복장을 수정한 16역할 후보를 원본·수정본·GIF로 비교하고 Allow/Deny한다. 현재 그림에 묶인 승인만 결과를 굽고 공용 등록한다.

**이럴 때 쓴다:**
- 포켓몬류 NPC 후보를 브렌던 규격으로 만들고 사용자가 승인·반려할 때
- 감독자·조수는 사용자의 Allow를 대신 기록하지 않는다.

**단계** (`npm run harness -- pokemon-character-casting <단계>`):
- `prepare-cast` — 전체 16역할 준비: 역할별 판형에 명시한 머리·복장 수정을 적용하고 네이티브·GIF·출처 검사를 거쳐 16역할 검토 묶음으로 저장한다. 자동 승인하지 않는다.
- `prepare-theme-cast` — 테마 주민·조련사 준비: 사막·설원·해안 9역할(주민 남·여, 조련사)을 원작 판형의 머리·복장 수정으로 만들고 검사 후 theme-cast-v1 묶음으로 저장한다. 다른 묶음과 판정은 건드리지 않으며 자동 승인하지 않는다.
- `prepare` — 후보 준비: 명시한 시드의 서로 다른 native 전신 후보를 굽고 중복 몸체 검사와 기존 네이티브 모션 구조 검사와 미리보기를 연결한다.
- `queue` — 후보 등록: 외부 native48×128과 GIF를 불변 후보 패키지로 가져온다. 검증된 판형 공유는 표시하고, 출처가 확인되지 않은 복제와 같은 그림의 중복 등록은 거부한다.
- `serve` — 사용자 검토 화면: SQLite에 보존되는 Allow/Deny, 반려 이유, 방향·프레임 검토, 승인 결과 다운로드.
- `status` — 승인 현황: 미결정·승인·반려·오래된 승인과 역할별 현재 선택을 읽는다.
- `build` — 승인 결과 굽기: 현재 패키지의 사용자 Allow와 네이티브 구조·재생 검수를 다시 확인한다. 미결정·Deny·변조는 거부한다.

**들어오는 길:** CLI 있음 · 에디터 화면 아직 없음 · 조수 도구 아직 없음

## modern-chipset — 현대 칩셋 도트 (modern4)

modern4 팔레트 현대 거리 칩셋의 기물·건물·타일을 3/4 시점으로 찍는다. 현재 지원 종류는 탈것(vehicle)이고 소품·건물·바닥 타일로 넓힌다. 프로젝트 안에서 받아들여진 그림을 기준으로, 작업자 5명이 다른 방향으로 pxgrid 에 한 픽셀씩 놓고 기계 검사와 독립 검수를 거친 뒤 사람이 고른다. 다른 타일셋(조선·포켓몬풍 야외 등)은 별도 하네스다.

**이럴 때 쓴다:**
- modern4 팔레트 현대 거리/도시 칩셋에 자동차·버스·트럭·열차 같은 탈것(그리고 앞으로 소품·건물·바닥 타일)이 필요할 때
- 기존 탈것 도트가 순수 옆모습이라 3/4(윗면이 면으로 보임)이 안 지켜진다는 지적이 있을 때
- modern4 가 아닌 다른 타일셋(조선·포켓몬풍·버들항 판타지)에는 쓰지 않는다 — 타일셋마다 별도 하네스

**단계** (`npm run harness -- modern-chipset <단계>`):
- `parking-followup` — 시설 미완성 후속 처리: 해시에 묶인 확장판 검수를 실제 수정 큐로 연결한다. 필수 결함을 보존하고 누적 수정 상한을 유지한다.
- `parking-wide` — 주차장 확장 조립: 별도 기획 검수 후 승인 칩을 12면 실험 맵으로 조립한다. 전체 시설 완성 판정은 별도다.
- `save-parking-project` — 주차장 정본 저장: 선택한 공용 키트를 새 SQLite 프로젝트에 저장하고 재로드·통행을 확인한다.
- `publish-parking` — 선택한 주차장 등록: 현재 검수·선택 해시의 주차장 표본을 두 층 키트와 공용 참고문서로 굽는다.
- `palette` — 팔레트: modern4 램프에서 탈것 전용 pxgrid 팔레트(palette.pal)를 다시 쓴다.
- `draw` — 후보 그리기: 탈것·시점 하나에 후보 5장을 백그라운드로 그린다(작업자 → 기계 검사 → 독립 검수 → 최대 3번 다시 그림).
- `status` — 현황: 판과 후보의 상태·검수 결과를 보여 준다.
- `sheet` — 고르기 시트: 기준 경찰차·지금 것·후보를 나란히 놓은 자체완결 HTML 을 ~/claude-viz 에 쓴다.
- `review` — 다시 검수: 이미 그린 판을 기준차 옆에서 다시 독립 검수한다.

## super-harness — 슈퍼하네싱 (기물·파생·공간)

- 개념 카드(src/assets/conceptCards.json)를 고치거나 새로 굽고 싶을 때 — 손으로 쓰지 말고 화면에서 교정 지시

**단계** (`npm run harness -- super-harness <단계>`):
- `discover` — 낱말 찾기: 조수 실패 로그(검색 0건·빈칸 수리 턴)와 낱말 은행에서 다음 개념을 고른다.

- `plan-review` — 기획 적대적 검수: 별도 세션 A/B가 텍스트 도면의 정체성·사용·동선·경계·축척·재료를 검수한다. 둘 다 현재 기획을 승인해야 재료 조사.
- `survey` — 재료 조사: 필수 칩·시대·실제 그림·공용 재고·조립 지침을 조사한다. 없으면 맵 제작 금지.
- `material-review` — 재료 승인: 독립 검수자가 핵심 재료·시대·도구 시공 가능성을 확인한다. 파일 해시에 승인을 묶는다.
- `art` — 칩 후보 제작: 격리 워크트리에서 전용 그림 하네스로 후보를 만든다. 그림과 하네스 결과가 없으면 막힘.
- `art-review` — 후보 선택 대기: 사람이 선택하고 공용 등록한 뒤 재료를 다시 조사한다. 자동 선택·설치하지 않는다.
- `build` — 카드 만들기: 재료(그림/이벤트)·구조·금지·예제 호출을 쓰고 새 프로젝트에서 예제가 실제로 지어질 때까지 고친다.
- `review` — 적대 검수: 서로 안 보는 검수자 2명(개념·구조 / 동작·재료). 전체·네 구역 그림과 사방 벽·시대·통행을 모두 확인한다. 둘 다 현재 해시를 통과해야 다음으로.
- `probe` — 조수 시험: 같은 요청을 카드 없이 2판·붙여서 2판 돌리고 판정자가 전후 그림을 비교한다.
- `bake` — 굽기: origin/main 위 브랜치로 번들에 넣고 PR·머지. 사람이 폐기하면 빼는 PR.

**들어오는 길:** CLI 아직 없음 · 에디터 화면 아직 없음 · 조수 도구 아직 없음

- 버들항 건물 후보를 새 지붕·창문·벽 재질로 만들고 사람이 하나씩 고를 때

**단계** (`npm run harness -- beodeul-building-review <단계>`):
- `build` — 비공개 초안 굽기: 원본 도트 부품을 1:1로 조립한다. 초안은 검수 화면에 공개하지 않는다.
- `validate` — 파일 계약 확인: 전체 초안 존재·크기·해시·원본 픽셀 일치를 확인한다. 문 개수의 시각 판정은 gate 단계에서 한다.
- `gate` — 적대적 Visual QA: 독립적인 질감·구조 이미지 검사와 숨긴 반려 표본 검사를 수행한다. 누락·실패·낡은 결과는 공개를 차단한다.
- `publish` — 검증 통과 후보 공개: 모든 후보의 현재 그림과 시드·검사 규칙이 일치하는 서명된 통과 증거가 있어야 공개한다. 사람의 허용은 별도다.
- `produce` — 후보 생성·검증·공개: 활성 시드 전체에 build → validate → gate → publish를 직렬로 수행한다. 실패하면 공개하지 않는다.
- `serve` — 허용/거절 화면: 큰 카드 갤러리·검색/필터·고정 메모/결정 패널·집중 보기·원본 비교로 검수하며 메모만 저장도 제공한다.
- `repair` — 메모대로 고쳐 다시 올리기: 검수 화면의 「메모대로 고쳐 다시 올리기」 요청을 받는 별도 서비스(:18322). 거절 메모를 작업자(codex)에게 주어 원본 부품으로 다시 그리고, 같은 build→validate→gate→publish를 거친다. 실패하면 시드를 원래 바이트로 되돌린다.
- `status` — 현재 선택: 현재 그림 해시와 일치하는 허용/거절/미선택을 보여 준다.
- `export` — 허용한 것만 내보내기: 사람이 현재 그림을 허용한 후보만 파일 팩으로 내보낸다(CLI 전용). 공용 설치는 install, 스토어 올리기는 슈퍼하네싱 탭의 「스토어에 올리기」 또는 OPRN_STORE_PUBLISHER (private store publisher).
- `install` — 허용한 건물 공용 번들 설치: 결정 로그에서 현재 그림 해시에 허용된 후보만 시트·카탈로그·참고문서로 굽는다(--profile <id>, 프로필은 profiles.json).

**들어오는 길:** CLI 있음 · 에디터 화면 아직 없음 · 조수 도구 아직 없음

## game-concepts — 새 게임 컨셉 카드

새 게임 피드의 공식 컨셉(제목·훅·기획 5칸·도트 썸네일)을 만들고, 사람이 받기/버리기로 고른 것만 스토어에 게시

**이럴 때 쓴다:**

- 새 게임 썸네일

## murim-chipset — 무림 칩셋 도트 (murim_wuxia · oprn-murim)

중국 무협 배경 공용 칩셋 murim_wuxia 의 객잔·누각 뼈대·객잔 살림·도장·바깥(산문·대숲·석등) 조각 후보를 코드 손 도트로 찍는다. 잠긴 팔레트(청회색 유약 기와·주칠·황토·흰 회벽·짙은 나무·소나무·청석·대나무·금, 7단 램프, joseon_baram 과 밝기 호환) → 화풍 판 style-r1(후보 글자 = 컨셉 줄) 뒤로는 줄(A 밝은 문파·B 강남 무관)마다 후보 A1·A2·B1·B2 를 그 줄 style 조각과 같은 색·결로 그린다. 판(rounds/<판>.py) → 기계 관문(P·Z·Q·O·F·S·R·J 조각 맞물림·Y 줄 재료·G 바닥 닿음·K 탁자·걸상 배치 견본, 경고 T·L·N) → 조선 조각·줄 기준 조각·Actor1 옆 고르기 시트 → 사람이 (항목, 줄)마다 pick/reject(그림 해시에 묶임) 순서. 관문 통과는 합격이 아니다. 고른 것(현재 해시)만 bake 단계가 공용 번들 murim_wuxia 로 굽는다 — 기물 조각은 공용 오브젝트 게이트(require_pass, bundle 맥락)를 모두 통과해야 하고 하나라도 거절이면 아무것도 쓰지 않는다.

**이럴 때 쓴다:**
- 무림·무협·중국풍 칩셋(murim_wuxia) 의 바닥·벽·지붕·문·계단·객잔 가구·도장 기물·산문·대숲·석등 같은 조각을 새로 그리거나 후보를 다시 낼 때
- 무림 칩셋 후보를 사람이 줄(A 밝은 문파·B 강남 무관)마다 고르게 하거나, 고른 기록이 지금 그림과 맞는지 확인할 때
- 고른 무림 조각을 공용 번들 타일셋 murim_wuxia(시트·정의·키트 mur-·참고문서·장소)로 굽거나 다시 구울 때 — bake 단계(게이트 필수)
- 조선(joseon_baram)·jp_city·버들항·modern 계열 칩셋에는 쓰지 않는다 — 타일셋마다 별도 하네스

**단계** (`npm run harness -- murim-chipset <단계>`):
- `validate` — 시드 점검: 시드 줄(lines)·항목(크기·종류·층·반복·조선 기준 조각·세트 조각과 맞물림)·판 모듈(후보 키: 화풍 판은 글자, 이후 판은 줄마다 <줄><번호> 2개 이상)·금지 조항·팔레트 호환을 점검한다.
- `palette` — 팔레트 보고: 잠긴 팔레트의 램프 단별 밝기를 joseon_baram 범위와 대조하고 가장 가까운 조선 램프를 보여 준다(파일을 쓰지 않는다).
- `list` — 항목 목록: 묶음(style·frame·inn·dojo·outdoor)별 시드 항목. 줄마다 ★ 는 사람이 고른 것 중 지금 그림과 해시가 맞는 것.
- `draw` — 후보 그리기: 판 모듈의 후보를 그려 qa-runs/harnesses/murim-chipset/<판>/ 에 1배·8배 PNG 와 manifest.json(해시)을 쓴다.
- `gate` — 기계 관문: P 팔레트 잠금·Z 크기·Q 불투명 계약·O 먹 윤곽·F 윗면 행·S 반복 이음·R 색만 바꾼 후보·J 세트 조각 맞물림·Y 줄 재료·G 바닥 닿음(걸상·가구 발이 칸 아래 경계)·K 배치 견본(탁자+걸상 layout: 화소 일치·좌우 앉는 면 = 탁자 윗면 가운데 ±2px·뒤 걸상 절반 이상 보임·앞 걸상 2~4px)(FAIL), T 가는 줄·L 빛·N 1px 잡티(WARN). 줄별로 센다. 통과는 합격이 아니다.
- `sheet` — 고르기 시트: 후보를 줄별로 묶어 1배·4배·반복·조립 보기로, 조선 같은 용도 조각·그 줄 화풍 기준 조각·Actor1 옆에 놓고 줄별 장면(판 모듈의 scenes — frame 6×5, inn 8×6 객잔 홀)까지 담은 자체완결 HTML 을 ~/claude-viz/murim-<판>.html 에 쓴다(관문 FAIL 이면 안 쓴다). 고른 후보에 ★ 줄 표시.
- `pick` — 고르기(사람·위임): 사람이 고른 후보를 시트 때 해시와 대조해 (항목, 줄)마다 ledger.json 에 기록하고 picked/<줄>/<항목>.png 로 복사한다. 화풍 판은 후보 글자 = 줄, 이후 판은 <줄><번호>. 그림이 바뀌면 그 기록은 무효. 사용자가 고르기를 위임했으면 --by delegated --basis … --review <독립 검수 판정 json>(판정 그림 해시 = 현재 그림일 때만).
- `reject` — 버리기(사람): 사람이 버린 후보와 이유를 기록한다(다음 판의 「하지 말 것」).
- `status` — 현황: 판별 그림·관문·시트 유무와 줄별·묶음별 고른 것(현재 해시와 맞는지)을 보여 준다.
- `bake` — 굽기(게이트 필수): 고른 것(현재 해시)만 모아 공용 번들 murim_wuxia 를 굽는다: 48열 16px 시트·정의(칸 통행·층·키트 mur-<줄>-…·오토타일·그룹 mur:)·참고문서(mur-start·mur-terrain·mur-objects·mur-large·mur-examples·mur-check)·장소 예제. --prepare-gate 는 기물 조각을 object-gate review 용 items.jsonl·PNG 로 내놓고, --dry 는 .tmp/murim-bake/dry/ 에만 그린다. 실제 굽기는 조각마다 require_pass(bundle) — 하나라도 거절이면 아무것도 쓰지 않는다. 건너뛰기 옵션 없음.

**들어오는 길:** CLI 있음 · 에디터 화면 아직 없음 · 조수 도구 아직 없음

## object-gate — 공용 오브젝트 게이트 (3/4 시점 + 버들항 화풍)

새로 만든 기물·타일 그림이 번들·공용 DB·스토어·공방 칩셋에 들어가기 전의 관문. 최종 통과는 서명된 사람 허용이다(사용자 결정 2026-10-20: AI 판정 보정 2회 실패, 사용자가 매번 눈으로 판정). 판정자(Claude Sonnet 5.5 high)가 3/4 시점과 버들항 화풍을 따로 판정해 화소 해시에 묶은 영수증은 1차 거름·조언이고, 사람이 검토 화면(serve-holds, 18323)에서 허용하면 그 해시·종류에 묶인 서명 기록이 모든 출구를 연다. 거절은 최종. 사람 결정이 없으면 보정 프로필의 PASS 만 지나간다. 감독·에이전트는 허용·거절하지 않는다.

**이럴 때 쓴다:**
- 어느 하네스·에디터 공방·스크립트든 새 기물(오브젝트) 그림을 번들·공용 DB·스토어·칩셋에 굽거나 올리기 전
- 굽기·게시 스크립트에 3/4 시점 관문을 붙일 때(require_pass / objectGateRefusal)

**단계** (`npm run harness -- object-gate <단계>`):
- `review` — 판정: 그림 하나(--png --kind [--style-kind] --name) 또는 묶음(--batch items.jsonl)을 판정자 ×네 번으로 재고 3/4·화풍 두 반쪽을 따로 적은 화소 해시 영수증을 쓴다.
- `calibrate` — 보정: 3/4 위반·정상 표본과 화풍 얕음·버들 수준 표본으로 현재 프로필을 잰다. 위반을 하나라도 통과시키거나 정상 표본 통과율이 하한 아래면 rejected. 답은 프롬프트 해시별로 캐시해 이어 돌릴 수 있다(--offline 은 캐시만).
- `rereview` — 재검수: 현재 번들 테마 칩셋의 키트·바닥 그룹을 시트에서 합성해 새 프로필로 다시 판정한다(중단 후 이어 돌리기). 보정 통과 프로필만 영수증을 쓰고, --audit 은 보고서만.
- `check` — 출구 확인: 그림 하나가 출구(bundle·shared·store·workshop-local)를 지나갈 수 있는지 영수증만 보고 답한다(모델 호출 없음).
- `enqueue` — 대기열 올리기: 묶음(--batch items.jsonl --id --title)을 사람 검토 대기열에 올린다. 영수증이 없는 그림만 AI 판정(review --advisory)을 받고, 어느 프로필로든 판정받은 그림은 다시 부르지 않는다. 아무것도 허용하지 않는다.
- `selftest-holds` — 위변조 시험: 임시 데이터·임시 키로 사람 허용 규칙(서명·세션·영수증 필수·한 화소·거절 최종·묶음 허용)을 TS·Python 출구 모두에서 확인한다. 모델 호출 없음.
- `serve-holds` — 사람 검토 대기열: AI 가 판정했고 사람 결정이 없는 그림(보류·불합격·미보정 통과)을 묶음별로 1배·4배, 버들항 기준 그림 옆에 AI 조언과 함께 놓고 사람이 허용/거절을 누르는 로컬 화면(기본 포트 18323). 「이 묶음 전부 허용」은 확인 문구를 직접 입력해야 하고 그림마다 서명 기록을 쓴다. 결정은 화소 해시·종류에 묶이고 저장소 밖 키로 서명된다. holds 는 묶음별 현황.
- `status` — 현황: 프로필·영수증 수와 통과율을 보여 준다.
- `audit` — 기존 그림 감사: 이미 번들에 든 기물을 판정만 하고 보고서를 쓴다. 막지 않는다.

**들어오는 길:** CLI 있음 · 에디터 화면 아직 없음 · 조수 도구 아직 없음

## building-kit — 테마 건물 부품 조립 (버들항 계열 oprn-atlas)

버들항(beodeul_city)과 같은 계열 oprn-atlas 의 16px 3/4 탑뷰 건물을 테마 넷(중세 판타지 왕국·사막 오아시스·설원 북방·버들항 귀족 구역)에 부품 조립으로 만든다. 테마마다 잠긴 팔레트(공유 램프는 버들항 실화소에서 뽑고, 테마 램프는 버들항 출처 또는 밝기 범위 안의 손 램프) → 줄(line) 셋의 화풍 판 style-r1(부품 최소 세트 + 조립 건물 둘) → 기계 관문(P 팔레트·Z 크기·Q 불투명·F 윗면 띠·S 반복 이음·J 세트 이음·Y 줄 재료·G 바닥 닿음 + 조립 A1~A11, WARN OUTLINE·CONTRAST·T·L·N) → 독립 Opus 검수(숨긴 함정 통과 시 회차 무효, 유효 3회 다수결) → 사람이 시트에서 (항목, 줄)마다 pick/reject(그림 해시에 묶임) → 사람이 고른 부품으로 조립한 건물만 object-gate 3/4 영수증(kind structure) → village 로 그 줄의 건물을 길·마당·광장이 있는 마을에 놓는다. 관문 통과는 합격이 아니다. 번들 굽기·타일셋 배선·참고문서는 사람이 고른 뒤의 별도 작업이다.

**이럴 때 쓴다:**
- 버들항 계열 테마 건물(중세 판타지 왕국·사막 오아시스·설원 북방·버들항 귀족 구역)의 지붕·벽 칸·창·문·기단·층 띠·굴뚝·탑·현관 부품 후보를 새로 그리거나 다시 낼 때
- 같은 테마 건물을 부품 교체로 크기·용도 변형(작은 집·긴 집·여관·대장장이·길드·교회·성문탑)으로 늘릴 때
- 테마 건물 후보를 사람이 시트에서 줄마다 고르게 하거나, 고른 부품으로 조립한 건물이 지금 그림과 맞는지 확인할 때
- 새 건물 그림을 번들·공용 DB·스토어에 넣기 전 3/4 관문(object-gate kind structure) 영수증을 확인할 때 — 부품은 조립 건물 영수증으로 덮인다
- 기존 버들항 건물 원본의 국소 보정에는 쓰지 않는다 — beodeul-architecture / beodeul-building-review
- 테마 건물을 마을 단위로 놓아 접지·길·문 방향·건물끼리 어울림을 볼 때

**단계** (`npm run harness -- building-kit <단계>`):
- `palette` — 팔레트 뽑기: 테마 팔레트를 다시 뽑는다 — 공유 램프(잔디·포석·기단 돌·나무·쇠)는 버들항 실제 화소에서, 테마 램프는 seed 출처(버들항 칸·조각) 또는 손 램프(단마다 버들항 같은 단 밝기 ±0.04 안). --check 는 비교만.
- `validate` — 시드 점검: 테마 넷 seed(규칙·줄·부품 세트 pieces/joins·조립 레시피·판 모듈 후보 키·팔레트 최신·Actor1·기준 그림)를 점검한다. 판 모듈이 아직 없으면 「그리기 전」으로 보고한다.
- `list` — 항목 목록: 테마·줄별 부품 세트와 조립 레시피. 줄마다 ★ = 사람이 고른 것(현재 그림과 해시가 맞을 때), - = 그 줄에서 뺀 항목.
- `draw` — 후보 그리기: 판 모듈 후보를 그려 qa-runs/harnesses/building-kit/<테마>/<판>/ 에 1배·4배·부품 PNG 와 manifest.json(해시)을 쓴다. --agent 는 (줄, 후보)마다 새 그리기 프로세스(기본 claude-opus-5-5 · effort high, BUILDING_KIT_DRAWER_MODEL/EFFORT 로만 바꾼다)를 띄운다. requireGableFront 판은 샌드박스 refs/ 에 회색 투영 안내도가 들어간다.
- `dry` — 후보 한 장 미리보기: 후보 하나를 그려 관문과 조립 결과를 그대로 보여 준다 — 그리기 에이전트가 스스로 고칠 때 쓰는 입구.
- `gate` — 기계 관문: 부품마다 P 팔레트·Z 크기·Q 불투명·F 윗면 띠·S 반복 이음·J 세트 이음·G 바닥 닿음(Y 줄 재료), 같은 항목 후보끼리 R, WARN OUTLINE·CONTRAST·T·L·N. FAIL 이 있으면 검수·시트로 가지 않는다.
- `assemble` — 조립: 조립 레시피대로 부품을 붙여 building.png·kit.json(칸 격자 lower/upper·walkGrid·door)을 만들고 조립 관문 A1~A15(문 하나·지붕/벽 틈 없음·지붕이 벽을 덮음·기단이 바닥에 닿음·맞닿은 조각 이음·지붕 비율 밴드·용마루 하한·같은 땅 행·탑 지붕 폭/재료·박공 정면 용마루 세로선과 왼쪽 밝은 사면·골이 뒤 지붕에 닿음·굴뚝이 지붕 위·requireGableFront 판은 박공 정면 질량 필수)을 건다. 질량 종류 ridge_side·gable_front·lean_to.
- `finish` — 마감(손 디테일): 조립 관문을 모두 통과한 건물마다(--line, --building) 새 Opus 5.5 high 프로세스(BUILDING_KIT_FINISH_MODEL/EFFORT, 시간 BUILDING_KIT_FINISH_TIMEOUT 기본 5400s)가 팔레트 글자 격자 pixels.txt 를 finish_draw.py 의 명시 좌표·행 문자열로 고쳐 기와 낱장 변화·처마 밝은 선·회벽 점묘·막돌·창턱/꽃상자/유리 반짝임·아치 문/징·소품을 더한다. check.py (a) 윤곽 그대로 (b) 문 재질 (c) 팔레트만 (d) 처마 선 ±1px (e) 코드 AST(난수·식 채우기 금지) (f) 12% 이상 변화 (g) 16px 자기상관 감소. 하네스가 깨끗한 입력으로 finish_draw.py·check.py 를 다시 돌려 finished/<후보>.<건물>.png|.json 에 쓴다. 통과는 합격이 아니다 — review/sheet/village/pick --finished 로 마감 그림 해시에 묶인 같은 길을 간다.
- `review` — 독립 검수: 관문을 통과한 조립 건물만. 버들항 기준 건물 + 섞인 후보 + 숨긴 함정(지붕/벽 틈·문 둘·평면 채우기·잡음·얇은 지붕 입면·색만 바꾼 원본, requireGableFront 판은 후보 자기 부품으로 만든 평평한 정면 입면 flat_elevation) 보드를 새 Opus 판정자에게 보인다. --finished 는 마감 그림(함정도 마감 그림에서 만든다)과 review-finished/ 영수증. 함정을 하나라도 통과시키면 그 회차 무효, 유효 3회 다수결, 영수증은 그림 해시+판정 원문 해시에 묶인다.
- `sheet` — 고르기 시트: 검수 PASS 후보만 버들항 기준 건물·Actor1·1배/3배·조립 건물·거리 장면과 함께 ~/claude-viz/bk-<테마>-<판>.html 자체완결 시트로 쓴다(--show-failed 는 실패 사유와 함께 회색). --finished 는 마감 건물(바탕·마감 비교, 마감 해시)을 bk-<테마>-<판>-finished.html 에.
- `pick` — 고르기(사람): 사람이 시트에서 고른 후보를 시트 때 해시(--sha 앞 8자리)와 현재 그림 해시로 대조해 ledger.json 에 (항목, 줄)마다 기록하고 picked/<줄>/<항목>.png 로 복사한다. 에이전트 대리 선택 경로는 없다. --finished 는 <건물> <후보> 로 마감 시트에 보인 마감 해시를 picked/<줄>/finished/<건물>.png 와 finishedPicks 에 기록한다.
- `reject` — 버리기(사람): 사람이 버린 후보와 이유를 그림 해시와 함께 기록한다(다음 판의 「하지 말 것」).
- `objgate` — 3/4 관문 영수증: 사람이 고른 부품으로 조립한 건물마다 object-gate require_pass(kind structure, context bundle)를 받는다. 부품은 조립 건물 영수증으로 덮인다. 영수증이 없으면 「3/4 관문 미통과」.
- `village` — 마을 놓기: 그 줄의 조립 건물(검수 PASS 영수증이 지금 그림 해시와 맞는 것만, --all 은 전부)을 테마 팔레트 색만으로 그린 잔디(북방은 눈) 바닥·구불구불한 길·광장·우물·나무 위에 놓는다. 문은 길을 향하고 마당 1~2칸을 거쳐 길까지 걸어갈 수 있다(BFS 확인). 건물끼리 겹치지 않고 같은 --seed 면 같은 마을이 나온다. PNG 1배·2배와 ~/claude-viz/bk-village-<테마>-<판>-<줄>.html. --finished 는 마감 검수 PASS 마감 건물로 놓는다.
- `projection` — 투영 안내도: 박공 정면 투영(앞 박공 → 북쪽으로 물러나는 세로 용마루 → 왼쪽 밝은·오른쪽 어두운 사면 → 뒤 꼭대기 ^, 그리고 ㄱ자 본채+날개+골+굴뚝)을 16px 칸 위 무채색 도형으로 그려 projection-*-1x/4x.png 로 쓴다. 사용자 참고 그림은 쓰지 않는다.
- `status` — 현황: 테마별 판·관문·검수·시트·고른 것(현재 해시와 맞는지)·3/4 영수증 유무를 보여 준다.

**들어오는 길:** CLI 있음 · 에디터 화면 아직 없음 · 조수 도구 아직 없음

## cast-portrait — 캐스트 대사 흉상 (기존 캐스트와 같은 규격)

프로젝트마다 캐스트 규격(harness-data/cast-portrait/projects/<project>.json: 기존 흉상 줄, 캔버스, 규칙, 생성 경로, 대사창 픽스처)을 두고 새 흉상을 그 캐스트와 같은 경로로 만든다(아스트라: char-gen command 엔진 + bake_astra_busts64, 64×64·16색·투명·머리 위 1~4화소·어깨 아래로 잘림·인접색 윤곽·얼굴만 바꾸는 표정). 원본은 줄이거나 자르지 않는다(원래 격자가 캔버스에 안 맞으면 버림). 기계 검사(크기·색 수·자리·윤곽 어둠 ≥70%·두 눈 대칭·캐스트 대비 머리 폭·얼굴 밖 변화 0) → 캐스트 줄 1·3배와 실제 대사창 → 눈가림 Argon 「같은 작가?」 5번(중앙값·과반, 캐스트·반려작으로 보정한 문턱) → 사람 선택(현재 그림 해시) → 설치. 에이전트는 고르지 않는다.

**이럴 때 쓴다:**
- 대사 흉상·초상(포트레잇)을 새로 만들거나 다시 그릴 때 — 아스트라 호라이즌 등 캐스트가 있는 프로젝트
- 「다른 포트레잇과 안 어울린다」「괴물같다」는 흉상을 고칠 때
- 다른 데모(첫사랑·떨어진 별)는 자기 캐스트 규격 파일로 calibrate·check·lineup·verdict 를 쓴다(생성 경로는 규격에 있을 때만)

**단계** (`npm run harness -- cast-portrait <단계>`):
- `list` — 규격 목록: 프로젝트별 캐스트 규격(줄·생성 경로·역할)을 보여 준다.
- `calibrate` — 캐스트 측정: 기존 캐스트 흉상을 같은 측정기로 재서 baseline.json 에 쓴다(크기·색·머리 위치·윤곽 어둠·머리 폭·눈 대칭).
- `draw` — 후보 그리기: 규격의 생성 경로(아스트라: char-gen + bake_astra_busts64)로 역할 후보 N개와 표정을 만든다. 원래 격자가 캔버스에 맞지 않으면 버린다(축소·자르기 금지).
- `import` — 가져오기: 같은 경로로 이미 만든 흉상 폴더를 후보로 등록한다. 캔버스와 다른 크기는 거절한다.
- `fix` — 손 보정: 표정 하나의 화소를 고치고 기록·해시를 다시 잡는다(이전 판정은 무효가 된다).
- `check` — 기계 검사: 캔버스·색 수·투명 배경·머리 위 여백·어깨 잘림·윤곽 어둠·두 눈 대칭·캐스트 대비 머리 폭·얼굴 밖 변화·원래 격자를 표정마다 검사한다. 실패는 종료 코드 1.
- `lineup` — 캐스트 줄 세우기: 후보마다 기존 캐스트 줄 안(4번째)에 1·3배, 표정 띠 4배를 만들고 글자로 가린 눈가림 묶음과 검수 지시문을 쓴다.
- `dialogue` — 실제 대사창: qa:runtime 으로 진짜 대사창에서 캐스트 대사와 후보 표정(기본·기쁨·놀람·슬픔)을 한 장씩 찍어 눈가림 묶음에 넣는다.
- `review` — 반복 눈가림 검수 (관문): 후보마다 새 Argon 호출 N번(기본 5)으로 「같은 작가?」를 묻고 적합도 중앙값·같은 작가 과반·표정별 결함 표·퍼짐을 기록한다. 문턱은 calibrate-review 값.
- `calibrate-review` — 검수 보정: 실제 캐스트(한 명씩 빼서 후보 자리에)=합격, 사용자 반려작=불합격을 같은 묶음으로 N번씩 검수해 둘을 가르는 문턱을 정한다.
- `verdict` — 비교 검수 기록 (참고): 후보 넷을 한 장에 비교한 독립 검수자 JSON 을 그림 해시에 묶어 기록한다. 관문이 아니다(한 번 호출은 흔들린다).
- `pick` — 사람 선택: 검사 통과 + 눈가림 「같은 작가, 결함 없음」이 현재 해시에 있을 때만, 사람이 고른 후보를 기록한다.
- `install` — 설치: 현재 해시에 사람 선택이 있는 후보만 규격의 설치 폴더로 복사하고 출처를 남긴다.
- `status` — 현황: 판·후보마다 검사·판정·선택 상태.

**들어오는 길:** CLI 있음 · 에디터 화면 아직 없음 · 조수 도구 아직 없음
