# 탐험·모험 상세 제작 프리셋 v1

플레이의 중심은 목적을 가지고 장소를 탐험하며 발견·동료·선택 또는 전투의 결과로 다음 행동을 바꾸는 경험이다. 모든 모험을 마을·숲·보스의 같은 구조로 복제하지 않는다. 중심 플레이가 탐험이면 발견과 통행, 전투면 전략과 승패, 동료 이야기면 인물과 선택이 핵심 검증 대상이다. 첫 범위의 사건을 완주 가능하게 만들며 뒤 챕터의 지도를 채우는 것으로 작업 진척을 대신하지 않는다.

## V01 출발의 동기와 첫 목표
입력: 소중한 사람/미지의 세계/임무 선택, 사용자 콘셉트와 첫 범위.
실행: 떠날 이유·목표의 단서·플레이어의 첫 행동을 실제 장면에 연결한다.
산출물: 출발 상황, 이해 가능한 목표, 첫 입력.
검증: 누구를 왜 찾거나 어디를 왜 탐험하는지 알 수 있으며 설명만 읽고 끝나지 않는다.
사람을 찾는 모험이면 그 사람의 마지막 행적과 현재 인물의 관계를 제시한다. 미지의 세계면 호기심을 만드는 관찰 가능한 현상과 안전하게 접근할 장소가 필요하다. 임무면 요청자·해야 할 일·현재 범위의 성공 조건을 명확히 한다. 사용자 설정에 없는 왕국 구원이나 세계 멸망을 출발 기본값으로 추가하지 않는다. 첫 선택은 떠나는 태도·함께할 사람·가져갈 정보처럼 장면의 결과에 연결한다. 아직 없는 거대한 지도나 미래 보스를 현재 플레이 목표처럼 안내하지 않는다.

## V02 핵심 플레이 반복
입력: 탐험/전투/동료 선택과 첫 제작 범위.
실행: 이동 → 발견 또는 조우 → 판단 → 행동 → 결과 → 다음 목표의 반복을 현재 구간에 구현한다.
산출물: 현재 범위의 한 번 이상 완결되는 플레이 흐름.
검증: 장소에 들어가기만 해도 완료되지 않고 핵심 행동과 결과가 실제로 이어진다.
탐험 중심은 눈에 보이는 단서·접근 가능한 조사·결과로 통행이나 목표가 바뀌어야 한다. 전투 중심은 적과 싸울 이유·선택 가능한 전략·승패 후 결과가 있어야 한다. 동료 중심은 인물의 의견·선택·실제 후속 반응이 필요하다. 세 모듈을 모두 자동 강제하지 않는다. 사용자 기획에 두 개가 연결되면 어느 행동이 다음 행동의 선행 조건인지 명시한다. 처음부터 모든 시스템을 설명하는 튜토리얼을 늘리지 않고 플레이 중 필요한 정보를 준다.

## V03 탐험 공간의 읽기와 발견
입력: 장소와 탐험 목표, 실제 타일 참고문서, 시작 위치.
실행: 랜드마크·갈림길·위험·조사 대상·보상을 읽을 수 있는 동선을 설계한다.
산출물: 현재 범위의 통행 공간과 발견 지점.
검증: 목표를 알아볼 시각 단서가 있고 필수 발견이 벽이나 장식 때문에 접근 불가능하지 않다.
갈림길은 양쪽 선택의 의미를 보여준다. 짧은 첫 범위라면 주변 단서 한두 개와 목표 하나로 충분하며 빈 길 맵을 여러 장 만들지 않는다. 조사 지점은 실제 소품 위에 배치하고 플레이어가 찾을 수 있게 한다. 숨겨진 길은 발견 근거와 실제 연결을 갖춘다. 눈·사막·항구 등 설정이 있으면 해당 기후와 소재를 일관되게 쓰되 타일 번호를 추측하지 않는다. 지도에 장소 이름만 붙이고 동일한 빈 바닥으로 복제하는 결과는 반려한다.

## V04 장애물·열쇠·통행 상태
입력: 탐험의 장애물, 현재 지원하는 상태·아이템·출입 도구.
실행: 막힘의 이유 → 해결 행동 → 실제 통행 또는 이동 조건 변화 → 결과 확인을 저작한다.
산출물: 잠김·해제 상태, 장애물 이벤트, 실제 열리는 경로.
검증: 해결 대사 뒤에도 길이 막혀 있거나 해결 없이 통과할 수 있는 모순이 없다.
열쇠를 요구하면 실제 소지 여부와 소비 정책을 읽고 조건을 만든다. 스위치를 켰다는 메시지보다 문 이벤트의 실제 조건이 중요하다. 다리·절벽·길은 통행 가능한 실제 칸과 이동 규칙으로 검증한다. 장식 그림만 제거하고 충돌이 남는지 확인한다. 첫 범위 밖 시스템을 해결의 선행 조건으로 만들지 않는다. 실패 선택 뒤 다시 시도할 수 있는지, 아이템을 소모한 뒤 진행이 영구히 막히지 않는지 확인한다. 재진입 때 이미 해제한 길을 초기화하지 않는다.

## V05 동료의 목적과 합류
입력: 동료 이야기 선택, 사용자 인물 설정, 실제 파티·배우 데이터.
실행: 동료가 합류할 이유·플레이어의 선택·합류 결과를 실제 인물과 데이터에 연결한다.
산출물: 동료 프로필, 합류 조건, 실제 파티 또는 동행 상태.
검증: 합류 대사만 있고 동료 데이터가 없거나 두 번 대화해 같은 동료가 반복 추가되지 않는다.
동료는 주인공의 목적과 겹치는 부분과 자기 목적을 동시에 가진다. 사용자 이름과 미정 외형을 보존한다. 전투 동료이면 실제 배우·직업·기술·장비를 확인하고 파티 참여를 연결한다. 비전투 동행이면 지원되는 이벤트·동행 구현을 사용하며 메뉴 파티에 있다고 주장하지 않는다. 거절하거나 아직 합류하지 않은 경우의 대사와 진행 조건을 구분한다. 첫 동료 한 명을 요구했는데 기본 파티의 여러 인물을 확정 등장인물로 취급하지 않는다.

## V06 동료와의 선택과 반응
입력: 인물별 목적·의견, 중심 플레이와 선택 문구.
실행: 동료의 제안과 플레이어 선택에 따른 상태·대사·행동을 작성한다.
산출물: 동료별 선택 분기와 후속 반응.
검증: 선택의 결과가 인물 관계나 탐험 행동에 반영되고 양쪽 분기가 같은 설명으로 끝나지 않는다.
위험한 지름길과 안전한 우회를 고른다면 실제 동선·정보·동료 반응 가운데 현재 범위에 의미 있는 차이를 둔다. 동료의 말을 듣지 않았다는 이유만으로 임의 이탈을 강제하지 않는다. 의견 충돌이 있으면 그 인물이 왜 그렇게 생각하는지 대사에서 읽힌다. 전투 결과와 관계 결과는 서로 다른 상태일 수 있다. 같은 동료와 다시 말할 때 이전 선택의 흔적이 남고 관계 변경을 반복 지급하지 않는다. 선택한 동료 중심 플레이를 적 처치 보상 한 줄로 축소하지 않는다.

## V07 전투 역할과 실제 기술
입력: 전투 중심 선택, 실제 파티와 적·기술·장비 DB.
실행: 파티 역할·적 행동·기술 효과·보조 자원을 첫 구간에 맞게 구성한다.
산출물: 실제 전투 데이터와 사용할 수 있는 전략.
검증: 기술 이름만 다르고 효과가 없거나 없는 스킬·트룹 ID를 참조하지 않는다.
JRPG 전투는 프로젝트가 지원하는 전투 규칙을 유지한다. 몬스터 수집을 섞었다면 해당 장르 문서와 실제 파티 정책을 함께 확인한다. 파티 역할은 피해·방어·회복·상태 등 실제 효과로 구별한다. 첫 플레이어가 가진 자원으로 승리할 수 있는지 확인하고 유용한 행동을 대사로 안내할 수 있다. 새 기술 스키마의 수치와 enum은 조회 후 쓴다. 중심 플레이가 탐험이나 동료이며 전투를 요구하지 않았으면 랜덤 조우나 보스를 첫 장면의 의무로 넣지 않는다.

## V08 전투 진입·승패·복귀
입력: 실제 트룹, 조우 trigger, 첫 도전 목표, 패배 정책.
실행: 전투 진입과 승리·패배·도주 각각의 결과를 상태·보상·복귀 위치로 연결한다.
산출물: 실행 가능한 전투 이벤트와 결과 분기.
검증: 전투 뒤 입력이 돌아오고 패배·도주를 승리로 처리하거나 보상을 반복하지 않는다.
전투를 여는 적은 실제 그림과 접근 가능한 위치를 가진다. 게임 시스템이 지원하는 승패 분기와 전투 명령을 확인한다. 승리 후 문을 열면 그 문의 조건과 보상 완료 플래그를 한 흐름으로 연결한다. 패배를 재도전으로 설계했다면 회복과 복귀 위치가 실제로 동작해야 한다. 도주가 허용되지 않는 보스라면 도주 조건을 실제 규칙으로 적용한다. 시뮬레이션 결과만으로 조우 이벤트와 게임 복귀까지 확인했다고 보고하지 않는다. 첫 범위에서 실제 입력을 통해 전투를 실행한다.

## V09 발견의 보상과 성장
입력: 탐험·선택·전투 결과, 현재 성장·아이템 도구.
실행: 행동에 맞는 정보·통행·아이템·성장의 보상을 실제 데이터로 연결한다.
산출물: 보상 이벤트와 바뀐 상태 또는 DB.
검증: 보상 메시지와 실제 소지품·경험·해제 상태가 일치하며 중복 지급하지 않는다.
발견의 보상은 꼭 돈과 경험치일 필요가 없다. 다음 장소의 의미를 이해하는 정보나 새 통행 경로도 결과가 될 수 있다. 아이템을 준다면 존재하는 아이템 ID와 실제 획득 기능을 사용한다. 성장 한 번을 넣으면 전후 데이터나 사용할 수 있는 기술의 차이를 확인한다. 숨은 보상은 필수 진행과 분리하고 발견하지 않아도 현재 구간을 끝낼 수 있어야 한다. 이미 연 보물이나 완료한 의뢰가 재진입 때 초기화되지 않는다. 사용자 기획에 없는 제작·경제·경영 시스템을 성장 보상 때문에 추가하지 않는다.

## V10 여정·의뢰·챕터 진행
입력: progression 선택과 첫 범위.
실행: 여정은 다음 목적지, 의뢰는 선택·수락·완료·귀환, 챕터는 현재 장의 사건과 다음 장 조건을 구현한다.
산출물: 실제 목표 상태와 공간 연결, 현재 범위의 종료.
검증: 사용자 진행 선택과 다른 선형 여행을 강제하지 않고 범위 밖 챕터를 완성했다고 보고하지 않는다.
여정은 출발 이유와 목적지를 잇는 단서를 따라간다. 의뢰 선택은 플레이어가 무엇을 수락했는지 상태로 기억하고 완료 보고가 중복 보상을 주지 않도록 한다. 챕터 방식은 현재 장의 시작과 종료를 구별하고 다음 장이 미구현이면 그 사실을 기록한다. 첫 출발 장면에서는 뒤 여행을 설계하더라도 지금 지도와 이벤트를 모두 늘리지 않는다. 최소 구간이 끝나는 조건은 핵심 행동의 결과와 연결하고 단순히 맵을 모두 방문한 것만으로 처리하지 않는다.

## V11 장소 미술과 도트 읽기
입력: 확정 배경·기후·16비트 도트 방향, 실제 타일 참고문서.
실행: 장소의 정체성과 플레이 단서를 선명한 도트 구조와 소품으로 배치한다.
산출물: 읽기 쉬운 탐험 무대와 실제 사용 자산.
검증: 장식 밀도가 길과 목표를 가리지 않고 소재·인물·전투 배경의 시점과 픽셀 밀도가 일관된다.
경이로운 톤은 관찰할 구조와 공간 대비로, 유쾌한 톤은 인물 반응과 명확한 발견으로 표현한다. 도트의 날카로운 픽셀 경계와 재료별 제한된 명암 단계를 실제 원본에서 확인한다. 유적·항구·숲을 같은 잔디 맵에 이름만 바꿔 붙이지 않는다. 사용자가 새 공간 설계를 원하면 완성 맵 가져오기를 직접 설계했다고 부르지 않는다. 공용 타일 자료는 조립법과 실제 칸의 근거로 읽는다. 첫 범위의 핵심 대상이 카메라 밖에 가려지는지 플레이 화면에서 확인한다.

## V12 발견과 위기의 연출
입력: 실제 발견·동료·전투 사건, 사용자의 톤.
실행: 인물 이동·시선·카메라·소리로 사건의 변화와 다음 목표를 보여준다.
산출물: 핵심 비트별 실행 가능한 연출 큐.
검증: 연출 종료 후 입력·카메라·동료 위치가 정상이며 중요한 정보를 건너뛰어 잃지 않는다.
새 장소 발견은 카메라로 볼 대상과 플레이어가 실제로 갈 수 있는 동선을 함께 보여준다. 위기는 적의 출현만으로 끝내지 않고 플레이어의 행동 이유와 해결 결과를 연결한다. 동료 이동은 실제 이벤트 ID와 방향을 사용한다. 음악과 효과음은 실제 자산이며 긴 생성 대기 때문에 첫 맵이 비어 있지 않게 한다. 제목·오프닝은 핵심 플레이 연결 뒤 제작한다. 사용자가 따뜻한 동료애를 골랐는데 임의 비극이나 죽음을 긴장 연출의 기본값으로 넣지 않는다.

## V13 첫 범위와 귀환의 결과
입력: scene/episode/short 선택, 현재 목표와 핵심 행동.
실행: 출발과 첫 선택, 작은 유적과 동료, 위기 해결과 귀환 중 선택한 범위의 결과를 구현한다.
산출물: 현재 구간 종료 조건과 실제 후속 반응·귀환.
검증: 사용자 범위의 끝까지 실행 가능하고 필요한 귀환이 실제로 연결된다.
출발 한 장면이면 떠날 결심이나 경로 선택의 결과가 끝이다. 작은 유적과 첫 동료면 유적의 목표와 합류 또는 발견 결과가 있어야 한다. 첫 위기 해결과 귀환이면 원래 장소에 돌아가 결과를 전달할 수 있어야 한다. 범위가 작다고 핵심 상호작용을 생략하지 않고 범위가 크다고 빈 맵 장수로 채우지 않는다. 공용 뼈대가 있으면 보존해야 하는 엔진 연결과 사용자 목표를 구별하고 장르의 실제 결과를 독립적으로 검증한다.

## V14 재진입과 의뢰 중복 방지
입력: 의뢰·보상·합류·통행 해제 상태, 실제 페이지 조건.
실행: 최초·진행 중·완료 후 페이지와 초기화 조건을 분리한다.
산출물: 재방문 반응과 중복 실행 보호.
검증: 재진입·연속 대화·저장 후 재개에서 동료·보상·전투가 원치 않게 반복되지 않는다.
완료한 의뢰를 보고하면 이미 끝난 상태에 맞는 반응을 보여준다. 보스가 다시 나타나는 모험을 의도하지 않았다면 완료 페이지에서 제거하거나 비전투 대화로 바꾼다. 문과 길은 해제한 상태를 유지한다. 아직 수락하지 않은 의뢰의 완료 조건을 만족했다고 보상을 주지 않는다. 취소나 실패 뒤 다시 수락할 수 있는 정책이면 실제 이벤트로 구현한다. 종료 뒤에는 자동 실행 대사가 계속 돌지 않으며 플레이어가 이동하거나 메뉴를 열 수 있어야 한다.

## V15 탐험과 전투 실제 검수
입력: 현재 범위의 정상·다른 선택·패배·재진입 경로.
실행: 실제 시작점부터 필수 발견·핵심 행동·결과·종료와 복귀를 실행한다.
산출물: 동선·상태·선택·전투·보상·재로드 증거.
검증: 빈 맵과 도구 성공 로그만으로 모험이 만들어졌다고 통과시키지 않는다.
탐험이면 필수 대상에 접근해 결과가 통행이나 목표를 바꾸는지 확인한다. 전투이면 실제 파티와 기술, 승패 뒤 복귀와 보상을 확인한다. 동료 선택이면 양쪽의 반응과 이후 상태를 확인한다. 존재하는 데이터와 실제 플레이 가능한 데이터는 다르다. 통행 lint는 필요한 근거이나 대사·선택·전투 결과를 검증하지 않는다. 실패하면 어디서 어떤 입력으로 막혔는지 기록하고 그 작업과 후속 검증을 다시 연다. 정본 저장 후 같은 프로젝트를 재로드해 현재 범위의 흐름을 확인한다.

## V16 다른 장르와 모험의 연결
입력: secondary와 blend 원문, 두 장르의 핵심 행동.
실행: 발견·동료·선택·전투 결과를 관계·수집·추리의 조건과 실제 반응으로 연결한다.
산출물: 두 장르의 결과를 공유하는 상태와 이벤트.
검증: 선택한 결합 방식이 실제 플레이에 있고 한 장르를 단순 배경으로 축소하지 않는다.
관계 결합은 여행의 선택이 동료의 신뢰와 다음 만남에, 수집 결합은 획득한 동료가 탐험·전투의 실제 입력에, 추리 결합은 발견한 사실이 증거와 추론에 이어질 수 있다. 지원되지 않는 특수 능력으로 통행이 열렸다고 대사만 쓰지 않는다. 에피소드 분리 선택이면 현재 범위의 한 사건을 먼저 완성하고 다음 장르 사건은 연결 조건을 기록한다. 한 선택이 양쪽에 영향을 준다면 각각의 상태 변화와 후속 반응을 별도로 검사한다.
