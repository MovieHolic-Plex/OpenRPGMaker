# Skills 전체판 보고

저장 범위: `content-packs/joseon-folklore/skills/`만. 최신 사용자 확대 지시로 파일럿12개를 전체36개로 확장했다. 공유 steering의 실제 필드명·prototype 상태 정보·초반 적 MP 부족 통합 지침을 확인했다. feat 커밋 ID는 작업 종료 응답에 기록한다.

## 저장 결과

- `data.json`: 계약 기술36개(직업24·적12), 상태10개(예약6·기본4), 속성5개. 실제 normalizer 출력과 왕복 일치.
- `design.json`: 직업별1/3/5/8/12/16 습득, 적15종 제안 연결, 보스3종 예고/표본 능력치, 상태 효과·기술별 수치·누락 상태 추가 정책.
- `icons/*.png`: 원본 코드 도트32px36개. `art.json`, `art-hashes.json`, `choreography-sources.json`: 등록 메타데이터·해시·기존 FX 출처.
- `review/`, `visual-review.json`: 실제 PNG 직접 검토. 땅가르기를 지면 균열 FX로, 호신부를 아군전체 결계 범위로 수정. 사용자 승인 주장 없음.
- `merge-state-defaults.mts`: 같은 ID의 기존 상태와 순서 보존, 빠진 것만 추가. README에 통합 방식 기록.
- `smoke.mts`, `smoke-results.json`: 제한된 직접 스크립트90개 확인과 관찰값. 모든 파일 저장 후 status를 마지막 기록.

| 검사 | 관찰 |

| 전체 기술 수치 | 36개 모두 피해/회복/타수·상태 확률 경계·기력·HP대가/흡수 표본 |
| 실제 전투 명령 | 직업24·적12 효과 발생/기력/대상/타수; 예고 있는 적은 strict/gauge 모두 확인 |
| 도사 레벨8 되살림 | 죽은 아군 HP0→60, 사망 제거, MP12 |

| 기본 상태 | prototype 독·맹독·침묵 존재, 사망 레코드 없음; pack에 정규화 기본4행 저장 |

보스 표본 HP650/MP30/공격48/방어24/정신28/민첩30. 파티 방어20/시작HP120에서 양쪽 flow 모두 **발동 전 1자기차례 예고**를 기록했다.

| 보스 | 기술 | 방어 중 대상별 피해 | 발동 후 파티HP | 기력 |
|---|---|---:|---|---:|
| 청동도깨비 | 청동강타 | 23 | 97 / 97 | 0 |
| 신부원혼 | 한의울음 | 0 (귀봉 부여) | 120 / 120 | 5 |
| 산호랑이 | 엄니돌진 | 17 (단일) | 103 / 120 | 3 |

세 보스 기술은 공유 레코드이므로 일반 멧돼지·처녀귀신에도 같은 예고가 적용된다. 상태 확률은 저항을 곱한다. prototype 배우 독C=60%에서 독묻힌날36%, 독이빨27%의 경계값을 검사했다. 물리 회피·기술 봉쇄·방어 배율·정화·부활 설명을 실제 효과에 맞췄다.

## 한계와 인계

파일 콘텐츠와 로컬 fixture 검사 근거다. SQLite/Supabase 정본 저장, public 등록, 실제 직업/적 행동표 연결, 출하 플레이어 시각/오프라인 검토, 통합 성장곡선 밸런스는 감독자 단계다. 초반 적 maxMp 조정은 monsters 담당 지침이며 이 폴더에서 적 레코드를 수정하지 않았다. 아이콘은 현재 SkillRecord에 직접 연결할 필드가 없다. FX는 기존 저장소 원본을 참조했다.

전체suite/gates/vitest/npm test/전체typecheck/stash/push/PR를 실행하지 않았다. 다른 역할, DB, core, registry, 계약을 수정하지 않았다. 재생성 명령은 README에 있다. `ready:true`는 파일 저장과 개별 검사 완료이며 `userApproved:false`다.
