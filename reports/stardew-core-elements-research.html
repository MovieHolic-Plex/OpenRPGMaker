직접 답변

‘수집·작물·캐릭터’가 관여하는가?

그렇다. 다만 셋만으로는 부족하고, 이름도 너무 데이터베이스답다.

작물은 농장 운영, 캐릭터는 마을과 인연, 수집은 도감·기부·장기 성취라는 플레이 목적을 나타내야 한다. 여기에 하루/계절/날씨, 동물, 가공, 낚시·채집, 건물·꾸미기가 연결돼야 빈 껍데기처럼 보이지 않는다.

핵심 판단

“오늘 무엇을 포기하고 무엇을 할까?”가 매일 달라지고, 그 선택이 내 농장과 마을에 남아야 한다.

Core loop

하루가 모든 시스템의 시계다

수면은 단순 장면 전환이 아니라 출하 정산, 성장, 생산, 일정, 날씨, 저장을 한 번만 확정하는 트랜잭션 경계다.

1. 아침 정보날짜 · 날씨 · 예보 · 생일 · 에너지
2. 우선순위밭, 동물, 주민, 낚시, 광산 중 선택
3. 활동시간·에너지를 아이템과 경험으로 교환
4. 전환가공 · 선물 · 기부 · 번들 · 보관
5. 정산출하 · 제작 완료 · 관계 · 해금
6. 다음 날성장과 변화가 보이고 새 계획이 생김
Visual inventory

필요한 콘텐츠 면적

현재 준비된 독자 이미지 방향. 각 카드는 고립된 메뉴가 아니라 동일한 아이템·시간·목표 상태를 공유해야 한다.

Seven pillars

조사된 7개 핵심 축

공식 기능 목록과 현행 시스템 설명에서 반복적으로 확인되는 구조다.

01

하루 · 에너지 · 수면

제한된 시간과 에너지가 선택을 만들고, 수면/정산/저장이 하루를 닫는다.

02

계절 · 달력 · 날씨

28일 계절, 생일, 축제, 비가 작물·물고기·채집·NPC·상점의 가능성을 회전시킨다.

03

농사 · 동물 · 가공

심기→돌보기→수확/생산→가공→판매→재투자가 점차 자동화되고 확장된다.

04

마을 · 관계 · 일정

주민의 실제 동선, 대화, 선물 취향, 생일, 관계 이벤트가 마을을 살아 있게 만든다.

05

낚시 · 채집 · 광산

농사 밖의 활동이 계절과 장소를 탐색하게 하고 아이템·스킬·경제로 다시 합류한다.

06

번들 · 박물관 · 도감

서로 다른 활동의 결과를 장기 성취와 세계 변화로 변환해 비선형 플레이에 방향을 준다.

07

건물 · 집 · 꾸미기

효율 개선만이 아니라 플레이어의 시간이 공간에 남는 개인화 피드백이다.

＋

스킬 · 제작 · 해금

모든 반복 행동이 숙련, 레시피, 도구, 직업 선택으로 장기 성장에 기여한다.

생활의 목적과 흐름

농장 생활농사·작물 + 동물 + 설비 + 건물
마을과 인연주민 관계 + 일정 + 생일 + 선물 + 이벤트
계절과 세계달력 + 날씨 + 축제 + 물고기/채집 출현
수집과 성취번들 + 박물관 + 도감 + 세계 해금
성장과 경제스킬 + 제작 + 업그레이드 + 출하

Delivery map

다음 구현 순서

넓게 늘리기보다 먼저 하루의 생명력을 만들고, 그다음 선택을 장기 목표에 수렴시킨다.

P1 · WORLD FEELS ALIVE

세계가 살아 움직이게

  1. 결정론적 일일 날씨와 예보
  2. 달력·생일·NPC 일정과 참조 무결성
  3. 동물 종·축사·수용량·먹이·교감·생산
  4. 하루 전환·저장·재로드·런타임 UI 통합
P2 · CHOICES BECOME GOALS

선택이 성취로 모이게

  1. 계절/시간/날씨 기반 낚시
  2. 계절 채집물 생성과 재생성
  3. 발견·출하·포획·기부 통합 도감
  4. 박물관 1회 기부와 이정표 보상
  5. 농장 건물 배치/업그레이드와 집 꾸미기
Quality gates

완료의 기준

기능이 “있다”보다 중복·손실 없이 하루와 저장을 통과하는지가 중요하다.

결정론예보·낚시·채집 미리보기는 플레이 RNG를 소비하지 않는다.
정확히 한 번성장·정산·생산·기부·보상이 재호출로 중복되지 않는다.
원자성인벤토리/돈 부족·초과 시 절반만 반영되는 상태가 없다.
참조 무결성ID rename/delete/repair/load/save가 모든 저작 참조를 함께 다룬다.
시각 검증1024×768과 1440×900에서 실제 조작과 스크린샷을 남긴다.
원격 정본저작 콘텐츠는 Supabase 저장 후 project id 재로드로 증명한다.
