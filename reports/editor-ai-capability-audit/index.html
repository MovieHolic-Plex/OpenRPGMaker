Recommended use

지금 가장 성공률 높게 쓰는 법

사용자가 도구 이름을 반드시 알 필요는 없지만, 요청을 “생성 → 검증 → 플레이 → 저장 재로드” 단계로 나누면 실패를 발견하기 쉽다.

🏠 집

  1. 위치·크기·외관과 “출입 가능한 별도 내부”를 명시한다.
  2. author_house 또는 마을 고수준 경로로 초안을 만든다.
  3. 문 앞 플레이 → 내부 진입 → 같은 문으로 복귀를 확인한다.
  4. 저장 후 프로젝트를 다시 불러와 전송 쌍을 재검사한다.
주의: 내부방 저수준 파이프라인만 단독 호출하는 경로는 현재 입구 이벤트 회귀가 있다.

📜 퀘스트

  1. author_story_arc / define_quest로 목표·선행조건·보상을 구조화한다.
  2. lint_quest와 generate_walkthrough를 실행한다.
  3. verify_quest 및 run_scene_test로 시작부터 보상까지 재생한다.
  4. 이벤트 페이지를 검수하고 저장·재로드한다.
주의: 복잡한 다중 페이지를 upsert_event 한 번에 맡기고 성공 메시지만 믿으면 안 된다.

🗺️ 한 맵 꾸미기

  1. 크기·분위기·시설 수·인구·동선을 먼저 계획한다.
  2. author_village로 큰 구조를 만든 뒤 길·물·식생·소품을 보강한다.
  3. show_map_region, run_lint, 구조 QA로 겹침과 막힘을 잡는다.
  4. 마지막 미감·밀도·랜드마크는 사람이 화면으로 조정한다.
주의: 자동 평가 통과는 “예쁘다”가 아니라 “구조적 오류를 덜 찾았다”는 뜻이다.

Failure ledger

숨기면 안 되는 빨간불 6 + 2

구조 테스트 6건과 E2E 2건의 실패를 성격별로 분리했다. 기준선 전체가 아니라 이번에 직접 실행한 선택 묶음이다.

집/내부 — 3건
  • 잘못된 wing을 막아야 한다는 테스트가 예상과 달리 성공.
  • 내부방 파이프라인에서 이름이 “입구”인 이벤트가 없음.
  • 주민 방 kit에서도 같은 “입구” 이벤트가 없음.

영향: 고수준 마을 집 왕복은 통과했지만 직접 내부방 제작의 안정성은 낮춰 판정했다.

퀘스트 — 1건 + E2E 1건
  • 예제 게임의 등록 적 5종 중 enemy_slime이 부대에서 미사용.
  • 저수준 UI proof가 quest-giver 이벤트를 찾지 못해 90초 타임아웃.

영향: 그래프 엔진 자체보다 “에디터에서 한 번에 저작해 보이는 경로”가 현재 약하다.

맵/라우팅 — 2건
  • variant map 없는 lay_path를 거부해야 한다는 guard 기대와 실제 동작이 어긋남.
  • 다중 도메인 요청에서 build_house_kit이 라이브 노출 도구 집합에서 밀려남.

영향: 전문 저수준 도구보다 author_village / author_house 같은 고수준 진입을 우선해야 한다.

AI UI — E2E 1건

공급자별 “OpenAI Codex 연결됨” 문구를 5초 안에 기대했지만 일시적으로 일반 “AI 연결됨”만 노출됐다. 수동 브라우저 확인에서는 잠시 뒤 공급자 문구가 보였다.

영향: 기능 자체보다는 비동기 상태 라벨/테스트 타이밍 회귀로 보인다.

AGY

AGY와 “에디터 모델 공급자”는 같은 것이 아니다

현재 화면에서 확인한 내장 AI 공급자는 OpenAI Codex OAuth다. AGY bridge는 외부 에이전트가 같은 에디터 채팅/상태를 조작하는 연결 통로이며, 그 자체가 에디터의 LLM 공급자는 아니다. 이전 실측에서는 bridge ping/status가 살아 있었지만, 에디터의 Google Antigravity 공급자는 로그인 상태가 아니었다.
