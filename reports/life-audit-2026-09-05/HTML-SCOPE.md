## 구현 범위와 편집 방향

- 보고서 디렉터리 안의 `DESIGN.md`, `index.html`과 필요한 보고서 전용 파일만 작성한다.
- 기존 `AUDIT.md`, `RUNTIME.md`, `EXECUTION.md`를 승인된 사실 원장으로 사용한다.
- 제품 소스·테스트·설정·게임 데이터·원격 프로젝트·기존 증거 PNG는 수정하지 않는다.
- 새로운 프레임워크·런타임 의존성·외부 폰트/CDN 없이 `file://`로 열린다.
- 기존 PNG의 상대 경로를 사용한다. 이미지를 CSS 배경 장식으로만 숨기지 않는다.
- 편집형 감사 문서: 밝은 종이색, 짙은 본문, 붉은 판정 표식, 초록의 실측 표식,
  큰 결론과 잘 읽히는 본문, 실제 화면을 중심으로 구성한다.
- 서체·색·간격·반응형·그림·표·경고·링크를 보고서 전용 `DESIGN.md`에 먼저 고정한다.
- 설명 도식은 실제 캡처와 구분한 SVG 또는 HTML/CSS로 만든다.
  최소한 "저작→소비자→플레이" 연결과 "하루 전환"을 설명한다.
- 목차, 핵심 결론, 심각도순 발견사항 13개, 실측 이야기, 7개 탭 판정,
  51개 하위 기능의 전체 상세, 테스트·이력·한계·인용이 포함되어야 한다.
- 실제 스크린샷을 최소 14장 표시하고, 원본을 열어 확인할 수 있게 한다.
  빈 상태와 기존 원격 저장본, 표시만 확인과 행동 실행을 구분한 캡션을 붙인다.
- 그림과 표는 좁은 화면에서도 본문을 밀어내지 않는다. 모든 내용을 숨겨서 통과하지 않는다.
- 모바일 보고서 폭 375px은 보고서의 반응형 요구이며 원래 편집기의 지원 범위를 뜻하지 않는다.
- 순수 산문을 고정하는 테스트를 만들지 않는다.

## 순차 mass-ulw 실행

하나의 HTML 파일은 여러 편집자가 동시에 수정하지 않는다.
기존 자료의 사실·문구와 편집 구성이 긴밀하므로 HTML 구현은 한 노드에 맡긴다.

1. `visual-engineering`: 디자인 계약과 완전한 HTML 구현, 실제 브라우저 자체 확인.
2. `deep`: 앞 노드에 의존해 승인된 감사 원장과 HTML을 대조하는 읽기 전용 검증.
   7개 탭·51개 행·13개 발견사항의 보존과 증거 수준 과장을 확인한다.
3. 감독자: 375/768/1280px 브라우저에서 전체 섹션·이미지·내부 링크·넘침을 직접 검증.
4. 커밋·PR 생성 후 ultrabrain 최종 검토. 수정 요청은 독립 항목별 격리 deep 작업으로
   나누고, 통합 결과를 다시 검토한다. 승인 전 병합하지 않는다.

## 사실과 검증의 한계

집중 테스트는 406 통과/4 실패, 전체 게이트는 30분 timeout이다.
이 보고서 때문에 제품 코드가 바뀐 것은 아니다. 시각 판독 도구의 기존 한계는
출하 화면의 깨짐/정상을 추측할 허가가 아니다. HTML의 레이아웃은 새 실제 브라우저에서
검사하고, 이미지 판독이 가능한 경로가 없다면 그 검증 한계를 정확히 남긴다.
