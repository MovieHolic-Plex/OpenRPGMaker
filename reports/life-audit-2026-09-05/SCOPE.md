# 생활 실동작 적대적 감사

## 최상위 목표

데이터베이스 생활의 모든 탭을 현재 소스와 실제 실행 증거로 판정하고,
작동 조건·끊긴 연결·미검증 범위를 스크린샷과 함께 보여주는 한국어 HTML 보고서를 제공한다.
보고서는 기능 소개가 아니라 사용자가 어떤 기능을 믿고 게임을 만들 수 있는지 결정하는 감사 자료다.

  현재 실행 결과와 분리한다. 위키와 탐색 에이전트의 요약도 소스 및 실제 실행으로 재확인한다.

## 판정 기준

각 하위 기능은 편집 UI, 저작 데이터 위치, 저장/로드, 런타임 소비자, 플레이 진입 조건을 연결한다.
증거 수준은 현재 브라우저 실행, 현재 자동 테스트, 정적 연결 확인, 과거 기록, 미검증으로 구분한다.
테스트 통과를 전체 플레이 성공으로, 빈 기본 데이터를 기능 미구현으로, 저장 가능한 필드를
플레이 효과가 있는 필드로 바꾸어 표현하지 않는다.

적대적 질문은 다음과 같다.

1. 데이터베이스에 값을 넣는 것만으로 게임에 효과가 생기는가?
2. 이벤트·시간·아이템·세션 연결이 없으면 어떤 부분이 작동하지 않는가?
3. 성공·실패·재시도·날짜 변경·저장 재개에서 자원이 잘못 변할 수 있는가?
4. 동일한 이름의 축사 용량과 공간 배치 용량은 실제로 연결되어 있는가?
5. 기존 완료 보고서가 현재의 실제 플레이를 증명하는가?

## 단계 및 작업 경계

### Phase 1 — 전수 조사와 증거

- 전용 워크트리: `/home/main/z-project/rpg-zzu-life-audit-p1`.
- 브랜치: `agent/life-audit-p1`, 편집기 포트: `9841`.
- 병렬 수집: 농사·주민, 제작·경제·날씨, 동물·공간·낚시·채집·박물관.
- 각 수집 노드는 읽기 전용이며 근거 파일과 행, 실제 소비자, 반례를 반환한다.
- 합성 노드는 세 수집 결과와 감독자 실행 기록을 소비하여 이 디렉터리에 감사 자료를 작성한다.
- 검증 노드는 전체 탭/하위 기능 누락, 인용 오류, 증거 수준 과장을 검사한다.
- 감독자는 관련 테스트와 브라우저 실측을 직접 확인하고 `npm run gates` 결과를 보존한다.
- 커밋과 PR을 만든 뒤 ultrabrain이 전체 변경과 증거를 검토한다.
- 수정은 독립 가능한 항목별 deep 작업자와 격리 워크트리로 처리하고 통합 재검토한다.
- ultrabrain 최종 승인 이후에만 PR을 병합한다.

### Phase 2 — 이미지 리치 HTML

- Phase 1 병합 이후 그 통합 기준점에서 새 전용 워크트리를 만든다.
- 검증된 감사 자료를 HTML과 캡션·설명 도식으로 구성한다.
- 실제 스크린샷을 제품 동작 증거로 쓰고, 설명용 그림은 증거와 명확히 구분한다.
- 브라우저에서 모든 섹션·이미지·링크를 확인하고 375/768/1280px의 가독성과 넘침을 검사한다.
- 커밋과 PR 생성, ultrabrain 검토, 필요 시 격리 deep 병렬 수정과 통합 재검토를 반복한다.
- 최종 승인 후 병합하고 HTML 절대 경로와 PR/커밋 및 검증 한계를 전달한다.

## 범위와 실행 원칙

- HEAVY: 사용자가 단계별 적대적 검토와 승인 후 병합을 요구했다.
- 제품 코드 및 게임 콘텐츠를 수정하지 않는다. 기존 원격 프로젝트 데이터를 쓰지 않는다.
- 저작 범위는 보고서, 그에 포함되는 증거 이미지, 최소한의 감사용 실행 자료다.
- 본 세션의 `WISH.md`와 타인의 워크트리 및 변경은 건드리지 않는다.
- 산문을 고정하는 테스트를 만들지 않는다. 실행 불가·기존 실패는 그대로 기록한다.
- 런타임 검증은 `player.html`을 사용하는 전용 하네스 경로만 사용한다.
- ulw-loop 상태: 원래 작업 폴더의 `.omo/ulw-loop/life-audit-20260905/`.
- 위상 순서와 병합 승인 조건은 마지막 단계까지 유지한다.
