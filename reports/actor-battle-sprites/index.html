이 스프라이트가 화면에 나오는 건 사이드뷰(rm2003) 스킨에서만이다. 포켓몬식 스킨은 뒷모습 구도라 이 시트를 버리고 공용 폴백을 쓴다.

3. 시트 해부 — 24칸 중 3칸만 산다

알파 픽셀 실측 — 48×48 셀당 불투명 픽셀 수

시트행 0 · 열 0행 0 · 열 1행 0 · 열 2행 1~7 (21칸)
hero-01-battle1,1326581,025전부 0
hero-02-battle1,0557531,093전부 0
hero-03-battle1,0931,041977전부 0
hero-04-battle1,028638966전부 0
규격과 내용이 어긋난다. 자산 계획서는 "3x8 battle sheet" 로 약속하고 파일도 384px 높이로 만들어 놨는데 행 1~7 은 전부 투명이다. 렌더러도 backgroundPosition 의 Y 를 항상 0 으로 두므로 (src/player/battleFieldDom.ts:336) 애초에 아랫행을 읽지 않는다. 파일의 약 7/8 이 빈 공간이고, 8행짜리 포즈 확장은 미완인 상태다.

프레임 ↔ 포즈 매핑 — applyBattlerPose, battleFieldDom.ts:322-338

런타임 pose읽는 열소스 좌표화면 크기
idle · defend0(0, 0) — 48×4848px × BATTLE_ASSET_PIXEL_SCALE 2 = 96 논리px
rm2003 에서 scale(1.25) → 120 논리px
attack1(48, 0) — 48×48
hit · dead2(96, 0) — 48×48

defend 는 전용 프레임이 없어 idle 을 재사용하고, dead 도 hit 프레임을 쓴다. 기절 표현은 프레임이 아니라 .defeated CSS 페이드가 담당한다.

4. 스킨에 따라 보이거나 안 보인다

rm2003 — "군청 창 · 사이드뷰" (기본값)

저작한 시트를 쓴다

partyFacing: "front" 이므로 battleCharacterResourceId 를 최우선으로 쓴다. 노드에 data-authored-battler="true" 가 붙고 94×96 박스에 심긴다.

pokemon — "흰 창 · 박스 HUD"

시트를 버리고 폴백

partyFacing: "back" — 뒷모습 구도가 필요해 저작 시트를 무시하고 bskin-ally-creature-back 공용 스프라이트로 폴백한다. 파티에 몬스터(speciesId)가 있으면 그 종족 그래픽이 대신 뜬다.

스킨 선택 위치 — 자료집 → 시스템 → 전투 UI 스타일 (system.battleUiStyle). 미설정이면 rm2003. 판정 코드는 src/player/battleFieldDom.ts:567.
