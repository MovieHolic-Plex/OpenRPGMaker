OR·NOT 묶음 조건 저작 + 겹침을 우선순위와 한 묶음으로

이벤트 페이지 조건을 UI 로 만들면 지금까지 무조건 AND 였다. 런타임은 처음부터 all/any/not 을 평가했는데 편집기에 만드는 길이 없었다. 그 길을 냈고, 같이 거짓말하고 있던 「겹침 금지」 체크박스를 판정 조건과 한 칸에 묶었다.

02왜 AND 밖에 없었나

조건 타입은 처음부터 13종 leaf + 묶음 3종(all/any/not) 이었고, 런타임 src/project/io/pageResolution.ts 의 evalPageCondition 은 묶음을 재귀로 평가해 왔다. 즉 기능은 있었고 저작 수단만 없었다.

편집기 쪽 걸림돌은 UI 가 아니라 자료 접근 방식이었다. 조건 변경 함수가 «목록에서 n 번째» 라는 평면 인덱스만 받았기 때문에, 묶음 안의 하위 조건을 가리킬 표현이 없었다. 그래서 화면을 그릴 수는 있어도 «OR 묶음의 두 번째 하위의 값을 3 으로» 같은 변경을 표현할 수 없다.

// 전 — 목록의 n 번째만 가리킬 수 있다
replaceCondition(context, index, next)

// 후 — 경로로 임의 깊이의 노드를 가리킨다
export type ConditionPath = readonly number[];
replaceConditionAtPath(context, [2, 0], next)   // 3번째 조건(묶음) 의 첫 하위
appendConditionAtPath(context, [2], child)      // 그 묶음에 하위 추가
removeConditionAtPath(context, [2, 1])
이게 먼저였다
경로 API 없이는 묶음 편집기를 «그릴» 수는 있어도 «쓸» 수 없다. 그래서 이 PR 의 실제 핵심은 화면이 아니라 pageConditionModel.ts 의 재귀 갱신이다.

03묶음 조건 화면

아래는 실제 편집기에서 UI 로만 만든 조건이다. «의뢰 수락이 켜졌거나, 소지금이 기준 이상이거나, 의뢰 수락이 켜지지 않았을 때» — 이 문장은 이전 버전에서는 표현이 불가능했다.

좁은 레일에서 읽히게 하려고 손본 것들:

  • 연산자를 라벨 앞으로. «하나 이상 만족» 이 아니라 OR 묶음: 하나 이상. 233px 폭에서 select 가 잘려도 앞의 AND/OR/NOT 은 살아남는다. 첫 촬영에서 «묶음: 하나 이…» 로 잘려 있었다.
  • 버튼 폭을 라벨에 맞춤. 고정 98px/66px 컬럼 때문에 «조건 추가» 가 «건 추가» 로 잘렸다. grid-template-columns: minmax(0,1fr) auto 로 교체.
  • 묶음 머리를 2행 grid. 1행 = 종류 select + 삭제, 2행 = 요약. 한 줄에 셋을 넣을 폭이 없다.
  • 중첩은 한 단계까지만 제시(MAX_GROUP_DEPTH = 2). 마지막 깊이의 종류 목록에서는 묶음을 빼서 더 깊이 못 들어간다 — 들여쓰기가 안 읽히기 때문.
빈 묶음은 조용히 거짓말한다
하위가 없는 all 은 항상 참, any 는 항상 거짓으로 평가된다. 저작자는 «아직 안 채웠으니 아무 영향 없겠지» 라고 읽는다. 그래서 (1) 새로 만들 때 하위 하나를 심고, (2) 그래도 비면 칸 안에 «하위 조건 없음 — 이 묶음은 항상 참/거짓» 이라고 적는다.

04겹침 체크박스가 하던 거짓말

런타임 통행 차단 조건은 src/project/runtimeEventState.ts 네 곳에서 동일하다:

event.priority === "same" && event.overlapForbidden

그런데 편집기에서 우선순위는 「언제」 그룹, 겹침은 「겹침과 통행」 그룹에 떨어져 있었다. 판정의 절반이 다른 방에 있으니 «겹침 금지를 켰는데 그냥 지나간다» 가 나온다. 우선순위를 겹침 옆으로 옮기고, 조건이 성립하지 않을 때는 체크박스를 잠갔다.

그룹 접힘 요약도 실제 판정을 말하게 했다. 같은 층이면 겹침 금지/겹침 허용, 아니면 맵 아래 · 통행 허용 — 접어둔 상태에서도 오해가 생기지 않는다.

07커밋에 넣지 않은 것

이 워크트리는 다른 세션과 공유 중이다. openwiki/editor-event-authoring.md 에 쓴 계약 문서 두 절(「묶음 조건(all/any/not) 저작」, 「우선순위와 겹침은 한 묶음」)은 커밋하지 않았다 — 같은 파일에 다른 세션이 아직 커밋하지 않은 코드의 문서가 스테이징돼 있어서, 파일 단위로 커밋하면 존재하지 않는 코드의 문서를 함께 싣게 된다. 내용은 워크트리에 남아 있어 다음 커밋에 자연히 실린다.

08다음에 할 만한 것

  • 묶음 요약을 한 줄 논리식으로. 지금은 «하나 이상 만족: 첫 하위 외 2개» 다. 접힌 상태에서 전체 논리를 읽으려면 A ∨ B ∨ ¬C 급의 압축 표기가 낫다.
  • 두 단계 이상 중첩. 지금은 폭 때문에 막았다. 넓은 편집 창(모달) 에서는 풀 수 있다.
  • 겹침 외 다른 «조건부 무의미» 설정 감사. 이번에 고친 건 한 쌍뿐이다. 같은 병 (다른 필드 값에 따라 죽는 컨트롤이 살아 보이는) 이 다른 그룹에도 있는지 훑을 가치가 있다.
