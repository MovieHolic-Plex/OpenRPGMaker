01무엇이 없었는가

먼저 코드를 읽고 엔진과 표면을 갈랐다. 다섯 항목 모두 "기능이 없다" 가 아니라 "기능은 도는데 사람이 그것에 닿을 수 없다" 였다. 가장 뚜렷한 증거는 loadConversation · searchConversations 였다 — 구현이 다 돼 있는데 호출 지점이 0 인 죽은 코드였다.

#기능이전 상태이 작업
1맥락 게이지 + 수동 압축 압축 엔진은 매 턴 돌지만 화면에 아무것도 없음. 남은 여유를 묻거나 미리 압축할 방법 없음 컴포저 게이지 1개 + 팝오버(지금 압축 · 압축 되돌리기 · 요약 원문 · 사용량)
2이전 대화 이어가기 저장은 매 턴 돌고 로드 함수도 있으나 호출 지점 0. 부팅 시 자동 복원만 남음 목록·검색·삭제 모달 + 기록을 새 세션에 실제로 주입
3감독 지침 항구적 규칙을 둘 자리가 없어 새 대화마다 사람이 다시 타이핑 project.aiInstructions → 시스템 프롬프트의 예산 밖 고정 섹션
4턴 되감기 없음. 잘못된 지시를 되돌리려면 Ctrl+Z 를 몇 번 눌러야 하는지 사람이 추측 사용자 버블의 「여기서 다시」 — 대화 + 그 턴의 프로젝트 편집을 함께 되돌림
5사용량 집계 감사 로그 문자열을 정규식으로 긁어 합산 (출력 토큰만, 요약·플래너 콜 누락) 세션의 chat 호출을 한 곳에서 감싸 모델별 호출/입력/출력 집계

02맥락 게이지와 수동 압축 신규 표면

게이지는 컴포저 액션 행의 28px 칩 하나다. 이 위치를 고른 이유는 두 가지다. 첫째, "바 높이 = f(textarea 줄 수)" 라는 컴포저 불변식을 지켜야 한다 — 팝오버는 흐름 밖에 있으므로 열려도 바가 커지지 않는다. 둘째, 가로 스크롤되는 컨텍스트 칩들 앞에 뒀다. 뒤에 두면 좁은 도크에서 꼬리표가 길어질 때 게이지가 스크롤 밖으로 밀려 사실상 사라진다.

맥락 11% 110,869 / 1,048,576 토큰 (11%) 자동 압축 임계 1,032,192 토큰 로컬 추정 110,869 토큰 (과금 계량 없음) 지금 압축 이 대화의 사용량 아직 요청 없음

실측: 창 1,048,576 토큰 중 110,869 사용(11%), 자동 압축 임계 1,032,192. 첫 턴부터 11% 인 것은 시스템 프롬프트 (능력 색인 포함)의 크기다. 톤 3단계(idle / near / warn)의 기준은 창 크기가 아니라 자동 압축 임계다 — 사람이 보는 색과 앱이 압축을 결정하는 선이 어긋나면 게이지는 거짓말이 된다.

수동 압축은 자동 압축과 설정이 다르다. 임계·턴 회로차단기를 무시하고 한 번은 시도하며(사람이 명시로 눌렀다), 잔존 창을 20,000 → 6,000 토큰으로 좁힌다. 자동 설정을 그대로 쓰면 중간 크기 대화에서 잘라낼 앞부분이 없어 "눌렀는데 아무 일도 없음" 이 된다.

03이전 대화 이어가기 죽은 코드 부활

loadConversation 과 searchConversations 는 호출 지점이 0이었다. 감독 콘솔 전환에서 시작 화면의 '이어가기' 버튼과 기록 검색 카드가 함께 사라졌기 때문이다. 목록·검색·삭제 모달로 그 조합을 되살렸다.

그리고 복원은 「화면만」 복원이었다. 복원 경로는 dropSession 을 지나 다음 세션이 시스템 프롬프트 하나로 시작한다 — 사용자에게는 이어진 것처럼 보이는데 모델은 직전 턴을 모른다. 이어가기를 붙이면서 이것도 고쳤다.

conversationReplay 가 감사 기록을 한 덩어리로 직렬화해 새 세션의 priorTranscript 로 주입한다. 주입 형태는 role:"user" + [restored-conversation] 마커 — 압축 요약이 이미 쓰는 검증된 안전 지대다. tool_calls 짝을 재구성하는 쪽은 짝이 하나만 어긋나도 Gemini/Cloud Code Assist 에서 400 이다. 주입문에는 "이미 지나간 일이므로 다시 실행하지 마라" 를 함께 넣는다.

04감독 지침 신규

"이 게임은 4방향 이동만 쓴다" 같은 항구적 규칙을 담을 자리가 없어, 사람이 새 대화마다 다시 타이핑했다. 저장 위치는 프로젝트 JSON 이다(localStorage 아님) — 지침은 그 게임의 성질이고 프로젝트를 옮기면 따라가야 한다. aiInstructions? 는 optional 필드라 마이그레이션이 없다(aiDocuments?·quests? 선례).

예산 밖에 넣은 것이 이 기능의 핵심이다. 시스템 프롬프트에는 문자 예산(DEFAULT_BUDGET_CHARS)이 있고 tokenBudget 보정이 그 값을 더 줄일 수 있다. 지침을 예산 안에 두면 긴 세션에서 통째로 잘려 규칙이 조용히 사라진다 — 능력 색인을 예산 밖에 둔 것과 같은 이유다. 압축·새 대화·대화 복원에도 남는다.

// src/ai/contextBuilder.ts — 조립의 마지막 두 단계

05턴 되감기 신규

대화만 자르면 그 턴이 맵에 깔아 놓은 타일은 남는다. 그래서 턴 시작 직전의 히스토리 마커를 잡아 두고 revertToHistoryMarker 로 그 시점 이후 스냅샷을 한 번에 되돌린다. 인덱스가 아니라 마커인 이유는 MAX_HISTORY 를 넘길 때 stack 이 shift 되어 인덱스가 흔들리기 때문이다.

되돌릴 편집이 없으면 그 사실을 말한다. revertToHistoryMarker 는 마커 이후 스냅샷이 없으면 false 를 돌려주고, 패널은 그때 "대화만 되감았다" 로 문구를 바꾼다. 조용히 반쪽만 되감는 것이 가장 나쁘다. 지시 텍스트는 입력창으로 되돌려 놓아 고쳐 다시 보낼 수 있게 한다.

06사용량 집계 — 그리고 비용을 안 쓴 이유

하네스 모달은 사용량을 감사 로그 문자열에서 /출력 토큰 ~(\d+)/ 로 긁어 합산하고 있었다. 출력 토큰뿐이고, 요약·플래너 콜을 통째로 빼먹고, 문구를 한 글자 고치면 조용히 0 이 된다. 세션의 chat 호출을 한 곳에서 감싸 모델별 호출 수/입력/출력을 센다(요약 콜 포함).

의도적 이탈 — 비용(USD)은 표시하지 않는다. 실제로 붙는 두 연결은 Codex(ChatGPT 구독)와 Antigravity(Google 구독)로 둘 다 구독제다. 토큰당 단가가 존재하지 않으므로 단가표를 박으면 근거 없는 숫자를 감독에게 파는 것이 된다. 대신 모델별 호출 수 · 입력 토큰 · 출력 토큰을 보여준다. usage 를 안 주는 응답은 callsWithoutUsage 로 따로 세어 "0" 과 "모름" 을 가른다.

캡처에서 「아직 요청 없음」인 것은 진단 환경이 없는 호스트로 요청을 보내 응답 자체가 없었기 때문이다 — 이것도 정직한 표시다.

07화면에서만 드러난 결함 3건 수정

단위 테스트 76건이 전부 초록인 상태에서 실제 브라우저로 표면을 하나씩 눌러 봤다. 셋이 깨져 있었다. 셋 다 DOM 은 맞고 CSS 가 지우거나 늘리는 결함이라, 스타일시트를 읽지 않는 fakeDom 테스트로는 잡히지 않는 종류다.

7-1. 기본 도크에서 메타 메뉴로 갈 길이 없었다 도달 불가

컴포저 ☰ 는 "유리·사이드는 헤더(더보기/설정)를 가지고 있으니 중복" 이라는 근거로 display:none 이었다. 그런데 그 헤더 밴드는 2026-08-28 에 통째로 폐기됐고 .ai-chat-toolbar 는 hidden + inert + is-empty 인 테스트 훅 컨테이너로만 남아 있었다.

실측 2026-08-30 (기본 도크 = 유리, 사이드 동일) 헤더 ☰ [data-testid=ai-more-menu-toggle] display: inline-grid, rect 0×0 ← 부모가 hidden 컴포저 ☰ [data-testid=ai-command-menu-toggle] display: none ← CSS 로 숨김 ⇒ 「이전 대화」·「감독 지침」에 닿을 수 있는 표면: 0개

즉 이번에 붙인 항목 중 둘은 기본 설정에서 도달 불가였다(맥락 압축만 게이지 팝오버로 살아 있었다). 낡은 근거의 규칙을 걷어 컴포저 ☰ 를 세 도크 모두에서 되살렸다. 추천 팝오버·설정 버튼은 중복이 맞으므로 그대로 숨긴다.

7-2. 두 새 모달이 가로 3열로 늘어섰다

모달 껍데기를 재사용하려고 database-modal-body 를 붙였더니, sidebar.css 의 .database-modal-backdrop .database-modal-window .database-modal-body (특이도 0,3,0)가 display:flex; flex-direction:row 를 박았다 — DB 스튜디오 사이드바 레이아웃 전제다. 감독 지침은 [안내][입력][카운터][저장] 이 나란히 서고, 이전 대화는 [검색][안내][목록] 이 3열이 됐다. 그 클래스를 떼고 본문 스타일을 직접 갖췄다 — 행 배치 전제는 DB 스튜디오 것이고, 이 모달은 DB 스튜디오가 아니다.

7-3. 같은 모달이 화면 높이를 다 먹었다

.database-modal-window 는 height: min(820px, 100vh - 24px) (database/desktop.css, @media (min-width: 800px))라서 목록 3줄짜리 창이 620~820px 로 늘어났고, 그리드 기본값 align-content: stretch 가 남는 높이를 행에 나눠 넣어 검색 입력 하나가 200px 가 됐다. desktop.css 가 더 늦게 실려 같은 (0,1,0)으로는 못 이기므로, 창 클래스를 함께 물어 (0,2,0)으로 올리고 두 본문 그리드와 목록에 align-content: start 를 줬다.

감독 지침 창 높이 (실측) 수정 전 window 620px = max-height 에 걸린 값 (내용은 ~250px) body 594px → grid rows 128.6 / 300.7 / 124.7 ← stretch 가 늘림 수정 후 window 330px = 내용에 맞음 body 304px → note 32 / textarea 204 / footer 28

부수 수정: 이전 대화 목록의 제목에서 [컨텍스트] 현재 맵: … footer 를 뺐다. 패널이 붙이는 기계 텍스트라, 목록의 모든 줄이 같은 맵 이름으로 시작해 사람이 대화를 가를 수 없었다.
