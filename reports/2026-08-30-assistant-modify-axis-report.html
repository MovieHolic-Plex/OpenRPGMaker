사용자가 본 것

"에디터 내의 조수에게 수정을 요구하면 맵을 아예 새로 만들어버린다"

요청

이 마을 담장이 엉망으로 깔렸어.
새로 만들지는 말고 지금 있는 것만 손봐줘.

[컨텍스트] 현재 맵: 잿불 마을 (map_ember_village)
         · 사용자 선택 영역: (2,2) 10×8

요청문에 신규 금지가 명시돼 있고, 대상 맵 id 도 footer 로 붙어 있다.

일어난 일

  • 플래너가 successTools=["author_village"] 항목을 만든다 — author_village 는 houseCount 최소 1 이라 "담장 수정" 항목이 집 최소 1채 신축을 완료 조건으로 갖는다.
  • 생성기가 그 조건을 만족시키려면 신축을 해야 한다. 새 맵을 만들어 거기에 짓는다.
  • 완료 게이트는 통과한다 — successTools 이름 매칭이 전부 맞았다.
  • 승인 카드는 마찰 없이 지나간다 — 파괴성 판정이 툴 이름 목록이라 "새로 만들기"는 파괴가 아니다.
  • 지목된 맵은 그대로 남는다. 사용자 눈에는 "새 맵이 하나 생겼다".
핵심: 모델이 지시를 무시한 것이 아니다. 하니스가 "신축을 해야 항목이 완료되는" 상태로 계획을 만들어 줬고, 모델은 그 계약을 충실히 따랐다.

결정 2건 · 남은 것

봐 주셔야 할 판단과, 손대지 않은 것

봐 주셔야 할 결정

  • 예산 12,000 → 13,200. 요청당 비용이 조금 오른다. 유지하면 초과분을 밸런스 상수·리소스 조회·집 키트·클러스터 규칙 섹션을 통째로 버려서 메꾼다 — 수정 축을 넣은 대가로 다른 지침이 조용히 사라지는 교환이라 예산을 올렸다.
  • 드롭 순서 변경. "내 구조물"을 정적 조언 뒤로 옮겼다. 파일이 스스로 적어 둔 원칙("값싼 정적 조언부터 버린다")과 실제 순서가 어긋나 있었다.

남은 것 (이 PR 밖)

  • pageItemCondition 실패 — HEAD 자체 회귀. 조수 띠 작업 쪽에서 봐야 한다.
  • evaluate_interior_room 은 여전히 sessionId 필수다. 복원 세션이 프로젝트에 저장되므로 furnish_interior_space 한 번 뒤에는 잡히지만, mapId 직접 지원이 더 깔끔하다.
  • 실제 LLM 게이트(RPG_ZZU_AI_MAP_EDIT=1)는 이 세션에서 돌리지 않았다 — 키가 필요한 라이브 호출이라 env 게이트로 남겼다.
  • 루트 tsconfig 의 aiSpecGate authMode 오류 18건은 기존 상태 그대로다(게이트는 tsconfig.app.json).
