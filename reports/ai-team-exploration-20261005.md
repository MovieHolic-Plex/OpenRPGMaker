## 고친 문제

1. **Gemini HTTP 400:** `set_project_settings.fonts`의 `enum`에 빈 문자열이 있어 모든 조수의 도구 요청이 거절됐다. 문자열 스키마로 바꾸고 기존 역할별 폰트 검증·빈 문자열 초기화 계약은 유지했다. 실제 재실행에서 조수 요청 성공 확인.
2. **실패인데 “확인 완료”:** 변경이 없는 실패 실행이 정상 조회처럼 끝났다. 팀 보드의 실패를 최종 상태에 반영하고 “작업을 끝내지 못했어요. 프로젝트는 바꾸지 않았어요.”로 표시한다.
3. **팀 보고 누락:** 최상위 assistant 텍스트만 받아 `team_report`와 맵 배정 실패 이유를 놓쳤다. 보고 본문과 모든 실패 배정을 보존한다.

2·3은 실제 장애 기록을 입력한 **통제된 브라우저 응답 검사**로 확인했다. 이 검사는 실제 모델 재호출 성공 증거와 구분하며 `verify-shots/ai-team-failure-copy-probe/report.json`에 출처를 기록했다.

## 남은 개선점

### P1 · 맵 폴더가 저장·로드 검증에서 소실됨

`src/project/io/shapeReferenceFields.ts:4`의 `validateMapTree`가 폴더의 `kind`, `name`을 반환하지 않으며, 폴더 ID를 첫 실제 맵 ID로 바꾼다. `MapTreeNode` 타입은 폴더를 지원한다.

두 형제 맵을 담은 폴더가 `등대 → [등대, 부두]`로 바뀌었다. 등대 배정이 그 하위 부두까지 예약하므로 부두의 별도 배정이 거절됐다. 실행기의 맵 소유권 제한은 지켰지만 의도한 병렬성을 잃었다.

**제안:** 폴더를 검증·저장·재로드 전체에서 보존하고, 형제 맵의 소유권 범위가 겹치지 않는지 확인한다. 실제 SQLite 트리와 좁은 검증 함수 호출 결과를 함께 남겼다: `verify-shots/ai-team-exploration-findings/folder-roundtrip.json`.

### P1 · 번역 검수가 최신 원문을 오판해 의미를 파괴함

실행 03에서 저장된 활성 페이지: **“내일 등대는 오전 열 시에 엽니다.”**

실행 05의 제작 조수: **“The lighthouse opens tomorrow at 10:00 AM.”** — 의미를 보존했다.

검수 조수는 실행되지 않는 옛 최상위 명령 **“등대에 오신 것을 환영합니다.”**를 원문으로 삼았다. 팀장은 그 보고를 따라 수정 조수를 보내 최종 활성 페이지를 **“Welcome to the lighthouse.”**로 덮어썼다. 같은 SQLite 프로젝트 재로드에서도 이 손실을 확인했다.

`scripts/lib/piTeamRuntime.ts:421`의 읽기 작업은 현재 작업 사본을 받아 검수한다. 번역 직전 원문을 별도로 보존·전달하는 계약이 없다.

**제안:** 배정 시점 활성 페이지의 원문·ID·명령 구조를 불변 기준으로 보존하여 검수에 제공한다. `get_event`에서 실행되지 않는 legacy 명령을 명확히 표시하고, 원문 근거 없는 의미 수정은 적용하지 않는다.

근거: `verify-shots/ai-team-exploration-20261005-continued/report.json`의 `05-translation-reviewed` → `wire.events` → `reviewer-1`의 `agent_done`, 후속 `builder-3` 배정, `reloaded`.

### P2 · 조수 내부의 대사 보조 도구가 동반 서비스 연결을 이어받지 못함

실행 05에서 `event_command_assist`가 `fetch() URL is invalid`, `/v1` 연결 실패로 종료됐다. 조수는 다른 쓰기 도구로 회복했다. `src/editor/tools/asyncToolRunner.ts:54`는 기본 설정과 선택적인 `chat` 전달에 의존한다.

**제안:** 부모 실행의 실제 공급자·인증·chat 전송을 내부 생성 도구에 전달하거나, 해당 실행 환경에서 지원되지 않는 도구를 노출하지 않는다.

### P2 · 정상 대기를 무변경 반복으로 오판함

실행 05에서 조수가 아직 실행 중인데 `wait_agents`를 세 번 호출했다는 이유로 “이미 적용된 상태다…다음 할 일로 넘어가라”는 `repeat_guard`가 발생했다. `scripts/lib/piAgentRuntime.ts:649`는 도구 이름과 맵 변경 여부로 반복을 판정한다.

**제안:** `wait_agents` 같은 조정 도구는 조수 상태 진전으로 판단한다. 맵이 바뀌지 않았다는 사실만으로 대기 중인 일을 완료로 간주하지 않는다. 읽기·대기 도구의 반복 판단도 실제 상태와 연결한다.
