💀 핵심 UX 문제점 (치명적)

요약: "초보 유저는 이 AI를 쓸 수 없다"

  • 슬래시 명령어 진입점 - 유저가 "/" 를 치면 스킬 목록이 뜨는데, 첫 화면이 "맵 인터뷰", "클러스터 수정" 같은 개발자용 도구
  • 한국어 UI인데 기술 용어 범벅 - "author_house", "BuildSpec", "villager-room-v1 하네스" 가 유저에게 노출됨
  • 100개 넘는 도구 중 유저가 실제로 쓸 건 5개 이하인데, 도메인 스코핑이 자동이라 뭐가 되는지 예측 불가
  • 에러 발생 시 "spec-gate-auto-expand", "invalid-args" 같은 코드 에러가 UI에 그대로 노출
  • 작업 시간이 길다 - 마을 하나 짓는데 tool_call 100회 이상, 유저는 수 분을 기다려야 함
🚪

진입 장벽: API 키 필수

AI를 쓰려면 OpenAI API 키 또는 ChatGPT OAuth 설정이 필요. 설정 모달이 "base URL", "model" 같은 기술 용어 투성이. RPG 만들려는 중학생이 이걸 어떻게 하라고?

⏳

인터랙션 딜레이

"집 지어줘" 한 마디에: intent 분류 → spec 검증 → tool loop(10-50회) → proposal 생성 → 유저 승인 대기. 최소 30초~수 분. 게임 "만드는 재미"를 죽인다.

🤯

인지 과부하

Proposal 카드에 "기술 상세" 펼치면 raw tool name이 그대로. "author_house wings:[{x:3,y:2,w:8,h:7}]" 이게 유저에게 뭔 의미? before/after 썸네일은 좋지만 나머지는 개발자 디버그 로그 수준.

🔄

되묻기 지옥

"집 만들어줘" → "야외 집인가요 실내인가요?" → "야외요" → "크기는?" → "적당히" → 그제서야 작업 시작. 유저가 원하는 건 "대충 깔끔한 집 하나"인데 면접을 봄.

현재 UX (8단계)

  • 1. 패널 열기 (사이드 1/3 차지)
  • 2. 인증 설정 (API 키 or OAuth)
  • 3. 슬래시 명령어 검색
  • 4. 파라미터 입력 (가로/세로/재질/모양)
  • 5. 대기 (reasoning blocks 스트리밍)
  • 6. tool call 로그 보기 (의미불명)
  • 7. Proposal 카드 검토
  • 8. 승인 후 반영

이상적 UX (3단계)

  • 1. "마을 만들어줘" 입력
  • 2. 실시간 미리보기 확인
  • 3. "좋아" / "더 크게" / "나무 더 많이"
  • ---
  • 인증: 내장 or 원클릭
  • 파라미터: AI가 알아서 추론
  • 기다림: 프로그레스로 달래기
  • 승인: 맵 위 직접 확인 후 탭

🎮 게임성(Gameplay) 관점의 문제

이 AI가 "RPG 만드는 경험"을 얼마나 재밌게 만들어주느냐.

🎯

피드백 루프가 없다

게임 제작의 핵심은 "만들기 → 바로 플레이 → 수정"의 빠른 반복. 이 AI는 "만들기 → 30초 대기 → 카드 읽기 → 승인 → 다시 수정 요청 → 30초 대기".

결과: Flow 상태에 진입할 수 없다. RPG 만드는 게 재밌는 게 아니라 AI 관리가 된다.

🎨

창작 주도권 박탈

"author_house" 하나면 집이 뚝딱. 근데 유저가 결정한 건 "가로10 세로10 회벽"뿐. 지붕 모양, 창문 위치, 정원 배치는 전부 AI가 함. 유저는 결과물의 "소유감"을 느끼지 못한다.

📦

블랙박스 생성

AI가 만든 집/마을/던전이 내부적으로 어떤 타일을 어떻게 조합했는지 유저가 이해할 수 없음. 나중에 "이 벽만 좀 바꾸고 싶은데" → 어떤 타일인지 모름 → AI한테 또 물어봐야 함 → 의존성 심화.

🔐

Spec Gate = 자유도 감옥

AI가 뭘 하려면 무조건 BuildSpec을 먼저 제출해야 하고, 겹치면 거부됨. 유저가 "여기에 나무 좀 넣어" 하면 spec 검증 → 자동 확장 → 경고 → 유저 혼란. 안전장치가 UX를 잡아먹는 전형적 사례.

🗺️

"만드는 재미" vs "지시하는 재미"

RPG Maker의 핵심 재미는 "내가 직접 타일을 놓는 즐거움". 이 AI는 그 재미를 "텍스트로 지시하고 결과를 기다리는" 경험으로 대체함. 마인크래프트를 음성 명령으로만 하는 느낌.

🏆

성취감 설계 부재

AI가 다 해주니까 유저 성취감이 없음. "내가 마을을 만들었다" vs "AI가 마을을 만들었고 나는 승인 버튼을 눌렀다". 게이미피케이션(진척도, 배지, 레벨업) 요소 제로.

반론: "그래도 잘 되는 것들"

  • Ghost Preview - AI 작업 중 맵 위에 실시간 미리보기. 이건 진짜 좋다. 기다리는 동안이라도 뭔가 보인다.
  • Region Task - 영역 선택 후 "여기에 숲" 하면 바로 적용. 이게 메인 UX여야 하는데 보조 기능 취급.
  • Skill 시스템 자체 - /집, /마을, /던전 으로 원탭 시공은 아이디어가 좋음. 문제는 실행.
  • Soft-confirm 어휘 - 타일 재료를 "일단 쓰고 나중에 확정" 개념. 유저 관점에서 마찰 감소.

⚔️ 스킬 시스템 비판

유저가 실제로 보는 "/" 슬래시 명령어 목록과 그 문제점.

🎓

/맵 인터뷰 (advanced)

무엇: AI에게 타일 의미를 가르치는 도구
문제: 유저가 "내가 AI를 가르쳐야 한다"는 것 자체가 UX 실패. "AI가 모른다"를 인정하는 UI. advanced 태그가 있어서 검색해야 보이지만, 검색 안 해도 개발자 도구가 상위에.

🏠

/집 짓기

무엇: 가로/세로/재질/모양 설정 후 집 생성
장점: 직관적. 파라미터 폼도 깔끔.
문제: 폼에서 "위치(비우면 자동)"가 뭔 뜻인지 초보는 모름. 결과가 프롬프트 품질에 의존.

🏘️

/마을 생성

무엇: 테마/집수/NPC수 설정하면 마을 통째로
장점: "강가의 어촌" 한 줄이면 마을 생성 - 킬러 피처
문제: 시간이 너무 오래 걸림. 집 3채면 2-3분. 실패 시 전부 롤백.

🛏️

/실내 방 시공

무엇: 실내 맵 시공 (벽/바닥/가구)
문제: 파라미터가 5개(요구사항/가로/세로/벽재질/방수). "villager-room-v1 하네스"라는 용어가 설명에 노출됨. 뭔 소리인지 유저는 모름.

⛏️

/던전 시공

무엇: 용암/석재/얼음 테마 던전 방
장점: 테마 선택이 enum이라 선택만 하면 됨
문제: "위험지형" "다리" 같은 옵션이 뭘 만드는지 미리보기가 없음.

📐

/선택 영역 학습 (advanced)

무엇: 맵에서 선택한 부분을 AI에게 가르침
문제: "구조물을 템플릿으로 배운다"가 뭔 뜻? 유저는 "AI 훈련" 개념 자체를 이해 못함. 이건 개발자 도구다.

스킬 시스템의 근본 문제

  • 목록 상단이 "advanced" 도구 (인터뷰/클러스터 수정) - 정작 쓸 일 없는 게 눈에 먼저 들어옴
  • "advanced" 태그로 숨겼지만, 슬래시 검색에서는 또 보임 - 정보 계층이 일관되지 않음
  • 각 스킬의 buildPrompt가 Korean 프로시저 지침서 - AI에게 절차를 지시하는 텍스트가 800바이트+
  • 유저에게 보이는 displayAs는 기계적 - "🏠 집 짓기 - 10x10 plaster" 는 영감을 안 줌
  • 결과 미리보기/갤러리가 없음 - "이 스킬 쓰면 이런 게 나와요" 예시 이미지 0개

📐 레이아웃 & 공간 활용 비판

📏

Side Dock = 캔버스 33% 강탈

기본 모드가 "오른쪽 1/3 고정". 1920px 모니터 기준 480px을 AI 패널이 먹음. 맵 편집 캔버스가 좁아지면서 2D 타일 작업의 정밀도가 떨어진다. AI를 안 쓸 때도 공간을 차지.

🫥

Float Dock = 맵 가림

float 모드로 전환하면 캔버스 위에 뜨는데, 커맨드바가 맵 하단을 가린다. 결국 "어디에 둬도 불편"한 상황. 팝업형 AI가 아니라 상시 존재하는 어시스턴트라서 위치 설계가 어중간.

📱

반응형 미대응

max-width: calc(100vw - 16px) 이지만 실제로 1024px 미만 화면에서의 동작이 불명확. 태블릿에서 RPG Maker를 쓰는 시나리오가 고려 안 됨. 접힘(collapse) 상태의 44px rail이 모바일에선 터치 영역으로 불충분.

🗳️ Proposal(제안) 시스템 비판

AI의 작업 결과를 유저가 검토하는 핵심 UI.

✅

컨셉은 좋다

"AI가 바로 반영하지 않고 유저 승인을 받는다" → 안전. before/after 썸네일 → 시각적 확인. 체크박스로 부분 승인 → 유연성. 이 3가지 원칙 자체는 훌륭함.

🔍

썸네일이 너무 작다

변경 bbox 크롭이긴 한데, 전체 맵 스케일에서의 비교가 안 됨. "집이 생겼네" 까지는 보이는데 "집 위치가 길이랑 연결되나?" "문 앞이 막혀있진 않나?" 같은 디테일은 확인 불가.

📋

체크박스 = 의존성 폭탄

부분 승인 시 "이 집을 선택 해제하면 이 집 안의 NPC도 자동으로 해제됩니다" 같은 의존성을 시스템이 처리하긴 하는데, 유저는 그 로직을 이해 못함. 결국 "전체 승인" 아니면 "전체 거부"만 함.

⏱️

"완성도 경고" 의미불명

proposalCompleteness 린트가 "미이행", "세계관 미기록" 같은 경고를 카드에 띄우는데, 유저 입장에서 이게 심각한 건지 무시해도 되는 건지 판단 불가. 경고 피로감.

핵심 인사이트

  • RPG ZZU AI의 최대 강점은 "복잡한 작업을 한 번에" - 마을/던전/퀘스트 통째 생성은 수동 대비 압도적
  • 최대 약점은 "간단한 작업도 복잡하게" - 나무 하나 심는 것도 prompt → tool → proposal → approve
  • Cursor처럼 "인라인 제안 + Tab 수락" 패턴을 맵 에디터에 적용하는 게 이상적인 방향
  • "큰 건 AI, 작은 건 직접" 분리가 안 됨 - 모든 AI 인터랙션이 같은 무거운 파이프라인을 탐

🔧 기술적 품질 (인정할 건 인정)

비판만 하면 불공정하니까. 이 시스템의 엔지니어링은 솔직히 대단하다.

🚀

Zero-dependency LLM Client

OpenAI SDK 없이 raw fetch + 커스텀 SSE 파서로 구현. 어떤 OpenAI 호환 엔드포인트든 사용 가능. 번들 크기 최소화. 기술적으로 깔끔.

🏗️

Draft/Commit 패턴

AI 도구가 프로젝트를 직접 수정하지 않고 structuredClone 복사본에서 작업. 실패해도 원본 무손상. 동시 작업 충돌 없음. 데이터 안정성 최고.

📐

Spec Gate 검증

공간 배치 전에 규격 제출 → 겹침/경계 검증 → 통과 후 실행. AI 환각으로 인한 맵 파괴를 원천 차단. 안전장치로서는 이상적.

🧩

Domain-scoped Tool Exposure

턴마다 40개만 노출 + 의도 분석으로 도메인 자동 선택. LLM이 100개 도구에 혼란받지 않음. 토큰 절약 + 정확도 상승. 스마트한 설계.

🔄

Multi-phase Orchestration

plan(supervisor) → execute(lite) → review(supervisor) 3단계 모델 분리. 비용 절감 + 품질 관리 동시 달성. production-grade 설계.

🌐

MCP Bridge

외부 에이전트(Claude, Codex 등)가 같은 AI 세션을 HTTP로 쓸 수 있는 브릿지. 에코시스템 확장성. 다만 유저에겐 보이지 않는 기능.

💥 근본적 모순

이 AI 어시스턴트가 안고 있는 해결 불가능한 긴장.

🎭

"도구" vs "동료"

도구라면 예측 가능해야 하고, 동료라면 자율적이어야 한다. 이 AI는 둘 다 아님. Spec Gate로 자율성을 제한하면서 동시에 "알아서 해줘" 경험을 약속. 유저는 "이 AI가 뭘 할 수 있는지"를 영원히 학습 중.

⚡

"안전" vs "속도"

Proposal 승인, BuildSpec 검증, 린트 게이트, 완성도 경고... 모두 안전장치. 하지만 각각이 1-5초씩 딜레이를 추가. 5개 안전장치 x 5초 = 25초 오버헤드. "빠른 창작" 경험과 양립 불가.

🧠

"초보용" vs "100개 도구"

시스템 프롬프트가 "초보 대면 3-5문장 응답"을 강제하면서, 내부적으로는 100개 도구를 조합하는 복잡한 파이프라인을 돌린다. UI는 그 복잡성을 숨기지 못하고 있다 (tool activity 라인이 그대로 보임).

💡 개선 제안 (뻔하지만 중요한 것들)

1️⃣

"맵 위 인라인 AI" 모드 추가

영역 선택 → 작은 팝오버 → "숲", "집", "호수" 버튼 → 즉시 적용(auto-approve). Region Task가 이미 이 경험에 가까운데, 채팅 없이 맵 위에서 직접 쓸 수 있게. Figma AI처럼.

2️⃣

프로그레스를 "게임처럼"

AI 작업 대기 시간에 "마을 건설 중... 집 1/3 완성 | 길 포장 중 | NPC 배치 중" 같은 서사형 프로그레스. Ghost Preview를 확대해서 건설 애니메이션처럼. 기다림을 "구경"으로.

3️⃣

갤러리 카탈로그

"/마을 생성" 선택 전에 "이런 마을이 만들어집니다" 예시 갤러리. 3-5가지 프리셋 이미지. 유저가 "이 스타일로" 선택하면 프롬프트 자동 구성. 텍스트 입력 최소화.

4️⃣

AI 패널 크기 동적 조절

작업 안 할 때: 44px 레일(아이콘만). 입력 중: 300px 커맨드 바. 작업 중: 전체 패널 확장. 결과 검토: 맵 위 오버레이. "맥락에 따른 크기"로 캔버스 공간 확보.

5️⃣

Tool Activity = 숨기기 기본

"author_house(wings:[...])" 같은 기술 로그는 기본 숨김. "집 짓는 중..." 한 줄만 표시. 전문가 모드에서만 펼치기. 유저에게 보이는 건 "결과"와 "진행률"뿐이어야.

6️⃣

Proposal = 맵 위 직접 확인

모달 카드 대신, Ghost Preview를 강화해서 맵 위에서 직접 확인 + "적용" / "취소" 플로팅 버튼. before/after 토글은 맵 캔버스에서. 별도 모달 창을 열지 않아도 되게.
