# 소품은 실제 사용 목적과 기준 대상이 있을 때만 놓는다

집 옆에 모아 놓았다는 사실만으로 의미 있는 배치가 되지 않는다. 개정5의 집 순서 n%4로 묶음을 선택하는 규칙도 임의 배치이므로 폐기한다. 개정6은 **공간의 용도 → 할 일 → 필요한 물건 → 기준 대상 → 사용할 자리와 접근 동선** 순서다. 소품 수나 종류를 채우려고 활동을 역으로 만들어내지 않는다.

## 먼저 저작할 입력

prop-programs.json의 houses[mapId]["x,y"]에 role(집/공간 용도), activity(할 일), reason(그 기능을 이곳에 지정한 이유)을 명시한다. 이 표본의 역할은 저자가 새로 지정한 외관 설정이며 지붕색으로 추론한 직업이나 실제 NPC/게임 이벤트가 아니다. 지정이 없으면 저작기를 중단한다. modulo·순번 교대·무작위 역할 배정·빈칸의 크기로 활동 고르기는 금지한다.

각 소품에는 ownerId, kit=activity, purpose(사용 목적), anchor(기준 대상), side를 기록한다. 용도가 정해지지 않았거나 물건을 놓는 이유를 설명할 수 없으면 생략한다. 같은 항아리도 세탁용 물과 약초 보관처럼 역할이 달라야 하며, 목적을 메타데이터와 참고문서에 남긴다. 이름표만 붙이고 위치를 그대로 두지 않는다.

## 활동별 필요한 관계

| activity | 주체/기준 | 필요한 물건과 이유 | 좁을 때 남기는 관계 |
|---|---|---|---|
| laundry | 주거 집과 빨랫줄 | 빨랫줄=건조, 그 옆 항아리=세탁용 물 | 빨랫줄+물 항아리 |
| growing | 실제 채소밭 | 허수아비=작물 보호, 씨앗 자루=파종 준비 | 채소밭+허수아비 |
| woodwork | 목재 작업대 | 장작=투입 목재, 상자=가공한 물건 보관 | 작업대+목재 |
| herbs | 약초 화분과 손질 작업대 | 화분=재배, 작업대=선별·건조, 항아리=손질한 약초 보관 | 화분+작업대 |
| storage | 지정한 물자 보관집 | 상자·통=운반할 물자 보관 | 상자+통 |
| fishing | 실제 선착장 | 바구니=낚시 도구, 통=어획 용기, 상자=어구 | 바구니+통; 부두가 없으면 모두 생략 |
| field-tending | 기존 실제 밭 | 허수아비=작물 보호, 씨앗=그 밭 파종 | 기존 밭이 없으면 모두 생략; 새 장식 밭으로 대체하지 않음 |

이 표본에서는 빨래 옆의 꽃처럼 할 일과 직접 관계없는 장식을 묶음 채우기용으로 추가하지 않는다. 꽃을 쓰려면 입구 환대/정원 관리 등 별도의 저작 목적과 기준점을 먼저 지정한다. 의자·벤치는 바라볼 대상/쉴 곳, 표지판은 실제 분기와 목적지, 우물은 사용할 생활권/접근 동선이 있어야 한다. 이번 저작기는 그 시설을 자동 추가하지 않는다.

## 정확한 조립 순서와 조건

1. 집의 activity를 정확히 골라 activities[activity].items를 읽는다. 항목은 [부품 이름,dx,dy,purpose,anchor]이며 compact는 최소 대안의 항목 인덱스다. 기준 대상부터 조립한다. 예: 목공은 작업대(0,2) → 목재(0,0) → 보관 상자(2,0). 작은 마당에서도 작업대를 빼고 상자만 남기지 않는다.
2. 집 h와 묶음 폭w/높이height에 대해 오른쪽 x=h.x+h.w+1, 왼쪽 x=h.x-w-1. y=h.y+h.h-height부터 h.y+1까지 위로 탐색하며 각 행에서 오른쪽→왼쪽을 검사한다. 집 벽과 한 칸 간격, 집의 y범위 안이다.
3. 소품 사전의 완전한 폭/높이와 상위 배열을 쓴다. 대상 lower=240, upper=-1이어야 한다. 집 내부, 길과 상하좌우1칸, 접근점 Manhattan 거리1 이내, 절벽 바로 옆1칸은 금지다. 아래 바닥은 KEEP. 숲·나무·밭·길을 소품 때문에 덮지 않는다.
4. anchor=house이면 소유 집, anchor=dock/farm이면 해당 맵의 activitySites에 기록한 실제 선착장/기존 밭이다. 그 외는 같은 소유자의 이름이 일치하는 소품이다. 기준 대상이 없으면 전체 묶음을 생략한다.
5. 두 사각형 A/B의 타일 거리 d=max(0,Ax-Bx-Bw+1,Bx-Ax-Aw+1)+max(0,Ay-By-Bh+1,By-Ay-Ah+1). 집 기준은6칸 이내, 부두 기준은12칸 이내, 밭/소품 기준은3칸 이내여야 한다. 거리만 통과해도 벽 너머라 사용할 수 없으면 안 되므로 아래 통행 검사를 함께 적용한다.
6. 모든 조각의 이웃에 도달 가능한 작업 칸이 있어야 한다. 다른 소품이 그 작업 칸을 차지하면 제외한다. 큰 묶음이 안 되면 활동별 compact만 시도하고, 그것도 안 되면 비워 둔다. 다른 활동·중앙 빈터로 바꾸지 않는다.
7. 최종 엔진 통행에서 사용할 수 없는 소품이 하나라도 있으면 같은 집의 묶음 전체를 철회한다. 모든 집 문앞·계단·부두·마을 입구의 도달성도 확인한다.

포구의 field-tending은 기존 (25,47) 밭을 기준으로 하며 새 채소밭을 중복 생성하지 않는다. fishing은 (56,45) 선착장에 가까운 어업 준비집만 사용한다. 정확한 집 원점·선택한 활동·이유·activitySites·yards는 각 마을 계획, 정확한 소품 목적/기준/두 레이어 배열은 소품 문서, 완성된 전체 배열과 그림은 전체 행 문서에 있다. activities/집별 선언 전체는 사용 목적 입력 사전에 있다.

## 자동 검사와 범위

- prop-purpose-mismatch: 집의 활동에 허용하지 않은 소품, 목적/기준 설명 불일치.
- prop-purpose-anchor-missing: 실제 작업대·빨랫줄·부두 등이 없거나 너무 먼 소품의 좌표.
- scarecrow-without-garden: 실제 채소밭 또는 기존 밭이 사라졌거나 멀어진 허수아비 좌표.
- prop-owner-missing / prop-outside-yard / unowned-prop: 소유자·마당 범위 및 마당 밖 소품 좌표.

부두의 upper199 전체, 기존 밭의 lower188 전체, 동반 소품의 upper 전체 배열을 확인한다. ‘계획에 기준이 있다고 쓰여 있다’만으로 통과시키지 않는다. 작업대를 일부러 지운 비교 그림은 남겨진 목재의 좌표를 오류로 반환한다. 정상·오류 문서 참조. 동결 참고 표본과 저작 계획의 구조·통행 검사이며 임의 마을의 미적 점수/실제 NPC 작업 시뮬레이션은 아니다.

## 공동 공간 개정7

위 마당 규칙은 kind=prop인 집의 작업 소품에 적용한다. 공동 우물터/정원/현관/안내는 kind=civic-prop와 placeId를 사용하며 civic-props의 실제 장소·사용칸 규칙으로 검사한다. 모든 소품을 집 좌우 마당에만 제한하지 않는다. 정원 가꾸기·환대도 명시한 배치 목적이다.
