# 작은 마을의 길·마당 구도

광원 보정 뒤에도 길이 배선처럼 보이고 집이 잔디 위에 따로 놓이면 지면 사용과 군락을 조정한다.
집의 원본 지붕·벽·윤곽·창문·문은 유지한다. 측면을 추가하지 않는다. 밝은 잔디 source 737은 기본 땅이다.

## 도구와 적용 범위

`naturalize_beodeul_hamlet({mapId})`는 공용 작은 마을 템플릿의 집 3~5채를 전체 배열로 확인한 뒤 길과 마당을 바꾼다.
집/교회 원점은 그대로, 전체 나무 그림·밑동·기초·출입 이벤트·시작점은 보존한다. 높이 있는 맵이나 임의 배치 마을에는 거절한다.
옛 포석 샛길을 지우고 큰길, 우물/교회 광장, 흙 접근로와 집 앞 마당을 구분한다. 기존 풀/꽃의 작은 점들은 정리하고 군락 경계에 다시 모은다.
완성된 구도의 반복 호출은 중복하지 않는다. 사람이 일부 지운 지면을 자동 복원하지는 않는다.
집/길/풀 장식 변경이 허용된 요청에서만 호출한다. 기존 맵 꾸미기는 새 맵 생성이나 author 재시공으로 대체하지 않는다.
새 `author_beodeul_town({houseCount:3~5,church?:true})`는 이 구도를 자동 적용한 뒤 일광 보정을 붙인다.
새 소규모 마을의 전체 칸 배열과 graft 통행/우선순위는 같은 용도의 작은 마을 예제 두 문서에 있다.

## source 사전 · 층 · 연결

공용 `beodeul_ground`/`tex_beodeul_ground`, 16px, 8열, 368칸. 기존 source 0..303 그림은 불변이다.
304..351: `bdg-hamlet-{soil,stone,meadow}-{mask}` 각각 16종, 1층 전체 바닥이다. 투명 칩이 아니다.
mask는 N=1/E=2/S=4/W=8의 OR 값. 인접한 같은 재료 칸 집합으로 계산하며 맵 밖은 연결하지 않는다.
soil은 밟힌 흙, stone은 원본 포석 3221의 테두리 없는 질감을 잔디와 연결, meadow는 기존 잔디색의 약한 덩어리 변화다.
352..355: `bdg-hamlet-steps-{0..3}`, 드문 디딤돌 1층. 접근로 일부에만 사용하며 문 칸에는 놓지 않는다.
356..361: `bdg-hamlet-vegetable-bed`, 3×2칸의 2층 작은 텃밭. 원래 1층 땅을 보존한다. 나머지 362..367은 패딩 빈칸이다.
모든 새 칸은 lower 우선순위, 네 방향 통행 true, terrain 0. 막는 가구와 구별한다.
전체 레시피의 네 층 배열은 CATALOG.md에 있다. source 번호와 대상 map 번호를 섞지 말고 translateTiles의 반환을 사용한다.
원래 구조 위에 덧그리지 않는다. 기초는 4층, 바닥 그림자는 2층, 집/나무는 3층이다.
새 하위 바닥은 원래 잔디 737 또는 알려진 옛 포석을 지운 칸만 쓴다. 기존 저자가 만든 다른 바닥은 보존한다.

## 현재 지원하는 배치

첫 cream 집의 실제 원점과 기준 (4,3)의 차이로 전체 core 오프셋을 얻는다.
민가 기준 원점은 (4,3),(17,2),(30,5),(5,18),(27,20). 3채 이상 전체 배열이 일치해야 한다.
교회는 동쪽 추가 띠의 (41,3), 12×13 전체 배열이 일치할 때 앞 광장을 적용한다.
민가 문 앞은 (6,9),(19,10),(32,11),(6,26),(30,26), 교회는 (48,16).
큰길 2칸 폭과 우물 마당을 연결하고, 남쪽 두 집은 서로 독립된 흙 접근로로 잇는다. 옛 큰 순환 포석길은 없앤다.
마당 중심은 (7,10),(21,11),(32,12),(8,27),(30.5,27). 타원형 칸 집합에 연결 mask를 적용한다.
텃밭은 cream 집 곁 (8,11), 빨랫줄은 원본 (24,7) 전체 배열을 확인하고 빈 (22,11)로만 옮긴다.
기존 소품·그늘 때문에 텃밭 칸이 비어 있지 않으면 그 칸은 보존한다. 추가 물체는 비어 있는 칸에만 놓으며 길·문·이벤트를 막지 않는다.
나무 아래와 마을 가장자리에 낮은 대비의 meadow를 묶고, 관목·풀은 나무 곁에 모은다. 중앙에는 비어 있는 땅을 남긴다.

## 정상/오류와 확인

hamlet-normal-error.png 왼쪽은 3×3 흙마당 mask 배열 [[6,14,12],[7,15,13],[3,11,9]], 오른쪽은 좌상단 칸을 interior mask15로 바꾼 실제 오류다.
code grass-transition-missing, 예제 맵 좌표 (0,0), expected mask6, actual15. grass-facing edge의 연결을 잃는다.
시트 크기, 모든 원본 304칸 해시, source 배열과 그림 일치를 하네스로 검사한다.
원본 건물 여섯 곳의 전체 3층 배열, 출입 이벤트·시작점·기존 출입 시험 맵은 저장 전후 일치로 확인한다.
마당/길에 추가된 물체 때문에 전체 통행은 일부 바뀔 수 있다. 실제 canMove로 모든 문 앞과 우물 복귀 경로를 계산하고 전용 플레이어에서 걷는다.
SQLite save → 같은 폴더 reopen → 전체 project 동등 비교가 완료 근거다. 그림만 export한 것은 정본 저장이 아니다.
