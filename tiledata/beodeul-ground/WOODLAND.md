# 식생의 깊이 · 연결 울타리 · 단일 돌벽

작은 구형 덤불과 나무를 겹침 없이 흩어 놓으면 동일한 평면의 스티커처럼 보인다. 접촉 그림자만 추가하면 나무 사이의 앞뒤 관계는 여전히 없다. 원본 나무 수관을 실제 지면 접점의 y 순서로 합성한 north/north-open/west/east 숲 조각을 사용한다. 원본 3종의 크기와 수관 모양이 다르고, 앞 나무가 뒤 나무 일부를 가린다. 숲 안의 점 같은 덤불 대신 나무 아래와 외곽에 높이 있는 풀 군락을 둔다. 전체 잔디 737과 건물 배치는 바꾸지 않는다.

## 적용 도구와 제한

`refine_beodeul_courtyard_vegetation({mapId})`: 인식된 54×34 우물 공동마당 예제의 6건물과 기존 나무 배열을 대조하고 적용한다. 변경된 나무·임의 마을·이벤트·높이 맵은 자동 보정하지 않는다. 이미 woodland 조각이 있으면 반복 변경하지 않는다. 새 마을은 author_beodeul_town({id,houseCount:5,church:true}) → compose_beodeul_courtyard_village({mapId:id}) → 이 도구 순서다. 기존 집·문 앞·길·마당·시작점·원래 실내 출입 시험은 유지한다.

## source / 층 / 충돌

- 공용 `beodeul_ground` / `tex_beodeul_ground`, 16px/8열. 기존 368칸은 픽셀과 번호를 보존했다. 시트 전체 칸/배열은 같은 용도의 「정확한 칸 배열·전체 조립」 문서에 있다.
- `bdg-woodland-north` / `north-open`: 8×5, `west`: 7×9, `east`: 7×8. 본체는 3층. 원본 수관·목·뿌리를 한 픽셀 합성에 넣어 각 타일의 투명 경계에서 뒤 나무가 사라지지 않게 했다.
- 각 레시피의 `upperCells`는 ★, `blockingCells`는 X/우선순위 lower. 줄기 접점만 막고 위쪽 잎 밑은 걸을 수 있다. 모든 잎을 X로 만들거나 풀의 O로 줄기의 X를 덮지 않는다.
- 같은 이름의 `-shadow`는 2층 투명 땅 그림자. 왼쪽 위 광원의 짧은 그늘과 짙은 접촉을 사용한다. 본체와 같은 원점에 놓는다.
- `fringe-0`, `fringe-1`은 3×2의 4층 ★ 풀 군락. 밑그늘·짙은 뿌리·줄기·밝은 잎끝이 있고 숲 밑동에 겹친다. ★는 아래 줄기의 통행을 상속한다. 마당과 길 가운데 반복하지 않는다.
- 울타리는 원본 밭 울타리(`bd-farm-fenced-plot`) 칸을 화소 그대로 옮긴 1×1 조각이다(2026-10-20, `scripts/content/build-beodeul-woodland-fence.py`). 모두 3층 X.
  `fence-horizontal`(가로), `fence-vertical`(서쪽 변 세로), `fence-vertical-east`(동쪽 변 세로), `fence-corner`(남서 모서리), `fence-corner-se`(남동), `fence-corner-nw`(북서), `fence-corner-ne`(북동).
  모서리는 방향이 정해져 있다 — 한 가지 모서리를 양쪽에 쓰지 않는다(동쪽에 남서 모서리를 쓰면 레일이 밖으로 삐진다). 북쪽이 막힌 울타리는 북서·북동 모서리와 가로 줄로 닫는다.
  예전 세 조각(가로·세로·모서리)은 PIL 도형 임시 그림이었고 번호 643~645 는 그대로 둔 채 그림만 원본 결로 바뀌었다. 원본 fence-run 은 문틈이 포함된 4×1 조각이므로 임의 잔디에 한 줄만 놓아 마당 경계라고 하지 않는다.
- source 번호는 현재 프로젝트의 map 번호와 다르다. `translateTiles`로 이식하고 source priority/passability를 다시 적용한다. 빈 -1은 해당 층을 보존한다.

## 완성 좌표

숲: north(0,0), north-open(23,0), north(46,0), west(0,5), west(0,24), east(34,7), east(47,25), north-open(38,29). 각 원점의 본체와 땅 그림자를 함께 놓는다. 맵 54×34 안에 전체 조각이 들어간다. 큰길의 서쪽 입구(0,18)는 비워 둔다.

텃밭: 식물(30,20)와 (33,20), 두 조각 3×2. 울타리 남변 (30..35,22), 남서 모서리 (29,22)·남동 모서리 (36,22), 서변 fence-vertical (29,20..21)·동변 fence-vertical-east (36,20..21). 북쪽은 큰길에서 들어가는 열린 면이다. 남쪽 민가 문(32,29)과 동쪽 접근로(37,22..28)는 막지 않는다. 집 앞 잔디에 짧은 울타리 두 조각을 따로 두었던 배치는 제거한다.

돌집(27,8): 박공 벽도 벽이다. 박공의 회벽 픽셀을 아래층과 같은 원본 돌벽 패턴으로 통일한다. 지붕 픽셀·알파 윤곽·문 한 개·원형창은 보존한다. 원본 대비 전체 픽셀 보존율 83%는 지붕 재저작이 아니라 사용자 지적한 벽 재질 통일 때문이다.

## 정상/오류와 검증

woodland-normal-error.png 왼쪽은 앞 나무가 뒤 나무를 가린 정상 순서, 오른쪽은 동일한 원본 나무들의 순서를 뒤집은 실제 합성 오류다. woodland-errors.json의 back-tree-over-front 좌표/픽셀 차이를 확인한다. 전체 네 층 배열과 모든 graft 규칙은 공동마당 예제 문서들에 있으며 원본 게임 픽셀 렌더도 함께 확인한다. 저장+재로드와 실제 player.html에서 6문 앞 도보 통행을 따로 확인한다. 기계적 검사가 시각적 자연스러움에 대한 사람의 판단을 대신하지 않는다.

## 붓으로 까는 숲 — 나무 composer·짙은 풀·숲 종류 (2026-10-20 r2 ~ 10-21 r5)

> 2026-10-22: `author_beodeul_town` 마을 숲과 버들항 `place_props` 숲(dense·impassable)은 composer 가 아니라 이어진 수관 오토타일(`BEODEUL_NATURE.forestCanopy`)로 깐다 —
> 사용자 「숲 오토타일을 제대로 적용해야 함」. 정본 `src/editor/tools/beodeulForest.ts` `shapeBeodeulCanopyMask`·`planBeodeulCanopy`·`writeBeodeulCanopy`·`plantBeodeulCanopyArea`,
> 규칙은 `openwiki/beodeul-city.md` 「마을·붓 숲 = 이어진 수관 오토타일」. 아래 composer 는 도로 숲 벽(`author_wild_route`)·이야기 산책·공동마당 경로다.

위 숲 조각(north/west/east…)은 공동마당 예제 전용 고정 그림이다. 도로 숲 벽(`author_wild_route`, 이야기 산책 맵)과 강가·해안 마을(`author_beodeul_town` river/coast) 숲은
나무 composer(`src/project/defaults/treeComposer.ts` `composeTreesPlaced`, jp 숲 r6 와 같은 칸 쌓기)가 짓는다. 밑동은 `planBeodeulForest` 가 고른다(r3, 아래) — 칸마다 남쪽(앞) 나무부터 4·3·2층에 쌓는다 —
앞 나무 수관이 뒤 나무 줄기를 가리고 숲 남쪽 끝 줄만 줄기·뿌리가 보인다. 정의 `src/assets/beodeulForestComposer.json`(빌더 `scripts/content/build-beodeul-forest-composer.py`), 도구 쪽 입구 `src/editor/tools/beodeulForest.ts` `composeBeodeulForest`.

### 숲 종류 forestType (두 도구 모두 같은 인자)

- `broadleaf` 활엽수림(기본): 줄기 나무 `bd-tree-d43edd`·`5844f6`(4×5), `1a786c`·`d61d7e`(3×4), 틈 덤불 `37f48b`·`f4f319`(2×2).
- `conifer` 침엽수림: 해안 절벽길 전나무 `bd-pick-coast-cliff-road-fir-l`(3×4)·`-m`·`-m2`·`-s`(2×3)와 원본 도시 숲의 측백 `bd-tree-eef4bc`·`28ad5e`·`c27062`(1×3). 마을의 낱 나무·덤불도 전나무·측백으로 바뀐다.
- `mixed` 혼효림: 원본 도시 숲(`tiledata/beodeul-city/render-full/city6.png`)처럼 큰 활엽수 사이에 측백·전나무가 선다. 침엽·혼효 마을은 숲 덩이를 크게 잡는다(맵의 20%, 덩이 24칸 이상).
- 공동마당 예제(`refine_beodeul_courtyard_vegetation`)도 고정 숲 조각 대신 그 조각이 덮던 칸에 혼효 composer 로 다시 세운다(r3).

### 밑동 고르기 planBeodeulForest (r3~r4, 2026-10-21 독립 검수 대응)

- 격자가 아니라 해시 순 탐욕 배치: 숲 남쪽 끝 칸 먼저, 나머지는 해시 순. 두 밑동은 |dx|<2·|dy|<2 안에 같이 서지 못한다. 가로 3·세로 2칸 안 나무와 같은 그림을 피한다.
- 숲 덩이 한 톤(r4 B, 사용자 승인): 숲 가장자리(깊이 ≤1)에만 밝은 연두 나무(T4 4×5·T3·B2 덤불), 속은 원본 짙은 초록 T3(D3)·덤불(D2). 큰 4×5 와 작은 3×4·2×2 가 섞인다.
- 보이는 칸(덮개 >2%)이 맵 밖으로 나가는 나무는 심지 않는다. 꼭대기가 한계에 딱 닿는 나무는 60% 를 건너뛰고, 그런 나무끼리 2칸 안에 하나만 — 윗줄 측백이 같은 높이로 늘어서지 않는다(N2).
- 침엽 꼭대기 칸이 다른 나무 줄기 칸에 꽂히는 배치는 건너뛴다(N4).
- 칸마다 앞에서부터 불투명 칸(덮개 ≥98%)이 나올 때까지 쌓인 조각 수가 층 수(숲 3, 숲 밖 2)를 넘으면 그 나무를 통째로 심지 않는다 — 감사 렌더의 `clip-check` 가 잘린 칸 0 을 확인한다.
- 나무 그림은 모두 원본 버들항 칸이다(재채색 없음). 수관 다시 그리기(A1·A2)는 사용자가 원본 수관(B)을 골라 폐기했다(2026-10-21).

### 나무 밑 땅 = 짙은 풀 오토타일 (r5, 2026-10-21 사용자 정정)

원본 도시(`tiledata/beodeul-city/render/city6_ground.png`)는 나무 밑 땅을 **짙은 풀** 덩이로 칠했다 — 짙은 결(원본 칸 `11628`) 둘레를
3~4px 디더 띠로 밝은 잔디에 풀어 둔 둥근 덩이. 버들항 칩셋 `autotileGroups` 에는 이 덩이의 가장자리가 없어서 `11628` 은 「버들항 풀밭」 땅 변형의 한 칸으로만
등록돼 있었고, 도로 도구가 그 속 칸을 **네모 판**으로 깔았다(사용자: 「저 짙은풀은 오토타일로 깔리는 바닥타일이잖아. 숲 내부를 꾸미는 용도로 쓰는」).

- 오토타일 그룹 `beodeul_dark_grass`(바탕 민무늬 잔디 737) · `beodeul_dark_grass_woodland`(바탕 숲 장면 잔디) — `ensureBeodeulDarkGrass` 가 대상 칩셋에 단다(편집기 붓·fill 도 그대로 쓴다). 8이웃 47모양, 맵 밖은 이어진 이웃.
- 속(8이웃 모두 짙은 풀) = 원본 칸 `11628`, 같은 결 원본 속 칸 `1597`·`12939`·`12946`·`12947`·`15152` 를 칸 위치 해시로 섞는다(새 화소 0). 속 칸은 그룹 멤버가 아니라 이웃으로만 들어 — 「버들항 풀밭」 으로 낱칸 깔린 11628 을 편집기가 가장자리 모양으로 바꾸지 않는다.
- 가장자리 46모양 × 바탕 2벌 = 92칸(`bdg-dark-grass-<plain|woodland>-<마스크>`, 공용 기초 칩셋, 빌더 `scripts/content/build-beodeul-forest-ground.py`): 화소마다 원본 `11628` 화소 또는 바탕 잔디 화소를 그대로 옮긴 조합이다. plain 벌(651~696)은 원본에 없는 색 0, woodland 벌(697~742)은 바탕이 채도 낮춘 잔디 650 이라 원본에 없는 색 4개(650 의 색)를 쓴다.
  경계는 밝은 이웃 칸까지 거리 5.8±2.7px(주기 16 안의 1·2·3·5배 물결 — 칸마다 혹 하나가 반복되지 않게, 위상은 칸 이음매 근처가 평균 깊이), 바깥 3.5px 는 4×4 Bayer 디더 띠. 바깥 모서리는 반지름 7.5 로 둥글리고 안쪽 모서리는 둥근 홈이다. 가시 다듬기(짙은 8이웃 ≤2 화소 3회)·크기 ≤3 낱점 지우기는 칸+여백 6px 창의 전역 필드에서 해 이음매 양쪽이 같게 지운다.
  **짙은 풀은 2×2 덩이에서만 보인다(r9):** 2×2 짙은 덩이에 들지 않는 칸(외딴 칸·한 칸 폭 띠, 마스크 0~15)은 바탕 잔디 그대로이고, 덩이 칸은 「한 칸 폭」 이음매(두 칸을 함께 품는 2×2 가 없는 이음매) 너머 이웃을 밝은 칸으로 보고 물러난다. 16px 한 칸 폭에는 땅 그늘을 그릴 자리가 없어 외딴 칸·띠를 어떻게 그려도 풀포기·덤불 사슬·구슬로 읽혔다(독립 Opus 적대 VQA 1~3판 불합격 78·72·72/93 → 4판 93/93 통과, 영수증 `harness-data/object-gate/vqa/beodeul-dark-grass-r9.opus-vqa-r*.json`).
- 깔리는 칸 = 나무 그림이 3×3 안에 닿는 숲 칸(`planBeodeulForest` 의 `dark`). 나무가 없는 숲 칸은 잔디로 둔다. 숲 덩이 경계가 칸 선이 아니라 둥근 물결 디더다.
- **코드가 그린 그늘 칸은 모두 뺐다** — r2~r4 의 숲 바닥 그늘 코드 칸(floor/edge/wfloor 64×3)·둘레 땅 그늘 덧칸(apron 63)은 시트·카탈로그에서 지웠고 composer 에 접지(ground)를 넘기지 않는다.
  줄기·수관 그림자로 따로 남긴 새 그늘 칸도 없다 — 원본처럼 짙은 풀 덩이가 나무 밑 그늘을 맡고, 줄기 밑 뿌리 그늘은 나무 그림 자체에 있다.
- 숲 장면 잔디(`bdg-woodland-grass`, 737 채도 ×0.84, r4 B 사용자 승인): 도로 숲 벽(`author_wild_route`)에서만 맵의 737 을 이 잔디로 바꾼다. 공용 잔디 737 그림은 그대로.
- **조우 풀숲은 몬스터 수집 게임 전용:** `author_wild_route` 는 `isDeclaredMonsterGame` 일 때만 길을 가로지르는 풀숲(로케이션 「풀숲 N」·풀숲 한정 조우)을 깐다. 깔 때도 짙은 풀 오토타일로 둥글게 푼다.
  일반 RPG 에서는 풀숲을 깔지 않고(grassPatches 무시·경고) encounters 를 맵 전체 조우로 넣는다.
- **3/4·화풍 관문:** 가장자리 92칸과 숲 장면 잔디 1칸(beodeul_ground 650~742)은 새 배열·새 색이다. 빌더는 칸마다 object-gate 출구(bundle)를 확인하고 막히면 쓰지 않는다 —
  판정자(Opus 적대 판정)가 통과시키기 전에는 `--draft`(초안 PR 전용)로만 굽는다. 판정 대상 칸 번호·화소 해시 = `woodland-judge-cells.json`.
