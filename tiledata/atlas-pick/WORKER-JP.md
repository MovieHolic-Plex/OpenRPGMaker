# 일본 도시 16px 조각 후보 찍기 — 작업자 절차서

너는 작업자 `jN`(j1…j5, 감독자가 번호를 준다)이다. `tiledata/atlas-pick/jobs-jp.json` 의 `workers.jN` 에 있는 기물마다
**후보 셋(A·B·C)** 을 직접 찍어 제출한다. 사용자가 브라우저(http://mdc-server:18303/ 「일본」 탭)에서 후보들을 나란히 보고 하나를 고른다.
네 일은 **고를 거리를 서로 다르게, 그리고 한눈에 무엇인지 읽히게** 만드는 것이다.

> **2판(2026-09-30)**: 건물 외관·역 입구·개찰구·신호등·주택·신사 배전·도리이·건널목·전봇대는 **조립형 킷**으로 옮겼다(`kits-jp.json`, 절차 `WORKER-JP-KIT.md`, 배정 `jobs-jp-kit.json`).
> 자판기·매표기는 크기를 바꿔 재작업(`rN`, `WORKER-JP-KIT.md` 5절). 이 문서는 보통 기물 절차로 그대로 쓴다.

저장소 루트 = 이 워크트리. 명령은 전부 루트에서 돈다. 네 기물 폴더 밖은 **읽기만** 한다.

2. `scripts/content/pixel-harness/pxgrid/README.md` — 격자 형식(`@block` `@def` `@stamp` `@px` `@layer`, 램프 격자 `@mat` `@mblock` `@tblock` `@tadj`), 단계형 작도, 자기 점검표.
3. `tiledata/hand-interior/v6-objects/LESSONS.md` — 손 도트에서 배운 것(자동 윤곽이 2px 부재를 먹는다, 잎 윤곽은 한 단만 어둡게 …).
4. 강남 조각(같은 칩셋 식구 — 방향 A 의 기준 결):
   - 강남역 맵 그림 `tiledata/atlas-biomes/modern/images/modern-gangnam-station.png` (90×85칸, 원 크기 16px)
   - 조각별 현재판 `tiledata/atlas-pick/candidates-modern/<slug>/v0.png` (고르는 화면 「현대(강남)」 탭과 같은 그림)
   - 그리는 코드(읽기만): `scripts/content/lib/modern/gangnam.py` `props.py` `cars.py` `marks.py` — 명암 단 수, 그림자 넣는 법(`shadowed`), 글자 굵기.
5. 네 기물의 `tiledata/atlas-pick/candidates-jp/<slug>/info.json` — 이름·설명·칸 수·층·팔레트 힌트.

## 1. 16px 실내 1판에서 사용자가 알려 준 것 (2026-09-30, 112개 판정)
- 고른 방향: **C 35 · B 31 · 현재판 유지 20 · A 11**. 「조금 다듬기」는 거의 안 고른다 → **A 도 눈에 띄게 좋아야** 한다.
- 거절 사유 1위는 **입체감·공간감 없음**: 윗면·옆면·앞면이 서로 다른 명도로 나뉘어야 한다. 상자형(자판기·매표기·새전함)은 **윗면(지붕판)이 보여야** 한다.
  시점은 맵과 같은 **위에서 약간 내려다보는 각** — 앞면이 주인공, 윗면은 1~3px 띠. 시점이 어긋나면(정면 도면, 완전 위에서 본 판) 「시야각이 이상」하다고 거절된다.
- **색감**: 탁하거나 튀는 색은 거절. 바닥(아스팔트·보도)과 명도를 분리하되 몸통 채도는 낮게. 주홍·네온 같은 강한 색은 **면적 작게, 한 덩이로**.
- **질감**: 재료가 16px 에서 읽혀야 한다(짚 = 가는 노란 결 + 어두운 틈, 기와 = 가로 골 줄, 돌 = 두세 단 덩이 + 이끼 점).
- **알아볼 수 있어야**: 「이게 뭐지?」는 실패다. **실루엣 한 색만으로 무엇인지 읽혀야** 한다(1단계 `#` 실루엣에서 먼저 확인). 안 읽히면 과장하라 — 고마이누는 머리를 크게, 전봇대는 완목·애자를 또렷하게.
- **크기**: 사용자는 작게 그린 것보다 **크게 또렷한 것**을 원했다. 칸 수가 모자라다고 판단되면 그리지 말고 감독자에게 「<slug> 를 w×h 로 키우자, 이유」 를 보고하라(칸 수는 목록이 정한다 — 멋대로 바꾸면 size 불합격).
- **어울림**: 강남 조각·현대 시트 바닥과 같이 놓였을 때 이어져야 한다. 윤곽은 검정이 아니라 그 재료의 어두운 단, 오른쪽·아래 테가 한 단 더 어둡다. 빛은 **왼쪽 위**. 베개 명암(사방을 어둡게) 금지.

## 2. 후보 방향 (기물 하나에 A·B·C 셋, 여유 있으면 D)
| 글자 | 방향 | 하는 일 |
|---|---|---|
| **A** | 강남 조각 결을 따른 판 | 강남 조각(자판기 옆 편의점 간판, 신호등, 차, 가로등)과 같은 명암 단 수·윤곽·그림자 방식으로. 「강남 시트에 원래 있던 것 같은」 판 |
| **B** | 명암·그림자 강화 | 같은 모양에 빛 구조를 세게: 윗면·빛 쪽 한 단 밝게, 그늘 쪽·앞면 한두 단 어둡게, 발치 오른쪽 아래 반투명 접지 그림자(`~` `-`, 2~3줄), 빛나는 물건(등롱·자판기·네온)은 속 밝기 + 바닥 불빛 번짐(`%`). 입체감이 가장 큰 판 |
| **C** | 실루엣 재해석 | 같은 칸 수 안에서 모양을 다시 생각한다: 무엇이 16px 에서 가장 잘 읽히는가, 비율·부재 굵기·과장. 새로 그린 판 |
| D… | 자유 | 더 좋은 생각이 있으면(선택) |

방향마다 **서로 달라야** 한다. 사용자는 「방향별 모아 보기」로 A 끼리·B 끼리 본다 — 글자 뜻을 지켜라.

## 3. 캔버스·층·색 규칙 (검사가 기계로 본다)
- **캔버스 = 칸 수 × 16** (`info.json` `canvas`). 16px 칸 격자에 맞춘다(좌상단 = 칸 모서리).
- **층**(`info.json` `layer`)마다 다르다:
  | 층 | 뜻 | 규칙 |
  |---|---|---|
  | `ground` | 바닥(아래층) | **칸 전부 불투명**. 아스팔트(`masph`)·보도(`mpave`)·자갈 바탕까지 네가 칠한다. 이어 붙이는 조각(횡단보도·선로·참도)은 위아래(또는 좌우) 가장자리가 맞게 |
  | `decal` | 바닥 덧칠 | 투명 배경. 바닥 위에 무늬만(꽃잎) |
  | `object` | 물체(위층) | 투명 배경. **맨 아래 그림 줄이 캔버스 아래 3px 안** — 바닥에 선다. 그림자는 발치 오른쪽 아래 |
  | `wall` | 벽 걸이 | 투명 배경. 벽면에 붙는 간판·노렌·등롱. 아래로 떨어지는 그림자 없이 벽에 붙은 그늘 한 줄 정도 |
  | `facade` | 건물 외관 블록 | 불투명 허용(벽을 꽉 채워도 된다). 맨 아래 줄 = 길과 만나는 1층 발치. 위·옆으로 다른 블록과 이어지게 |
  | `over` | 공중(맨 위층) | 투명 배경. 전선 — 좌우 끝 높이가 같아 이어 붙는다 |
- **색은 `palette.pal`(= `tiledata/atlas-pick/palette/jp.pal` 사본) 안에서만.**
  - `m` 으로 시작하는 램프(`masph` `mpave` `mconc` `mglass` `mmetal` `mwhite` `mred` `mgreen` …) = 현대 칩셋·강남 조각과 **같은 색**. 거리 바닥·건물 벽·유리·쇠는 이것부터.
  - 일본 색: `shu`(도리이 주홍) `akachin`(붉은 등롱) `ai`(노렌 남색) `kawara`(기와) `hinoki`(흰 나무) `sumi`(짙은 나무) `washi`(종이) `sakura` `matsu`(소나무) `moss` `ishi`(돌) `lacq`(검정 칠·택시) `taxi`(노랑) `neon`(분홍 네온) `neonc`(청록 네온) `kgreen` `korange` `kblue`(콘비니 띠) `pole`(콘크리트 전봇대·블록) `kasa`(청동 녹).
  - 쓰는 법: `@mat w hinoki 3` 로 재료 글자를 정하고 `@mblock` 으로 칠한 뒤 `@tblock X Y 램프`·`@tadj` 로 단을 놓는다(README 「램프 격자」).
  - 반투명은 `~`(그림자 속 110) `-`(그림자 번짐 58) `%`(불빛 번짐 120) 셋뿐. **팔레트에 색을 더하지 마라** — 모자라면 감독자에게 말한다.
- 실루엣 단계 표시색 `#` 이 최종본에 남으면 불합격.
- **EasyRPG 칸 0**: 현대 시트 0~2729 칸(EasyRPG 계열, 폐기)을 베끼거나 잘라 붙이지 마라. 검사가 그 칸과 95% 이상 닮은 칸을 불합격시킨다.
- **제3자 복사 0**: REFMAP(`~/.local/share/oprn/refmap-downloads/_packs/`)·인터넷 그림은 **봐도 되지만 화소를 옮기지 마라.** 검사가 95% 이상 닮은 칸을 불합격시킨다. 실제 상표·로고(세븐일레븐·JR 로고 등)를 그리지 마라 — 색 띠와 일반 낱말(「えき」「駅」「薬」「らーめん」)만.
- **글자**: 한자·가나는 도트로 읽히게 **획 2px** 가 기본(작은 부글자만 1px). 글자 칸이 모자라면 글자 수를 줄여라(「パチンコ」 네 자면 충분). 알아볼 수 없는 가짜 글자 금지.

## 4. 파일 규약 (다섯 명이 동시에 쓴다 — 자기 파일만)
기물 폴더 `tiledata/atlas-pick/candidates-jp/<slug>/`.

| 파일 | 누가 | 내용 |
|---|---|---|
| `info.json` `palette.pal` | make_jp_jobs.py (고치지 마라) | 기물 규격, 팔레트 사본 |
| `jN-A.pxg` `jN-B.pxg` `jN-C.pxg` … | **너** | 후보 격자. 첫 줄들: `@size W H` `@cell 16` `@palette palette.pal` |
| `jN-A.note` … | **너** | 한 줄 메모: 무엇을 어떻게 그렸고 왜(예: 「윗면 2px 밝게, 캔 견본 세 줄, 발치 그림자 2줄」) |
| `jN-A.png` `-x4.png` `.txt` `.check.json` | check_candidate.py 가 만든다 | 렌더·평탄화 격자·검사 결과 |
| `work/jN-*` | 너(선택) | 단계 파일(1-silhouette … 5-clean). 화면은 `jN-X.pxg` 만 읽는다 |

- 다른 작업자 파일, `picks` 저장소, `palette/`, `jobs-jp.json`, 다른 세트(`candidates-modern/`)는 **절대 건드리지 않는다.**
- **git 커밋·stash·push, npm test·vitest·gates·typecheck 금지.** 감독자가 모아 커밋한다.
- `/tmp` 에 소스를 두지 마라(사라진다). 단계 파일은 `work/` 아래.

## 5. 기물 하나 절차
```bash
S=tiledata/atlas-pick/candidates-jp/<slug>
cat $S/info.json                                   # 칸 수·층·설명·팔레트 힌트
#   1 실루엣(# 한 색) → 2 평면 색 → 3 빛(왼쪽 위) → 4 결 → 5 정리.  단계 파일은 $S/work/ 에
echo "한 줄 메모" > $S/jN-A.note
python3 scripts/content/atlas-pick/check_candidate.py $S/jN-A.pxg      # 렌더 + 검사 (몇 초)
python3 scripts/content/atlas-pick/context.py $S/jN-A.pxg              # 거리 맥락 그림 → $S/jN-A.ctx.png (4배)
```
- 검사 뒤 **반드시 `jN-A-x4.png` 와 `jN-A.ctx.png` 를 열어 눈으로 본다.** 숫자가 합격이어도 눈으로 이상하면 고친다. 특히 「실루엣만으로 무엇인지 읽히나」「윗면·앞면이 나뉘나」.
- `pxlint16` 는 참고 표시다(불합격이어도 제출 가능). hard 불합격(✗)은 고쳐서 합격시킨 뒤 제출한다. 도저히 안 되면 메모에 이유를 적고 남겨 둔다(화면에 빨갛게 뜬다).
- 한 기물에 20분을 넘기지 마라. 셋을 다 낸 뒤 시간이 남으면 좋은 방향을 하나 더(D).
- 짝 기물(택시 둘·고마이누 둘·지붕/외벽·선로/건널목판·자판기 둘)은 **같은 방향 글자끼리 한 식구**로 보이게 — j3-B 음료 자판기와 j3-B 담배 자판기는 같은 높이·같은 명암 방식.

## 6. 끝나면
```bash
python3 scripts/content/atlas-pick/check_candidate.py --set jp --worker jN      # 네 후보 전부 다시 검사
```
감독자에게 짧게 보고: 기물 수·후보 수·hard 불합격 목록, 키우자고 제안할 기물(있으면), 방향별로 가장 자신 있는 후보 한두 개와 이유. 파일 경로는 절대 경로로.

## 7. 감독자용 (작업자는 읽지 않아도 된다)
- 목록·폴더 다시 만들기: `python3 scripts/content/atlas-pick/make_jp_jobs.py` (있는 후보 파일은 건드리지 않는다). 팔레트: `make_jp_palette.py` → `palette/jp.pal`, 그다음 make_jp_jobs.py 로 폴더 사본 갱신.
- 현대 세트(강남 v0) 다시 뽑기: `python3 scripts/content/atlas-pick/make_modern_set.py`.
- 화면 서버: `systemctl --user {status,restart} atlas-pick` (`~/.config/systemd/user/atlas-pick.service`, 포트 18303). 먼저 `export XDG_RUNTIME_DIR=/run/user/$(id -u) DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u)/bus`.
- 선택은 SQLite `tiledata/atlas-pick/picks.sqlite` 에 쌓인다(추가만 하는 이력). 자세한 것은 pick_server.py 머리말.
