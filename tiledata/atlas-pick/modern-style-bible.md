## 0. 참고 팩에서 읽은 것 (눈대중)

- 바탕은 **차가운 청보라 회색**, 따뜻한 색은 지붕·붉은 벽·단풍·간판에만 쓴다.
- 건물은 「지붕 윗면 + 앞벽 + 드리운 그림자」의 키 큰 덩어리다. 재료(벽돌·타일·콘크리트·판자)마다 면 색이 다르고 단은 3~5개.
- 윤곽은 검정이 아니라 어두운 청보라. 캐릭터는 문·차와 같은 눈높이 규모.
- 우리 2차 데모의 약점: 벽이 한 색, 층띠가 얇음, 창이 스티커, 이웃 건물 앞뒤 차이 없음, 1층 가게가 안으로 들어가지 않음.

## 2. 빛과 면마다 램프 단

빛은 **왼쪽 위**. 그림자는 항상 오른쪽 아래. 한 화면에서 한 번이라도 뒤집히면 공간감이 깨진다. `t` 는 그 재료의 기본 단(0)에서의 상대 단.

| 면 | 단 |
|---|---|
| 지붕 윗면 | +2 (앞 모서리 lip +1) |
| 앞면(기본) | 0 (줄눈 -1/+1 쌍, 물때 -1) |
| 슬래브 아래·처마 그림자 | -2 (다음 줄 -1) |
| 오른쪽 옆면 | -2 |
| 바닥에 드리운 그림자 | -2, 가장자리 -1(부드러운 끝) |
| 윤곽 | sumi |

## 3. 3D 규칙 (16px 칸, 수치는 견본 `proof.png` 에서 실제 사용한 값)

1. **건물 = 지붕 윗면 + 앞벽 + 드리운 그림자.** 지붕 윗면 = **밑면 깊이 D×16px**(§10 — 옛 「12px + lip 4px」 는 1×1 견본용 얇은 띠였고 3/4 시점 계약 미달로 **폐기**), 앞 lip 2px(+2/+1). 지붕 위 기물(실외기·물탱크 등)은 윗면 + 앞면 + 옆면(-2) + 오른쪽 아래로 길게 드리운 그림자.
2. **슬래브 두께 4px**: 윗면 +2, 앞면 +1 ×2, 아래 모서리 -2. 바로 아래 **3px 그림자**(-2/-2/-1)를 벽에 드리운다.
3. **창의 깊이**: 위 2px 그늘, 왼쪽 1px 그늘(틀 그늘) · 안쪽 물건 · 반사는 대각 점 · **문턱 윗면 +2, 좌우 1px씩 더 나옴** · 문턱 아래 2px 그림자. 창은 스티커가 아니라 벽에 파인 구멍이다.
4. **튀어나온 기둥**: 앞면 3 + 옆면 2~5px(-2). 앞으로 나올수록 옆면을 넓게(아파트 5, 잡거 3).
5. **1층 가게는 물러선다**: 입구 재료에만 위 2줄(-2)·다음 2줄(-1)·왼쪽 2칸(-1) 그늘, 물러선 깊이 **8px**. 윗층 슬래브 그림자가 가게 윗부분에 내려온다. 벽 밑은 주춧돌. 차양·간판 아래에 -2 그림자 2줄.
6. **이웃 앞뒤 차이**: 가까운 건물의 밑변을 먼 건물보다 **8px 낮게** 놓고, 앞 건물 A 가 뒤 건물 B 의 왼쪽 **12px 에 그림자**(8px 는 -2, 4px 는 -1)를 드리운다.
7. **재료마다 면 색을 다르게**: 한 면이 기본 단 하나로 끝나면 안 된다. (위 그늘 -2 → 본체 0 → 슬래브 +1/+2 → 슬래브 밑 -2)를 층마다 반복 + 줄눈·물때. 단 5개 이상이 넓게 쓰이는 면이 화면에 있어야 벽이 산다.
8. **가로수**: 줄기 폭 = 밑변 폭(4px). 수관 약 32×48, 뒤 어두운 덩어리 → 앞 밝은 덩어리(덩어리마다 왼쪽 위 밝게), 보도에 그림자.

## 5. 32px 참고 → 16px 변환 규칙

- 참고의 1px 특징 = 16px 에서 **0.5px** 이므로 그대로 옮기지 않는다. **면의 단 구성과 배치**(무엇이 무엇 위에 드리우는가)만 가져온다.
- 32px 의 4~5단 벽 → 16px 는 **3~4단**(-2, 0, +1, +2)로 줄이고 줄눈은 1px 한 줄로.
- 32px 창 틀 2px → 16px 는 1px 틀 + 위 2px 그늘. 창 크기는 히어로 규모 표를 따른다.
- 글자·로고는 참고에서 옮기지 않는다(손 도트, 탁점 없음).
- 윤곽은 sumi 1px 이되 **밝은 면에서는 윤곽을 생략**하고 명암 단차로 형태를 낸다.

## 9. 알려 둔 한계 (정직한 목록)

1. **층 32px 는 압축**이다 — 히어로 1.33배. 참고 팩은 더 크고, 진짜 도시 규모가 아니다. 문 28은 히어로(24)보다 크지만 층 안에서 유일하게 지킨 규모 비.
2. **증명 블록과 히어로는 손으로 한 번 그린 것**이다. 킷 시트에 통합해 조립·통행·이음 검사를 돌려 본 적이 없다(§7-4 가 그 일).
3. 대각 반사와 패널 벽은 단순하다. 차·가로수는 **규모 그림에만** 있고 증명 블록엔 없다.
4. **154색은 일본 전용 124색보다 크다** — 학원·강남 재료를 한 벌로 묶은 대가다. 세트별로 쓰는 램프는 더 적다.
5. 대응표는 **자동 최근접**이라 시각 검토가 필요하다(36색 약함, 16색 모호). 밝은 끝이 거칠다(순백·연한 채도색 없음).
6. 대응표는 색만 옮긴다 — 윤곽·면 배분·밀도(결)는 다시 찍어야 한다.
7. 참고 색은 낮은 해상도로 눈대중한 것이다. 수치가 참고 팩과 같다고 주장하지 않는다.
8. 2차 데모(옛 jp 팔레트)는 견본 페이지에 **비교용**으로 남겼을 뿐 modern3 로 재작업하지 않았다.

## 10. 3/4 시점 계약 (2026-09-30, 사용자 판정 「일본 칩셋이 3/4 view 라고 하나, 전혀 안 지켜졌다」)

**진단.** 일본 킷·오브젝트, 강남 소품 일부, 학원 일부, 이 문서의 옛 증명 블록은 **정면 도면 + 앞면에 붙은 얇은 지붕 띠**였다. 맵 바닥은 칸당 1:1 위에서 본 판인데 물건만 정면이면 두 시점이 어긋나 「시야각이 이상」으로 읽힌다. 참고 팩(오사카 s1–s5, RPG Maker VX)은 진짜 3/4 이다 — 눈으로만 보고 픽셀은 베끼지 않는다.

### 10-1. 원리
1. **바닥 평면은 칸당 1:1 위에서 본 판**이다(16px = 1칸, 세로 압축 없음).
2. 물건은 **윗면 + 앞면** 두 면으로 그린다. **윗면 두께 T = 밑면 깊이 D(칸) × 16px**(건물, 1:1). 소품은 실제 깊이의 0.5~1.0배로 압축해도 된다.
3. **앞면 높이 F = 실제 높이** — 32px/층 규모표(§4)를 그대로 쓴다. 층수를 세는 것은 앞면이다. 윗면은 층수에 안 들어간다.
4. 옆면은 **안 보인다**(왼쪽 위 빛, 정면 고정). 예외: 소품 오른쪽 옆 −2 는 허용하나 T 에 넣지 않는다.
5. 스프라이트 높이 = F + T. 밑변 정렬은 앞면 맨 아래.

### 10-2. 건물 (증명: `style-demo-view34/shop3f.png`, `conbini.png`)
- 지붕판 = 깊이 D×16 (D=2 → 32px). 뒤 난간 캡 +3 → 안쪽 면 0/−2 → 바닥 +2(16px 이음 줄) → 옆 난간 → 앞 캡 2px.
- 지붕 위에 **실외기·물탱크·옥상 출입구** 를 얹고, 앞으로 **−2 그림자**를 떨어뜨려 지붕판이 평면으로 읽히게 한다. (지붕판을 너무 어지럽히면 검사기 평탄 판정이 깨진다 — 기물은 지붕 면적의 절반 미만.)
- 앞면 = 층수 × 32 (1층 가게는 44~48). 1층 입구는 8px 물러선다(§3-5).
- **통행**: 막힘(blocked) = 밑면 D×16 (앞면 맨 아래에서 위로 D칸). 그 위 나머지 = walk-behind(over). 즉 건물 **바로 뒤에 선 주인공은 지붕판에 가려지고**, 앞에 선 주인공은 앞면 앞에 그려진다. 막힘 칸의 「윗층」 이 곧 지붕 윗면이다 — 윗면은 밟는 곳이 아니라 **가리는 곳**.
- 옆면은 그리지 않는다. 이웃 건물 사이가 벌어져 있어도 옆벽은 안 보인다(정면 고정).

#### 10-2b. 앞면의 깊이 (사용자 판정 「벽이 평평해서 공간감이 없다」 — 2026-09-30)
앞면을 한 장의 벽지로 칠하지 않는다. 층·창·차양·발코니마다 **윗면 + 앞 가장자리 + 아래로 떨어지는 그림자** 가 있어야 한다. 이 표의 수치는 증명 `shop3f.png`·`conbini.png` 에서 실제로 쓴 값이다. **검사기로 못 잰다 — 눈으로 확인한다.**
| 부위 | 윗면(밝은 줄) | 앞면 | 아래 그림자 | 비고 |
|---|---|---|---|---|
| 층 사이 슬래브(처마·띠) | 3px | 2px + 1px 가장자리 하이라이트 | 3px | 합 9행. 층마다 반복. 벽면 그림자가 창 윗줄을 덮는다 |
| 창 | 문턱 윗면 2px | 문턱 앞 1px | 문턱 아래 2px | 창은 **들어가 있다**: 위쪽 안쪽 그림자 1px, 창틀 아래 1px 밝은 줄 |
| 필라스터(기둥형 벽 띠) | — | 폭 4px | 오른쪽 1px 어둠 | 벽면에서 튀어나온 띠. 창 사이마다 |
| 발코니 | 윗면 4px | 난간 2px + 가장자리 1px | 3px | 난간 살은 앞면 위. 뒤 문·창은 그림자 속 |
| 1층 출입구 | 문턱 윗면 2px | — | — | 8px **물러선다**: 문 위·양옆에 어두운 안쪽 면 |
| 간판판 | 윗면 2px | 12px | 3px | 벽에 얹힌 판. 정면 부착이라도 윗면과 그림자를 준다 |
| 차양 | 앞으로 튀어나온 윗면 7 | 앞 가장자리 3 | 벽 그림자 2 | 줄무늬 띠 한 장 금지 |
| 1층 가게 높이 | | 48 이상 | | 32/층 규칙의 예외(가게 1층) |
- 광원은 왼쪽 위. 슬래브·발코니의 오른쪽 끝에는 1px 어두운 옆 그림자만 허용하고 옆면을 그리지 않는다.
- 편의점 간판·유리벽처럼 **평면에 붙은 것** 은 평평해도 정상이나, 그 위아래 슬래브·문턱·매트가 깊이를 만든다.

### 10-4. 금지

- **옆에서 본 정면 입면도 차**: 가로 진행 차가 옆면 한 장(지붕·보닛·트렁크 윗면 없음)이거나 세로 진행 차가 앞면만 있는 것 — 택시는 **두 방향 모두** 위 표 형태로 그린다.

## 11. 실내 3/4 (2026-09-30)

실외 §10 과 같은 원리다: **바닥은 1:1 위에서 본 판, 물건은 윗면 T + 앞면 F**. 실내에서 가장 자주 어기는 것은 **벽에 붙는 키 큰 가구**(옷장·책장·찬장·벽난로)를 앞면 한 장으로 그리는 것이다. 벽 자체는 그대로 둔다 — **천장 윗면 + 2칸 벽 앞면**(벽이 이미 3/4 이다).

### 11-1. 가구 종류별 T/F 표 (T = 윗면 px, F = 앞면 px, 16px 칸)
| 종류 | 예 | T (윗면) | F (앞면) | 윗면이 어디에 보이나 |
|---|---|---|---|---|
| **벽 붙은 키 큰 가구** | 옷장, 책장, 찬장, 벽난로, 선반, 사물함, 자판기 | **4~6px** | 나머지 전부 (키 − T) | 벽 쪽(맨 위). 위에서 T 를 지나 **앞 가장자리 하이라이트 1행**, 이어서 **처마 그림자 2px**, 그 아래가 문·선반이 **들어간** 앞면 |
| 기둥·굵은 지지대 | 석주, 목주 | 폭 = 깊이 D×16 의 윗면 (둥근 단면은 타원 캡 3~4px) | 키 | 맨 위 |
| 탁자·침대·카운터 | 식탁, 침대, 계산대 | 깊이의 0.5~1.0배 (보통 8~14px) | 다리·측면 아래 8~14px | 상판 전체 (물건은 상판 위) |
| 의자 | 의자, 스툴 | 좌판 윗면 4~6px | 다리 6~8px | 등받이는 좌판 뒤에서 솟는다 |
| 상자·항아리·통 | 상자, 통, 화분 | 4~8px (뚜껑·입구) | 8~16px | 윗면 |
| 벽 부착물 | 액자, 거울, 벽걸이 | 없음(벽 앞면에 붙음) | 벽 위 | 정상 — 평면 부착은 평평해도 된다 |
- **T 의 뜻**: 밝은 윗면이 아니라 **앞 가장자리 하이라이트가 처음 나오는 행 번호**로 잰다(가구 실루엣 위에서 9행 안). 옛 그림은 T=1~2 (앞 가장자리가 맨 위에 붙음), 새 그림은 T=5~6.
- **앞면은 안쪽으로 들어간다**: 문·서랍·선반은 1~2px 안쪽 그림자, 벽난로는 아궁이가 들어간 어둠, 책장은 책이 선반 안에 앉는다. 처마(코니스) 그림자 2px 가 윗면 바로 밑을 눌러 준다.

- **금지**: 앞면 한 장(T≤2), 윗면이 앞면과 같은 크기(TOPDOWN: T>8 또는 앞면 <15px), 벽 구조 바꾸기(천장 윗면+벽 2칸 유지).

## 12. 칸수 계산 — 1칸 = 16px = 1m (2026-09-30, 사용자 확정 16 px/m)

지금까지 칸수는 감으로 정했다(자판기 2x2, 서랍장 1x1 …). **실제 크기에서 계산**하도록 바꾼다. 계산기: `scripts/content/atlas-pick/size_calc.py`, 표 정본: `tiledata/atlas-pick/size-table.json`, 전수 점검: `tiledata/atlas-pick/size-audit.json`, 표준 캔버스 사이드카: `tiledata/atlas-pick/size-std.json`.
(이력: 같은 날 먼저 「주인공 170cm 기준 1 m = 14 px」 잠정 기준으로 만들어 `abcaf7dcc` 로 커밋했으나, 사용자가 「16x16 기준으로 칸수를 재설계」 를 확정해 이 절 전체를 16 px/m 으로 다시 썼다. 14 px 숫자는 이 절에 남기지 않는다.)

### 12-1. 기준
- **1 칸 = 16 px = 1 m.** 캔버스 폭(칸) = ceil(실제 폭 m). 폭 1.0 m 인 물건은 폭 16 px, 한 칸을 꽉 채운다.
- 주인공은 **16x24, 발자국 1칸 그대로**다.
- **모순(기록)**: 이 축척에서 주인공 24 px = **1.5 m** 로, 실사 170 cm 와 어긋난다(키 2.0 m 옷장이 32 px = 주인공의 1.33배). 주인공은 축약 캐릭터이므로 손대지 않고, 표는 히어로가 아니라 「1칸 = 1 m」 에 묶는다. 「히어로 옆에 세웠을 때 어색함」 은 이 모순의 부작용이므로 판단할 때 1.5 m 를 감안한다(옷장은 히어로보다 8px 크게 보이는 것이 정상).

### 12-2. 공식
| 값 | 식 |
|---|---|
| 그림 폭 px | 실제 폭 W(m) x 16 (칸 경계를 1 px 넘으면 1 px 깎음) |
| 캔버스 폭(칸) | ceil(W) |
| 앞면 F px | 실제 높이 H(m) x 16 |
| 윗면 T0 (원본) | 실제 깊이 D(m) x 16 |
| 윗면 T (압축) | T0 x **압축계수 c** (종류별 하한 tmin·상한) |
| 캔버스 높이(칸) N | N0 = ceil(F / 16) 에서 시작, **F + T <= 16 x N** 이 되는 첫 N |
| 막힘(blocked) | 폭 칸 x max(1, round(D)). 벽 붙은 가구·기둥은 깊이 1. 그 위 칸은 walk-behind(over) |

- **압축계수 c**: 윗면은 3/4 시점에서 세로로 눌려 보인다. 자립 가구 0.6(T 하한 4), 침대·의자·화분·긴 판 0.5, 벽 붙은 키 큰 가구 0.6(T 4~6), 가는 기둥 0.5(T 하한 2), 벽 부착 평면(칠판·문) T 0, 가로 진행 차량 0.30(T 하한 6), 세로 진행 차량 0.65(T 하한 6). **표에는 원본 T0 와 압축 T, 최종 T 를 모두 적는다.** F 도 원본(H x 16)과 최종을 함께 적는다.
- **넘침 규칙 (누가 먼저 양보하는가)** — F + T 가 16 x N 을 넘는 양을 o 라 할 때:
  1. o <= 6 px 이면 칸을 늘리지 않고 아낀다. **먼저 T(윗면)가 양보한다**: 종류의 하한 tmin 까지 줄인다(윗면은 4 px 아래로 가면 3/4 읽기가 무너진다).
  2. T 를 하한까지 줄이고도 남으면 **그다음에 F(앞면)가 양보한다**: 단 **4 px 이하이고 F 의 15% 이내**일 때만. 넘으면 칸을 하나 늘린다(N+1). (서랍장 F16 은 4 px = 25% 라서 F 는 못 깎는다.)
  3. o > 6 px 이거나 위가 안 되면 N+1.
  - 요약: **T → F → 칸 늘림** 순서. 앞면(F)은 사람이 알아보는 몸통이므로 마지막에, 그것도 4 px·15% 한도 안에서만 깎는다.
- **옷장 앞면을 깎는 규칙**: 키 2.0 m = F 32 px = 정확히 2칸이라 윗면 T 를 둘 자리가 없다. T 를 하한 4 로 두고 **F 를 4 px(12.5%) 깎아 F 28 + T 4 = 32** 로 정한다. 허용 범위는 F 26~28 / T 4~6(F+T = 32). 기본은 T 를 하한(4)에 두는 쪽이며 F 26 T 6 은 손이 갈 때만. 같은 규칙이 키 1.8 m 물건(사물함·약품장·자판기: F 29 → 28)에 적용된다.
- **축약 관례**(가로등·전봇대·신호등·차량·가로수·건물)는 화면 한 장에 넣으려고 줄이는 것이 게임 문법이다 → 감사에서 `exempt` 로 따로 센다.

### 12-6. 충돌 기록 — 「일본 자판기는 2x2」
- 사용자가 앞서 「일본 자판기는 2x2 사이즈로. 자판기를 여러 종류를 할거임.」 이라 했고 jp `vending_drink`·`vending_ice` info.json 에 `resized: [1,2] → [2,2]` 로 남아 있다.
- 16 px/m 표에서는 자판기 1대 = 폭 1.0 m = **16 px = 1칸**(1x2). 2x2 캔버스에 그리면 옆 자판기와 폭이 맞지 않는다.
- **해석**: 2x2 는 「자판기 **두 대 한 벌**(나란히)」의 칸수로 읽는다(`vending_pair`, 폭 32 = 2칸). 낱개 자판기는 1x2 로 정한다. 이 해석이 사용자 의도와 다르면 사용자가 다시 정한다 — 그때까지 **표(1x2)가 기준**이고, 기존 2x2 후보는 지우지 않고 두며 전수 점검에는 `alt`(쌍 해석)로 기록한다.
