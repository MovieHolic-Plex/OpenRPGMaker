# 일본 세트 「조립형 킷」 부품 찍기 — 작업자 절차서

너는 작업자 `kN`(k1…k10, 감독자가 번호를 준다)이다. `tiledata/atlas-pick/jobs-jp-kit.json` 의 `workers.kN.kits` 에 적힌 **킷 한 벌**을 맡는다.
재작업 작업자 `rN` 은 1~4절을 건너뛰고 **5절**과 `WORKER-JP.md` 를 따른다.

## 왜 킷인가 (사용자 요구, 2026-09-30)
사용자가 1판 일본 후보를 보다가 이렇게 남겼다.
- konbini_front 「편의점을 이렇게 단독 칩셋으로 하지 말고 조립형으로」 · zakkyo_building 「건물은 조립형으로」
- station_entrance 「하나의 단독 칩셋보다 조립형」 · station_gate 「조립형 + **실제 통행이 가능해야**」 · jp_signal 「조립형으로」

한 장 그림은 크기가 하나뿐이다. 맵에서는 폭 5칸 가게, 9칸 가게, 3층·5층 빌딩, 통로 셋·다섯 개찰구가 필요하다.
그래서 **이어 붙는 부품 묶음 + 조립 설계도**로 바꾼다. 사용자는 부품 낱장이 아니라 **조립한 결과**(여러 크기 설계도를 거리 위에 놓은 그림)를 보고 고른다.
후보 단위 = **킷 한 벌**: 후보 A 는 킷 부품 전부를 A 결로, B 는 전부 B 결로.

## 1. 킷·시트·설계도
- **부품** = 16px 칸 단위 조각(1×1, 1×2, 2×1 …). 부품마다 층(`facade` 불투명 건물 블록 · `ground` 불투명 바닥 · `object`·`wall`·`over`·`decal` 투명), 반복 방향(`x`·`y`·`xy`), 통행(`X` 막힘 · `F` 걸음 · `C` 사람 위로 지나감), 문(door) 여부가 있다.
- **부품 시트** = 킷의 부품 전부를 한 장에 놓은 그림. 자리는 조립기가 정했다(`slots.txt`). 네 후보 파일 하나 = 시트 한 장:
  `candidates-jp/<킷>/kN-A.pxg`, `kN-B.pxg`, `kN-C.pxg` (첫 줄 `@size W H` `@cell 16` `@palette palette.pal` — W·H 는 `info.json` `canvas`).
  **자리 밖에는 아무것도 칠하지 마라**(빈 자리는 투명). 부품이 자기 칸 밖으로 번지면 조립할 때 잘린다.
- **설계도(조립 예)** = kits-jp.json `examples`. 낱말 하나 = 부품 하나. 조립기가 부품을 잘라 설계도대로 붙이고, 거리(보도·차도) 또는 역 바닥 위에 놓아 굽는다. 폭·층수·길이가 다른 예가 여러 개다 — **모든 예에서 좋아 보여야** 한다.
- **다른 킷 빌리기**: `kit_bldg` 의 1층은 `S:band_l` 처럼 `kit_shopfront` 부품을 빌린다(같은 방향 글자 후보 → 없으면 파일럿). 그래서 k1·k2 는 kits-jp.json 의 두 킷 `contract` 이음 줄(벽 맨 아래 1px = 간판 띠 맨 위 1px = `mconc` 2단)을 **반드시** 지킨다.
- 설계도·부품 목록을 바꾸고 싶으면(부품이 모자라다, 크기가 틀렸다) **고치지 말고 감독자에게** 「<킷>: <부품> 을 이렇게 바꾸자, 이유」 를 보고하라. kits-jp.json 을 고치면 자리(좌표)가 밀려 다른 후보가 깨진다.

## 2. 결 규칙 (WORKER-JP.md 1·3절 + 16px 실내 1판 교훈 WORKER.md 1-b절)
- 1판 판정: **C 35 · B 31 · 현재판 유지 20 · A 11**, 「조금 다듬기」는 거의 안 고른다 → **A 도 눈에 띄게 좋아야** 한다.
- 거절 1위 = **입체감·공간감 없음**: 윗면·옆면·앞면이 다른 명도. 시점은 맵과 같은 **위에서 약간 내려다보는 정면 고정 각** — 앞면이 주인공, 윗면(지붕판·옥상 난간·기계 윗면)은 1~3px 띠로 보인다. 정면 도면·완전 위에서 본 판은 「시야각이 이상」으로 거절된다.
  > **[폐기 2026-09-30 — modern-style-bible.md §10 「3/4 시점 계약」이 대체]** 위 「1~3px 띠 · 정면 도면」 안내가 일본 킷이 정면 도면으로 나온 원인이었다(사용자: 「3/4 view 라고 하나, 전혀 안 지켜졌다」). 새 기준: **윗면 두께 T = 밑면 깊이 D×16px, 앞면 F = 층수×32**. 건물 T/F 0.10~1.10(T≥14), 자판기류 0.22~0.60, 차 0.28~0.95. 앞면만 있고 윗면이 없거나 1~3px 띠면 **FRONT/NOTOP 으로 거절**한다. 후보를 낸 뒤 `python3 scripts/content/atlas-pick/view34_check.py <png>:<분류>` 로 확인하라. 견본: `tiledata/atlas-pick/style-demo-view34/`.
- **색감**: 탁하거나 튀는 색 거절. 바닥(보도·아스팔트)과 명도를 분리하되 몸통 채도는 낮게. 주홍·네온은 면적 작게 한 덩이로.
- **질감**: 재료가 16px 에서 읽혀야 한다(타일 = 줄눈, 기와 = 가로 골, 쇠 = 밝은 테 한 줄, 유리 = 반사 사선).
- **알아볼 수 있어야**: 조립한 결과가 한눈에 콘비니·이자카야·역 입구로 읽혀야 한다. **세부가 많다고 이기지 않는다** — 읽히는 덩이 몇 개가 잔 점 스무 개보다 낫다.
- **어울림**: 강남 조각·현대 시트 바닥과 이어진다. 윤곽은 검정이 아니라 재료의 어두운 단, 오른쪽·아래 테가 한 단 더 어둡다. 빛은 **왼쪽 위**. 베개 명암 금지.
- **반복 소재는 변형이 필요하다**(사용자 1-b: 「반복 소재는 변형 여러 개」) — 킷에 변형 부품(창 세 종, 간판 가운데 A·B)이 있으면 서로 분명히 다르게.
- **집 외형 규칙**(사용자): 벽 면 3칸 이상, 창은 벽 가운데 칸에만(문 바로 옆 금지), 지붕 사선 뒤 빈칸 금지. 설계도가 이미 지킨다 — 부품이 이를 깨는 모양(창이 칸 가장자리에 붙음)이 되지 않게.
- 색은 `palette.pal`(= `palette/jp.pal`) 안에서만, `@mat`·`@mblock`·`@tblock`·`@tadj` 로. 반투명은 `~` `-` `%` 셋뿐이고 **투명 층 부품에만**(facade·ground 부품은 전 화소 불투명 — 검사 PART_HOLES).
- 한자·가나는 획 2px 기본, 가짜 글자 금지, 실제 상표·로고 금지(색 띠·일반 낱말만).
- EasyRPG 칸(현대 시트 0~2729)·REFMAP·서드파티 팩(`~/.local/share/oprn/refmap-downloads/_packs/`, `~/third-party-assets/`)은 **봐도 되지만 화소를 옮기지 마라.** 검사가 95% 이상 닮은 칸을 불합격시킨다. 그런 팩을 저장소에 복사·커밋하지 마라.

## 3. 이음 — 킷에서 가장 중요한 것
킷이 한 장 그림과 다른 점은 **이어 붙인 자리가 안 보여야** 한다는 것이다.
- `repeat` 가 `x` 인 부품은 **왼 끝 열과 오른 끝 열이 이어져야** 한다: 무늬 주기를 16의 약수(4·8·16)로, 테두리·틀은 한쪽에만(예: 유리창 틀은 왼쪽 1px 만 — 이어 붙이면 틀이 한 번씩 나온다), 빛·그늘 끝선(왼 밝음·오른 어둠)은 **끝 부품(l·r)** 에만.
  파일럿의 셔터가 왼 끝을 밝게·오른 끝을 어둡게 칠했다가 조립기가 「셔터를 x 로 이어 붙이면 경계가 튄다」로 잡았다 — 이런 것이다.
- `y` 반복(층 벽·기둥·계단·세로 간판)은 위아래 끝 줄이 이어져야 한다. 한 층 벽 부품의 위 1px·아래 1px 층 이음 줄은 모든 벽 부품에서 같은 단.
- **이웃 이음**: 킷 `contract` 에 적힌 줄(띠 밑 그늘 두 줄, 문턱 세 줄, 팔 높이 y=3~6, 기둥 x=6~10 …)은 모든 부품이 같은 픽셀 높이·같은 단으로 지킨다. 서로 다른 부품이 나란히 서도 그 줄이 한 줄로 이어진다.
- 조립기가 보는 것: 반복 부품을 세 번 이어 붙여 경계 차를 부품 속 가장 큰 이음과 견준다(`SEAM`, 점수 1.3 초과면 경고). 경고는 불합격이 아니지만 **거의 다 진짜 이음 자국**이다 — 고쳐라.

## 4. 통행 — 설계도가 정한다
- 통행은 칸마다 부품의 `walk` 로 정해진다(그림으로 정하지 않는다). 그림은 그 통행과 맞아야 한다:
  `X` 칸 = 벽·기계 몸통·기둥 밑동(사람이 못 들어가 보이게) · `F` 칸 = 문 아랫칸·계단·통로·바닥(발 디딜 곳이 보이게) · `C` 칸 = 처마·팔·전선·기둥 윗부분(사람이 그 밑을 지나간다 — 칸 아래쪽이 비어 보이게).
- 조립기 검사: `DOOR_REACH`(드나드는 칸에 거리에서 닿는가), `THROUGH`(개찰구·도리이·건널목은 위 → 아래로 걸어서 지나가는가), `DOOR_FRONT`(문 바로 아래가 막혔나).
  설계도는 감독자가 이미 통과시켜 두었다 — 네가 부품 크기·자리를 지키면 통과한다. 「통행 표시」 그림(`kN-A.walk-<예>.png`)에서 빨강 = 막힘, 파랑 테 = 드나드는 칸, 노랑 점 = 사람 위, 초록 = 지나가는 길.
- **개찰구(k4)**: 사용자 요구가 「실제 통행 가능」이다. 기계 몸통은 칸 가운데 10~12px 로 좁히고 통로 칸은 발 디딜 바닥이 보이게 — 통로가 기계에 먹혀 보이면 통과해도 실패다.

## 5. 재작업 기물 rN (킷 아님 — 보통 기물, 절차는 WORKER-JP.md 그대로)
- 사용자 메모: vending_drink·vending_cig 「2x2 사이즈로. 자판기를 여러 종류를 할거임.」, ticket_machine 「3x2 및, 공간감을 살려라」.
- 크기는 `jobs-jp.json`·각 `info.json` 이 이미 바꿨다(`resized` 에 이유). 옛 크기 후보(`j3-*`·`j4-*`)는 화면에서 「옛 크기」로 접힌다 — 참고만.
- 파일은 `candidates-jp/<기물>/rN-A.pxg …`, 검사 `check_candidate.py`, 맥락 `context.py`(WORKER-JP.md 5절).
- **자판기 식구**(음료 흰·담배·커피·아이스크림·캡슐토이, r1·r2 두 사람): 같은 방향 글자끼리 **같은 높이·같은 윗면 두께(2~3px 지붕판)·같은 옆면 폭(오른 3~4px 한 단 어둡게)·같은 발치 그림자**. 몸통 색·견본 칸 무늬만 다르다.
  나란히 세웠을 때 한 줄 자판기 코너로 읽혀야 한다. 둘이 먼저 윗면 두께·옆면 폭 숫자를 note 에 적어 맞춰라(r1 이 정하고 r2 가 따른다).
- **매표기 3×2 공간감**: 몸통 윗면의 비스듬한 조작판(밝은 단 3~4px)이 핵심, 기계 사이 이음 그늘 1px, 오른 끝 옆면, 뒤 벽의 요금표 판이 기계보다 한 단 어둡게 뒤로 물러나 보이게.

## 6. 절차 (킷 작업자)
```bash
K=tiledata/atlas-pick/candidates-jp/<킷>
cat $K/slots.txt                                        # 부품 자리(px)
python3 scripts/content/atlas-pick/jp_kit_compose.py prepare   # (자리 파일이 없을 때만 — 이미 돼 있다)
#   방향 하나를 시트 한 장으로: 1 실루엣(# 한 색, 부품마다) → 2 평면 색 → 3 빛(왼쪽 위) → 4 결 → 5 정리.
#   도우미 스크립트를 쓰려면 $K/work/kN_<방향>.py 에(파일럿 pilot_shopfront.py 처럼 부품 좌표로 그리고 pxg_emit.emit 으로 .pxg 를 쓴다).
#   보간·잡음·그라디언트 함수 금지 — 단을 손으로 놓는 사각형·선·도안만.
echo "한 줄 메모" > $K/kN-A.note
python3 scripts/content/atlas-pick/jp_kit_compose.py $K/kN-A.pxg      # 검사 + 조립 (수 초)
```
- 조립 뒤 **반드시 `$K/kN-A.board.png` 를 열어 눈으로 본다**(모든 조립 예 맥락·통행 3배 + 반복 이음 띠). 숫자가 합격이어도 이상하면 고친다. 특히:
  「가장 큰 예에서도 반복이 티 나지 않나」 「작은 예에서도 무엇인지 읽히나」 「윗면·앞면이 나뉘나」 「다른 킷 부품(빌린 1층 등)과 이음 줄이 맞나」.
- hard 불합격(✗ — REF·COVER·JOIN·DOOR_REACH·THROUGH·PART_EMPTY·PART_HOLES, check_candidate 의 size·palette·easyrpg·refmap·mark·bg)은 **0 으로 만든 뒤** 제출. `pxlint16` 은 참고.
- 셋(A·B·C)을 다 낸 뒤 시간이 남으면 D. 셋은 **서로 달라야** 한다(WORKER-JP.md 2절 방향표 — A 강남 결, B 명암·그림자 강화, C 실루엣 재해석). 킷에서 C 는 비율·부재 굵기·지붕 모양을 다시 생각하되 **자리(칸 수)는 그대로**.
- 킷 하나에 한 방향 40~60분을 넘기지 마라. 부품이 많으면 먼저 반복 부품(벽·창·띠)을 끝내고 끝 부품·덧칠 부품으로.
- 끝나면:

## 8. 감독자용
- 킷 추가·수정: `kits-jp.json` 을 고친 뒤 `jp_kit_compose.py prepare`(자리가 바뀌면 있는 후보 시트가 어긋난다 — 후보가 생긴 뒤에는 부품을 **끝에만** 덧붙여라). 설계도만 바꾸면 자리는 그대로다 → `jp_kit_compose.py --all` 로 다시 조립.
- 빌려 쓰는 예(kit_bldg 1층 = kit_shopfront)는 빌려 준 킷 후보가 바뀌면 `--kit kit_bldg` 로 다시 조립해야 새 그림이 된다. 사용자가 kit_shopfront 를 고르면 그 후보를 빌린다.
- 화면: 킷 항목은 「킷」 배지, 대체된 옛 기물은 「→킷」 배지로 숨긴다(「킷으로 옮긴 옛 기물」 켜면 보임). 옛 기물의 선택·메모 기록은 DB 에 그대로 있다.
- 메모 반영 기록(킷 후보가 들어온 뒤): `python3 scripts/content/atlas-pick/picks_db.py address jp <옛 slug> "조립형 킷 <킷> 로 옮김"`.
- 서비스 재시작: `export XDG_RUNTIME_DIR=/run/user/$(id -u) DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u)/bus; systemctl --user restart atlas-pick` (18303. 18300 은 건드리지 않는다).
