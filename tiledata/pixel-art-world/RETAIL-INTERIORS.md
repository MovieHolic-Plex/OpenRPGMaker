# 천장 아래 벽과 두 종류의 가게

사용자 확정 규칙(2026-09-25): **오토타일 천장 아래에는 반드시 벽이 있어야 한다.**
32px·0기준. 같은 천장이 세로로 연속되면 그 덩어리의 마지막 칸을 남쪽 끝으로 본다.
끝 바로 아래에 벽 몸통→하단 마감 두 행을 둔다. 맵 남쪽 끝·짧은 내벽 끝도 예외가 아니다.
천장을 지워 문을 만들 때 위쪽 천장 끝에 필요한 벽 높이까지 먼저 확보한다.
문 앞을 벽으로 막고 통행만 켜는 방식은 금지다. 가구 상부는 벽에 겹쳐도 밑동은 바닥이어야 한다.

## 소유와 실행

- `retail-interiors-layout.json`: 가게2종의 외곽·문턱·방·가구 원점·접근 좌표.
- `prepare-pixel-art-world-retail-interiors.mjs`: 현재 프로젝트 소유 참고문서/아틀라스와
  사용자 PNG의 해시를 확인하고 전체 배열·원본 해상도 그림·정상/오류 문서를 만든다.
- `retail-interiors-compiled.json`: 완성 하위/상위 배열, 천장·벽면 좌표와 조립 지침.
- `pixel-art-world-ceiling-walls.mjs`: 남쪽 노출 끝 산출, 벽 배치, 누락 검사.
  벽이 맵 밖으로 나가거나 다른 천장과 겹치면 실패한다. 같은 타일 번호라도 시트별 역할을 확인한다.
- `save-pixel-art-world-host-patch.mjs`: 호스트 API CAS 저장·전체 재로드·변경 이미지 재읽기.
- `publish-pixel-art-world-local-library.mjs`: 정본 배열과 청사진이 같은 가게만 검토된 공용 루트에 등록.
  공용 장소·맵·타일 참고문서·전체 조립 킷·그림을 같은 사용자 공용 SQLite에 게시·재로드한다.

그림은 사용자 로컬 전용이다. 원본/가공 소재를 Git/public/번들에 배포하지 않는다.
기존380원본 범위 안의 파일만 재사용하며 새 다운로드는 없다.

## 이자카야 보정

현재 이자카야는 **14×24, 분리 조리실·다다미 개인실·부스2·바6**이다.
`tiledata/pixel-art-world/izakaya-kitchen-layout.json`이 청사진이며
`izakaya-ceiling-compiled.json`이 전체 배열이다. 생성기는
`scripts/content/prepare-pixel-art-world-izakaya-ceiling.mjs`다.
홀은 원본 목재 마루0/1(원본 첫 행 x0/1, 2×1 반복), 주방은6, 개인실만 다다미다.
다다미는 원본2×3 배열 `[[296,297],[304,305],[312,313]]`을 가로3회·세로2회 반복한다.
개인실 내부는(7,15)부터6×6, 탁자·방석6 완전체는(8,16)부터4×4이다.
북쪽 천장y12 아래 벽y13/14, 서쪽x6 벽, 동쪽·남쪽 외벽이 방을 둘러싼다.
유일한 열린 출입구(6,18)/(6,19)를 통해 들어가며 탁자 둘레1칸을 비운다.
문턱 바깥은 목재 마루다. 미닫이문·신발장·신발 착탈 이벤트를 구현했다고 주장하지 않는다.
주방 문은(6,4)/(6,5), 작업행y4..5, 냉장고(11,1), 조리대(7,1), 레인지(10,2)다.
부스(1,3)/(1,10), 바6석(7..12,10)과 의자 뒤y11, 급차대(1,17)/급차기(4,17)를 둔다.
주통로x5는 끊기지 않고 x4는 급차기 앞 두 행만 점유한다. 모든 가구 밑동은 바닥이다.
천장480..526(47변형), count528을 유지한다.86천장칸·78벽면칸이며
모든 남쪽 노출 천장 끝 아래에17/25 벽 두 행을 둔다. 남쪽 천장y21 아래는y22/23이다.
실제 충돌 엔진으로82개 접근/문턱 목표를 확인한다. 주방과 개인실 문을 각각 막으면
그 방만 고립되어야 한다. 개인실 서벽 한 칸을 바닥으로 바꾸는 반례의 경계 누출도 확인한다.
다다미가 방 밖으로 번지거나 방 안에서 빠진 경우 생성기를 실패시킨다.
정본 저장→동일SQLite 재로드→로컬 공용CAS 게시/재로드 순서이며
정적 장소와 저장 맵 두 경로를 함께 갱신한다. 증거는 `output/paw-izakaya-private-room/`.
원본·파생 그림 추가 다운로드와 재배포는 없다. 구조 확인은 새 LLM 재현 실험이 아니다.

## 검증 범위

이자카야86천장/78벽면, 서점·아이스크림점 각각41천장/34벽면.
실제 충돌 엔진으로 접근점82/28/34개와 가게의 모든 빈 바닥 연결을 확인한다.
각 정상/오류 그림은 벽면 하나를 바닥으로 바꾸고 출구를 막은 반례를 포함한다.
`CEILING_WALL_MISSING`, `APPROACH_BLOCKED`로 검출하고 전체 오류 배열을 참고문서에 보관한다.
이자카야는 직원 출입구 봉쇄 시 주방만 고립되는지도 확인한다.

구조/통행 검사는 미적 승인이나 새 LLM 생성 성공률이 아니다. 두 가게는 실제 저장된 독립 맵이며
도시 입구·판매·착석 이벤트는 별도다. 이전 학교/주택/시설 전체를 새 벽 규칙으로 재저작한 결과가 아니다.
