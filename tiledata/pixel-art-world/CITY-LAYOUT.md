# 햇살동 50×50 — 목적과 보행 연결부터 저작하는 청사진

2026-09-24. `city-layout.json`이 시설 역할·구역·건물 범위·지면·도로·소품·연결의
공용 원본이다. `prepare-pixel-art-world-city.mjs`는 이를 실제 조립 타일로 바꾸고
`city-50.json`과 `src/assets/pixelArtWorldCity.json`을 함께 만든다. 원본 그림은
사용자가 내려받아 로컬에서 합성한다. 이 문서나 JSON에는 소재 픽셀을 포함하지 않는다.

## 확인한 자료와 적용 범위

- [RPG Maker 공식 Mapping: Towns](https://rpgmakerweb.com/blog/mapping-towns):
  마을의 목적과 중심 시설, 짧은 접근 동선, 역할 없는 빈 공간, 격자에 맞춘 반복 배치를
  짚는다. 여기서는 학교·생활 상가·주거·공원을 구분하고 등간격 3×3 블록을 버리는
  설계 판단에 사용했다. 특정 타일 수나 배치의 미감을 보증하는 공식은 아니다.
- [Tiled 공식 Focus on Level Design with Automapping, 2026-07-14](https://www.mapeditor.org/2026/07/14/focus-on-level-design-with-automapping.html):
  편집할 blueprint와 규칙으로 생성되는 최종 타일을 분리한다. 여기서는 JSON의
  의미·geometry와 타일 출력을 분리하는 작업 순서에 적용했다. Tiled 규칙 엔진을
  사용하거나 그 예제 던전을 복제한 것은 아니다.
- [COHO, ECCV 2024 / arXiv 2407.11294](https://arxiv.org/abs/2407.11294):
  건물·블록·지역·도시를 속성이 있는 그래프로 다루는 연구다. 여기서는 시설과 구역,
  방문 목적과 실제 보행 연결을 기록하는 표현 원칙만 참고했다. 학습 모델·샘플링
  알고리즘·논문의 평가 결과를 구현하거나 재현했다고 주장하지 않는다.

위 자료를 2026-09-24 직접 열어 확인했다. 최근 공식 문서와 선행 연구를 함께
참고한 것이며, 가장 최신 연구를 망라했다거나 연구가 이 지도의 품질을 입증한다는 뜻이 아니다.

## 구역과 움직임

| 구역 | 범위 x,y,w,h | 역할과 연결 |
|---|---|---|
| 학교 | 1,1,18,23 | 학교 정문 → 앞마당 → 흙 휴식 마당 → 학교 앞 횡단보도 |
| 공공 보행로 | 21,0,27,14 | 도서관과 의원을 짧은 공유 보행로로 묶고 상가 사이 길로 연결 |
| 생활 상가 | 19,14,30,12 | 편의점과 식당 전면을 생활도로 북쪽 보도에 가까이 둠 |
| 주거 골목 | 1,32,34,17 | 서로 다른 깊이의 두 집과 사무실, 좁은 앞길과 막다른 접속로 |
| 공원 | 35,32,15,18 | 상가 맞은편 횡단보도 → 생울타리 사이 입구 → 놀이 공간과 벤치 |

주도로는 `(0,25,50,5)`, 남쪽 접속로는 `(19,30,3,17)`이다. 반복 사거리 네 개를
만들지 않는다. 북측 보도는 y23..24, 남측 보도는 y30..31이다. 주도로 중앙은 y27의
원본 가로 흰 줄14를 두 칸 표시/두 칸 공백으로 놓으며 횡단보도와 접속로 앞은 비운다.
도로 중앙 표시를 보행 연결로 계산하지 않는다.

시설 8동의 크기와 원본 조립은 유지하고 위치를 바꿨다. 정확한 문·양쪽 접근칸은
생성된 `entrances`가 소유한다. 이벤트 저작기는 옛 절대좌표를 재사용하지 말고
이 배열과 `room`, `entranceWidth`, `start`를 읽어야 한다.

## 검토한 추가 조각

ST-Convi-E01의6은 세로 흰 줄,14는 가로 흰 줄이다. 14를 주도로 중앙 점선에도
사용한다. 표시 색이나 원본 픽셀을 새로 그리지 않는다.

ST-Park-E01의 생울타리는 원본 3열×2행의 `[152,153,154] / [160,161,162]`다.
양 끝을 보존하고 가운데153/161만 늘린다. 학교 마당 앞과 뒤, 의원 뒤, 공원 입구의
경계를 만드는 데 사용한다. ST-Schl-E01의363은 완결된 공 한 칸이며 학교 흙 마당에
둔다. 이 공간을 경기장 규격을 갖춘 운동장이라고 주장하지 않는다.

## 생성 중 지켜지는 조건

`node scripts/content/prepare-pixel-art-world-city.mjs`는 파일을 쓰기 전에 다음을 확인한다.

1. 50×50 크기, 시설8개, 원본 타일 범위, 건물과 소속 구역의 유효 범위.
2. 건물 bbox끼리 겹치지 않고 도로·보행 geometry가 건물을 침범하지 않음.
3. 소품은 건물과 기존 upper 조각을 덮지 않고, 횡단보도와 중앙 표시는 차도에만 놓임.
4. 모든 문짝 앞 접근칸이 시작점에서 저작된 보행 지면과 지정 횡단보도로 연결됨.
5. graph의 모든 시설·중간 지점과16개 연결에 실제 경로가 존재함.

4·5의 계산은 잔디와 무표시 차도를 지름길로 사용하지 않는다. 런타임 자체에서
잔디를 차단한다는 뜻은 아니다. `design.graph.edges[].cells`는 행 우선 인덱스로
계산한 실제 경로, `distance`는 이동 칸 수다. `design.generationChecks`에 해당
생성의 문짝 접근 좌표와 연결 수를 기록한다. 이 검사는 생성기의 콘텐츠 무결성
조건이며 테스트 스위트나 플레이어 런타임 QA를 대신하지 않는다.

## 실제 그림과 남은 경계

사용자 다운로드 원본 다섯 개의 SHA를 확인해 전체1600×1600 PNG를 합성하고 직접
열어 도로 점선, 횡단보도, 생울타리 끝, 건물·소품 연결을 확인했다. 로컬 증거는
`output/paw-city-review/city-structure-v2.png`이며 저장소에는 넣지 않는다.

학교 마당과 공원에는 의도된 비포장 공간이 남아 있다. 문·동선 연결이 된다는 사실은
도시 미감에 대한 완료 승인이나 연구상 품질 보증이 아니다. 이 변경은 생성 코드와
청사진까지만 다루며, 실제 설치 완료는 감독자가 정본 저장·재로드·플레이어 출입을
확인한 뒤 보고한다. 이 작업에서 테스트/게이트/정본 DB 쓰기는 실행하지 않았다.
