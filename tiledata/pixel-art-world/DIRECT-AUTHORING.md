# 완성 맵 복사 없는 직접 배치

이 용도는 새 평면을 설계할 때 읽는다. 가구 한 개의 전체 부품 배열은 재사용하지만
완성 방·가게·학교·도시 배열을 찍지 않는다. 요청의 면적/인원/방 관계를 먼저 계획한다.
검증에서는 완성 맵/래스터 킷/조립 장면 문서와 복제 도구를 제거한다.

## 설계 순서

1. 방별 실제 쓰이는 바닥, 출입구, 직원/손님 통로를 정한다. 벽 정면의 높이도 면적에 포함한다.
2. 아래 사전의 materials.mapped가 현재 아틀라스 번호다. originalTiles는 출처 확인용이다.
   floor를 lower에 놓고 목재2×1/다다미2×3 등 바닥 패턴을 반복한다.
3. ceiling.paintTile을 lower에 놓으면 paint_tiles가47변형을 이웃에 맞춰 자동 선택한다.
   이미 선택된 코너 번호를 손으로 추측하지 않는다. 나중에 뚫은 통로 이웃도 재성형된다.
4. 같은 열에서 연속 천장 덩어리의 남쪽 끝 바로 아래에 벽 정면 전체를 둔다.
   wall-wood/clinic은2행, wall-sento/gym은3행이다. 내부 세로벽 끝과 맵 남쪽 끝도 생략하지 않는다.
   세로벽 출입구는 위쪽 천장을 벽 높이만큼 먼저 끝내고, 벽 정면 아래에 통과할 바닥을 둔다.
5. 가구 원점은 좌상단이다. 아래 tiles의 모든 칸을 upper에 무회전/무반전으로 놓는다.
   같은 tile 값을 쓰는 여러 위치는 paint_tiles cells 배열 한 번에 전달할 수 있다.
   paint_tiles의 하위 수정은 같은 칸의 상위 가구를 보존한다. 가구를 지울 때만 upper의 tile:-1을 명시한다.
   벽 근처 정확한 조립에는 cells 또는 line을 사용한다. rect는 벽 옆 틈을 자동 확장할 수 있다.
6. standing 가구는 supportCells가 모두 바닥이어야 한다. 상체가 북벽에 겹치는 것은 허용한다.
   wall-mounted는 전체 바운딩 박스가 벽 정면에 걸려야 한다. 가구 전체를 천장에 놓지 않는다.
7. 수납장/냉장고/주방/세면대는 남쪽 조작면에 도달할 수 있어야 한다.
   의자는 바라보는 방향에 식탁/카운터가 있고 반대쪽에 앉으러 접근할 칸을 확보한다.
   카운터의 손님쪽과 직원쪽 둘 다 접근한다. 서로 다른upper 가구는 겹치지 않는다.
8. 이 프로젝트의 다다미는 천장/벽으로 독립 구획한다. 통로에 노출된 방석만으로 개인실이라 하지 않는다.
   개방 거실에는 목재 바닥을 사용한다. 침실·욕실·화장실은 각각 공용 공간에 직접 출입하도록 한다.
9. 탁구대의 네트는 남북으로 놓여 있으므로 선수는 동서에서 마주본다. 양 끝3칸을 비운다.
10. 출입구에서 각 방과 조작면에 도달하는지 검사한다. 문턱을 막았을 때 개인실 경계가 새지 않아야 한다.
    쓸모없는 빈 바닥은 줄이되 실제 통로/작업/경기 여유는 가구로 채우지 않는다.
11. inspect_interior_layout(mapId, wallMaterial, entry, rooms, requirements)로 실제 구조를 검사한다.
    독립방마다 고유id, 내부 바닥seed, 문턱전체doorways를 선언한다. 문턱을 모두 닫은 바닥 연결성으로
    각 방이 현관/다른 방과 분리되는지, 각1~2칸 문턱이 공용 공간과 직접 닿는지 검사한다.
    가구는 방 경계로 인정하지 않는다. rooms를 생략한 검사는 독립방을 검증하지 않는다.
    requirements.objects에는 사전 ID의 대체 목록ids와 min/max 수량을 넣는다. 방 안에 있어야 하는
    가구에는 roomId를, 동쪽/서쪽 요청에는 side:"east"/"west"를 붙인다. requirements.roomIds에는
    필수 독립방id를 나열한다. maxArea/maxEmptySquare는 요청한 면적/빈 바닥 상한이 있을 때만 넣는다.
    남쪽 출입구 요구는 southExit:true로 검사한다. 예: 욕조1개가 필요한 bath 방이라면
    {"objects":[{"ids":["bath-tub-horizontal"],"min":1,"max":1,"roomId":"bath"}],"roomIds":["bath"]}.
    이는 방의 크기나 타일 좌표를 지정하지 않는다. 최초 요청조건을 수정 도중 지우거나 줄이지 않는다.
    욕조와 변기 앞에도 접근 가능한 바닥을 남긴다. 좌석/조작면과 연결 통로를 확보한 뒤 남는 면적을 줄인다.
    maxEmptySquare는 가구 없는 연속 바닥의 최대 정사각형 한 변이다. 복도 폭이나 미학 점수는 아니다.
    빈칸 검사만 피하려고 용도 없는 가구를 채우지 않는다.
    issues를 paint_tiles로 직접 고치고 다시 검사한다. 이 도구는 자동 배치/복사/수정을 하지 않는다.
12. 결과를 show_map_region으로 보고 잘못된 칸을 직접 고친다. 열린 문턱은 개폐문 이벤트가 아니다.
    완성 그림을 보았다는 것만으로 통행 검사·벽 검사·게임 동작까지 성공했다고 보고하지 않는다.
    오류0은 선언한 요구조건만 통과한 것이다. 선언 누락/복도 폭/미적 품질은 별도로 검토한다. 낭비되는 방 크기는 줄인다.
    특히 4칸 폭의 긴 복도는 maxEmptySquare:4를 통과할 수 있다. 검사 통과를 이유로 유지하지 않는다.
    주택의 순수 이동 통로는 1~2칸을 기본으로 설계하고, 그보다 넓은 부분에는 실제 생활/작업 용도가 있어야 한다.
    개인실 입구는 그림에서도 벽 끝과 문턱이 분명히 보여야 한다. 바닥 연결성만 분리됐다고 승인하지 않는다.
    구조 통과와 시각 합격을 별도로 기록한다. 시각 검토에서 남은 문제가 있으면 완성 예제로 공용에 등록하지 않는다.

## 사전 읽기

동일 용도의 dictionary 문서를 nextOffset이 null일 때까지 읽고 normal/error 객체 그림도 모두 본다.
그림의 왼쪽은 전체 가구, 오른쪽은 밑단 한 칸이 빠진 오류다. 이 그림은 방 배치 정답이 아니다.
사전은 현재 사용자 로컬 공용 타일셋에서 추출한다. 추가 다운로드나 픽셀 재배포는 하지 않는다.
사용자 타일셋 원본과 해시, 원본→현재 번호, 전체 가구 배열/지지칸은 dictionary에 함께 있다.
완성 맵에 없는 새로운 평면의 성공은 실제 조수 출력과 구조/시각 검토로 판단한다.
