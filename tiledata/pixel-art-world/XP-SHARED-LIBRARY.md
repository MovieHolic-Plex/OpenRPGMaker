# 사용자 로컬 XP 공용 자료

원본 픽셀은 다운로드한 사용자 폴더와 로컬 SQLite에만 저장한다. 저장소에는 메타데이터와 생성 코드만 둔다.

## 준비와 설치

1. `xp-library-layout.json`의 8개 그룹/원본 SHA와 사용자 다운로드 목록을 대조한다.
2. 정본 호스트를 `read-pixel-art-world-host.mjs`로 읽어 project id·SHA·저장 폴더 영수증을 만든다.
3. `prepare-pixel-art-world-xp-library.mjs <dev URL> <개인 원본 경로 목록 JSON> <정본 source-proof.json> <개인 출력>`.
   실제 편집기 가져오기 함수가 모든 PNG의 SHA·치수와 아틀라스 경계·레퍼런스 한도를 검사한다.
4. 8그룹 전체 조립 이미지와 원본을 직접 비교한다. 분류/받침/레이어를 수정하면 다시 생성한다.
5. `publish-pixel-art-world-xp-library.mjs <준비 폴더> <개인 공용 출력> --publish-local`.
   라이브러리 파일·현재 카탈로그·배치 사전 SHA를 대조하고, 첨부만 무손실 압축한다.
   공용 SQLite의 `pixel-art-world-xp-local`을 CAS 저장·재로드한다. 기존 공용 자료는 보존한다.
6. `install-pixel-art-world-shared-host.mjs <호스트 URL> <공용 library.json> <개인 영수증 폴더>`.
   정본 백업·에셋 저장·CAS·재로드를 수행한다. 기존 맵과 공간 구조는 그대로 유지한다.

개인 경로 목록은 `pathByPackId`(원본ID→로컬 PNG 경로)와 `backingSeeds`(key/localPath)를 가진다.
다운로드 아카이브의 원본 판본이 달라지면 해시를 우회하지 말고 다른 판본으로 학습한다.

## AI가 읽을 자료

타일 용도는 `list_tileset_references` → `read_tileset_reference`로 읽는다.
오브젝트는 `read_spatial_reference(kind: object, id, tilesetId)`로 읽는다.
공용 ID는 `shared_paw_xp_*`, 오브젝트 ID는 `shared_paw_*_swatch`다.
타일 번호는 그룹별로 다르므로 원본 파일의 번호나 다른 아틀라스의 번호를 그대로 쓰지 않는다.

- 140개 원본: 원본 이미지, 모든 프레임의 47변형, 전체 조립/오류 배열, 원본 쿼터 좌표와 256입력 마스크 사전.
- 139개 오브젝트: 4×3 전체 lower/upper 배열과 실제 조립 그림, 해당 타일의 전체 참고문서.
- 템플릿 GroundBase01: 문서는 제공하지만 완성 오브젝트 스탬프에서 제외.
- 받침 0–8: 잔디·흙·모래·아스팔트·콘크리트·실내 바닥·지붕·물·중앙 벽지. 9–15는 배치 금지 공백.
- 98개 lower 자동 성형. 42개 수동 조립(upper39, lower 교단1·러너2).
- Ditch4종: 47마스크×4프레임. 188개의 animationStrips를 보존한다. 3fps는 편집기 선택이다.

## 시각 검토에서 수정한 사례

- 처음 불투명한 타일을 아무 받침으로 사용하지 않는다. Pool은 콘크리트 바닥, 창문/커튼/덩굴은 벽, 난간은 지붕을 명시한다.
- 벽지 원본16번은 가장자리 세로 테가 포함됐다. 반복 받침은 도서관 원본17번(픽셀32,64,32,32)을 쓴다.
- Carpet08ST/09ST는 원본 그림의 가로 단차와 열린 남·북 끝을 보고 계단형 세로 러너로 분류했다.
  이는 제작자의 명시적 용도 설명이 아닌 시각 판정이다. 닫힌 러그/임의 분기 자동 성형으로 사용하지 않는다.
- Saku 난간은 사각 조립만 검토했다. 복잡한 오목 형상에 그대로 확대 적용하지 않는다.

이 자료는 소재 조립 표본이다. 장소·지역·방의 완성도를 의미하지 않으며, 출입구·층 이동·가구 지지·캐릭터 통행은
각 실제 맵에서 별도로 저작하고 검토해야 한다. 참고자료의 수와 소재 지원 범위를 혼동하지 않는다.
