# 버들항 살림집 문 · 손 도트 열림 시안 v1

2026-10-04. 사용자의 “니가 도트찍어서 … gif” 요청으로 직접 픽셀 좌표를 저작했다.
출처는 프로젝트 소유 버들항 시트의 `bd-house-h101_0` 문, 원본 칸 5743/2333이다.
새 외부 그림·생성 이미지·문자 캐릭터는 사용하지 않았다. 새 문 단계는 프로젝트 기존 자산과 같은 이용 조건을 따른다.

- 생성: `python3 scripts/content/build-beodeul-door.py`
- 참고문서 번들: `node scripts/content/prepare-beodeul-door-references.mjs`
- `manifest.json`: 경첩·폭·후퇴량·GIF 순서·원본 불변 검사 결과
- `house-door.gif`와 `door-detail.gif`는 그림 동작 시안이다. 게임 적용은 아래 공용 도구로 한다.

## 공용 도구로 게임에 적용

집을 찍고 `create_transfer_pair`로 출입 이벤트를 연결한 뒤:

```json
{"tool":"apply_beodeul_door_animation","mapId":"map_blank_start","eventId":"실제 야외 출입 이벤트 id","frameMs":100}
```

도구는 문 앞 이벤트 (gx,gy)의 위 `(gx,gy-2)`부터 1×2칸을 검사한다. 원본 5743/2333 문만 받는다.
시트 16칸을 현재 맵 타일셋에 이식하고, 입장 페이지에 열기 1→7·복원 스위치·기존 transfer를 넣는다.
실내에 조건부 auto 이벤트를 만들어 야외 문을 닫힘으로 복원한다. 일반 맵 이벤트는 transfer에서 종료된다.
유일한 귀환 페이지를 찾으면 도착 전 열림·닫기 스위치, 야외 auto 이벤트의 도착 후 닫기 6→0을 연결한다.
보조 auto 이벤트는 먼저 자기 스위치를 내린다. 재적용은 이벤트·스위치·명령·이식을 중복하지 않는다.
기존 대사와 명령은 순서를 유지한다. 조건 페이지/다중 transfer/다른 문/다른 픽셀 규격은 거부한다.
닫힘은 원본과 같은 그림이고, 기존 건물 통행 ×는 그대로다. 그림이 열린 동안 앞 칸의 출입 이벤트가 작동한다.

## 정확한 사전과 배치

tilesetId `beodeul_door`, texture `tex_beodeul_door`, 판본 v1.
원본 `public/assets/beodeul-door/door-states.png`: 128×32 RGBA, 16px 칸, 한 줄 8칸, 총 16칸.
논리 프레임은 16×32(1×2칸). 0기준 단계 i의 원본 픽셀 상자는 `(i*16,0,16,32)`.
모든 프레임의 아래층 전체 배열은 `[[-1],[-1]]`. 윗층 전체 배열은 아래 표와 같다.

| i | 문짝 폭/끝 후퇴(px) | upper 전체 배열 | kit id |
|---|---|---|---|
| 0 | 8/0, 닫힘 | `[[0],[8]]` | `bd-door-stage-0` |
| 1 | 8/1 | `[[1],[9]]` | `bd-door-stage-1` |
| 2 | 7/2 | `[[2],[10]]` | `bd-door-stage-2` |
| 3 | 6/3 | `[[3],[11]]` | `bd-door-stage-3` |
| 4 | 5/4 | `[[4],[12]]` | `bd-door-stage-4` |
| 5 | 3/5 | `[[5],[13]]` | `bd-door-stage-5` |
| 6 | 2/6 | `[[6],[14]]` | `bd-door-stage-6` |
| 7 | 1/7, 열림 | `[[7],[15]]` | `bd-door-stage-7` |

![8단계 실제 시트 확대](image:bd-door-stages-image)

1. 외관을 먼저 조립한다. 이 문은 고정 1×2칸이며 반복해 넓히거나 다른 문에 자동 적용하지 않는다.
2. 살림집 원점이 (hx,hy)이면 새 문 블록 원점은 `(hx+2,hy+4)`이다.
   예: 야외 집 원점 (8,1) → 그림 상단 (10,5), 그림 하단 (10,6), 문 앞 접근칸 (10,7).
3. 원래 윗층 5743/2333의 두 칸을 함께 교체한다. 교차 타일셋은 엔진의 tile graft로 두 칸을
   대상 타일셋에 이식한 뒤 사용해야 한다. `beodeul_door` 번호를 `beodeul_city` 번호로 쓰지 않는다.
4. 단계 i의 위/아래 칸을 같은 프레임에 함께 교체한다. 열기 0→7, 닫기 7→0.
   GIF 시안은 중간 100ms, 닫힘 800ms, 열림 950ms다.
5. 문틀·인방·문턱의 픽셀 위치는 고정이고 문짝만 안쪽으로 회전한다. 문 안의 검은 공간은 불투명하다.
   투명으로 지우면 밑의 닫힌 문이 다시 비친다. 자동 반복 `animationStrips`는 등록하지 않았다.
6. 그림 상자와 출입 이벤트는 별개다. 문 앞 (10,7) playerTouch 이벤트의 시퀀스에
   열림 단계·대기·transfer는 위 공용 도구로 연결한다. 시트 자체의 반복 애니메이션은 아니다.

## 정상/오류와 확인 범위

![왼쪽 정상 / 오른쪽 위아래 단계 혼합](image:bd-door-errors-image)

왼쪽은 단계4의 전체 배열 `[[4],[12]]`, 오른쪽은 잘못된 `[[4],[8]]`이다.
오류 코드 `door-stage-mismatch`, 문 블록 로컬 (0,1). 검사 조건은 `bottomTile-topTile === 8`.
입력 `(stage:4,origin:(10,5))`의 정답은 윗층 `(10,5)=4,(10,6)=12`, 아래층 두 칸은 -1.
실제 그림은 원본 두 칸을 연결한 것으로 확대는 nearest-neighbor만 사용한다.

빌드는 닫힘 프레임의 원본 바이트 일치, 8단계 구별, 문틀/문턱 불변을 검사한다.
전 단계는 통행 ×, 홈 윗층, 렌더 priority lower(정면 벽과 동일)이다.
열렸다는 그림만으로 건물 안쪽 칸의 통행을 풀지 않는다. 실제 진입은 기존 transfer가 담당한다.
기존 메타데이터 수정은 없으며 새 16칸에만 이 판정을 적용했다.
건물 전체·가구·양문·다른 크기 문은 이 시트에 없다. 건물은 `beodeul_city`, 실내는 `atlas_biome_interior`를 쓴다.
구조 검사와 GIF 관찰은 실제 게임 애니메이션 실행 검증을 대신하지 않는다.
