# 공용 타일 정밀 조립·검증

대상 forest_harmony / tex_forest_harmony / 16px / 30열. 타일 인덱스는 0부터, 맵 원점은 좌상단이며 x는 오른쪽, y는 아래쪽으로 증가한다. 다른 칩셋의 같은 번호는 다른 그림이다.

## 저가 AI 실행 절차
1. list_tileset_references → 이 용도(public-assembly-v2)의 문서 전체와 이미지를 read_tileset_reference로 읽는다.
2. inspect_tile_recipe로 실제 맵 타일셋, 전체 크기, 두 레이어 배열, 문/접근칸을 확인한다.
3. stamp_tile_recipe에 아래 JSON을 전달한다. overwrite는 기본 false. 이벤트가 있으면 항상 거절한다.
4. validate_tile_recipes에 배치한 원점 목록과 실제 맵 입출구 entryPoints를 전달한다. valid:true, issueCount:0이어야 한다.
5. 전체/확대 화면을 직접 보고 부품을 검수한다. 구조 통과를 미적 품질 승인으로 말하지 않는다. SQLite 저장 후 다시 읽는다.

```json
{"mapId":"실제맵ID","placement":{"recipeId":"house-wood","x":5,"y":8},"referencePurpose":"public-assembly-v2"}
```

inspect에는 referencePurpose를 주지 않는다. validate 입력 예시:

```json
{"mapId":"실제맵ID","placements":[{"recipeId":"house-wood","x":5,"y":8}],"entryPoints":[{"x":9,"y":20}]}
```

mapId와 외부 출입구는 실제 맵에서 조회한 값으로 교체한다. 빈터를 임의로 입구라고 부르지 않는다. entryPoints 생략 시 내장 문앞/게이트 접근칸만 검사하며 맵 전체 출입구 확인이 아니다.

## 결합과 반복
숲: 왼쪽 마감 → 미리 충돌을 해결한 반복 부분 → 오른쪽 마감. forest-strip은 14×6이고 최종 배열에서 x=0..3, 4..9, 10..13을 차례로 쓴다. 이 세 조각은 서로 겹치지 않는다. 원본 6×6 본체를 그대로 반복하는 legacy stamp_forest_recipe는 N=1..16, 폭=6N+2이며 본체를 먼저 깔고 마감을 겹쳐 쓰는 별도 조립법이다. 두 절차를 섞지 않는다. 좁은 폭으로 줄이려고 뿌리를 자르지 않는다.
건물: 하위 지붕/벽 → 상위 지붕 캡/창문 → 하위 문 상단·하단 → 문 아래 접근칸 2개 확보. 전체 9×9 영역 필요.
가구: 하위 바닥 유지 → 상위 좌234 → 중235 → 우236. 단독 중간 조각은 탁자가 아니다. 확장 시 235만 수평 반복한다.
울타리: NW378/NE380/SW438/SE410 → 가로379 반복 → 세로408 반복 → 남쪽 (3,4) 비우기. 문폭1칸, 바로 안/밖 칸도 비운다.
동굴: 잔디 절벽 상단618/619/620 → 암벽651/652/653 반복 → 893 입구 → 남쪽 접근칸. 893은 원본 월드맵413의 투명 이식을 사용하고 하위 받침652를 합성한다. 전이 이벤트와 목적지 맵은 별도로 작성한다.

## 레이어·통행·그림을 구별한다
배열의 lowerTiles/upperTiles가 실행값이고 roles는 검증용이다. -1은 명시적 비우기다. 투명하다고 항상 상위가 아니다. 동굴은 하위+받침, 울타리/가구는 상위+바닥 보존이다. 문 그래픽329/359, 동굴893은 현재 solid다. 그래픽 칸을 출입 경로로 간주하지 않으며 남쪽 접근칸에서 버튼 전이를 저작한다. 전이 실행은 이 타일 검사에 포함되지 않는다.

## 적용 조건
원본 이미지·열 수·칸 수·이식 정의·해당 부품/레이어가 다르면 거절한다. 전 영역과 접근칸이 맵 안에 들어가야 한다. overwrite:true는 전체 사각형을 덮으므로 기존 건물·길이 있는 곳에 자동 지정하지 않는다. 임의 폭/임의 모양을 지원한다고 추정하지 않는다. 승인된 배열을 쓰거나 영역을 바꾼다. 이 문서가 저가 모델 자체의 성공률을 측정한 결과는 아니다.
