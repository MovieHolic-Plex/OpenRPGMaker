# 공용 타일·AI 참고문헌 등록 기준

사용자 확정 기준(2026-09-22). 특정 프로젝트의 메모가 아니라 모든 프로젝트에서 읽을 공용 자료다.
타일셋별로 `tiledata/tilesets/<tilesetId>/`에 정본을 두고 공용 번들 정의의 referenceDocuments에 포함한다.
기존 프로젝트와 공용 맵에도 보충하고 SQLite 재로드와 실제 자료집 화면으로 입증한다.

다음 항목이 모두 있어야 배치용 문서로 완료 처리한다.

1. 정확한 사전: tilesetId, image/판본 식별, 0기준 원본 칸/픽셀 좌표, 16px 등 실제 칸 크기,
   폭·높이, 하위/상위 전체 배열, 투명/받침/이식 정의. 다른 칩셋의 타일 번호를 섞지 않는다.
2. 실행 순서: 부품별 원점과 반복식, 겹침 우선순위, 좌·우 마감, 안/밖 모서리 방향,
   최소 크기와 금지 조건. “자연스럽게”, “적절히”만으로 끝내지 않는다.
3. 건물·가구·숲·울타리·동굴을 다루면 각각 완전한 조립 예제를 제공한다.
   없는 소재는 없다고 적고 공용의 다른 원본/이식 절차를 특정한다. 임의 번호를 만들지 않는다.
4. 입력→전체 하위/상위 정답 배열→원본 해상도 완성 그림을 연결한다.
   픽셀 확대는 nearest-neighbor만 쓰고 AI가 그린 모형을 실제 타일 출력이라고 하지 않는다.
5. 반복 가능한 조각과 고정 조각을 분리한다. 문 그림, 문앞 접근칸, 출입구, 상호작용/전이 이벤트를 구분한다.
6. 정상/오류 나란한 그림을 제공한다. 잘린 뿌리·빠진 줄기·반대 외곽·잘못된 레이어·막힌 출입구를
   실제로 변조해 검출하고 오류 코드와 맵 좌표를 기록한다.
7. 자동 검사는 구조와 통행의 확인 범위를 명시한다. 이벤트 실행/미적 품질/저가 모델 성공률을
   구조 검사 통과로 대신 주장하지 않는다. 저장 전 실패하면 부분 배치가 남지 않아야 한다.
8. 기존 문서와 tileMeta/group의 잘못된 레이어 설명을 실제 엔진 판정과 대조해 고치고 before/after를 남긴다.
   투명 여부·홈 레이어·통행·렌더 우선순위는 별개의 정보다.

현재 구현 예: forest_harmony/recipes/catalog.json, public-assembly-v2 용도,
inspect_tile_recipe / stamp_tile_recipe / validate_tile_recipes.
