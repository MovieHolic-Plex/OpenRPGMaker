# 적대적 검수 — desert-castle (사막 성·오아시스)

**총평: 조건부** (보고된 두 보정 — 오아시스 **풀** 덩이 둘레 둥글게, 야자 배경 투명 — 은 부품 단위로 실제로 됐다. 그러나 조수가 맨 먼저 받는 「완성 배치도」의 오아시스 **못**은 여전히 직각 상자이고 야자가 하나도 없으며, 덩이 붓은 16px 마다 같은 톱니가 되풀이된다.)

검증 방법: 보고·`compare-ref.png` 를 믿지 않고 ① 최신 `parts/` 를 6배로 열고 알파값을 셌다 ② 지금 팩(`build/place-packs/desert-castle`, 21:15/21:45 빌드)의 `sheet.png`+`tileset.json` 으로 야자 키트를 모래·풀 바탕에 다시 그렸다 ③ 팩의 완성 배치도 렌더(`layouts-out/main.png`)와 조수 결과 `/tmp/asst-bd/dc4-keep.png`(18:45 시험, 같은 배치도 키트를 찍음 — `dc4.log` 16행 `get_spatial_design bd-layout-desert-castle-main`) 오아시스를 같은 칸 범위(x0~23, y26~45)로 잘라 4배로 대조했다.

반려·조건 사유 상위 5
1. **팩 완성 배치도의 오아시스 못이 직각 상자 — FAIL.** 배치도 단계 `blob oasis_pond cx12 cy36 rx4.5 ry3.5` 가 작은 타원을 칸으로 깎아 못이 서·북 두 변이 곧은 직사각형 + 오목 모서리 칸 계단 셋이 된다(배치도 4배 크롭의 (275,320)-(320,560) 서쪽 변, (285,310)-(600,350) 북쪽 변, 계단 (580,290)·(390,530)·(460,600)). 데모 render-1x 의 손 마스크 못(북쪽 혹·남쪽 만)과 전혀 다르다 — 조수는 데모가 아니라 이 배치도를 받는다. dc4 조수 결과의 못도 같은 상자다. 증거 `desert-castle-layout-pond-box.png`, `desert-castle-dc4-oasis.png`.
2. **배치도 오아시스에 야자·갈대·낙타 말뚝이 없다 — FAIL(스토어 팩).** `layouts/main.json` 단계 18개에 palm·reeds 스탬프 0. 앵커 ⑤「못·야자·낙타 말뚝·물통」 중 못만 남는다. dc4 조수는 팩 안에서 야자를 못 찾고 다른 칩셋의 잎 없는 고목(`obj:tree/desert/big-1`·`mid-2`·`small-1`)을 오아시스에 꽂았다(그 시점 팩에는 야자 id 0 — `grep -c bd-pick-desert-*-palm dc4.json` = 0). 지금 팩에는 야자 4종이 있으나 id 가 `bd-pick-desert-pyramid-palm-*`(빌린 이웃 장소 이름)라, dc4 조수가 쓴 검색어 `bd-pick-desert-castle` 접두로는 걸리지 않는다(검색 동작 자체는 재실행 안 함 — 이름 기준 추정).
3. **오아시스 풀 붓 5×5 덩이가 16px 주기 톱니 왕관 — WEAK→FAIL.** `check-autotile.png` oasis-grass 5×5 (260,1012)-(636,1341): 네 변이 곧고 칸마다 같은 삼각 톱니 셋이 나란히 — 「둥근 덩이」가 아니라 톱니 바퀴 테. 배치도에서도 긴 직선 사선 + 같은 간격 톱니(4배 크롭 (60,60)-(700,250)). 데모 맵은 칸 마스크가 불규칙해서 가려졌을 뿐이다. 증거 `desert-castle-grass-dune.png`.
4. **모래 언덕 능선(autotile-dune-crest)이 구슬 박힌 줄·계단 턱 — FAIL(보고 인정).** 나선·5×5 시험에서 능선이 16px 마다 같은 마디(구슬)가 박힌 끊긴 줄, 덩이 속은 투명이라 「높낮이」가 안 읽힌다. 증거 같은 그림 오른쪽.
5. **물 속 잔물결이 16px 벽지 — WEAK.** oasis-pond 15번 칸 잔물결이 줄마다 같은 자리에 되풀이(render-1x 오아시스 3배 (300,250)-(750,560), 배치도 동일). 칸 경계 계단도 데모 못 북쪽 (625,290)(3배 좌표)에 한 칸 남음.

## 만든 쪽 보고와 다른 점
- 보고는 「오아시스 풀 덩이 둘레 네모 칸 → 둥글게」 만 다뤘다. 실제 조수 결과(dc4)에서 네모였던 것은 **배치도에서 온 풀과 못 모두**였고, 지금 배치도에서 풀은 고쳐졌지만 **못은 그대로 상자**다.
- 「야자를 팩에 추가」 — 부품·팩 시트에는 들어갔다. 그러나 조수가 그대로 찍는 완성 배치도에는 0그루이고, 팩 안 id 가 `desert-pyramid` 이름이라 `bd-pick-desert-castle` 접두 검색으로는 안 잡힐 것이다(추정).
- `compare-ref.png` 는 데모 맵(손 마스크)만 비교한다. 조수 경로(배치도 키트 → 맵)의 결과는 비교 시트에 없다.
- `check-autotile.png` 5×5 네모 붓을 추가했다고 했지만, 그 그림이 바로 톱니 왕관 사각형을 보여 준다(통과 근거가 아니라 반려 근거).
