CHAPTER 02

계산식 수술 — 공식은 그대로, 체감은 뒤집는다

기존 뺄셈 공식을 깨지 않고, 기본값과 옵션으로 “재미”를 되돌렸다. 호환성은 유지, 체감은 개선.

Before variance 0 / crit 0 — 주사위 없는 전투

모든 타격 고정값. 크리는 평생 안 터지고, 터지면 ×3이라 테스트 사각지대.

criticalRate: 0, variance: 0 → r1.amount === r2.amount (rng 달라도 같음)
플레이어는 “같은 버튼 30번”을 친다. 오버킬 표기로 타격감만 가리고 긴장은 없다.

After DEFAULT 10% / 4%×1.5 — “살짝 흔들리는” 전투

DEFAULT_SKILL_VARIANCE = 10 DEFAULT_SKILL_CRIT_RATE = 4 DEFAULT_SKILL_CRIT_MULT = 1.5 // 명시하면 그 값 우선 → 기존 데이터 호환 variance:0, crit:0 을 쓰면 여전히 결정론

실행: rng 0.0 → 34, rng 1.0 → 26 — 다른 값. explicit variance:0 → r1===r2 유지.

battleDamage.ts 테스트 SC2 교정

Before 방어 뺄셈 — 둘 다 키우면 제자리

magnitude -= floor(effectiveDefense/2) def 40→80(+40): 피해 -20 atk 40→80(+40): 피해 +20 둘 다 +40 → 피해 변화 0

레벨 곡선이 공격·방어를 같이 올려 후반 체감 평탄화.

After 감쇠식 A/B — def/(def+80)

if (useDiminishingDefense) reduction = def/(def+80) // 40→33% 80→50% 160→67% magnitude *= (1 - reduction) else magnitude -= floor(def/2) // 호환 유지 export function computeDiminishingDefenseReduction(def)

옵트인: useDiminishingDefense:true 또는 gen1 모델에서. 실측 power30 vs def80 → legacy 20 vs dimin 30.

After 예측=실제 패리티 — 장비가 예측에 스며든다

// types.ts effectiveStats?: { attack, defense, mind, agility } // battlers.ts — snapshot에 주입 effectiveStats: { attackPower, defense, mind, agility } // predict.ts — 우선 사용 if (battler.effectiveStats) return { ...battler.effectiveStats }; battlerStatsFromMutable(project, battler) // 정확 비교용

이전: parameterValueAtLevel(curve, level)만 — 장비 +3이 예측에 0.

이제: snapshot이 런타임 스탯을 그대로 들고와 예측과 실제가 같은 수치를 본다. UI 신뢰도 회복.

CHAPTER 03

런타임·상태 수술 — 멈추지 않고, 터지지 않는다

상태 하나가 게임을 멈추고, 배율 하나가 보스를 녹이던 두 균열을 봉합했다.

Before 배율 무제한 곱샘

attackMultiplierForStates = ∏ attackMultiplier ×2 두 개 → ×4 → 보스 원샷 defenseMultiplierForStates = ∏ ×0.5 두 개 → ×0.25 → 종이 보스

상한·하한 없음. 장비+상태 중첩 시 기하급수.

After clamp 0.4 ~ 2.5

raw = ∏ multiplier return clamp(raw, 0.4, 2.5) // battleStates.ts ×4 → 2.5 ×0.25 → 0.4

보스 원샷·무적 방지. 로그 경고 없이 깔끔히 클램프 — 밸런스 테스트에서 तुरंत 체감.

실측: 공격업×2 두 개 → 2.5, 방어다운×0.5 두 개 → 0.4

Before 독·수면 = 영원 전투 → 조용히 escape

독: floor(maxHp*%/100), cap hp-1 → 절대 안 죽음 수면: canBattlerAct=false → 아무도 행동 불가 → 200R 강제 escape, 원인 불명

After 타임라인에 기록되는 stalemate

// runtime.ts recordTimeline({ kind:"stalemate", reason:"strictCap" }) result="escape" // 동일하되 원인 기록 // types.ts kind: "stalemate" reason: "natural" | ... | "strictCap"

플레이어에겐 같은 탈출이지만, 로그·QA·리플레이에서 원인이 보인다. 다음 단계: 독 1HP 캡을 “전투불능 허용” 옵션으로 확장 가능.

After wait 시각화 — 연출과 ATB 분리

// 이전 if (pendingWaitMs>0){ deltaMs -= consumed; // ATB 멈춤 if(deltaMs<=0) return; } // 패치 let visualWaitMs = pendingWaitMs; pendingWaitMs = 0; void visualWaitMs; // ATB는 그대로 충전 // 연출은 DOM이 처리, 로직은 멈추지 않음

이전: 배틀 이벤트 wait 1초면 1초간 ATB 정지 → “왜 멈췄지?”

패치: wait는 visual로만 취급, tick은 계속 charge. 둔화/가속 버프 설계 공간 확보.

테스트 교정: gauge === gaugeAfterDefend → gauge > gaugeAfterDefend — 의도대로 흐른다.

hpTurn 문자열 파싱 — 데이터 드리븐으로 한 걸음

기존: hpDamagePercentFrom(hpTurn) 정규식 파싱 유지(호환) 추가: runtimeEffects.hpDamagePercentPerTurn 우선 사용 신규: hpDamagePercentForStateExplicit() 노출 향후: 신규 상태는 runtimeEffects 필수화 후 마이그레이션

한글 DB나 표현이 바뀌어도 지속피해가 0이 되지 않도록, 코드가 아닌 데이터가 진실이 되게 했다.

CHAPTER 04

보상·성장 수술 — 돌아오는 재미를 처벌하지 않는다

레벨업 곡선은 그대로 두되, 주변 보상·패널티가 체류 동기를 갉던 부분을 고쳤다.

Before 갭 패널티 90% 증발

gap >=10 → floor(exp*0.1) // 90% 컷 gap >=5 → floor(exp*0.5) // 50% 컷

뒤로 가서 돕기·도감·파밍이 전부 손해. 오픈월드·우정 시스템과 충돌.

500 exp가 10레벨 차이 나면 50만 남는다.

After 70% / 50% — 돌아와도 남는다

gap >=10 → floor(exp*0.5) // 50% 컷 gap >=5 → floor(exp*0.7) // 30% 컷 // rewardPolicy.ts

실측: 500×0.5=250, gap5→350. 귀환·탐험 동기가 살아난다. 정책 플래그 뒤라 끌 수도 있다.

500 exp가 10레벨 차이 나도 250 — 절반은 남는다.

After 드랍 pity — 운이 나빠도 언젠간 준다

// battleRewards.ts effectiveRate = min(100, base + pityBonus) miss → pityBonus = min(30, pityBonus+8) hit → pityBonus = 0 // 5% 드랍 20회 0개 확률 36% → pity로 완화

천장 없이 독립시행이던 드랍에 보정 누적. 5회 연속 꽝이면 +15%p 근처까지 올라간다.

시나리오결과
base 5% + rng 7% (원래 꽝)pity 2회 후 적중
500회 × rng 7% 고정500회 전부 적중
연속 미드랍 최대 보정+30%p

stateless라 전투 단위에서만 누적 — 세션 간 pity는 다음 단계에서 영속화 가능.

ATB 민첩 — FLOOR는 유지하되, 설계 공간을 열었다

CHARGE_PER_AGILITY = 0.1/43, FLOOR = 0.02 유지 // battleTurnGauge.ts — 신규 API effectiveChargeRate(battler) // 상태 보정 포함 노출 msToReady(battler) // UI에 “다음 행동까지 Nms” // 둔화/가속 버프는 상태 배율을 hasteMultiplier로 해석해 확장 가능

완전 리스케일은 3일짜리 작업이라, 이번엔 API와 주석으로 길을 냈다. 다음 패치에서 상태가 민첩에 직접 영향을 주도록 확장하면 된다.
