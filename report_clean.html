01먼저 분모를 고쳐야 한다 — 480칸은 타일이 아니다

모든 칩셋은 코드에서 강제로 480 슬롯으로 등록된다(count = DEFAULT_TILE_COUNT, constants.ts:26). 슬롯 수는 그 칩셋의 그림에서 유도되지 않는다. 그래서 PNG 알파 채널을 16px 격자로 훑어 불투명 픽셀이 0개인 슬롯을 셌다.

MEASURED 6,240 슬롯 중 672칸(10.8%)이 100% 투명이다. 서술할 대상이 아예 없는 빈 공기다. 정직한 분모는 5568이다. 이 측정은 두 관측군(레드팀 PIL 스윕 + 리드 독립 PIL 재실행)에서 수치가 완전히 일치했다.

13개 칩셋은 13개 독립 문제가 아니다

MEASURED world 와 retro_world 는 알파 마스크가 100.0% 동일하고 480개 타일의 실루엣이 전부 동일하다 — 색만 바꾼 순수 리컬러다. combined_town↔retro_exterior 는 473/480, dungeon↔retro_dungeon 321/480, interior↔retro_house 339/480 이 동일 실루엣이다. 즉 한쪽을 서술하면 다른 쪽으로 전이 가능한 커버리지가 상당히 존재한다 — "0인 칩셋 7개"의 상당 부분은 새로 저작할 필요가 없는 물량이다.

05진짜 문제는 "몇 개 있냐"가 아니라 "있는 게 도달하냐"

던전의 480칸 큐레이션 테이블은 AI 에게 보이지 않는다

tileSemanticsDungeon.ts 에는 8배 확대 비전 감사로 판독한 480칸 전수 라벨이 있다(엔트리당 태그 평균 4.87개). 그런데 themePacks.ts:8 은 실내 테이블만 임포트하고, 조회는 isInteriorPackTileset(tileset) 으로 게이트된다(themePacks.ts:416).

결과: AI 의 유일한 타일 의미 조회 도구 get_tile_info 는 tileMeta 만 읽는다(tilesetSemanticChecker.ts:110-111). 그래서 AI 는 "회록 석재 바닥 126" 이라는 자동생성 문자열을 보고, 사람이 판독한 "회록색 석재 바닥" 은 knownTileLabel 뒤에 앉아 있다 — 그 함수의 소비자는 데모 캔버스 파일 하나뿐이다. git 이력에 배선 시도가 되돌려진 흔적은 없다. 그냥 한 번도 안 했다.

이걸 배선하면 던전 478개 자동생성 라벨이 큐레이션 라벨로 바뀐다. 타입이 동일하고(DungeonTileSemanticEntry = CombinedTownTileSemanticEntry) 구조적 장애물이 없다. 실제 작업은 불리언 게이트를 텍스처키→테이블 맵으로 바꾸는 것 + 실내 전용으로 하드코딩된 미그룹 시더를 파라미터화하는 것이다. 단 설명 커버리지는 개선되지 않는다 — 큐레이션 테이블에는 문장 필드가 없다.

자동생성 라벨이 결손을 숨긴다 — 자기 인증 신뢰도

MEASURED 자동생성된 그룹이름 + 번호 라벨 1,319개 전부에 confidence: "high" 가 찍힌다(themePacks.ts:427). 그리고 list_unclassified_tiles 는 라벨이 비어 있지 않은 타일을 건너뛴다. 즉 자동생성 라벨은 (1) 스스로 높은 신뢰도라고 선언하고 (2) 미분류 목록에서 그 타일을 지워 버린다. 결손이 큐레이션 대기열에 절대 올라오지 않는다.

대조적으로 마을 칩셋의 describeChipsetTile 은 77칸에 대해 usage:"unknown" + "needs manual classification before AI placement" 라고 스스로 결손을 신고한다. 정직한 설계는 이미 레포 안에 있고, 다른 계층이 그걸 안 따른다.

배치 규칙 91.9%는 설명의 복사본이다

MEASURED 135개 그룹 중 124개(91.9%)의 placementRules 가 description 과 축자 동일 문자열이다. 원인은 저작 누락이 아니라 packGroup() 팩토리에 placementRules 인자가 없고 themePacks.ts:572 가 placementRules: description 으로 복사하기 때문이다. 독립적인 배치 정보를 가진 그룹은 11개, 전부 마을 칩셋이다. "모든 그룹이 배치 규칙을 갖는다"는 타입이 필수 필드로 강제한 결과일 뿐이다.

같은 팩토리에 patternGrammar 인자도 없다. 그래서 던전·실내·스칼록시 그룹은 구조적으로 기계 판독 가능한 배치 문법을 가질 수 없고, 계단·절벽 같은 확장 문법이 산문 안에 묻힌다. 그런데 AI 컨텍스트는 그 산문을 100자에서 자른다 — 던전 최장 설명 284자는 정확히 타일 번호표가 잘려 나간다. 아이러니하게 AI 제안 경로의 프롬프트에는 "Do not hide this inside prose" 라는 규범이 코드에 박혀 있다.

설명 0인 칩셋을 고르면 AI 시공이 전부 죽는다 — 경고는 없다

13개 칩셋 전부가 에디터 선택기에 커버리지 경고 없이 동등하게 제공된다. 설명 0인 칩셋에서 material="물" 같은 이름 기반 시공을 시도하면 resolveMaterialByLabel 이 status:"missing" 을 돌려주고 ToolError material-not-found 로 build_wall·build_roof·place_door·paint_road·place_props·fill_region 등 전부 실패한다. 참고할 사전(ask:"labels")조차 빈 배열이고, 시스템 프롬프트의 타일 어휘 섹션도 통째로 비어 나간다. 유일한 생존 경로는 정수 인덱스 paint_tiles 인데 프롬프트가 타일 번호 추측을 금지한다.

06이 데이터는 누가 언제 만들었나

MEASURED 타일 의미 관련 커밋의 월별 분포: 2026-06 = 4건, 2026-07 = 38건, 2026-08 = 6건. 실내 480칸 전수 판독은 2026-07-12, 던전은 2026-07-13 의 비전 확대 감사에서 나왔고, 스칼록시 3종은 같은 2026-07-12 에 단일 벌크 커밋으로 임포트됐다. 즉 이 자산의 거의 전부가 2026년 7월 중순 닷새 안에 만들어졌고 이후 정지 상태다.

그리고 MEASURED 라이브 Supabase 68개 프로젝트 행 전체에서 사람이 저작한 타일 메타는 1건, AI 가 저작한 것은 0건이다. 그 1건조차 라벨·설명 텍스트는 시드와 바이트 단위로 동일하고 통행성만 바꾼 것이다. 제품 수명 전체에서 아무도 타일 의미를 손으로 쓴 적이 없다. 커버리지는 100% 코드 시드다.

참고 — openwiki 표는 낡지 않았다

조사 시작 시 openwiki/interior-tile-benchmark.md 의 2026-08-20 커버리지 표가 낡았을 것이라 가정했다. 틀렸다. 라벨·그룹·오토타일(실내 10 / 던전 13 / 나머지 0)·통행성 전 축에서 재현된다. 낡은 쪽은 이 조사의 초기 측정이었다 — autotiles 라는 존재하지 않는 필드를 읽어 전 칩셋 0을 보고했고, 실제 필드는 autotileGroups(types/base.ts:297)였다.

07지금 손댈 순서

  1. 던전 큐레이션 테이블 배선 — 자동생성 라벨 478개 → 사람이 판독한 라벨. 타입 동일, 되돌려진 시도 없음, 구조적 장애 없음. 이 조사에서 나온 가장 값싼 개선이다.
  2. 자동생성 라벨의 confidence:"high" 제거 — 결손이 list_unclassified_tiles 에 다시 나타나게 만드는 한 줄. 이걸 고치지 않으면 나머지 개선의 우선순위를 시스템이 스스로 숨긴다.
  3. 마을 칩셋 77칸 미분류 처리 — 이미 usage:"unknown" 으로 정확히 열거되어 있는 확정 작업 목록이다. 추가로 블록 공유 318칸을 블록 크기 순(34, 24, 24, 20…)으로 내리면 문장당 효과가 가장 크다.
  4. 리컬러 전이 — world→retro_world 는 실루엣 480/480 동일이므로 한쪽 저작이 다른 쪽에 그대로 적용된다. "0인 칩셋 7개"를 처음부터 만들 필요가 없다.
  5. packGroup 에 placementRules·patternGrammar 인자 추가 + 사용자 저작 템플릿에 확장 문법 3종 추가. 배치 규칙 91.9% 복제, 산문 100자 절단, 실내 20칸 결손이 모두 이 한 결손으로 수렴한다.
  6. 커버리지 0 칩셋 선택 시 경고 — 지금은 AI 시공이 통째로 죽는 칩셋이 아무 표시 없이 동등하게 제공된다.

버그 3건 (조사 부산물)

1. 타일 177 · 207 · 208 · 209 는 confirmed: true 인데 동시에 usage:"unknown" 이다. barrelObjects/bannerObjects 가 그룹·확정 목록·통행성에는 등록됐지만 서술 분기가 없다.
2. 마을 큐레이션 테이블에 중복 인덱스 246 · 288 · 306. 특히 288 은 "꽃"(통행 가능) 과 "꽃 덤불"(통행 불가) 로 스스로 모순하며, 해소 순서가 소비자마다 다르다(나중 승리 / 먼저 승리 / 둘 다 생존). 벤치마크 정답 목록에는 288 이 두 번 들어간다.
3. 지식 인스펙터에서 번들 그룹의 설명만 고쳐도 저장 시 role·레이어·배치 문법·통행성이 재유도된다. 135개 그룹 왕복 실측: 53개는 비사각이라 저장 자체가 실패하고, 저장되는 82개 중 role 50개·레이어 72개가 바뀌며 배치 문법 16개가 소실된다. 벽을 상위 레이어 소품으로 바꿔 놓는다.

08수치 계보와 검증

MEASURED = 출처가 말하는 값(파일:행 또는 실행 산출물) · ASSUMED = 내가 고른 기준 · DERIVED = 위 둘로 계산.

ASSUMED 이 리포트가 "서술됨"으로 세는 기준은 사람이 쓴 문장에 도달하는 칸이다. 그룹이름 + 번호 자동생성 라벨은 정보량이 "이 타일이 어느 그룹인가" 1비트뿐이라 제외했다. 분모는 도화 가능 슬롯 5568을 쓴다(전체 6,240에서 100% 투명 672칸 제외). 다른 기준을 쓰면 숫자가 달라지므로 계층별 원시값을 03절 표에 병기했다.
