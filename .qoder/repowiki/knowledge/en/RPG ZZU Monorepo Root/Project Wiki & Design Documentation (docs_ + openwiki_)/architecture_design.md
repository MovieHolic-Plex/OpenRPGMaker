Two complementary documentation trees coexist:
- `openwiki/` is the AI pre-edit context layer. `PROJECT_WIKI.md` defines a strict read order (entry → quickstart → focused page → source files) and enumerates ownership boundaries (`src/app`, `src/editor`, `src/player`, `src/battle`, `src/project`, `src/assets`, `src/styles`, `test`). Focused pages cover subsystems: `architecture.md`, `editor-workflows.md`, `runtime-and-data.md`, `autotiles.md`, `castle-map.md`, `large-village-generation.md`, `testing.md`, `cpen-openwiki.md`. This directory is consumed by coding agents before any edit.
- `docs/` holds human-facing artifacts: Markdown specs under `specs/`, `knowledge/`, `ontology/`, `skills/`, `superpowers/{plans,research,specs}/`; HTML guides generated from those docs (e.g. `openwiki-guide.html`, `castle-*.html`, `harness-*.html`); image-heavy case catalogs under `interior-wall-frame-cases/`; and standalone reviews/critiques at the root.
There is no build tooling inside this scope — the two trees are plain text assets consumed by humans and LLM agents, with `openwiki/` acting as the agent entry point and `docs/` as the human reference library.
