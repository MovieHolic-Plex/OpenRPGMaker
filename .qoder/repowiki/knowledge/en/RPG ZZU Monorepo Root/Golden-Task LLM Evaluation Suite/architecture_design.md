Two-layer design inside `evals/`:
- Runner layer: `run.mjs` is a thin Node bootstrap that loads `.env.local` (minimal dotenv parser, no dependency), then delegates to `vitest run --config evals/vitest.config.mjs`, passing `EVAL_TASKS` to control how many tasks to execute.
- Test layer: one or more `*.eval.ts` files consumed only by the custom vitest config (`include: ["evals/**/*.eval.ts"]`, `environment: "node"`, 10-min default timeout). Each file imports production code via the `@` alias pointing at `../src` — e.g. `AssistantSession`, `chatCompletion`, `scoreProject`, `GOLDEN_TASKS` from `@/ai/*` and `@/evals/*`.
- `llmSuite.eval.ts` is the canonical end-to-end evaluator: it instantiates `AssistantSession` with a per-task `AiConfig` (model defaults to `minimax/minimax-m3`, overridable via `VITE_LLM_MODEL`), wraps calls in a per-task timeout, runs `scoreProject(project, task)`, extracts tool-call counts from `session.exportAudit()`, and writes a summary JSON under `evals/results/<timestamp>.json` (no raw prompts/responses).
- Other `*Smoke.eval.ts` files are feature-specific live smoke tests (agentic, dbTools, demoTeach, interview, npc, template) that follow the same pattern of constructing an `AssistantSession`, sending a prompt, and asserting on the proposed project / tool call log.
- Dependency direction is strictly inward: `evals/` depends on `src/ai`, `src/evals`, `src/project`; nothing in `src/` imports back into `evals/`. The suite is gated by `describe.skipIf(!API_KEY)` so it is skipped when `VITE_LLM_API_KEY` is absent.
