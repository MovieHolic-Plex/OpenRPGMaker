- Two parallel Vite entry points share the same `src/` tree: `vite.config.ts` builds the in-browser editor (dev on port 9999, preview on 9888) while `vite.player.config.ts` re-bundles it as a self-contained runtime via `player.html`, swapping editor-only modules with shims under `src/player/export*Shim.ts`.
- A single `tsconfig.json` plus `tsconfig.app.json` enforce strict ES2022 + bundler module resolution across both targets; the `@/*` path alias is mirrored in every config so editor, player, tests, and Node scripts all resolve identically.
- The dev server injects an `/__rpgzzu/ai-activity` middleware that mirrors AssistantSession JSONL to `output/ai-activity/`, giving the MCP/AI scripts (`scripts/rpgzzu-assistant-mcp.mjs`, `scripts/chatgpt-oauth-companion.mjs`) a shared disk bus for live inspection.
- `vitest.config.ts` runs unit/golden tests against `test/**/*.test.ts` in a node environment, while `vitest.live.config.ts` and Playwright's `playwright.config.ts` are opt-in variants for Supabase-backed or browser e2e flows — all three test configs reuse the same `@/*` alias.
- `pnpm-workspace.yaml` declares this repo as a pnpm workspace (with esbuild allowBuilds), and `package.json` centralizes every cross-cutting script (`dev`, `build`, `build:player`, `test`, `test:e2e`, `construction:harness`, `ontology:*`, `openwiki:*`) so each child module (assets_and_pwa, scripts_tooling, evals, rpg_maker_skills, docs_wiki, test_artifacts) is invoked through these root commands rather than independently.
