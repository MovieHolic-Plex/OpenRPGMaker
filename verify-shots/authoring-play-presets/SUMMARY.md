# 공용 플레이 프리셋 96종 연결 확인

2026-10-05. 기존 24종에서 72종을 추가해 12개 분야·각 8종·총 96종으로 확장했다.
Firefox 격리 브라우저에서 실제 등록 도구와 편집기 표면을 확인했다.

- 12종씩 8페이지를 조회해 고유 ID 96개를 얻었다. 마지막 nextOffset은 null이다.
- 96종 전체의 상세 조회: 각 3단계 이상 / 확인 항목 3개 이상 / not-run 표시.
- 모든 조회·작성·검사 도구 참조가 활성 레지스트리에 있고 작성 도구는 모두 write 모드다.
- 초기 좁힌 도구 목록에 목록/상세 조회 도구가 있다. 현재 Pi 지침과 첫 플레이 읽기 허용 목록에서도 확인했다.
- 목록으로 고르고 상세만 읽는다. 초기 상세 도구 스키마에 96종 ID enum을 주입하지 않는다.
- 잘못된 ID·분류·offset·limit은 오류로 거부된다. 생활 원본의 어종·작물·생활 스킬이 조회되거나 부재로 표시된다.
- 12개 분야 필터는 모두 8 / 96을 표시한다. 요청 초안 유지, 빈 검색에서 요청 숨김, 390px 가로 넘침 없음.
- 요청 확인은 선택한 ID·사용자 원문·현재 맵을 포함한 초안을 반환한다. 자동 전송·정본 콘텐츠 변경은 없다.
- 최종 proof.json은 passed:true, 브라우저 오류 0건이다.

## AI 조수의 선택·조합 지침

일반 제작·수정 요청에서도 조수가 후보를 조회하고 필요한 지침을 읽는다.
사용자의 프리셋 지정이나 편집기 메뉴 선택은 선행 조건이 아니다. 복합 요청은 관련 지침을
각각 읽고 공통 대상·상태를 재사용한다. 설명·조회 요청은 읽기와 설명까지 수행한다.
실제 LLM의 자율 선택·작성·완주를 실행한 근거는 아니다.

## 즉시 확인

- `time-causality.png`: 시대·인과 8종의 선택 화면.
- `loot-equipment.png`: 전리품·장비 8종의 선택 화면.
- `mobile.png`: 좁은 화면의 목록과 요청 초안.
- `proof.json`: 현재 96종의 실제 도구 반환·노출·분야 필터·요청문 관측 결과.
- `catalog-96.json`: 공용 TypeScript 카탈로그 모듈을 직접 실행해 추출한 96종 목록.
- `ai-consumer.json`: 현재 proof.json에서 요약한 조수 연결 결과.

첫 로딩의 시간 초과는 boot-timeout.json, 뒤이은 지도 목록·타일 팔레트 모듈 로딩 오류는
module-loading-errors.json에 보존했다. 해당 모듈 응답을 확인하고 로딩이 끝난 상태에서
동일 경로를 다시 확인한 최종 실행은 오류 없이 통과했다. 관련 패널 코드를 수정하지 않았다.

사용자 정본 프로젝트의 콘텐츠는 수정하지 않았다. 96종을 LLM으로 제작하거나 실제 게임에서
모두 완주한 증거가 아니다. 사용자의 작동 확인 요청 후 관련 Vitest와 앱 타입 검사, CSS 게이트를 실행했다.

## 병합 전 검증

- `authoringPlayPresets`: 페이지네이션·검색·잘못된 입력·읽기 불변성·최신 원본·부재 표시·도구 연결 7개 통과.
- 도구 노출·발견·카탈로그 예산 관련 4개 파일에서 총 18개 통과, 1개 실패. 실패는 기존 `show_title_opening`을 빠뜨린 오프닝 도구 기대 목록이다.
- CSS 게이트는 변경 전·후 모두 exit 1. `css-baseline-comparison.json`의 유일한 출력 차이는 추가한 CSS 선언 6개의 집계이며, 실패 항목과 변경된 기존 승자 수는 같다. 기준선은 갱신하지 않았다.
- 앱 타입 검사는 기본 4GB 힙에서 메모리 한도로 중단됐다. CI와 같은 10GB로 실행한 결과 기존 이벤트 그림 미리보기 파일에 오류 2개가 나왔다. 최신 main의 수정과 통합 후 재확인한다.
