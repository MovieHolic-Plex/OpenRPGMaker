## 시점 보정과 하네스

사용자가 첫 외장 시안이 정면 입면에 가깝다고 지적했다. 해당 시안을 폐기하고
넓은 지붕 윗면·앞벽·후퇴한 옆벽, 첨탑의 여러 면을 코드 도트로 다시 그렸다.
AGENTS.md에는 야외 건물 3/4 계약과 버들항용 하네스 경로를 추가했다.

`npm run harness -- beodeul-architecture build`, `validate`, `review`를 실제 실행했다.
source는 `src/harnesses/beodeul-architecture/node/build.py`, 시드는 `harness-data/beodeul-architecture/seed.json`.
기계 검사는 모든 키트 source 배열과 실제 시트 픽셀 일치, 선언한 면의 불투명 픽셀/면적,
옆벽 폭(11px), 한 입구 메타를 확인했다. 결과는 `harness-data/beodeul-architecture/inspection.json`의 그림 해시에 묶인다.
이는 인간 승인 기록이나 자동 미적 합격 판정이 아니다.
church/brick/sage의 실제 확대·면 마스크 그림과 전체 6종 그림, 저장된 마을 그림을 직접 열어
윗면·앞벽·옆벽 연결과 한 문, 다른 창문, 벽 콘셉트를 시각 확인했다.

정상/오류 그림은 brick 집의 오른쪽 source 칸 열을 실제 삭제한 변조이며
`missing-side-face` (6,4)로 확인한다. 생성기에 변조와 검사 근거를 넣었다.

## 모든 집의 기초

이전 도구는 h101_0 기초만 지원했다. 기존 native h104_0/h107_0/h109_1/h112_0/cathedral에도
전용 기초를 더했다. source 0~47(기존 빈 슬롯 포함)을 보존한 채 112칸/21레시피로 확장했다.
새 기초는 ★로 기존 통행을 따른다. 문 열은 투명이며 한 칸의 꾸밈 충돌이 전체 기초를 취소하지 않도록
점유된 칸을 건너뛰고 다른 부분을 보충한다. 새 3/4 6종은 기초가 그림 안에 포함돼 평면 기초를 중복하지 않는다.

`common-proof.json`: 새/기존 프로젝트의 공용 source·참고문서 등록, 문서 저장 스키마 한계,
원래 5채 마을에서 빠진 4채의 기초 실제 적용, 모든 칸 방향 통행 불변, 재호출 불변을 확인했다.
`look_at_houses`도 버들항 source/graft 전체 배열을 읽도록 보정했다.
합본 마을 칸만 탐지해 0채를 ‘다양함’으로 보고하던 경로 대신 실제 민가 5채·교회 1채를 확인한다.

## 실제 AI와 저장 오류 복구

실제 편집기 AI `opencodex/gpt-6-astra`를 기존 프로젝트에 실행했다.
원문과 호출 기록은 `../assistant-beodeul-village/architecture/coherent-buildings/`.
조수는 건물 사전 6쪽과 실제 건물/오류 그림, 접지 지침을 읽고 resize_map → tile_erase → refine_beodeul_village로 보정했다.
자동 규모 지침이 먼저 44칸으로 확장하며 빈 띠에 끝길 타일을 복사하여 첫 보정은 안전 검사로 거부됐다.
조수는 그 새 띠만 비운 후 다시 적용했다. 원래 40칸 안의 콘텐츠는 그 지우기 범위에 포함되지 않는다.

첫 실행은 턴 상한에 도달했고, 저장 시 작은 마을 예제 문서가 124,694자로 120,000자 상한을 넘어서 실패했다.
기존 SQLite revision 7은 보존됐다. 실제로 쓰지 않는 graft를 예제에서 제거하여 80,662자로 줄였고,
같은 성공 호출 3개를 기록된 인자 그대로 재적용했다. 교회 앞 길은 첨탑 벽을 돌아 마당으로 연결하도록 공용 도구를 고쳤다.
이 결과를 SQLite API로 저장하고 같은 대상을 다시 열어 프로젝트 전체를 비교했다.
실행기가 저장 전에 실제 AI 초안을 파일로 남기도록 개선하여 이후 저장 실패에서도 초안이 사라지지 않게 했다.
초기 AI 호출 전체가 오류 없이 저장됐다고 주장하지 않는다.
