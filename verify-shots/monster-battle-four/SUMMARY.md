# 새 네 종 전투 에셋 제작 기록

## 범위

갓파·회색 늑대·동굴 박쥐·해골 전사, 네 종의 9포즈씩 총36칸이다.
기본 그림은 직전 갓파/세 종 도트 초안과 완전히 같은 픽셀로 보존했다.
팔·다리·턱·날개·검·방패 좌표를 각각 바꿔 새 셀을 찍고, 쓰러짐은 별도의 그림으로 직접 그렸다.
생성형 이미지·비트맵 통째 이동/회전·축소는 사용하지 않는다.

## 즉시 확인

- `four-battle-poses-ko.gif`: 네 종류의 포즈 재생, 저작 동작 미리보기. 게임 녹화가 아니다.
- `four-attacks.png`: 네 종류의 공격 칸.
- `kappa-01-poses.png`, `wolf-grey-poses.png`, `bat-cave-poses.png`, `skeleton-knight-poses.png`: 전36칸의 3배 확대.
- 실제 전투는 `runtime/SUMMARY.md`를 먼저 읽고 거기서 지정한 PNG를 연다.

## 원본과 공용 배선

- 64px 원본, 192×192px 공개 시트, 정확한 idle_a 초상64px. 원본 PNG 재로드 일치.
- 각 종의 아홉 칸은 서로 다르고, 여백·알파0/255·쓰러짐 접지y60을 확인했다.
- 팔레트는 갓파22/늑대15/박쥐17/해골16색. `pixels.json`에 칸별 경계·해시를 남겼다.
- 늑대와 해골의 카탈로그/재생성/기존 개별 명령 셀을 48→64로 바꿨다. 축소하지 않았다.
- 포즈 시트·초상·원본36칸·자료집 설명/검토 해시·접촉 경계·PWA 캐시v8에 연결했다.
- 기존 전체/종별 재생성도 registry에서 네 종의 새 원본을 호출한다.
- 직접 본 전36칸에서 갓파 손가락이 납작해지는 공격 포즈를 발견해 손은 모양을 유지하도록 고쳤다.

## 실제 전투 확인 범위

`player.html + exportProjectStoreShim`, retro2003, 임시 fixture로 네 종의 기본 표시를 직접 보았다.
기존 렌더러의 명시적 칸 선택 API로 36칸의 선택 산식을 별도 확인했다.
강제 칸 선택은 실제 행동 관측 기록에 섞지 않았다.

실제 키보드 입력(방어→적 공격→아군 공격)에서 네 종 모두 준비·이동·공격·복귀·피격이
rAF 샘플에 잡혔다. 격파 시 dead 선택은 네 종 모두 기록됐고, dead의 rAF 샘플은 해골에서만
잡혔다. 다른 세 종의 dead는 기존 격파 처리 사이에 선택된 기록이며, 화면에 유지된 시간의 근거가 아니다.
원본 쓰러짐 그림은 포즈 표와 GIF에서 별도로 확인했다.
starter 요청0·런타임 오류0. `runtime/report.json`에 렌더 샘플/칸 선택 기록을 구분해 남겼다.

첫 QA fixture의 공격력1은 방어 대상으로 피해가0이라 착탄 칸이 지나가는 사례였다.
fixture 공격력35로 정상 피해를 내도록 수정한 뒤 네 종의 실제 공격·피격을 관측했다.
게임 엔진이나 사용자 능력치를 수정하지 않았다.

## 저장 범위

공용 파일의 로컬 변경이다. 사용자 SQLite/호스트/LegacyDb에 쓰지 않았고 커밋·PR·배포하지 않았다.
이 네 종류의 전투 에셋 결과가 기존 139종 일괄 초안의 그림 승인을 뜻하지 않는다.
전체 gates/vitest/typecheck는 실행하지 않았다.
