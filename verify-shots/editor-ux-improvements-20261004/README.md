# 편집기 UX 지연 개선 — 2026-10-04

자료집 입력, 작은 타일 편집의 되돌리기, 긴 이벤트 창 열기를 개선했다.
기준선은 [수정 전 감사](../editor-ux-audit-20261004/README.md)의 `d7a3f0136e`이며,
수정 후 실행은 동일한 합성 fixture와 네이티브 편집기 화면을 사용한다.

| 동작 | 수정 전 | 수정 후 | 시간 감소 |
|---|---:|---:|---:|
| 아이템 설명 한 글자 / 1,000개 | 1,291ms | 148ms | 89% |
| Ctrl+Z / 512×512 타일 맵 | 860ms | 328ms | 62% |
| 이벤트 목록 열기 / 문장 명령 1,000개 | 3,521ms | 2,153ms | 39% |

입력과 되돌리기는 3회 중앙값, 이벤트 열기는 1회다. 시간은 **자동화 입력 시작 → 두 requestAnimationFrame**이며
Playwright 통신·프레임 대기를 포함한다. 실제 픽셀 표시 시점이나 순수 함수 실행 시간을 뜻하지 않는다.
Chromium 1440×900, 배율 1, CPU 제한 없음, reduced-motion, Vite 개발 모드 조건이다.
계정 서비스에 연결하지 못하는 console 네트워크 오류는 있으나 uncaught page error는 두 실행 모두 0개다.
레거시 `event-pages-v3` 샘플을 확장한 UI 전용 fixture이며 모델 호출·팀 호스트·정본 SQLite 저장은 하지 않았다.
공용 자료 hydration을 비웠으므로 출하 Electron/실제 프로젝트 전체 성능으로 일반화하지 않는다.

## 무엇을 줄였나

- 자료집: 설명 입력은 목록 투영을 바꾸지 않아 행을 갱신하지 않는다. 이름·종류·부위·아이콘 변경은 붙은 행만 고친다.
  기존 가상 목록을 연결해 1,000개 중 측정 시 21개 행만 DOM에 붙인다. 세 입력 모두 행 생성/제거 0, 50ms 이상 long task 0이다.
  개수·검색·선택은 전체 자료를 기준으로 유지한다. 고정 행 높이와 실측 피치로 스크롤 지도를 맞추고 키보드로 창 경계를 넘는다.
- 되돌리기: 작은 lowerTiles/upperTiles 변경은 정확한 칸만 기존 `updateMapTiles`의 쓰기 시 복제로 복원한다.
  512×512의 세 Ctrl+Z 모두 `scope: map`, 칸 1개 통지였고 해당 store 적용은 2.7 / 3.0 / 3.8ms였다.
  그 외 프레임·히스토리 갱신 비용은 전체 지연에 포함된다. 초안 보관함·잠긴 지형·다른 맵 속성·타일셋·큰 변경은 기존 전체 복원이다.
- 이벤트: 보이지 않는 스토리/플로우/목록을 열 때 미리 만들지 않는다. 같은 보기의 재적용에서도 중복 생성하지 않는다.
  선택 경로는 네이티브 선택 상태에서 읽어 AI 삽입 대상이 숨은 목록 DOM에 의존하지 않게 했다.
  목록 자체의 1,000개 명령 DOM 생성은 남아 있어, 긴 이벤트의 추가 개선은 목록 가상화가 다음 후보다.

## 편집 정확성과 화면 근거

두 레이어의 실제 undo/redo, 다른 맵 정체성, 덧그림·그림자·스택, 크기, 이벤트,
새 초안과 보관함에만 남은 초안, 잠긴 지형, 프로젝트 복원을 확인했다.

```bash

# 서버가 준비된 뒤 두 실행을 직렬로 실행한다. 기준선 폴더를 덮지 않는다.

WINDOWED=1 OUT=verify-shots/editor-ux-recheck/forms BASE=http://127.0.0.1:9911 node scripts/qa/editor-ux-forms-audit.mjs
```

제품 코드를 바꿨으면 서버를 완전히 재시작한다. HMR로 서로 다른 store 모듈이 남으면 잘못된 화면으로 검증할 수 있다.
`PROFILE=1`은 입력 CPU 조사용 실행이며 성능 비교 값으로 쓰지 않는다. 프로젝트 콘텐츠 저장/배포 작업은 아니다.
