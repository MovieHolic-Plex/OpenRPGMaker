# 공용 DB 등록과 실제 조수 확인 — 2026-10-04

먼저 `publication.json`(공용 DB 저장/재조회)과 `reloaded-audit.json`(두 실제 조수 결과의 SQLite 재로드)을 읽는다.
그림은 `gallery.png`로 두 결과를 한 번에 확인하며, 필요할 때 각 `assistant-*-final/map_*.png`를 연다.

## 공용 DB

저장 대상: `/home/main/.local/share/oprn/shared-content.sqlite`.

| 라이브러리 | 내용 | 적용 |
|---|---|---|
| `worldmap-human-selected` | 사람 선택 79개, 1,620칸, 3용도 참고문서·그림 | 새·기존 프로젝트 기본 자료 |
| `worldmap-real-joseon` | 정본에서 다시 읽은 실제 지형 조선 전도 | 공용 완성 지역, 요청 시 가져오기 |
| `worldmap-real-yucatan` | 정본에서 다시 읽은 실제 유카탄 지형 + 판타지 화풍 | 공용 완성 지역, 요청 시 가져오기 |

등록 전 현재 사람 선택과 source SHA/배열/PNG를 하네스로 대조했다. 두 전도의 공용 사본은 원본과 렌더 픽셀이 같다.
등록은 로컬 공식 CAS API를 사용하며 각 판본을 같은 DB에서 다시 읽었다. LegacyDb/원격에는 쓰지 않았다.
미선택 스팀펑크 교정 후보는 포함하지 않는다. 선택 pack의 하네스 재등록은 같은 판본으로 유지됐다.

`contract.json`: 기존 프로젝트에 공용 기본 자료 적용 후 기존 맵 보존, 새 프로젝트의 선택 킷 79개,
사례 그림의 요청 시 설치, 지형/크기/장소 좌표/전용 타일셋 보존, 같은 SQLite 저장·재로드를 확인했다.
`strict-properties.json`: 실제 Pi 도구 경계에서 선택값 null을 채운 요청으로 크기만 75%로 바뀌며 바닥·다른 속성은 보존됐다.

## 실제 모델 확인

실제 `opencodex/gpt-6-astra`를 편집기와 같은 Pi 런타임으로 호출했다. 도구 ID나 배치 좌표는 요청에 주지 않았다.
모델이 도구 발견 → 실제 공용 DB(41개 라이브러리) 검색 → 사례 문서·그림 + 아이콘 조립 문서 전 페이지·그림
→ 지역 가져오기 → 좌표 선택 → 두 아이콘 배치 → 배열/입구/완성 PNG 검사까지 수행했다.

| 요청 | 도구 호출 | 오류 | 결과 프로젝트 ID | 재로드 판본 |
|---|---:|---:|---|---:|
| 유카탄 지도에 수도·항구 | 36 | 0 | `4be8544a-78d6-4f11-aece-51b5fbefe869` | 2 |
| 조선 지도에 대성·목조 마을 | 38 | 0 | `c9849afe-5372-4000-a0d2-276e2e5f6f88` | 2 |

정본 폴더는 각 `reloaded-audit.json`의 `folder`다. 아이콘 네 개 모두 전체 배열 일치와 입구 바로 아래→입구 이동이 확인됐다.
두 결과는 원본 lowerTiles/실제 지형 ops/기존 시작 맵·위치를 보존하며 캐릭터 크기는 .75다.
각 맵은 `worldmap_<새 mapId>` 타일셋을 따로 소유한다. 원본 전도의 마을 이동 이벤트는 새 사본에 복사하지 않았다.

## 발견하고 수정한 문제

- 업로드 지역의 그림이 snapshot 가져오기에서 빠짐, worldmapSource/characterScale/locations 소실 → 종속 그림과 필드 보존.
- 공용 전도 사본이 같은 예약 타일셋을 편집 → 새 맵마다 전용 타일셋 설치.
- 장소 검색이 지역 문서의 kind를 알려주지 않음 → `referenceRead:{kind:'region',id}`를 명시하고 현재 공용 catalog를 합침.
- 엄격 모델의 빈 선택 ID가 기존 맵 대상으로 해석됨 → 빈 선택 ID는 생략 취급.
- 엄격 모델이 미사용 지형/맵 속성을 실제 기본값으로 채움 → 다섯 관련 Pi 도구의 선택값만 nullable schema로 노출하고 실행 전에 null만 제거.
  0/false/빈 배열과 필수 null은 별도로 유지한다. 크기 변경 시 불필요한 clearForBackground를 실행하던 실제 호출에서 발견했다.
- 바닥 PNG에 구운 숲·길·건물을 일반 마을의 빈 바닥으로 판정 → 정확한 월드 키트 1:1 raster 형식에만 이 계측을 적용하지 않는다.
  일반 맵의 검사는 유지된다. 최종 두 LLM 실행은 이 수정 전 경고에 따라 이미지를 다시 읽고 원본을 보존했으며,
  저장 결과를 수정한 계측으로 다시 읽어 오탐 제외를 확인했다.

## 근거 해석

조선 `summary.json`의 원래 `passed:false`는 SQLite가 JSON 키 순서를 바꾼 것을 내용 변경으로 센 감사 코드의 오류였다.
같은 저장 대상을 다시 읽고 객체 값으로 비교한 `reloaded-audit.json`에서 실제 값 불변을 확인했다. 원래 보고서는 보존했다.
유카탄 첫 final 실행의 summary에는 이후 보강한 바닥/전용 타일셋 필드가 없으므로 같은 재로드 감사로 보완했다.
저장된 모델 텍스트만으로 합격하지 않았다.

저장된 Opus 연결은 접속하지 못했고, 앞선 실행들의 빈 인자/지형 op 실패를 고친 뒤 실제 Astra로 새 프로젝트에서 다시 실행했다.
마지막 실행만 위 통과 집계에 사용한다. 키·비공개 추론·provider prompt payload는 보존하지 않았다.

CLI 검증 범위: 편집기와 같은 도구·발견·문서 관문·실제 모델·정본 저장. UI 의도 선언 호출과 클릭 경로는 별도다.
게임 전체의 오프닝/엔딩/마을 연결이나 마야 건축 고증을 검증한 결과가 아니다. gates/vitest/전체 typecheck는 실행하지 않았다.
