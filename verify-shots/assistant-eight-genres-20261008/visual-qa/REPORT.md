## 무엇을 잘못 평가했나

최초 보고는 플레이 성공, 저장, 일부 화면 결함을 확인했지만 **요청한 장소가 실제로 그 장소처럼 보이는지를 독립적인 필수 합격 조건으로 적용하지 않았다.** 동굴의 반복 판석과 부적합한 외형을 적고도 결론을 기능 조립 능력 중심으로 썼다. 그림을 보고 전체 장소 품질을 불합격시키는 책임을 다하지 못한 평가였다.

정정한 결론은 다음과 같다. 내부 AI는 작은 게임의 맵 연결과 여러 실제 시스템을 조립했다. **검수한 동굴은 동굴 형상부터 실패했고, 여덟 사례 모두 적어도 한 필수 시각 축에서 실패했다.** 이를 완성 게임의 품질 합격으로 표현할 수 없다. 최초 판단은 [수정 전 보고서](/home/main/.codex/worktrees/fbff/rpg-zzu/verify-shots/assistant-eight-genres-20261008/visual-qa/history/REPORT-before-visual-correction.md)에 보존했다. 기능·저장 판정은 해당 증거대로 유지했다.

## 추가 검수 범위와 방법

- 추가 렌더와 판정 전에 [검수 계약](/home/main/.codex/worktrees/fbff/rpg-zzu/verify-shots/assistant-eight-genres-20261008/visual-qa/CONTRACT.md)을 고정했다. 이는 사용자 지적 후 보강한 기준이며 최초 실험에서 사전 등록한 기준이라고 소급하지 않는다.
- 여덟 SQLite를 읽기 전용으로 열어 전체 문서와 타일 blob SHA를 대조하고 **모든 25개 맵**을 목록화했다. 각 사례의 빈 시작 맵 여덟 개도 기록했다. 이 맵들은 새로 제작한 장소의 실패 수를 늘리는 데 사용하지 않았다.
- 기존 `scripts/qa-game/render.mts`와 제품 `drawMapTileLayer`로 25개 맵의 **전체 지형·기물 그림을 렌더하고 직접 열어 보았다.** 이 그림에는 이벤트·배우·상태별 외형·UI가 없다. 실제 플레이 캡처라고 표시하지 않는다.
- 기존 compiled player의 SUMMARY와 관측 영수증을 읽고 **실제 플레이 PNG 15개**를 대조했다. 11개를 이번 검수에서 추가로 열었고 네 개는 앞선 감독자 검수에서 직접 확인한 그림이다. 현재 정본 전체도와 원래 시도의 플레이 그림을 구분해 보존했다. 이미지가 있다는 사실만으로 모든 동적 상태를 통과시키지 않았다.
- 동굴은 현재 프로젝트의 `referenceDocuments` 소유 표식을 제품 함수 `restoreOwnedReferenceDocuments`로 읽기 전용 투영에 복원하고 `export-tileset-references.mjs`로 추출했다. 던전 안내와 바다 동굴 문서 전체, 실제 참고 이미지 두 개를 읽고 열었다. 저장 프로젝트에는 쓰지 않았다.
- 여덟 사례의 공개 도구 추적에서 참고자료 조회, 맵 이미지 요청·전달, 실패, 품질 경고를 확인했다. 조수의 완료 선언과 독립적인 시각 수락 판정을 구분했다.

### 조수가 실제로 본 것과 놓친 것

[도구 추적](/home/main/.codex/worktrees/fbff/rpg-zzu/verify-shots/assistant-eight-genres-20261008/visual-qa/tool-visual-trace-audit.json)에 따르면 조수는 던전 MD 6쪽·이미지 8장, 이어서 나머지 MD 2쪽을 받았다. 성공한 동굴 `show_map_region` 세 번은 **모두 (0,0) 20×15**였다. 서로 다른 전체 영역을 확인한 세 번이 아니다. 24×24 전체와 최종 변경 뒤 모든 영역에 대한 시각 수락 검수를 증명하지 않는다. 마을 미리보기 한 번은 `map-rendering-unavailable`로 실패했고, 맵 이미지가 모델에 전달된 성공 이벤트도 다섯 번 기록됐다.

따라서 **이미지 조회를 전혀 안 한 사례라고 설명하면 부정확하다.** 이미지를 받고도 장소 의미·조립·전체 범위를 검수해 불합격 처리하지 못한 사례다. 외부 평가자와 감독자의 최초 평가에도 같은 누락이 있었다.

동굴 바닥 작업은 다음 순서였다. 참고자료의 2×2 동굴 바닥 kit를 먼저 일부 찍었지만, `fill_region(material:"바닥 동굴")`은 라벨 재료를 찾지 못해 실패했다. 도구가 제시한 채우기 재료는 길 포석·광장 판석·풀밭·물·모랫길이었다. 바로 다음 호출에서 **「버들항 광장 판석」으로 576/576칸을 변경**했다. 동굴 바닥 kit의 이름을 읽는 것과 해당 패턴을 면 전체에 조립하는 능력이 분리되어 있었다.

현재 자료는 천장 밑에 벽 앞면 2–3행을 잇고 입구→목표물→문 동선을 구성하라고 한다. 실제 맵은 이 조립 계약을 충족하지 않는다. 참고 조각 #11 자체도 십자/격자 모양이라 이름만 보고 암반 천장이라고 승인하면 안 된다. **참고자료의 라벨·내용·실제 조각 그림도 함께 검수해야 한다.** `beodeul_city` 안에는 동굴용 조각이 있으므로 칩셋의 도시 이름만으로 실패 원인을 설명하지 않는다.

[참고자료 출처 영수증](/home/main/.codex/worktrees/fbff/rpg-zzu/verify-shots/assistant-eight-genres-20261008/visual-qa/reference-source.json)에 현재 프로젝트·번들 SHA와 복원 방법을 기록했다. 참고 바다 동굴 지도는 Python으로 그린 분위기·배치 참고 그림이다. 게임 엔진에서 통과한 정상 동굴 표본이라고 주장하지 않는다.

필수 축 하나라도 실패하면 시각 불합격이다. 이 표의 통과는 명시한 정적 구조 또는 직접 관측한 장면의 범위에 한정한다. **아름다움 점수나 장르별 일반 성공률이 아니다.** 밝은 갤러리, 시대가 지정되지 않은 학교의 재료, 야외 시설, 단순한 잔디 전장 자체를 임의로 실패시키지 않았다.

- **몬스터:** 마을→들판 (10,0), 들판→체육관 (10,0), 상점 귀환 (7,11)은 표식 없는 투명 전이. 상점·체육관은 잔디와 소수 기물이며 실내 의도를 확정하지 못해 장소 축은 미검증이다. 모든 종·스타터·포획 상태의 외형은 미검증이다.
- **스토리:** 정원과 집 안의 구조는 보인다. 마지막 문 대상은 바닥에 선 사람 외형. 첫 기억의 실제 상태1과 표시3/3이 다르다. 기억 물건의 탐색 자체를 실패로 보지 않았다.
- **갤러리:** 벽·액자·금고는 보인다. (9,3)의 두 동쪽 전이에는 문이 없고 남쪽에 보이는 출구와 다른 좌표다. 꽃잎1인데 기본 HUD514/514가 남는다. 공포 연출 전체는 미검증이다.
- **학교:** 칠판·책상/의자·옷장은 보인다. 복도→교실 (3,4), 복도→창고 (17,3)은 문 없는 바닥 칸이다. 모든 추격·숨기·포착 외형 프레임은 미검증이다.
- **농장:** 여섯 밭의 경계가 보이지 않는다. 마지막 부분 수선의 실제 stage1 파종 그림은 나무이고 주인공을 가린다. 집/가게 문과 실제 전이는 대응한다. 전체 성장·급수 외형은 미검증이다.
- **파트너:** 실제 슬라임을 확인했지만 진화 안내는 킹슬라임, 외형은 용이다. 한 맵이나 액터 방식 자체를 실패로 판정하지 않았다. 장소별 설비와 서비스 식별은 미검증이다.
- **액션:** 벽 띠와 전장은 읽힌다. 잠긴 곳에도 열린 잔디 틈만 보이고 적 둘씩 겹친다. 기력 비용의 기능 증거와 공격·피격·가드·회피 전체 시각 연출 검수를 구분했다.

사례별 모든 맵과 실제 이미지 출처는 `review.json`에 있다. 보고서와 영수증에는 17개 작성 장소와 여덟 빈 시작 맵의 전체도를 모두 기록하고, 비교 화면에는 동굴 전체도와 실제 플레이 증거를 표시한다. 남은 여덟 빈 시작 맵은 목록과 원본 전체도에 보존한다.

## 필요한 도구와 수락 조건 — 우선순위 정정

### P0: 장소 의미와 실제 상태를 보는 독립 시각 검수

**기존 경로를 확장할 제안:** `show_map_region` 이미지 전달, 참고자료, 하네스의 해시 기반 `review`, compiled player를 결합한다. 별도 검수자가 최종 정본의 전체 장소와 중요한 실제 상태를 읽고 축별 통과/실패/미검증을 반환해야 한다.

| 항목 | 계약 |
|---|---|
| 입력 | projectId·최종 full SHA·맵 묶음/각 맵 SHA, 요청한 장소·상호작용·상태, 현재 참고자료와 실제 자산 그림, 전체도와 native PNG/상태 영수증 |
| 출력 | 축별 판정, mapId·좌표·장면·직접 본 결함, PNG SHA, 검수한 범위와 미검증 범위, 보수 후 다시 확인할 조건 |
| 완료 거절 | 장소 형태·입구·필수 대상·상태 외형 실패, 일부 영역만 조회, 마지막 변경 이전 그림, 렌더 실패, 배우 생략 전체도만으로 동적 상태 합격 |
| 교정 | 엔진에서 직접 본 정상 동굴과 이번 실패 동굴로 검수자 판정을 교정. 현재 분위기 참고 그림을 정상 게임 표본으로 대신 쓰지 않음 |
| 수락 | 동굴 전체에 연결된 암반/벽·통로·입구가 보이고 실제 왕복 좌표와 일치. 약초와 보스를 그림으로 구별. 다른 게임도 각 필수 축을 현재 해시로 검수 |

현재 [Pi 완료 처리](/home/main/.codex/worktrees/fbff/rpg-zzu/scripts/lib/piAgentRuntime.ts:813)는 배치 품질을 한 번 권고한 뒤 재검사 미달도 숫자로 알린다. 이 JRPG도 두 번째 `layout_quality.ok=false`가 남았다. 빈칸 비율을 무조건 강제하는 것은 해결책이 아니다. 동굴 통로와 열린 공간의 목적을 검수해야 하며 기물로 채워 숫자만 낮추면 더 나빠질 수 있다. `evaluate_game_quality`와 정적 모험 완료 규칙도 미술 인증이 아니라고 [기존 계약](/home/main/.codex/worktrees/fbff/rpg-zzu/openwiki/editor-ai-tools.md:2330)에 명시되어 있다.

### P1: 장소 재료·패턴 조립과 입구의 시각 배선

- `stamp_object`는 기존 동굴 kit/그룹의 작성된 셀을 찍을 수 있고, `stamp_layer_block`은 여러 층의 완성 배열을 넣는다. `paint_tiles`도 있다. **동굴 조각을 배치할 도구 자체가 없다고 주장하지 않는다.**
- 부족한 연결은 참고자료의 바닥 패턴→해당 면 조립, 천장 경계→앞면 벽→코너→통행 공간, 입구 그림→실제 전이 좌표다. `fill_region`은 현재 일반 재료 그룹을 사용하며 이 시도에서 동굴 패턴 라벨이 거절됐다.
- 입력은 검수된 패턴/kit ID·용도·레이어·경계와 동선 계약. 출력은 원자적 조립, 보존 diff, entrance 좌표, 전체 그림과 미검증 진술이어야 한다. 동굴 바닥 실패를 도시 판석으로 바꾸어 요청을 축소하면 완료를 거절한다.
- 미궁·동굴 등 장소 개념의 교정은 기존 `super-harness` 절차로 제안·검수한다. concept card를 손으로 바꾸거나 감독자가 사람의 자산 선택을 대신하지 않는다. 새 그림 제작부터 시작하기 전에 기존 조각의 품질과 연결 가능성을 확인한다.
- 수락은 같은 저장본의 실제 전체 그림과 원래 입력 왕복이다. 출입구 좌표 반환, 통행 검사, 채우기 성공만으로 시각 통과를 주지 않는다.

### P0/P1: 상태 외형·HUD를 기능과 같은 완료 조건으로 취급

기억1/표시3, 꽃잎1/HUD514, 작물/나무, 킹슬라임/용, 잠긴 문/열린 틈은 장식 취향이 아니라 실제 게임 상태를 잘못 읽게 만드는 결함이다. 기존 도구와 플레이 검수의 상태 영수증에 해당 PNG를 묶어 실패를 반환해야 한다. 원 보고서의 저장·분기·보상·처치 연결 개선은 그대로 필요하다.

## 한계와 재현

게임과 제품 소스는 이 정정 검수에서 수정하지 않았다. 모든 동적 외형을 새로 플레이한 전수 검사는 아니다. 해당 미검증 항목은 표와 영수증에 남겼다. 기능 합격을 미술 합격으로 확장하거나 추가 검수 기준을 최초 사전 기준으로 바꾸지 않았다.

읽기 전용 추출·렌더·현재 참고자료 복원·trace 감사·영수증 작성 스크립트는 원 실행 폴더의 `visual-qa/`에 보존했다. `prepare-genre-visual-qa.mjs` 원본은 최초 출력 후 큰 JSON을 원 실행 폴더로 옮겼으므로 재현 시 새 출력 폴더와 source 경로를 사용한다. `inventory.json`에 현재 source 경로가 있다. 참고자료 추출은 다음 기존 명령으로 새 폴더에 수행한다.

```bash
node scripts/content/export-tileset-references.mjs <읽기 전용 current-reference-view.json> beodeul_city <새 참고자료 폴더>
```

검수 PNG의 해시와 원본 경로는 `review.json`에, HTML 표시용 축소 사본의 해시는 `display-image-provenance.json`에 있다. 과거 보고/데이터/최종 영수증은 `history/`에 보존했다.
