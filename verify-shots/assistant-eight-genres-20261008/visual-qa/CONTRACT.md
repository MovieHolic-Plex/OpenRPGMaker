# 장소·게임 화면 시각 검수 보강

2026-10-08. 사용자가 동굴 품질과 Visual QA 누락을 지적하여 수행하는 추가 검수다. 최초 보고와 평가는 history에 보존한다. 제작 완료·기능 통과·캡처 생성은 시각 합격이 아니다.

## 검수 기준 — 추가 캡처와 판정 전에 고정

각 프로젝트의 모든 맵을 정본 전체 SHA와 맵 SHA에 묶어 목록화한다. 플레이 경로 밖의 원래 빈 맵도 목록에서 숨기지 않는다. 지형 전체도는 기존 에디터의 drawMapTileLayer를 사용하는 qa-game renderer로 만든다. 이 전체도는 이벤트·배우를 표시하지 않는 읽기 전용 지형 투영이며 실제 플레이 캡처와 별도로 표시한다. 누락된 자산을 기본 그림으로 바꾸지 않는다.

실제 게임 화면은 기존 compiled player의 PNG와 상태 영수증을 함께 검수한다. SUMMARY를 먼저 읽고 자유 필드·실내·상호작용·HUD 중 필요한 화면을 연다. 메뉴·대사에 가려진 화면은 전체 장소 품질을 합격시킬 수 없으며 상태 주입·이동 강제·게임 콘텐츠 변경을 하지 않는다. 부족한 뷰는 미검증으로 남긴다.

### 장소별 판정 축

1. **장소 식별과 형상:** 요청한 장소를 이름·대사 없이 구조로 읽을 수 있는가. 동굴은 암반 경계·둘러싸인 통로/공간·굴 입구와 내부 형상을 검사한다. 도시 판석과 기물 반복만으로 동굴 통과를 주지 않는다. 학교·전시실·집·밭도 해당 기능의 공간 구조와 기물을 대조한다.
2. **타일 조립과 레이어:** 벽·바닥·가구의 연결, 잘린 조각, 투명 칸, 허공 기물, 같은 장식의 무의미한 반복, 통로를 막는 시각 구조를 본다. 코드의 빈 타일 비율만으로 실패를 판정하지 않는다.
3. **출입구와 동선:** 문·입구·귀환 지점이 그림으로 읽히고 실제 전이 좌표와 맞는가. NPC를 문이라고 표시하거나 아무 표식 없는 바닥 칸에 전이를 둔 사례를 별도로 적는다. 원래 입력으로 왕복 성공해도 시각 합격이 되지 않는다.
4. **상호작용·목표물 인식:** 밭 여섯 칸, 기억 물건, 약초, 가게, 옷장, 열쇠, 적·보스·보상물이 실제 그림으로 구별되는가. 같은 외형을 다르게 안내하거나 성장 그림이 작물과 다르면 실패다.
5. **배우·UI·장르 일치:** 실제 개체/종과 필드·전투 외형, 겹침·가림, 체력·진도와 HUD, 요청과 무관한 기본 타이틀·오프닝을 본다. 실제 이미지를 못 본 항목은 설정만으로 시각 통과를 주지 않는다.

각 축은 통과/실패/미검증으로 판정한다. 하나의 필수 축 실패는 해당 사례의 시각 불합격이며 기능 성공으로 상쇄하지 않는다. 여러 맵 중 일부만 본 경우 전체 품질 합격을 주지 않는다. 아름다움 점수·성공률·자동 인간 승인을 만들지 않는다.

## 보고와 도구 제안

불합격은 case/mapId·좌표 또는 장면·정본/PNG SHA·직접 본 결함·현재 도구와 예상 개선·수락 검수를 기록한다. 전체도와 런타임 캡처의 한계를 구분한다. 내부 AI가 실제 show_map_region/render 결과를 조회했는지 추적하며 조회 자체를 품질 합격으로 세지 않는다. 기존 참고자료·등록 장소·공간 하네스·이미지 전달/검수 경로를 먼저 확인한다. 잘못된 지도 그림을 이 검수 중 수선해 원 실험을 합격시키지 않는다.
