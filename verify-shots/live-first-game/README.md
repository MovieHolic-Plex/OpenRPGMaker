# 실제 첫 제작·저장·출하 검증 (2026-10-03~04)

## 판정 범위

독립된 루프백 SQLite 호스트에서 추리·미스터리 인터뷰를 직접 입력하고 실제 기본 모델
`gemini-3.8-flash`를 호출했다. 요청은 「멈춘 시계의 기억」의 회중시계 조사 → 두 기억 선택지
→ 서로 다른 대사 → 기억의 길 → 첫 구간 엔딩이다. 공유 사용자 호스트의 권한·데이터는 수정하지 않았다.

**자동 첫 생성은 완료되지 않았다.** 실제 조수에게 후속 요청을 보내 핵심 이벤트와 누락 음악을
완성했다. 후속 제작·내보내기가 성공해도 자동 생성의 성공으로 계산하지 않는다.

## 고친 코드

1. 워커의 공용 카탈로그를 판본별로 설치하고 팀원이 재사용한다. 최초 설치는 스트림 시작 전에 끝낸다.
2. Pi 작업 사본의 타일셋·업로드 항목은 기존 읽기 전용 공유 계약을 사용한다. 맵·DB는 분리한다.
3. 첫 생성의 팀원 턴 상한이 공통 `workBudget`에 덮이지 않도록 실제 자식 요청에서 다시 제한한다.
4. 헤드리스 워커도 설치된 BGM 파일 목록을 읽어 기존 음악 가용성 필터를 적용한다.
5. 호스트가 SDK의 `player.html`에 편집기 브리지를 주입하지 않는다. 바이트 변경으로 ZIP 무결성 검사가 실패하던 결함이다.
6. ZIP 플레이어가 SQLite 미디어 `ref`를 패키지의 실제 업로드 파일 경로로 해석한다.
7. 내보내기는 불필요한 참고문서를 제거한 뒤 사본을 만들고, 보존된 업로드 자산도 원본과 분리한다.

## 런타임 결과

`gameplay.json`과 `keep/SUMMARY.md`, `release/SUMMARY.md`를 먼저 읽는다.
검사 대상은 패키지의 실제 `player.html`과 `project.json`이며 편집기 play 모드를 통과하지 않는다.
정본의 기획·이벤트·맵 타일·음악을 패키지와 비교하고, 두 선택지를 실제 키보드로 각각 플레이한다.
외부 요청은 차단한다. 런타임 결과와 시각적 완성도 판정은 별개다.

최종 검사에서 두 분기 모두 7/7 비트를 통과했다(총 14/14). 각기 다른 결과 대사를 확인하고
정상 키보드 이동으로 같은 첫 구간 엔딩에 도착했다. JavaScript 오류·외부 요청·실패한 미디어
요청은 없었다. 실제 플레이어 그림도 디코딩되었다. 실행 소요는 간직 27.480초, 놓아주기 24.780초다.
전환 직후 좌표는 페이드 완료보다 먼저 커밋되므로 `data-live-flags`에서 입력 ON·이벤트 종료를
기다린 뒤 다음 키를 보낸다. 초기 검사에서 그 대기를 빠뜨린 실패는 게임의 길 막힘으로 계산하지 않았다.

이 결과는 엔딩까지 작동한다는 근거다. 회중시계의 시각적 식별, 공간 연출, 인물 외형을 포함한
기획 충실도와 미적 완성도를 합격으로 판정한 결과는 아니다.

## 남은 문제와 검증 제한

- 핵심 플레이보다 반복적인 맵 장식에 시간을 쓰는 자동 제작 순서는 해결을 입증하지 못했다.
- 작은 2맵 게임에 85MB 프로젝트 JSON과 331MB ZIP이 필요했다. 기본 타일/이미지 카탈로그 포함 정책은 이번에 바꾸지 않았다.
- 첫 변경까지 약 3분 51초 걸렸다. 카탈로그 캐시와 사본 개선이 즉시 첫 결과를 보장하지 않는다.
- 120턴 상한 수정 뒤 새 자동 첫 생성 전체를 다시 완주한 결과는 없다.
- 전체 gates/Vitest/typecheck는 AGENTS의 이 세션 실행 제한에 따라 돌리지 않았다.
  앱·플레이어 빌드, 실제 모델 실행·정본 저장/재로드, 실제 ZIP 내보내기와 전용 런타임 경로로 확인한다.
- 회귀 테스트는 작성했으며 이 세션에서 실행하지 않았다.
