# 512/1024 플레이어 부하 실측 검토

- 명령: `node scripts/qa/map-size-benchmark.mjs --sizes 512,1024 --frames 600 --out verify-shots/map-size-1024-20261001`
- 직접 확인한 프로세스 종료 코드: **0**. 준비 실행 1회 제외, 크기별 3회 교대 실행.
- 각 크기 정지 1,800프레임 + 이동 1,800프레임. 실제 오른쪽 이동, 이동 중 타일 전체 재생성 없음, 브라우저 오류 없음.
- `512-field.png` / `1024-field.png` 직접 열람: 두 화면의 동일 바닥·플레이어·HUD가 정상 표시된다.
- 측정은 main `593ea9c6dc05e48d6319da79f6b36a932a5c31ef` 위 미커밋 1024 변경 상태다. 원시 JSON에 dirty 여부와 SHA-256을 기록했다. 실행 후 측정 대상 5파일의 해시가 모두 일치함을 확인했다(`validation.json`).

## 수치 해석

`SUMMARY.md`의 중앙값은 실행별 수치를 3회 중 가운데 값으로 합친 것이다.
CPU p95와 프레임 간격 p95 역시 **실행별 p95의 중앙값**이다. CPU 최대는 3회 전체 최대다.

- 동기 맵 진입: 147.30 → **481.50ms** (3.27배). 첫 postrender까지: 208.10 → **542.60ms**.
- 이동 프레임 CPU: 중앙값 **2.10ms → 2.10ms**, p95 5.20 → **5.00ms**, 최대 14.70 → **15.80ms**.
- 이동 FPS 중앙값: **60.01 → 60.01**. 면적이 4배여도 표시 타일 객체는 **3,000 → 3,000**.
- 이동 프레임 간격 p95: 19.10 → **18.90ms**. 각 크기 1,797개 간격 중 50ms 초과는 각 **1회**, 최대는 512에서 60.80ms, 1024에서 56.10ms. 일시적인 긴 프레임이 전혀 없었다고 주장하지 않는다. 발생 원인은 따로 식별하지 않았다.
- GC 후 총 JS heap: 109.82 → **127.81MiB**. 기준 32×32 맵 대비 진입 후 추가 heap: 2.20 → **8.20MiB**.

## 측정 범위

기준 맵을 띄울 때 이미 target의 논리 배열을 로드한다. 따라서 **추가 heap만으로 맵 전체 RAM을 말할 수 없다**.
총 heap에는 프로젝트와 플레이어 공통 메모리 및 target의 로드된 논리 배열이 포함된다.
둘 다 Chromium JS heap이며 native·GPU 메모리나 프로세스 전체 RSS가 아니다.
진입 시간도 파일 로드·JSON 파싱·타이틀 부팅을 제외한 실제 씬 전환의 동기 비용이다.

실제 내보내기 player 경로이며 편집기 셸을 통과하지 않는다. 정본 프로젝트 쓰기는 없다.
합본 마을 타일 360, 16px, 바닥 1층, 높이 없음, NPC 0명, 640×480, SwiftShader 조건이다.
CPU 측정에는 GPU 작업 완료가 포함되지 않는다. 공유 머신 loadavg는 시작 13.05/11.30/9.18,
종료 19.28/19.13/13.64였다. 우리 테스트/타입 검사/편집기 QA는 실측이 끝난 뒤 실행했다.

1024의 비평탄 높이 지형은 이번 측정에서 다루지 않았다. 편집기의 `EditScene.renderReliefLayer`
전체 CanvasTexture 경로가 남아 있으며 래스터 폭이 16,384px이다. 다층 타일·이벤트가 많은 맵,
높이 붓·되돌리기·파일 저장·사용자 GPU에서의 성능은 이 숫자로 보장하지 않는다.

## 측정 뒤 하네스 정리

실측 당시 스크립트는 `measured-benchmark-source.txt`에 바이트 그대로 보존했다.
실측 뒤 긴 `--frames` 입력에도 표본을 모을 시간을 주도록 deadline을
`max(45000, count * 40)`으로 바꾸고 결과 설명에서 p95/최대 집계 방식을 바로잡았다.
이번 600프레임은 전후 모두 **45초** deadline이며 수집/측정 로직은 동일하다.
런타임 3파일과 상한 소스는 실측 이후 바뀌지 않았다.

`benchmark.log`는 반복되는 Vite public-assets 경로 안내를 생략하고 실행 단계/회차 JSON과 결과 보고서를 보존한다. 프레임 원시 데이터는 `raw-results.json`에 전부 있다.
