# 아이템 탭 정보 위계 정리 — 실측 증거

`node scripts/_capture-db-items.mjs verify-shots/db-items/<before|after>` 로 찍었다.
세 폭(1440×900 / 1280×800 / 1024×768) × 네 상태(기본 · 약 · 무기 · 스위치).

## before 가 보여주는 결함

1. **"수치" 카드가 이름값을 못 한다** — 가격·범위·포획 배율·볼 등급·연결 스킬이 한 장에
   섞여 있다. 카드 제목만 읽고 무엇이 들어 있는지 예측할 수 없다.
2. **scope 컨트롤이 두 개다** — 약 종류에서 "수치 → 범위" 셀렉트와 "범위 → 대상"
   세그먼트가 같은 `record.scope` 를 동시에 편집한다(장비 `slot` 중복과 같은 실패 모양).
3. **그래픽 카드가 효과 카드 사이에 끼어 있다** — [기본][수치][그래픽][범위][회복량] 순서라
   "이게 무엇인가"와 "무엇을 하는가"가 뒤섞인다.
4. **"사용 가능" 카드가 4 번 복제된다** — 약·책·씨앗·특수 패널이 각자 한 장씩 그린다.
5. **필터 칩이 11 개 평평하게 흐른다** — 개수도, 소비/장비 구분도 없다.

## after

카드 순서가 위계다: 요약 → `정의`(기본 · 그래픽) → `효과`(대상과 사용 시점 · 종류별 효과 ·
연결 스킬) → `사용 제한`(사용 가능 · 포획). scope 컨트롤은 종류마다 정확히 하나
(약 = 세그먼트, 그 외 = 공용 셀렉트). 칩은 개수 배지를 달고 소비/장비 묶음으로 갈린다.
칩 블록 높이는 before 와 같다(1024×768 실측 ~82px).
