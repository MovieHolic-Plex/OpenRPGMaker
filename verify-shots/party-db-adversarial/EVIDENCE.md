# N. 2차 검증에서 뒤집힌 판정 (독립 리뷰 2패스 이후, 깨끗한 재현으로 확정)

## N-1. 겹침(C절) — **확정. Pass A 의 "오탐" 반론을 기각한다**
Pass A 는 "legend 가 fieldset 테두리를 파고드는 정상 렌더를 rect 교차가 오인했다"고 보류를 요구했다.

**서로 합성돼 「전투몋뺑니메」 형태의 판독 불가 글자 뭉치**로 렌더된다. 정상 legend 렌더가 아니다.
→ **P0 유지.** Pass B 의 육안 판정이 옳았다.

## N-2. 직업 곡선 카드 — **융착 + 그래프 완전 부재 확정**
`zoom-classes-curve-label.png`: `최대 HPLv1:40` `최대 MPLv1:12` `공격력Lv1:22` `방어력Lv1:14`.

근인은 Pass A 지적대로 `gap` 이 아니라 **`display` 미선언**:

같은 규칙에 남은 `align-content: center` 는 block 에서 무효 속성 → grid 의도의 미완성 흔적.

## N-3. 삭제 확인 만료 누출 — **오탐. 철회한다**
1차 배치에서 "라벨이 `삭제` 인데 단일 클릭으로 삭제됨(LEAK)"으로 읽었으나, 직전 테스트의
무장 상태가 남은 오염된 시퀀스였다. 신선 부팅 후 최소 재현(`s1_expiryBoundary`):
```
arm → "정말 삭제?" → 3.4초 대기 → 라벨 "삭제" → 단일 클릭
→ rows 8→8 (삭제되지 않음), 라벨 "정말 삭제?" 로 재무장
```
→ **만료 후 클릭은 삭제가 아니라 재무장. 누출 없음.** 2단계 삭제 설계는 건전하다.

## N-4. 레코드 교차 무장 — **안전 가드는 유지되나 라벨이 낡는다 (신규 P2)**
`s2_crossSelect` (신선 부팅):
```
A 무장 → "정말 삭제?" → 선택을 B 로 변경 → 라벨 여전히 "정말 삭제?" (A 소유의 낡은 라벨)
→ B 에서 1회 클릭: rows 10→10 (가드가 거부, 아무 피드백 없음)
→ 2회 클릭: rows 9 (B 삭제)
```
과거 사고(A 무장 후 B 즉시 삭제)의 **회귀는 없다**(`databaseRecordViews.ts:344-351` 가드 유효).

## N-7. 추가로 확인된 접근성·상호작용 사실 (1차 배치 이후)

  `tabindex` 전부 `null`(활성 0 / 비활성 -1 관리 없음), `aria-controls` 전부 없음
  → 광고한 ARIA 탭 패턴을 구현하지 않음.
- 레코드 행: `<button role="row" tabindex="0" aria-selected="true">`.
  처음에 "`role="row"` 는 무효"라고 적었으나 **틀렸다** — 주인공 스튜디오 목록은 조상이
  `role="grid"`(`databaseActorStudio.ts:31`)이므로 `row` + `aria-selected` 는 정당하다.
  실제 결함은 그 아래 셀이 `role="cell"` 이었다는 점뿐이다(`cell` 은 `role="table"` 전용,
  `grid` 의 행은 `gridcell` 을 소유한다 — ARIA 1.2). → `gridcell` 로 교정.
- 포커스 링: 레코드 행·`db-add-record` 는 `solid 2px rgb(74,87,214)` 로 양호.
  반면 `db-view-toggle-gallery` 와 목록 검색 입력은 `auto 1px rgb(16,16,16)` = **UA 기본 링**.
- 복제: 정상 동작(직업 6→7, 신규 이름 `전사 사본`).
- 아이템 목록: 윈도잉되어 DOM 행 수가 25→16 으로 변동, `scrollHeight 5714` 로 끝까지 도달.
  **226개 전수 도달성은 미검증**으로 남긴다(윈도잉 때문에 단순 카운트로 판정 불가).
- 카테고리 칩 필터 동작: 셀렉터 불일치로 **미검증**.
