- 관련 단위·계약 테스트: 12파일 124개 통과. 법칙·설정집·모달·깊은 링크·카메라 이동 포함.

- Chromium 통합본 E2E: 1개 통과(2.0분). 전체 저장/닫기/재열기, 연속 검색, Enter/Space 잠금, 삭제 확인/취소, 1024·900·800px에서 편집 버튼과 카드 이름의 중심점 hit test 통과.
- CSS 게이트 통과. 표면 게이트는 main과 같은 6개 스냅샷 테스트 및 `.selected` CSS 기준선 불일치로 실패한다. 수정 전 main을 직접 실행해 전체 오류 내용의 일치를 확인했다(`surface-comparison.json`).
- 최종 전체 게이트: exit 1. 앱 타입 검사와 CSS는 통과했으며, 단위 테스트는 13,068개 중 12,849개 통과·204개 실패·15개 건너뜀이다(`gates.json`).
- 저장된 기준선 밖 실패 27파일을 수정본/main에서 직접 재실행: 양쪽 모두 214개 중 190개 통과·24개 실패. 실패 테스트와 경로를 정규화한 오류 원문이 모두 일치했고 수정본에만 있는 실패는 0개다(`test-comparison.json`). 전체 실행에서 실패했던 32개 검사는 이 재실행에서 통과했다. 기준선 파일을 변경하거나 실패를 숨기지 않았다.

## 실행 범위

브라우저는 Chromium 실제 편집기와 격리된 `blankProject` 세션을 사용한다. 호스트의 네트워크 변경에 의한 localhost 모듈 로딩 취소를 피하기 위해 `WORLD_QA_ROUTE_MODULES=1`로 동일한 응답을 Node fetch로 중계했다. 모든 편집은 UI 이벤트로 실행했으며 강제 클릭이나 store 직접 조작을 사용하지 않았다.

실제 사용자 프로젝트 및 LegacyDb 콘텐츠는 수정하지 않았다. 이번 작업은 편집기/데이터 정규화 코드 수정이며, 직렬화 왕복과 브라우저 저장·재열기를 검증한다. 원격 저장 검증이나 실제 LLM 출력 품질 검증을 했다고 주장하지 않는다. 과거 압축 과정에서 이미 제거된 false 값은 복원할 근거가 없어 미정으로 남는다.
