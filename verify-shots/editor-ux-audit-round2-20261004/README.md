생활 폼의 비용은 `databaseLifeCollectionsView.ts:121–122`에서 모든 물고기를 순회하고
`:351`의 전체 아이템 선택지를 `:797`에서 만드는 경로로 설명된다. 검색은 `:101`에서
탭 전체를 새로 그리며 `database.ts:1015`의 blur와 검색 노드 교체 뒤 포커스를 복원하지 않는다.

전체 선택은 `commandInspector.ts:85`에서 각 행에 대해 선택 경로를 `some`으로 검색하며
JSON.stringify를 반복한다. 평평한 1,000행/1,000선택의 이 루프는 코드상 최대
500,500개의 경로 비교를 수행한다. 이것은 소스로 계산한 횟수이며 브라우저에서 직접 센 횟수는 아니다.
선택 툴바 등의 추가 작업도 있으므로 관측된 긴 작업 전체를 이 루프 하나의 CPU 시간으로 단정하지 않는다.

맵 전환은 `mapList.ts:1288`의 선택이 `mapSidebarSection.ts:26`의 동기 구독 갱신을
일으킨 뒤 명시적으로 다시 그리는 경로다. 캡처의 `treeReplacements=4`는
**childList 레코드 4개 = 비우기/붙이기 2쌍**이며 렌더 4회가 아니다.
행마다 `Object.keys(project.maps)`를 만드는 비용도 남아 있다. 썸네일 캐시는 120개로
제한되므로 300맵 조건의 비용에는 캐시 교체와 비동기 썸네일 작업이 섞일 수 있다.
현재 aggregate wall 시간으로 중복 렌더만의 기여도나 수정 후 개선률을 계산하지 않는다.

진행 복제 계측은 `structuredClone` 인자 중 이벤트 형태의 객체를 센다.
보이는 진행 패널에서는 첫 클릭 1,000회, 이후 500회였고, 접힌 상태에서는 모두 500회였다.
‘그리기’로 전환한 비교 조건에서는 이벤트 복제/진행 DOM 갱신 모두 0회, 긴 작업도 0회였다.
서로 패널 폭과 버튼 자동화 조건이 달라 wall 시간 자체는 진행 비용의 A/B 지표로 쓰지 않는다.
접힌 부모는 hidden이지만 진행 루트는 hidden=false인 상태도 함께 기록했다.

캐릭터 그리기는 canvas의 세로 뷰포트 교차와 표시 크기로 visible/offscreen을 분류했다.
도구가 넣은 geometry 읽기는 추가 비용이므로 이 결과는 불필요한 **작업 횟수**의 근거이며
CPU 절감률은 아니다. 모달 닫기 이후 지속되는 누수는 이번 관측에서 재현되지 않았다.

## 아직 코드 확인만 한 후속 후보

아래 항목은 **시간·메모리 실측 전**이다. 기존 가설을 재확인한 것과 새 트리거를 보고서에서 구분했다.

- 필터를 켜고 타일을 선택하면 닫힌 구조물/붓 보조 내용까지 만든다. 현재 버들항의 구조물 725개,
  타일 27,648개에서 캔버스 생성·유사도 정렬·맵 사용처 검색이 겹친다.
- 높이 호버는 캐시 검사 전에 전체 높이 서명을 계산한다. 첫/마지막 언덕은 뷰포트 밖 칸까지
  좌표 배열을 만든 뒤 필터링한다. 지면 지문 재생성과 전체 픽셀 backing도 별도 후보다.
  backing 3배열의 공식은 `7 × (16W) × (16H+P)` bytes; 총 프로세스 메모리나 실측값이 아니다.
- 자료집 ‘연결’은 이름 같은 표시용 필드 편집에도 프로젝트 정체성이 바뀌어 이벤트 참조를 재검색한다.
- 조수 대화 검색은 페이지를 나누기 전에 전 프로젝트의 전체 대화를 읽고 검사/정렬한다.
  작은 작업 이미지 캡처도 자르기 전에 맵의 보조 레이어 전체를 복사한다.
- 공간 저작 데이터가 있는 조수 체크포인트는 roundtrip skeleton 재사용을 끈다.
  조수 실행 중 칸 정보 없는 사람의 높이 편집에는 전체 칸 비교가 추가될 수 있다.
- 저장은 한 칸 변경도 한 맵 안에서 큰 직렬화/비교를 수행할 수 있다. 여러 단계 역사 점프는
  최근에 고친 단일 칸 undo 경로를 거치지 않고 스냅샷을 반복 복제한다.
- 전투 애니메이션 미리보기는 셀 DOM을 반복 교체하고, 멈추거나 캐시된 상태에도
  document.body의 다른 DOM 변경을 관찰한다. 기억된 자료집 탭의 숨은 자동 재생도 추가 확인 대상이다.
- Electron app://의 공용 카탈로그 ETag/304 전달 누락은 전용 앱 실행으로 확인해야 한다.
  개발 HTTP 브라우저 캡처로 이 항목을 검증했다고 보지 않는다.

표시 상태로 미리보기 렌더를 제어하는 수정에서는 조수의 백그라운드 실행·진행·체크포인트 계약을 유지한다.
높이 서명 캐시는 제자리 수정 경로가 있어 객체 정체성만으로 도입하면 안 된다.
저장/undo 최적화는 초안 보관함과 저장 기준본 불변성 등 기존 계약을 함께 검토해야 한다.
