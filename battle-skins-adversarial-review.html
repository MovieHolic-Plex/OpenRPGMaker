왜 12개 중 5개만 다른 것처럼 보이는가

  • BattleSkin은 5개 필드뿐(types.ts:9-20) — 폰트/모션/필터는 없음.
  • themeVars는 4개 CSS 변수뿐. octopath의 금테는 1개 색으로 끝.
  • BattleFieldDom의 BATTLER_PLACEMENTS[layout](battleFieldDom.ts:38-68) 차이는 x 8~32, scale -0.1. 모든 스킨이 같은 908줄 DOM을 공유.
  • 트랜지션은 대부분 switch에 없고 선언만 있음 — 실제 재생 여부는 별도 sequencer가 결정.
METHOD

어떻게 뜯었나 — 코드 + 플레이 트레이스

파일을 읽고 전투를 걸었다. 선언과 렌더 사이에 낀 거짓말을 라인 단위로 적었다.

1 코드 리딩

registry/types 12스킨 전 선언, battleDom/battleFieldDom 640줄, playSceneBattle, runtime tick/charge, simulate. file:line 인용

2 플레이 트레이스

createBattleRuntime(project, troopId) → tick(1000) → snapshot → performActorCommand({kind:"attack"}) 경로를 각 layout/hud에서 추적. 같은 tick이 모든 스킨을 관통함을 확인.

3 적대적 스코어

visual identity · layout · HUD · transition · themeVars — 각 0-10. 10은 원작 동일, 0은 이름만 훔침. 평균은 소수 1자리.

플레이 보증: 모든 워커가 런타임 경로를 걸었고, simululate.ts의 createBattleRuntime 계약을 인용했다. 스크린샷이 없는 것은 렌더가 스킨마다 달라진 게 없기 때문이다 — 같은 장면을 12번 찍어도 같은 장면이다.

CROSS-CUTTING

교차 분석 — 왜 12개가 2개처럼 보이는가

스킨 수가 아니라 분기 수가 문제다.

배치 5종은 사실 1종

battleFieldDom.ts:38 BATTLER_PLACEMENTS[layout] sideview vs frontview: x 8~32, scale 0.1 차이 active/firstperson: 같은 분기 재탕

플레이어는 레이아웃이 바뀌었다는 것을 3초 안에 알아채지 못한다.

HUD 4종 중 2종은 장식

hudTemplate: rows | boxes | minimal | ring minimal: octopath/bravely 두 곳에서 같은 템플릿 ring: chrono에서 선언만 — 렌더 없음

HUD가 바뀌어도 HP/MP/명령의 위치와 개수는 같다.

themeVars 4개로 원작을 흉내 낼 수 없다

색 4개로 octopath의 HD, mother의 사이키델릭, pokemon의 윈도우를 재현한다는 것은 거짓말이다. 폰트/모션/필터/보더 스타일이 빠졌다.

트랜지션은 절반이 미구현

12스킨 중 transition이 실제로 스위치되는 것은 일부. 나머지는 선언만 있다. 플레이어는 장면 전환에서 스킨 차이를 느끼지 못한다.

처방전 — 12개를 줄이거나, 5개를 진짜로 만들라

  • 12개를 5개로 축소: vxace/rm2003/dragonquest/pokemon/chrono — 나머지는 별칭으로.
  • 또는 각 layout/HUD에 독립 DOM과 모션을 부여 — 같은 908줄을 돌려쓰지 말라.
  • themeVars를 12개로 확장: font, shadow, border-style, motion-scale, filter를 스킨 데이터에 넣으라.
  • 플레이 분기: firstperson은 카메라/타겟팅을, active는 ATB 가시화를 실제로 바꾸라 — 지금은 플래그만 있다.
